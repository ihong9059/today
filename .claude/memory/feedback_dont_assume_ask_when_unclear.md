## 🚨 핵심 (먼저 읽기)

사용자가 명시적으로 정보를 주지 않은 사항에 대해 **짐작 금지**. 특히:
- 외부 모듈·보드 결선
- 같은 IP 주소가 여러 보드 의미할 때
- dev kit (PCA10056, PCA10100 등)의 역할 (flash 호스트 vs target chip)
- 핀맵
- 페리퍼럴 분배 옵션

→ 모르면 **반드시 명확히 질문**. 표 형식으로 옵션 제시하고 선택 받기.

## 2026-06-07 박제 사건

**상황**: 한림용인CC LoRa 송수신 펌웨어 작성. 사용자: "PCA10056과 PCA10100에 LoRa가 연결된 BLE Module (14pin)에 연결되어 있습니다. PCA10056에는 RS485 센서가 연결되어 있고, 동일 mode로 setting."

**짐작 (틀림)**:
- PCA10056 = nRF52840 dev kit / PCA10100 = nRF52833 dev kit이라 핀맵 다르다고 가정
- TX 측은 SW-UART, RX 측은 HW UART로 분리 진행

**실제 (사용자 지적)**:
- 두 dev kit는 **flash 호스트 (J-Link OB)만 사용**
- 실제 chip은 양쪽 모두 **외부 UTTEC BLE Module nRF52832 (동일 보드)**
- LoRa는 양쪽 BLE Module에 **동일한 J28 핀맵으로 결선**되어 있음
- 따라서 펌웨어 핀맵도 양쪽 동일해야 함

**결과**: 빌드/flash 시간 낭비 + 사용자 지적 받음. 동일 사용자 지적: "모르면 물어봐야지요. 짐작해서 일을 진행합니까?"

## How to apply

**🚨 BEFORE 작업 진행**:
1. 사용자가 명시적으로 답하지 않은 핀맵·결선·페리퍼럴 → 표 형식 옵션 제시
2. 사용자 선택 받기 (Y/n 또는 a/b/c)
3. 받은 답변을 confirm 표로 다시 보여주고 진행
4. 모호한 답변이면 다시 질문 (해석 짐작 금지)

**❌ 금지 행동**:
- "default 가정"을 명시 없이 그대로 진행 — 가정한 default는 표로 보여주고 확인 받기
- 사용자가 "동일", "같은" 등 표현 사용 시 자기 멋대로 해석 — 어떤 면에서 동일인지 확인
- dev kit 모델명만 보고 핀맵 추정 — 외부 모듈 결선 우선 확인
