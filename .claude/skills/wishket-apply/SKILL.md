위시캣 지원서 작성 절차:

## 사용법

```
/wishket-apply 152759
```

프로젝트 ID를 인자로 전달하면 해당 프로젝트에 맞는 지원서를 생성합니다.

---

## 0. ID가 입력되지 않은 경우

ID 없이 `/wishket-apply`만 호출된 경우:

### Step 1: 최근 가능프로젝트 확인

위시캣/ 폴더에서 가장 최근 `*_가능프로젝트.md` 파일을 찾아 지원 추천/검토 필요 프로젝트 목록을 표시합니다.

```
위시캣/2026-02-10_가능프로젝트.md
```

### Step 2: 프로젝트 선택 요청

사용자에게 다음과 같이 질문합니다:

```
지원서를 작성할 프로젝트를 선택해주세요:

[지원 추천 프로젝트]
1. 152XXX - 프로젝트명 (예산, 기간)

[검토 필요 프로젝트]
2. 152YYY - 프로젝트명 (예산, 기간)

[직접 입력]
3. 프로젝트 ID 직접 입력

어떤 프로젝트에 지원하시겠습니까?
```

### Step 3: 선택 후 진행

사용자가 선택하면 해당 프로젝트 ID로 지원서 작성을 진행합니다.

### 가능프로젝트 파일이 없는 경우

```
최근 가능프로젝트.md 파일이 없습니다.
먼저 /wishket-check 를 실행하여 프로젝트를 검토하거나,
지원할 프로젝트 ID를 직접 입력해주세요.

예: /wishket-apply 152759
```

## 1. 프로젝트 정보 수집

https://www.wishket.com/project/{ID}/ 에서 상세 정보를 수집합니다.

수집 항목:
- 프로젝트명
- 예산 (월 단가 또는 총액)
- 기간
- 시작일
- 근무지 (상주/원격)
- 모집 마감일
- 모집 인원
- 필수 기술 스택
- 상세 업무 내용
- 필수 자격요건
- 우대 사항
- 산출물

---

## 2. 이력서/역량 자료 확인

지원서류/ 폴더에서 다음 파일들을 확인합니다:

```
지원서류/
├── 이력서_홍광선.pdf
├── 경력서 - 임호균.pdf
└── 보유기술.pdf
```

### 주요 역량 요약

**홍광선 (40년 경력)**
- 삼성전자: Audio/Video Controller, STB
- 파나소닉: LCD/I/O Printer Controller
- 유티즘: LED, IoT, Zigbee, LoRaWAN, Factory Automation
- 핵심: ARM, C/Assembler, RTOS, BLE, Zigbee, LoRaWAN

**임호균 (38년 경력, 3개국 8개사 60+프로젝트)**
- 삼성전자: Video/Motor Controller Board
- AuthenTec(미국): ARM CPU 설계, ASIC
- QuickLogic(미국): FPGA 설계
- 대한전선: WINDER CONTROLLER (CAN/RS485)
- 핵심: ARM, DSP, FPGA, ASIC, PCB, Motor Controller, RTOS

**보유기술.pdf (양산 실적)**
- EtherCAT 컨트롤러 (CM4 기반) - 국내 양산 판매 중
- V-Cut 컨트롤러 (Pi3, 2축 제어) - 중국 수출
- 컴프레샤 컨트롤러 (STM32F756, FreeRTOS) - 국내 양산
- 세탁기 컨트롤러 (STM32F407, FreeRTOS) - 국내 양산
- BLE 온도 컨트롤러 (nRF52832) - 국내 양산
- 회로설계 25년, OrCAD/EasyEDA 상급, PADS 중급

## 3. 기술 스펙 매칭 분석

프로젝트 요구사항과 보유 역량을 1:1 매칭합니다.

분석 형식:
```
요구 기술 --> 보유 역량 --> 매칭 여부
```

매칭 기호:
- [O] : 완벽 매칭 (경험 있음)
- [△] : 부분 매칭 (유사 경험)
- [X] : 미매칭 (경험 없음)

## 5. 지원서 작성 원칙

### DO (해야 할 것)

1. **기술 스펙 1:1 매칭**
   - 프로젝트 요구사항을 하나씩 짚어서 대응 역량 명시
   - 구체적인 프로젝트명과 경험 제시

2. **양산 실적 강조**
   - "양산 판매 중", "중국 수출" 등 실적 증거
   - 보유기술.pdf의 5개 양산 제품 활용

3. **구체적 수치 제시**
   - "38년 경력", "25년 회로설계", "60+ 프로젝트"
   - "5개 제품 양산", "3개국 8개사"

4. **관련 경험 우선 배치**
   - 프로젝트와 가장 관련 높은 경험을 상단에 배치
   - 대기업 경력(삼성, 파나소닉)으로 신뢰도 확보

5. **부족한 부분 솔직히 기술**
   - 약점이 있으면 대안 제시
   - 예: "C# 경험 부족 → C++ 기반 개발 제안"

### DON'T (하지 말 것)

1. 요구하지 않은 기술 장황하게 나열
2. 관련 없는 경험 포함
3. 추상적 표현 ("다양한 경험", "풍부한 역량")
4. 마크다운 표 사용 (txt 파일이므로 텍스트 형식)
5. **회사명(UTTEC, 유티즘 등) 절대 사용 금지** - 중간 중계 업체에서 회사명 노출 시 페널티 부과. "당사", "저희 팀" 등으로 대체할 것. URL에 포함된 회사명도 제거하거나 마스킹 처리.
