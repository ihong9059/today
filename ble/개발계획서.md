# ESP32-C3 스마트폰 개발 & BLE OTA 프로젝트 계획서

## 프로젝트 개요

스마트폰(Android)에서 ESP32-C3 펌웨어를 개발하고, BLE를 통해 OTA 업데이트하여 데스크톱 없이 임베디드 개발 사이클을 완성한다.

```
[스마트폰에서 코드 작성]
        ↓
[클라우드에서 컴파일] (GitHub Actions)
        ↓
[.bin 다운로드]
        ↓
[BLE OTA로 ESP32-C3에 플래싱]
        ↓
[동작 확인 / 반복]
```

---

## Phase 0: 초기 부트스트랩 (USB, 1회만)

> ESP32-C3에 BLE OTA 서버 펌웨어를 최초 1회 USB로 플래싱한다.
> 이후 모든 업데이트는 BLE OTA로 진행.

### 필요 장비
- ESP32-C3 개발보드 (USB-C 포트)
- Android 스마트폰 (USB OTG 지원)
- USB-C to USB-C 케이블 (또는 OTG 어댑터)

### 작업
| # | 작업 | 도구 |
|---|------|------|
| 1 | Termux 설치 및 기본 환경 구성 | Android Play Store |
| 2 | esptool 설치 (`pip install esptool`) | Termux |
| 3 | BLE OTA 부트로더 펌웨어 빌드 | GitHub Actions (또는 PC) |
| 4 | USB OTG로 ESP32-C3에 최초 플래싱 | esptool + Termux |

### 최초 플래싱 명령
```bash
# Termux에서 USB OTG를 통한 플래싱
esptool.py --chip esp32c3 --port /dev/ttyUSB0 --baud 460800 \
  write_flash -z 0x0 bootloader.bin 0x8000 partition-table.bin 0x10000 ble_ota.bin
```

## Phase 2: 클라우드 빌드 파이프라인 (GitHub Actions)

> 스마트폰에서는 ESP-IDF 네이티브 컴파일이 비현실적이므로, GitHub Actions로 빌드한다.

### 2-1. 레포지토리 구조
```
esp32c3-ble-project/
├── .github/
│   └── workflows/
│       └── build.yml          # GitHub Actions 빌드
├── main/
│   ├── CMakeLists.txt
│   ├── main.c                 # 메인 애플리케이션
│   ├── ble_ota.c              # BLE OTA 서버
│   └── ble_ota.h
├── partitions.csv             # OTA 파티션 테이블
├── sdkconfig.defaults         # ESP-IDF 설정
└── CMakeLists.txt
```

### 2-2. GitHub Actions 워크플로우
```yaml
# .github/workflows/build.yml
name: ESP32-C3 Build

on:
  push:
    branches: [main]
  workflow_dispatch:            # 수동 트리거 (스마트폰에서)

jobs:
  build:
    runs-on: ubuntu-latest
    container:
      image: espressif/idf:v5.3

    steps:
      - uses: actions/checkout@v4

      - name: Build firmware
        run: |
          . /opt/esp/idf/export.sh
          idf.py set-target esp32c3
          idf.py build

      - name: Upload firmware
        uses: actions/upload-artifact@v4
        with:
          name: firmware
          path: |
            build/bootloader/bootloader.bin
            build/partition_table/partition-table.bin
            build/*.bin
```

### 2-3. 빌드 → 다운로드 워크플로우
```
[코드 수정] → git push → [Actions 자동 빌드] → [Artifacts 다운로드] → [BLE OTA]
```
- 스마트폰에서 GitHub Actions 페이지 접속하여 `.bin` 다운로드
- 또는 `gh` CLI를 Termux에서 사용:
```bash
gh run download --name firmware
```

## Phase 3: BLE OTA 시스템 구현

### 3-1. ESP32-C3 측 (펌웨어)

**파티션 테이블 (partitions.csv):**
```csv
# Name,    Type, SubType, Offset,   Size
nvs,       data, nvs,     ,         0x6000
otadata,   data, ota,     ,         0x2000
phy_init,  data, phy,     ,         0x1000
ota_0,     app,  ota_0,   ,         0x190000
ota_1,     app,  ota_1,   ,         0x190000
```

**BLE OTA 서버 핵심 로직:**
```c
// ble_ota.c — BLE GATT 서비스로 펌웨어 수신
#include "esp_ota_ops.h"
#include "nimble/nimble_port.h"

#define OTA_SVC_UUID        0xFE00
#define OTA_DATA_CHR_UUID   0xFE01  // 펌웨어 데이터 수신
#define OTA_CTRL_CHR_UUID   0xFE02  // 제어 (시작/완료/취소)

static esp_ota_handle_t ota_handle;
static const esp_partition_t *update_partition;
static uint32_t total_received = 0;

// 펌웨어 청크 수신
int ota_data_write(uint8_t *data, uint16_t len) {
    if (total_received == 0) {
        update_partition = esp_ota_get_next_update_partition(NULL);
        esp_ota_begin(update_partition, OTA_SIZE_UNKNOWN, &ota_handle);
    }
    esp_ota_write(ota_handle, data, len);
    total_received += len;
    return 0;
}

// OTA 완료
void ota_finish(void) {
    esp_ota_end(ota_handle);
    esp_ota_set_boot_partition(update_partition);
    total_received = 0;
    esp_restart();
}
```

### 3-2. Android 앱 (BLE OTA 클라이언트)

**옵션 A: 기존 앱 활용 (빠른 시작)**
- [ESP32 BLE OTA Android](https://github.com/fbiego/ESP32_BLE_OTA_Android) — 오픈소스, 즉시 사용 가능
- nRF Connect — 범용 BLE 도구, GATT 수동 Write 가능

**옵션 B: 커스텀 앱 개발 (추후)**
- Kotlin + Android BLE API
- 펌웨어 선택 → 청크 분할 → BLE GATT Write → 진행률 표시

### 3-3. BLE OTA 전송 사양

| 항목 | 값 |
|------|-----|
| BLE 버전 | 5.0 (ESP32-C3 지원) |
| MTU | 512 bytes (negotiate) |
| 청크 크기 | 500 bytes/패킷 |
| 전송 속도 | ~10-15 KB/s |
| 500KB 펌웨어 전송 | 약 30~50초 |
| 보안 | BLE Bonding + 펌웨어 서명 검증 |

## Phase 4: 개발 사이클 운영

### 일상 개발 워크플로우

```
1. Claude에게 기능/수정 요청
       ↓
2. 코드 리뷰 후 Acode에서 편집 또는 직접 Git push
       ↓
3. GitHub Actions 자동 빌드 (약 2-3분)
       ↓
4. 스마트폰에서 .bin 다운로드
       ↓
5. BLE OTA 앱으로 ESP32-C3에 전송 (약 30-50초)
       ↓
6. ESP32-C3 자동 재부팅 → 동작 확인
       ↓
7. 문제 있으면 1번으로 반복
```

### 디버깅 방법
- **BLE Serial**: UART 출력을 BLE로 스마트폰에 전송
- **nRF Connect**: BLE 서비스/특성 실시간 모니터링
- **LED 상태 표시**: GPIO로 상태 피드백
