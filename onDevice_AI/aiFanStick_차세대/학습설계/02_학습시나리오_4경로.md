# 학습 시나리오 4 경로

## 한 줄 결론

> **단일 정답 없음. 비용·표현력·차별화 사이의 trade-off로 4 경로 존재. 본 vault 기준 권장: 경로 D (응원봉 자체 SLM) 검증 완료 → 경로 C (현재 운영) + 경로 D 병행 → 중기 경로 B (폰 LoRA) 추가.**

---

## 4 경로 한눈 비교

| 경로 | 위치 | 모델 | 학습 비용 | 추론 시간 | 표현력 | 차별화 | 권장도 |
|:-:|---|---|---|---|---|---|:-:|
| **A** | ESP32-S3 직접 | microGPT 변형 (~150K) | 0 (PC 1~2시간) | 50~500ms | 짧은 응답 | ★★★★★ (특허) | ★★★★ |
| **B** | 스마트폰 | Gemma 2B + LoRA | 무료 (Colab T4) | 3~8초 | 자연어 QA | ★★★ | ★★★ |
| **C** | 클라우드 (현재) | OpenAI gpt-4o-mini | 학습 X | ~2초 | 최고 | ★ | ★★★★★ (운영 중) |
| **D** | 응원봉 자체 SLM | microGPT 변형 (~150K~500K) | 0 | 50~500ms | 짧은 응답 + LED | ★★★★★ (마케팅 카피) | ★★★★★ |

(경로 A와 D는 **같은 ESP32-S3 위치**이지만 **다른 의미**: A는 "응원봉 단독 작동", D는 "스마트폰 + 응원봉 양쪽에 SLM 분산". 자세히는 후술.)

---

## 경로 A — ESP32-S3 직접 (응원봉 단독 작동)

### 정의
응원봉 안의 ESP32-S3가 **스마트폰 없이 단독으로** 음성 인식 + AI 응답 + LED 제어.

### 모델
- microGPT 변형 (Korean-Small): vocab=2000, n_embd=32, n_layer=2, ~154K params
- INT8 양자화: 155 KB (SRAM 520 KB의 29.7%)
- 추론: token당 0.5~5 ms (16 토큰 응답 < 100 ms)

### 학습
- 데이터: 한국어 콘서트 QA 500~2000쌍 + LED 태그
- 학습 환경: PC (Python 순수 또는 numpy)
- 학습 시간: 5,000~10,000 step, 약 1~3시간 (n_embd=32 기준 microGPT 4K의 16배 시간)
- 양자화: 학습 후 1회 INT8 변환 (대칭 양자화)

### 가능한가?
- **학습**: ✅ 가능 (PC 무료)
- **추론**: ✅ 가능 (Phase 1B 분석으로 확인)
- **음성 인식**: ❌ 매우 어려움 (응원봉의 ICS-43434 마이크 + ESP32-S3로 한국어 STT 거의 불가능)
- **응답 풍부도**: ❌ 한계 (4K vs 150K도 짧은 응답 수준)

### 장점
- 스마트폰 불필요 (응원봉만 있으면 됨)
- 인터넷 0% (가장 강한 차별화)
- 양산 단가 영향 0 (ESP32-S3 그대로)
- "외부 인터넷 0% AI" 카피 + 특허 보강 핵심

### 단점
- **음성 인식이 응원봉 단독 → 비현실적** (콘서트 노이즈 환경 + ESP32-S3 STT 어려움)
- 4K~150K params로는 자연어 QA 한계
- 결국 "버튼 + 사전 정의 응답"에 가까움

### 결론
**응원봉 단독 동작은 비현실적**. 실용적으론 **경로 D (응원봉 + 폰 분담)**의 일부로 활용.

---

## 경로 B — 스마트폰 온디바이스 (Gemma 2B + LoRA)

### 정의
스마트폰 앱이 **Gemma 2B (또는 Phi-2 등)** 를 로컬 실행 + 콘서트 도메인 LoRA 파인튜닝.

### 근거
응원봉 vault `newMvp/온디바이스_AI_검토서.md` (2026-02-27)에서 이미 권장.

### 모델
- Gemma 3n 2B Q4: 1.2 GB, ~2 GB RAM 필요 (응원봉 검토서 권장)
- 또는 Phi-2 Q4: 1.8 GB
- 또는 TinyLlama 1.1B Q4: 0.7 GB (저사양 폰)

### 학습 (LoRA 파인튜닝)
- 데이터: 콘서트 도메인 QA 500~2000쌍
- 환경: Google Colab T4 GPU (무료) 또는 RTX 3060+
- 도구: Unsloth (4bit LoRA, 2~5x 빠름) 또는 Hugging Face PEFT
- 학습 시간: 1~3시간
- 산출: LoRA adapter 약 10~50 MB (추가 다운로드)

### 가능한가?
- **LoRA 파인튜닝**: ✅ 매우 가능 (Unsloth 가이드 풍부)
- **폰 추론**: ✅ MediaPipe LLM 또는 llama.cpp (응원봉 검토서 검증)
- **응답 시간**: ⚠️ 3~8초 (Pixel 8) ~ 8~10초 (저사양)
- **기기 제한**: ⚠️ 4 GB RAM 미만 폰은 불가 → 시장 일부 제외

### 장점
- **본격 자연어 QA** 가능 (Gemma 2B는 GPT-4의 8% 정도 품질)
- 오프라인 동작 (콘서트장 인터넷 끊김 OK)
- LoRA 파인튜닝으로 콘서트 도메인 특화 가능
- API 비용 0 (모델 다운로드 1회만)

### 단점
- 응답 시간 느림 (3~8초 vs 클라우드 2초)
- 모델 다운로드 1.2 GB (사용자 부담)
- 저사양 폰 미지원
- 응원봉 차별화에는 기여 X (스마트폰의 일이라)

### 결론
**중기 채택 권장**. 본격 오프라인 QA에는 이 경로가 유일한 현실적 답.

## 경로 C — 클라우드 (현재 운영)

### 정의
스마트폰 앱이 **OpenAI gpt-4o-mini 또는 Gemini** API 호출 (현재 운영 중).

### 학습
- 학습 불필요 (모델은 이미 한국어 처리 능력 보유)
- 시스템 프롬프트로 콘서트 도메인 주입 (`prompt_generator.py` 215줄)

### 가능한가?
- ✅ **이미 운영 중** (서버 8081, OpenAI 폴백 Gemini)
- ✅ 응답 ~2초

### 장점
- 학습 비용 0
- 응답 속도 가장 빠름
- 응답 품질 가장 높음 (GPT-4 클래스)
- 기존 인프라 그대로 재활용

### 단점
- **콘서트장 인터넷 끊김 시 불가** ❌
- API 비용 발생 (gpt-4o-mini ~$0.0001/요청, 5만 명 × 100요청 = $500/콘서트)
- API 키 보안 (newMvp 시 디컴파일 위험)
- 차별화 가치 ★ (OpenAI를 쓰는 누구나 가능)

### 결론
**즉시 활용 + 영구 유지**. 단일 솔루션은 아니지만 **메인 경로로 운영**.

## 경로 D — 응원봉 자체 SLM (특허·마케팅 핵심)

### 정의
**응원봉 ESP32-S3에 자체 SLM 탑재** + 스마트폰의 메인 AI는 별개 운영. 응원봉 단독으로는 제한 응답 + 색상 매핑.

### 차이점 (경로 A와)
- 경로 A: 응원봉 단독으로 모든 기능 시도 (음성 인식 포함, 비현실적)
- 경로 D: 응원봉은 **결정적 룩업/응답 + LED 매핑**, 스마트폰은 메인 AI (음성 인식 + 자연어 QA)

### 응원봉의 역할 (경로 D)
1. **셋리스트 룩업**: 곡명 → LED 색상 매핑 (인터넷 0%, 즉시)
2. **간단 응답 생성**: microGPT 변형 (~150K) → "보라해", "최고예요" 등 짧은 응답
3. **인터넷 끊김 시 폴백**: 폰 ↔ 클라우드가 끊기면 응원봉이 직접 응답
4. **마케팅 카피**: "외부 인터넷 0%, 응원봉 자체 GPT 탑재" → 특허 보강

### 모델
- Korean-Small: ~154K params, INT8 155 KB (Phase 1B 분석)
- 또는 더 작은 Tiny Korean: ~30K params, INT8 30 KB (룩업+짧은 응답 충분)

### 학습
- 데이터: 한국어 콘서트 QA + LED 태그 100~500쌍 (적은 양으로 충분, 도메인 협소)
- 환경: PC microGPT 변형 (n_embd=32, n_layer=2)
- 시간: 1~3시간
- 양자화: INT8

### 가능한가?
- ✅ **Phase 1A·1B 검증 완료** (5/8) — 모델 자체 탑재 가능
- ✅ 학습 가능 (PC, 무료)
- ⚠️ 음성 인식은 폰이 담당 (응원봉은 결과 받기만)

### 장점 (Stage 4 영업의 핵심)
- ★★★★★ **차별화 카피**: "외부 인터넷 0% 응원봉 GPT" — 다른 응원봉에 없는 유일성
- ★★★★★ **특허 보강**: 현재 출원의 차세대 청구항으로 추가 가능
- ★★★★ Stage 4 (1,500만) 패키지 PoC 직접 사례
- ★★★ BOM 영향 0 (ESP32-S3 그대로)
- ★★★ 강사양성·호오컨설팅·인프런 강의 사례

### 단점
- 응원봉 단독 표현력은 짧은 응답 수준
- 한국어 데이터셋 사용자 수동 수집 필요 (1~2주)
- C++ 포팅 1~2주 (1인)

### 결론
**즉시 검증 진행 권장**. Phase 2 (보드 도착 후) 핵심 작업.

| 시점 | 경로 | 작업 |
