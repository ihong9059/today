# 데이터셋 설계

## 한 줄 결론

> **콘서트 도메인 QA 500~2000쌍 + LED 태그 형식. ChatGPT 합성 70% + 사용자 수동 검수 30%로 1~2주 구축. 소규모지만 도메인 협소해서 충분.**

---

## 1. 데이터 형식 표준

### 1-1. 한 항목 (record) 형식

```json
{
  "id": "Q001",
  "category": "setlist",
  "question": "다음 곡이 뭐야?",
  "context": {
    "current_song_index": 2,
    "current_song": "좋아좋아",
    "next_song": "봄날"
  },
  "answer": "다음 곡은 '봄날'이야! 분홍색 준비!",
  "led_tag": "[LED:255,182,193]",
  "full_response": "다음 곡은 '봄날'이야! 분홍색 준비! [LED:255,182,193]"
}
```

### 1-2. 학습용 평탄화 (flattened) 형식

microGPT/Korean-Small 학습용 단일 텍스트:

```
<|user|>다음 곡이 뭐야?<|assistant|>다음 곡은 '봄날'이야! 분홍색 준비! [LED:255,182,193]<|end|>
```

또는 BOS 토큰 사용:

```
[BOS]Q: 다음 곡 뭐야? A: 다음은 '봄날'! 분홍색 준비! [LED:255,182,193][BOS]
```

→ 작은 모델일수록 형식 단순할수록 학습 잘 됨.

## 2. 카테고리별 목표 항목 수

| 카테고리 | 항목 수 | 비율 | 난이도 | 우선순위 |
|---|---:|:-:|:-:|:-:|
| **A. 셋리스트** (다음 곡, 응원법) | 100~200 | 25% | 하 | ★★★★★ |
| **B. 멤버 정보** (생일, 본명) | 50~100 | 10% | 하 | ★★★★ |
| **C. 팬덤 용어** (보라해 등) | 50~100 | 10% | 하 | ★★★★ |
| **D. 자연 대화** (감정·일반) | 200~500 | 30% | 중 | ★★★ |
| **E. LED 색상 룩업** | 50~100 | 10% | 하 | ★★★★★ |
| **F. 콘서트 진행 (떼창·앵콜)** | 100~200 | 15% | 중 | ★★★ |
| **합계** | **500~1,200** | 100% | | |

→ **최소 500쌍, 권장 1,000~2,000쌍**.

## 3. 데이터 출처 (구축 방법)

### 3-1. ChatGPT 합성 (70% 비중)

**프롬프트 예시**:

```
당신은 K-POP 팬덤 전문가입니다. BTS 콘서트 응원봉 AI 비서가 답할 수 있는 
질문-응답 쌍을 100개 생성해주세요.

[조건]
1. 카테고리: 셋리스트 50개, 멤버 정보 30개, 팬덤 용어 20개
2. 응답 형식: 친근한 반말, 끝에 LED 색상 태그 [LED:R,G,B]
3. 셋리스트 곡: Dynamite, 좋아좋아, 봄날, Butter, Boy With Luv, 피 땀 눈물, 달려라 방탄, 소우주
4. 멤버: RM, 진, 슈가, 제이홉, 지민, 뷔, 정국

[출력 형식]
JSON 배열로:
[
  {"q": "...", "a": "...", "led": [R,G,B]}
]
```

**예상 산출**: 1,000쌍 (10번 호출 × 100쌍, ChatGPT Plus 1시간)

### 3-2. 사용자 수동 검수/추가 (30% 비중)

ChatGPT 합성 결과를 검수 + 도메인 특수 항목 직접 작성:

| 항목 | 사용자 작업 |
|---|---|
| 셋리스트 정확성 | 이미 `concert_data.json` 8곡 확정 → 검증 |
| 멤버 정보 정확성 | RM 9/12, 진 12/4 등 사실 확인 |
| 팬덤 용어 누락 검사 | "보라해", "아미밤" 등 확인 |
| 응원법 정확성 | 실제 콘서트 영상 또는 응원법 사이트 확인 |
| 부적절 답변 제거 | "오빠 사진 보내줘" 등 부적절 응답 제거 |

**예상 시간**: 1,000쌍 검수 + 200쌍 추가 = 8~16시간 (사용자 직접)

### 3-3. 운영 데이터 활용 (옵션, 30% 추가)

현재 운영 중인 mvp 서버 (Tailscale 100.79.180.64) 로그가 있다면:
- 실제 사용자 음성 STT 결과 → 응답 품질 검수
- 자주 묻는 질문 패턴 → 추가 데이터셋

→ 현재 운영 데이터 양이 충분한지는 별도 확인 필요.

## 4. 토크나이저 선택

### 4-1. 옵션 비교

| 토크나이저 | 한국어 | vocab | 구현 난이도 | 권장 |
|---|:-:|:-:|:-:|:-:|
| char-level (microGPT 방식) | ❌ 한국어 부적합 | 27 | 매우 하 | X |
| **자모 분리** (ㄱ, ㅏ, ㄴ) | ✅ 부분 가능 | ~70 | 하 | ★ |
| **byte-level BPE** | ✅ 가능 | 256~512 | 중 | ★★★★ |
| **sentencepiece BPE** | ✅ 권장 | 1,000~5,000 | 중 (라이브러리) | ★★★★★ |
| **wordpiece** (BERT) | ✅ 가능 | 30,000+ | 중 | ★★ |

### 4-2. 권장: sentencepiece BPE

```python
# 학습 (PC에서 1회)
import sentencepiece as spm
spm.SentencePieceTrainer.train(
    input='dataset.txt',
    model_prefix='kpop_tokenizer',
    vocab_size=2000,
    model_type='bpe',
    character_coverage=1.0,  # 한국어 전체 커버
    pad_id=0, unk_id=1, bos_id=2, eos_id=3
)
# 산출: kpop_tokenizer.model (약 100~300 KB)
```

ESP32-S3 추론 시:
- 토크나이저는 vocab + merge rules → C++ 포팅 (200~400줄)
- 또는 단순화: 사전 토큰화된 데이터 미리 정수 시퀀스로 저장

### 4-3. 더 단순한 대안: 영어 + 한국어 키워드 매핑

만약 vocab 비용 부담이면:
- 응답을 영어/한자/숫자/이모지 위주로 작성 + LED RGB
- 예: `"Next: Spring Day. Pink! [LED:255,182,193]"`
- vocab ~100으로 가능, 한국어 표시는 폰 측에서 매핑

→ 응원봉 단독 출력에 적합 (디스플레이 한국어 어차피 작은 OLED).

## 5. 학습 데이터 통계 (목표)

### 5-1. 형태소 분포 추정 (1,000 QA × 평균 30 토큰 = 30,000 토큰)

| 항목 | 값 |
|---|---|
| 총 QA 쌍 | 1,000 |
| 평균 질문 길이 | 5~10 토큰 |
| 평균 응답 길이 | 15~25 토큰 (LED 태그 포함) |
| 총 토큰 | ~30,000 |
| Unique vocab | ~2,000 (sentencepiece BPE) |

### 5-2. 학습 step 추정

microGPT는 step당 1 doc 학습 (block_size 16). Korean-Small (n_embd=32, block=64)에서:

| 데이터 | 모델 | num_steps | 시간 (PC) |
|---|---|---:|---|
| 1,000 QA | Korean-Small (154K) | 10,000 step (10 epoch) | ~2~3시간 |
| 1,000 QA | Korean-Small (154K) | 30,000 step (30 epoch) | ~6~10시간 |

→ ChatGPT 합성 데이터는 노이즈 큼 → 5~10 epoch 권장 (overfitting 방지).

## 6. 데이터셋 구축 일정

### Week 1
- [ ] ChatGPT 합성 1,000쌍 (10시간)
- [ ] 사용자 수동 검수 + 정정 (8시간)
- [ ] sentencepiece 토크나이저 학습 (1시간)
- [ ] 데이터 검증 (vocab 커버리지, 길이 분포) (2시간)

### Week 2
- [ ] 부족한 카테고리 (자연 대화 D) 추가 200쌍 (4시간)
- [ ] LED 색상 정확성 검증 (`concert_data.json` 매핑) (2시간)
- [ ] 학습 / 검증 분할 (90% / 10%) (1시간)
- [ ] microGPT 변형 (Korean-Small) 코드 수정 + 첫 학습 (4시간)

### Week 3
- [ ] 학습 결과 평가 (생성 텍스트 품질) (4시간)
- [ ] 응답 부족한 카테고리 추가 학습 데이터 (4시간)
- [ ] INT8 양자화 + ESP32-S3 포팅 준비 (Phase 2 시작)

→ **총 약 40~60시간** (사용자 + Claude 분담), **3~4주**.

### 7-1. 안전한 데이터
- ChatGPT 합성 (사용자 가공 책임) ✅

### 7-2. 주의 데이터
- 가사 일부 인용 → 짧은 인용 (저작권법 §28 인용) 권장, 전문 X

→ 안전: **공개된 사실 정보 (생일, 곡 발매일, 응원법) 위주**.
