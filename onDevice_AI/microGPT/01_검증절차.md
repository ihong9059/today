## 사전 조건

- Python 3.10+ (권장 3.12)
- pip 설치 도구
- numpy, torch (선택, 없어도 200줄 순수 Python 동작)
- 인터넷 (Karpathy GitHub 접근)
- 시간 1~2시간

## Step 3 — 모델 파라미터 분석 (15분)

### 절차

학습 직후 코드에 다음 추가:

```python
# 파라미터 개수 측정
total_params = sum(p.numel() for p in model.parameters())
print(f"Total parameters: {total_params}")

# 메모리 사용량 (FP32 기준)
import sys
total_bytes_fp32 = total_params * 4  # FP32
print(f"FP32 size: {total_bytes_fp32} bytes = {total_bytes_fp32/1024:.1f} KB")
print(f"INT8 size: {total_params} bytes = {total_params/1024:.1f} KB")
print(f"INT4 size: {total_params/2} bytes = {total_params/2048:.1f} KB")
```

### 체크리스트
- [ ] 총 파라미터 수 확인 (예상: 4,192)
- [ ] FP32 크기 (예상: 16.7 KB)
- [ ] INT8 크기 (예상: 4.2 KB)
- [ ] INT4 크기 (예상: 2.1 KB)

### 결과 기록 영역

```
총 파라미터: 4,192 (실측 확인, train.py 출력 "num params: 4192")

내역:
  wte (token embed)    : 27 × 16 = 432
  wpe (position embed) : 16 × 16 = 256
  lm_head              : 27 × 16 = 432
  attn_wq/wk/wv/wo (1L): 4 × (16×16) = 1,024
  mlp_fc1              : 64 × 16 = 1,024
  mlp_fc2              : 16 × 64 = 1,024
  ─────────────────────────────────────
  합계                  : 4,192

가중치 메모리:
  FP32 (4 bytes): 16,768 bytes = 16.4 KB
  INT8 (1 byte) :  4,192 bytes =  4.1 KB
  INT4 (0.5 byte):  2,096 bytes =  2.0 KB

ESP32-S3 SRAM 520 KB 대비:
  FP32: 16.4 / 520 =  3.15% 사용 (잔여 503.6 KB)
  INT8:  4.1 / 520 =  0.79% 사용 (잔여 515.9 KB)
  INT4:  2.0 / 520 =  0.39% 사용 (잔여 518.0 KB)

결론: 탑재 가능 (압도적 여유)
  ─ FP32도 SRAM의 3% 미만으로 들어감
  ─ 활성값(activation) + 토크나이저 + 추론 코드 합쳐도 < 100 KB 예상
  ─ KV-cache (1 layer × 16 block × 16 embd × 4B = 1 KB) 무시 가능
  ─ AI FanStick 차세대 → ESP32-S3 N16R8 (PSRAM 8MB)는 오버스펙
  ─ 단, 모델 자체의 표현력은 4K 파라미터 = "이름 생성" 수준
    실용 응답에는 더 큰 모델 필요 (10K~100K), 그래도 SRAM 여유
```

## Step 4 — ESP32-S3 포팅 가능성 분석 (30분)

### 검증 항목

#### 4-1. 메모리 가능성
- ESP32-S3 SRAM: 520 KB (내장)
- 옵션: ESP32-S3-N16R8 = 추가 PSRAM 8 MB

| 양자화 | 모델 크기 | SRAM 사용 | PSRAM 필요? |
|---|:-:|:-:|:-:|
| FP32 | 16.7 KB | 3% | 불필요 |
| INT8 | 4.2 KB | 1% | 불필요 |
| INT4 | 2.1 KB | 0.4% | 불필요 |

→ **메모리는 압도적 여유**. SRAM 520KB의 1% 미만 사용.

#### 4-2. 연산 가능성

ESP32-S3 사양:
- Xtensa LX7 듀얼코어 (240MHz)
- 부동소수점 가속 (FP32 일부 지원)
- AI 가속기 없음 (Cadence Tensilica DSP는 있지만 별도 프로그래밍)

**예상 추론 시간**:
- 4,192 파라미터 transformer-like 추론
- 1 토큰 생성: 추정 10~50ms (양자화 후)
- 10 토큰 생성: 100~500ms

→ **인터랙티브 응답 가능** (목표 < 1초).

#### 4-3. 코드 변환 (Python → C++)

Karpathy 200줄 Python을 ESP32-S3 C++로 변환:

| Python 요소 | C++ 변환 | 난이도 |
|---|---|:-:|
| numpy.matmul | 직접 구현 또는 ESP-DSP 라이브러리 | 중 |
| numpy.softmax | 직접 구현 (지수함수 lookup) | 중 |
| 토큰화 (BPE) | C++ 구현 (200~300줄) | 중 |
| Cross-entropy loss | (학습은 PC에서, 추론만 ESP32) | — |
| 가중치 로드 | flash 또는 PSRAM | 하 |

→ 학습은 PC에서 → 가중치만 ESP32에 flash. 추론 코드 약 500~1000줄 C++ 추정.

- [ ] 연산 가능성 결론 (실시간 / 준실시간 / 너무 느림)
- [ ] 코드 변환 난이도 결론 (1주 / 2주 / 1개월+)

### 결과 기록 영역 (분석 후 채움)

```
메모리 결론: 가능 (압도적 여유)
  ─ FP32 16.4 KB / SRAM 520 KB = 3.15%
  ─ INT8  4.1 KB / SRAM 520 KB = 0.79%
  ─ INT4  2.0 KB / SRAM 520 KB = 0.39%
  ─ 활성값(activation)도 한 번에 16~64 float만 유지 → < 1 KB

연산 결론 (PC 실측 + ESP32-S3 이론):
  PC 실측 (Python 순수, inference_bench.py 200 샘플 평균):
    ─ token당  0.510 ms
    ─ sample(16 token)당  8.16 ms
    ─ 처리량: 122 samples/sec

  이론 FLOPS (n_embd=16, n_head=4, block_size=16):
    ─ token당 약 4,000 FLOPS (forward, avg pos)

  ESP32-S3 추정 (Xtensa LX7 @ 240MHz):
    ─ 실효 성능: 50~100 MFLOPS (FP32, FPU, 메모리·캐시 포함)
    ─ INT8+SIMD (ESP-DSP): 200~400 MMAC/s
    ─ 추정 token당:
       · FP32  : 0.04~0.10 ms (이론) → 0.5~5 ms (보수, C++ 오버헤드)
       · INT8  : 0.01~0.02 ms (이론) → 0.1~1 ms  (보수)
    ─ 추정 sample(16 token)당:
       · FP32  : 10~80 ms (보수)
       · INT8  : 2~20 ms  (보수)
    ─ 인터랙티브 응답 (< 1초) 압도적 여유

코드 변환 난이도: 중 (1~2주 1인 작업)
  필요 모듈 (C++ 추정 줄수):
    ─ matvec / matmul       : 30~50줄 (또는 ESP-DSP esp_dsp_dotprod_f32)
    ─ rmsnorm               : 15줄
    ─ softmax               : 20줄
    ─ KV cache              : 30줄 (block_size 고정 배열)
    ─ multi-head attention  : 80~120줄
    ─ MLP block             : 30줄
    ─ embedding lookup      : 10줄
    ─ sampling (top-k/top-p): 30줄
    ─ tokenizer (char→int)  : 20줄
    ─ 가중치 로드 (flash)   : 50줄
    ─ FreeRTOS task wrapper : 50~100줄
    ─ 기타 (main, UART, etc): 100줄
    ─ 합계                   : 약 500~700줄 C++

  학습은 PC에서 → 가중치 binary blob (16 KB FP32 / 4 KB INT8) → flash 영역 mmap

포팅 권장 시점: Phase 2 즉시 (ESP32-S3 보드 입수 후)
  ─ Phase 1A 검증 완료, 추가 PC 실험 불필요
  ─ 보드 도착 → hello_world (5분) → 가중치 flash → 추론 (1~2주)

다음 검토:
   - INT8 양자화: 직접 구현 (대칭 양자화, 채널별 scale) - 학습 후 1회
   - ESP-DSP 라이브러리: dotprod_f32, mulc_f32 등 SIMD 활용
   - ESP32-S3 vs ESP32-P4 비교 (P4: RISC-V 400MHz + AI 가속기)
       · S3로도 충분, P4는 더 큰 모델(100K+) 필요 시
   - ESP-IDF 선택 (Arduino IDE는 FreeRTOS·flash 매핑 제약)
   - PSRAM 8MB 옵션 (N16R8): microGPT는 불필요, 더 큰 SLM 시 활용
```
