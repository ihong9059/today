## 1. 연구 배경 (Background)

### 1.1 왜 지금 On-Device AI인가
2025~2026년이 **"클라우드 AI → On-Device AI" 변곡점** (시장조사/README.md §1). SLM(소형 언어모델) + NPU 보편화로 태스크 특화 AI는 디바이스에서 도는 것이 새 표준. 이 흐름의 정중앙에 UTTEC의 38년 임베디드 강점이 위치.

### 1.2 정의 (재확인)
**On-Device AI** = AI 추론을 **기기 자체 하드웨어에서 직접 수행**하는 방식. 학습은 클라우드, 추론은 디바이스(MCU·NPU·SoC). 4대 가치: **Privacy / Latency / Offline / Cost**. 4대 기술: **Quantization / Pruning / Distillation / NPU 가속**. 전체 정의는 `00_정의_OnDeviceAI.md` 참조.

### 1.3 UTTEC 영업 맥락
- Stage 4 (On-Device AI) 1,500만 패키지의 기술 근거 부족 → 본 vault가 해결
- 한국기계 등 첫 Stage 4 수주 시도 시 **"실제 보드에서 돌리고 측정해봤다"** 증거 필수
- 차별화: 다른 강사·외주는 분석만 제출, UTTEC은 **실측 데이터 첨부**

| 축 | 핵심 질문 | 본 계획서의 실험 |

## 3. 연구 가설 (Hypotheses)

### H1 — 모델 적재성 (model fit)
**ESP32-S3 SRAM 512KB + PSRAM 8MB에 100K~10M 파라미터 모델이 적재된다.**
- 검증: E1, E2 — microGPT 4K/154K INT8 적재 측정
- 기각 조건: 154K INT8조차 PSRAM 포함 안 들어가면 H1 부분 기각

### H2 — 추론 실용성 (inference usability)
**ESP32-S3에서 작은 모델(≤10K params) 추론 latency가 100ms 이내**
- 검증: E1, E3 — microGPT·AI FanStick SLM 실측
- 기각 조건: 100ms 초과 시 응용 범위 축소 필요

### H3 — AI 가속 효과 (acceleration impact)
**ESP32-S3의 vector SIMD가 무가속(esp32wroom) 대비 3배 이상 가속**
- 검증: E4 — 동일 모델 esp32s3 vs esp32wroom 비교
- 기각 조건: 3배 미만이면 AI SIMD 영업 카피 약화 → 메모리 효율 축으로 전환

### H4 — 클로스 ISA 이식성 (cross-ISA portability)
**Xtensa(esp32s3) 모델이 ARM Cortex-M4F(pca10056)에 의미 있는 작업 가능 수준으로 이식된다.**
- 검증: E5 — microGPT 4K를 nRF52840에 포팅
- 기각 조건: 정확도·속도 1/10 미만이면 H4 기각, ESP 진영 only로 영업 전략 한정

### H5 — 극한 baseline (extreme bound)
**pca10040 (64KB RAM)에 "의미 있는 task" 모델이 들어간다 (KWS·이상탐지 등)**
- 검증: E6 — 가장 작은 모델 적재 시도
- 기각 조건: 모든 task에서 안 됨 → 64KB는 "AI 불가 baseline"으로 영업 카피

### H6 — 미드레인지 폰 한계 (T3- bound)
**2020 미드레인지 폰(Galaxy A51 5G, NPU 2.1 TOPS)에서 TinyLlama 1.1B Q4가 실용 속도로 동작 (≥5 tok/s)**
- 검증: E8 — llama.cpp Android 구동
- 기각 조건: 5 tok/s 미만이면 미드레인지 LLM은 "어려움"으로 영업 자료에 반영

### H7 — 양자화 trade-off (quantization cost)
**INT8 양자화로 미세 task 정확도 손실 ≤5%, 메모리 1/4 절감**
- 검증: E10 — PC에서 FP32 → INT8 → INT4 비교
- 기각 조건: 손실 ≥10%면 mixed precision 또는 INT16 권장으로 전환
