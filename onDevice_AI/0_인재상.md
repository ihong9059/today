# onDevice_AI vault 담당자 인재상

> **본 문서는 채용·평가·onboarding의 단일 출처.** 실험계획서 §11(책임 분담)에 등장하는 "담당자"가 어떤 사람이어야 하는지를 구체화. 감독이 후보자를 평가할 때, 후보자가 본인 적합도를 자가 진단할 때 동일하게 사용.

---

## 개요 (Executive Summary)

| 항목 | 내용 |
|---|---|
| **핵심 한 줄** | 임베디드 펌웨어 ↔ ML 모델의 **경계를 즐기는 미드레벨 엔지니어**, 정량 측정과 문서화를 자기 자산으로 여기는 사람 |
| **연차 가이드** | 3~7년 (한쪽 전문 + 다른 쪽 학습 의지 / 양쪽 경험은 보너스) |
| **핵심 3 역량** | (1) **임베디드 C/C++** (ESP-IDF 또는 Cortex-M 펌웨어 경험 ≥1년) (2) **ML 추론 파이프라인** (PyTorch/TF + 양자화 경험) (3) **측정·문서화 규율** |
| **핵심 마인드** | 가설 기반 사고, 단일 출처(SSOT) 원칙 존중, **AI 협업(Claude) 적극 활용**, 마케팅 정지선 존중 |
| **운영 모델** | 담당자 1명 풀타임 + Claude AI 협업 + 감독(홍광선) 주간 리뷰. 3~5개월. |
| **Red flag** | 양산 매출 욕구 강함 / 문서화 기피 / 클라우드 AI만 경험 / Linux 거부감 |

**한 줄 결론**: "혼자 펌웨어 빌드해서 보드에 flash하고, 가중치 양자화해서 latency 측정하고, 결과를 표로 만들어 영업팀에 넘기는 일을 **재미있다**고 느끼는 사람."

## 1. 역할 맥락 (Role Context)

### 1.1 담당자가 하는 일
실험계획서 §7의 **12 실험(E1~E12)을 4 Phase에 걸쳐 실행** + 결과를 매트릭스·entity·영업 자료로 흘려보냄. 구체적으로:

1. **PC 환경 셋업** — Ubuntu에서 ESP-IDF·nRF Connect SDK·PyTorch 빌드 가능 상태
2. **모델 학습·양자화** — microGPT, KWS, 센서 분류 등 PC에서 학습 → INT8/INT4 양자화
3. **보드 포팅** — Xtensa·ARM·RISC-V 3 ISA에 동일 모델을 이식 + flash
4. **측정** — SRAM·Flash·latency·정확도를 100회 평균으로 정량화
5. **비교** — 보드 간·양자화 간 trade-off 표·그래프 작성
6. **문서화** — `hardware/<board>/01~05_*.md`, `_matrix.md` 갱신
7. **데모** — Phase 4 종료 시 영업용 동영상 demo 1건 산출

### 1.2 담당자가 하지 않는 일
- ❌ **양산 펌웨어 통합** (정지선 ⛔)
- ❌ **영업 직접 방문** (산출물 제공까지)
- ❌ **고객 응대** (감독이 처리)
- ❌ **무관한 사내 잡무**

### 1.3 협업 모델
| 역할 | 책임 | 상호작용 빈도 |
|---|---|---|
| **담당자** | 실험 실행, 측정, 1차 문서화 | 매일 |
| **Claude** | 분석·시뮬레이션·코드 보조·디버깅·문서화 협업 | **매일 (적극)** |
| **감독 (홍광선)** | 우선순위 결정, 영업 매핑, 정지선 관리 | 주간 1:1 |

→ **AI 협업이 핵심**. Claude를 코드 리뷰어·페어 프로그래머·문서 정리자로 활용 가능한 사람이 적합.

## 2. 필수 기술 (Required Skills) — 3-Tier

## 3. 적합한 페르소나 (Personas)

세 가지 후보 타입 모두 본 vault에 적합. 강점·학습 영역만 다름.

### A타입 — 펌웨어 강점 + ML 학습형 🔧

**프로필**: 임베디드 펌웨어 3~7년, ML은 책·MOOC 수준 또는 토이 프로젝트 경험.

**강점**: E1·E4·E5·E6·E7 (포팅·측정·비교) — 즉시 생산성.
**학습 기간**: ML 파이프라인(E9)에 첫 2주 투자. 양자화 개념(E10)도 학습.
**리스크**: ML 정확도 해석에 시간 소요. teacher-student 증류 개념 학습 필요.
**구체 모델**: STM32 또는 ESP32로 1건 이상 양산 펌웨어 경험 + 회사에서 "AI 한번 봐줘" 라는 임무로 PyTorch 토이 돌려본 사람.

### B타입 — ML 강점 + 펌웨어 학습형 🧠

**프로필**: ML 엔지니어 2~5년 (CV·NLP·시계열 무관), 임베디드는 Arduino 수준 또는 학부 시절 경험.

**강점**: E9·E10·E3·E11 (학습·양자화·응용 설계) — 즉시 생산성.
**학습 기간**: ESP-IDF·Zephyr 빌드 환경(E1 사전 작업)에 첫 2~3주 투자. CMSIS-NN·ESP-DL 학습.
**리스크**: 메모리 수동 관리·debug 첫 경험에서 막힐 수 있음. UART·flash 워크플로 적응 필요.
**구체 모델**: 회사·연구실에서 PyTorch로 모델 만들어본 ML 엔지니어 + 학부 시절 Arduino 또는 라즈베리파이 토이 1~2건 경험.

### C타입 — 풀스택 Edge AI 🎯 (Best fit, 희소)

**프로필**: 임베디드 ML 5~10년. TFLM·CMSIS-NN·ESP-DL 중 1개 이상 양산급 경험.

**강점**: 전 실험(E1~E12) 즉시 가능. 새 라이브러리·SDK 자율 학습.
**학습 기간**: 첫 주 onboarding 후 즉시 Phase 1 본격 진행.
**리스크**: 인건비. 양산 욕구 강할 수 있어 정지선 사전 합의 중요.
**구체 모델**: 스타트업에서 Edge AI 제품 1건 양산 경험 + 본인이 "검증 단계 일도 좋다"고 합의된 경우.

**현실 우선순위**: **A타입 ≥ B타입 > C타입** (가용성·인건비·정지선 정합성). C타입이 와도 정지선·검증 단계 합의가 사전 필수.

## 4. 소프트 스킬 / 마인드셋 (Mindset)

기술보다 **장기적으로 더 중요**. 본 vault는 5개월 짜리이지만, 그 안에 30+ 측정·문서·결과 동기화가 일어남.

### 4.1 가설 기반 사고 (Hypothesis-Driven)
- 새 실험을 시작할 때 "이건 정의 §6의 어느 Q에 답하는가?" 자문
- 측정 전 예상치를 미리 적고, 결과와 비교해 차이의 원인 추적
- "그냥 돌려보자" 는 마인드는 본 vault와 안 맞음

### 4.2 단일 출처 원칙 (SSOT — Single Source of Truth)
- `_matrix.md` 1곳에 결과 기록, 보드 폴더에 복제 X
- 응용 정의는 `applications/` 1곳, 보드 폴더에 재기재 X
- 시간순 기록은 `log.md` 1곳

### 4.3 정량 측정 규율
- "빠르다·느리다" 가 아닌 "100회 평균 45ms, σ=12ms"
- 모든 측정은 재현 가능한 절차 + raw data (`results/` 폴더)
- 측정 조건(주파수·전원·온도) 명시

### 4.4 AI 협업 적극성 ⭐ 핵심
- **Claude를 페어 프로그래머·디버거·리뷰어로 매일 활용**
- 코드 막히면 Claude에게 먼저 묻고, 결과를 검증
- 문서 초안은 Claude → 본인 보정 → 최종
- 'AI 안 써본 사람'은 본 vault 효율 50%↓

### 4.5 정지선 존중 ⛔
- 마케팅 정지선(2026-05-08): Phase 4 종료 = 끝
- 양산 응원봉 칩 교체·양산 펌웨어 SLM 통합 ⛔
- 양산 요구 발생 시 → 정지선 문서 회신 + 별도 프로젝트 분리

### 4.6 영업 가치 인식
- 본 vault의 최종 목적은 영업 (Stage 4 1,500만)
- "기술적으로 흥미롭지만 영업 무관"한 실험은 우선순위 ↓
- 영업 데모 가능성을 항상 의식

## 5. Red Flags (부적합 신호)

다음 중 2개 이상 해당하면 본 vault 적합도 ↓.

| Red Flag | 왜 부적합한가 |
|---|---|
| 🚩 **양산 매출 만드는 일에 강한 욕구** | 정지선 충돌. Phase 4 종료를 좌절로 받아들임. |
| 🚩 **클라우드 AI(OpenAI API 등)만 경험** | On-Device 핵심 가치(Privacy·Offline·Cost) 체감 부족 |
| 🚩 **문서 작성 기피·"코드만 보면 안다"** | vault 운영 불가 — 매트릭스·log·spec 갱신 필수 |
| 🚩 **AI 도구(Claude·Copilot 등) 사용 거부** | 1인 + AI 협업 모델이 무력화 |
| 🚩 **Linux/CLI 거부감, GUI만 선호** | Ubuntu 빌드 환경 적응 못함 |
| 🚩 **"PoC만 빠르게, 측정·문서는 나중에"** | 본 vault는 측정·문서가 산출물 본질 |
| 🚩 **혼자 일하기 싫음·항상 팀 필요** | 1인 + Claude + 주간 감독 1:1 구조에 부적합 |
| 🚩 **임베디드 또는 ML 한쪽 0 + 학습 의지 없음** | 양쪽 다 0이면 부적합. 한쪽 0 + 학습 의지 ✅ 면 OK |

## 6. 평가 체크리스트 (Hiring Checklist)

감독이 후보자를 면담할 때 항목별로 체크. 합계 점수로 적합도 판단.

### 6.1 기술 면접 (60분, 30점)

| 질문·과제 | 답이 와야 하는 형태 | 점수 |
|---|---|:-:|
| Q1. ESP32 또는 Cortex-M 펌웨어 프로젝트 1건 설명 (5분) | 메모리·인터럽트·디버그 경험 언급 | /5 |
| Q2. PyTorch·TF로 학습한 모델 1건 설명 (5분) | Loss·정확도·overfitting 언급 | /5 |
| Q3. INT8 양자화가 모델에 미치는 영향 설명 | "메모리 1/4, 정확도 ~수% 손실, dynamic vs static" 수준 | /3 |
| Q4. On-Device AI의 4 가치 중 본인이 가장 매력적이라 느낀 것 | 어떤 답이든 진정성 (Privacy·Latency·Offline·Cost) | /3 |
| Q5. 본 vault 정의 §6 5축 중 본인이 가장 흥미로운 축 + 이유 | 모델·하드웨어·응용·양자화·영업 중 답+이유 | /4 |
| Q6. Claude 또는 AI 도구 일상 사용 사례 1건 | 구체 사례 (코드 보조·문서 등) | /4 |
| Q7. 마지막으로 측정한 latency·메모리 사용량 사례 | 정량 답변 (단위·조건 포함) | /3 |
| Q8. 양산 적용 욕구 자기 평가 (정직하게) | "검증 단계 일도 좋다" 답 (정지선 정합성) | /3 |

### 6.2 코딩 과제 (3~5시간, 30점)

**과제**: "Ubuntu에서 microGPT 4K (Karpathy 200줄)을 학습한 뒤, 가중치를 INT8로 양자화하고 추론 함수를 C로 작성해 PC에서 실행. 결과를 표 1장으로 정리."

| 평가 항목 | 점수 |
|---|:-:|
| 학습 재현 (Loss 수렴 확인) | /5 |
| 양자화 구현 (FP32 → INT8) | /5 |
| C 추론 함수 (메모리 정적 할당) | /8 |
| 측정 표 (시간·정확도·메모리) | /5 |
| 코드 품질 (가독성·주석) | /4 |
| 문서 (README·실행 방법) | /3 |

### 6.3 가치 정합성 면담 (30분, 20점)

| 질문 | 점수 |
|---|:-:|
| 본 vault의 마케팅 정지선 설명 후 반응 — 받아들이는가 | /5 |
| 5개월 후 vault archive — 단기 프로젝트 동의하는가 | /5 |
| 결과가 영업 자료가 됨에 동의하는가 (학술 publication 아님) | /5 |
| 감독·Claude·본인 3자 협업 모델 이해하는가 | /5 |

### 6.4 합격 기준
| 점수 | 판정 |
|:-:|---|
| ≥ 65/80 | ✅ 즉시 합격 |
| 50~64 | ⚠️ 학습 기간 명시 후 합격 (예: ML 부족 → 첫 2주 PyTorch 집중) |
| < 50 | ❌ 불합격 |

## 7. Onboarding 학습 곡선 예상

| 페르소나 | Day 1~7 | Week 2~3 | Week 4+ |
|---|---|---|---|

## 10. 자가 진단 체크리스트 (후보자용)

본 vault 합류를 고려하는 후보자가 자기 적합도를 미리 가늠하도록.

체크된 항목이 많을수록 적합도 ↑.

### 기술
- [ ] ESP32 또는 Cortex-M 펌웨어 프로젝트 1건 이상 완성한 적 있다
- [ ] PyTorch 또는 TF로 모델 학습한 적 있다 (분류·회귀 무관)
- [ ] INT8 양자화가 무엇인지 한 문장으로 설명 가능하다
- [ ] Ubuntu CLI에서 `ssh·git·make·cmake` 자유롭다
- [ ] Python 학습 스크립트 작성 + 실행 가능하다

### 도구
- [ ] Claude·Copilot·Cursor 등 AI 도구 일상 사용 중
- [ ] Markdown으로 기술 문서 작성 경험 있다
- [ ] 코드 리뷰·페어 프로그래밍 경험 있다

### 마인드
- [ ] 결과를 표·그래프로 정리하는 것을 즐긴다
- [ ] "5개월 후 archive되는 프로젝트"에 거부감 없다
- [ ] 영업 자료 산출이 자기 일의 가치라는 점에 동의한다
- [ ] 양산보다 검증·실증에 가치를 느낀다
- [ ] 혼자 깊이 일하는 것을 좋아한다 (감독은 주간 1회)

### 도메인
- [ ] On-Device AI라는 용어를 들으면 호기심이 생긴다
- [ ] microGPT(Karpathy 200줄) 또는 TinyML이라는 단어가 익숙하다
- [ ] "8달러 칩에서 AI"라는 표현이 흥미롭다

**자가 점수**: 체크 14~15개 → 즉시 지원 / 10~13개 → 학습 의지로 지원 / <10 → 다른 프로젝트 권장
