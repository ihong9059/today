### 보강 필요한 갭 (7개)

#### 1. 종료/archive 조건 미정

CLAUDE.md "완료 시 archive 가능"만 있고 **"완료"가 무엇인지** 정의 없음.

- KPI 6개 모두 ✅인지?
- Stage 4 첫 수주 시인지?
- Phase 3 완료(F·G 끝)인지?

→ README 또는 0_검증계획 끝에 "vault 종료 조건" 섹션 1개 필요.

#### 2. Step 1 시작점이 외부 검색 의존

`microGPT/01_검증절차.md` Step 1:

> "정확한 URL은 사용자가 GitHub karpathy/micrograd 또는 nanoGPT에서 확인"

Karpathy의 단독 'microGPT' repo는 실재하지 않을 가능성 높음. 실제로는 `karpathy/nanoGPT` 또는 `karpathy/makemore`.

→ **vault 첫 단계에서 막힘**. 시작 전 URL·버전 확정 필요.

#### 3. 반증/실패 시 분기 부재

위험 표는 있지만 *임계치* 없음.

- 양자화 후 정확도 *몇 %* 떨어지면 가설 반증?
- 추론 시간 *몇 ms* 초과 시 다른 모델로?
- 다른 모델로 갈지 영업 방향만 바꿀지 미정

→ 0_검증계획 "위험" 표에 "임계치" 열 추가 + "반증 시 분기" 섹션.

#### 4. 사용자 vs Claude 작업 구분 누락

CLAUDE.md는 "사용자 직접 작업 vs Claude 작업 구분" 명시.
하지만 4개 검증 절차 파일 Step 헤더에 `[사용자]` / `[Claude]` / `[협업]` 태그 없음.

→ 각 Step 제목 옆에 태그 추가 (약 30개 Step × 10초 = 5분 작업).

예시:
```
## Step 1 [사용자] — Karpathy 원본 코드 다운로드
## Step 2 [협업] — PC 직접 실행
## Step 3 [Claude] — 모델 파라미터 분석
```

#### 5. Phase 1B 위치 모호

- 매트릭스 B = `microGPT/01_검증절차.md` Step 4 (포팅 가능성 분석)
- README 진행 상태 표에는 "microGPT 직접 실행" 한 행만 있음
- Step 4를 같이 하는지 별도인지 표에서 안 보임

→ README 진행 상태 표를 Step 단위로 세분화 또는 1A·1B 행 분리.

#### 6. 새 가설 추가 규칙 없음

CLAUDE.md "다음 검증 추천해줘 → 가설 1~2개 제시" 가이드 있음.
하지만 매트릭스 A~G는 고정. 새 가설(예: ESP32-P4 비교, 도메인 fine-tuning)을 어디에 넣을지 미정.

- `microGPT/02_xxx.md`?
- `통합검증/03_xxx.md`?
- 매트릭스 H, I 추가?

→ CLAUDE.md "파일 명명" 섹션에 "신규 가설 = 같은 폴더 내 02·03 prefix" 규칙 명시.
