## 이 계획서의 목적

영상의학 병원을 인수한다는 것은 단순히 시설과 장비를 사는 것이 아닙니다.
**"의료 데이터를 국제 표준으로 관리하는 시스템"**을 갖추면, 다음과 같은 이점이 생깁니다:

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                       │
│  병원 인수만 한 경우:                                                │
│    → 기존처럼 운영, 차별화 없음                                     │
│                                                                       │
│  SNOMED CT 시스템을 갖춘 경우:                                        │
│    → AI 진단 도입 가능 (Lunit, Vuno 등)                              │
│    → 다른 병원과 데이터 호환 (전원, 협진)                            │
│    → 보험 청구 자동화 (ICD-10 자동 변환)                             │
│    → 의료 데이터 자산화 (연구, 2차 활용)                             │
│    → 해외 환자 유치 (글로벌 표준)                                    │
│    → 향후 추가 병원 인수 시 시스템 통합 용이                         │
│                                                                       │
│  ★ 한 마디로: "데이터가 돈이 되는 병원"을 만드는 것                  │
│                                                                       │
└─────────────────────────────────────────────────────────────────────┘
```

## 1. SNOMED CT를 도입해야 하는 이유

### 1.1 현재 대부분 영상의학 병원의 문제

현재 대부분의 영상의학 병원은 판독 결과를 **자유 텍스트(자연어)**로만 기록합니다.

```
[현재 상황 — 비표준]

  전문의가 X-ray를 보고 판독문을 씁니다:
  "Chest PA에서 좌측 하엽에 consolidation 소견 있으며,
   폐렴 의심됩니다. 심비대 소견은 없습니다."

  문제점:
  ├── 이 텍스트는 컴퓨터가 이해할 수 없음
  ├── 다른 병원과 데이터 호환 불가
  ├── "consolidation"을 다른 의사는 "경화"로 쓸 수 있음 → 용어 불일치
  ├── AI 분석에 활용 불가
  ├── 통계 산출 불가 ("이번 달 폐렴 환자가 몇 명?")
  └── 보험 청구 시 ICD-10 코드를 수동으로 별도 입력
```

### 1.2 SNOMED CT를 도입하면 바뀌는 것

```
[SNOMED CT 도입 후 — 표준화]

  전문의가 판독문을 쓰면, 시스템이 자동으로 코드를 부여합니다:

  판독문: "좌측 하엽에 폐렴 소견"
      ↓ 자동 변환
  ┌──────────────────────────────────────────────┐
  │  소견:     233604007 | Pneumonia              │
  │  위치:     41224006  | Lower lobe of left lung │
  │  확실성:   415684004 | Suspected              │
  │  검사방법: 399208008 | Plain chest X-ray       │
  └──────────────────────────────────────────────┘
      ↓ 자동
  ├── EHR(전자건강기록)에 구조화 저장
  ├── DICOM SR(구조화 보고서) 자동 생성
  ├── ICD-10: J18.1 자동 매핑 → 보험 청구 자동화
  ├── CDS: "폐렴 의심 → 추가 검사 권고" 자동 표시
  ├── 통계: "이번 달 좌측 폐렴 의심 32건" 자동 집계
  └── 다른 병원에 전원 시 코드만 전송하면 완벽 이해
```

### 1.3 왜 지금 해야 하는가?

| 근거 | 상세 |
|------|------|
| **한국 SNOMED CT 가입** | 2020년 SNOMED International 회원국 가입 → **무료 라이선스 사용 가능** |
| **디지털의료제품법** | 2025년 1월 시행 → AI 의료기기 규제 프레임워크 마련 → 표준화 필수 |
| **AI 의료 시장 성장** | 2025년 $29억 → 2033년 $86억 (CAGR 14.2%) |
| **경쟁사 미진출** | 한국에서 판독문 SNOMED CT 자동 변환 특화 솔루션은 아직 없음 |
| **원격판독 시장** | 원격판독센터 증가 (연세포커스의원 등) → 표준화 수요 급증 |
| **선점 효과** | 지금 시스템을 갖추면, 추후 추가 병원 인수/확장 시 즉시 통합 가능 |

## 2. 인수 전 확인해야 할 사항

병원 인수 전, 현재 시스템 상태를 정확히 파악해야 합니다.

### 2.1 IT 인프라 현황 체크리스트

| 확인 항목 | 확인 내용 | 왜 중요한가 |
|----------|----------|------------|
| **PACS 시스템** | 어떤 PACS를 사용하는가? (인피니트, 마로뷰 등) | SNOMED CT / AI 연동 가능 여부 결정 |
| **EMR 시스템** | 어떤 EMR을 사용하는가? (유비케어, 비트컴퓨터 등) | HL7 FHIR 지원 여부, 코드 체계 확장 가능 여부 |
| **DICOM 버전** | 3.0 이상인가? DICOM SR을 지원하는가? | 구조화 보고서 생성을 위해 필수 |
| **네트워크** | 내부 네트워크 속도/보안 수준 | AI 모델 추론, 클라우드 연동에 필요 |
| **서버 인프라** | 온프레미스/클라우드 여부, GPU 보유 여부 | AI 모델 배포 방식 결정 |
| **데이터 백업** | 기존 판독 데이터 보관 기간/용량 | 학습 데이터 활용 가능 여부 |

### 2.2 데이터 현황 체크리스트

| 확인 항목 | 확인 내용 | 왜 중요한가 |
|----------|----------|------------|
| **기존 판독문** | 판독문이 몇 건 있는가? (최소 1,000건 이상 필요) | AI 학습/코딩 시스템 학습용 데이터 |
| **코드 체계** | 현재 어떤 코드를 쓰는가? (ICD-10만? 자체 코드?) | SNOMED CT 전환 범위 결정 |
| **판독 양식** | 판독문 형식이 통일되어 있는가? | 자동 코딩 정확도에 직접 영향 |
| **약어 목록** | 기관 내 사용 약어 목록이 있는가? | NER 모델 커스텀 사전에 필수 |
| **촬영 장비** | X-ray 장비 종류/수량 | AI 모델의 장비별 편향(bias) 확인 |

### 2.3 인력 현황 체크리스트

| 확인 항목 | 확인 내용 | 왜 중요한가 |
|----------|----------|------------|
| **영상의학 전문의** | 인원, 경력, 전문 분야 | AI 검증, 코드 리뷰, 어노테이션 참여 |
| **IT 인력** | EMR/PACS 관리 인력 유무 | 시스템 도입 주체 |
| **행정 인력** | 보험 청구 담당자 | ICD-10 자동 변환으로 업무 변화 |
| **판독 업무량** | 일/월 판독 건수 | 시스템 규모 설계, ROI 계산에 필수 |

## 4. Phase 1: 기반 구축

**기간**: 인수 후 1~3개월
**목표**: SNOMED CT 사용 환경을 마련하고, 기존 시스템을 진단하여 확장 준비

### 4.1 SNOMED CT 라이선스 취득

| 단계 | 작업 내용 | 상세 |
|------|----------|------|
| 1 | K-HIS(한국보건의료정보원)에 Affiliate License 신청 | 한국은 2020년 SNOMED International 회원국 → **무료** 라이선스 |
| 2 | SNOMED CT 국제판 데이터 다운로드 | RF2(Release Format 2) 형태의 데이터 파일 확보 |
| 3 | SNOMED CT 한국어 에디션 확인 | 한국어 번역된 서술(Description)이 있는 부분 확인 |
| 4 | Global Patient Set(GPS) 추가 확보 | 무료 서브셋으로 어디서든 사용 가능한 기본 코드셋 |

**왜 해야 하는가**: SNOMED CT는 라이선스 없이 사용하면 법적 문제가 됩니다. 다만 한국은 회원국이므로 무료로 취득 가능합니다. 이 라이선스가 모든 후속 작업의 법적 기반입니다.

### 4.2 PACS/EMR 확장성 평가

```
현재 PACS/EMR 시스템을 다음 기준으로 평가합니다:

  [필수 요건]
  ├── DICOM 3.0 지원 여부                    → SR(Structured Report) 저장 가능?
  ├── DICOM SR 뷰어 내장 여부                → AI 결과를 PACS에서 열람 가능?
  ├── API/플러그인 확장 가능 여부             → 외부 AI/코딩 시스템 연동 가능?
  ├── HL7 FHIR R4 지원 여부                  → 다른 병원/시스템과 데이터 교환?
  └── 코드 체계 커스텀 필드 지원             → SNOMED CT 코드를 저장할 필드?

  [평가 결과에 따른 판단]
  ├── 모두 지원 → 기존 시스템에 확장 모듈만 추가
  ├── 일부 미지원 → 해당 모듈 업그레이드 또는 미들웨어 도입
  └── 대부분 미지원 → PACS/EMR 교체 검토 (비용 대비 판단)
```

### 4.3 SNOMED CT 데이터베이스 구축

| 작업 | 상세 | 산출물 |
|------|------|--------|
| SNOMED CT RF2 데이터를 PostgreSQL에 적재 | 개념(Concept), 서술(Description), 관계(Relationship) 테이블 | 검색 가능한 SNOMED CT DB |
| 계층 구조 인덱싱 | IS-A 관계를 재귀적으로 펼쳐서 "상위 코드 검색 시 하위 코드 포함" 구현 | 계층 검색 API |
| 한국어/영어 이중 검색 | "폐렴"으로 검색해도, "Pneumonia"로 검색해도 233604007을 반환 | 다국어 검색 인터페이스 |

**왜 해야 하는가**: SNOMED CT는 35만+ 개의 개념을 포함한 거대한 체계입니다. 이것을 데이터베이스로 구축해 놓아야 이후 매핑, 검색, AI 연동 등 모든 작업의 기초가 됩니다.

### 4.4 핵심 인력 확보/교육

| 역할 | 필요 인원 | 업무 내용 |
|------|:---------:|----------|
| SNOMED CT 전문가 | 1명 | 온톨로지 구조 이해, 코드 매핑 감독, 품질 관리 |
| 의료정보 엔지니어 | 1~2명 | DB 구축, PACS/EMR 연동 개발, API 개발 |
| 영상의학 전문의 자문 | 기존 인력 활용 | 코드 매핑 검증, 판독 양식 설계 참여 |

## 5. Phase 2: 데이터 표준화

**기간**: 3~6개월
**목표**: 기존 데이터를 정리하고, SNOMED CT 기반의 표준 판독 체계를 수립

### 5.1 영상의학 핵심 SNOMED CT 코드 서브셋 구축

병원에서 다루는 질환에 해당하는 SNOMED CT 코드를 선별하여 "우리 병원 전용 서브셋"을 만듭니다.

**왜 해야 하는가**: SNOMED CT는 35만+ 개의 코드가 있지만, 영상의학 병원에서 실제로 사용하는 코드는 수백 개 수준입니다. 전체를 다루면 혼란만 가중되므로, **핵심 코드만 추출**하여 사용합니다.

### 5.2 표준 판독 양식(Template) 설계

**왜 해야 하는가**: 자유 텍스트 판독문은 의사마다 표현이 달라 자동 코딩이 어렵습니다. **반구조화된 템플릿**을 도입하면 자동 코딩 정확도가 크게 향상됩니다.

```
[기존 — 자유 텍스트]

  "Chest PA에서 좌하엽에 consolidation 보이며 pneumonia r/o.
   심장 크기 정상. Pleural effusion (-). 기타 특이소견 없음."

  → 의사마다 표현 상이, 약어 혼용, 구조화 불가

[개선 — 반구조화 템플릿]

  ┌─────────────────────────────────────────────────────┐
  │  검사종류: [Chest PA / Chest AP / Lateral]           │
  │                                                       │
  │  소견 1:                                              │
  │    질환/소견: [드롭다운: 폐렴 / 기흉 / 흉막삼출 ...] │
  │    위치:     [드롭다운: 좌상엽 / 좌하엽 / 우상엽 ...]│
  │    확실성:   [확정 / 의심 / 가능성 있음]              │
  │    심각도:   [경증 / 중등도 / 중증]                   │
  │    비고:     [자유 텍스트 — 추가 기술]                │
  │                                                       │
  │  소견 2: (추가 시)                                    │
  │    ...                                                │
  │                                                       │
  │  종합 소견: [자유 텍스트]                              │
  │  권고 사항: [추가 검사 / 경과 관찰 / 응급 조치]       │
  └─────────────────────────────────────────────────────┘

  → 드롭다운 선택 시 SNOMED CT 코드가 자동 매핑
  → 자유 텍스트 영역도 유지 → 의사의 상세 기술 보장
  → AI 자동 코딩 정확도 대폭 향상
```

### 5.3 ICD-10 ↔ SNOMED CT 크로스매핑 테이블 구축

**왜 해야 하는가**: 보험 청구는 ICD-10을 사용합니다. SNOMED CT로 코딩된 진단을 ICD-10으로 자동 변환해야 보험 청구를 자동화할 수 있습니다.

| SNOMED CT Code | SNOMED CT 명칭 | → | ICD-10 | ICD-10 명칭 |
|:-:|---|:-:|:-:|---|
| 233604007 | Pneumonia | → | J18.9 | 폐렴, 상세불명 |
| 233607000 | Bacterial pneumonia | → | J15.9 | 세균성 폐렴 |
| 75570004 | Viral pneumonia | → | J12.9 | 바이러스성 폐렴 |
| 36118008 | Pneumothorax | → | J93.9 | 기흉 |
| 8186001 | Cardiomegaly | → | I51.7 | 심비대 |
| 60046008 | Pleural effusion | → | J90 | 흉막삼출 |
| 840539006 | COVID-19 | → | U07.1 | COVID-19 확인 |

> **주의**: SNOMED CT → ICD-10 변환 시 정보가 손실될 수 있습니다 (위치, 심각도 정보 등). 진료 기록에는 SNOMED CT를 유지하고, 보험 청구용으로만 ICD-10을 자동 생성합니다.

| 작업 | 목적 | 방법 |
|------|------|------|

| 질환 빈도 분석 | 핵심 코드 서브셋 우선순위 결정 | 진단명별 건수 집계 |

## 6. Phase 3: AI 진단 시스템 도입

**기간**: 6~10개월
**목표**: X-ray AI 진단 보조 시스템을 도입하고 SNOMED CT 코드로 결과를 출력

### 6.1 AI 제품 선택 가이드

**왜 해야 하는가**: 직접 AI를 개발하는 것은 비현실적입니다(학습 데이터 수만 장, 임상 검증 수년 소요). 이미 식약처/FDA 승인을 받은 상용 제품을 도입하는 것이 합리적입니다.

| 제품 | 기업 | 대상 | 특장점 | 인허가 |
|------|------|------|--------|--------|
| **INSIGHT CXR** | Lunit (한국) | 흉부 X-ray | AUC 0.93, 10종+ 질환 감지, 글로벌 3,000+ 도입 | FDA, CE, 식약처 |
| **Med-Chest X-ray** | VUNO (한국) | 흉부 X-ray | 다중 질환 분류 | FDA, 식약처 |
| **AVIEW** | Coreline Soft (한국) | 폐질환 종합 | FDA 11건 (국내 최다) | FDA, CE, 식약처 |
| **qXR-Detect** | Qure.ai (인도) | 흉부 X-ray | 26개 소견 감지 | FDA 9건 |

**권장**: 한국 병원이므로 **Lunit INSIGHT CXR** 또는 **VUNO** 도입 우선 검토 (한국어 지원, 식약처 승인, 기술 지원 용이)

### 6.2 AI 결과 → SNOMED CT 변환 파이프라인

AI 제품이 출력하는 결과를 SNOMED CT 코드로 자동 변환하는 파이프라인을 구축합니다.

```
[AI 출력 → SNOMED CT 변환 흐름]

  X-ray 촬영 (DICOM)
       │
       ▼
  PACS에 저장
       │
       ▼
  AI 모델 추론 (<1초)
  ├── 질환: "Pneumonia" (확률 92%)
  ├── 위치: 좌하엽 (바운딩 박스 좌표)
  └── 히트맵: Grad-CAM 이미지
       │
       ▼
  SNOMED CT 매핑 엔진 (자동)
  ├── "Pneumonia"      → 233604007
  ├── 좌하엽 좌표      → 41224006 (Lower lobe of left lung)
  ├── 확률 92%         → 410605003 (Definite, ≥90%)
  └── 검사방법         → 399208008 (Plain chest X-ray)
       │
       ▼
  구조화 결과 생성
  ├── DICOM SR (구조화 보고서) → PACS에 저장
  ├── HL7 FHIR Observation → EMR에 전송
  └── ICD-10 자동 매핑 → 보험 청구 코드
       │
       ▼
  전문의 최종 확인 (Human-in-the-Loop)
  └── 승인 / 수정 / 추가 소견 기입
```

### 6.3 AI 확률 → SNOMED CT 확실성 코드 매핑 기준

| AI 확률 | SNOMED CT 확실성 | 코드 | 임상 의미 |
|:-------:|:----------------:|:-:|---|
| ≥ 90% | 확정 (Definite) | 410605003 | 거의 확실, 추가 확인 권장 |
| 70~89% | 가능성 높음 (Probable) | 2931005 | 높은 가능성, 추가 검사 권고 |
| 50~69% | 의심 (Suspected) | 415684004 | 가능성 있음, 감별 진단 필요 |
| 30~49% | 가능성 있음 (Possible) | 60022001 | 낮은 가능성, 주의 관찰 |
| < 30% | 배제 가능 (Unlikely) | 261665006 | 해당 질환은 아닐 가능성 높음 |

## 7. Phase 4: 판독문 자동 코딩 시스템

**기간**: 10~14개월
**목표**: 전문의가 작성한 판독문(자유 텍스트)을 AI가 읽어 SNOMED CT 코드를 자동 추천

### 7.1 기술 구현 방식

```
[3단계 파이프라인]

  판독문: "S8에 2.3cm 크기의 HCC 의심 소견"
       │
       ▼
  1단계: NER (개체명 인식)
  ├── S8         → 부위 (Body Site)
  ├── 2.3cm      → 수치 (Measurement)
  ├── HCC        → 진단 (Diagnosis)
  └── 의심       → 확실성 (Certainty)
       │
       ▼
  2단계: Entity Linking (SNOMED CT 매핑)
  ├── "HCC" → 벡터 유사도 검색 → 254707005 (Hepatocellular carcinoma)
  ├── "S8"  → 간 해부학 코드 → Segment VIII of liver
  └── "의심" → 415684004 (Suspected)
       │
       ▼
  3단계: Ontology 검증
  ├── 위치: "간(Liver)" + 진단: "간세포암" → 논리적 일관성 ✅
  ├── (만약 위치: "간" + 진단: "충수염" → 논리적 모순 → 차단 ❌)
  └── 신뢰도 스코어 부여 → 고신뢰: 자동 코딩 / 저신뢰: 사람 검토
```

### 7.2 기술 스택

| 구성요소 | 추천 기술 | 역할 |
|----------|----------|------|
| NER 엔진 | KoBERT + 의학 Fine-tuning | 한국어 판독문에서 개체명 추출 |
| Entity Linker | SapBERT + FAISS 벡터 검색 | SNOMED CT 코드 매핑 (F1 0.871) |
| LLM RAG | GPT-4o 또는 Claude API + SNOMED CT 벡터 DB | 유효 매칭 96.2% |
| 온톨로지 검증 | SNOMED CT IS-A 관계 그래프 | 논리적 모순 차단 |
| 리뷰 UI | React 웹 인터페이스 | 코드 추천 → 전문의 승인/수정 |
| 피드백 루프 | MLflow + 재학습 파이프라인 | 전문의 수정 내역으로 모델 개선 |

### 7.3 도입 전략: 점진적 범위 확장

```
[범위 확장 순서]

  Step 1: 흉부(Chest) 질환 → 가장 판독 건수가 많은 분야
     ↓
  Step 2: 근골격계(MSK) → 골절, 관절 질환
     ↓
  Step 3: 복부(Abdomen) → 간, 담도, 신장
     ↓
  Step 4: 두경부(Head & Neck) → 뇌, 부비동
     ↓
  Step 5: 유방(Breast) → Mammography

  ★ 좁은 범위에서 높은 정확도를 달성한 후 점진 확장하는 것이 핵심 전략
```

## 13. 핵심 요약 — 의사결정자를 위한 1페이지

### 한 줄 요약

> **SNOMED CT 국제 표준을 기반으로 영상의학 병원의 데이터를 체계화하면, "판독만 하는 병원"에서 "데이터가 돈이 되는 디지털 병원"으로 전환할 수 있다.**

### 핵심 의사결정 사항

| 질문 | 답변 |
|------|------|
| **꼭 SNOMED CT여야 하는가?** | 그렇다. SNOMED CT는 전 세계 40개국이 사용하는 유일한 임상 용어 표준이며, 한국도 2020년 가입. AI 의료기기, HL7 FHIR 모두 SNOMED CT를 기준으로 한다. |
| **비용은 얼마나 드는가?** | 18개월간 약 2~3.5억원. 라이선스는 무료. 주요 비용은 개발 인건비와 AI 제품 라이선스. |
| **언제부터 효과가 나는가?** | Phase 2(6개월) 완료 시 보험 청구 자동화 효과 발생. Phase 3(10개월) 완료 시 AI 판독 보조 시작. |
| **의사들이 받아들이는가?** | Human-in-the-Loop(의사가 최종 결정) 원칙 유지. 업무를 대체하는 것이 아니라 **보조하는 것**임을 명확히. |
| **위험은 없는가?** | 판독문 자동 코딩은 "코딩 보조 도구"로 의료기기 규제 대상이 아님. X-ray AI는 식약처 승인 제품 사용. |

### 실행 우선순위

```
[즉시 착수]
  ├── SNOMED CT Affiliate License 신청 (무료, 1~2주)
  ├── 인수 대상 병원 PACS/EMR 기술 실사 (Due Diligence)
  └── 의료정보 엔지니어 채용/외주 탐색

[인수 후 3개월 내]
  ├── SNOMED CT DB 구축
  ├── 핵심 코드 서브셋(흉부 질환) 선정
  └── 판독 양식 표준화 시작

[6개월 내]
  ├── ICD-10 ↔ SNOMED CT 매핑 테이블 완성
  ├── X-ray AI 제품 도입 (Lunit 또는 VUNO)
  └── 보험 청구 자동화 시작 → 첫 번째 ROI 발생

[12개월 내]
  ├── 판독문 자동 코딩 MVP 운영
  └── HL7 FHIR 기반 외부 연동 시작
```
