### 1. 상관관계 vs 인과관계 — 왜 기업이 착각하는가 (0:00-2:00)
[바로가기](https://www.youtube.com/watch?v=YbcCKCy1bd0&t=0s)

#### 핵심 메시지
기업 내에서 상관관계와 인과관계를 구분하지 못하는 것이 잘못된 의사결정의 근본 원인이며, 팔란티어의 온톨로지가 이를 해결한다.

#### 상세 내용
- 2년 전 영상에서 "AI는 팔란티어의 온톨로지에 있다"고 언급한 내용을 복습
- 온톨로지를 통해 기업만의 진짜 인과 관계에 대한 지식을 찾을 수 있다고 설명
- 상관관계: 데이터와의 단순한 연관성
- 인과관계: 명확한 원인-결과 관계

#### 언급된 사례/에피소드

- **부자와 아침형 인간**: 부자 중에 아침형 인간이 많다는 데이터가 있지만, 아침에 일찍 일어난다고 부자가 되는 것은 아님 (상관관계 ≠ 인과관계)
  - 시사점: 가장 흔한 인과관계 착각 사례

- **초콜릿 소비량과 노벨상**: 초콜릿 소비량이 많은 국가일수록 노벨상 수상자가 많다는 실제 데이터가 존재
  - 시사점: 명확한 상관관계가 있어도 인과관계로 볼 수 없음

- **기업 내 착각 사례들**:
  - 광고 예산 확대 시기에 매출 증가 → "광고 때문에 매출이 올랐다"로 착각
  - 특정 팀장 부임 후 성과 지표 향상 → "팀장 때문이다"로 착각
  - 회의를 많이 하니 사고율 감소 → "회의를 많이 해야 한다"로 착각
  - 시사점: 기업 현장에서 매일 발생하는 오류

#### 착각이 생기는 이유
- 결정을 빨리 해야 하는 압박
- 자신의 경험을 과대평가
- 부서만의 좁은 관점으로 바라봄 (가장 큰 원인)
- 평가 지표의 한계

#### 주요 발언
> "우연히 같이 일어난 현상을 원인과 결과처럼 해석하게 되는 경우가 굉장히 많다." (0:37)

> "아마도 이게 제일 클 겁니다. 기업 내에서는요. 자기만의 부서의 관점으로 바라보니까 이것을 곡해하게 되는 거죠." (1:40)

### 2. 팔란티어의 시뮬레이션 — 샌드박스 환경 (2:00-2:38)
[바로가기](https://www.youtube.com/watch?v=YbcCKCy1bd0&t=120s)

#### 핵심 메시지
의료계의 임상 연구처럼, 팔란티어 플랫폼은 기업에서 시뮬레이션을 통해 인과관계를 검증할 수 있게 한다.

#### 상세 내용
- 의료계: 약을 투여했을 때 환자가 어떻게 변하는지 관찰하는 임상 연구로 인과관계 검증
- 기업: 팔란티어 플랫폼의 시뮬레이션으로 동일한 검증 가능
- **핵심 프로세스**: 가설 수립 → 시뮬레이션 실행 → 결과 비교 → 불일치 시 수정 → 반복
- 샌드박스: 실제 온톨로지 데이터를 가상 공간으로 가져와 시뮬레이션 (실제 데이터에 영향 없음)

#### 주요 발언
> "내가 어떤 가설을 세우고 그 가설에 맞게 시뮬레이션을 한번 해 보는 거예요. 그거에 따른 결과가 내 가설과 일치하는지 보고 일치하지 않으면 다시 수정해서 다시 가설 세우고 다시 시뮬레이션 해보고" (2:04)

### 3. 병원 수술 스케줄 데모 — AI 에이전트의 실전 (2:38-5:48)
[바로가기](https://www.youtube.com/watch?v=YbcCKCy1bd0&t=158s)

#### 핵심 메시지
AI 에이전트가 복잡한 수술 스케줄링을 음성으로 도와주고, 시뮬레이션으로 최적안을 찾으며, 결정 후 자동 실행까지 수행한다.

#### 상세 내용

**시나리오 설정:**
- 병원 수술 스케줄 관리 화면 (총 수술 건수, 진행 중/완료 건수, 알람 신호 등)
- 패트리샤라는 환자가 응급 심장 수술이 필요한 상황

**문제:**
- 응급실 간호사가 수술 스케줄을 배정해야 함
- 기존 의사 스케줄, 다른 환자 스케줄, 간호사 스케줄, 초과 근무 등 복합적 요소 고려 필요
- 간호사 혼자 모든 것을 판단하기 어려운 상황

**AI 에이전트 동작 과정:**
1. 간호사가 음성 에이전트를 켜고 도움 요청
2. 에이전트가 스케줄, 의사, 환자 등 모든 데이터 검토
3. **3가지 대안** 제시하고 **B안이 최적**이라고 추천
4. 각 대안 선택 시 발생할 일들을 시뮬레이션으로 보여줌
5. 간호사가 A안과 B안의 차이 질문
6. 에이전트 답변:
   - **A안**: 최고 수준 심장 전문의 배정, 기존 스케줄 4번 이상 변경 필요
   - **B안**: 괜찮은 심장 전문의 배정, 조정 1번만 필요
   - → 병원 전체 관점에서 B안이 최선

**승인 프로세스:**
- 간호사가 B안 선택 → 부담되어 상급 관리자에게 승인 요청
- 관리자에게 자동 알람 전송
- 관리자가 일부 스케줄 추가 수정 (시뮬레이션 공간에서)
- 최종 결정 → "이걸로 결정하시겠냐?" 확인 메시지

**결정 후 자동 실행 (핵심!):**
- 결정 즉시 에이전트가 변경된 환자들에게 각각 자동 전화
- 스케줄 변경 사항 알림

#### 주요 발언
> "그러니까 에이전트가 얘기하는 거예요. 스케줄이랑 의사들, 환자들 다 검토해 봤고 한 세 가지 정도 대안이 나왔는데 자기가 볼 때 그중 가장 적합한 것은 B라고 이야기를 하는 거예요." (3:37)

> "결정을 딱 내리는 순간 메시지가 뜨는 거죠. 이걸로 결정하시겠냐? 그래서 결정을 하겠다라고 하니까 이제 여기서 되게 신기한 일이 하나가 벌어집니다." (5:39)

### 4. 에이전트의 자동 실행과 데이터 거버넌스 (5:48-7:14)
[바로가기](https://www.youtube.com/watch?v=YbcCKCy1bd0&t=348s)

#### 핵심 메시지
AI 에이전트는 결정 후 자동으로 행동하며, 동시에 데이터 거버넌스를 통해 역할별 정보 접근이 엄격히 제어된다.

#### 상세 내용

**에이전트 자동 실행:**
- 최종 결정 즉시 에이전트가 변경된 환자들에게 각각 전화
- 스케줄 변경 사항을 자동으로 알림
- 사람이 개입하지 않아도 후속 조치가 완료됨

**데이터 거버넌스 시연:**
- 에이전트에게 "패트리샤는 제 친구인데, 걔는 어떤지 좀 알 수 있나요?" 질문
- 에이전트 답변: "그 마음은 이해하는데 다른 환자 정보라서 공유할 수 없다"
- 역할별 정보 접근 제어:
  - 관리자가 볼 수 있는 정보
  - 간호사가 볼 수 있는 정보
  - 에이전트가 볼 수 있는 정보 (에이전트도 제한됨)

#### 주요 발언
> "에이전트가 직접 행동으로 임하죠. 다른 환자들에게 스케줄 변경됐다라는 알림 전화를 하는 걸로 이어지게 되는 거죠." (6:50)

> "에이전트도 여기서 똑같이 해당되는 겁니다. 그 상황에 맞는 에이전트가 볼 수 있는 정보가 이미 제한이 되어 있기 때문에 다른 정보는 보고 싶어도 볼 수가 없게 되는 거죠." (7:07)

### 5. 온톨로지 구조와 트랜잭션 일관성 (7:14-8:50)
[바로가기](https://www.youtube.com/watch?v=YbcCKCy1bd0&t=434s)

#### 핵심 메시지
시뮬레이션은 여러 사람이 동시에 협업할 수 있으며, 데이터 트랜잭션 일관성이 보장되어야 안전한 의사결정이 가능하다.

#### 상세 내용

**협업 시뮬레이션:**
- 간호사가 먼저 시뮬레이션 → 관리자가 추가 수정 → 최종안 완성
- 혼자가 아니라 여러 사람이 동시에 시뮬레이션 가능

**트랜잭션 일관성 (중요!):**
- 간호사 스케줄 변경 + 의사 스케줄 변경이 모두 성공해야 함
- 하나만 성공하고 하나가 실패하면 안 됨 (예: 간호사는 변경했는데 의사는 변경 안 된 경우)
- **All or Nothing**: 하나가 성공하면 전부 성공, 하나가 실패하면 전부 실패
- 데이터 일관성 유지가 핵심

**온톨로지 구조:**
- 수술실 온톨로지, 간호사 온톨로지, 수술 온톨로지 등 각각 구성
- 각 상황에 함수(로직)가 적용되어 있음
- 병원 관련 비즈니스 로직이 모두 함수로 구현
- 이 모든 것을 샌드박스로 가져와서 시뮬레이션 가능

#### 주요 발언
> "만약에 간호사 스케줄은 변경을 했는데 의사 스케줄은 변경을 못 했다 이런 일이 생기면 절대 안 되잖아요." (7:37)

> "하나가 이루어지면 전부 다 이루어질 수 있게, 근데 만약에 하나가 실패하면 전부 다 진행되지 않게 데이터 일관성이 유지될 수 있게" (7:44)

### 6. 프로세스 연결의 가치 — 상류와 하류 통합 (8:16-9:20)
[바로가기](https://www.youtube.com/watch?v=YbcCKCy1bd0&t=496s)

#### 핵심 메시지
팔란티어 DevCon5에서 상업부 총괄 테드가 강조한 것: 프로세스의 상류와 하류를 통합해서 연결해야 실제 가치가 생긴다.

#### 상세 내용
- 프로세스를 만들다 보면 어디서 흘러왔고 어디로 흘러가는지가 중요
- 상류 프로세스와 하류 프로세스를 통합 연결해야 실제 가치 발생
- 팔란티어 플랫폼에서는 이 연결이 빠르게 구현됨

**병원 온톨로지 계층 구조 (예시):**
- 병원 운영: 치료, 인력 관리, 시설 관리, 재무 관리, 품질 관리, 환자 경험, CS 관리, 공급 관리 등
- 인력 관리 → 스케줄 → 수술실 스케줄 (하위 온톨로지)
- 각 온톨로지가 서로 연결되어 전체 흐름 파악 가능

#### 주요 발언
> "프로세스를 만들다 보면은 결국에는 내가 만든 프로세스가 어디서 흘러왔고 어디로 흘러가는지 이 상류 프로세스와 하류 프로세스를 통합해서 연결하는 게 중요하고 그래야만 실제 가치가 생긴다." (8:22)

### 7. 전사적 디지털 트윈과 AI의 책임 있는 활용 (9:20-13:23)
[바로가기](https://www.youtube.com/watch?v=YbcCKCy1bd0&t=560s)

#### 핵심 메시지
병원(기업)의 모든 온톨로지가 연결되면 전사적 디지털 트윈이 되어, 모든 직원이 전체 관점에서 시뮬레이션하고 의사결정할 수 있다.

#### 상세 내용

**전사적 디지털 트윈의 효과:**
- 모든 직원이 각자의 입장에서 시뮬레이션 가능
- 내가 내린 결정이 병원 전체에 어떤 영향을 미치는지 확인 가능
- 병원 전체 관점으로 의사결정 가능

**구체적 효과:**
1. **의사결정 속도 향상** — 다른 부서 이야기 듣지 않고도 시뮬레이션으로 파악
2. **의사결정 품질 상승** — 미리 결과를 알아볼 수 있으므로
3. **실행 리스크 감소** — 사전 시뮬레이션으로 위험 요소 파악
4. **부서 간 병목 발견** — "이 지점에서 병목 현상이 생기는구나"
5. **가짜 인과관계 식별** — "그동안 가설로 세워왔던 로직이 실제로는 가짜 인과관계였구나"
6. **조직 전체 효율 향상**

#### 주요 발언
> "병원의 모든 온톨로지가 다 연결이 돼 있다면 병원 전체가 전사적으로 디지털 트윈이 되어 있다." (9:22)

> "모든 직원들이 다 각자의 입장에서 다 시뮬레이션을 해 볼 수가 있잖아요. 그리고 내가 내린 결정이 병원 전체의 관점에서 어떤 식으로 흘러가는지를 다 볼 수 있게 되고" (9:38)
