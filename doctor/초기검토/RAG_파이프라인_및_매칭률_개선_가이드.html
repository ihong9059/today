RAG의 정의

RAG = Retrieval-Augmented Generation (검색 증강 생성)

LLM(대규모 언어 모델)이 답변을 생성하기 전에, 외부 데이터베이스에서 관련 정보를 먼저 "검색"한 뒤, 그 정보를 "참고"하여 더 정확한 답변을 "생성"하는 기술입니다.

2

왜 RAG가 필요한가?

LLM 단독 사용의 3가지 문제

⚠️ 문제 1: 환각 (Hallucination)

LLM에게 "HCC의 SNOMED CT 코드가 뭐야?"라고 물으면, "254637999"라고 답할 수 있습니다.
이 코드는 실제로 존재하지 않습니다! LLM이 패턴을 학습해서 "그럴듯한" 번호를 지어낸 것입니다.

⚠️ 문제 2: 학습 데이터의 한계

SNOMED CT의 35만+ 코드가 모두 학습 데이터에 포함되지 않을 수 있습니다. 특히 최신 코드, 희귀 질환 코드, 한국어 에디션 코드는 LLM이 모를 가능성이 높습니다.

⚠️ 문제 3: 버전 불일치

SNOMED CT는 연 2회 업데이트됩니다. LLM의 학습 데이터는 특정 시점에 고정되어 있어, 새로 추가된 코드를 알 수 없습니다.

RAG가 이 문제들을 해결하는 방법

✅ RAG의 해결 방식

LLM의 "기억"에 의존하지 않고, 실제 SNOMED CT 데이터베이스를 "검색"하여 참고합니다.

  • 환각 방지 → 실제 DB에 있는 코드만 후보로 제시
  • 누락 방지 → DB에 35만+ 코드가 전부 있으므로 빠짐없이 검색
  • 최신 반영 → DB를 최신 버전으로 유지하면 항상 최신 코드 반영

벡터(Vector)란? — 초보자를 위한 설명

💡 벡터 = 단어의 의미를 숫자로 표현한 것

예시: "간세포암" → [0.82, 0.15, -0.34, 0.91, ...] (768개 숫자)

"HCC" → [0.80, 0.17, -0.31, 0.89, ...] ← 간세포암과 숫자 배열이 매우 비슷!

"감기" → [0.12, 0.65, 0.48, -0.22, ...] ← 간세포암과 숫자가 매우 다름

GPS 좌표처럼, 의미가 비슷한 단어들은 "의미 공간"에서 가까운 곳에 위치합니다. 컴퓨터는 이 거리를 계산하여 "비슷한 의미"를 찾습니다.

FAISS란?

FAISS = Meta(구 Facebook)가 만든 초고속 벡터 검색 엔진

35만 개의 SNOMED CT 벡터 중 입력과 가장 유사한 10개를 0.01초 만에 찾아줍니다.

비유: "간세포암"과 가장 관련 있는 책 10권을 0.01초 만에 찾아주는 초고속 사서

낮은 정확 매칭률의 5가지 원인

#원인핵심 문제비유
1SNOMED CT 과도한 세분화비슷한 코드가 너무 많음 (35만+)100종류의 비슷한 파란색 중 하나를 고르기
2판독문 모호성/약어한/영 혼용, 기관별 약어 차이방언이 섞인 문서를 표준어로 번역

4의미 유형 혼동disorder/finding/situation 구분 어려움"폐렴"이 질환인지 소견인지 병력인지

(수십 개 더) 의사 의도: 233604007 (일반 폐렴) AI 선택: 385093006 (지역사회 획득 폐렴) → 유효 ✅ / 정확 ❌

원인 2: 판독문이 모호하다

💬 같은 "의심"을 병원마다 다르게 표현

서울대: "r/o" (rule out)

삼성: "S/O" (suggestive of)

세브란스: "c/w" (consistent with)

전부 같은 "의심"인데 표현이 모두 다름 → AI 혼란

요약

Part 1 — RAG 핵심 요약

  1. 1LLM 단독은 환각(없는 코드 생성) 위험이 높다
  2. 2RAG = 먼저 DB에서 검색 + LLM이 후보 중 선택 → "교과서 보고 시험 보기"
  3. 3SNOMED CT RAG: 판독문 → NER → 벡터 검색(FAISS) → LLM(GPT-4o) → 온톨로지 검증
  4. 4성능: RAG로 유효 매칭 96.2% 달성 (LLM 단독 ~80% 대비 크게 향상)

Part 2 — 정확 매칭률 개선 핵심 요약

❌ 왜 57.6%로 낮은가?
  1. SNOMED CT 코드가 너무 많고 세분화
  2. 한국어 판독문이 모호하고 약어 불일치
  3. 1:N 매핑 (하나의 표현 → 여러 코드)
  4. 질환/소견/병력 의미 유형 혼동
  5. LLM 환각 (없는 코드 생성)
✅ 어떻게 개선하는가?
  1. 도메인 특화 (간 → 폐 순차 확장) [+10~15%p]
  2. Human-in-the-Loop (신뢰도별 분기) [최종 99%]
  3. 피드백 루프 (전문의 수정 → 재학습) [+10~15%p]
  4. 기관별 커스텀 사전 + 전이학습 [+5~8%p]
  5. 다단계 후보 재순위화 (Funnel) [+8~12%p]
