SNOMED CT가 뭔가요?

한 줄 정의

SNOMED CT = 전 세계 의사들이 같은 "언어"로 소통할 수 있게 해주는 의료 용어 번호 체계

한국어로 "폐렴", 영어로 "Pneumonia", 일본어로 "肺炎" — 같은 질환인데 표현이 다릅니다.
SNOMED CT는 이것을 233604007이라는 하나의 번호로 통일합니다.

쉬운 비유 우리가 전화번호로 사람을 특정하듯, SNOMED CT는 모든 의료 개념에 고유 전화번호를 부여합니다.
"폐렴"의 전화번호는 233604007, "심장"의 전화번호는 80891009입니다.

AI 결과 변환 과정

AI 모델이 X-ray를 분석한 결과를 SNOMED CT 표준 코드로 변환하는 6단계 과정입니다.

Stage 1
AI 모델 Raw 출력
AI가 X-ray를 분석하여 질환명, 확률, 위치(bbox)를 출력합니다.
{"label": "Pneumonia", "probability": 0.92, "bbox": [120, 200, 350, 450]}
Stage 2
라벨 → SNOMED CT 매핑
사전 정의된 매핑 테이블로 AI 라벨을 SNOMED CT 코드로 변환합니다.
"Pneumonia"→233604007Pneumonia
Stage 3
확실성/심각도 결정
AI 확률(0.92)을 SNOMED CT 확실성 코드로 변환합니다.
확률 92%→410605003Definite (≥90%)
Stage 4
위치 정보 코딩
Bounding Box 좌표를 해부학적 영역 코드로 변환합니다.
bbox [120,200,350,450]→41224006좌하엽
Stage 5
후조합 표현 생성
모든 코드를 하나의 구조화된 결과로 조합합니다.
질환: 233604007 (Pneumonia) 위치: 41224006 (좌하엽) 확실성: 410605003 (Definite) 확률: 0.92
Stage 6
출력 포맷 변환
최종 결과를 DICOM SR, HL7 FHIR, ICD-10 등 표준 포맷으로 변환합니다.
DICOM SR HL7 FHIR ICD-10 (보험)

DICOM SR 연동

DICOM SR (Structured Report)이란? 영상 판독 결과를 "구조화된 코드"로 저장하는 DICOM 표준입니다.
자유 텍스트("좌하엽에 폐렴 소견")가 아니라 SNOMED CT 코드로 기록하므로 컴퓨터가 자동으로 처리할 수 있습니다.

공개 데이터셋 ↔ SNOMED CT 매핑

왜 중요한가? AI를 학습시킬 때 사용하는 데이터셋의 라벨과, 실제 배포 시 출력하는 SNOMED CT 코드가 정확히 대응해야 합니다.
매핑이 잘못되면 "폐렴"을 "결핵"으로 코딩하는 심각한 오류가 발생할 수 있습니다.

매핑 시 주의사항

1:N 매핑
데이터셋의 "Fracture" 하나가 SNOMED CT에서는 부위별로 수십 개 코드에 대응됩니다.
의미 불일치
"Lung Opacity"는 소견(Finding)이지 진단(Disorder)이 아닙니다. 구분이 필요합니다.
위치 정보 부재
데이터셋 라벨에 좌/우/엽 정보가 없으므로, AI의 Bbox/Segmentation으로 부위를 추가 코딩해야 합니다.
버전 관리
SNOMED CT는 반기마다 업데이트됩니다. 매핑 테이블도 함께 갱신해야 합니다.

ICD-10 크로스매핑

왜 ICD-10도 필요한가? SNOMED CT는 임상 기록용이고, ICD-10은 보험 청구용입니다.
AI가 SNOMED CT로 코딩한 결과를 ICD-10으로 자동 변환하면 보험 청구가 자동화됩니다.

SNOMED CT 매핑 (핵심 부분)

# AI 라벨 → SNOMED CT 매핑 테이블 FINDING_MAP = { "Pneumonia": {"code": "233604007", "display": "Pneumonia"}, "Pneumothorax": {"code": "36118008", "display": "Pneumothorax"}, "Cardiomegaly": {"code": "8186001", "display": "Cardiomegaly"}, # ... 14개 질환 전체 } # AI 확률 → 확실성 코드 def get_certainty(probability): if probability >= 0.90: return "410605003" # Definite if probability >= 0.70: return "2931005" # Probable if probability >= 0.50: return "415684004" # Suspected return "261665006" # Unlikely # 사용 예시 ai_result = {"label": "Pneumonia", "probability": 0.92} snomed = FINDING_MAP[ai_result["label"]] certainty = get_certainty(ai_result["probability"]) print(f"질환: {snomed['code']} ({snomed['display']})") print(f"확실성: {certainty}") # 출력: # 질환: 233604007 (Pneumonia) # 확실성: 410605003 (Definite)

FHIR 보고서 생성 (핵심 부분)

# SNOMED CT 결과를 FHIR JSON으로 변환 fhir_observation = { "resourceType": "Observation", "code": { "coding": [{ "system": "http://snomed.info/sct", "code": snomed["code"], # "233604007" "display": snomed["display"] # "Pneumonia" }] }, "bodySite": { "coding": [{ "system": "http://snomed.info/sct", "code": "41224006", # 좌하엽 "display": "Lower lobe of left lung" }] } } # → 이 JSON을 FHIR 서버에 POST하면 의료 시스템에 자동 등록

구축 로드맵

X-ray AI 시스템에 SNOMED CT를 적용하는 4단계 로드맵입니다.

Phase 1
즉시 적용
2주
  • 라벨 ↔ SNOMED CT 매핑 테이블 작성
  • 확률 → 확실성 코드 규칙 정의
  • ICD-10 크로스매핑 확보
Phase 2
단기 개발
1~2개월
  • SNOMED CT 매핑 모듈 개발
  • FHIR 보고서 생성 모듈
  • 규칙 기반 위치 매핑
Phase 3
중기 통합
3~6개월
  • DICOM SR 출력 모듈
  • PACS 연동 테스트
  • AI 기반 정밀 위치 매핑
Phase 4
장기 인증
6~12개월
  • IHE 상호운용성 인증
  • 식약처/FDA 허가 서류 반영
  • 버전 자동 업데이트 체계
