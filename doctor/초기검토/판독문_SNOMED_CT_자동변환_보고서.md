## 1. Executive Summary

**결론: AI를 활용한 판독문 → SNOMED CT 자동 변환은 기술적으로 가능하며, 이미 글로벌 시장에서 상용화가 진행 중이다.**

- GPT-4 + RAG 방식으로 **96.2%의 유효 SNOMED CT 용어 매칭률** 달성 (2025년 한국 연구)
- SapBERT 기반 비지도학습으로 질환(Disorder) 카테고리에서 **F1 0.871** 달성
- 다만, **정확 매칭률(Exact Match)은 57.6%** 수준으로, **인간 검증(Human-in-the-Loop)이 여전히 필요**
- 시장 규모: AI 의료 코딩 시장 **2025년 $29억 → 2033년 $86억** (CAGR 14.2%)
- 한국은 **2020년 SNOMED International 회원국** 가입 → 무료 라이선스 사용 가능

## 2. 기술적 타당성 분석

### 2.1 가능한가? — Yes, 단 조건부

| 구분 | 현재 수준 | 비고 |
|------|----------|------|
| 개체명 인식(NER) | F1 0.90+ | BioBERT, Med7 등으로 부위/진단/수치 추출 가능 |
| SNOMED CT 매핑 | 유효 매칭 96.2% | GPT-4 + RAG 조합 시 |
| 정확 매칭(Exact Match) | 57.6% | 인간 검증 필수 영역 |
| 질환 카테고리 매핑 | F1 0.871 | SapBERT + FAISS 비지도학습 |
| 한국어 판독문 처리 | 가능 | 다국어 LLM + 한국어 의학 코퍼스 필요 |

### 2.2 핵심 기술 원리: NLP to Ontology Mapping (3단계)

```
[판독문 원문] → [1단계: NER] → [2단계: 의미적 매핑] → [3단계: 온톨로지 검증] → [SNOMED CT 코드]
```

**1단계 — 개체명 인식 (Entity Extraction)**
- 입력: "S8에 2.3cm 크기의 HCC 의심 소견"
- 출력: `S8(부위)`, `2.3cm(수치)`, `HCC(진단)`, `의심(확신도)`
- 기술: BioBERT, ClinicalBERT, Med7, SpaCy + 의학 어댑테이션

**2단계 — 의미적 유사도 매핑 (Semantic Similarity)**
- 추출된 엔티티와 SNOMED CT 사전 용어 간 **벡터 유사도** 계산
- "HCC" → `Hepatocellular carcinoma (Concept ID: 254707005)`
- 기술: SapBERT + FAISS (코사인 유사도 0.9 임계값), GPT-4o + RAG

**3단계 — 계층 구조 검증 (Ontology Reasoning)**
- SNOMED CT의 계층 구조로 **논리적 모순 차단**
- 예: 위치가 '간(Liver)'인데 '충수염' 코드 매핑 시도 → 시스템이 차단
- 기술: SNOMED CT IS-A 관계 그래프, 온톨로지 추론 엔진

### 2.3 현재 기술의 한계

| 한계 | 설명 | 대응 방안 |
|------|------|----------|
| 정확 매칭률 부족 | Exact Match 57.6% | Human-in-the-Loop 워크플로우 |
| 한국어 학습 데이터 부족 | 영어 중심 모델이 대부분 | 한국어 판독문 코퍼스 구축 필요 |
| 희귀 질환 코딩 | 드문 코드는 학습 데이터 부족 | 전문의 피드백 루프 |
| 약어/줄임말 다양성 | 기관별 약어 차이 | 기관별 커스텀 사전 구축 |

```
└──────────────────────────────┬──────────────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────────────┐
│                     API Gateway / 오케스트레이션                      │
└──┬───────────────┬───────────────┬──────────────┬───────────────────┘
   │               │               │              │
   ▼               ▼               ▼              ▼
┌──────┐    ┌───────────┐   ┌──────────┐   ┌──────────────┐
│ NER  │    │ Entity    │   │ Ontology │   │ Human-in-    │
│Engine│───▶│ Linker    │──▶│ Validator│──▶│ the-Loop     │
│      │    │(SNOMED CT)│   │          │   │ Review UI    │
└──────┘    └───────────┘   └──────────┘   └──────────────┘
   │               │               │              │
   ▼               ▼               ▼              ▼
┌──────────────────────────────────────────────────────────────────┐
│                        데이터 레이어                               │

```

### 3.2 개발 단계별 흐름

#### Phase 1: 데이터 및 기반 구축 (3~4개월)

| 단계 | 작업 내용 | 산출물 |
|------|----------|--------|
| 1-1 | SNOMED CT Affiliate License 취득 (K-HIS) | 라이선스 |
| 1-2 | SNOMED CT 한국어 에디션 데이터 확보 및 DB 구축 | SNOMED CT 검색 가능 DB |
| 1-3 | 한국어 판독문 코퍼스 수집 (협력 병원) | 익명화된 판독문 데이터셋 |
| 1-4 | 판독문 어노테이션 (영상의학 전문의 참여) | NER 학습용 라벨링 데이터 |
| 1-5 | 간(Liver) 질환군 우선 범위 정의 | HCC, LC, Fatty Liver 등 타겟 질환 목록 |

#### Phase 2: NLP 엔진 개발 (4~5개월)

| 단계 | 작업 내용 | 기술 스택 |
|------|----------|----------|
| 2-1 | 한국어 의학 NER 모델 학습 | BioBERT/KoBERT Fine-tuning |
| 2-2 | SNOMED CT Entity Linker 개발 | SapBERT + FAISS 벡터 검색 |
| 2-3 | LLM 기반 RAG 파이프라인 구축 | GPT-4o / Claude API + SNOMED CT 벡터 DB |
| 2-4 | 온톨로지 검증 로직 구현 | SNOMED CT IS-A 관계 그래프 |
| 2-5 | 신뢰도 스코어링 시스템 | 고신뢰 → 자동 코딩 / 저신뢰 → 사람 검토 |

#### Phase 3: 서비스 플랫폼 개발 (3~4개월)

| 단계 | 작업 내용 | 산출물 |
|------|----------|--------|
| 3-1 | REST API 개발 | 판독문 입력 → SNOMED CT 코드 반환 API |
| 3-2 | 리뷰 UI 개발 | 코드 추천/승인/수정 웹 인터페이스 |
| 3-3 | PACS/EMR 연동 모듈 | HL7 FHIR R4 기반 인터페이스 |
| 3-4 | 피드백 루프 구축 | 전문의 수정 사항 → 모델 재학습 파이프라인 |

#### Phase 4: 검증 및 출시 (3~4개월)

| 단계 | 작업 내용 | 산출물 |
|------|----------|--------|

| 4-4 | 상용 출시 | v1.0 |

**총 예상 개발 기간: 13~17개월**

## 4. 기술 스택 상세

### 4.1 NER (개체명 인식)

| 기술 | 특징 | 적합도 |
|------|------|--------|
| **BioBERT** | PubMed 사전학습, 의학 NER SOTA | 높음 (영어) |
| **KoBERT + 의학 Fine-tuning** | 한국어 BERT, 한국어 판독문에 최적 | 높음 (한국어) |
| **ClinicalBERT** | MIMIC-III 임상 노트 학습 | 중간 |
| **Med7** | 약물/용량/경로 등 7개 엔티티 특화 | 보조 활용 |
| **SpaCy + SciBERT** | Bi-GRU 조합으로 F1 0.90 달성 | 높음 |

### 4.2 Entity Linking (SNOMED CT 매핑)

| 기술 | 방식 | 성능 |
|------|------|------|
| **SapBERT + FAISS** | 벡터 유사도 기반 비지도학습 | F1 0.871 (질환) |
| **GPT-4o + RAG** | LLM + 검색 증강 생성 | 유효 매칭 96.2% |
| **Amazon Comprehend Medical** | AWS 관리형 서비스 (InferSNOMEDCT API) | 상용 검증 완료 |
| **MedCAT** | 자기지도학습, UMLS/SNOMED CT | 대규모 병원 검증 |

### 4.3 인프라

| 구성요소 | 추천 기술 |
|----------|----------|
| 클라우드 | AWS (Comprehend Medical 연계) 또는 GCP |
| 벡터 DB | FAISS, Pinecone, Weaviate |
| SNOMED CT DB | PostgreSQL + 계층 구조 인덱싱 |
| API | FastAPI (Python) |
| 프론트엔드 | React + 코드 리뷰 UI |

## 5. 비즈니스 모델

### 5.1 가능한 비즈니스 모델 유형

#### 모델 A: B2B SaaS — 판독 코딩 자동화 플랫폼

```
┌─────────────────────────────────────────────────┐
│              수익 모델 구조                        │
│                                                  │
│  [병원/의원] ──API 호출──▶ [코딩 플랫폼]           │
│                                                  │
│  과금 방식:                                       │
│  ├─ Per-Report: 건당 과금 (₩500~2,000/건)        │
│  ├─ 월정액: 기관 규모별 (₩50만~500만/월)          │
│  └─ Enterprise: 연간 계약 (협의)                  │
└─────────────────────────────────────────────────┘
```

**타겟 고객**: 원격판독센터 (연세포커스의원 등), 중소 병원, 건강검진센터
**핵심 가치**: 판독 후 코딩 시간 절감, 표준화된 데이터 자산 확보

#### 모델 B: 데이터 표준화 플랫폼 — 의료 데이터 거래소

```
[비정형 판독문] → [SNOMED CT 코딩] → [표준화된 구조화 데이터]
                                           │
                              ┌─────────────┼─────────────┐
                              ▼             ▼             ▼
                        [제약사 R&D]  [보험사 심사]  [AI 학습 데이터]
```

**핵심 가치**: 비정형 의료 데이터를 국제 표준으로 구조화하여 데이터의 2차 활용 가치 창출
**수익원**: 데이터 표준화 수수료 + 데이터 중개 수수료

#### 모델 C: EMR/PACS 플러그인

| 항목 | 내용 |
|------|------|
| 형태 | 기존 EMR/PACS에 플러그인으로 설치 |
| 과금 | 월정액 라이선스 (₩100만~300만/월) |
| 타겟 | 대형 병원, 종합병원 |
| 차별점 | 기존 워크플로우 변경 없이 바로 적용 |

#### 모델 D: 글로벌 원격판독 코딩 서비스

| 항목 | 내용 |
|------|------|
| 형태 | AI 코딩 + 한국 영상의학 전문의 원격판독 패키지 |
| 타겟 | 동남아, 중동 등 영상의학 전문의 부족 국가 |
| 차별점 | 판독 + 코딩 원스톱 서비스 |
| 수익원 | 건당 판독료 + 코딩 수수료 |

### 5.2 비즈니스 모델 비교 평가

**시장 기회**: 한국 시장에서 **판독문 → SNOMED CT 자동 변환**에 특화된 솔루션은 아직 없음. Lunit 등 영상 AI 기업도 이 영역에는 미진출 상태.

### 7.2 의료기기 규제 (MFDS)

| 분류 | 기준 | 규제 수준 |
|------|------|----------|

**권장**: Phase 1에서는 **"코딩 보조 도구"**로 포지셔닝하여 의료기기 규제를 회피하고, 전문의가 최종 승인하는 Human-in-the-Loop 구조 유지

## 10. 결론

### 핵심 요약

| 질문 | 답변 |
|------|------|
| **AI 자동 변환이 가능한가?** | **가능하다.** GPT-4+RAG로 96.2% 유효 매칭. 다만 완전 자동화는 아직 어렵고, Human-in-the-Loop 필수. |
| **어떤 흐름으로 Tool을 만드는가?** | NER → Entity Linking → Ontology Validation의 3단계 파이프라인. 간(Liver) 특화로 시작하여 점진 확장. |
| **어떤 비즈니스 모델이 가능한가?** | B2B SaaS (건당/월정액)로 시작 → EMR 플러그인 확장 → 데이터 표준화 플랫폼으로 성장. |

### 차별화 전략

1. **한국어 판독문 특화** — 글로벌 솔루션이 아직 커버하지 못하는 영역
2. **간(Liver) 도메인 집중** — 좁은 범위에서 높은 정확도 달성 후 확장
3. **원격판독센터 파트너십** — 연세포커스의원 등 기존 판독 인프라 활용
4. **Human-in-the-Loop** — 의료기기 규제 회피 + 정확도 보장의 이중 효과

### 핵심 성공 요인

1. **양질의 한국어 판독문 학습 데이터 확보** (대학병원/판독센터 협력)
2. **영상의학 전문의 참여** (어노테이션, 검증, 피드백)
3. **SNOMED CT 전문 인력 확보** (온톨로지/용어 전문가)
4. **규제 전략 수립** (비의료기기 포지셔닝 → 점진적 인허가)
