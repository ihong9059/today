## 0. 한 줄 요약

옵시디언은 "**로컬 마크다운 파일들의 양방향 링크 그래프**"이다. 데이터는 평생 내 손에 남고(파일 = 진실의 소스), 도구가 사라져도 자료는 남는다. 핵심 가치는 **포맷이 아니라 연결**에 있다.

> "옵시디언 회사가 망해도 OK — 마크다운 파일이 남으니까" — 구요한 (티타임즈TV)

---

## 1. 옵시디언의 본질

### 1.1 정의
- **로컬 우선(Local-first) 노트 앱**: 클라우드 없이 내 PC의 폴더가 곧 보관소(Vault)
- **마크다운(.md) 파일** 기반: 텍스트 에디터·VS Code·Claude Code로도 모두 열림
- **그래프 데이터베이스**: 노트 사이의 `[[링크]]`가 자동으로 양방향 연결을 만들어 그래프를 형성
- **플러그인 생태계**: 1,500+ 커뮤니티 플러그인 (Dataview, Templater, Excalidraw 등)

### 1.2 다른 도구와의 차이

| 도구 | 데이터 위치 | 데이터 소유 | 연결 모델 | 핵심 약점 |
|------|------------|------------|----------|----------|
| **Obsidian** | 로컬 .md 파일 | 100% 사용자 | 양방향 링크 + 그래프 | 모바일 동기화 유료 |
| **Notion** | 클라우드(자체) | 회사가 호스팅 | DB·Relation | 회사 종료 = 자료 잠김 위험 |
| **Roam Research** | 클라우드(자체) | 회사가 호스팅 | 블록 단위 양방향 | 비싸고 폐쇄적 |
| **Logseq** | 로컬(블록 기반) | 100% 사용자 | 블록 단위 양방향 | 학습 곡선 |
| **Apple Notes** | iCloud | Apple 의존 | 단순 폴더 | 마크다운 부재 |
| **OneNote** | 클라우드(MS) | MS 의존 | 단순 트리 | 검색·연결 약함 |

**선택 기준 한 줄**:
- "**평생 가져갈 자료**"는 옵시디언 → 마크다운으로 영구 소유
- "**팀과 빠르게 공유**"는 Notion → 협업·DB 강함
- 둘 다 쓰면 됨: 영구 자산은 Obsidian, 단기 협업은 Notion

### 1.3 핵심 철학 3가지

1. **데이터 영구 소유권 (Data Sovereignty)**
   - 마크다운은 30년 후에도 열림 (PDF·HTML 다음으로 표준)
   - 회사가 망하거나 가격 인상해도 내 파일은 그대로
2. **연결이 가치다 (Links Over Folders)**
   - 폴더는 **위치**, 링크는 **의미** — 같은 노트가 여러 맥락에 동시 존재 가능
   - 시간 흐름에 따라 연결이 늘어나며 **복리 효과**
3. **점진적 정리 (Just-in-Time Organization)**
   - 처음부터 완벽한 폴더 구조 = 함정
   - 일단 던지고, 자주 쓰는 것이 자연스럽게 구조를 만듦

## 2. 핵심 구성 요소

### 2.1 Vault (보관소)
- 옵시디언이 인식하는 **루트 폴더**. 이 폴더 = 하나의 두뇌
- 사용자(홍광선)의 경우: `C:\todo\today\myWiki\second-brain\` (Vault 후보)
- 한 PC에 Vault 여러 개 가능 (개인용 / 회사용 분리 등)

### 2.2 노트 (Note)
- `.md` 마크다운 파일 1개 = 1개 노트
- 파일명 = 노트 제목 (Obsidian 권장)
- 한 노트는 **하나의 개념**만 담는 것이 이상적 (Atomic Note 원칙, 제텔카스텐)

### 2.3 양방향 링크 `[[페이지명]]`
- A 노트에서 `[[B]]`라고 쓰면 B 노트의 백링크 패널에 A가 자동 등록
- **수동으로 맞물리는 작업이 0** — 한 방향만 적어도 양방향 자동 형성
- 표시 텍스트 변경: `[[B|보고 싶은 글자]]`

### 2.4 그래프 뷰 (Graph View)
- 모든 노트 = 점, 모든 링크 = 선
- 점이 굵을수록 = 링크 많은 허브 노트
- 한 점을 클릭하면 그 주변만 보는 **로컬 그래프**도 가능

### 2.5 프론트매터 (Frontmatter)
- 노트 최상단 YAML 메타데이터
- 옵시디언은 이를 자동 인식하고 Dataview·검색에 활용
```yaml
---
title: 노트 제목
type: project | entity | thought | log
created: 2026-05-06
updated: 2026-05-06
tags: [태그1, 태그2]
links: [관련페이지1, 관련페이지2]
---
```

### 2.6 태그 `#태그명`
- 본문 어디서든 `#태그`로 분류
- 링크보다 **느슨한 연결** (그룹핑 용도)
- 계층 가능: `#영업/정부지원`, `#영업/민간`

### 2.7 임베드 `![[페이지명]]`
- 다른 노트의 내용을 현재 노트에 **삽입**해서 보여줌
- 변경 시 자동 반영 (참조이지 복사 아님)
- 블록 단위 임베드: `![[페이지명#^블록ID]]`

## 3. 무엇을 입력하는가 (입력 대상)

### 핵심 원칙: "**미래의 나에게 쓸모가 있을 정보**"만

옵시디언은 **검색 엔진이 아니다**. 구글로 5초에 찾을 정보는 넣지 마라. 다음 4가지가 진짜 입력 대상:

1. **나만의 관점·해석·판단** (구글에 없음)
2. **자주 다시 보는 참조 자료** (검색보다 빠른 접근)
3. **시간 흐름에 따라 누적되는 자산** (사람·프로젝트·매출·실패)
4. **여러 노트가 만나야 의미가 생기는 단편**

### 3.1 일상 캡처 (Inbox 노트)

**대상**:
- 떠오른 생각·아이디어 (1줄~3줄도 OK)
- 회의·통화 메모
- 읽은 책·기사·영상의 발췌 인용
- 우연히 들은 사람·회사·도구 이름

**처리 원칙**:
- **속도 우선**: 형식 신경 쓰지 말고 던져넣기
- 하루치 inbox → 다음 날 또는 주말에 정리(승격·삭제·통합)
- 처리 안 된 inbox가 100개를 넘으면 정리 우선순위 상승

**예시**:
```markdown
---
type: inbox
created: 2026-05-06
---
# 2026-05-06 inbox

- 한국기계 김부장: 6/15 시연 제안서 보냈음, 회신 대기
- 영상 발췌(구요한 티타임즈): "2주 뒤에 뵙겠습니다" → 학습 어질리티 캐치프레이즈
- 아이디어: 강사양성 파일럿 모집 페이지에 myWiki 데모 영상 추가하면?
- 떠오른 단어: "데이터 영구 소유권" → Stage 0 견적서 카피 후보
```

### 3.2 학습 자료 (raw/ + 자기 요약)

**대상**:
- 책·강의·영상의 핵심 정리
- 논문·기술 문서 요약
- 강의 듣고 나서 **자기 언어로** 재구성한 노트

**처리 원칙**:
- **원본은 raw/에 보관(불변)**, 요약·해석은 별도 노트(가변)
- 요약은 **3단 구조** 권장: ① 한 줄 요약 ② 핵심 5~7개 ③ 내 사업/일에의 시사점
- "**아 그렇구나**"로 끝나면 노트가 죽음 → 반드시 "**그래서 나는?**" 문장 1줄 강제

**예시 (사용자 실제 운영)**:
```
유투브/3Blue1Brown_딥러닝_시리즈/
├── README.md (시리즈 인덱스 + 권장 시청 순서)
├── 01_Chapter1_What_is_a_Neural_Network_상세.md
├── 02_Chapter2_Gradient_Descent_상세.md
└── ... (9편)
```
→ 강사양성 파일럿 Day 5·6 콘텐츠로 **시사점 도출**까지 완료된 사례

### 3.3 프로젝트 자료

**대상**:
- 기획서·요구사항·설계 결정 로그
- 진행 상황 (주간 회고 형태)
- 산출물 링크 (PDF·외부 URL)
- 이해관계자 노트 (고객사·파트너)

**처리 원칙**:
- 프로젝트 1개 = **허브 노트 1개** (`[[프로젝트명]]`)
- 허브에서 모든 하위 자료로 링크 (`[[프로젝트명_요구사항]]`, `[[프로젝트명_설계_2026-05]]`)
- 프로젝트 종료 시 **회고 노트** 작성 → strengths/gaps에 흡수

**예시 (사용자 실제)**:
- `revita.md` (프로젝트 허브)
  - → `[[REVITA_LDO_교체_검토_2026-05-06]]`
  - → `[[REVITA_펌웨어_EN_제어_A안]]`
  - → `[[revita_고객_서울대병원]]`

### 3.4 사람·조직 엔티티

**대상**:
- **개인**: 실제 만난 사람 (고객, 파트너, 강사, 멘토)
- **조직**: 거래처·경쟁사·정부기관·교육기관
- **공인 인물**: 영상에서 자주 언급되는 영향력 있는 사람 (예: 구요한, 김문정, Karpathy)

**필수 필드**:
- 이름, 소속, 직책
- 첫 만남 (날짜·맥락)
- 관계 강도 (lead / contact / partner / customer / churned)
- 마지막 접촉 (날짜·내용)
- 관심사·강점·메모

**처리 원칙**:
- **모든 미팅·통화·이메일은 해당 엔티티 노트에 한 줄씩 누적**
- 사람 노트가 두꺼워질수록 → 다음 만남 때 맥락 풍부 → 관계 깊어짐
- 6개월 이상 미접촉 시 **잠자는 관계** 태그 → 정기 점검 대상

**예시 구조**:
```markdown
---
title: 김부장(한국기계)
type: entity
tags: [#사람/고객, #영업/현재단계]
created: 2026-04-12
updated: 2026-05-06
links: [한국기계, Stage_0_시연, 강사양성_파일럿]
---
```

### 3.5 도구·기술 엔티티

**대상**:
- 자주 쓰는 SW (Claude Code, n8n, Tailscale...)
- 학습 중인 기술 (CUDA, ESP32-S3, microGPT...)
- 미사용/보류 결정한 도구도 **판단 근거**와 함께 기록 (예: Figma 보류 사유)

**처리 원칙**:
- 단순 사용법은 X (그건 공식 문서가 잘 함)
- "**나에게 어떻게 쓰는가**", "**어떤 한계를 만났는가**", "**대체 도구는?**"이 핵심
- 가격·라이선스·계정 변경 이력도 누적

### 3.6 사고·통찰 (thoughts/)

**대상**:
- 여러 노트를 본 결과 머리에서 합성된 **새 판단**
- "A + B = 새로운 C" 형태의 인사이트
- 사업 방향 결정의 근거가 된 추론

**처리 원칙**:
- thoughts는 **정직한 1인칭**으로 (블로그 톤 X, 일기 톤 O)
- 결정의 **근거가 된 노트들에 역링크** 필수
- 6개월 후 다시 읽었을 때 "**그때 왜 그렇게 생각했는지**" 복원 가능해야 함

**예시 (사용자 실제 thoughts)**:
- `2026-04-22_사업전환-AI시대.md` — LED→AI 3대 사업 전환 근거
- `2026-04-22_wiki-운영-소감.md` — Wiki 3일차 소감, 자동화의 가치

### 3.7 로그·시간 흐름 (log.md)

**대상**:
- 위키에 무언가 들어올 때마다 **한 줄 로그** (`ingest`, `update`, `correction`, `cleanup`, `revenue`, `lost`, `market`)
- 위키를 참조하여 의사결정한 사실 (`use`)
- 사업 성과 (수주·매출·실패)

**처리 원칙**:
- log.md는 **시간 역순** (최신이 위)
- 한 항목 = `## [날짜] 분류 | 한 줄 요약` + 3~5줄 본문
- 월말/분기말에 log를 훑어보면 **무엇을 했는지** 자동으로 보임

### 3.8 외부 소스 원본 (raw/)

**대상**:
- PDF, 사진, 스캔 문서
- 다운로드한 자막·트랜스크립트
- Junction으로 다른 폴더 연결 (사용자 사례: `raw/위시캣`, `raw/작업보고서`)

**처리 원칙**:
- **불변 폴더** — 절대 편집 X
- LLM도 읽기 전용으로 취급
- 원본을 가공한 결과(요약·해석)는 raw/ 밖에 별도로 작성

### 3.9 입력하지 말아야 할 것 ❌

- 구글에 5초면 찾는 일반 지식 (예: "리액트 useEffect 사용법")
- 비밀번호·API 키·신용카드 (별도 vault 또는 1Password)
- 누군가의 사적 정보 (의료·법적 민감정보)
- 1회용 임시 메모 (영수증, 일회성 인증번호)

## 4. 어떻게 처리하는가 (처리 방법론)

### 4.1 표준 5단계: **C-O-P-C-S**

```
Capture → Organize → Process → Connect → Synthesize
(캡처)   (분류)    (가공)    (연결)    (통합)
```

#### Step 1. Capture (캡처)
- **속도 최우선**, 형식 무시
- 모든 캡처는 **inbox 노트** 또는 **데일리 노트**에
- 도구: 핸드폰 → Obsidian Mobile / 메모앱 → 주말에 옮김
- 권장 플러그인: **Quick Add**, **Templater** (단축키 1방으로 새 inbox)

#### Step 2. Organize (분류)
- 1차 분류는 **PARA** 모델
  - **P**rojects: 마감일 있는 활동 (예: 한국기계 시연 PDF)
  - **A**reas: 지속 책임 (예: 영업, 강사양성, 가족)
  - **R**esources: 참고 자료 (예: 3Blue1Brown 시리즈)
  - **A**rchive: 종료된 것 (예: 종료된 프로젝트)
- 사용자(홍광선)의 second-brain 구조는 PARA의 변형:
  - `entities/` ≈ Areas의 사람·조직·도구
  - `raw/` ≈ Resources의 원본
  - `thoughts/` ≈ Areas의 인사이트
  - `projects.md` ≈ Projects 허브

#### Step 3. Process (가공)
- 원본을 **자기 언어**로 다시 쓰기
- 핵심 추출: 해당 노트가 답하는 **질문 1개**를 적기
  - 좋은 노트: "**Claude Design 발견 시 Figma 학습 보류 결정의 근거는?**"
  - 나쁜 노트: "**Figma란?**" (구글링)
- **Atomic Notes 원칙**: 한 노트 = 한 개념. 너무 길면 분할

#### Step 4. Connect (연결)
- 가공한 노트에서 **이미 있는 노트**로 `[[링크]]`
- 새 개념이면 일단 빨간색 빈 링크로 두기 (옵시디언이 표시함) → 나중에 만들면 자동 연결
- 최소 1개 이상의 링크 — 고립 노트 금지

#### Step 5. Synthesize (통합)
- 같은 주제 노트가 5~10개 모이면 **MOC** (Map of Content) 작성
- 여러 사실이 합쳐져 새 판단이 되면 **thoughts/** 노트
- 분기마다 thoughts를 모아 **방향 판단** 페이지(예: `ai-direction.md`) 갱신

### 4.2 일·주·월 사이클

| 주기 | 활동 | 시간 |
|------|------|------|
| **매일** | inbox 캡처 + log.md 한 줄 기록 | 5~10분 |
| **매주** | inbox 처리 (승격/삭제) + 주간 회고 | 30분 |
| **매월** | thoughts 점검 + me/strengths/gaps 갱신 | 1시간 |
| **매분기** | ai-direction.md + 영업전략 재판단 | 2시간 |
| **매년** | 전체 그래프 점검 + 아카이브 | 반나절 |

### 4.3 사용자(홍광선) 운영 패턴 (실증)

이미 second-brain에 정의된 워크플로우 (`CLAUDE.md`):

1. **수집(Ingest)**: 새 정보 → 관련 페이지 통합 → log.md ingest 로그
2. **해석(Interpret)**: 재료를 던지면 Claude가 자동으로 위치 결정 + 연결
3. **활용(Use)**: 의사결정에 참조 → log.md use 로그
4. **질의(Query)**: 자신에 대해 질문 → index.md 탐색 → 종합 답변
5. **점검(Lint)**: 정원사 사이클로 고아·모순·노후 점검

이는 **이 설명서가 권장하는 C-O-P-C-S 5단계의 한국어판** 이며, 이미 잘 작동 중.

## 5. 연결 관계는 어떻게 진행하는가 (연결 구축 7가지 방법)

### 5.1 직접 링크 `[[페이지명]]`
**가장 강력한 연결**. 한 번 적으면 양방향 자동.
- A 노트에서 `[[B]]` → A의 outgoing + B의 backlink 자동
- B 노트가 없어도 작성 가능 (빈 링크) → 나중에 클릭해서 생성
- **사용 시점**: 두 개념이 직접 관련 있을 때

### 5.2 별칭 링크 `[[페이지명|표시텍스트]]`
파일명은 정식, 본문은 자연스럽게.
- `[[홍광선|UTTEC 대표]]` → 표시는 "UTTEC 대표", 클릭 시 홍광선 노트로
- **사용 시점**: 한 인물·개념이 여러 별칭으로 불릴 때

### 5.3 태그 `#태그`
**느슨한 그룹**. 링크보다 약하지만 빠르게 분류.
- `#영업/정부지원`, `#영업/민간`, `#영업/현재단계`
- 계층 태그: `#영업/정부지원/디지털배움터`
- **사용 시점**: 여러 노트를 가로지르는 카테고리

### 5.4 프론트매터 `links:` 배열
명시적 관계 선언. **Dataview로 쿼리 가능**.
```yaml
links: [강사양성_파일럿, 한국기계, Stage_0]
```
- **사용 시점**: 노트 본문에 자연스럽게 안 들어가지만 관계는 명확할 때

### 5.5 MOC (Map of Content) 허브
한 주제의 **인덱스 노트**. 다른 노트들의 모음.
```markdown
# 영업 채널 MOC

## 정부 지원 (9채널)
- [[디지털배움터]] ⭐ 1순위
- [[서울시_정보통신교육]]
- ...

## 민간 채널 (15채널)
- [[인프런]]
- [[휴넷]]
- ...
```
- **사용 시점**: 노트 5~10개 이상 같은 주제로 쌓일 때

### 5.6 임베드 `![[페이지명]]` / `![[페이지명#섹션]]` / `![[페이지명#^블록]]`
**다른 노트 내용을 가져와서 보여줌**.
- 사용자(홍광선) 적용 가능 사례:
  - `2026-05-06_작업보고서.md`에 `![[디지털배움터#Day 1 액션]]` → 보고서가 진실 소스를 자동 반영
- **사용 시점**: 한 자료를 여러 곳에서 보고 싶을 때 (복사 X, 참조 O)

### 5.7 Dataview 쿼리 (동적 연결)
플러그인. **연결을 데이터베이스처럼 쿼리**.
```dataview
TABLE 관계강도, 마지막접촉
FROM "entities"
WHERE contains(tags, "고객")
SORT 마지막접촉 DESC
```
- **사용 시점**: "현재 lead 상태인 고객 모두 보여줘", "최근 30일간 ingest된 노트" 등 자동 목록

### 5.8 연결 강도 가이드라인

| 강도 | 방법 | 예시 |
|:----:|------|------|
| 강함 | `[[직접 링크]]` | 본문에서 명시적 언급 |
| 중간 | 프론트매터 `links:` | 관련 있지만 본문에 없음 |
| 약함 | `#태그` | 같은 카테고리 |
| 동적 | Dataview | 조건부 그룹 |
| 시각적 | 임베드 | 진실 소스 1개를 여러 곳에서 |

## 6. 연결을 어떻게 파악하는가 (관계 파악 7가지 도구)

### 6.1 백링크 패널 (Backlinks)
**가장 자주 쓰는 도구**. 현재 노트를 가리키는 **모든 노트** 자동 표시.
- 단축키: `Ctrl+Shift+B` (Windows)
- 화면 우측에 항상 띄워두기 권장
- **활용**: 사람 노트 열면 그 사람과 관련된 모든 미팅·프로젝트가 자동으로 보임

### 6.2 아웃고잉 링크 패널 (Outgoing Links)
현재 노트가 **가리키는** 곳들.
- 백링크의 역방향
- 중복 표시: 본문에 여러 번 링크된 곳은 횟수 표시 → **중요도 추정 가능**

### 6.3 그래프 뷰 (Graph View) — 전역
**Vault 전체의 연결 지도**. 시각적 이해.
- 단축키: `Ctrl+G` (Windows)
- 점이 굵은 노드 = **허브 노트** (많은 곳에서 참조됨)
- 점이 외딴 노드 = **고아 노트** 후보
- 색상으로 폴더·태그별 구분 가능

**활용 시나리오**:
- "**위키가 한쪽으로 치우쳤네**" → 균형 점검
- "**한 점에 너무 많이 몰림**" → 분할 검토
- "**고립된 점들**" → 연결 보강 또는 삭제

### 6.4 로컬 그래프 (Local Graph)
**현재 노트의 N-hop 이웃**만 보기.
- 단축키: `Ctrl+Shift+G`
- 깊이(depth) 슬라이더로 1-hop, 2-hop, 3-hop 조절
- **활용**: 한 노트를 중심으로 "이게 어떤 맥락에 있는가?"를 30초 안에 파악

### 6.5 검색 (Search)
**고급 연산자** 지원:
- `tag:#영업/정부지원`
- `path:"entities/"`
- `file:(2026-05-)` (파일명 정규식)
- `line:("Stage 0" -완료)` (한 줄 안에서 함께 등장 + 제외)
- `[/실패|lost/]` (정규식 그룹)

### 6.6 Dataview 인덱스
**자동 갱신되는 표·리스트**.
```dataview
LIST
FROM "thoughts"
WHERE date(created) >= date(2026-04-01)
SORT created DESC
```
- 새 thoughts 생기면 자동으로 표에 추가됨
- 정원사가 수동으로 인덱스 갱신할 필요 X

### 6.7 정원사(Lint) 사이클
**그래프 건강 점검**:

| 점검 항목 | 도구 | 주기 |
|----------|------|------|
| 고아 노트 (링크·백링크 0) | Graph View 필터 | 월 1회 |
| 깨진 링크 (없는 페이지로 링크) | 옵시디언 자체 + Lint 플러그인 | 주 1회 |
| 미작성 빈 링크 | 빨간색으로 표시됨 | 작성 즉시 |
| 노후 노트 (`updated` 6개월+) | Dataview 쿼리 | 분기 1회 |
| 모순 노트 (서로 반대 주장) | LLM 도움 받기 | 분기 1회 |

**사용자 운영 사례**: `wiki-lint`, `wiki-clean`, `wiki-query` 스킬이 이 역할 수행 중.

### 6.8 Claude Code 연계 파악
**LLM이 그래프를 읽어서 답변하는 방식**:
- `myWiki/second-brain/CLAUDE.md`가 시스템 프롬프트 역할
- `index.md`가 1차 라우팅 (어디서 찾을지)
- `log.md`가 시간순 검색
- `entities/`가 명사형 검색
- → "**홍광선이 한국기계와 마지막에 한 일?**" 같은 자연어 질의 가능

## 7. 폴더·파일 명명 규칙

### 7.1 폴더 (사용자 second-brain 사례 인용)

```
second-brain/                # Vault 루트
├── CLAUDE.md                # AI용 시스템 프롬프트 (스키마)
├── index.md                 # 모든 페이지 1줄 요약 인덱스
├── log.md                   # 시간순 활동 로그
├── me.md / skills.md / gaps.md / strengths.md  # 자기 이해
├── ai-direction.md          # 방향 판단 프레임워크
├── entities/                # 명사형 (사람·조직·도구·프로젝트)
├── thoughts/                # 통찰·인사이트·일기
└── raw/                     # 외부 원본 (불변)
```

### 7.2 파일명 규칙
- **공백 사용 가능** (옵시디언은 공백 허용)
- 그래도 **언더스코어 또는 한글**이 안전 (Git/CLI 친화)
- 시간 순서가 중요한 노트는 **YYYY-MM-DD_** 접두사
  - `2026-05-06_사업전환_의사결정.md`
- 카테고리 prefix는 폴더로 대체 권장 (파일명에 카테고리 X)

### 7.3 노트 길이
- **너무 길면**: 분할 (3,000자 넘으면 검토)
- **너무 짧으면**: 통합 또는 inbox에 남겨두기
- 적정: 500~1,500자 (정보 1덩어리)

- **/work-start, /work-end**: 세션 단위 자동 갱신

### 8.3 Memory MCP 연계
- `myWiki/ontology/memory.json` = 옵시디언과 별개의 **그래프 DB**

- LLM이 어느 한 쪽이 비어 있어도 다른 쪽으로 fallback

### 8.4 자동 캡처 워크플로우 예시
```

  → log.md ingest 로그 추가
  → 다음 미팅 시 컨텍스트 자동 풍부
```

## 10. 안티패턴 (피해야 할 함정)

### 10.1 ❌ Folder-First 정리 강박
- 처음부터 완벽한 폴더 트리 만들고 싶어함 → 작성보다 정리에 시간 더 씀
- **해결**: 일단 던지고, 자주 쓰는 게 자연스럽게 폴더화

### 10.2 ❌ 빈 노트 양산
- 제목만 있고 내용 1줄 → 그래프 더럽힘
- **해결**: 일주일 후에도 빈 노트 = 삭제

### 10.3 ❌ 고립된 노트
- 링크·백링크 모두 0개
- **해결**: 작성 시 최소 1개 링크 강제 (Templater로 자동화)

### 10.4 ❌ Mega-note (한 노트에 모든 것)
- "프로젝트.md" 하나에 1만 자 → 검색·인용·연결 모두 망함
- **해결**: Atomic 분할

### 10.5 ❌ 백업 안 하기
- 옵시디언은 로컬 파일 = 디스크 죽으면 끝
- **해결**: Git + 외부 백업 (사용자: today 저장소 git push, myWiki도 push)

### 10.6 ❌ 모든 영상·기사 풀 텍스트 복사
- 자동 클리퍼로 무차별 저장 → 위키가 쓰레기장
- **해결**: 발췌 + 요약 + 시사점 1줄 (사용자의 /yt-summary 패턴)

### 10.7 ❌ 자기 검열로 안 쓰기
- "**이걸 적어도 되나**" 망설임 → 결국 안 씀
- **해결**: Vault는 비공개. 거칠어도 OK. 일기 톤이 자연스러움

### 10.8 ❌ 도구 바꾸기 중독
- Notion → Obsidian → Logseq → Roam → … 한 달마다 갈아탐
- **해결**: 옵시디언은 마크다운이라 어디로든 이전 가능. 일단 6개월 써봐라

## 12. 자주 묻는 질문 (FAQ)

### Q1. Notion에서 옮겨와야 하나?
- **둘 다 써라**. 영구 자산은 Obsidian, 단기 협업·DB는 Notion.
- 이전 시 Notion 내보내기 → Markdown → Obsidian Vault에 복사

### Q2. 모바일 동기화 어떻게?
- 공식 Sync (월 $4) 가장 편함
- 무료 대안: GitHub + Working Copy (iOS) / Termux (Android)
- Tailscale 활용 자체 동기화도 가능

### Q3. 한글 입력 깨짐?
- 옵시디언 자체는 UTF-8 완벽 지원
- 깨짐은 보통 OS 인코딩 또는 Git autocrlf 설정 문제

### Q4. 그래프 뷰가 너무 복잡해서 안 보임
- 1,000개 이상 노트면 자연스러운 현상
- 로컬 그래프(`Ctrl+Shift+G`)와 필터(태그·폴더) 활용
- 그래프 뷰는 **시각화 보조**일 뿐, 메인 도구는 검색·백링크

### Q5. AI(Claude Code)와 합치면 위험?
- 로컬 파일이라 옵시디언 안에서 AI가 데이터를 갖고 어디로 보내지 않음
- 단, Claude Code 같은 외부 LLM 호출 시 그 호출만큼은 외부 전송됨
- 민감 자료는 별도 vault 분리 권장

### Q6. 정원사 사이클을 자동화할 수 있나?
- 가능. 사용자(홍광선)는 이미 `/wiki-lint`, `/wiki-query`, `/wiki-clean` 스킬로 자동화 중.
- 일반인은 Dataview 쿼리만으로도 80% 커버.
