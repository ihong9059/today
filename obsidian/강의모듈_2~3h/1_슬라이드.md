## S2. PKM 5단계 진화

| 단계 | 도구 | 시기 | 정리 주체 |

## S3. 왜 옵시디언인가 — 5가지

| # | 이유 | 의미 |
|:-:|---|---|
| 1 | **로컬 우선** | 회사 망해도 내 데이터는 내 컴퓨터에 |
| 2 | **마크다운** | 어떤 도구에도 옮길 수 있는 표준 |
| 3 | **양방향 링크** | `[[문서명]]` 한 줄로 자동 백링크 |
| 4 | **그래프 뷰** | 지식의 연결을 시각화 |
| 5 | **LLM-친화 substrate** | Claude가 읽고 정리하기 좋은 구조 |

## S4. 옵시디언 구성요소

```
Vault (전체 폴더)
 ├── 노트 (.md 파일)
 ├── 폴더 (선택, 강제 아님)
 ├── 태그 (#태그)
 ├── 링크 ([[다른노트]])
 └── 그래프 뷰 (자동 생성)
```

→ 폴더보다 **태그·링크**가 더 강력. 폴더는 1차원, 태그·링크는 다차원.

---

## S5. 양방향 링크의 마법

```
[A 노트] —— [[B]] ——> [B 노트]
                       ↑
        [B의 백링크 패널]에 자동으로 A가 표시됨
```

**한 줄 작성 → 양방향 자동 연결**. 이것이 옵시디언의 핵심.

---

## S6. 4-Agent emergent 시스템

```
사용자 myWiki = 4개 행위자가 함께 만드는 emergent 시스템

  ┌──────────────────────────────────────────┐
  │  Substrate  : 옵시디언 (LLM-친화 구조)    │
  │  Schema     : CLAUDE.md (보이지 않는 규칙)│
  │  Agent      : Claude (정리·합성·인사이트)  │
  │  Director   : 사용자 (방향 결정·피드백)    │
  └──────────────────────────────────────────┘
       ↓
   "자연스러운 정리"가 자동으로 일어남
```

## S7. Claude의 묵시적 ontology

- 옵시디언은 ontology(타입 시스템)를 강제 안 함
- 그러나 Claude가 LLM 훈련 중 흡수한 묵시적 ontology로 보완
- **결과**: 형식을 안 정해도 정리된다

> 비유: 책장에 책을 막 꽂아둬도, AI 사서가 매일 정리해주는 도서관

## S13. Part 3 — 사례 2: 제조업 엔지니어 (REVITA)

**4축 분류 기준** (제품/단계/부서/컴포넌트)

```
revita/
  ├── 제품 (Tower / Link)         ← 폴더
  ├── 단계 (G1~G5 게이트)          ← 태그
  ├── 부서 (영업/구매/개발/생산)   ← 태그
  └── 컴포넌트 (LoRa/RS485/HW)    ← 링크
```

**제품만 폴더, 나머지는 태그·링크**.
