# GPU 성능의 비밀: 왜 데이터 크기가 중요한가?

## 개요

이 문서는 두 가지 예제를 통해 GPU 성능의 핵심 원리를 설명합니다.

| 예제 | 데이터 수 | 결과 |
|------|----------|------|
| `cpu_vs_gpu_10K.cu` | 1만 개 | GPU가 **더 느림** |
| `cpu_vs_gpu_50M.cu` | 5천만 개 | GPU가 **13배 빠름** |

---

## 실행 방법

```bash
cd ~/cuda/week1/code

# 1만 개 테스트 (GPU가 느린 경우)
nvcc cpu_vs_gpu_10K.cu -o cpu_vs_gpu_10K
./cpu_vs_gpu_10K

# 5천만 개 테스트 (GPU가 빠른 경우)
nvcc cpu_vs_gpu_50M.cu -o cpu_vs_gpu_50M
./cpu_vs_gpu_50M
```

---

## 테스트 결과

### 1만 개 (작은 데이터)

```
CPU 시간:         0.34 ms
GPU 전체 시간:    0.67 ms
GPU 커널만:       0.09 ms

❌ GPU가 2배 더 느림!
```

### 5천만 개 (큰 데이터)

```
CPU 시간:         1667 ms (1.7초)
GPU 전체 시간:     672 ms
GPU 커널만:        126 ms

✅ GPU 커널이 13.2배 빠름!
✅ 전체적으로도 2.5배 빠름!
```

---

## 왜 이런 차이가 발생하는가?

### GPU 사용 시 필수 단계

GPU를 사용하려면 반드시 거쳐야 하는 단계들이 있습니다:

```
┌─────────────────────────────────────────────────────────────────┐
│                        GPU 사용 과정                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   [CPU 메모리]                         [GPU 메모리]             │
│       h_a  ─────── (1) 복사 ─────────▶  d_a                    │
│       h_b  ─────── (1) 복사 ─────────▶  d_b                    │
│                                          │                      │
│                                    (2) GPU 연산                 │
│                                          │                      │
│                                          ▼                      │
│       h_c  ◀────── (3) 복사 ───────────  d_c                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

각 단계의 시간:
1. **CPU → GPU 복사**: PCIe 버스 통해 데이터 전송 (느림)
2. **GPU 연산**: 수천 개 코어가 병렬 처리 (빠름)
3. **GPU → CPU 복사**: 결과를 다시 전송 (느림)

### 1만 개일 때 - 오버헤드가 연산보다 큼

```
┌─────────────────────────────────────────────────────────┐
│  1만 개 데이터 (39 KB)                                  │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  CPU 연산:  ████ 0.34ms                                │
│                                                         │
│  GPU 과정:                                              │
│  ├─ 메모리 할당:    ██████████ 0.20ms                  │
│  ├─ CPU→GPU 복사:   ████████ 0.15ms                    │
│  ├─ GPU 연산:       █ 0.09ms  ← 실제 연산은 빠름!      │
│  └─ GPU→CPU 복사:   ██████████ 0.23ms                  │
│  ────────────────────────────                           │
│  GPU 전체:          ██████████████████████████ 0.67ms  │
│                                                         │
│  ❌ 오버헤드(0.58ms) > 절약한 시간(0.25ms)             │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**문제점**:
- GPU 커널은 0.09ms로 CPU(0.34ms)보다 빠름
- 하지만 메모리 전송에 0.58ms 소요
- **오버헤드가 이득보다 큼!**

### 5천만 개일 때 - 연산이 오버헤드를 압도

```
┌─────────────────────────────────────────────────────────┐
│  5천만 개 데이터 (190 MB)                               │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  CPU 연산:  ████████████████████████████████ 1667ms    │
│                        (1.7초 대기...)                  │
│                                                         │
│  GPU 과정:                                              │
│  ├─ 메모리 할당:    █ 50ms                             │
│  ├─ CPU→GPU 복사:   ████████ 250ms                     │
│  ├─ GPU 연산:       ███ 126ms  ← 13배 빠른 연산!       │
│  └─ GPU→CPU 복사:   ██████ 246ms                       │
│  ─────────────────────────────                          │
│  GPU 전체:          █████████████████ 672ms            │
│                                                         │
│  ✅ 절약한 시간(995ms) >> 오버헤드(546ms)              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**성공 요인**:
- CPU는 1.7초 걸림 → GPU는 0.67초
- **1초를 절약!**
- 오버헤드(메모리 전송)가 있어도 충분히 이득

## GPU가 빠른 이유

### CPU vs GPU 구조

```
┌─────────────────────────────────────────────────────────┐
│  CPU (Jetson Nano: 4코어)                               │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐                      │
│   │코어1│ │코어2│ │코어3│ │코어4│                      │
│   └─────┘ └─────┘ └─────┘ └─────┘                      │
│                                                         │
│   → 4개 작업을 동시에 처리 가능                        │
│   → 5천만 개 처리: 1250만 개씩 순차 처리               │
│                                                         │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  GPU (Jetson Nano: 128 CUDA 코어)                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   ┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐    │
│   │ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ │    │
│   └─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘    │
│   ┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐    │
│   │ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ ││ │    │
│   └─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘└─┘    │
│   ... (총 128개 코어)                                   │
│                                                         │
│   → 128개 작업을 동시에 처리 가능                      │
│   → 5천만 개 처리: 39만 개씩 순차 처리                 │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 병렬 처리 비교

5천만 개 요소를 처리할 때:

| 항목 | CPU (4코어) | GPU (128코어) |
|------|-------------|---------------|
| 동시 처리 | 4개 | 128개 |
| 반복 횟수 | 1,250만 회 | 39만 회 |
| 이론적 속도 | 1x | 32x |
| 실제 속도 | 1x | **13x** |

*실제 속도가 이론보다 낮은 이유: 메모리 대역폭, 코어 클럭 차이 등*

## 핵심 교훈

### 1. 손익분기점이 존재한다

```
         GPU 효과
            ▲
            │                    ╱
            │                  ╱
     빠름   │                ╱
            │              ╱
            │            ╱  ← 손익분기점 (약 100만 개)
     ───────┼──────────╳─────────────────▶ 데이터 수
            │        ╱│
     느림   │      ╱  │
            │    ╱    │
            │  ╱      │
            │╱        │
            │         │
            작은 데이터    큰 데이터
```

### 2. GPU 사용 판단 기준

| 상황 | GPU 사용? | 이유 |
|------|----------|------|
| 데이터 < 10만 개 | ❌ 비추천 | 오버헤드 > 이득 |
| 데이터 > 100만 개 | ✅ 추천 | 병렬 처리 효과 발휘 |
| 반복 연산 (학습 등) | ✅ 강력 추천 | 한 번 전송 후 계속 사용 |
| 단발성 작은 연산 | ❌ 비추천 | CPU가 더 효율적 |

### 3. 최적화 전략

```
┌─────────────────────────────────────────────────────────┐
│  GPU 성능 최적화 3대 원칙                               │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1️⃣  메모리 전송 최소화                                 │
│      - 데이터를 GPU에 올리면 최대한 오래 유지           │
│      - 중간 결과를 CPU로 가져오지 않기                  │
│                                                         │
│  2️⃣  충분한 데이터 확보                                 │
│      - 최소 수십만 개 이상의 데이터                     │
│      - 작은 데이터는 CPU가 더 효율적                    │
│                                                         │
│  3️⃣  연산 집약적 작업 선택                              │
│      - 단순 복사보다 복잡한 계산이 유리                 │
│      - 행렬 연산, 딥러닝, 이미지 처리 등               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 실제 응용 사례

### GPU가 효과적인 경우

| 분야 | 데이터 규모 | GPU 속도 향상 |
|------|------------|--------------|
| 딥러닝 학습 | 수백만~수억 파라미터 | 10~100x |
| 이미지 처리 | 수백만 픽셀 | 10~50x |
| 물리 시뮬레이션 | 수백만 입자 | 20~100x |
| 암호화폐 채굴 | 무한 반복 | 100x+ |

### GPU가 비효과적인 경우

| 분야 | 이유 |
|------|------|
| 웹 서버 | 작은 요청들, 순차적 처리 |
| 데이터베이스 쿼리 | 분기 처리가 많음 |
| 파일 I/O | GPU와 무관한 작업 |
