# CPU vs GPU 성능 비교 테스트

## 테스트 개요

이 테스트는 동일한 연산을 CPU와 GPU에서 수행하여 성능 차이를 측정합니다.

- **파일**: `code/cpu_vs_gpu.cu`
- **배열 크기**: 1,000만 개 (38.1 MB)
- **연산**: 각 요소에 대해 덧셈, 제곱, 제곱근 수행

## 실행 방법

```bash
cd ~/cuda/week1/code
/usr/local/cuda/bin/nvcc cpu_vs_gpu.cu -o cpu_vs_gpu
./cpu_vs_gpu
```

## 테스트 결과 (Jetson Nano)

| 측정 항목 | 시간 | 속도 향상 |
|----------|------|----------|
| **CPU** | 332.65 ms | - |
| **GPU 커널만** | 44.15 ms | **7.54x** |
| **GPU 전체** (메모리 전송 포함) | 210.69 ms | **1.58x** |

## 결과 분석

### 1. GPU 커널은 CPU보다 7.5배 빠름

GPU는 수천 개의 코어가 병렬로 작업을 수행합니다.
- CPU: 4개 코어가 순차적으로 1천만 개 요소 처리
- GPU: 128개 CUDA 코어가 동시에 처리

```
CPU:  [1][2][3][4][5][6][7][8]...  → 순차 처리
GPU:  [1,2,3,...128] [129,130,...256] ...  → 병렬 처리
```

### 2. 메모리 전송이 병목

GPU 전체 시간(210ms)이 커널 시간(44ms)보다 훨씬 긴 이유:

```
[호스트 메모리] ──복사(~80ms)──> [GPU 메모리]
                                    ↓
                              GPU 연산 (44ms)
                                    ↓
[호스트 메모리] <──복사(~80ms)── [GPU 메모리]
```

**메모리 전송 시간 ≈ 160ms** (전체의 76%)

### 3. GPU 사용이 유리한 경우

| 상황 | GPU 효과 |
|------|---------|
| 대량의 데이터 병렬 처리 | ✅ 매우 효과적 |
| 데이터를 GPU에 유지하며 반복 연산 | ✅ 매우 효과적 |
| 작은 데이터, 단순 연산 | ❌ 오히려 느림 |
| 메모리 전송이 빈번한 경우 | ⚠️ 효과 감소 |

## 핵심 교훈

### GPU 최적화의 3가지 원칙

1. **메모리 전송 최소화**
   - 데이터를 GPU에 올리면 최대한 오래 유지
   - 중간 결과를 CPU로 가져오지 않기

2. **충분한 병렬성 확보**
   - 수천~수백만 개의 작업이 있어야 GPU 효과 발휘
   - 작은 작업은 CPU가 더 빠를 수 있음

3. **연산 집약적 작업 선택**
   - 메모리 접근보다 연산이 많은 작업이 유리
   - 행렬 연산, 이미지 처리, 딥러닝 등

## 코드 구조 설명

```c
// CPU 버전 - 순차 처리
void cpu_compute(float *a, float *b, float *c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = sqrt((a[i] + b[i]) * (a[i] + b[i]));
    }
}

// GPU 버전 - 병렬 처리
__global__ void gpu_compute(float *a, float *b, float *c, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        c[idx] = sqrtf((a[idx] + b[idx]) * (a[idx] + b[idx]));
    }
}
```

### 시간 측정 방법

- **CPU 시간**: `clock_gettime()` 사용
- **GPU 커널 시간**: `cudaEvent` 사용 (정확한 GPU 타이밍)
- **GPU 전체 시간**: 메모리 복사 포함한 전체 시간
