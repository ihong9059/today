# Day 3: CUDA 개념 이해

## 1. CPU vs GPU

### 1.1 비유로 이해하기

```
┌─────────────────────────────────────────────────────┐
│                    CPU (교수님)                      │
│                                                     │
│    👨‍🏫 한 명의 천재 교수님                          │
│    - 어려운 문제도 잘 풀어요                         │
│    - 하지만 한 번에 하나씩 처리해요                   │
│                                                     │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│                    GPU (학생들)                      │
│                                                     │
│    👨‍🎓👩‍🎓👨‍🎓👩‍🎓👨‍🎓👩‍🎓👨‍🎓👩‍🎓  수백 명의 학생들           │
│    - 간단한 문제를 아주 잘 풀어요                     │
│    - 동시에 수백 개를 처리해요!                       │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 1.2 수치로 비교

| 항목 | CPU | GPU |
|------|-----|-----|
| 코어 수 | 4~16개 | 수백~수천 개 |
| 클럭 속도 | 3~5 GHz | 1~2 GHz |
| 특기 | 복잡한 작업 | 단순 반복 작업 |
| 비유 | 천재 1명 | 일반인 1000명 |

### 1.3 언제 GPU가 빠를까?

**시험지 1000장 채점하기**

```
CPU 방식: 교수님 1명이 순차적으로
┌────┐ ┌────┐ ┌────┐     ┌────┐
│ 1  │→│ 2  │→│ 3  │→...→│1000│  = 1000분
└────┘ └────┘ └────┘     └────┘

GPU 방식: 학생 1000명이 동시에
┌────┐ ┌────┐ ┌────┐     ┌────┐
│ 1  │ │ 2  │ │ 3  │ ... │1000│  = 1분!
└────┘ └────┘ └────┘     └────┘
  ↓      ↓      ↓          ↓
 동시에 처리!
```

## 2. 병렬 처리란?

### 2.1 순차 처리 vs 병렬 처리

```python
# 순차 처리 (CPU 스타일)
for i in range(1000):
    result[i] = a[i] + b[i]  # 1000번 반복

# 병렬 처리 (GPU 스타일)
# 1000개의 스레드가 동시에 실행!
result[threadId] = a[threadId] + b[threadId]
```

### 2.2 병렬 처리가 가능한 조건

1. **독립적인 작업**: 각 계산이 서로 영향을 주지 않음
2. **같은 연산 반복**: 같은 작업을 데이터만 바꿔서 반복
3. **많은 데이터**: 데이터가 많을수록 효과적

**좋은 예시:**
- 이미지의 모든 픽셀 밝기 조절
- 벡터/행렬의 모든 원소 계산
- 영상의 모든 프레임 처리

**나쁜 예시:**
- 피보나치 수열 계산 (앞의 결과가 필요)
- 파일 순차 읽기
- 조건에 따라 다른 처리

## 3. CUDA 프로그래밍 모델

### 3.1 Host와 Device

```
┌─────────────────────────────────────────┐
│                 Host (CPU)              │
│  - 프로그램 시작점                        │
│  - GPU에 일 시키기                        │
│  - 결과 받아오기                          │
└────────────────┬────────────────────────┘
                 │ 데이터 전송
                 ↓
┌─────────────────────────────────────────┐
│               Device (GPU)              │
│  - 실제 병렬 계산 수행                    │
│  - 수천 개의 스레드가 동시 실행           │
└─────────────────────────────────────────┘
```

### 3.2 Kernel (커널)

GPU에서 실행되는 함수를 **커널(Kernel)**이라고 합니다.

```c
// 일반 함수 (CPU에서 실행)
void cpuFunction() {
    // CPU 코드
}

// 커널 함수 (GPU에서 실행)
__global__ void gpuKernel() {
    // GPU 코드 - 수천 번 동시 실행!
}
```

**`__global__`** 키워드가 "이 함수는 GPU에서 실행해!"라고 알려줍니다.

### 3.3 Thread, Block, Grid

GPU의 작업 단위를 이해해봅시다.

```
┌───────────────────────────────────────────────────┐
│                    Grid (그리드)                   │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐             │
│  │  Block  │ │  Block  │ │  Block  │  ...        │
│  │   0     │ │   1     │ │   2     │             │
│  └─────────┘ └─────────┘ └─────────┘             │
│       │                                           │
│       ↓                                           │
│  ┌─────────────────────────────────┐             │
│  │           Block 0               │             │
│  │  ┌───┐ ┌───┐ ┌───┐ ┌───┐      │             │
│  │  │ T │ │ T │ │ T │ │ T │ ...  │             │
│  │  │ 0 │ │ 1 │ │ 2 │ │ 3 │      │  Thread     │
│  │  └───┘ └───┘ └───┘ └───┘      │             │
│  └─────────────────────────────────┘             │
└───────────────────────────────────────────────────┘
```

| 단위 | 설명 | 비유 |
|------|------|------|
| **Thread** | 가장 작은 실행 단위 | 학생 1명 |
| **Block** | Thread의 모임 | 반 1개 |
| **Grid** | Block의 모임 | 학교 전체 |

### 3.4 Thread 번호 알아내기

각 Thread는 자신의 번호를 알 수 있습니다:

```c
__global__ void kernel() {
    int idx = threadIdx.x;  // 블록 내 스레드 번호
    // 이 값으로 어떤 데이터를 처리할지 결정
}
```

## 4. Jetson의 특별함: Unified Memory

### 4.1 일반 GPU vs Jetson

**일반 데스크톱 GPU:**
```
CPU 메모리 ←──복사──→ GPU 메모리
(RAM)                  (VRAM)
   ↑                      ↑
  별도!                  별도!
```

**Jetson (Unified Memory):**
```
┌─────────────────────────────┐
│      공유 메모리             │
│   CPU와 GPU가 함께 사용      │
│      복사 필요 없음!         │
└─────────────────────────────┘
        ↑           ↑
       CPU         GPU
```

### 4.2 장점

1. **코드가 간단해짐**: 메모리 복사 코드 불필요
2. **메모리 절약**: 데이터 중복 저장 불필요
3. **초보자에게 쉬움**: 복잡한 메모리 관리 불필요

## 5. CUDA 프로그램 흐름

```
1. CPU에서 데이터 준비
        ↓
2. GPU 메모리 할당
        ↓
3. 데이터를 GPU로 복사 (Jetson은 생략 가능)
        ↓
4. 커널 실행 (GPU 계산)
        ↓
5. 결과를 CPU로 복사 (Jetson은 생략 가능)
        ↓
6. GPU 메모리 해제
        ↓
7. 결과 사용
```

## 6. 코드 미리보기

내일 작성할 Hello CUDA의 구조:

```c
#include <stdio.h>

// GPU에서 실행될 함수 (커널)
__global__ void helloFromGPU() {
    printf("Hello from GPU! Thread %d\n", threadIdx.x);
}

int main() {
    // CPU 코드
    printf("Hello from CPU!\n");

    // GPU 커널 호출: 1개 블록, 10개 스레드
    helloFromGPU<<<1, 10>>>();

    // GPU 작업 완료 대기
    cudaDeviceSynchronize();

    return 0;
}
```

**`<<<1, 10>>>`** = "1개 블록에서 10개 스레드로 실행해!"
