## 1. 프로젝트 개요

### 1.1 목적

생산 라인에서 볼트를 실시간으로 촬영하여 AI 기반 이미지 분석으로 **양품과 불량을 자동 선별**하는 시스템 구축

### 1.2 기대 효과

| 항목 | 현재 (수작업) | 도입 후 (AI) |
|:-----|:-------------|:-------------|
| 검사 속도 | 5~10개/분 | **60~120개/분** |
| 검사 정확도 | 95% (피로 영향) | **99%+** |
| 인건비 | 검사원 상주 | 자동화 |
| 일관성 | 검사원별 차이 | **일관된 기준** |

### 1.3 프로젝트 범위

```
[카메라 촬영] → [이미지 전처리] → [AI 분석] → [양품/불량 판정] → [선별 장치 제어]
```

## 4. 소프트웨어 구성

### 4.1 개발 환경

| 항목 | 선택 | 비고 |
|:-----|:-----|:-----|
| **언어** | Python 3.8+ | 빠른 개발, 풍부한 라이브러리 |
| **딥러닝 프레임워크** | PyTorch / TensorFlow | 모델 학습 |
| **추론 엔진** | TensorRT / ONNX Runtime | 실시간 추론 최적화 |
| **이미지 처리** | OpenCV | 전처리, 후처리 |
| **카메라 SDK** | Pylon (Basler) / Spinnaker (FLIR) | 카메라 제어 |

### 4.2 AI 모델 선택

#### 옵션 1: 이미지 분류 (Classification)

```
입력: 볼트 이미지 → 출력: 양품/불량 (2 클래스)
```

| 모델 | 정확도 | 속도 | 권장 상황 |
|:-----|:------:|:----:|:----------|
| MobileNetV3 | 높음 | 매우 빠름 | 실시간 처리 우선 |
| EfficientNet-B0 | 매우 높음 | 빠름 | 균형 |
| ResNet-50 | 매우 높음 | 보통 | 정확도 우선 |

**장점:** 간단, 빠름
**단점:** 불량 위치 파악 불가

#### 옵션 2: 객체 검출 (Object Detection)

```
입력: 볼트 이미지 → 출력: 불량 부위 위치 + 유형
```

| 모델 | 정확도 | 속도 | 권장 상황 |
|:-----|:------:|:----:|:----------|
| YOLOv8n | 높음 | 매우 빠름 | 실시간 + 위치 필요 |
| YOLOv8s | 매우 높음 | 빠름 | 균형 |
| Faster R-CNN | 최고 | 느림 | 정확도 최우선 |

**장점:** 불량 위치 및 유형 파악 가능
**단점:** 라벨링 작업 많음

#### 옵션 3: 이상 탐지 (Anomaly Detection)

```
입력: 볼트 이미지 → 출력: 정상/이상 점수
```

| 모델 | 특징 |
|:-----|:-----|
| PatchCore | 적은 학습 데이터로 가능 |
| FastFlow | 빠른 추론 |
| PaDiM | 높은 정확도 |

**장점:** 양품 데이터만으로 학습 가능
**단점:** 불량 유형 구분 어려움

### 4.3 권장 접근법

**1단계:** 이미지 분류 (MobileNetV3)로 시작
- 빠른 구현 및 검증
- 기본 성능 확인

**2단계:** 객체 검출 (YOLOv8)로 확장
- 불량 유형별 분류
- 불량 위치 시각화

### 6.1 개발 단계

```
[데이터 수집] → [라벨링] → [데이터 증강] → [모델 학습] → [검증] → [최적화] → [배포]
```

### 6.2 데이터 증강 (Data Augmentation)

| 기법 | 효과 |
|:-----|:-----|
| 회전 (±15°) | 방향 변동 대응 |
| 이동 (±10%) | 위치 변동 대응 |
| 밝기 조절 (±20%) | 조명 변동 대응 |
| 대비 조절 | 카메라 설정 변동 대응 |
| 좌우/상하 반전 | 데이터 양 2~4배 증가 |

### 6.3 학습 환경

| 환경 | 장점 | 비용 |
|:-----|:-----|:-----|
| **로컬 GPU** | 데이터 보안, 빠른 반복 | 하드웨어 비용 |
| **Google Colab** | 무료 GPU, 쉬운 접근 | 시간 제한 |
| **AWS/GCP** | 강력한 GPU, 확장성 | 사용량 기반 과금 |

### 6.4 모델 평가 지표

| 지표 | 설명 | 목표 |
|:-----|:-----|:-----|
| **정확도 (Accuracy)** | 전체 정답 비율 | 99%+ |
| **정밀도 (Precision)** | 불량 판정 중 실제 불량 | 95%+ |
| **재현율 (Recall)** | 실제 불량 중 검출 비율 | **99%+** (중요) |
| **F1 Score** | 정밀도와 재현율의 조화평균 | 97%+ |

> **핵심:** 재현율(Recall)이 가장 중요 - 불량을 양품으로 오판하면 안 됨

## 7. 시스템 통합

### 7.1 실시간 처리 파이프라인

```python
while running:
    # 1. 이미지 획득
    image = camera.capture()

    # 2. 전처리
    processed = preprocess(image)

    # 3. AI 추론
    result = model.predict(processed)

    # 4. 판정
    if result['class'] == 'defect':
        plc.reject()  # 불량 배출
        log_defect(image, result)
    else:
        plc.pass()    # 양품 통과

    # 5. 모니터링 업데이트
    dashboard.update(result)
```

### 7.2 처리 시간 목표

| 단계 | 목표 시간 | 비고 |
|:-----|----------:|:-----|
| 이미지 획득 | 10ms | 트리거 동기화 |
| 전처리 | 5ms | 리사이즈, 정규화 |
| AI 추론 | 15ms | TensorRT 최적화 |
| 판정 + 출력 | 5ms | PLC 통신 |
| **총합** | **35ms** | **28 FPS 가능** |

### 7.3 PLC 통신
