온톨로지는 **"판단의 기준을 세우기 위한 데이터 구조"** 이고, 팔란티어 파운드리는 그 위에 동적 데이터를 흘려 의사결정을 자동화하는 **기업의 운영 체제(OS)** 다. LLM의 확률 모델로는 채울 수 없는 "결정론적 구조"를 제공하며, AI 시대 기업의 핵심 인프라가 될 것이다.

### 3. 팔란티어가 빅데이터 기업과 다른 이유 (03:00-06:00)
[바로가기](https://www.youtube.com/watch?v=d_AqALJMs-U&t=180s)

#### 핵심 메시지
2003년 창업한 팔란티어는 빅데이터 기업들과 달리 **"빅데이터 + 구조화 + 자동화"**를 동시에 추구했고, 국방/재난 같은 "엄격한 의사결정"이 필요한 분야부터 시작했다.

#### 상세 내용
- 빅데이터 기업들: 데이터를 모을 줄만 알았음. 데이터 간 숨은 구조/관계/연결/맥락은 활용 못함 → 매번 사람이 수작업
- 팔란티어: 창업할 때부터 데이터 + 구조화 + 자동화를 같이 추구
- ERP/MES/SCM/PLM 등에서 데이터를 가져와 구조 속에 담고 의사결정으로 가는 미들웨어 성격
- 2003년 창업 → 23년간 자동화/구조화 프레임워크 축적
- 첫 타게팅: 국방/공공(재난) 분야 → 사람 목숨이 걸려 확률적 판단 불가
- 제품 두 가지: **고담**(국방), **파운드리**(민간 기업)

#### 언급된 사례/에피소드
- **국방의 엄격성**: "확률적으로 경우의 수를 따져 가지고 그럴싸하게 해 가지고는 안 되는 영역" → 팔란티어가 결정론적 구조를 채택한 근본 이유

#### 주요 발언
> "(빅데이터 기업들은) 데이터를 모을 줄만 알았어요. 걔네들 간의 어떤 그 데이터간에 숨어 있는 구조 관계 연결 맥락 이걸 이용하지 못했던 거죠." (03:30)

> "사람의 목숨이 왔다 갔다 할 수 있으니까. 그래서 국방 쪽을 가장 먼저 타게팅을 한 거고." (05:21)

### 5. 미래 전망 — 기업의 OS가 된다 (12:00-15:50)
[바로가기](https://www.youtube.com/watch?v=d_AqALJMs-U&t=720s)

#### 핵심 메시지
온톨로지 시스템은 5년 뒤 **"기업의 OS"**가 되고, ERP/CRM/SCM은 그 위에서 돌아가는 애플리케이션이 된다. 안 한 기업과는 거대한 격차가 벌어질 것.

#### 상세 내용
- AI 플랫폼(AIP) 추가 — 멀티모달 데이터 플랫폼(MMDP)으로 이미지/영상/음성도 처리
- 기업 OS화: ERP, CRM, SCM은 애플리케이션으로 격하
- 두 갈래 진화:
  1. 미들웨어형 OS (팔란티어처럼)
  2. 개별 솔루션에 온톨로지 기능 내장 (Salesforce 등)
- 의사결정자는 **"맞다/틀리다 판단 + 책임"**만, AI 에이전트가 LLM으로 조언
- 바이브코딩/하네스엔진 등으로 인력 구조조정 진행 중 → 온톨로지 있는 곳/없는 곳 격차 폭발

#### 주요 발언
> "온톨로지 시스템으로 구조화된 곳하고 그렇지 않은 곳하고는요. 앞으로 기업 자체 가치라든지 지속성... 엄청나게 큰 격차가 벌어질 거라 보여지고 있어요." (16:11)

> "기업의 운영 OS가 될 것이다. 오퍼레이션 시스템이 되는 거다." (17:07)

### 7. 수백억 들인 AI는 왜 뻔한 실수를 반복할까 (23:00-26:30)
[바로가기](https://www.youtube.com/watch?v=d_AqALJMs-U&t=1380s)

#### 핵심 메시지
ERP(가계부) + MES(생산 작업반장) + SCM(배송 추적기)이 다 갖춰져 있어도 **관계와 판단의 맥락이 없으면 답이 안 나온다**. 데이터는 각자 입장대로 있는데 일맥상통하지 않는 게 함정이다.

#### 상세 내용
- ERP/MES/SCM은 운영 애플리케이션 — 현황만 보여줌
- CEO가 "왜 이런 결과?" 물어도 답 안 나옴 → 어느 순간 대화 단절
- MES도 답 못 줌, 물류 쪽도 답 못 줌
- 데이터 사일로: 영업/재무/생산 담당이 같은 숫자로 다른 얘기
- 각자는 자기 입장대로 옳지만 일맥상통 X → 함정
- AI 모델 95% 정확도라도 5% 때문에 잘못된 의사결정 반복

#### 언급된 사례/에피소드
- **수백억 AI 프로젝트 실패담**: 데이터 양 충분, 예측 모델 95% 정확, 알고리즘 정교, 과적합도 OK → 그런데 판단이 잘못됨. 실제 한국 기업에서 본 사례. 외부 용역 업체로 조용히 지켜봄
- **데이터의 모순**: "데이터는 딱 그 사람 입장대로 나와 있어요. 그런데 일맥상통하지가 않아." (담당자 별로 본인 유리한 순서로 데이터 정렬)

#### 주요 발언
> "갑만 있는 거예요. 갑만." (밸류만 있고 맥락 없음) (25:43)

> "데이터는 1번부터 100번이 있는데 그거를 어떤 순서로 보여주냐 따라 가지고 거짓말은 아니지만 순서를 바꾸면 달라지거든요." (26:58)

### 8. 사일로 해결 + 책임지는 리더 (26:30-30:30)
[바로가기](https://www.youtube.com/watch?v=d_AqALJMs-U&t=1590s)

#### 핵심 메시지
온톨로지는 처음에 정의 전쟁(Definition War)으로 엄청 싸우지만, CEO가 단일 정의를 내려주면 락인(lock-in)되어 실패도 자산이 되는 시스템이 된다. AI 시대 대체되지 않는 사람은 **"책임지는 리더"**다.

#### 상세 내용
- 온톨로지 정의 단계: 비즈니스 용어/의미 정의에서 부서 간 충돌 폭발
- CEO가 단일 정의 결정 → 모두 따름
- 동적 데이터 흘러들어 → 자동 판단 → 지명된 책임자가 액션
- 잘했나 못했나 판단 → 못했어도 자산화(다음에 어떻게 할지 피드백)
- 락인 효과: "내가 더 책임지면 안 됩니까?" — 실패도 성과
- **AI 시대 대체되지 않는 핵심**: 리더 역할 (AI 에이전트들을 부리는 리더)

#### 주요 발언
> "처음에는 엄청 싸워요. 담당자들끼리." (27:48)

> "그게 바로 락인 효과예요. 한번 이렇게 구축이 되면 락인이 돼서 실패도 자산이 되는 그런 시스템이 되는 겁니다." (29:09)

> "리더의 역할을 한 사람은 리플레이스가 되지 않는다는 거죠. 대신 그 리더는 AI 에이전트들을 쓰는 거예요." (29:53)

### 9. 액션 우선 접근 + 빅데이터의 배신 (30:30-32:30)
[바로가기](https://www.youtube.com/watch?v=d_AqALJMs-U&t=1830s)

#### 핵심 메시지
팔란티어 파운드리는 데이터/시스템부터가 아니라 **"어떤 액션이 필요한가"**부터 정의하고 거기서 역으로 필요한 오브젝트/관계/속성/데이터를 끌어온다.

#### 상세 내용
- 기존 방식: 데이터부터 → 분석 → 시각화 → 의사결정
- 팔란티어 방식: **액션 → 필요한 오브젝트/관계/속성 → 데이터 역추적**
- 첫 인상이 황량했던 이유 → 시스템 위주 UI가 아니라 액션 위주
- 빅스터(연사 회사) 2026년 초 "에이전트 전문 기업"으로 사명 변경
- 빅데이터에는 "구조/관계/연결/맥락"이 빠져 있었다는 자각

#### 주요 발언
> "어떤 의사결정 판단을 받을 것이냐, 어떤 액션을 먼저 설정을 하고 거기에 액션이 필요한 오브젝트라든지 관계 속성이 무엇인 데이터를 역으로 가는 거." (30:55)

### 12. 수학과 온톨로지 3계층 (시멘틱/키네틱/다이나믹) (37:30-44:00)
[바로가기](https://www.youtube.com/watch?v=d_AqALJMs-U&t=2250s)

#### 핵심 메시지
온톨로지는 수학과 동형이다. ① **시멘틱 레이어**(수의 정의=의미) → ② **키네틱 레이어**(방정식/함수=관계) → ③ **다이나믹 레이어**(미적분=변화). 팔란티어는 이 3계층을 모두 커버한다.

#### 상세 내용
- **시멘틱 레이어 (Semantic)**: 정의(자연수/정수/실수). 의미 = 시멘틱
- **키네틱 레이어 (Kinetic)**: 관계 = 방정식/부등식/함수 (피타고라스 정리). 행위 영역
- **다이나믹 레이어 (Dynamic)**: 변화 = 미적분 (뉴턴, 16세기). 움직이는 세계의 수학적 표현
- 과거 정적 온톨로지 = 시멘틱 레이어만
- 팔란티어 = 시멘틱 + 키네틱 + 다이나믹
- 인과관계는 다이나믹 레이어 (사후 분석/피드백 루프)
- "디지털 트윈"이라 불리는 이유 = 동적 세계 표현

#### 데이터 리니지 (Data Lineage)
- 그래프 시각화는 "재미용" — 본질 X
- 본질: ERP/MES/CRM → Raw Data → Curated Data → Ontology Data 변환 추적
- 인과를 알려면 데이터 개보(데이터가 어디서 어떻게 왔는지) 추적 필수

#### 그래프 DB 저장 방식
- **RDF**: Resource Description Framework, 주술목 (정적, 느림)
- **LPG**: Labeled Property Graph (속성값 포함, 시계열에 적합)
- 팔란티어 = RDF + LPG **혼용**으로 속도 향상

#### 주요 발언
> "(피타고라스의) 그게 2000년 전에 나왔는데 16세기에 어떤 사람이 나서 야 이것만 가지고 세상을 표현할 수 있어? 그 사람이 뉴턴이잖아요. 움직이는 세계를 수학적으로 표현한 거예요. 그게 바로 우리가 어렵게 생각하는 미분과 적분인 거예요." (40:58)

- 가장 아픈 페인포인트 분야부터 (제조: 제품 추화, 수율 개선)
- 시멘틱은 5개 정도 오브젝트로 테스트 가능, 키네틱부터 막힘
- 시멘틱+키네틱만 해도 약 2년 — 충분히 의미 있음
- 다이나믹은 그 후 — 도구도 1-2년 후 더 좋아짐
- POC 기간: 약 3개월 + 데이터 표준화 통합 과정 동시
- 의사결정은 2개 이내로 한정 (생산/품질/재고 중)
- EIS/BI ≠ 온톨로지 — 현황만 보여줌, 사장님이 또 고민해야
- 온톨로지 = **고민의 내용**까지 생성

## 도입 가이드 (연사 권고)

### 시작 단계
1. **가장 비싼 의사결정 1-2개부터** (생산/품질/재고 중 택 1-2)
2. CEO 또는 최고 의사결정권자 직접 참여 — 정의 전쟁 중재
3. 외부 FDE/컨설팅 펌 활용 (초기에 내부 FDE 채용은 비효율)
4. POC 기간 약 3개월 + 데이터 표준화/통합 과정 동시 진행

### 절대 하지 말 것
- ❌ SI 방식 단순 용역으로 접근 (반드시 실패)
- ❌ LLM만으로 온톨로지 구현 시도 (할루시네이션 회피 불가)
- ❌ 의사결정 3개 이상으로 동시 확장
- ❌ 데이터부터 보기 (액션부터 보기)

### 솔루션 선택 3가지 조건
1. **LLM에만 의존하는 솔루션 X** (결정론적 구조 필수)
2. **데이터 파이프라인 + 데이터 리니지** 갖춘 솔루션
3. **작은 의사결정부터** 시작 가능한 솔루션
