# 팔란티어 파운드리 5개 레이어 심층 분석

## 문서 목적
Kelly Ontology Hub 시리즈 #0 영상에서 소개된 5층 아키텍처를 **레이어별 심층 분해** + **UTTEC 무료 대체 매핑** + **영업 메시지 도출**까지 통합한 작업 문서.

기존 [팔란티어_파운드리_5개레이어_아키텍처_상세.md](팔란티어_파운드리_5개레이어_아키텍처_상세.md)는 영상 트랜스크립트 기반 요약. 본 문서는 **각 레이어를 한 챕터씩 깊이 분석**하여 사업화 자료로 직접 활용 가능하도록 재구성.

## 한 페이지 요약

```
┌──────────────────────────────────────────────────────────────────┐
│  5층 Application (Workshop)        — 현장 작업자가 클릭 1회로 행동  │
│  4층 Analytics (Code/Quiver/AIP)   — 분석가/AI가 부품 검토         │
│  3층 ★ Ontology (Object Manager)  — 의미 부여, 디지털 트윈 본체    │
│  2층 Data Integration (Pipeline)   — 사일로 해체, 재료 수집         │
│  1층 Core Services (Inf/Auth)      — 단단한 기반 (보안·계정·모니터) │
└──────────────────────────────────────────────────────────────────┘
        ↑ 데이터가 위로 올라가며 의미를 얻음
        ↓ 액션이 아래로 내려가며 실세계에 영향(Writeback)
```

| 층 | 핵심 질문 | 결과물 |
|----|----------|--------|
| 5 | "지금 무엇을 해야 하나?" | 운영 앱 |
| 4 | "왜 이런 일이 일어나는가?" | 인사이트 |
| 3 | "이 데이터가 무엇을 의미하나?" | 디지털 트윈 |
| 2 | "어떻게 데이터를 모을까?" | 정제된 데이터셋 |
| 1 | "안전하게 어떻게 운영할까?" | 인프라 |

# 1층 ─ Core Services (코어 서비스)

## 비유
**건물의 기초·전기·수도** — 평상시엔 보이지 않지만 빠지면 무너진다.

## 정의
Foundry의 모든 상위 레이어가 공통으로 사용하는 **인프라 + 보안 + 운영** 서비스 묶음. 사용자에게는 "그냥 켜져 있는 것"으로 보이지만, 엔터프라이즈 채택의 결정 요인.

## 핵심 구성요소
| 구성요소 | 역할 |
|---------|------|
| **Authentication & Authorization** | SSO(SAML/OIDC), 부서·역할별 권한, 행/열 단위 ACL |
| **Audit & Lineage** | 누가 언제 무엇을 봤고/바꿨는지 전수 기록 |
| **Compute Orchestration** | Spark·KubeFlow·Container 자원 관리 |
| **Storage Backbone** | 다중 클라우드(Azure/AWS/GCP) 추상화, 데이터 버저닝 |
| **Networking & VPC** | 망분리, 폐쇄망 / 에어갭 모드 지원 |
| **Monitoring & Alerting** | 파이프라인·앱 헬스 체크, 운영 SLA |
| **Compliance** | FedRAMP High, IL5, GDPR, HIPAA 인증 패키지 |

## 데이터 흐름
- **상향**: 1층은 데이터를 직접 만들지 않음. 2~5층의 모든 작업이 1층의 자원·인증을 통과
- **하향**: 5층 액션은 1층 감사 로그에 기록되어 거버넌스 보장

## 시장 맥락
- 정부·국방·금융이 채택한 결정적 이유 = **이 1층의 인증 패키지**
- 동등한 1층을 무료로 구축하려면 **여러 도구 조합**이 필요 (단일 솔루션 부재)

## UTTEC 무료 대체 매핑 (95% 커버 가능)
| 영역 | 무료/저가 대체 | 커버 |
|------|---------------|------|
| 인증 | Tailscale (mesh VPN, MagicDNS, ACL) | ✅ |
| 형상관리 | Git + GitHub | ✅ |
| 컴퓨트 | Docker Compose / k3s | ✅ |
| 모니터링 | Grafana + Prometheus + Loki | ✅ |
| 감사로그 | OpenTelemetry + Loki | ⚠️ 7할 |
| 컴플라이언스 인증 | (불가 — 공인 인증 영역) | ❌ |

→ **결론**: 일반 중소기업 보안 수준은 무료로 충분히 커버. 정부/금융/국방용 컴플라이언스는 영역 외.

## UTTEC 영업 메시지
> "Foundry 1층의 95%를 Tailscale + Git + Docker + Grafana로 무료 재현. 정부·국방용 인증이 필요 없는 중소기업이라면 1/100 가격에 동일 보안·운영 수준 달성."

# 2층 ─ Data Integration (데이터 통합층)

## 비유
**공장의 수송 시스템 + 정제 라인** — 광산(원본)에서 캐온 광석(원본 데이터)을 깨끗한 합금(정제 데이터)으로 가공.

## 정의
세상에 흩어진 데이터를 **한 곳에 모으고 정제**하는 층. ETL(Extract-Transform-Load) + ELT의 진화형. 데이터 사일로 해체의 실질적 무대.

## 핵심 도구
| 도구 | 용도 |
|------|------|
| **Data Connection (Hyperauto)** | 1,000+ 커넥터로 클라우드/온프레미스 시스템 연결 |
| **Pipeline Builder** | 비코더용 시각적 노드 기반 변환 (드래그 & 드롭) |
| **Code Workbook** | 코더용 Python/SQL/PySpark 코드 환경 |
| **Magritte (Spark 기반)** | 대규모 배치 처리 |
| **Streaming** | Kafka 기반 실시간 처리 |

## 데이터 처리 단계
```
Raw → Cleaned → Transformed → Curated → Ontology-Ready
 (1)     (2)         (3)            (4)         (5)
```
1. 원본 그대로 적재 (Bronze)
2. 결측치·중복 제거 (Silver)
3. 정규화·집계·조인 (Gold)
4. 비즈니스 로직 적용 (Curated)
5. 3층 온톨로지 객체로 매핑 가능한 상태

## 핵심 차별화 — Hyperauto
- 메타데이터 기반 자동 스키마 변경 감지
- ERP 시스템(SAP/Oracle) 변경 시 파이프라인 자동 재생성
- "데이터 엔지니어 없이도 운영 가능"

## 시장 맥락
- 경쟁: Databricks, Snowflake, Talend, Informatica
- Foundry의 차별화는 "다음 층(온톨로지)와 매끄럽게 연결" — 단독 ETL 도구로는 약함

## UTTEC 무료 대체 매핑 (80% 커버 가능)
| 기능 | 무료 대체 | 커버 |
|------|----------|------|
| 시각적 변환 | **n8n** (노드 400+, 자체 호스팅) | ✅ |
| 코드 변환 | Jupyter + PySpark | ✅ |
| 커넥터 | n8n 통합 + Python 라이브러리 | ✅ |
| 스키마 자동감지 | (수동) | ⚠️ |
| 대규모 배치 | DuckDB / Polars (단일 서버) | ⚠️ 데이터 크기 한계 |

→ **결론**: 데이터 1억 행 이하 중소기업은 n8n + Python으로 80% 충분. PB 규모 처리는 Foundry 영역.

## UTTEC 영업 메시지
> "n8n으로 비코더 영업·운영팀이 직접 데이터 파이프라인을 만든다. Pipeline Builder의 핵심 가치(시각적 통합 + 코드 결합)를 1주 안에 시범 구축."

# 3층 ★ Ontology Manager (온톨로지 층) — 가장 중요

## 비유
**살아있는 작전 상황실** — 부품(데이터)을 의미 있는 비즈니스 객체(고객/제품/주문)로 조립.

## 정의
2층에서 정제된 데이터에 **의미·관계·행동(Action)**를 부여하여 **디지털 트윈**을 만드는 층. Foundry의 정수이자 경쟁사 대비 결정적 차별화 지점.

## 3대 구성요소
| 요소 | 영문 | 의미 | 예시 |
|------|------|------|------|
| **객체** | Object Type | 비즈니스 명사 | 고객, 제품, 주문, 장비 |
| **속성** | Property | 객체의 데이터 필드 | 이름, 가격, 상태 |
| **관계** | Link Type | 객체 간 연결(★) | 고객이 주문한다, 주문이 제품을 포함한다 |

## Action — 3층의 숨은 영웅
**Action**은 객체에 적용 가능한 **동사**. 단순 읽기 전용이 아니라 **상태를 변경**할 수 있게 함.

| 객체 | Property (명사) | Action (동사) |
|------|----------------|--------------|
| 주문 | id, 고객, 금액, 상태 | 주문승인, 주문취소, 환불처리 |
| 장비 | id, 모델, 위치, 가동상태 | 정지, 재시작, 점검의뢰 |
| 고객 | 이름, 등급, 이메일 | 등급변경, 알림발송 |

→ **객체(명사) + Action(동사) = 운영 앱의 토대**

## 두 가지 운영 모드
1. **읽기 모드 (Analytical)**: 4층 분석가가 객체 그래프를 탐색 — "어떤 고객이 어떤 제품을 주문했나?"
2. **쓰기 모드 (Operational)**: 5층 앱이 Action을 호출 — "이 주문을 승인하고 ERP에 반영"

## 데이터 흐름의 결정적 변환
```
2층:  주문_테이블_언더바_최종_언더바_진짜_최종_언더바_V3.csv
        ↓ (온톨로지 매핑)
3층:  Order(id, customer→Customer, items→[Product])
        ↓ (Action 정의)
3층:  approveOrder(order: Order, approver: User) → ERP Writeback
```

## 시장 맥락
- 경쟁사 대안: Microsoft Fabric의 OneLake, Databricks Unity Catalog (메타데이터만 다룸)
- Foundry의 차별화 = **Action까지 일급 시민**으로 다룸 (다른 도구는 분석 메타데이터에 머무름)

## UTTEC 무료 대체 매핑 (70% 커버 가능)
| 기능 | 무료 대체 | 커버 |
|------|----------|------|
| 객체·속성 정의 | **Memory MCP** (entities + observations) | ✅ |
| 객체 간 관계 | **Memory MCP** (relations) | ✅ |
| 시각 탐색 | **Obsidian Graph View** | ✅ |
| 자연어 질의 | **Claude + Obsidian** | ✅ |
| Action 정의 | **demo_live.html + n8n Webhook** | ⚠️ 70% (UI 약함) |
| 권한 모델 | Tailscale ACL | ⚠️ |
| 버저닝 | Git + frontmatter `updated:` | ✅ |
| 대규모 동기화 | (수동 또는 n8n) | ⚠️ |

→ **결론**: 디지털 트윈의 70%까지 무료 구현 가능. Memory MCP가 핵심 발견 (2026-05-05).

## 핵심 통찰 (시리즈 #3에서 도출)
> **객체(명사) + 액션(동사) = 운영 앱**
> 이게 분석 툴(BI)과 운영 앱의 결정적 차이.

기존 BI 도구들은 "객체"는 다루지만 "액션"이 없어서 결국 대시보드에 머무름. Foundry는 액션이 일급 시민이라 클릭 → ERP까지 갈 수 있음.

## UTTEC 영업 메시지
> "Foundry 3층 온톨로지의 70%를 Memory MCP + Obsidian으로 무료 재현. '진짜_최종_V3'에서 '주문/고객/제품'으로의 사고 전환을 1주에 체험. 디지털 트윈을 1억이 아니라 0원에 시작."

# 4층 ─ Analytics (분석층)

## 비유
**부품 검사실 + 실험실** — 의미 있는 부품(객체)이 어떻게 작동하는지 정밀 분석.

## 정의
3층 온톨로지를 입력으로 받아 **인사이트·예측·이상탐지**를 수행하는 층. 비즈니스 언어 위에서 분석하기 때문에 SQL 조인 지옥에서 해방.

## 핵심 도구
| 도구 | 용도 |
|------|------|
| **Code Workbook** | Python/R/SQL 노트북, Object 직접 import |
| **Quiver** | 시각화 + 코호트 분석 + 시계열 (BI 가까움) |
| **Contour** | 비코더용 노코드 분석 (필터·그룹·시각화) |
| **AIP (Artificial Intelligence Platform)** | LLM·전통 ML 통합 (Claude/GPT 호출, Action 자동 생성) |
| **Vertex (스트림)** | 실시간 그래프 알고리즘 |

## 분석 종류 (4가지)
1. **기술 분석 (Descriptive)**: "지난주 매출은?"
2. **진단 분석 (Diagnostic)**: "왜 매출이 줄었나?"
3. **예측 분석 (Predictive)**: "다음주 매출은?"
4. **처방 분석 (Prescriptive)**: "무엇을 해야 매출이 오르나?" → **5층 Action 자동 호출 가능**

## AIP — Foundry의 LLM 통합
- 객체에 자연어 프롬프트 첨부 가능
- LLM이 객체 데이터를 보고 Action 자동 제안
- 예: "이 주문을 분석하고 위험하면 'flagOrder' 액션 호출"
- AI Co-Scientist의 Foundry 버전

## 데이터 흐름
```
3층 객체 → Code Workbook (분석) → 인사이트
                            ↓
                    4층 결과를 새 객체로 저장 (Derived Object)
                            ↓
                    5층 앱이 이 결과를 표시 + Action 호출
```

## 시장 맥락
- 경쟁: Databricks Notebook, Tableau, Power BI, Snowflake Notebook
- 차별화 = **온톨로지 객체를 직접 import** (테이블 조인 불필요)

## UTTEC 무료 대체 매핑 (90% 커버)
| 기능 | 무료 대체 | 커버 |
|------|----------|------|
| 노트북 | **Jupyter + Google Colab** | ✅ |
| 비코더 분석 | Obsidian Dataview + Claude 자연어 질의 | ✅ |
| 시각화 | Plotly / matplotlib / D3.js / Three.js | ✅ |
| LLM 통합 | **Claude Code + Claude API** | ✅ |
| ML 모델 | PyTorch / scikit-learn / Prophet (이미 보유) | ✅ |
| 실시간 분석 | DuckDB + 폴링 / WebSocket | ⚠️ |

→ **결론**: 4층은 가장 쉽게 무료 대체 가능 (90%). UTTEC은 이미 13개 AI 모델 보유.

## UTTEC 영업 메시지
> "분석 레이어는 무료 도구로 90% 커버. Jupyter + Claude API + Three.js만으로 Foundry Quiver/Contour와 동일 결과. 우리 13개 AI 모델 + Claude AIP 결합으로 처방 분석까지 즉시 가능."

# 5층 ─ Application Layer (Workshop)

## 비유
**현장 작업자의 손에 들린 도구·계기판** — 분석 결과가 실제 행동으로 변환되는 종착지이자 새로운 데이터의 출발점.

## 정의
3층 객체 + 4층 분석 결과를 활용하여 **현장 작업자가 직접 사용하는 운영 앱**을 만드는 층. **닫힌 피드백 루프의 종결자.**

## 핵심 도구
| 도구 | 용도 |
|------|------|
| **Workshop** | 노코드 앱 빌더 (드래그 & 드롭) |
| **Slate** | 고급 사용자용 (Custom HTML/JS 가능) |
| **Marketplace** | 앱 템플릿 공유 |
| **Mobile (iOS/Android)** | 현장용 모바일 앱 |

## 5층 앱의 4대 패턴
1. **모니터링 대시보드**: 실시간 객체 상태 표시 (= 4층의 시각화 + Action 버튼)
2. **워크플로우 앱**: 단계별 작업 진행 (예: 주문 승인 → 제품 출하 → 배송 추적)
3. **결정 보조 앱**: AI 추천 + 사용자 선택 → Action 호출
4. **데이터 입력 앱**: 현장에서 직접 데이터 추가 (= Writeback 시작점)

## 핵심 차별화 — Action을 통한 Writeback
```
사용자 클릭 (5층 앱)
    ↓
Action 호출 (3층 온톨로지)
    ↓
ERP/MES/SAP 시스템에 데이터 쓰기 (역방향)
    ↓
다음 사이클의 데이터로 재진입 → 1층 감사로그 기록
```

이게 "보고서가 아니라 도구"라는 표현의 정확한 의미.

## 데이터 흐름의 완성
```
1층 → 2층 → 3층 → 4층 → 5층 → (Writeback) → 외부 시스템 → 다시 2층으로 흡수
```

## 시장 맥락
- 경쟁: PowerApps, Retool, Internal, Appsmith
- 차별화 = **온톨로지와 일급 통합** + **Action 자동 권한 체크 + 감사로그**
- 일반 No-Code 도구는 권한·로그를 직접 구현해야 함

## UTTEC 무료 대체 매핑 (60% 커버)
| 기능 | 무료 대체 | 커버 |
|------|----------|------|
| 노코드 앱 | **Retool / Appsmith / Budibase** (오픈소스) | ✅ |
| 대시보드 | **demo_live.html (Three.js)** | ✅ (이미 보유 4종) |
| 모바일 앱 | Flutter (이미 보유) | ✅ |
| Webhook 트리거 | **n8n Webhook 노드** | ✅ |
| 권한 모델 | Tailscale ACL + JWT | ⚠️ |
| Writeback to ERP | n8n 커넥터 (SAP/ODBC) | ⚠️ 70% |
| 감사로그 | OpenTelemetry → Loki | ⚠️ |

→ **결론**: 일반 ERP가 SaaS형이면 60% 커버. 폐쇄망 SAP는 Foundry 강세.

## UTTEC 영업 메시지

# 통합 정리 — 5층의 데이터 흐름과 가치 사슬

## 상향 흐름 (Bottom-Up): 데이터 → 의미 → 행동
```
1층 (인프라 가동)
  ↓ "안전한 환경 제공"
2층 (Pipeline Builder, 데이터 정제)
  ↓ "정제된 테이블"
3층 (Ontology, 의미 부여)
  ↓ "Customer/Order/Product 객체"
4층 (Code Workbook, 분석)
  ↓ "인사이트 + 예측"
5층 (Workshop 앱, 행동 도구)
  ↓ "사용자 클릭"
Action 호출
  ↓
3층에 다시 객체 상태 변경 + 외부 시스템(ERP) Writeback
```

## 하향 흐름 (Top-Down): 행동 → 데이터
```
5층 사용자 클릭 → 4층 영향 측정 → 3층 객체 갱신 → 2층 다음 배치 → 1층 감사
```

## 닫힌 피드백 루프의 의미
이 두 흐름이 **하나의 사이클**로 연결되어, 분석한 결과가 행동을 만들고, 그 행동이 다시 더 똑똑한 데이터를 낳음. **복리 구조**.

| 사이클 횟수 | 데이터 품질 | 의사결정 정확도 |
|------------|------------|---------------|
| 1회 | 베이스라인 | 70% |
| 10회 | 액션 결과 누적 | 80% |
| 100회 | 패턴 학습 | 90% |
| 1000회 | 도메인 표준 | 95%+ |

→ Foundry의 진짜 가치는 시간이 지날수록 데이터·결정 품질이 자가 향상하는 점.
