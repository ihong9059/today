### 1. 인트로 및 기존 AI 활용 방식 (0:00-2:32)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=0s)

#### 핵심 메시지
GPT 등장 3년 반이 지났지만, 대부분의 연구자는 여전히 복사-붙여넣기 방식으로 AI를 사용하고 있다.

#### 상세 내용
- LLM(Large Language Model)은 토큰을 이어붙여 텍스트를 생성하는 생성형 모델
- 챗봇 형태로 사용: 채팅창에 텍스트 입력, 파일 첨부(PDF, 워드, 마크다운)
- 주요 용도: 요약, 번역, 초안 작성, 피드백
- **핵심 문제**: 복사-붙여넣기를 끊임없이 반복하는 비효율적 패턴
  - AI에게 자료 줄 때도 복붙
  - AI 출력물을 활용할 때도 복붙
  - 실행 결과를 다시 AI에게 줄 때도 복붙
- 실제 작업은 한 번에 끝나지 않음: 변형→피드백→수정→재수정의 연속

#### 주요 발언
> "작업하는 패턴을 돌이켜 보시면 복사 붙여넣기, 복사 붙여넣기 계속 왔다 갔다 할 겁니다."

### 2. AI 에이전트란 무엇인가? (2:32-4:33)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=152s)

#### 핵심 메시지
에이전트는 목표를 주면 스스로 계획을 세우고, 단계별로 실행하며, 메모리와 도구를 활용하는 자율적 AI 시스템이다.

#### 상세 내용
- **정의**: 태스크/목표가 주어지면 → 리즈닝 → 계획 수립 → 단계별 실행
- **에이전트의 3가지 핵심 요소**:
  1. **계획(Planning)**: 리즈닝을 통해 좋은 계획을 세움
  2. **메모리(Memory)**:
     - Short-term: 채팅창 내 대화 맥락
     - Long-term: 파일로 중간 결과 저장, 나중에 다시 로딩
  3. **도구(Tool)**: 캘린더 조회, 코드 실행, 인터넷 검색 등 액션 수행

#### 언급된 사례/에피소드
- **단계별 작업 예시**: 1단계 실행 → 중간 정리 자료를 파일로 저장 → 2단계에서 불러와 사용 → 작업 상황을 플랜에 맞춰 중간중간 저장하고 로딩

#### 주요 발언
> "에이전트가 뭐냐고 할 때, 질문하면 답만 하는게 아니고 계획을 세워요. 계획을 세울 때 여러 가지 생각 과정들을 거쳐 가지고 좋은 계획을 세우고."

### 3. 챗봇 vs 에이전트 비교 (4:33-6:46)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=273s)

#### 핵심 메시지
챗봇은 대화창 안에서만 동작하고 인간이 모든 실행을 담당하지만, 에이전트는 큰 목표를 받아 자율적으로 계획→실행→피드백 루프를 돌린다.

#### 상세 내용
- **챗봇의 한계**:
  - 프롬프트 입력 → 답변 수신 (프롬프트 엔지니어링 필요)
  - 대화창 안에서만 동작, 범위 벗어난 작업 어려움
  - AI가 코드를 줘도 인간이 복붙해서 실행해야 함
  - 대화 종료 = 작업 종료, 사실상 휘발
  - 복잡한 작업은 인간이 일을 쪼개서 조금씩 시켜야 함

- **에이전트의 장점**:
  - 큰 목표 설정 → AI가 계획 수립 (인간 피드백으로 다듬기 가능)
  - 실행 + 결과 피드백을 자율적으로 수행
  - 오류 발생 시 자체 디버깅
  - 롱텀 메모리로 작업 이어가기 가능
  - 멀티 에이전트로 병렬 처리 가능

#### 주요 발언
> "에이전트는 그 실행을 자기가 스스로 하기 때문에 오류 문구를 자기가 직접 보고 바로 실수를 찾아 가지고 고칠 수가 있습니다."

### 4. 에이전트의 실제 동작 방식 (6:46-10:26)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=406s)

#### 핵심 메시지
에이전트는 코드 실행, 파일 조작, API 호출을 통해 실질적인 작업을 수행하며, 목표 설정만 해주면 인간이 개입할 필요가 크게 줄어든다.

#### 상세 내용
- **수행 가능한 액션들**:
  - 파이썬 코드 작성 + 자체 실행
  - 파일 조작: 워크스페이스 내 파일 복사/생성/삭제
  - 중간 결과물 파일 저장 → 나중에 다시 불러와 사용
  - API 호출로 외부 서비스 실행
  - 멀티 에이전트: A, B, C 작업을 병렬(parallel)로 처리 후 합산

- **챗봇과의 구체적 비교 예시**:
  - 챗봇: "분석하는 코드 줘봐" → 코드를 받아서 → 인간이 복붙 실행 → 오류 나면 오류 문구 복붙 → "어떻게 해야 돼?" → 수정 코드 받아서 → 또 실행...
  - 에이전트: "이 자료 분석해서 그래프 그려줘" → 파일 자체 열기 → 구조 파악 → 코드 작성 → 자체 실행 → 결과 저장 → "PPT에 넣어 드릴까요?"

#### 주요 발언
> "목표 설정만 해 주면 얘가 알아서 그 실질적인 작업까지 해 줄 수가 있습니다."

### 5. 에이전틱 작업의 기본 구조 (10:26-12:00)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=626s)

#### 핵심 메시지
에이전트는 Goal → Reasoning → Action → Result → State 변경의 사이클을 반복하며, 매 사이클마다 상태가 변하므로 새로운 판단을 내린다.

#### 상세 내용
- **기본 루프**: Goal 입력 → Reasoning(생각) → Action(Tool 호출 텍스트 명령어 생성) → 실행 → Result(성공 또는 오류) → State 변경
- 대화는 일직선으로 이어지지만, 에이전트는 사이클마다 상태가 바뀜
- State A → State B로 넘어가면 새로운 추론 → 새로운 액션 → 새로운 결과
- 일이 다 끝나면 "종료했습니다. 확인해 주세요."

### 6. 최신 AI 연구 동향 및 사례 (12:00-17:50)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=720s)

#### 핵심 메시지
AI 에이전트가 이미 연구 자동화에서 실질적인 성과를 내고 있으며, 자율실험실까지 등장했다.

#### 상세 내용

**사카나 AI 연구 (Nature, 2026.3.25)**:
- 엔드투엔드 자동화: 아이디에이션 → 실험 → 논문 작성 → 리뷰까지 전 과정
- 아이디어 생성 → 논문 DB 검색으로 신규성 검증 → 실행 가능성/새로움 점수화
- 사전 연구 → 가설 탐색 → 튜닝 → 본격 실험 → Ablation Study → 그래프 생성
- 페이퍼 템플릿에 맞춰 논문 작성 → 자체 리뷰 → 새 아이디어 도출
- **성과**: 논문 3편 투고, 1편 피어리뷰 통과 게재
- 모델 성능 향상에 따라 결과물 품질도 지속 상승 (GPT-4 → Sonnet 3.5 → Gemini 2.5)

**Ginkgo Bioworks 자율실험실 (bioRxiv, 2026.2)**:
- GPT-5 기반 자율 실험실 구축
- 클라우드랩: 로봇 암이 있는 자동화 카트에서 원격 실험 수행
- 데이터 분석 → 리즈닝 → 가설 생성 → 실험 명령어 생성 → 로봇 실행 → 결과 분석 → 루프
- 펩타이드 합성(Solid-phase peptide synthesis) 최적화
- **성과**: 기존 SOTA 대비 40% 비용 절감

#### 주요 발언
> "사카나 AI에서 논문 3편을 투고했고, 그 중 하나가 피어리뷰를 통과해서 게재가 됐습니다. 그 정도 성능까지 지금 나오고 있습니다."

> "GPT-5 기반으로 해서 자율랩을 만들었습니다. AI가 알아서 로봇을 조작을 해 가지고 실험을 하는 겁니다."

### 8. Agent.md / Rules 개념 설명 (19:22-23:00)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=1162s)

#### 핵심 메시지
Agent.md는 에이전트가 매 세션 시작 시 읽는 프로젝트 지침서로, 워크스페이스의 "운영 메모 쪽지" 역할을 한다.

#### 상세 내용
- **배치 위치**: 프로젝트 폴더(워크스페이스) 루트
- **작성 형식**: 마크다운(.md)
- **효과**: 에이전트가 매번 백지 상태가 아니라, 프로젝트를 아는 상태로 시작
- **포함 내용**:
  - 프로젝트가 무엇인지 (최상단)
  - 폴더 구조 설명 (파일 찾기 시간 단축)
  - 분석 방법 지침
  - 결과 정리 방법 (보고서 형식, 그래프 스타일, 글자 크기, 색상 등)
  - 해도 되는 것 / 하면 안 되는 것
  - 에이전트의 작업 방식 지침

- **점진적 발전**: 작업하면서 반복적으로 알려줘야 하는 것이 발견되면, Agent.md에 추가하여 항구적으로 기억시킴

#### 주요 발언
> "에이전트는 매번 새로운 대화를 시작할 때마다 일단 그 운영 메모 쪽지를 하나 읽고, '아 내가 이런 일을 하고 있었구나' 하면서 상황 파악을 하고 일을 항상 시작을 하게 됩니다."

### 9. Skills 개념 설명 (23:00-29:10)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=1380s)

#### 핵심 메시지
스킬은 반복 작업을 표준화한 재사용 가능한 지시서(SOP)로, 에이전트가 매번 "창의적으로 달라지는" 문제를 방지한다.

#### 상세 내용
- **문제 상황**: 텍스트로 설명해도 매번 약간씩 다르게 수행
- **해결**: 구체적 절차를 스킬로 작성하여 표준화
- **역할**: 에이전트 입장에서 일종의 SOP(Standard Operating Procedure)
- **활용**: 반복적으로 내리는 지시를 스킬로 만들어 놓으면, 구구절절 설명하거나 복붙할 필요 없음

### 10. MCP (Model Context Protocol) 설명 (25:38-29:10)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=1538s)

#### 핵심 메시지
MCP는 에이전트가 외부 서비스에 접근할 수 있게 하는 표준 프로토콜로, 에이전트의 도구 활용 범위를 크게 확장한다.

#### 상세 내용
- MCP 서버가 제공하는 도구를 에이전트가 연결하여 사용
- 캘린더, DB, 검색 엔진, 외부 API 등에 접근 가능
- 에이전트가 워크스페이스 내 파일 조작 + MCP를 통한 외부 서비스 = 통합 작업 환경

- **멀티 에이전트 협업**: 한 에이전트가 작업, 다른 에이전트가 비판적 검토
- 각 에이전트가 독립적으로 다른 관점에서 같은 결과를 리뷰

### 13. 에이전트 실패 패턴과 한계 (44:33-53:25)
[바로가기](https://www.youtube.com/watch?v=tZ9KFQOA6NM&t=2673s)

#### 핵심 메시지
에이전트를 과신하면 위험하며, 환각/맥락 잊음/과도한 자신감 등 다양한 실패 패턴을 인지하고 대비해야 한다.

#### 상세 내용
- **주요 실패 패턴**:
  - 환각(Hallucination): 존재하지 않는 정보를 자신있게 생성
  - 맥락 잊음: 긴 작업 중 초반 지시사항 망각
  - 과도한 자신감: 틀린 결과에도 확신하는 태도
  - 복잡한 작업일수록 실패 확률 증가
- **대응 전략**: 결과물 검증 필수, 중간 체크포인트 설정

### 14. 인간 연구자의 역할과 역량 (53:25-60:36)

#### 핵심 메시지
AI 에이전트 시대에도 판단, 검토, 방향 설정은 인간 연구자의 핵심 역할이며, Context 관리와 개인 자동화 파이프라인이 경쟁력이다.

#### 상세 내용
- **인간이 담당해야 할 역할**: 판단력, 검토, 방향 설정
- **연구자가 키워야 할 능력**:
  - Context 관리 전략 (발산과 수렴)
  - 에이전트와의 효과적 협업 방법
  - 개인 자동화 파이프라인 구축
- **개인 자동화 파이프라인 예시**: 데이터 수집 → 전처리 → 분석 → 시각화 → 보고서 작성을 에이전트 체인으로 구성
