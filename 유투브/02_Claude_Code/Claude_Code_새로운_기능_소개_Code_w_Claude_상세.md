- **이벤트**: Anthropic "Code w/ Claude" 발표

## 핵심 요약

발표는 "변경 로그(changelog)에서 빠진 *배경 이야기*"를 풀어내는 형식. Claude Code의 최근 출시 기능들을 **두 개의 테마**로 묶어 설명한다.

1. **개발자 경험(Developer Experience)** — 사용자가 클라우드/멀티 환경에서 더 많은 시간을 보내게 되면서, Claude Code 자체를 더 편하게 만드는 기능들.
2. **자율성(Autonomy)** — 키보드에서 손을 떼고 있는 동안에도 Claude가 더 많은 작업을 안전하게 수행할 수 있도록 돕는 기능들.

마지막으로 다루지 못한 나머지 기능들을 빠르게 훑고, 추가 정보 채널을 안내한다.

### 2. 개발자 경험 ① 원격 제어(Remote Control) (01:40 – 03:25)
[바로가기](https://www.youtube.com/watch?v=adIV8wlAFFE&t=100s)

#### 핵심 메시지
터미널에서 시작한 세션을 **모바일 브라우저나 모바일 앱**으로 이어받아 외출 중에도 작업을 계속할 수 있다.

#### 상세 내용
- 활성화: 터미널에 `원격 제어`(remote control) 입력 → 웹 Claude Code 링크 발급.
- 동일 세션, 동일 개발 환경에 모바일에서 접속.
- 입력 동기화: 터미널에 명령을 치면 웹에서도 보이고, 그 반대도 마찬가지.

#### 언급된 사례/에피소드
- **장기 세션 + 외출 패턴**: 발표자 본인이 가장 선호하는 사용 패턴. 여러 PR에 걸쳐 컨텍스트가 쌓인 long-running 세션에 원격 제어를 켜두고, *심부름하면서* 휴대폰으로 sub-agent 실행을 지시.

#### 주요 발언
> "오랫동안 미뤄왔던 일을 시작해 보는 건 어때요? 심부름 좀 하고 오세요." (01:54)

### 3. 개발자 경험 ② 깜빡임 없는 렌더링 + TUI Full Screen + 음성 모드 (03:25 – 06:25)
[바로가기](https://www.youtube.com/watch?v=adIV8wlAFFE&t=205s)

#### 핵심 메시지
터미널 UI를 **전체 화면 모드**로 전환하면서 스크롤백을 가상화 — 깜빡임 제거, 클릭 가능한 요소, 긴 세션에서도 일정한 메모리 사용량.

#### 상세 내용
- 기존 문제: 스크롤백에 줄을 추가하는 방식이 정렬에 민감 → 화면 재도색 → 깜빡임.
- 활성화: `tui full screen` 입력. (*Tui = Terminal UI 약어*)
- 구체 이점:
  - 깜빡임 없는 출력 보장
  - 도구 호출/요소 클릭 가능
  - 긴 세션에서도 메모리 일정 유지
  - 접혀 있는 도구 호출 창을 한 번의 클릭으로 펼침
  - 스크롤백을 위로 올려 검토 중에도 새 메시지 도착을 별도 알림으로 통지(아래 화살표 버튼) → 검토 흐름이 끊기지 않음
- 발표자 팀은 대부분 이 모드로 전환했고 "바로 차이를 느낄 수 있다"고 강조.

#### 음성 모드 언급
- `/voice` 명령어로 토글, **스페이스바 길게 누름**으로 음성 입력.
- 데모: *"농담 10개 파일과 재미있는 사실 10개 파일을 만들어 주세요"* 음성 입력으로 실행 → 풀스크린 모드의 매끄러운 렌더링 시연.

#### 주요 발언
> "클라우드 코드를 사용하면서 화면 깜빡임 현상을 경험해 보신 분이 몇 분이나 되시나요? 아, 그게 바로 당신이 진정한 베테랑이라는 걸 알 수 있는 거죠." (03:33)

### 4. 개발자 경험 ③ Claude Code Desktop 개편 (06:25 – 10:34)
[바로가기](https://www.youtube.com/watch?v=adIV8wlAFFE&t=385s)

#### 핵심 메시지
데스크톱/웹에서의 멀티 세션 관리를 위해 사이드바·필터·분할 화면·댓글·**챕터 고정** 등 UX를 전면 개편.

#### 상세 내용 (Excalidraw 데모 기반)
- **데모 셋업**: 오픈소스 화이트보드 앱 Excalidraw를 베이스로, 기본 도형(직사각형/마름모/타원)에 *사다리꼴* 추가하는 시나리오.
- **사이드바**:
  - 핀(pin) 섹션
  - 고급 필터링/그룹화 (프로젝트별 그룹화 가능)
  - **드래그 앤 드롭으로 분할 화면** 열기
- **세션 뷰**:
  - 우측 상단 세션 조회수
  - 녹취록 외에 해당 세션의 **Plan** 열람 가능
  - 임의 영역을 선택해 **댓글** 남기기 → 모든 댓글은 나중에 Claude가 취합해 한 번에 응답
  - **Diff 뷰** 열기 + 아무 줄에나 댓글
  - **파일 뷰** — 작업 디렉토리 전체 구조 확인 + 빠른 편집
- **실험 기능: 챕터로 고정(Pin as chapter)**
  - 어시스턴트 메시지 위 마우스 호버 시 "챕터로 고정" 버튼.
  - 클릭하면 해당 부분의 제목이 자동 생성되고 편집 가능 (예: "Debug pointer down event", "사다리꼴 요소에 누락된 거리를 추가하는 함수").
  - 여러 챕터 → 좌측 상단의 **목차(Table of Contents)** 로 변환되어 긴 녹취록 사이를 점프 이동.
  - 발표자 멘트: 데스크톱 책임자 **Anthony Morris**(X에서)에게 피드백 주면 "내일 바로 배포할 것"이라며 농담.
- **터미널 통합**: 데스크톱 안에서 바로 터미널을 열어 `서버 시작` → `localhost:3002` 띄움 → 사다리꼴(주황색) 그리기 데모.

#### 디자인 철학
> "이러한 모든 기능이 선택 사항이 됨에 따라 여러분이 클라우드에서 보내는 시간이 점점 더 많아질 것입니다. 그것들은 기본 설정이 아닙니다. 그것들은 그냥 필요할 때 움켜쥐는 물건일 뿐이에요." (08:34)

### 5. 자율성 ① 자동 모드(Auto Mode) — 권한 분류기 (10:34 – 12:00)
[바로가기](https://www.youtube.com/watch?v=adIV8wlAFFE&t=634s)

#### 핵심 메시지
권한 요청 프롬프트를 **분류기(classifier)** 가 자동으로 처리 — 사용자가 자리를 비워도 Claude가 *대신* 결정.

#### 상세 내용
- 출발점: 잠깐 자리를 비우고 돌아오면 권한 요청, 브랜치 충돌, 빌드 명령 누락 등으로 작업이 멈춰 있던 페인 포인트.
- 분류기가 도구 호출에 대해 **두 가지 질문**을 한다:
  1. 그 행동은 **파괴적(destructive)**인가?
  2. **프롬프트 인젝션(prompt injection)** 처럼 보이는가?
- 안전 판정 → 그대로 실행 / 위험 판정 → Claude가 도구 호출을 차단, 에이전트가 다음 행동을 다시 결정.
- 효과: Anthropic 내부에서 큰 시간 절약. 장시간 작업에서 "돌아와 보니 권한 프롬프트에 멈춰 있는" 상황이 줄어듦.

### 6. 자율성 ② 작업 트리(Worktree) (12:00 – 16:15)
[바로가기](https://www.youtube.com/watch?v=adIV8wlAFFE&t=720s)

#### 핵심 메시지
Git worktree를 Claude Code에 통합 — 여러 기능을 **격리된 환경에서 병렬로** 작업.

#### 상세 내용
- 발표자가 가장 좋아하는 기능. *"이 고통을 극복하는 데 도움이 되었기 때문"*.
- Git worktree는 새 브랜치 + 저장소 파일 복사를 제공하지만 운용에 까다로움이 있어 Anthropic이 인터페이스를 개선.
- **공유 파일 지정 필드**: `node_modules`처럼 worktree 전반에서 공유해야 할 파일을 Claude Code 설정에 명시 가능.
- 진입 방법:
  - `/worktree` 슬래시 명령어로 새 세션 + 새 worktree 동시 생성
  - 또는 자연어로 *"worktree 만들어 달라"* 요청
  - **Claude 자체가 판단**해서 worktree 진입/종료 도구를 호출 → CLAUDE.md에 의도를 적어두면 명시할 필요도 없음
- 종료 시 *harness*가 worktree를 자동 정리.

#### 언급된 사례/에피소드
- **3-way 병렬 데모**: Excalidraw에 (1) 6번째 색상 추가 (2) 모서리 둥글기 슬라이더 추가 (3) 별 모양 도형 추가 — 세 worktree를 동시에 돌림.
- 결과: 메인 체크아웃은 원본 그대로 유지된 채, 각 worktree는 독립 포트(localhost:3003 등)에서 변경된 기능을 동시에 검증 가능.

#### 주요 발언
> "그렇게 하면 여러 가지 PR을 동시에 경신하는 장시간 러닝 세션을 진행할 수 있습니다." (15:04)

### 7. 자율성 ③ 자동 메모리(Auto Memory) (16:15 – 18:05)
[바로가기](https://www.youtube.com/watch?v=adIV8wlAFFE&t=975s)

#### 핵심 메시지
Claude가 **세션 동안 지식을 축적**해서 토큰 낭비를 줄이는 자동 메모리 시스템. 사용자가 수동 설정할 필요 없음.

#### 상세 내용
- 페인 포인트: Claude Code가 매번 백지에서 시작한다고 느껴 동일한 컨텍스트(빌드 명령, 디버그 정보, 환경 설정)에 토큰을 반복 소모.
- 작동 방식:
  - 빌드 명령, 디버그 팁, 프로젝트 환경 설정 등 **기억해 달라**고 요청 가능.
  - Claude는 *"앞으로의 대화에 유용할 정보인지"* 기준으로 무엇을 저장할지 자체 판단.
  - 프로젝트마다 디렉터리를 관리, 그 안에 **memory.md** 인덱스 파일이 존재.
  - `cloud.md`(CLAUDE.md)처럼 대화에 포함되지만 **Claude가 단독으로 관리**.
  - 인덱스에서 더 자세한 다른 파일로 링크 → "기술과 마찬가지로 **점진적 정보 공개(progressive disclosure)**"를 활용.
- **하위 에이전트(sub-agent)** 에도 적용:
  - 커스텀 sub-agent에 *memory: user* 또는 *memory: project* 지정으로 전용 메모리 디렉터리 설정.
- 모델 측면:
  - 이 기능은 모델 발전 없이는 불가능. **Opus 4.7과 최신 모델**은 디렉터리 내 파일 집합으로 메모리를 관리하는 능력이 Opus 4 대비 크게 향상.

#### 주요 발언
> "보시다시피, 클로드는 이 능력 덕분에 포켓몬 실력이 훨씬 좋아졌습니다." (17:57) — *(Anthropic의 Claude Plays Pokémon 실험을 가리키는 농담)*

### 8. 자율성 ④ 코드 리뷰 (`/ultra review`) (18:05 – 19:10)
[바로가기](https://www.youtube.com/watch?v=adIV8wlAFFE&t=1085s)

#### 핵심 메시지
**여러 단계 + 여러 주체** 로 구성된 코드 리뷰 패턴을 도구화 — Claude가 PR을 스스로 검토.

#### 상세 내용
- Anthropic 내부 발견: 코드의 여러 측면을 독립적으로 검토하는 *리뷰어 팀*을 구성하고, 각 결과가 보고할 가치가 있는지 한 번 더 확인.
- 효과: "원래라면 몇 시간 걸렸거나 아예 놓쳤을 문제"를 잡아냄.
- 트리거 두 가지:
  - **GitHub 앱**으로 모든 PR에 자동 적용
  - 클라우드 코드에서 **`/ultra review`** 슬래시 명령어로 수동 실행

#### 자율성 4종 세트 정리
> "자동 모드, 작업 트리, 자동 메모리 및 코드 검토 덕분에 이제 승인해야 할 작업 수가 줄어들고, 더 많은 에이전트가 안전하게 병렬로 작업하며, 세션은 시간이 지남에 따라 지식을 축적하고, Claude 팀이 변경 사항을 검토하는 등 모든 작업이 완료되어 사용자가 직접 각 PR을 검토할 필요가 없어졌습니다." (18:41)

### 9. 루틴(Routines) — 사용자 개입 없는 자동 실행 (19:10 – 23:18)
[바로가기](https://www.youtube.com/watch?v=adIV8wlAFFE&t=1150s)

#### 핵심 메시지
**연구 프리뷰**로 출시된 "Routines" — Claude Code 세션을 트리거 기반으로 자동 실행. *아이디어 생성 자체*도 자동화.

#### 루틴 구성
- **재료**: 프롬프트 + 저장소 + 관련 커넥터 + 트리거.
- **트리거 종류**:
  1. **Cron 스케줄** (시간별/일별)
  2. **GitHub 웹훅 이벤트**
  3. **API 엔드포인트** (외부에서 호출)

#### 사용 사례
- **GitHub 이슈 분류 + Slack 통보**: 매일 GitHub 이슈를 분류 → 가장 중요한 것 요약 → Slack 커넥터로 전송.
- **이커머스 매출 트리거**: 판매가 발생할 때마다 루틴 실행.
- **발표자 본인의 1주일 운용 루틴**: *"전날 이후 가장 많은 React 코드가 생성된 최신 공개 GitHub 이슈 스캔, 내가 담당하는 라벨(영역 플러그인, 영역 훅) 한정, 가장 많은 리액션 상위 10개 정렬"* — 매일 아침 보고서가 도착.

#### `/loop` 슬래시 명령어
- Routines와 별개로 **단일 Claude Code 세션 내부 자동화**용.
- 데모: *"슬래시루프, 1분 동안 농담 하나 해줘"* → 분할 화면에서 백업 화면을 나란히 보면서 매분 농담 출력.
  - 농담 예시: *"프로그래머들이 다크 모드를 선호하는 이유 — 빛이 버그를 끌어들이니까."*
- 내부 구현: Claude에 **`cron 생성 도구`**(작업 시작 도구와 유사)가 추가됨. 설정에서 비활성화 가능.

#### 로컬 vs 원격
- **로컬 루틴**: 노트북을 켜둬야 함.
- **원격 루틴**: Anthropic 서버가 스케줄/실행 대행 — 발표자 선호.

#### 도구 검색(Tool Search)
- 실제 도구 정의에 **간접 단계(indirection)** 를 추가.
- 효과: 사용자 환경에 직접 부담을 주지 않으면서 한 번에 더 많은 도구를 제공 가능.
