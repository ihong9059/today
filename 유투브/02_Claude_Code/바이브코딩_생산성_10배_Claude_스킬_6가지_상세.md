## 구간별 상세 내용

### 1. Task Observer — 일하면서 스스로 개선되는 스킬 (00:45–03:22)
[바로가기](https://www.youtube.com/watch?v=ss4lbO8M8wk&t=45s)

#### 핵심 메시지
스킬의 최대 문제는 만드는 것이 아니라 **최신 상태로 유지하는 것**. Task Observer는 실제 작업 중 발생하는 문제에서 교훈을 자동 수집해 스킬 개선안으로 기록한다.

#### 상세 내용
- 원리: "앉아서 에이전트가 저지를 모든 실수를 예측할 수는 없다" → 작업 중 유용한 교훈을 감시. 같은 해결책이 새 스킬이 될 수 있으면 기록, 기존 스킬에 새 규칙이 필요하면 그것도 기록
- 설치 옵션 2가지: 메인 `.claude` 폴더(모든 세션 적용) vs **프로젝트별 설치(권장** — 프로젝트별 교훈 분리·관리 용이)
- 생성 파일 2개: ① `log.md` — 발견한 모든 교훈 기록 (스킬별 섹션 + 제안 변경사항) ② 모든 스킬에 적용할 **전역 규칙 파일** (예: "어떤 스킬도 실제 고객 이름을 파일에 쓰지 말 것")
- 셋업 시 CLAUDE.md에 지시문 추가 → 작업 중 스킬이 계속 실행되며 교훈 수집
- **즉시 스킬을 바꾸지 않음**: 로그의 교훈은 미래 세션에서 활용되고, 영구 반영 전에 사람이 검토 — "한 번의 나쁜 결과가 에이전트가 영원히 따르는 규칙이 되는 것"을 방지

#### 언급된 사례/에피소드
- **Logo Hub SVG 로고 사건**: 영상 애니메이션 제작 스킬에서 브랜드 로고가 필요(모델은 로고를 제대로 못 그려 SVG 코드로 제공해야 함). Logo Hub에서 수동으로 받아왔는데, 에이전트가 Logo Hub의 터미널 도구를 쓸 수 있다고 짐작해 시도 → 용도가 달라 실패
  - Task Observer가 ① "Logo Hub 도구를 애니메이션 시스템에 쓰지 말 것" ② 올바른 로고 소스 — 두 교훈을 기록
  - 검토 후 스킬에 반영 → 이제 애니메이션 에이전트가 수동 개입 없이 로고를 정확히 가져옴

#### 주요 발언
> "스킬의 가장 큰 문제는 만드는 게 아니라 최신으로 유지하는 것입니다. 에이전트가 같은 실수를 반복할 때마다 여러분이 직접 알아채고 스킬을 개선해야 하죠." (00:45)

> "이것이 한 번의 나쁜 결과가 에이전트가 영원히 따르는 규칙으로 자동으로 굳어지는 것을 막아줍니다." (02:27)

### 2. 마케팅 스킬 3종 — 온보딩·페이월·이탈 방지 (03:22–06:57)
[바로가기](https://www.youtube.com/watch?v=ss4lbO8M8wk&t=202s)

#### 핵심 메시지
Corey Haines의 48개 마케팅 스킬 컬렉션 중 **앱 안에 직접 구현되는 3가지**: 작동하는 제품도 온보딩·페이월·이탈 방지가 없으면 돈을 벌기 전에 사용자를 잃는다.

#### 상세 내용
- 데모 앱: Next.js 헬스장 앱 (멤버십 가입·트레이너 선택·운동 선택) + Supabase (DB·로그인)
- 스킬의 존재 이유 재확인: "에이전트가 이미 갖고 있지 않은 정보를 주는 것" — Supabase는 계속 업데이트되어 모델 학습 시점과 버전이 어긋남 → Supabase 스킬도 함께 설치 권장
- **온보딩 스킬**: AI 코딩하는 사람 대부분이 놓치는 부분. 기존 가입 = 5단계에 걸쳐 5가지 응답 → 개선: 이미 입력한 카드에서 이름 자동 채움, 새로 묻는 것은 헬스장 위치뿐. 요금제 페이지로 직행하며 **가장 인기 있는 플랜을 미리 선택**(결정 부담 완화). 제거한 설정 단계들은 하단 진행 바로 이동해 나중에 완성 — "수년간 실제 제품에서 검증된 사용자 행동 기반이지 지어낸 선택이 아님"
- **페이월 스킬**: 무료 가입 허용 → 유료 시 얻는 것을 보여주고 일부 콘텐츠는 잠금 → 잠금 화면에서 가격 페이지로 직행. "그냥 '페이월 추가해줘'라고 하면 에이전트는 이런 원칙이 내장돼 있지 않아 이런 선택을 하지 않는다"
- **이탈(churn) 방지 스킬**: 해지 시도 시 즉시 종료하지 않고 **이유를 먼저 물은 뒤 그 답에 맞는 더 나은 제안** 제시. 디자인 디테일 — "멤버십 일시정지"가 메인 버튼, "해지 계속"은 아래 일반 텍스트
- 데모라 아직 일반적(generic) — 실제 사용자 데이터와 판매 내용을 주면 제품 맞춤 결정으로 구체화됨

#### 주요 발언
> "작동하는 제품도 돈을 벌기 전에 사람들을 잃을 수 있습니다." (03:24)

> "이건 지어낸 선택이 아닙니다. 수년간의 테스트를 거쳐 실제 제품들에서 사람들이 어떻게 행동했는지에 기반한 것입니다." (05:35)

### 3. Karpathy의 4가지 규칙 — 에이전트의 월권 차단 (06:57–08:40)
[바로가기](https://www.youtube.com/watch?v=ss4lbO8M8wk&t=417s)

#### 핵심 메시지
"코딩 에이전트 문제의 대부분은 코드가 아니라 **시키지 않은 결정을 에이전트가 내리는 데서** 온다." Andrej Karpathy의 조언을 4가지 규칙으로 만든 스킬 — 영상 제작진이 모든 AI 코딩 프로젝트에 적용하는 규칙.

#### 상세 내용
- **규칙 1 — 짐작 금지**: 요청이 불명확하면 무엇을 가정하는지 밝히고, 옵션들을 보여주고, 프로젝트 방향을 바꿀 수 있는 결정 전에 물어야 함
- **규칙 2 — 과잉 구축 금지**: 요청한 것보다 많이 만들지 말 것. 아직 없는 문제를 위한 기능·설정·시스템 추가 대신 **작동하는 가장 단순한 해법** 사용
- **규칙 3 — 범위 밖 변경 금지**: 준 일 밖의 것을 바꾸지 말 것. 기존 스타일에 맞추고, 자기가 만든 혼란만 정리하고, 다른 문제는 직접 고치지 말고 **보고**
- **규칙 4 — 검증 없이 완료 선언 금지**: 시작 전에 결과가 무엇이어야 하고 어떻게 확인할지 정의 → 모든 체크가 통과할 때까지 작업
- **설치 팁**: 스킬로 설치하지 않고 개발 폴더(모든 코딩 프로젝트를 담는 상위 폴더) 루트의 `claude.md`에 4규칙을 복사 — Claude Code는 프로젝트 내부와 **상위 폴더들의 claude.md를 함께 읽으므로**, 모든 코딩 프로젝트에 같은 기본 규칙이 적용되면서 무관한 세션에는 영향 없음

#### 주요 발언
> "코딩 에이전트의 문제 대부분은 코드 자체에서 오지 않습니다. 여러분이 시키지 않은 결정을 에이전트가 내리는 데서 옵니다." (06:57)

> "다른 문제들은 스스로 고치는 대신 여러분에게 알려야 합니다." (07:39)

### 4. Open CLI — 100개+ 웹사이트를 에이전트 명령어로 (08:40–10:12)
[바로가기](https://www.youtube.com/watch?v=ss4lbO8M8wk&t=520s)

#### 핵심 메시지
브라우저 에이전트가 페이지를 열고 버튼을 찾아 느리게 헤매는 대신, Open CLI는 **로그인된 계정을 포함한 100개 이상의 웹사이트를 직접 실행 가능한 명령어**로 바꾼다.

#### 상세 내용
- 3부 구성: ① 메인 Open CLI 도구 ② Chrome 확장 프로그램 ③ 에이전트에게 사용법을 가르치는 스킬 세트
- 각 명령은 하나의 명확한 일만 수행 — "X를 열고 북마크 찾아 복사해줘" 대신 명령 하나로 북마크를 깨끗한 목록으로 반환
- Chrome 확장이 이미 로그인된 사이트와 연결 → **비밀번호 재입력 없이** 에이전트가 내 계정 사용
- 스킬은 올바른 명령 찾기, 필요 시 새 명령 만들기, 사이트 변경 시 명령 수정까지 가르침
- **용도 경계 명시**: 내 계정으로 웹사이트에서 하는 작업용. **남에게 판매하는 앱 안의 공식 도구(API)를 대체하는 용도가 아님**

#### 언급된 사례/에피소드
- **X(트위터) 사례**: X는 공식 API 접근에 과금 → Chrome에 이미 로그인돼 있다면 Open CLI로 에이전트가 게시물 검색·북마크 읽기·포스팅·답글·팔로우 가능
  - 활용: 제품 아이디어 리서치 시 사람들이 그 문제에 대해 뭐라고 하는지 검색, 저장해둔 게시물을 리서치용 목록으로 정리

#### 주요 발언
> "AI 에이전트의 가장 큰 한계 중 하나는 여전히 웹사이트 사용에 서툴다는 것입니다." (08:40)

### 5. Variate — 디자인 버전을 만들고 비교하는 메뉴 (10:12–11:34)
[바로가기](https://www.youtube.com/watch?v=ss4lbO8M8wk&t=612s)

#### 핵심 메시지
AI 모델은 같은 디자인을 반복하는 경향이 있으므로 첫 결과를 받아들이지 말고 여러 버전을 비교해야 한다. Variate는 **페이지의 한 부분씩 버전을 만들어 전환·비교·조합**하게 해준다.

#### 상세 내용
- Hallmark 디자인 스킬(채널에서 이전 소개, 스타 다수)과 같은 제작자
- 주 추천 용도: **랜딩 페이지**
- 동작: 앱에 작은 메뉴 추가 → 한 부분(예: 히어로 섹션)의 여러 버전 간 전환, 나머지는 그대로 유지. 로그인 후 메인 앱에 들어가면 메뉴는 사라짐
- 실제 Next.js 앱뿐 아니라 **HTML 프로토타입에서도 동일 작동** (이 채널의 표준 워크플로우: 디자인은 단순 HTML 페이지에서 시작)
- 선택한 버전은 에이전트에게 직접 전달 → 다른 부분의 버전 추가 요청 가능 → 버튼 하나, 섹션 하나, 헤더 단위로 시도해 **마음에 드는 조합으로 믹스**

#### 주요 발언
> "AI 모델들은 같은 디자인을 반복하는 경향이 있습니다. 그러니 처음 주는 디자인을 받아들이지 말고 여러 버전을 요청해서 비교해야 합니다." (10:12)

### 6. Minimalist Entrepreneur — 만들 가치가 있는지부터 검증 (11:34–13:08)
[바로가기](https://www.youtube.com/watch?v=ss4lbO8M8wk&t=694s)

#### 핵심 메시지
"아무도 원하지 않는 것을 만들면 앞의 모든 스킬이 무의미하다." Gumroad 창업자 Sahil Lavingia의 책 『The Minimalist Entrepreneur』를 10개 스킬로 변환 — **제품을 만들지 말지가 첫 결정**이다.

#### 상세 내용
- 10개 스킬 중 9개가 사업 구축 단계를 순서대로 안내
- **스킬 1 — 대상 그룹 찾기 (역방향 접근)**: 보통은 아이디어 먼저 → 원할 사람 찾기. 이 스킬은 **사람 먼저** — 이미 속한 그룹에서 사람들이 반복해서 불평하는 문제를 찾고, 그중 하나가 제품 아이디어가 됨. 이어 그 그룹이 만들 가치가 있는지 검증: 광고비 없이 도달 가능한가 + 이런 문제 해결에 이미 돈을 쓰는가
- **스킬 2 — 검증(validation)**: 만들기 전에 지불 의사 확인. "businesses" 같은 넓은 답 거부 — **이름을 댈 수 있는 실제 10명** + 그중 **최소 3명의 지불 의사** 요구
- 나머지 7개 스킬: 최소 버전 선택 → 먼저 손으로 직접 해보기 → 첫 고객 확보 → 가격 설정 → 마케팅 → 투자 유치 없이 성장 → 채용 전 회사 운영 방식 결정

#### 주요 발언
> "지금까지 다룬 모든 스킬은 에이전트가 더 나은 제품을 만들게 돕지만, 아무도 원하지 않는 것을 만들고 있다면 그 무엇도 중요하지 않습니다." (11:34)

> "'기업들'처럼 넓은 답은 받아주지 않습니다. 이름을 댈 수 있는 실제 10명을 원하고, 그중 최소 3명이 돈을 내겠다고 말하기를 원합니다." (12:46)
