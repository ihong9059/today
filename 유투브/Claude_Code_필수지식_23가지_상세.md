#### 다이나믹 워크플로우 vs 배치 비교 ⭐

| 차원 | 다이나믹 워크플로우 | 배치 |
|---|---|---|
| 본질 | 복잡한 목표 → 조사/실행/검증/결과 합치까지 전부 단계별 | 같은 패턴 반복 작업 병렬 분할 |
| 워커 수 | 작업 복잡도에 따라 가변 | **5~30개 고정 병렬** |
| 적합 작업 | 복잡성 ↑ + 논리적 흐름 중요 | 반복 작업 ↑ |
| 페이즈 | 조사→실행→검증→결과 | 단순 병렬 |

#### 시연
> "프로젝트를 컨스로 마이그레이션 해 줘"

→ 5~30개 서브 에이전트 무조건 생성 + 병렬

#### 주요 발언

### 7. 골 (Goal) — `/goal` 메타프롬프팅 (06:40 - 08:10)

[바로가기](https://www.youtube.com/watch?v=sfCm60LVVuI&t=400s)

#### 핵심 메시지 ⭐⭐⭐
**메타프롬프팅 필수** — 단순 프롬프트 X. **목표 / 배경 / 제약 / 성공기준** 명확 정의로 오랫동안 완성도 높은 작업 유도.

#### 메타프롬프팅 vs 단순 프롬프팅

| ❌ 나쁜 예 (단순 프롬프팅) | ✅ 좋은 예 (메타프롬프팅) |
|---|---|
| "프로젝트를 컨스로 마이그레이션 해 줘" | "이 프로젝트를 컨스 기반으로 변경할 수 있도록 골 프롬프트를 작성해 줘" |

→ 두 번째 방식으로 작성하면 Claude Code가 적합한 구조로 프롬프트 자동 생성

#### 골 프롬프트 자동 생성 구조 (디테일)

| 항목 | 본질 |
|---|---|
| **목표 (Goal)** | 무엇을 달성하려 하는가 |
| **현재 배경 (Context)** | 어떤 것들을 확인하고 준비할지 |
| **목표** (재정의) | 건드려도 되는 것 / 건드리면 안 되는 것 |
| **마이그레이션 매핑 규칙** | (마이그레이션 작업 시) |
| **제약 + 원칙** | 지켜야 하는 부분 + 권장 방식 |
| **성공 기준 (Acceptance Criteria)** | 완성됐는지 확인하는 기준 |

→ 이 구조로 인해 **언제 끝내도 될지 / 언제 완성됐는지** 자가 확인 가능.

#### 주요 발언
> "메타프롬프팅을 저는 추천을 드리고..."

> "골이라는 기능이 어떤 기능인지 클로드 코드가 이미 잘 이해하고 있기 때문에 거기에 적합한 구조로 프롬프트를 잘 만들어 줘요."

> "이걸 그대로 여러분이 복사해 가지고 골에다가 넣어서 붙여 넣기 해서 바로 실행을 하시면은 잘 실행이 된다."

### 8. 스킬 크리에이터 (Skill Creator) (08:10 - 09:10)

[바로가기](https://www.youtube.com/watch?v=sfCm60LVVuI&t=490s)

#### 핵심 메시지 ⭐⭐⭐
**"생각보다 많은 분들이 아직 안 쓰시는데..."** — 스킬 자동 생성 + **벤치마킹** + **deprecated 시점 자동 알림**.

#### 상세 내용
- 시연: "UI 검증하는 스킬 만들어 줘"
- Skill Creator 활용 시 장점 3가지:
  1. **벤치마킹 자동** — 스킬 사용 시 절약되는 리소스 정량화
  2. **모델 기본 능력 확인** — 이 스킬이 모델에 이미 탑재된 능력인지 확인
  3. **Deprecated 자동 알림** — 만든 스킬이 언제 쓸모없어질지 알림

#### 세션 흐름 ↔ 스킬 변환 패턴 ⭐
- 단순 프롬프팅으로 만드는 것보다 **대화 중 발견된 자동화 후보**를 같은 세션에서 Skill Creator로 변환하면 **정확도 ↑**
- 세션 동안 진행한 요소 그대로 스킬화

#### 주요 발언
> "우리가 만든 스킬이 언제 디플리케이트가 될지도 정확히 알 수가 있어요."

### 9. 퍼미션스 프롬프트 (Permissions Prompt) (09:10 - 09:50)

[바로가기](https://www.youtube.com/watch?v=sfCm60LVVuI&t=550s)

#### 핵심 메시지 ⭐⭐

#### 동작 원리
1. 지금까지의 대화 전부 확인
2. 사용자가 허가했던 작업들 + 안전했던 작업들 분석
3. **올라리스트** 안에 그 요소들 추가
4. 앞으로 다시 권한 물어보지 않도록 설정

#### 핵심 가치
- 일반 모드 사용자도 빠르게 "바이브 코딩" 가능
- 권한 질문 빈도 ↓

### 10. BTW — 세션 분리 질문 + 포크 (F키) (09:50 - 10:35)

[바로가기](https://www.youtube.com/watch?v=sfCm60LVVuI&t=590s)

#### 핵심 메시지 ⭐⭐
세션 더럽히지 않고 질문 가능. **F 키로 포크** → 기존 컨텍스트 유지하면서 분기.

#### 동작 원리
1. BTW로 질문 입력 (예: "프로젝트 제목 뭐야")
2. 밑에 새로운 채팅창 생성
3. **F 키 누르면 포크** — 기존 대화 전부 유지하면서 분기
4. 마우스로도 가능

#### 사용 시나리오
- 잠깐 질문하고 싶을 때 (메인 세션 컨텍스트 보존)
- **여러 세션 병렬 시작 + 컨텍스트 공유** 시 (코덱스 패턴 동일)

#### 주요 발언
> "병렬로 여러 개의 세션들을 시작을 하고 싶은데 그 친구들이 지금까지 있었던 모든 컨텍스트들을 다 공유를 했으면 좋겠다라는 생각이 들었을 때 굉장히 유용하게 쓸 수 있는 요소다."
