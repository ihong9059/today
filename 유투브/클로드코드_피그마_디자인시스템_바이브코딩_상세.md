### 1. 인트로 — 바이브 코딩에 디자인 시스템이 필요한 이유 (0:00-2:45)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=0s)

#### 핵심 메시지
디자인 시스템 없이 바이브 코딩하면 일관성 부재, 유지보수 비효율, 토큰 낭비가 발생하므로, 피그마 디자인 시스템을 기반으로 클로드 코드로 작업하는 것이 효율적이다.

#### 상세 내용
- 피그마 디자인 시스템 기반으로 클로드 코드로 랜딩 페이지를 바이브 코딩하는 과정을 진행
- "나는 혼자 하는데 왜 디자인 시스템이 필요하죠?"라는 의문에 대한 답변
- **디자인 시스템이 필요한 3가지 이유**:
  1. **일관된 디자인**: 컴포넌트와 토큰으로 통일된 디자인 유지
  2. **유지보수 효율**: 원본 하나만 수정하면 전체 반영
  3. **비용(토큰) 절감**: 매번 디자인을 설명하지 않아도 됨
- 실제 프로젝트 소개: 피그마 피디아, 스크린플로우 — 컴포넌트를 블록처럼 조합하여 페이지 구성
- 필요 조건: 클로드 코드 + 피그마 유료 버전

#### 주요 발언
> "혼자 하더라도 컴포넌트랑 토큰을 디자인 시스템으로 잡고 서비스 페이지를 만드는 것이 훨씬 효율적입니다."

### 2. 피그마 디자인 시스템 핵심 요소 — 베리어블 (2:45-5:30)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=165s)

#### 핵심 메시지
베리어블은 디자인 토큰을 피그마 안에서 구현하는 기능으로, 가장 작은 디자인 속성을 코드/JSON으로 만들어 용도별로 관리할 수 있게 한다.

#### 상세 내용
- **디자인 토큰**: 가장 작은 디자인 속성(컬러값, 간격 수치 등)을 코드나 JSON 형태로 만든 것
- **베리어블**: 디자인 토큰을 피그마 안에서 구현하는 기능
- **4가지 종류**: 컬러, 넘버, 스트링, 블린(Boolean)
- 용도별로 분류하여 필요할 때 가져다 쓸 수 있도록 체계적으로 관리
- 예: 프라이머리 컬러, 세컨더리 컬러, 배경색, 텍스트 컬러 등을 변수로 등록

#### 주요 발언
> "디자인 토큰은 가장 작은 디자인 속성을 코드나 JSON으로 만든 겁니다. 이걸 용도별로 분류해서 필요할 때 가져다 쓸 수 있게 합니다."

### 3. 피그마 디자인 시스템 핵심 요소 — 스타일과 컴포넌트 (5:30-8:20)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=330s)

#### 핵심 메시지
스타일은 반복적인 디자인 속성을 등록해 재사용하는 기능이고, 컴포넌트는 원본(마스터)을 만들고 인스턴스(사본)로 화면을 구성하는 템플릿 시스템이다.

#### 상세 내용
- **스타일(Style)**:
  - 반복적으로 사용되는 디자인 속성(컬러, 이펙트, 타이포그라피 등)을 등록해서 쓰는 기능
  - 한 번 등록하면 어디서든 불러와서 적용 가능
- **컴포넌트(Component)**:
  - 피그마 안의 템플릿 개념
  - 원본(마스터 컴포넌트) 하나를 만들고, 인스턴스(사본)로 화면을 구성
  - **4종 프로퍼티**: 텍스트, 블린(Boolean), 인스턴스 수압(Instance Swap), 베리언트(Variant)
- **핵심 공통점**: 원본 수정 시 모든 사본이 한번에 수정됨 — 코드에서도 동일한 원리
- **작업 흐름**: 토큰 제작 → 컴포넌트에 적용 → 작은 단위부터 조합 → 템플릿 → 페이지

#### 주요 발언
> "원본을 수정하면 모든 사본이 한번에 수정됩니다. 이것이 디자인 시스템의 핵심이고, 코드에서도 동일하게 작동합니다."

### 4. 피그마 MCP 개념 및 종류 (8:20-10:51)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=500s)

#### 핵심 메시지
MCP는 클로드 코드와 외부 도구를 연결하는 커넥터이며, 피그마 MCP에는 공식 데브모드 MCP(디자인→코드 특화)와 서드파티 톡투 피그마 MCP(디자인 수정/자동화 특화)가 있다.

#### 상세 내용
- **MCP(Model Context Protocol)**: 커서나 클로드 코드 같은 프로그램과 외부(피그마, 슬랙 등)를 연결하는 USB 허브/커넥터 같은 것
- 연동하면 클로드에서 시킨 작업을 피그마에서 수행하거나, 슬랙에서 처리 가능

- **데브모드 MCP (Figma Dev Mode MCP)**:
  - 피그마 자체에서 제공하는 공식 MCP
  - 디자인→코드(Design-to-Code) 기능에 최적화
  - 유료 유저만 사용 가능 (피그마 풀 시트 또는 데브 모드 시트)
  - 변수, 스타일 코드 추출, 디자인 시스템 읽기에 최적화
  - 플러그인 없이 사용 가능

- **톡투 피그마 MCP (Talk-to-Figma MCP)**:
  - 서드파티로 개발된 플러그인 기반 MCP
  - 피그마 파일 내 디자인 수정, 인스턴스 교체, 어노테이션(주석) 작성 등 자동화
  - 약 40가지 도구 제공
  - 피그마 무료 계정에서도 활용 가능
  - 디자인을 코드로 읽어오는 것도 가능하지만, 데브모드 MCP만큼 잘 되지는 않음
  - 베리어블 읽기도 가능하나 원활하지 않음

- **사용 추천**:
  - 디자인→코드 작업: 데브모드 MCP
  - 디자인 작업장 내 수정/주석/자동화: 톡투 피그마 MCP

#### 주요 발언
> "디자인→코드 할 때는 데브모드 MCP를 쓰시고, 디자인 작업장 안에서 수정하거나 주석 달거나 할 때는 톡투 피그마 MCP를 쓰시라고 추천드려요."

### 5. 클로드 코드에 피그마 데브모드 MCP 연결하기 (10:51-13:07)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=651s)

#### 핵심 메시지
클로드 코드를 커서 확장 프로그램 또는 터미널에서 설치하고, MCP 연결 명령어를 붙여넣기하면 피그마 데브모드 MCP가 연결되어 13가지 도구를 사용할 수 있다.

#### 상세 내용
- **클로드 코드 설치 방법 2가지**:
  1. **커서 확장 프로그램**: 커서 좌측 메뉴 → 확장 프로그램 → "Claude Code" 검색 → 설치 → "Claude Code Open" 메뉴로 시작
  2. **터미널**: 제공된 코드를 복사하여 커서 터미널에 붙여넣기 → 설치 완료 후 `claude` 입력하여 시작

- **데브모드 MCP 연결 과정**:
  1. 피그마에서 제공한 MCP 연결 명령어를 복사
  2. 클로드 코드 채팅 또는 터미널에 붙여넣기
  3. "연결되었다"는 메시지 확인
  4. `/mcp`를 입력하여 "Figma MCP Connected" 상태 확인
  5. 처음 연결 시 피그마 인증 브라우저가 열릴 수 있음 → 인증 완료 후 연결

- **연결 확인**: View Tool 선택 → 13가지 활용 가능한 도구 목록 확인

#### 주요 발언
> "슬래시를 누르고 MCP를 쳐 보시면 피그마 MCP가 커넥티드 되었다라고 뜹니다."

### 6. 피그마에서 프레임 읽어오기 실습 (13:07-14:48)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=787s)

#### 핵심 메시지
피그마에서 데브모드를 켜고 프레임을 선택한 상태에서 클로드 코드에 읽기 요청을 하면, MCP가 스크린샷과 컨텍스트를 자동으로 읽어온다.

#### 상세 내용
- 피그마에서 제공된 프롬프트(36번 프레임)의 위 세 줄만 복사
- 오른쪽의 "가이드"라는 프레임을 선택
- **중요**: 데브모드 MCP는 데브모드가 열려 있어야 읽을 수 있음
- 클로드 코드에 프롬프트를 붙여넣고 요청
- 피그마 URL 입력을 요청하는 에러가 뜰 수 있음 → 피그마 파일 링크를 복사하여 붙여넣기
- MCP가 스크린샷을 찍어오고 컨텍스트를 읽기 시작
- 데브모드 MCP에는 베리어블을 읽어오는 전용 도구가 내장되어 있음

#### 언급된 사례/에피소드
- **피그마 URL 에러**: 최근 피그마 URL을 입력하라는 에러가 자주 발생 → 링크를 복사하여 수동 입력으로 해결

### 7. 디자인 토큰 추출 및 코드 파일 생성 (14:48-16:08)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=888s)

#### 핵심 메시지
피그마의 컬러와 타이포그라피 변수들을 MCP가 읽어서 JS 파일에 토큰으로 자동 추출하고, 컴포넌트를 코드로 변환하여 파일 구조를 생성한다.

#### 상세 내용
- **토큰 추출 요청**: "피그마의 컬러와 타이포그라피 변수들을 읽고 토큰들을 추출해서 JS 파일에 업데이트해 달라"
- 결과: 토큰이 용도에 따라 정리되어 JS 파일에 자동 생성
  - 초반에 설명한 디자인 토큰(가장 작은 디자인 속성의 코드화)이 실제로 구현된 것
- **컴포넌트 코드화**: 컴포넌트 전체 섹션을 선택 → "지금 선택한 섹션의 컴포넌트를 코드로 만들어 줘" 요청
  - 새로 변수를 제작하고 컴포넌트 페이지까지 제작
  - 앞서 제작했던 변수 기반으로 컴포넌트 코드 생성
- **파일 구조 확인**: 피그마 데모 폴더 내에 버튼, 드롭다운, 헤더, 인덱스, 서치, 폼 등 컴포넌트 파일 생성
- **CSS 파일**: 피그마 theme.css 파일에 변수 토큰들이 코드화되어 들어감

### 8. 디자인 시스템 페이지 시각화 및 컨텍스트 관리 (16:08-18:16)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=968s)

#### 핵심 메시지
추출한 변수와 컴포넌트를 디자인 시스템 페이지로 시각화하고, 컨텍스트 70% 초과 시 /compact로 압축하여 맥락 유실을 방지해야 한다.

#### 상세 내용
- **디자인 시스템 페이지 생성**: "지금까지 제작된 변수와 컴포넌트를 디자인 시스템 페이지로 만들어 줘" 요청
  - 토큰과 컴포넌트 기반의 시각적 디자인 시스템 페이지 자동 생성
  - 로컬 서버 주소를 물어보거나 "브라우저를 띄워 달라"고 요청하여 확인

- **컨텍스트 관리 (중요)**:
  - 오른쪽 하단에 "87% Used"라고 표시 = 전체 맥락(컨텍스트) 사용량
  - **100%가 차면**: 클로드가 앞 컨텍스트를 자체적으로 압축 → 느려지거나 맥락 유실 가능
  - **권장**: 70% 넘으면 적정한 시점에 `/compact` 처리
  - `/compact`를 입력하면 전체 맥락을 요약 압축

#### 주요 발언
> "컨텍스트가 100%가 차면 앞 컨텍스트를 자체적으로 클로드가 압축해 버리는데, 그렇게 되면 조금 느리거나 너무 많은 컨텍스트가 유실될 수 있습니다."

### 9. CLAUDE.md 파일로 작업 원칙 등록 (18:16-19:18)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=1096s)

#### 핵심 메시지
CLAUDE.md 파일에 디자인 시스템 규칙과 작업 원칙을 등록하면, 매번 설명하지 않아도 클로드가 자동으로 규칙을 읽고 맥락에 맞게 작업한다.

#### 상세 내용
- **CLAUDE.md 파일**: 클로드가 작업할 때마다 자동으로 읽는 설정 파일
- **등록할 내용 (작업 원칙)**:
  1. **단계별 작업 계획**: 어떻게 작업하고 보고할 것인지
  2. **토큰 사용 계획**: 기존에 있는 토큰은 재사용, 새로 필요한 토큰이 없으면 "없다"고 보고
  3. **하드코딩 금지**: 하드코딩하지 말고 토큰이나 컴포넌트 활용
  4. **누락 요소 확인**: 토큰이나 컴포넌트에 없는 요소가 있을 경우 무조건 물어보고 진행
- 프롬프트에서도 "CLAUDE.md에 명시된 원칙을 기반으로 작업하라"고 추가 명시 가능

#### 주요 발언
> "CLAUDE.md라는 파일에 등록을 해 놓으시면 클로드가 작업할 때마다 이걸 읽어서 맥락에 맞게 작업을 합니다."

> "하드코딩하지 말고 토큰이나 컴포넌트에 없는 요소가 있을 경우 무조건 물어보고 진행을 해라."

### 10. 최종 랜딩 페이지 바이브 코딩 (19:18-20:47)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=1158s)

#### 핵심 메시지
추출한 토큰과 컴포넌트 기반으로 피그마 디자인 시안과 거의 유사한 랜딩 페이지를 바이브 코딩으로 생성할 수 있으며, 디테일은 추가 대화로 다듬어야 한다.

#### 상세 내용
- **랜딩 페이지 제작 과정**:
  1. 피그마로 이동하여 "컴포넌트 적용된 버전" 화면 클릭
  2. 클로드 코드에 "지금 선택한 프레임 화면을 읽어서 컴포넌트/토큰 구조 파악하고 랜딩 페이지를 구현해 달라" 요청
  3. 클로드가 어떻게 작업할지 물어봄 → 기존에 없는 요소 처리 방법 확인
  4. 옵션 선택 후 진행 → 피그마 디자인 시스템 기반으로 작업
  5. 원본과 거의 유사한 아웃풋 생성

- **결과물 확인**:
  - 기존 디자인 시안의 대부분을 반영
  - 정렬 틀어짐, 아이콘 찌그러짐, 로고 이상 등 디테일은 MCP 대화로 추가 다듬기 필요

- **핵심 포인트**: 디자인 시스템(토큰+컴포넌트)을 먼저 잡았기 때문에, 원본에 가까운 일관된 결과물을 얻을 수 있었음

#### 주요 발언
> "기본적으로 우리가 작업해 놓은 컴포넌트를 기반으로 작업을 했다라는 거를 확인하실 수 있어요."

### 11. 마무리 및 유용한 팁 — 피그마 커뮤니티 소스 활용 (20:47-21:39)
[바로가기](https://www.youtube.com/watch?v=cSx1GCgoCrU&t=1247s)

#### 핵심 메시지
처음부터 디자인 시스템을 만들기 부담되면 피그마 커뮤니티의 무료 디자인 시스템 소스로 시작할 수 있으며, 어떤 프로덕트든 디자인 시스템을 먼저 잡고 토큰을 적용하면 효율적이다.

#### 상세 내용
- **추가 실습 권장**: 시간이 되면 제공된 추가 화면도 작업해 보기 추천
- **피그마 커뮤니티 활용**:
  - 처음부터 디자인 시스템 작업이 부담되면 커뮤니티 소스로 시작
  - 피그마 커뮤니티에 "디자인 시스템"만 검색해도 좋은 무료 소스가 매우 많음
  - 라이센스는 반드시 확인 필요
  - 피그마 디자인 시스템 원본을 제공하는 추천 사이트 3곳 안내

- **핵심 조언**: 이 프로덕트뿐만 아니라 다른 프로덕트 하실 때도 기본적으로 디자인 시스템을 잡고 토큰 적용해서 진행하면:
  1. 토큰(비용)을 절약할 수 있음
  2. 내가 원하는 아웃풋에 더 가까운 화면을 만들 수 있음

#### 주요 발언
> "디자인 시스템을 잡고 토큰을 적용해서 진행하시면 토큰을 녹이지 않고 더 내가 원하는 아웃풋에 가까운 화면을 만드실 수가 있을 거예요."

> "만약에 처음부터 디자인 시스템 작업하는 게 부담이 되신다면 커뮤니티 소스로부터 시작을 해 보시는 걸 추천드려요."

## 전체 워크플로우 정리

```
[1단계] 피그마 디자인 시스템 구성
  └─ 베리어블(토큰) 정의: 컬러, 넘버, 스트링, 블린
  └─ 스타일 등록: 컬러, 이펙트, 타이포그라피
  └─ 컴포넌트 제작: 원본 → 인스턴스 구조

[2단계] 클로드 코드 + 데브모드 MCP 연결
  └─ 커서 확장 프로그램 또는 터미널로 클로드 코드 설치
  └─ MCP 연결 명령어 입력 → 피그마 인증
  └─ /mcp로 연결 확인 (13가지 도구)

[3단계] 토큰/컴포넌트 코드 추출
  └─ 피그마에서 데브모드 열기 + 프레임 선택
  └─ 베리어블/스타일 → JS/CSS 토큰 파일 자동 생성
  └─ 컴포넌트 → 개별 코드 파일 생성 (버튼, 헤더, 폼 등)

[4단계] CLAUDE.md 작업 원칙 등록
  └─ 토큰 재사용 원칙
  └─ 하드코딩 금지
  └─ 누락 요소 확인 후 진행

[5단계] 최종 페이지 바이브 코딩
  └─ 피그마 디자인 시안 프레임 선택
  └─ 토큰/컴포넌트 기반 랜딩 페이지 생성
  └─ MCP 대화로 디테일 다듬기
```

## 도구/리소스 정리

| 도구/리소스 | 용도 | 비용 |

| CLAUDE.md | 작업 원칙/규칙 등록 | 무료 |
