## 영상 정보

- **재생시간**: 10:13
- **업로드**: 2026-06-13
- **링크**: https://www.youtube.com/watch?v=gC0qIatTldg

> ⚠️ 자동 생성 자막 기반이라 고유명사 오인식이 많습니다. 본문은 교정한 표기를 사용합니다.
> - 익스필드/슬필드/픽스필드 → **Higgsfield(힉스필드)**
> - 시덴스(클린) → **Seedance(시댄스, 영상 생성 모델)**
> - 나노바나 → **Nano Banana(이미지 생성 모델)**
> - 리모션 → **Remotion(코드 기반 모션그래픽 도구)**
> - 헤리메스 → Hermes(다른 에이전트 예시)

## 한 줄 요약
클로드(Claude)에 **Higgsfield MCP**를 연결하면, 채팅 대화만으로 썸네일·랜딩페이지·카드뉴스·모션그래픽·스토리보드 기반 장편 영상까지 **이미지/영상 생성**을 직접 수행할 수 있다. 핵심 비유: **"클로드는 감독, Higgsfield는 촬영팀"**. 단, 버튼 한 번에 작품이 나오는 마법은 아니며 결과 품질은 **사용자의 상상력·방향성·취향**에 달려 있다.

## 구간별 상세 내용

### 1. 도입 — Higgsfield MCP란 무엇인가 (00:00-01:40)
[바로가기](https://www.youtube.com/watch?v=gC0qIatTldg&t=0s)

#### 핵심 메시지
영상·3D 아이콘·썸네일·모션그래픽을 전부 클로드와 대화하며 만들었다. 클로드 자체는 이미지/영상을 생성하지 못하지만, Higgsfield MCP가 그 "손"을 달아준다.

#### 상세 내용
- Higgsfield는 현재 세계적으로 주목받는 이미지·영상 생성 서비스 중 하나. **GPT 이미지·Nano Banana(이미지), Seedance(영상)** 같은 여러 모델을 한 곳에서 사용 가능.
- 바이럴 포맷·카메라 무브먼트 **프리셋**을 제공해 복잡한 편집 없이 퀄리티 높은 콘텐츠를 빠르게 생성.
- 클로드 같은 에이전트는 **기획·지시는 잘하지만 이미지/영상을 직접 생성하지 못함** → 그 공백을 MCP가 채움.
- **MCP라 클로드에만 묶이지 않음** — GPT, Hermes 등 다른 에이전트도 같은 MCP 서버만 연결하면 동일하게 활용 가능.
- ⚠️ 마법 도구가 아님: 버튼 하나로 만족스러운 작품이 나오지 않는다. **좋은 결과 vs 흔한 AI스러운 결과**를 가르는 건 사용자의 상상력과 방향성.

#### 주요 발언
> "클로드가 감독이라면 익스필드(Higgsfield)는 실제 촬영팀인 거죠." (01:03)

> "이게 무슨 마법 같은 도구는 아니라는 겁니다. 버튼 하나 눌렀다고 알아서 만족스러운 작품이 튀어나오는 건 아니기 때문에..." (01:19)

### 2. 연결 방법 — MCP 커넥터 등록 & 권한 설정 (01:40-02:42)
[바로가기](https://www.youtube.com/watch?v=gC0qIatTldg&t=100s)

#### 핵심 메시지
클로드 데스크톱 앱에서 커스텀 커넥터로 Higgsfield MCP 주소를 등록하고, 크레딧이 소모되는 생성 동작의 권한을 신중히 설정한다.

#### 상세 내용 (연결 절차)
1. 클로드 앱 실행 → **사이드바 → 커스터마이즈 → 커넥터** 클릭
2. **+ 버튼 → 커스텀 커넥터 추가** 클릭
3. Higgsfield 홈페이지 → **MCP 탭**에서 MCP 주소 복사
4. 클로드로 돌아와 이름="익스필드(Higgsfield)", 주소칸에 붙여넣기 → 추가
5. "연결하라" 버튼 → 계정 연결 진행
6. **권한 설정**: 이미지·영상 생성 같은 동작은 **실제 크레딧이 소모**되므로 "매번 물어보기"를 추천. (발표자는 빠른 실행을 위해 전부 "항상 허용"으로 설정)
7. 연결 확인: "MCP를 통해 넌 어떤 작업을 할 수 있지?"라고 질문 → 가능 작업 목록 응답

#### 주요 발언
> "이미지 만들기나 영상 생성 같은 생성 동작은 실제 크레딧이 나가는 동작이기 때문에 매번 물어보게 두는 걸 추천합니다." (02:22)

### 3. 사례 1 — 썸네일 만들기 (캐릭터 레퍼런스 시트) (02:42-04:14)
[바로가기](https://www.youtube.com/watch?v=gC0qIatTldg&t=162s)

#### 핵심 메시지
얼굴을 여러 각도로 찍은 "캐릭터 레퍼런스 시트"를 먼저 만들어 인식률을 높인 뒤, 그것을 토대로 배경·레이아웃을 구상해 썸네일을 생성하고 대화로 수정한다.

#### 상세 내용
- **캐릭터 레퍼런스 시트** = 본인 얼굴을 여러 각도로 찍은 사진 모음집. 썸네일에 얼굴이 들어가야 하므로 다양한 각도를 보여줘 AI가 잘 인식하게 함.
- MCP로 사용하면 클로드가 **적합한 모델 자동 지정 + 프롬프트 적절히 작성**.
- 첫 결과는 한 번에 완벽하지 않음 → **수정 버튼 누르고 대화하듯 고쳐가기**.
- 직접 촬영한 게 아니어도 꽤 안정적으로 결과가 나옴. 레퍼런스 시트를 활용해 추가로 영상 생성 작업도 수행.

#### 주요 발언
> "여기서부터 필요한 부분을 대화하듯이 고쳐 가면 됩니다." (03:33)

### 4. 사례 2 — 랜딩 페이지 (코드 + 비주얼 동시 생성) (04:14-05:48)
[바로가기](https://www.youtube.com/watch?v=gC0qIatTldg&t=254s)

#### 핵심 메시지
자기소개 랜딩 페이지를, **코드도 클로드가 짜고 그 안에 들어갈 비주얼(영상·3D 아이콘)도 클로드가 생성**하여 하나의 작동하는 페이지로 완성.

#### 상세 내용
- 본인 정보가 담긴 로컬 폴더("슬로우라이프")를 지정 → 별도 설명 없이 클로드가 정보를 읽어 활용.
- 상단엔 앞서 만든 영상을 전체화면 배치, 하단 섹션엔 **3D 아이콘** 사용. 생성 자료는 지정 폴더(SF 폴더)에 저장해 재사용.
- 클로드가 정보 확인 → 코드 작성 → Higgsfield로 3D 아이콘 실제 생성 → 스크롤 시 영상·아이콘이 자연스럽게 구현.
- 디테일은 결국 사람이 손봐야 하지만, **0 → 80까지 가는 과정이 비교 불가하게 빨라짐**(예전엔 코드·영상·아이콘을 하나하나 따로 만들어야 했음).

#### 주요 발언
> "예전에는 코드 짜고 영상 따로 만들고 아이콘이나 이미지를 하나하나 만드는 게 정말 귀찮고 오래 걸리는 작업이었는데, 이제는 0에서 80 정도까지 가는 그 과정 자체가 말도 안 되게 빨라진 거 같습니다." (05:36)

### 5. 사례 3 — 카드 뉴스 (동적 이미지 + 자동화) (05:48-06:28)
[바로가기](https://www.youtube.com/watch?v=gC0qIatTldg&t=348s)

#### 핵심 메시지
정적 사진·텍스트만 쓰는 기존 카드뉴스보다, **동적 이미지를 추가**하면 훨씬 다채로운 결과. 간단한 요청에도 괜찮게 나옴.

#### 상세 내용
- 카드뉴스 자동화는 흔하지만, 동적 이미지를 더하면 차별화.
- 간단히 요청했는데 이미지도 그럴싸하고 레이아웃·글자 크기 정도만 수정하면 됨.
- **스케줄/크론 작업까지 연결**하면 SNS 운영·꾸준한 콘텐츠 발행에 생산성을 크게 높임.

### 6. 사례 4 — 모션 그래픽 (심심한 구간 채우기) (06:28-07:31)
[바로가기](https://www.youtube.com/watch?v=gC0qIatTldg&t=388s)

#### 핵심 메시지
영상 중 화면 변화가 없어 심심해지는 구간을, 예전엔 **Remotion** 모션그래픽으로 채웠지만 이제는 스크립트만 주면 Higgsfield가 바로 생성.

#### 상세 내용
- 특정 구간 내용(스크립트)만 주면 그에 맞춰 모션그래픽 영상을 즉시 생성.
- 사용 가능한 **프리셋이 매우 다양**(화려·창의적 포맷). 발표자는 "3D 렌더" 프리셋 선택.
- ⚠️ **함정**: 생성 중 오류 발생 → 확인해 보니 **Seedance 모델의 안전 필터가 민감**하게 작동(본인 사진인데도 필터에 걸림). → **웹에서 다시 시도**하면 해결.
- 나온 결과물을 편집 시 해당 구간 위에 덮으면 끝.

#### 언급된 사례/에피소드
- **Seedance 안전 필터 오작동**: 본인 얼굴 사진인데 안전 필터에 차단됨 → MCP 대신 웹 인터페이스에서 재시도하는 우회법.

### 7. 사례 5 — 스토리보드 기반 장편 영상 (07:31-08:54)
[바로가기](https://www.youtube.com/watch?v=gC0qIatTldg&t=451s)

#### 핵심 메시지
단순 숏폼이 아닌 의도대로 흘러가는 긴 영상은 **스토리보드 기법**으로 만든다. 스토리라인 설명 → 씬별 이미지 → 개별 영상 → 연결까지 자동.

#### 상세 내용
- 목표: "맥북으로 코딩하며 어디서든 일하는 인디해커의 하루" 브이로그 형식의 긴 영상.
- 절차: 구현하려는 **스토리라인 설명 → 스토리보드 생성 → 스토리보드 기반으로 씬별 이미지 생성 → 개별 영상(클립) 제작 → 모두 이어붙여 최종 영상 완성**.
- 폴더엔 프레임별 이미지·각 클립이 모두 생성됨.
- AI가 알아서 만드는 게 아니라 **내가 의도한 방향대로** 움직여 → 컨트롤이 쉽고 컷 간 일관성도 잘 유지.

#### 주요 발언
> "이렇게 만들면 AI가 알아서 만드는 게 아니라 제가 의도한 방향대로 움직여 주기 때문에 컨트롤도 훨씬 쉬워지고 컷 간의 일관성도 잘 유지되는 거 같습니다." (08:46)

### 8. 마무리 — 벽은 낮아졌고, 남은 건 상상력과 취향 (08:54-10:13)
[바로가기](https://www.youtube.com/watch?v=gC0qIatTldg&t=534s)

#### 핵심 메시지
예전 개인 창작자의 한계는 제작 능력·비용이었으나 그 벽이 크게 낮아졌다. 남은 벽은 상상력. 도구가 마법이 되느냐 AI 슬롭(slop)이 되느냐는 결국 **취향**의 문제이며, **감독은 여전히 사람**이다.

#### 상세 내용
- 과거: 디자인 못 하면 막히고, 영상 편집 못 하면 막히고, 외주 아니면 아이디어가 있어도 구현 어려움.
- 현재: 그 벽이 낮아짐 → 남은 병목은 오히려 **본인의 상상력**.
- 취향이 없으면 "그럴듯한 결과물이 더 빠르게 많이 만들어질 뿐". 내 채널에 어울리는 분위기·썸네일·반응 포인트를 **내가 알고 있어야** 도구가 진짜 증폭기(amplifier)가 됨.

#### 주요 발언
> "이게 마법 같은 도구가 되느냐 아니면 AI 슬롭이 되느냐를 가르는 건 결국 취향이라고 생각합니다." (09:27)

> "결국 도구는 훨씬 좋아졌지만 여전히 감독은 사람인 거죠." (09:51)

## 핵심 인사이트
1. **클로드 = 감독, Higgsfield = 촬영팀.** 클로드는 기획·지시·코드를 담당하고, 생성이라는 "손"은 MCP가 제공한다.
2. **MCP는 에이전트 종속이 아니다.** 같은 MCP 서버를 GPT·Hermes 등 어디든 붙이면 동일 기능을 쓸 수 있다 — 도구의 이식성이 핵심 가치.
3. **워크플로우 통합이 진짜 이득.** 코드·영상·아이콘을 한 대화 안에서 처리해 "0→80"이 극적으로 빨라진다. 단, 마지막 디테일(20)은 사람이 손본다.
4. **크레딧 비용 주의.** 생성 동작마다 크레딧 소모 → 권한을 "항상 허용"으로 두면 빠르지만 비용 통제 약화. 신중하려면 "매번 물어보기".
5. **안전 필터 우회 팁.** Seedance가 본인 사진도 막을 수 있음 → 웹 인터페이스 재시도.
6. **장편은 스토리보드 우선.** 의도·일관성을 잡으려면 스토리라인→스토리보드를 먼저 만들고 씬을 생성해야 한다.
7. **결국 차별화는 취향.** 도구가 평준화될수록 "무엇을 보여줄지 아는 사람"만 증폭기를 제대로 쓴다.
