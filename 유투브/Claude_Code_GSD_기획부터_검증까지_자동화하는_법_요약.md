## 전체 요약

### 핵심 주제
Claude Code가 작업할수록 품질이 저하되는 "Context Rot(컨텍스트 부패)" 현상과, 이를 시스템으로 해결한 GSD(Get Shit Done) 도구의 원리 분석. 나아가 프롬프트 엔지니어링의 다음 단계인 "컨텍스트 엔지니어링" 개념을 소개.

### 핵심 내용
1. **Context Rot 문제**: Claude Code는 컨텍스트 윈도우(메모장)가 차면 품질이 떨어지고, 앞서 정한 규칙을 잊고 같은 실수를 반복하게 됨
2. **GSD 도구**: 클로드 코드 위에 설치하는 메타프롬프팅 시스템으로, 5단계 워크플로우(질문→논의→계획→실행→검증)를 통해 컨텍스트 롯 문제를 해결
3. **GSD의 3가지 핵심 원리**: 컨텍스트 격리(서브 에이전트), 구조화된 전달(마크다운 문서), 원자적 계획(계획서 단위 실행)
4. **컨텍스트 엔지니어링**: AI에게 올바른 컨텍스트를 올바른 타이밍에 올바른 형태로 전달하는 기술 - 프롬프트 엔지니어링의 다음 단계
5. **GSD 없이도 적용 가능한 3가지 원칙**: 대화를 줄이고 문서를 늘리기, 큰 작업은 쪼개서 시키기, 검증 자동화하기

|------|------|------|

| GSD 사용 기업 | Amazon, Google, Shopify | 대기업 엔지니어들도 활용 중 |

## 구간별 요약

### 1. Context Rot이란? (0:00-0:38)
[바로가기](https://www.youtube.com/watch?v=oU-BbX0Om4I&t=0s)

- Claude Code 사용 경험: 처음엔 천재처럼 작동하다가 1시간쯤 지나면 이전에 만든 파일을 까먹고, 규칙을 무시하며, 본인이 짠 코드를 덮어씀
- 이는 사용자 잘못이 아닌 Claude Code의 구조적 한계 - "Context Rot"

### 2. 바이브코딩의 한계 (0:38-0:59)
[바로가기](https://www.youtube.com/watch?v=oU-BbX0Om4I&t=38s)

- 처음엔 잘 되니까 계속 시키지만, 프로젝트가 커지면 컨텍스트가 터지면서 버그 쏟아짐
- 악순환으로 인해 "AI 코딩은 프로토타입까지만"이라는 인식 형성

### 3. GSD 소개 (0:59-1:42)
[바로가기](https://www.youtube.com/watch?v=oU-BbX0Om4I&t=59s)

- GSD(Get Shit Done): Claude Code 위에 설치하는 메타프롬프팅 시스템
- 설치: 터미널에서 `npx gsd-init` 한 줄이면 끝
- 제작자 철학: "나는 솔로 개발자다. 코드를 안 짠다. 클로드 코드가 짠다"

### 4. 5단계 워크플로우 (1:42-3:25)
[바로가기](https://www.youtube.com/watch?v=oU-BbX0Om4I&t=102s)

- **1단계 (질문)**: `/gsd new-project` → 기술 스택, 제약 조건, 엣지 케이스 질문
- **2단계 (논의)**: `/gsd discuss-phase` → 레이아웃, 에러 처리 방식 등 모호한 부분 구체화
- **3단계 (계획)**: `/gsd plan-phase` → 라이브러리 리서치, XML 형식 계획서 생성, 자체 검증
- **4단계 (실행)**: `/gsd execute-phase` → 웨이브 기반 병렬/순차 실행, 서브 에이전트 활용
- **5단계 (검증)**: `/gsd verify-work` → 코드 존재 확인, 테스트 통과 여부, 사용자 직접 확인

### 5. GSD의 3가지 핵심 원리 (3:25-4:53)
[바로가기](https://www.youtube.com/watch?v=oU-BbX0Om4I&t=205s)

- **컨텍스트 격리**: 팀장(오케스트레이터)은 교통 정리만, 팀원(서브 에이전트)은 각자 담당 부분만 처리
- **구조화된 전달**: 채팅 히스토리 대신 project.md, requirements.md, state.md 등 마크다운 파일만 전달
- **원자적 계획**: 하나의 계획서가 하나의 서브 에이전트 컨텍스트 안에서 완결될 수 있는 크기로 쪼개기

### 6. 컨텍스트 엔지니어링 (4:53-6:00)
[바로가기](https://www.youtube.com/watch?v=oU-BbX0Om4I&t=293s)

- GSD가 진짜 해결하는 건 AI와 인간 사이의 커뮤니케이션 문제
- **프롬프트 엔지니어링**: "어떻게 말하냐"의 문제
- **컨텍스트 엔지니어링**: "무엇을, 언제, 얼마나 보여주냐"의 문제 - 차원이 다름

### 7. GSD 없이도 가져갈 3가지 원칙 (6:00-6:43)
[바로가기](https://www.youtube.com/watch?v=oU-BbX0Om4I&t=360s)

- **첫째**: 대화를 줄이고 문서를 늘리기 (CLAUDE.md, 스킬 파일 활용)
- **둘째**: 큰 작업은 쪼개서 시키기 (원자적으로 시키면 컨텍스트 넘칠 일 없음)
- **셋째**: 검증을 자동화하기 (테스트 코드 먼저 짜고 구현 맡기기)

## 주요 인용구

> "클로드 코드 쓰시는 분들이 경험 있으실 거예요. 처음엔 천재예요. 파일 구조 파악하고 코드 짜고 테스트까지 알아서 해요. 근데 한 시간쯤 지나면 갑자기 아까 만든 파일을 까먹어요."

> "이거 여러분 잘못이 아닙니다. 클로드 코드의 구조적 한계예요. 이름이 있어요. 컨텍스트 롯이라고 합니다."

> "GSD는 코드를 대신 짜 주는 도구가 아니에요. 클로드 코드가 잘 짜게 만드는 도구예요. 컨텍스트를 관리해 주는 거예요."

> "프롬프트 엔지니어링은 어떻게 말하냐의 문제였잖아요. 컨텍스트 엔지니어링은 무엇을 언제 얼마나 보여주냐의 문제예요."

> "윈도우가 아무리 커져도 쓰레기를 많이 넣으면 쓰레기가 나오거든요. 무엇을 넣느냐가 항상 핵심이에요."
