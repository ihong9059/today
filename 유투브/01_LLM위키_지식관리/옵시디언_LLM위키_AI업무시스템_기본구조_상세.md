## 한 줄 요약

카파시(Karpathy)가 소개한 **LLM Wiki** = "AI가 관리하는 나만의 업무 위키". 옵시디언(마크다운·파일 기반) 볼트에 **4폴더 구조(source / wiki / agent.md / output)**를 만들고, 원본은 source에 모아 AI가 주제별 wiki 문서로 정리·연결·업데이트하게 하면, **매번 업무 맥락을 설명할 필요 없이** 메모가 실제 업무 결과물(보고서·기획안)로 이어진다.

### 2. 왜 노트앱은 "지식 무덤"이 되는가 — 3가지 비용 (00:50 - 01:50)
[바로가기](https://www.youtube.com/watch?v=UbxFpDuWt8Q&t=50s)

#### 핵심 메시지
"두 번째 뇌"를 만들고 싶어 했지만 대부분의 노트앱은 **지식 무덤**이 된다 — 입력·검색·유지 3가지 비용 때문.

#### 상세 내용
- **입력 비용**: 자료를 일일이 정리해서 넣어야 함
- **검색 비용**: 저장한 것 같은데 필요할 때 못 찾음
- **유지 비용**: 새 자료 ↔ 기존 노트 연결, 오래된 내용 업데이트, 중복 정리에 큰 노력
- 결과: "나중에 읽겠다"고 밀어둔 자료 창고 — **"문제는 그 '나중'이 거의 오지 않는다는 것"**

#### 주요 발언
> "대부분의 노트앱은 시간이 지나면 두 번째 뇌가 아니라 지식 무덤이 되었습니다." (01:05)

### 3. AI가 바꾼 구조 + 마크다운·옵시디언의 강점 (01:50 - 03:13)
[바로가기](https://www.youtube.com/watch?v=UbxFpDuWt8Q&t=110s)

#### 핵심 메시지
이제 사람이 직접 정리하지 않아도 AI가 읽고·요약하고·분류하고·연결하고·결과물로 바꿔준다. 단, 조건 = **AI가 잘 읽을 수 있는 형식(마크다운)으로 저장**되어 있어야 한다.

#### 상세 내용
- 마크다운 = 사람과 AI가 모두 읽기 쉬운 구조화 텍스트
- 노션·에버노트: 화면은 예쁘지만 내부 구조가 **앱에 의존**
- 옵시디언: **폴더 + 텍스트 파일 기반** → AI 에이전트가 폴더 읽기·파일 수정·새 문서 생성·기존 문서 연결이 훨씬 쉬움
- 비유: 기존 노트앱 = "사람이 보기 좋은 정리함" / 옵시디언 = **"사람도 AI도 읽고 이해하는 지식 작업장"**

#### 주요 발언
> "기존 노트앱은 사람이 보기 좋은 정리함에 가까웠다면, 옵시디언은 사람도 AI도 읽고 이해할 수 있는 지식 작업장에 가깝습니다." (02:48)

### 5. 시작 순서 6단계 — 4폴더 구조 (03:51 - 06:29)
[바로가기](https://www.youtube.com/watch?v=UbxFpDuWt8Q&t=231s)

#### 핵심 메시지
새 볼트 1개 + 폴더 4개(**source / wiki / agent.md / output**)로 시작. 핵심 원칙 = **source 원본은 절대 수정하지 않는다**.

#### 상세 내용
1. **새 볼트 생성**
2. **폴더 4개 생성**:
   - `source/` — 원본 자료 (회의록, 리서치, 프로젝트 문서, 기획 초안, 기사, PDF). **원본 불변 원칙** — 원본이 바뀌면 AI가 어떤 자료를 근거로 정리했는지 추적 불가
   - `wiki/` — LLM이 정리한 결과물 = "AI가 정리한 지식 백과사전"
   - `agent.md` — AI가 지켜야 할 규칙 (정리 방식·출처 기록 방식·업데이트 방식) → 일관된 결과물
   - `output/` — 업무 결과물
3. **source에 원본 투입** — 처음부터 많이 넣을 필요 없음 (회의록 3 + 보고서 3 + 기획 초안 1이면 충분)
4. **최초 정리 요청**: "source 폴더의 자료를 읽고 wiki 폴더에 주제별 문서를 만들어 줘. 중복 내용은 합치고, 중요한 결정 사항과 업무 기준은 따로 정리해 줘."
5. **증분 업데이트 요청**: "새로 추가한 source 자료를 읽고 기존 wiki 문서 중 업데이트가 필요한 문서를 수정해 줘. 새로운 개념이 있으면 새 문서를 만들고 관련 문서와 링크로 연결해 줘."
6. **결과물 요청**: "wiki 내용 바탕으로 회의 공유용 요약본 만들어 줘" / "기획 방향성 문서 참고해 임원 보고 1페이지 보고서 만들어 줘"

#### 주요 발언
> "source 폴더의 원본 자료는 절대 수정하지 않습니다. 원본이 바뀌면 나중에 AI가 어떤 자료를 근거로 정리했는지 추적하기 어려워지기 때문입니다." (04:38)

### 6. 실전 활용 — 신규 프로젝트 기획 예시 (06:29 - 07:46)
[바로가기](https://www.youtube.com/watch?v=UbxFpDuWt8Q&t=389s)

#### 핵심 메시지
사람은 **판단과 편집**, AI는 **반복 정리와 연결** — 역할 분담이 LLM Wiki의 운영 모델.

#### 언급된 사례/에피소드
- **신규 프로젝트 기획**: source에 회의록·리서치·시장조사·프로젝트 문서·기획 초안·기사 PDF 투입 → "프로젝트 개요 / 문제 정의 / 경쟁사 비교 / 핵심 의사결정 / 리스크 요인으로 정리해 줘" → wiki에 5개 md 생성
- 이후 활용: "wiki 참고해서 1페이지 기획안 초안" / "경쟁사 비교 문서 참고해서 우리 서비스 차별화 포인트 5개" — **AI가 쌓아둔 지식 구조를 계속 참고**하므로 가능
