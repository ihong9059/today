## 구간별 상세 내용

### 1. 문제 제기 - 메모 2,000개의 비극 (00:00-01:50)
[바로가기](https://www.youtube.com/watch?v=blnnF9ubEVo&t=0s)

#### 핵심 메시지
AI로 매일 무수한 콘텐츠를 만들지만, 정리 없이는 토큰만 소모하고 결과물 질도 떨어진다. 개인용 RAG 시스템이 필수적이다.

#### 상세 내용
- AI로 매일 콘텐츠를 만들고 있지만, 정리가 안 된 상태에서 AI에게 작업을 요청하면 자료를 찾아 헤매며 토큰을 과다 소비
- 토큰이 아깝다고 화면 여러 개 띄워놓고 무엇이든 만들려 하지만, 체계 없이 쌓이면 건강(사용자)과 AI 건강(토큰 효율) 모두 해침
- 이를 해결하려면 RAG(Retrieval-Augmented Generation) 시스템이 필요
- 일반 RAG는 벡터 데이터베이스 구축 필요 → 복잡하고 비용이 큼 → 개인에게는 부담

#### 주요 발언
> "이게 우리들 현실 아닙니까, 여러분? AI로 무수히 많은 콘텐츠를 만들고 있죠."

> "정리가 안 돼 있으면요. 찾아 헤매다가 토큰을 정말 많이 쓰게 되거든요."

> "여러분들만의 시스템을 잘 갖춰 놓지 않으면 토큰 소모는 늘어나고 작업 결과물의 질은 떨어질 수밖에 없습니다."

### 2. 도서관 비유 - 3단계 폴더 구조 (02:10-04:30)
[바로가기](https://www.youtube.com/watch?v=blnnF9ubEVo&t=130s)

#### 핵심 메시지
도서관의 창고-서가-안내데스크 비유로 3단계 폴더 구조(Raw/Wiki/Master Index)를 설명. 마크다운 파일 기반으로 AI가 읽고 쓸 수 있는 형태.

#### 상세 내용
- **Raw (창고)**: 콘텐츠가 생기면 무조건 넣는 곳. 웹 자료, 과거 작업물, 메모 등 모든 원본 저장
- **Wiki/Docs (서가)**: 잘 정돈된 데이터를 관리하기 쉽고 읽기 쉽게 보관하는 공간. AI가 Raw에서 문서를 가져와 정리해서 구축
- **Master Index (리셉션 데스크)**: 새 세션이나 다른 AI 모델이 오면 바로 파일로 가는 게 아니라, 먼저 안내 데스크에서 파일 위치를 확인. 인덱스 파일로 문서 검색 효율화
- 세 개의 공간 = 세 개의 폴더
- 마크다운으로 작업 → 모든 AI가 마크다운을 읽고 쓸 수 있음

#### 언급된 사례/에피소드
- **도서관 비유**: 창고(Raw) → 서가(Docs) → 리셉션 데스크(Master Index)로 직관적 설명
  - 시사점: 복잡한 RAG 개념을 누구나 이해할 수 있는 비유로 풀어냄

#### 주요 발언
> "컨텐츠가 생기면 무조건 이쪽에 넣으면 됩니다. 웹에서 찾은 자료도 넣고, 과거에 작업했던 것도 여기에 다 넣습니다."

> "리셉션 데스크 와서 내가 어떤 작업을 하려고 하는데 그 파일이 어디에 있습니까라고 물어봐야 되거든요."

### 3. 같은 폴더, 두 개의 창 - VS Code + 옵시디언 (04:30-07:00)
[바로가기](https://www.youtube.com/watch?v=blnnF9ubEVo&t=270s)

#### 핵심 메시지
VS Code는 AI(Claude Code)가 작업하는 공간, 옵시디언은 사람이 편안하게 읽고 관리하는 공간. 하나의 폴더를 두 도구가 동시에 바라본다.

#### 상세 내용
- **옵시디언**: 마크다운 파일을 읽고 쓰는 로컬 기반 노트 에디터. 서버가 아닌 로컬 컴퓨터 베이스
- **VS Code**: 클로드 코드와 연동되어 코딩 작업뿐 아니라 모든 AI 에이전트의 작업 공간
- 핵심: 하나의 폴더를 VS Code와 옵시디언이 동시에 열고 있음
- 옵시디언 = 사람이 읽고 관리하는 도구
- VS Code = 컴퓨터(AI)를 위한 도구
- Claude Code에서 "개인 지식 시스템을 구축하려고 한다"라고 맥락을 주면, AI가 정확히 의도를 파악

#### 언급된 사례/에피소드
- **실시간 데모**: Claude Code에서 폴더 구조 생성 명령 → VS Code 좌측에 Raw/Docs/Index.md 자동 생성 → 옵시디언에서도 동일하게 확인
  - 시사점: 한 쪽에서 변경하면 다른 쪽에서도 즉시 반영되는 양방향 동기화

#### 주요 발언
> "옵시디언에서 읽는 목적은 편안하게 읽을 수 있고 관리할 수 있는 목적이고요. 비주얼 스튜디오 코드는 컴퓨터를 위한 도구다."

### 4. Raw -> Wiki -> Master Index 실전 데모 (07:00-11:30)
[바로가기](https://www.youtube.com/watch?v=blnnF9ubEVo&t=420s)

#### 핵심 메시지
CLAUDE.md를 통해 폴더별 AI 작업 규칙을 설정하고, "정리해 줘" 한 마디로 전체 워크플로(Raw 분석 → Docs 생성 → Index 업데이트)가 자동 실행된다.

#### 상세 내용
- **CLAUDE.md의 역할**: 클로드 코드가 각 폴더에서 작업할 때 가장 먼저 읽는 파일. 일종의 작업 매뉴얼
- **Raw 폴더 CLAUDE.md 규칙**:
  - 이 폴더의 목적은 원본을 보관하는 곳
  - 절대 규칙: 원본 내용을 임의로 수정하지 않는다
  - 요약/재구성은 Docs에서만 한다. 여기서는 저장만
  - 최소화된 프론트 매터 스키마 제공
  - 워크플로(작업 흐름) 설명 포함
- **Docs 폴더 CLAUDE.md 규칙**:
  - 목적: 재사용 가능한 지식. 원본을 소화해 내 언어로 재구성하는 곳
- **옵시디언 호환 설정**:
  - 일반 링크 대신 위키 링크([[]])  사용
  - 각 노트 상단에 YAML 프론트 매터 (태그, 소스, 생성일 등)
- **테스트 실행**: 다양한 타입의 테스트 원본 4개 생성 (유튜브 관련, 유발 하라리 사피엔스 메모, 음성 메모 등) → "정리해 줘" 명령 → 자동으로 Docs + Index.md 업데이트
- 파일명을 잘 만드는 것이 중요: AI가 파일을 파악할 때 파일명을 제일 먼저 봄

#### 언급된 사례/에피소드
- **유발 하라리 사피엔스 메모**: 책을 읽으면서 휘갈겨 쓴 메모를 Raw에 넣는 예시
  - 시사점: 정형화되지 않은 원본도 AI가 정리 가능
- **음성 메모 변환**: 음성 메시지도 Raw에 넣을 수 있음
  - 시사점: 텍스트 외 다양한 형태의 입력 지원
- **유튜브 AI 콘텐츠 기획 문서**: Raw의 유튜브 관련 원본 → Docs에 정리된 기획 문서로 변환
  - 시사점: 실제 작업 워크플로 시연

#### 주요 발언
> "CLAUDE.md는 폴더 폴더마다 만들 수 있고, 클로드 코드가 각 폴더에 무슨 일을 할 때 가장 먼저 읽는 파일입니다. 일종의 작업 매뉴얼 같은 거죠."

> "이 폴더의 목적은 원본을 보관하는 곳이다. 절대 규칙: 원본 내용을 임의로 수정하지 않는다."

> "어떤 AI가 와도 이 폴더에는 요걸 따라라."

### 5. 토큰 절약 + 세컨드 브레인 구축 (11:30-13:30)
[바로가기](https://www.youtube.com/watch?v=blnnF9ubEVo&t=690s)

#### 핵심 메시지
옵시디언 그래프 뷰로 문서 간 연결을 시각화하고, 문서가 쌓일수록 세컨드 브레인으로 발전한다. 폴더를 늘리고 각각에 CLAUDE.md를 두면 AI에게 폴더별 역할을 지정 가능.

#### 상세 내용
- 옵시디언 그래프 뷰에서 인덱스 문서, Docs, 리드미 등의 연결 구조를 시각적으로 확인
- VS Code(AI 작업)와 옵시디언(사람 작업)이 계속 서로 연동되면서 작업이 점점 구조화
- 문서가 쌓일수록 "세컨드 브레인" 구축
- Raw/Docs 두 개 폴더에서 시작하지만, 필요에 따라 폴더 확장 가능
- 각 폴더에 CLAUDE.md로 AI 에이전트에게 "교통 정리" 가능
- 가장 상위 폴더에도 CLAUDE.md를 두어 전체 가이드라인 제공 가능

#### 주요 발언
> "이게 여러분의 세컨드 브레인이 될 수 있는 거고요."

> "각각의 폴더는 CLAUDE.md라고 하는 가이드라인을 통해서 AI 에이전트에게 교통 정리를 시킬 수가 있는 겁니다."

### 6. 옵시디언 커스터마이징 + 마무리 (13:30-14:32)
[바로가기](https://www.youtube.com/watch?v=blnnF9ubEVo&t=810s)

#### 핵심 메시지
옵시디언은 CSS로 전체 스타일링이 가능하며, 작업 환경을 세팅하면 AI가 스스로 공간을 관리하는 작업 파트너가 된다.

#### 상세 내용
- 옵시디언 테마 색상 변경 가능 (연사는 클로드 사랑으로 주황색 선호)

- 폰트 커스터마이징 (연사는 명조체 선호)
- 무수히 많은 플러그인과 기능 존재
- 핵심은 도구 자체가 아니라 "어떻게 체계적으로 하는 그릇을 만들 것이냐"
- 다음 영상에서 더 깊은 내용 예고

#### 주요 발언
> "가장 핵심은 바로 이겁니다. 얘를 어떻게 체계적으로 하는 그릇을 만들 것이냐."

> "작업 환경을 딱 세팅해 놓으시면 AI가 스스로 그 공간을 관리하면서 여러분들의 작업 파트너 기능을 할 것 같습니다."
