## 한 줄 요약

업무 AI의 가장 큰 병목은 **AI 성능이 아니라 "AI에게 줄 맥락이 흩어져 있다는 것"** — 해법 = 매번 맥락을 설명하는 대신 **AI가 참고할 맥락 저장소(LLM Wiki)**를 만드는 것. 4요소(source/wiki/output/agent.md) + 4단계 프로세스(투입→정리→증분 업데이트→결과물)는 1편과 동일하되, "1회성 대화 vs 누적 구조" 대비와 **도구 독립성**(ChatGPT→Claude→무엇이 와도 자료 구조는 영속) 논리가 강화된 정제판.

### 1. 도입 — "왜 내가 AI를 교육시키고 있지?" (00:00 - 01:54)
[바로가기](https://www.youtube.com/watch?v=RWDBO_KNPlc&t=0s)

#### 핵심 메시지
"그 자료 어디 있지? 지난 회의 결론이 뭐였지?" — 메일함·카톡·슬랙·노션·드라이브를 뒤지다 정작 일은 시작도 못 한 채 지친다. AI를 써도 내 업무·상황·지난 결정·정리해 둔 자료를 모르니 **매번 설명**해야 한다.

#### 상세 내용
- AI 도입 초기 기대(일이 빨라질 것) vs 현실(AI가 내 업무를 모름 → 교육 비용)
- 핵심 명제: AI를 잘 쓰는 사람 = 질문을 잘하는 사람이 아니라 **AI가 참고할 자기만의 업무 지식 시스템을 가진 사람**
- 가장 현실적인 조합 = 옵시디언 + LLM Wiki

#### 주요 발언
> "AI를 쓰고 있는데 왜 내가 AI를 교육시키느라 시간을 쓰고 있지?" (00:54)

### 2. 기존 노트앱의 3가지 문제 (01:54 - 03:00)
[바로가기](https://www.youtube.com/watch?v=RWDBO_KNPlc&t=114s)

#### 핵심 메시지
노션·에버노트·구글문서·메모앱·"카톡 나에게 보내기"까지 — 시간이 지나면 모두 자료 창고가 된다.

#### 상세 내용

- **문제 3 — 업데이트가 안 된다**: 새 자료가 예전 자료와 연결되지 않음 — 예전 메모는 그대로, 새 메모는 따로
- (1편의 입력·검색·유지 3비용과 같은 구조의 다른 표현)

### 3. AI 전제 조건 + 옵시디언의 강점 (03:00 - 04:08)
[바로가기](https://www.youtube.com/watch?v=RWDBO_KNPlc&t=180s)

#### 핵심 메시지
AI가 정리를 대신해 주는 시대 — 단, **AI가 잘 읽을 수 있는 형태로 저장**되어 있어야 하며, 그 지점에서 옵시디언(로컬 폴더 + 마크다운 파일)이 강하다.

#### 상세 내용
- 옵시디언은 내 컴퓨터 폴더 안에 마크다운 파일로 저장 → AI가 읽기 쉬움
- 기존 노트앱 = "사람이 보기 좋은 정리함" / 옵시디언 = "사람과 AI가 같이 일하는 지식 작업장"
- 질문 잘하는 법만큼 **"AI가 참고할 자료를 어떻게 쌓아둘 것인가"**가 중요해짐

### 4. LLM Wiki = 맥락 저장소 — 1회성 대화와의 대비 (04:08 - 05:18)
[바로가기](https://www.youtube.com/watch?v=RWDBO_KNPlc&t=248s)

#### 핵심 메시지
LLM Wiki = "AI가 계속 참고하고 업데이트할 수 있는 나만의 업무 데이터베이스". 보통의 AI 사용은 **매번 새로 시작하는 방식**, LLM Wiki는 **지식이 쌓이고 연결되고 재사용되는 구조**.

#### 상세 내용
- 1회성 패턴: 자료 붙여넣기 → 질문 → 답변 → 대화 끝 → 다음 주에 또 자료 붙여넣기
- LLM Wiki 패턴: 한곳에 모음 → AI가 주제별 문서 정리 → 새 자료를 기존 문서와 연결·업데이트 → 위키 기반 결과물 생성
- **핵심**: 매번 맥락 설명 ✗ → **맥락 저장소 구축** ✓

#### 주요 발언
> "AI와의 대화가 일회성으로 끝나는 게 아니라 내 업무 지식이 계속 쌓이고 연결되고 재사용되는 구조가 되는 거죠." (04:57)

### 5. 구조 4요소 + 실제 프로세스 4단계 (05:18 - 08:52)
[바로가기](https://www.youtube.com/watch?v=RWDBO_KNPlc&t=318s)

#### 핵심 메시지
새 볼트 + 4요소(source / wiki / output / agent.md)로 시작 — 1편과 동일 구조의 재정리 + agent.md 규칙 예시가 더 구체화.

#### 상세 내용
- **source/**: 원본 (회의록·보고서·기사·PDF·리서치). **가능한 수정 금지** — AI 정리 근거 추적
- **wiki/**: AI가 정리한 지식 문서 — "소스가 재료 창고라면 위키는 업무 백과사전"
- **output/**: 보고서 초안, 회의 공유용 요약본, 업무 매뉴얼
- **agent.md**: AI 업무 지시서 — 예시 규칙 3개: "원본 자료는 수정하지 말 것 / 새 문서를 만들 때는 출처를 남길 것 / 중복되는 내용은 합칠 것"
- **프로세스**: ① 원본 투입 (회의록 3 + 보고서 1 + 기획 초안 1이면 충분) → ② 최초 정리 요청 (+ "각 문서에 참고한 원본 자료를 표시해 줘" — 1편 대비 추가) → ③ 증분 업데이트 ("새 자료만 따로 요약하는 게 아니라 기존 지식 구조에 연결") → ④ 결과물 요청 ("임원 보고용 1페이지 기획안" / "차별화 포인트 5개")
- 역할 분담: 사람 = 방향·판단·편집 / AI = 반복 정리·연결·초안 생성

#### 언급된 사례/에피소드
- **신규 서비스 기획**: source 투입 → wiki에 6문서 자동 생성 (프로젝트 개요 / 문제 정의 / 타겟 고객 / 경쟁사 비교 / 핵심 의사결정 / 리스크 요인)

### 7. 정리 — 병목은 AI 성능이 아니다 (10:51 - 12:11)
[바로가기](https://www.youtube.com/watch?v=RWDBO_KNPlc&t=651s)

#### 핵심 메시지
업무 AI의 가장 큰 병목 = **AI에게 줄 맥락이 흩어져 있다는 것** (자료는 여기저기, 결정은 회의록 속에, 아이디어는 메모앱에). LLM Wiki가 그 해법 구조.

#### 주요 발언
> "업무에서 AI를 쓰다 보면 가장 큰 병목은 AI의 성능이 아니라 AI에게 줄 맥락이 흩어져 있다는 겁니다." (10:54)

> "앞으로 AI를 잘 쓰는 사람은 단순히 프롬프트를 잘 쓰는 사람이 아닐 가능성이 큽니다. AI가 계속 참고할 수 있는 자기만의 지식 시스템을 가진 사람일 가능성이 크죠." (11:39)
