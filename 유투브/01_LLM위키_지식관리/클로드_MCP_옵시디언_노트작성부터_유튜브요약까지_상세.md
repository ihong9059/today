### 3. MCP란 무엇인가 (Model Context Protocol) (3:40-5:35)
[바로가기](https://www.youtube.com/watch?v=NQYzjrJ7jKY&t=220)

#### 핵심 메시지
MCP는 **공용어(프로토콜)**. 한국인·일본인·미국인이 공용어를 쓰면 언어 장벽이 사라지듯, MCP 서버 하나면 ChatGPT·Claude·Grok·Gemini 등 모든 LLM과 소통 가능.

#### 상세 내용
- **언어 비유**: 한국어/영어/일어 각각 배우는 대신 공용어 1개
- **Notion 예시**: 원래는 Claude/GPT/Gemini 각각의 방식대로 따로 통합 필요 → MCP로 1번 만들면 모두 사용 가능
- **24핀/마이크로 5핀 USB 통합 비유** (휴대폰 충전기 단자 통합 역사)
- **Google A2A (Agent-to-Agent)** 프로토콜도 같은 결의 시도로 언급
- 커뮤니티 형성 → 다양한 개발자들이 도구를 쏟아내는 효과

#### 언급된 사례/개념
- **MCP = Model Context Protocol** (모델 컨텍스트 프로토콜)
- **Google A2A**: 며칠 전 발표된 에이전트 간 프로토콜
- **CMD스페이스 어벤져스**: 민이 운영하는 메모리/RAG/페르소나별 시스템 구축 프로젝트

#### 주요 발언
> "한국인 일본인 미국인이 있다고 하면 제가 이 셋과 소통하기 위해서는 한국어도 알아야 되고 영어도 알아야 되고 일본어도 알아야 되잖아요. 근데 이렇게 하면 제가 알아야 되는 언어들이 너무 많아지고... 이것을 쉽게 만들기 위해서 우리가 공용어를 만들자라고 생각하는 게 프로토콜."

> "이렇게 규약이 정해지는 만큼 그 커뮤니티가 형성될 수 있다라는 게 큰 장점."

### 6. Obsidian MCP 설치 절차 (10:30-13:50)
[바로가기](https://www.youtube.com/watch?v=NQYzjrJ7jKY&t=630)

#### 핵심 메시지
GitHub README의 JSON 스니펫을 복사 → Claude Desktop 설정 편집기에 붙여넣기 → 옵시디언 vault 경로(인자) 추가 → 앱 재시작.

#### 상세 내용

**설치 단계**:
1. GitHub Obsidian MCP README의 `MCP Servers` JSON 스니펫 복사
2. Claude Desktop 켜기 → 좌측 상단 **설정**
3. **개발자** 탭 → **설정 편집** → 텍스트 편집기로 열기
4. 빈 중괄호 `{}` 안에 복사한 내용 붙여넣기
5. **인자(args)에 옵시디언 vault 경로** 추가
6. Claude Desktop 종료 후 재실행 → 우측 하단 망치 모양 도구 아이콘 확인

**Mac 경로 복사 꿀팁** (요한이 처음 알았다고 놀란 트릭):
- Finder → 옵시디언 vault 폴더 우클릭
- **Option 키** 누른 상태로 드롭다운 보기 → "**경로 이름 복사**" 메뉴 표시됨
- Windows의 경우 탐색기에서도 비슷한 기능 존재

#### 언급된 사례/에피소드
- **점점점(...) 메뉴 → Reveal in Finder**: 옵시디언 노트의 실제 경로 찾는 법
- **Option 키 + 우클릭**: 숨겨진 메뉴 활성화

#### 주요 발언
> "옵션 키를 한 번 눌러 보시겠어요? 그러면 이제 밑에 '경로 이름 복사'가 있습니다. 요런 기능이 매개에 숨어 있습니다." (요한)

> "전혀 몰랐어요. 우리 개발자가 알려드리네요. 감사합니다."

### 7. Obsidian MCP의 기본 기능 (Tool 목록) (13:50-15:55)
[바로가기](https://www.youtube.com/watch?v=NQYzjrJ7jKY&t=830)

#### 핵심 메시지
Obsidian MCP가 제공하는 도구는 ~12개. 그중 **Edit**가 핵심 — 위치를 모른 채로도 헤딩을 찾아 수정 가능.

#### 상세 내용

**Obsidian MCP 도구 목록**:
| 도구 | 기능 |
|------|------|
| **add-tag** | YAML frontmatter에 태그 추가 |
| **remove-tag** | 태그 제거 |
| **rename-tag** | 태그 이름 변경 |
| **create-directory** | 폴더 생성 |
| **create-note** | 파일 생성 |
| **delete-note** | 파일 삭제 |
| **edit** ★ | 위치 자동 탐색 후 수정 (가장 강력) |
| **list-vaults** | 여러 vault 사용자용 vault 목록 |
| **move-note** | 파일 이동 |
| **read** ★ | 마크다운 파일 내용을 Claude 컨텍스트로 가져옴 |
| **search** | vault 내 파일 검색 |

#### 언급된 사례/개념
- **Edit의 강점**: "어디를 수정할지 모르고서 수정하는 게 큰 장점" — 헤딩 번호나 내용으로 자동 탐색
- **Read = 즉석 RAG**: "RAG는 아니지만 MD 임베딩, 자연어 검색 가능"
- **GitHub URL을 LLM에 넣고 직접 물어보기 팁**: 도구 설명을 LLM이 자동 분석 (커서 활용 사례)

#### 주요 발언
> "Edit 중에 예를 들어서 헤딩 여러 개가 있는데 이 중에서 몇 번째 헤딩 이렇게 말해도 되고, 아니면 어떤 내용으로 어떤 헤딩 내용을 수정해 줘 라고 하면 그 내용을 찾아서 수정해 주기 때문에..."

### 8. 데모 1 — "아인슈타인이 추천하는 점심 메뉴" 노트 생성 (15:55-19:15)
[바로가기](https://www.youtube.com/watch?v=NQYzjrJ7jKY&t=955)

#### 핵심 메시지
기능 명시 없이 "옵시디언 노트로 만들어 줘" 한 마디만으로 자동으로 create-note 호출. Claude는 MCP 호출에 대해 무조건 사용자 허용을 받는 구조.

#### 상세 내용

**데모 시나리오**:
1. "오늘 점심 메뉴를 아인슈타인이 추천해 주는 걸로 해줘" → 한국에서 먹기 힘든 메뉴 추천
2. "이걸 노트로 추가해 볼까요?" → "옵시디언 노트로 만들어 줘"
3. Claude가 자동으로 `create-note` 도구 호출 → 사용자 허용 클릭
4. `Cmd+5` 누르면 옵시디언 최신 파일에 노트 생성 확인

**MCP 허용 정책 비교**:
| 클라이언트 | 허용 방식 |
|-----------|----------|
| **Claude Desktop** | 무조건 허용 받아야 함 (예측 가능한 작업 보장) |
| **Cursor / n8n** | 클라이언트 SDK 수정으로 자동화 가능 |

**업그레이드 데모**:
- "야물 프론트 매터를 사용해서 값들을 추천해 줘. 필드명은 네가 알아서"
- Claude가 자동으로 `edit` 호출 → filename, 평점, 분류 등 추가
- → "옵시디언은 Open World DB 같은 느낌"

#### 언급된 사례/개념
- **YAML Frontmatter 활용**: "스위스에서 먹는 점심들만 모아봐", "30점 이상만 모아봐" 식의 쿼리 가능
- **DataView 플러그인 활용 가능성** (간접 시사)

#### 주요 발언
> "옵시디언은 사실은 굉장히 Open World DB 같은 느낌이거든요. 모든 마크다운 파일을 다 DB로 쓸 수 있기 때문에 요렇게만 만들어 놓으면 나중에 할 수 있는 것들이 많습니다."

### 9. 데모 2 — Wiki Link 자동 연결 ([[]] 트릭) (19:15-22:10)
[바로가기](https://www.youtube.com/watch?v=NQYzjrJ7jKY&t=1155)

#### 핵심 메시지
"중요한 키워드와 메뉴명은 `[[ ]]`로 감싸 줘"라고 프롬프트하면 자동으로 옵시디언 위키 링크가 만들어져, 그래프 뷰에서 즉시 노드 연결 형태로 시각화됨.

#### 상세 내용

**프롬프트 예시**: "중요한 키워드와 메뉴명은 `[[키워드]]` 식으로 만들어 주라"

**확인 절차**:
- `Cmd+P` (Mac) → "로컬" / "그래프 뷰" 검색
- 필터 → 태그 보기

**결과 시각화**:
- "아인슈타인의 점심 식사 메뉴 추천" 노트 → "물리학", "미각의 대비", "허물 운동" 등 자동 연결 노드 생성
- 다음에 "물리학"으로 검색하거나 그래프 뷰 탐색 시 즉시 발견 가능

**핵심 철학** (요한):
> 옵시디언은 노트에 들어오는 **경로를 다양화**시켜 놓는 게 중요하다.

여러 키워드/태그/노트 연결을 통해 옛 기억에 접속할 수 있는 가능성을 늘리는 것.

#### 주요 발언
> "옵시디언은 노트에 들어오는 경로들을 다양화시켜 놓는 게 중요해요. 여러 가지 키워드들을 이렇게 태그나 노트 연결들로 열어 놓으시면 언제든지 우리의 옛 기억들에 접속할 수 있는 가능성이 많아집니다."

- "물리학에서 부조" 입력 → 양식대로 정리된 노트 생성
- 마지막 섹션 "관련 개념"에 다음 공부할 키워드 자동 제안
- 그 키워드를 복사해서 다시 입력 → 연쇄 학습

**향후 확장 (MCP Prompt 기능)**:
- MCP 기본 규격에 **Prompt** 기능 존재 (현재 Claude 클라이언트 미구현)
- 구현 시 슬래시(/) → 프롬프트 리스트 → 선택 가능 예상
- 버전별 프롬프트 관리 가능

**대안**: 프로젝트 첨부 파일에 템플릿 넣어두기 (현재도 가능)

#### 주요 발언
> "이게 너무 좋은 게 양식들을 미리 만들어 놓으시면 내가 원하는 형태로 강제할 수가 있어요. 언어 모델 잘 쓰는 방법 중에 하나."

> "Claude가 최종 첨삭하게 해서 용어 정리해 놓는 거 정말 추천드립니다."

#### 주의사항 (영상 내 언급)
- 한글-영어 띄어쓰기 등 출력 스타일 보정은 시스템 프롬프트로 별도 강제 필요

### 11. Raycast 익스텐션으로 MCP 에이전트 자동 전환 (25:30-27:30)
[바로가기](https://www.youtube.com/watch?v=NQYzjrJ7jKY&t=1530)

#### 핵심 메시지
손현호가 만든 **Raycast 익스텐션**으로 Claude의 MCP config 파일을 시나리오별로 덮어쓰기. "사용 중인 MCP만 열어둬야 오류가 적다"는 운영 노하우.

#### 상세 내용

**문제**:
- 모든 MCP 서버를 켜둘 경우 의도와 다른 도구 호출 발생
- 옵시디언만 해도 Obsidian-MCP / MCP-Obsidian 두 개 존재 → Claude가 어떤 걸 쓸지 애매해짐
- 측정한 도구만 열어두는 게 정답

**해결 — 손현호의 Raycast 익스텐션**:
- MCP config 파일을 시나리오별로 자동 덮어쓰기
- 에이전트(시스템 인스트럭션 + 사용 가능 툴 조합)를 빠르게 전환
- "AI Behind"(채널) 멤버십에서 공개 예정

**철학**:
> MCP의 핵심은 "에이전트 만들기" — 시스템 인스트럭션 + 툴셋 조합

#### 주요 발언
> "MCP의 에이전트로 내가 강제하지 않으면 여러 가지 서버가 열려 있게끔 하면 좀 오류가 많죠. 원하지 않는 걸 호출하기도 하고요."

> "사실상 에이전트라고 생각해요. 시스템 인스트럭션을 만들어 놓고 거기에서 사용할 수 있는 툴들을 만들어 놓고 왔다 갔다 할 수 있으면 좋겠다."
