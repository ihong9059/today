### 2. AI 기억의 구조적 문제 (0:30-1:00)
[바로가기](https://www.youtube.com/watch?v=xjQ4K4j3joU&t=30s)

#### 핵심 메시지
AI와 대화하는 모든 사람이 겪는 구조적 문제 — 기억의 휘발성과 RAG의 한계

#### 상세 내용
- 새 대화를 열 때마다 같은 설명을 반복: "나는 이런 서비스를 만들고 있어", "내 상황은 이래"
- 이것은 개인만의 문제가 아닌 AI와 대화하는 모든 사람이 겪는 구조적 문제
- AI들은 대화가 끝나면 대부분의 기억을 잃음 — 지식이 쌓이는 게 아니라 매번 휘발
- 대부분의 AI는 이 문제를 RAG(Retrieval-Augmented Generation)로 해결
- RAG: 질문할 때마다 원본 문서를 처음부터 검색해서 관련 조각을 찾고 답변 생성

#### 언급된 사례/에피소드
- **일상적 반복 설명**: 매번 "나는 이런 서비스를 만들고 있어, 내 상황은 이래"를 반복해야 하는 비효율

#### 주요 발언
> "AI와 대화하는 모든 사람이 겪는 구조적 문제죠. 우리가 쓰는 AI들은 대화가 끝나면 대부분의 기억을 잃습니다. 지식이 쌓이는 게 아니라 매번 휘발됩니다."

### 3. 카파시의 LLM Wiki 아이디어 (1:00-2:55)
[바로가기](https://www.youtube.com/watch?v=xjQ4K4j3joU&t=60s)

#### 핵심 메시지
안드레이 카파시가 공개한 LLM Wiki는 RAG 대신 LLM이 직접 위키를 만들고 유지보수하는 시스템으로, "컴파일" 개념을 지식에 적용한 것이다.

#### 상세 내용
- 안드레이 카파시: 바이브 코딩이라는 용어를 만든 사람, AI 업계에서 가장 영향력 있는 엔지니어 중 한 명
- 4월 초 X(트위터)에 글을 올리고 GitHub에 "LLM Wiki"라는 아이디어 파일 공개
- 완성된 프로그램이 아닌 아이디어 파일이었지만, 며칠 만에 엄청난 주목
- **핵심 아이디어**: RAG처럼 매번 원본을 검색하는 대신, LLM이 직접 위키를 만들고 유지보수하게 하자
- **"컴파일" 개념**: 프로그래밍에서 코드를 실행 가능한 형태로 번역하는 작업을 지식에 적용 — 흩어진 원재료를 연결되고 탐색 가능한 위키 형태로 번역

##### 3개 레이어 구조
1. **Raw (원재료)**: 논문, 기사, 메모. 불변 — LLM은 읽기만 하고 절대 수정하지 않음. 지식의 원천
2. **Wiki**: AI가 전적으로 소유하는 마크다운 파일 디렉토리. 요약, 엔티티, 분석 파일. 사람은 읽기만. AI가 생성/업데이트/교차 참조 유지
3. **Schema**: CLAUDE.md 같은 설정 파일. AI에게 사용법을 알려주는 설계도

##### 3가지 핵심 작업
1. **Ingest**: 원재료를 넣으면 AI가 읽고, 요약 페이지를 쓰고, 인덱스를 업데이트하고, 관련 페이지 전체를 수정 — 정보를 "소화"하는 과정
2. **Query**: 위키에 질문을 던지면 관련 페이지를 찾아 근거 있는 답변을 합성. 좋은 답변은 다시 위키에 저장 가능
3. **Lint**: 주기적으로 위키 전체를 품질 검증 — 모순, 오래된 정보, 누락된 연결을 찾아냄

#### 언급된 사례/에피소드
- **카파시의 GitHub Gist**: LLM Wiki 아이디어 문서가 며칠 만에 큰 주목을 받음
- **유지보수 포기 문제**: 사람들이 지식 정리 작업을 포기하는 이유는 유지보수 부담이 가치보다 빨리 커지기 때문. AI는 게으르지 않으므로 유지보수 비용이 거의 0

#### 주요 발언
> "사람들이 지식 정리 작업을 포기하는 이유는 유지보수 부담이 가치보다 빨리 커지기 때문이에요. 쉽게 말해 귀찮기 때문이죠. 하지만 AI는 게으르지 않습니다. 즉 유지보수 비용이 거의 0이 되니까 위키를 실제로 유지할 수 있습니다."

### 4. "나"를 주제로 위키 만들기 (2:55-3:46)
[바로가기](https://www.youtube.com/watch?v=xjQ4K4j3joU&t=175s)

#### 핵심 메시지
대부분의 LLM Wiki 활용 사례는 논문/기사 정리이지만, 연사는 "나 자신"이라는 찾아도 안 나오는 정보를 기록하여 감정 없는 객관적 판단을 가능하게 했다.

#### 상세 내용
- 다양한 사례를 찾아봤으나, 대부분 논문 정리/트렌드 기사 기반 위키 — 리서치 프로젝트에는 맞지만 본인에게는 맞지 않음
- 카파시 본인도 논문 정리 위키로 사용 중
- 찾아도 안 나오는 정보 = "나에 대한 정보" — 어떤 서비스를 왜 만들었고, 거기서 뭘 느꼈는지, 개인적인 고민들과 사고 과정
- **목표**: 어떤 AI가 와도 이 위키 하나만 읽으면 즉시 나를 완벽히 이해할 수 있도록 "또 하나의 나"를 만드는 것
- **부가 효과**: 정보로만 재구성된 "나"이기 때문에 감정 없는 판단이 가능 — 그날의 기분이나 사사로운 감정에 휘둘리지 않고 기계적 사고 가능

#### 주요 발언
> "저는 찾아도 안 나오는 정보를 기록하고 싶었습니다. 그게 저에 대한 정보죠."

> "제가 오로지 정보로만 재구성되니까 감정 없는 판단이 가능해서요. 그날의 기분이나 사사로운 감정에 휘둘리지 않고 기계적인 사고가 가능합니다."

### 6. 실습 — 초기 세팅 (5:22-8:00)
[바로가기](https://www.youtube.com/watch?v=xjQ4K4j3joU&t=322s)

#### 핵심 메시지
옵시디언 설치부터 GitHub 연동, CLAUDE.md 작성까지 초기 세팅 과정. 원샷으로 완벽한 구조를 만들지 말고 쓰면서 진화시키는 것이 중요.

#### 상세 내용

##### 옵시디언 설정
1. 옵시디언 검색/다운로드 (무료)
2. 새 보관함 생성 → "세컨드"라고 이름 (보관함 = 폴더)
3. 외형 설정 → 테마 선택 (미니멀)
4. 커뮤니티 플러그인:
   - **Git 플러그인**: 폴더를 어디서나 꺼내 볼 수 있고 버전 관리 및 팀 공유 가능
   - **터미널 플러그인**: 옵시디언 내부에서 클로드 코드 실행 가능
5. 일반 설정 → 옵시디언 CLI 활성화
6. **Web Clipper 확장 프로그램**: 웹 기사를 클릭 한 번으로 마크다운 변환 → 볼트에 저장

##### GitHub 연동
- GitHub에서 "세컨드"라는 프라이빗 레포지토리 생성
- 터미널에서 Git 연동

##### CLAUDE.md와 스킬
- 카파시의 LLM Wiki 전문을 Claude Code에 붙여넣기 → 기본 폴더 구조 생성
- 카파시가 의도적으로 문서를 추상적으로 작성 → 각자 에이전트와 협업해서 자기 버전을 만들라는 의도
- CLAUDE.md(시스템 설계도)를 제대로 작성 — 가장 중요한 파일
- Ingest, Query, Lint를 Claude Code 스킬로 생성하여 편하게 사용

#### 언급된 사례/에피소드
- **연사의 플러그인 구성**: Git, 터미널, Web Clipper 등 실제 사용 중인 플러그인 공개
- **지식 베이스 공유**: Git을 통해 여러 명이 같이 위키를 공유 가능 → "엄청난 양의 기억들이 쌓이겠네요"

#### 주요 발언
> "원샷으로 완벽한 구조를 만들려고 하지 마시고 쓰면서 진화시키면 됩니다."

> "이 파일이 가장 중요하니 필요에 따라 클로드와 이야기하면서 목적에 맞게 깎아 보시는 걸 추천드립니다." (CLAUDE.md에 대해)

### 7. 나를 재료로 넣기 (8:00-9:22)
[바로가기](https://www.youtube.com/watch?v=xjQ4K4j3joU&t=480s)

#### 핵심 메시지
AI가 이미 알고 있는 나에 대한 지식을 정제하여 추출하는 것이 핵심이며, 대화 기록 전체를 넣는 것이 아니다.

#### 상세 내용
- 연사는 하루 종일 클로드와 대화하면서 작업 → 클로드가 이미 연사에 대해 많이 알고 있음
- 클로드에게 "나에 대한 백과사전을 써줘" 요청 → raw_memories 폴더에 저장
- **대안 방법 1**: GPT를 주로 쓰는 분은 ChatGPT에서 전체 메모리를 복사
- **대안 방법 2**: 클로드에게 "직접 나를 인터뷰해줘" 요청 → AI가 질문하고 사용자가 대답하면 정리
- 과거 노션 등에 기록한 레퍼런스, 기획 파일도 raw_information 폴더에 옮기기
- **핵심 원칙**: 대화 기록 전체를 넣는 게 아니라, AI가 이미 정제하고 구조화한 나에 대한 지식을 뽑아내는 것

#### 언급된 사례/에피소드
- **노션 기록 활용**: 연사가 지금까지 노션에 작성해온 레퍼런스, 기획 파일 등을 내보내기로 raw_information 폴더에 이전
- **초기 세팅 vs 지속 성장**: 앞 단계들은 초기 세팅(한 번만 하면 끝), 진짜 강력해지는 건 매일 새로운 정보가 쌓일 때

#### 주요 발언
> "핵심은 대화 기록 전체를 넣는 게 아닙니다. AI가 이미 정제하고 구조화한 나에 대한 지식을 뽑아내는 거예요."

> "이 시스템이 진짜 강력해지는 건 매일매일 새로운 정보가 쌓일 때입니다. 매일 작업이 진행될 때마다 그 세션에서 나온 주요 결정이나 배운 것, 새로운 아이디어나 후회까지도 기록하면 위키가 계속해서 성장합니다."

### 8. Ingest/Lint/Query 실행 및 결과 (9:22-10:55)
[바로가기](https://www.youtube.com/watch?v=xjQ4K4j3joU&t=562s)

#### 핵심 메시지
Ingest로 위키 파일이 생성되고 서로 연결되며, Lint로 품질을 유지하고, Query로 근거 있는 답변을 얻는 전체 워크플로우가 동작한다.

#### 상세 내용

##### Ingest 실행
- 위키 폴더에 파일이 하나씩 생성
- 각 페이지에 위키 링크가 생기면서 서로 연결 시작
- 그래프 뷰: 빈 화면에서 시작 → 노드가 하나씩 연결

##### Lint 실행
- 질문 전에 Lint를 돌려 정리
- 클로드 코드가 위키의 모든 파일을 읽으면서 문제 해결
- 주기적으로 돌리면 위키가 계속 "건강"해짐

##### Query 실행
- 실제 정보들을 토대로 근거 있는 답변 생성
- 위키로 만들어진 "나"는 감정이 없음 — 오로지 기록한 정보만으로 냉정하게 분석
- 처음에 빈 화면에서 시작 → 현재 수십 개의 노드가 연결

##### 스케일 업 방안
- 위키가 수백 페이지 넘어가면: 그래프 파일 같은 도구로 지식 그래프 만들어 토큰 효율 향상
- 대화 원본 통째로 보존하고 싶다면: mem0 같은 메모리 시스템 사용
- 하지만 현재는 마크다운 폴더 하나면 충분

#### 주요 발언
> "위키로 만들어진 나는 감정이 없습니다. 오로지 제가 기록한 정보들만 갖고 냉정하게 분석합니다."

> "이건 시간이 갈수록 더 풍부해질 거예요."

### 9. 마무리 — 지식의 복리 효과 (10:55-11:13)

#### 핵심 메시지
