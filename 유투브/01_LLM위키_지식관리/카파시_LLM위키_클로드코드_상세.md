### 1. 도입 및 위키 소개 (00:00-02:14)

#### 핵심 메시지
연사의 사업 전체를 AI가 정리한 위키를 시연. Obsidian 그래프 뷰에서 노드/백링크를 통해 연관 문서에 쉽게 접근 가능. 5분 만에 세팅 가능.

#### 상세 내용
- 옵시디언 그래프 뷰: 여러 노드(문서)들이 관계로 연결된 시각적 지식 맵

- Claude Code를 쓰지 않는 분들을 위해 Claude 데스크톱(코워크) 버전도 준비
- 세컨드 브레인이 복리처럼 늘어나는 지식 시스템

#### 주요 발언
> "이걸 만들어 두기만 하면 여러분들 세컨드 브레인을 계속해서 복리처럼 늘어나는 지식 시스템을 만들 수 있다."

### 2. 안드레이 카파시 LLM 위키 개념 (02:14-03:36)
[바로가기](https://www.youtube.com/watch?v=H9Wml5xDLLY&t=134s)

#### 핵심 메시지
전 테슬라 AI 디렉터 카파시가 X에서 "LLM으로 개인 지식 베이스를 만드는 게 엄청나게 유용하다"고 공개. 핵심: 마크다운 폴더만으로 충분, 벡터 DB/임베딩 불필요.

#### 상세 내용
- 카파시가 X에 "LLM으로 개인 지식 베이스를 만드는 게 엄청나게 유용하다는 걸 깨달았다" 포스트 → 며칠 만에 바이럴
- 핵심 메시지: "나는 비싼 RAG 기술을 써야 할 줄 알았는데 그냥 마크다운 폴더만으로도 충분했다"
- 벡터 데이터베이스, 임베딩 모델 → 전부 불필요
- 구조: Raw 폴더(원본) → Claude Code(분류/연결) → Wiki 폴더(정리된 지식)
- 딱 폴더 두 개(Raw + Wiki)가 전부
- Wiki 안에 Index 폴더: 파일 위치/내용을 정리한 문서. 검색/질문 시 인덱스를 따라가서 답을 찾는 방식

#### 언급된 사례/에피소드
- **카파시의 X 포스트**: 짧은 한 마디가 며칠 만에 바이럴
  - 시사점: AI 분야 최고 전문가도 단순한 마크다운 폴더 방식의 효과를 인정

#### 주요 발언
> "카파시가 이렇게 말했어요. 나는 비싼 RAG 기술을 써야 할 줄 알았는데 그냥 마크다운 폴더만으로도 충분했다. 벡터 데이터베이스, 임베딩, 그게 다 필요 없다는 겁니다."

### 3. RAG vs LLM 위키 비교 (03:36-04:47)
[바로가기](https://www.youtube.com/watch?v=H9Wml5xDLLY&t=216s)

#### 핵심 메시지
RAG는 유사도 검색(청크 기반)이지만, 위키는 문서 간 관계를 따라가는 방식으로 맥락을 더 깊게 이해. 인프라 비용 0원, 토큰 사용량 95% 절감 사례.

#### 상세 내용
- **RAG**: 유사도 검색. "이 청크랑 비슷한 거 찾아줘" 방식
- **LLM 위키**: 관계를 따라가는 방식. 링크로 연결되어 있어 맥락을 훨씬 깊게 이해
- 인프라: 마크다운 파일이 전부 → 임베딩 비용, DB 호스팅, 벡터 DB, 유지보수 불필요
- Claude Code한테 시키기만 하면 자동 생성
- 일반 AI 챗봇은 대화가 끝나면 사라지지만, 위키는 지식이 복리처럼 계속 쌓임
- "AI가 모든 걸 기억하고 정리해 주는 지치지 않는 개인 비서"

#### 언급된 사례/에피소드
- **383개 파일 정리 사례**: X에서 어떤 분이 383개의 흩어진 파일 + 미팅 녹음 100개를 이 방식으로 정리 → 토큰 사용량 95% 절감
  - 시사점: 대량의 비정형 자료도 효과적으로 정리 가능

#### 주요 발언
> "RAG는 유사도 검색인데... 위키는 관계를 따라가는 거예요. 링크로 연결이 되어 있으니까 맥락을 훨씬 더 깊게 이해할 수가 있는 거죠."

> "383개의 흩어진 파일이랑 미팅 녹화를 이 방식으로 정리를 했더니 토큰 사용량이 95%나 줄었다."

### 4. 옵시디언 및 Claude Code 환경 설정 (04:47-08:06)
[바로가기](https://www.youtube.com/watch?v=H9Wml5xDLLY&t=287s)

#### 핵심 메시지
Obsidian 설치 → 보관함 생성 → GitHub에서 카파시의 프롬프트 복사 → Claude Code에 붙여넣기 → 자동으로 전체 구조 생성. 별도 지시 없이 프롬프트만으로 완성.

#### 상세 내용
- Obsidian 무료 다운로드 → 새 보관함 생성 (이름: 예 "my-wiki")
- GitHub에서 카파시의 LLM 위키 마크다운 프롬프트 전체 복사
- Claude Code 실행 → 프롬프트 붙여넣기 + 추가 프롬프트 입력
- 자동 생성되는 것: Raw 폴더, Wiki 폴더, CLAUDE.md, Index 폴더, 린팅/쿼리/소스 수집 기능
- 하위 폴더도 자동 생성: analysis, concept, entities 등
- CLAUDE.md: Claude Code가 작업 시 항상 참고하는 문서

#### 주요 발언
> "클로드 코드한테 이거 구현해라고 했을 뿐인데 이렇게 Raw 폴더, Wiki 폴더 만들어지고 구조가 완성되었다고 합니다."

### 5. 자료 ingest 및 자동 분류 (08:06-12:12)
[바로가기](https://www.youtube.com/watch?v=H9Wml5xDLLY&t=486s)

#### 핵심 메시지
Obsidian Web Clipper로 웹 자료를 Raw에 저장 → "ingest 해줘"로 자동 분류/위키 생성/관계 연결. 린팅으로 연결 오류 점검.

#### 상세 내용
- **Obsidian Web Clipper**: 크롬 웹스토어에서 설치. 기본 템플릿 위치를 "raw"로 변경하면 Raw 폴더에 자동 저장
- 웹 페이지 클리핑 시 소스, 생성일, 태그, 내용이 자동 포함
- Claude Code에 "ingest 해줘" 또는 "분석해 줘" 입력 → 자동 분류/위키 문서 생성
- 질문: 자연어로 "이거 분석해 주세요", "혹시 이런 자료 있나요?" 등
- 점검: "lint 해줘" → 잘못 연결된 문서, 미연결 자료 등 자동 확인
- 생성 결과: 소스 요약, 개체(entity), 개념(concept) 등 자동 분류

#### 주요 발언
> "그냥 소스를 Raw 파일에 넣고 그다음에 ingest 해줘. 혹은 분석해 줘. 식으로 말씀하시면 되고 질문은 그냥 자연스럽게 자연어로 하시면 됩니다."

### 6. 유튜브 데이터 연동 데모 (12:12-14:03)
[바로가기](https://www.youtube.com/watch?v=H9Wml5xDLLY&t=732s)

#### 핵심 메시지
유튜브 자막을 Raw에 넣고 ingest하면 영상 내용이 자동 분류/연결. 네이트 허크는 36개 영상 자막을 14분 만에 지식 시스템으로 구축.

#### 상세 내용
- 유튜브 영상 URL + "해당 유튜브 자막을 추출해서 ingest를 진행해" 입력
- Claude Code가 자막 추출 → 핵심 요약 → 위키 반영 (소스 요약 1개, 개체 1개, 개념 3개 등 자동 생성)
- 옵시디언 그래프 뷰에서 새 노드와 관계 자동 생성 확인
- 관련 페이지/백링크 자동 연결

#### 언급된 사례/에피소드
- **네이트 허크 사례**: 자기 영상 자막 36개를 한꺼번에 넣어서 14분 만에 영상 전체를 연결하는 지식 시스템 구축
  - 시사점: 대량 콘텐츠도 단시간에 체계적 지식으로 변환 가능

#### 주요 발언
> "이런 게 계속 쌓이면 여러분만의 AI 두뇌가 만들어지는 겁니다."

### 7. 위키 활용 및 질의응답 + 린팅 (14:03-22:10)
[바로가기](https://www.youtube.com/watch?v=H9Wml5xDLLY&t=843s)

#### 핵심 메시지
자연어로 질문하면 Claude Code가 위키에서 답을 찾아줌. 린팅으로 문서 품질 관리. 클로드 코워크로도 동일하게 관리 가능.

#### 상세 내용
- 위키가 만들어진 후 자연어 질문으로 활용 (예: "클로드에서 MCP는 뭐야?")
- Claude Code가 위키 문서를 탐색하여 답변
- 린팅: "lint 해줘" → 문서 연결 오류/미연결 자료/잘못된 링크 등 자동 점검
- 핫 캐시: 자주 조회하는 문서를 빠르게 접근
- 클로드 코워크에서도 동일한 폴더를 열어 관리 가능 (코딩 불필요)
