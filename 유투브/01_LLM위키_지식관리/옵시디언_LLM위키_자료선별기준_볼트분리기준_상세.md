## 한 줄 요약

LLM 위키는 자료 창고가 아니라 **"AI가 읽고 판단하고 결과물을 만드는 맥락 시스템"** — 자료는 **3기준(반복 사용 / 의사결정 영향 / 업무 연결) 중 2개 이상** 통과 시만 넣고, 볼트는 **기본 1개**(부서는 폴더가 아닌 **속성**으로 표시)로 운영하며, 분리는 **보안·목적·워크플로우·검색 오염** 4가지 경우에만 한다.

### 2. 함정 — 위키를 채우려고 자료를 만들지 마라 (01:22 - 02:52)
[바로가기](https://www.youtube.com/watch?v=of7Sr3uOlkA&t=82s)

#### 핵심 메시지
LLM 위키는 자료 창고가 아니라 **맥락 시스템**이다. 그리고 위키는 채우는 게 목표가 아니라 **"어차피 발생하는 것들을 흘려보내는 통로"**다.

#### 상세 내용
- "일단 다 넣어두면 언젠가 쓰겠지" 방식은 위험 — 기준 없이 넣으면 "검색해야 할 쓰레기 더미"가 됨
- 흔한 함정: 추가할 자료를 **새로 만들어야** 하더라 → 순서가 뒤집힌 것
- 이미 일어난 일만 넣어도 위키는 채워진다: 회의 → 회의록 / 결정 → 결정 이유 / AI에게 좋은 답 → 그 답 기록
- **5분 룰**: 정리하는 데 5분 이상 걸리면 보류. 5분 안에 들어가는 자료만으로 충분

#### 주요 발언
> "위키는 채우는 게 목표가 아닙니다. 어차피 발생하는 것들을 흘려보내는 통로입니다." (02:11)

> "위키에 넣으려고 일부러 글을 쓰기 시작하면 그 순간부터 부담이 되고 결국 안 하게 됩니다." (02:36)

### 3. 자료 선별 기준 3가지 (02:52 - 05:07)
[바로가기](https://www.youtube.com/watch?v=of7Sr3uOlkA&t=172s)

#### 핵심 메시지
3가지 기준 중 **2개 이상 해당하면 넣고, 1개 이하면 보류/버림**.

#### 상세 내용
- **기준 1 — 반복해서 다시 쓰는가?**
  - 넣지 않음: 한 번 보고 끝나는 공지, 단순 알림, 오늘만 필요한 임시 자료, 이번 주 점심 메뉴
  - 넣음: 회의 때 반복 참고 자료, 계속 업데이트되는 업무 기준, 자주 묻는 고객 응대 내용, 고객 응대 기준, 계약 검토 체크리스트, 월간 보고서 작성 방식
- **기준 2 — 의사결정에 영향을 주는가?**
  - LLM 위키의 목적은 단순 저장이 아니라 **판단을 돕는 것** — "AI에게 물었을 때 답변의 질을 바꿔주는 자료"인가
  - 넣음: 고객 피드백, 가격 정책 변경 내역, 업무 프로세스, 의사결정의 배경
  - 넣지 않음: 인터넷에서 복사한 일반 정보 (내 업무 맥락과 연결 안 되면 — "그냥 검색하면 되고 AI가 더 잘함")
- **기준 3 — 내 업무·프로젝트와 연결되는가?**
  - 아무리 좋은 자료라도 내 업무와 연결 안 되면 위키 안에서 **소음**
  - 자료 넣기 전 자문 3가지: 어떤 프로젝트와 연결? 어떤 업무 개선에 쓰일까? 어떤 질문에 답하기 위해 쓰일까? — 답할 수 있으면 통과, 어려우면 보류

#### 언급된 사례/에피소드
- **AI 뉴스 기사 100개 저장**: 영상 기획·서비스 설계·업무 개선 어디에 쓸지 연결하지 않으면 나중에 다시 찾지 못함 → 기준 3의 반례

### 4. 넣을 때 라벨 규칙 2가지 (05:07 - 06:42)
[바로가기](https://www.youtube.com/watch?v=of7Sr3uOlkA&t=307s)

#### 핵심 메시지
선별 기준을 통과한 자료라도 그냥 넣으면 안 된다 — **라벨(출처·맥락 + AI 가독 형태)**을 붙여야 한다.

#### 상세 내용
- **규칙 1 — 출처와 맥락을 함께 남긴다**: 중요한 것은 자료 자체보다 **자료의 맥락**
  - 회의록: 대화 통째 복사가 아니라 "언제·누가·무엇을·왜 결정했는지 + 다음 할 일"
  - PDF·기사: 출처, 작성일, 핵심 요약, 내 생각, 관련 프로젝트를 같이
- **규칙 2 — AI가 읽을 수 있는 형태로 정리**: 너무 길거나 구조·맥락 없으면 활용도 하락
  - 최소 구성: 한 줄 요약 + 핵심 내용 3개 + 관련 프로젝트 + 관련 부서
  - **제목에서 의미가 드러나야 함**: `회의록.txt` ✗ → `26년 6월 11일 영업 전략 회의 — 신규 고객 응대 프로세스 개선` ✓

#### 주요 발언
> "LLM 위키에서 중요한 것은 자료 자체보다 자료의 맥락입니다." (05:26)

### 5. 실전 예시 — 고객 컴플레인 이메일 (06:42 - 07:52)
[바로가기](https://www.youtube.com/watch?v=of7Sr3uOlkA&t=402s)

#### 핵심 메시지
3분짜리 라벨링 노트 하나가 나중에 AI 답변의 질을 바꾼다.

#### 언급된 사례/에피소드
- **"견적서 받는 데 3일 걸렸어요. 경쟁사는 당일 해줍니다" 이메일**:
  - 기준 1 (반복): 다음 분기 프로세스 개선 회의에서 또 꺼냄 → 통과
  - 기준 2 (의사결정): 견적 프로세스 변경 판단 근거 → 통과
  - 기준 3 (업무 연결): 진행 중인 신규 고객 응대 개선 프로젝트와 직결 → 통과
  - 3/3 통과 → 라벨 붙여서 저장, 여기까지 **3분**
  - 효과: 나중에 "고객 이탈 원인 분석해 줘" 질문 시 답변의 질을 바꿈

### 6. 볼트 분리 — 처음부터 나누지 마라 (07:52 - 09:02)
[바로가기](https://www.youtube.com/watch?v=of7Sr3uOlkA&t=472s)

#### 핵심 메시지
부서별 볼트 분리는 비추천 — 이유는 ① 기술적(연결 단절), ② 분류 자체가 불가능.

#### 상세 내용
- **이유 1 — 기술적**: 옵시디언의 핵심 기능(링크·백링크·그래프 뷰·검색)은 전부 **볼트 단위로만 작동** → 볼트를 나누는 순간 부서 간 연결이 끊김
- **이유 2 — 분류 불가능**: 현실 업무 자료는 대부분 부서 2~3개에 걸침
  - 고객 피드백 = 세일즈? 프로덕트? / 계약 회의록 = 어드민? 리걸? / 프로젝트 예산 = 파이낸스? 프로젝트?

#### 언급된 사례/에피소드
- **영업팀 A사 계약 회의록 ↔ 법무팀 계약 검토 체크리스트**: 당연히 연결되어야 할 자료인데 세일즈 볼트/리걸 볼트로 나누면 "영원히 서로를 모름" — 링크 불가, 검색 동시 노출 불가, AI도 한쪽만 읽고 답함

#### 주요 발언
> "부서 자료는 서로 연결될 때 가치가 생기는데, 볼트 분리는 그 가치를 원천 차단하는 겁니다." (08:54)

### 7. 폴더 vs 속성 — 부서는 속성으로 (09:02 - 11:14)
[바로가기](https://www.youtube.com/watch?v=of7Sr3uOlkA&t=542s)

#### 핵심 메시지
볼트 대신 부서 **폴더**로 나눠도 같은 문제가 반복된다 (한 노트는 폴더 하나에만 들어감). **폴더는 한 가지 축(프로젝트/영역)으로만, 부서는 속성(property)으로**.

#### 상세 내용
- 흔한 실수: `Department/` 폴더 아래 세일즈·리걸·파이낸스 → 계약 회의록은 어느 폴더? 볼트의 문제가 폴더에서 재현
- **원칙**: 폴더는 "무엇을 위한 자료인가" = **프로젝트·영역 축**으로만 분류
- **부서는 노트 상단 속성으로**: type / department / project / status / source / 생성일
- 폴더는 1개만 선택 가능하지만 **속성은 여러 개 동시 부여 가능** — 계약 회의록에 department: 세일즈 + 리걸 둘 다 붙이면 고민 소멸
- AI 이해도도 향상: "업무와 법무에 걸친 자료구나 / 회의록이구나 / 진행 중 프로젝트구나"
- 부서별 모아보기: 속성 검색 또는 "세일즈 인덱스" 노트 하나에 링크로 수집 — 폴더 없이도 가능

#### 주요 발언
> "부서 폴더를 만들고 싶은 충동이 들 때가 바로 속성을 써야 할 때죠." (11:08)

### 8. 볼트를 나눠야 하는 4가지 경우 (11:14 - 13:14)
[바로가기](https://www.youtube.com/watch?v=of7Sr3uOlkA&t=674s)

#### 핵심 메시지
볼트 = **AI에게 전달하는 컨텍스트의 범위**. 진짜 질문은 "부서가 다른가"가 아니라 **"이걸 AI에게 넘겨도 되는가"**.

#### 상세 내용
- **분리 케이스 1 — AI에게 넘기면 안 되는 자료 (보안)**: 고객 개인정보, 기밀 계약서, 인사 자료 → 업무 볼트와 **물리적 분리**. "정리 문제가 아니라 보안 문제라서 속성으로 해결 안 됨"
- **분리 케이스 2 — 지식의 목적이 완전히 다를 때**: 개인 독서 노트(자기 이해·학습) vs 회사 업무 위키(업무 처리·결과물 생성)
- **분리 케이스 3 — 템플릿·워크플로우가 완전히 다를 때**: 영상 제작 볼트(원고·썸네일·촬영·편집·업로드) vs 업무 볼트(회의록·보고서·고객 대응·프로세스)
- **분리 케이스 4 — 검색 결과가 계속 오염될 때 (최후의 수단)**: 업무 질문에 개인 독서 노트가 자꾸 섞임 → 먼저 속성 필터링("department가 세일즈인 노트만 참고해 답해줘")으로 범위 좁히기 → 그래도 오염되면 그때 분리

### 9. 전자책 소개 + 전체 정리 (13:14 - 17:27)
[바로가기](https://www.youtube.com/watch?v=of7Sr3uOlkA&t=794s)

#### 핵심 메시지
기능(폴더·마크다운·플러그인)보다 중요한 것은 **"무엇을 넣고, 어떻게 연결하고, 어떤 결과물을 만들 것인가"**. LLM 위키의 최종 목적은 예쁜 노트가 아니라 **결과물**(보고서·제안서·회의 요약·체크리스트·영상 원고·리서치 정리).

#### 상세 내용
- 전자책 "AI 시대 나만의 LLM 위키 만들기" 3가지 특징: ① 자료 판단 기준(판단이 아니라 시스템이 되도록) ② 구조화 방식(폴더 축·속성 표시·AI 가독 구조) ③ 결과물 중심 (저장→요약→맥락 연결→AI 질문→결과물 생성 흐름)
- 대상: 옵시디언 깔았는데 뭘 넣을지 모르는 분 / 모았는데 못 찾는 분 / AI에게 매번 업무 맥락 설명에 지친 분 / 회사 자료를 위키처럼 정리하고 싶은 분
- **최종 정리**: 선별 3기준(반복·의사결정·업무연결) 2개 이상 → 넣기 / 라벨 2규칙(출처·맥락 + AI 가독 형태) / 위키 채우려고 자료 만들지 말 것 (5분 룰) / 기본 1볼트, 폴더는 프로젝트 축, 부서는 속성 / 분리는 보안·목적·워크플로우·검색 오염 4경우만

#### 주요 발언
> "결국 중요한 건 자료를 많이 모으는 게 아닙니다. AI가 읽을 수 있게 정리하고, 내 업무 맥락과 연결하고, 다시 결과물로 꺼낼 수 있게 만드는 것입니다." (16:52)
