## 1. 개요

### 1.1 공장자동화 통신의 중요성

공장자동화(FA: Factory Automation)에서 통신 프로토콜은 센서, PLC, HMI, 서버 간의 데이터 교환을 담당하는 핵심 요소입니다. 예지정비 시스템에서는 실시간 센서 데이터를 수집하고, AI 분석 결과를 기반으로 설비를 제어해야 하므로 **신뢰성**, **실시간성**, **확장성**이 매우 중요합니다.

### 1.2 통신 계층 구조

```
┌─────────────────────────────────────────────────────────────┐
│  Level 4: Enterprise    │  ERP, SCM, MES                    │
│  ─────────────────────────────────────────────────────────  │
│  통신: HTTP/REST, MQTT, AMQP                                │
├─────────────────────────────────────────────────────────────┤
│  Level 3: Site          │  SCADA, Historian, Analytics      │
│  ─────────────────────────────────────────────────────────  │
│  통신: OPC-UA, MQTT, Modbus TCP                             │
├─────────────────────────────────────────────────────────────┤
│  Level 2: Control       │  PLC, DCS, Edge Gateway           │
│  ─────────────────────────────────────────────────────────  │
│  통신: Modbus RTU/TCP, PROFINET, EtherNet/IP               │
├─────────────────────────────────────────────────────────────┤
│  Level 1: Field         │  센서, 액추에이터, 드라이브       │
│  ─────────────────────────────────────────────────────────  │
│  통신: 4-20mA, RS485, IO-Link, HART                         │
└─────────────────────────────────────────────────────────────┘
```

## 2. 계층별 통신 구조

### 2.1 센서 계층 (Level 1)

| 통신 방식 | 특징 | 적용 |
|----------|------|------|
| **4-20mA** | 아날로그, 노이즈 강함, 단방향 | 온도, 압력, 유량 센서 |
| **RS485** | 디지털, 다중 연결, 최대 1.2km | 스마트 센서, 드라이브 |
| **IO-Link** | 디지털, 양방향, 파라미터 설정 | 최신 스마트 센서 |

### 2.2 제어 계층 (Level 2)

| 통신 방식 | 특징 | 적용 |
|----------|------|------|
| **Modbus RTU** | RS485 기반, 간단, 널리 사용 | PLC-센서 통신 |
| **Modbus TCP** | 이더넷 기반, IP 네트워크 활용 | PLC-Gateway 통신 |
| **PROFINET** | 실시간 이더넷, 고속 | Siemens 시스템 |
| **EtherNet/IP** | 표준 이더넷, CIP 프로토콜 | Rockwell 시스템 |

### 2.3 감시/관리 계층 (Level 3-4)

| 통신 방식 | 특징 | 적용 |
|----------|------|------|
| **OPC-UA** | 플랫폼 독립, 보안 내장 | SCADA-서버 연동 |
| **MQTT** | 경량, Pub/Sub, IoT 표준 | 클라우드 연동 |
| **HTTP/REST** | 웹 표준, 범용성 | 대시보드, API |
| **WebSocket** | 양방향, 실시간 | 실시간 모니터링 |

## 3. 필드버스 프로토콜

### 3.1 Modbus

#### 3.1.1 개요
- **개발:** 1979년 Modicon (현 Schneider Electric)
- **특징:** 간단한 구조, 로열티 무료, 가장 널리 사용
- **종류:** Modbus RTU, Modbus ASCII, Modbus TCP

#### 3.1.2 Modbus RTU

```
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│ Slave ID │ Function │  Data    │  CRC     │ (Silent) │
│ (1 byte) │ (1 byte) │ (N bytes)│ (2 bytes)│          │
└──────────┴──────────┴──────────┴──────────┴──────────┘
```

**주요 Function Code:**

| Code | 기능 | 설명 |
|------|------|------|
| 01 | Read Coils | 디지털 출력 읽기 |
| 02 | Read Discrete Inputs | 디지털 입력 읽기 |
| 03 | Read Holding Registers | 아날로그 출력 레지스터 읽기 |
| 04 | Read Input Registers | 아날로그 입력 레지스터 읽기 |
| 05 | Write Single Coil | 단일 디지털 출력 쓰기 |
| 06 | Write Single Register | 단일 레지스터 쓰기 |
| 15 | Write Multiple Coils | 다중 디지털 출력 쓰기 |
| 16 | Write Multiple Registers | 다중 레지스터 쓰기 |

**통신 설정 예시:**
```
Baud Rate: 9600 / 19200 / 38400 / 115200 bps
Data Bits: 8
Parity: None / Even / Odd
Stop Bits: 1 / 2
```

#### 3.1.3 Modbus TCP

```
┌─────────────────────────────────────────────────────────┐
│                    MBAP Header (7 bytes)                │
├──────────┬──────────┬──────────┬──────────┬─────────────┤
│Trans ID  │Protocol  │ Length   │ Unit ID  │   PDU       │
│(2 bytes) │(2 bytes) │(2 bytes) │(1 byte)  │ (N bytes)   │
└──────────┴──────────┴──────────┴──────────┴─────────────┘

기본 포트: TCP 502
```

### 3.2 RS485 통신

#### 3.2.1 특징
- **전송 방식:** 차동 신호 (노이즈 강함)
- **토폴로지:** 멀티드롭 (최대 32개 장치)
- **거리:** 최대 1,200m (낮은 속도에서)
- **속도:** 최대 10Mbps (짧은 거리에서)

#### 3.2.2 배선

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│  Master  │─────│  Slave 1 │─────│  Slave 2 │───...
│          │     │          │     │          │
│  A  B GND│     │  A  B GND│     │  A  B GND│
└──┬──┬──┬─┘     └──┬──┬──┬─┘     └──┬──┬──┬─┘
   │  │  │          │  │  │          │  │  │
   └──┼──┼──────────┼──┼──┼──────────┼──┼──┘
      └──┼──────────┼──┼──┼──────────┼──┘
         └──────────┴──┴──┴──────────┘

종단 저항: 120Ω (양 끝에 설치)
```

### 3.3 PROFIBUS

#### 3.3.1 종류
- **PROFIBUS DP:** 분산 주변장치 (가장 많이 사용)
- **PROFIBUS PA:** 프로세스 자동화 (방폭 환경)
- **PROFIBUS FMS:** 통합 솔루션 (거의 사용 안 함)

#### 3.3.2 특징
- **속도:** 최대 12Mbps
- **노드:** 최대 127개
- **토폴로지:** 버스형

## 4. 산업용 이더넷 프로토콜

### 4.1 PROFINET

#### 4.1.1 특징
- **개발:** Siemens, PROFIBUS International
- **기반:** 표준 이더넷 (IEEE 802.3)
- **실시간:** IRT (Isochronous Real-Time) 지원
- **사이클 타임:** < 1ms 가능

#### 4.1.2 통신 클래스

| 클래스 | 사이클 타임 | 적용 |
|--------|------------|------|
| NRT | 100ms | 일반 자동화 |
| RT | 1-10ms | 모션 제어 |
| IRT | < 1ms | 고속 동기화 |

### 4.2 EtherNet/IP

#### 4.2.1 특징
- **개발:** Rockwell Automation, ODVA
- **기반:** TCP/IP, UDP/IP
- **프로토콜:** CIP (Common Industrial Protocol)
- **포트:** TCP 44818, UDP 2222

#### 4.2.2 통신 모델

```
┌─────────────────┐
│   Application   │
├─────────────────┤
│      CIP        │  ← Common Industrial Protocol
├─────────────────┤
│  TCP/IP or UDP  │
├─────────────────┤
│    Ethernet     │
└─────────────────┘
```

### 4.3 OPC-UA

#### 4.3.1 특징
- **개발:** OPC Foundation
- **독립성:** 플랫폼, 벤더 독립
- **보안:** 인증, 암호화 내장
- **정보 모델:** 객체 지향, 확장 가능

#### 4.3.2 통신 구조

```
┌─────────────────────────────────────────┐
│           OPC UA Application            │
├─────────────────────────────────────────┤
│         OPC UA Services                 │
│  (Read, Write, Subscribe, Browse, ...)  │
├─────────────────────────────────────────┤
│         OPC UA Transport                │
│  (UA TCP, HTTPS, AMQP, MQTT)           │
├─────────────────────────────────────────┤
│         Network Layer (TCP/IP)          │
└─────────────────────────────────────────┘

기본 포트: TCP 4840
```

#### 4.3.3 보안 모드

| 모드 | 인증 | 암호화 | 적용 |
|------|------|--------|------|
| None | X | X | 테스트 환경 |
| Sign | O | X | 내부 네트워크 |
| SignAndEncrypt | O | O | 운영 환경 |

| 802.11n | 2.4/5 GHz | 600 Mbps | 일반 IoT |

| 802.11ax | 2.4/5/6 GHz | 9.6 Gbps | 고밀도 IoT |

### 5.2 LoRa / LoRaWAN

#### 5.2.1 특징
- **거리:** 최대 15km (개방 환경)
- **속도:** 0.3 ~ 50 kbps
- **전력:** 초저전력
- **적용:** 원격 센서, 스마트 미터링

#### 5.2.2 네트워크 구조

```
┌─────────┐    LoRa    ┌─────────┐   IP    ┌─────────┐
│End Node │ ─────────▶ │ Gateway │ ─────▶ │ Network │
│(센서)   │            │         │         │ Server  │
└─────────┘            └─────────┘         └─────────┘
```

### 5.3 Zigbee (IEEE 802.15.4)

| 항목 | 사양 |
|------|------|
| 주파수 | 2.4 GHz |
| 속도 | 250 kbps |
| 거리 | 10-100m |
| 노드 | 최대 65,000개 |

## 6. 클라우드 통신 프로토콜

### 6.1 MQTT

#### 6.1.1 특징
- **모델:** Publish/Subscribe
- **경량:** 최소 2바이트 헤더
- **QoS:** 0 (At most once), 1 (At least once), 2 (Exactly once)
- **포트:** TCP 1883 (일반), 8883 (TLS)

#### 6.1.2 구조

```
┌──────────┐     Publish      ┌──────────┐     Deliver     ┌──────────┐
│Publisher │ ───────────────▶ │  Broker  │ ───────────────▶│Subscriber│
│ (센서)   │   Topic: /temp   │ (Server) │   Topic: /temp  │ (서버)   │
└──────────┘                  └──────────┘                  └──────────┘
```

#### 6.1.3 Topic 구조 예시

```
factory/hankookmech/shredder/sensor/vibration/axis1
factory/hankookmech/shredder/sensor/temperature/motor
factory/hankookmech/shredder/control/speed
factory/hankookmech/shredder/alert/overload
```

### 6.2 HTTP/REST API

#### 6.2.1 RESTful 설계 원칙

| 메서드 | 용도 | 예시 |
|--------|------|------|
| GET | 조회 | GET /api/sensors |
| POST | 생성 | POST /api/sensors |
| PUT | 전체 수정 | PUT /api/sensors/1 |
| PATCH | 부분 수정 | PATCH /api/sensors/1 |
| DELETE | 삭제 | DELETE /api/sensors/1 |

#### 6.2.2 API 예시

```json
// GET /api/sensors/vibration/1
{
  "id": 1,
  "type": "vibration",
  "location": "bearing_axis1",
  "value": 12.5,
  "unit": "mm/s",
  "timestamp": "2026-01-17T10:30:00Z",
  "status": "normal"
}
```

### 6.3 WebSocket

#### 6.3.1 특징
- **연결:** 지속적 양방향 통신
- **프로토콜:** ws:// (일반), wss:// (TLS)
- **적용:** 실시간 대시보드, 알림

#### 6.3.2 연결 과정

```
Client                              Server
   │                                   │
   │──── HTTP Upgrade Request ────────▶│
   │                                   │
   │◀─── HTTP 101 Switching ──────────│
   │                                   │
   │◀═══════ WebSocket ═══════════════▶│
   │      (Full-duplex 통신)           │
```

```
│         └────────────────┴────────────────┘                     │

│                    MQTT / HTTPS                                 │
└──────────────────────────┼──────────────────────────────────────┘
                           │
                    ┌──────┴──────┐
                    │ 4G Router   │
                    └──────┬──────┘
                           │
                    ┌──────┴──────┐
                    │Edge Gateway │  ◀── UTTEC 엣지 컨트롤러

                           │
           ┌───────────────┼───────────────┐
           │               │               │

    │Modbus RTU   │ │Modbus TCP   │ │  RS485      │
```

### 8.2 프로토콜 상세

| 구간 | 프로토콜 | 설정 |
|------|----------|------|
| 센서 → Gateway | Modbus RTU | 9600bps, 8N1 |
| Gateway → 인버터 | Modbus TCP | Port 502 |
| Gateway → PLC | RS485 | 19200bps |
| Gateway → Cloud | MQTT | TLS, QoS 1 |
| Cloud → Dashboard | HTTPS/WSS | Port 443 |

### 8.3 Modbus 레지스터 맵

#### 8.3.1 진동 센서 (Slave ID: 1-4)

| 주소 | 데이터 | 타입 | 단위 |
|------|--------|------|------|
| 40001 | 진동 속도 RMS | Float32 | mm/s |
| 40003 | 진동 가속도 Peak | Float32 | g |
| 40005 | 주파수 | Float32 | Hz |
| 40007 | 온도 | Float32 | °C |
| 40009 | 상태 | Uint16 | 0:정상, 1:경고, 2:위험 |

#### 8.3.2 전류 센서 (Slave ID: 5-6)

| 주소 | 데이터 | 타입 | 단위 |
|------|--------|------|------|
| 40001 | 전류 RMS | Float32 | A |
| 40003 | 역률 | Float32 | - |
| 40005 | 유효전력 | Float32 | kW |
| 40007 | 피크 전류 | Float32 | A |

#### 8.3.3 인버터 제어 (Modbus TCP)

| 주소 | 데이터 | R/W | 설명 |
|------|--------|-----|------|
| 40001 | 주파수 설정 | R/W | 0.01 Hz |
| 40002 | 운전 명령 | R/W | 0:정지, 1:정회전, 2:역회전 |
| 40003 | 현재 주파수 | R | 0.01 Hz |
| 40004 | 출력 전류 | R | 0.1 A |
| 40005 | 상태 | R | 비트맵 |

### 8.4 MQTT Topic 구조

```
hankookmech/
├── shredder/
```
