지원 사유

안녕하세요. 홍광선입니다.

"ESP32-P4 아두이노 → ESP-IDF 마이그레이션" 프로젝트를 검토하였습니다.

본 프로젝트의 핵심인 **ESP-IDF / FreeRTOS 기반 펌웨어 개발 +
아두이노 레거시 코드 마이그레이션**은 당사가 38년간 다뤄온
임베디드 펌웨어의 정확한 영역입니다.

당사는 **FreeRTOS 기반 양산 제품을 5종 보유**하고 있으며,
보유기술 자료에도 명시된 핵심 역량입니다:

- 컴프레샤 컨트롤러 (STM32F756 + FreeRTOS) - 국내 양산
- 세탁기 컨트롤러 (STM32F407 + FreeRTOS) - 국내 양산
- BLE 온도 컨트롤러 (nRF52832) - 국내 양산
- EtherCAT 컨트롤러 (CM4 + Linux) - 국내 양산
- V-Cut 컨트롤러 (Raspberry Pi 3) - 중국 수출

특히 본 프로젝트와 직접 매칭되는 영역:

- **FreeRTOS** 양산 5종 (Task 분리, Queue, Semaphore, ISR 표준 패턴)
- **C/C++ 38년+** 임베디드 펌웨어 양산
- **저수준 MCU 이해 + bring-up 경험** (아두이노 추상화 → 네이티브
  레지스터 직접 제어 패턴 다수)
- **외주 코드 인수 + 리팩토링** 경험 (V-Cut 컨트롤러 양산화 사례)
- **임베디드 GUI** (PyQt + LCD UI 양산)
- **실시간 데이터 시각화** (산업 HMI 양산)

TensorFlow Lite for Microcontrollers(TFLM)는 본 프로젝트의 신규
학습 영역이나, 당사는 솔직하게 이를 명시하고 35일 내 학습 + 적용
계획을 제시드립니다. TFLM은 ESP-IDF 공식 컴포넌트로 통합되어
있어 진입 장벽이 낮습니다.

근무지(관악구) 상주 가능합니다.

부족 영역에 대한 솔직한 입장
============================================================

본 프로젝트의 직접 경험이 부족한 영역과 대응:

(1) TensorFlow Lite for Microcontrollers (TFLM)
- 솔직히 TFLM 직접 양산 경험은 없음
- 그러나 다음 이점이 있어 35일 내 적용 가능:
  * ESP-IDF 공식 컴포넌트(esp-tflite-micro)로 제공되어 통합 용이
  * 클라이언트가 기존 AI 모델을 제공 (재학습 불필요)
  * "포팅" 작업이지 모델 설계 작업이 아님
  * TFLM API는 "Interpreter / Tensor / Invoke"의 단순 구조
- 사전 학습: 계약 전 1주 esp-tflite-micro 공식 예제 학습
- 학습 자료: TF 공식 가이드 + ESP-IDF 예제 코드

(2) ESP32-P4
- ESP32 시리즈는 양산 경험 있으나 P4는 신규 칩
- 그러나 ESP-IDF는 동일 → 빠른 적응 가능
- ESP32-P4 특징(RISC-V 코어, GUI 가속) 학습 1주 내 가능
- ESP-IDF 5.x 환경 표준화로 칩별 차이 최소화

(3) 3D 그래프 시각화
- 임베디드 MCU에서 3D 그래프는 리소스 제약 큼
- 공고에서도 "MCU 리소스 고려하여 2D 대체 방안 제안 권장" 명시
- 대안 제안: 2D + 컬러 매핑(Heatmap), 또는 회전 가능한 등각투영
- 클라이언트와 협의하여 최적 방식 결정

종합: **FreeRTOS 양산 5종 + ESP-IDF 경험 + 외주 코드 인수
패턴**의 강력한 매칭과 **TFLM 학습 의지 명시**로 35일 단기
프로젝트 책임 완수 가능합니다.
