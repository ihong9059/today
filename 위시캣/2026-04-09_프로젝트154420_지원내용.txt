[2. EtherCAT 컨트롤러 (CM4 기반) - 국내 양산 판매 중] ★★★

제품: EtherCAT Master 컨트롤러
- 플랫폼: Raspberry Pi CM4 + 자체 캐리어 보드
- 통신: **EtherCAT (산업용 결정형 이더넷)**
- 상태: **국내 양산 판매 중**

본 프로젝트와의 연관:
- EtherCAT은 ISO-TP와 마찬가지로 **물리 계층 위의 다중 프레임

- 상위 명령 → 분할 → 전송 → 수신 → 재조립 → 응답의 시퀀스가
  동일한 패턴
- DC(Distributed Clock) 동기화 → 차량 진단의 타이밍 처리와
  유사한 정밀 시퀀스 제어

[3. 컴프레샤 컨트롤러 (STM32F756 + FreeRTOS) - 국내 양산]

제품: 산업용 공기압축기 정밀 제어 보드
- 통신: **Modbus RTU/TCP, RS-232, RS-485**
- 상태: **국내 양산 판매 중**

본 프로젝트와의 연관:
- Modbus RTU는 CAN과 동일하게 **요청-응답 다중 프레임** 프로토콜
- NRC(Negative Response Code)에 해당하는 Modbus 예외 응답 처리
- 통신 타임아웃 / 재시도 / 에러 복구 표준 패턴
- 상태 머신 기반 통신 시퀀스 양산 적용

[4. 삼성전자 Motor Controller Board (임호균 이사)]

- BLDC 모터 제어 + 통신 보드
- CAN 통신 기반 상위 제어기 연동
- 인버터 펌웨어 양산

[5. AuthenTec (미국) - ARM CPU 설계 (임호균 이사)]

부족 영역에 대한 솔직한 입장과 학습 계획
------------------------------------------------------------

본 프로젝트의 직접 경험이 부족한 영역과 대응 방안:

(1) UDS (ISO 14229)
- 솔직히 자동차 진단 표준 자체의 직접 양산 경험은 없음
- 그러나 본질적으로 CAN 위에 정의된 요청-응답 진단 프로토콜로,
  Modbus / EtherCAT / 산업 진단 프로토콜과 동일한 구조
- ISO 14229 표준 문서 + Vector CANoe 튜토리얼로 1~2주 학습 후
  실무 적용 가능
- CAN 기본 25년+ 경험이 학습 속도를 크게 단축시킴

(2) ISO-TP (ISO 15765-2)
- CAN 8바이트 프레임을 다중 프레임으로 분할/재조립하는 프로토콜
- EtherCAT의 Mailbox / Modbus의 다중 코일 읽기와 동일한 패턴
- ISO 15765-2 표준 문서 1주 학습으로 적용 가능

(3) J2534 Pass-Thru
- 자동차 진단 장비와 PC 간 표준 API
- Windows DLL 형태의 명세된 API 호출 → 학습 부담 낮음
- SAE J2534 표준 + 샘플 코드로 1주 내 학습 가능

(4) DoIP (ISO 13400, 우대)
- 이더넷 위 자동차 진단 프로토콜
- 본 프로젝트는 CAN 기반이 주력이므로 우선순위 낮음
- 향후 확장 시 점진적 학습 계획

(5) MFC
- 과거 경험 있으나 최근 활용은 적음
- 1주 내 재학습 가능
- 핵심 로직(C++)은 즉시 작성 가능, GUI는 점진적 적응

종합: **CAN 통신 25년+ 경력자의 자동차 진단 분야 전환** 형태로,
2주 학습 + 8주 개발의 일정으로 충분히 수행 가능합니다.
