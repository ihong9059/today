## 1. Domino — Codenet Protocol

### 1.1 프로토콜 개요

Domino Codenet은 Domino 산업용 잉크젯 프린터를 외부 컨트롤러(PLC, PC, SCADA)에서 원격 제어하기 위한 독점 통신 프로토콜이다.

**버전:**
- **Codenet 1** — A-Series, A-Series+ 프린터용 (원본 프로토콜)
- **Codenet 2** — Ax-Series (Ax150i, Ax350i, Ax550i), M-Series용. Codenet 1 하위호환, 2바이트 확장 명령(`0x1B 0x7E`) 추가

**지원 프린터:** A-Series, A-Series+, Ax-Series, M-Series, V-Series

**공식 사양서:** Domino Part No. **EPT033760** ("Ax-Series Codenet Communications")

### 1.2 통신 인터페이스

| 인터페이스 | 설명 |
|-----------|------|
| **TCP/IP** | RJ-45 이더넷 포트, 표준 TCP 소켓 연결 |
| **RS-232** | 물리 RS-232 커넥터, 프린터 메뉴에서 Codenet 프로토콜 선택 |

프린터 설정 경로: `Home > Setup > Printer network > Protocol settings > Codenet`

### 1.3 기본 포트 및 연결 설정

**TCP/IP:**

| 항목 | 값 |
|------|-----|
| 기본 포트 | **7000** |
| 보조 포트 | 7001 |
| V-Series 대안 | 9100 |

**RS-232:**

| 파라미터 | 기본값 | 설정 범위 |
|---------|--------|----------|
| Baud Rate | 9600 | 1200 ~ 115200 |
| Data Bits | 8 | 5, 6, 7, 8 |
| Parity | Even | None, Odd, Even |
| Stop Bits | 1 | 1, 2 |
| Flow Control | 설정 가능 | None, RTS/CTS |

**타이밍:**

| 항목 | 기본값 | 범위 |
|------|--------|------|
| Timeout | 3000ms | 100 ~ 600,000ms |
| 재시도 횟수 | 3 | 0 ~ 100 |
| 요청간 지연 | 0ms | 0 ~ 600,000ms |
| 재연결 지연 | 1000ms | - |

### 1.4 메시지 포맷

#### Variant A: Ax-Series / A-Series (Codenet 1 & 2)

```
[ESC] [Command Byte(s)] [Parameters...] [EOT]
```

| 바이트 | Hex | 설명 |
|-------|-----|------|
| ESC | `0x1B` | 명령 시작 구분자 |
| EOT | `0x04` | 전송 종료 (프린터가 이후 수신 중단) |
| ACK | `0x06` | 긍정 응답 |
| NAK | `0x15` | 부정 응답 (이후 3바이트 에러코드) |
| ETX | `0x03` | 텍스트 종료 / SW_RESET |

- 하나의 페이로드에 **다수 명령** 포함 가능 (각각 ESC로 시작)
- Codenet 2 확장 명령: `ESC ~` (`0x1B 0x7E`) 접두사
- **EOT(0x04) 수신 시 프린터는 수신을 중단** — 이후 바이트 무시

#### Variant B: V-Series (SOH/ETB 기반)

```
[SOH] [Command=Value] [STX] [Param] [ETX] [,] [STX] [Data] [ETX] [ETB]
```

| 바이트 | Hex | 설명 |
|-------|-----|------|
| SOH | `0x01` | 헤더 시작 |
| STX | `0x02` | 텍스트 시작 |
| ETX | `0x03` | 텍스트 종료 |
| ETB | `0x17` | 전송 블록 종료 |

#### Variant C: 대안 프레임 (일부 구현체)

```
[STX] [Header: 04 1C 1E] [Layout] [Q1] [ETB] [D] [VarData] [Checksum] [CR]
```

- 문자 인코딩: **CP850** (DOS 코드 페이지)
- 가변 데이터: LF(`0x0A`)로 구분
- 체크섬: **Modulo-256** (STX 제외, 이후 모든 바이트 합의 하위 8비트, 2자리 hex)

```python
checksum = sum(pre_checksum.encode('cp850')) & 0xFF
```

### 1.5 주요 명령어

#### Ax-Series / A-Series (Codenet 1 & 2)

| 명령 | 바이트 | 포맷 | 설명 |
|------|-------|------|------|
| 프린터 ID | `A` (0x41) | `ESC A EOT` | 프린터 ID 조회 |
| 메시지 할당 | `P` (0x50) | `ESC P [head] [msg_num] EOT` | 메시지/라벨을 프린트 헤드에 할당 |
| 메시지 조회 | `P` (0x50) | `ESC P [head] ? EOT` | 현재 할당된 메시지 조회 |
| 헤드 활성화 | `Q` (0x51) | `ESC Q [head] [Y/N] EOT` | 프린트 헤드 활성화/비활성화 |
| 헤드 상태 조회 | `Q` (0x51) | `ESC Q [head] ? EOT` | 헤드 활성 상태 조회 |
| 제품 카운트 | `T` (0x54) | `ESC T 1 ? EOT` | 제품 카운트 조회 (6자리) |
| 카운트 리셋 | `T` (0x54) | `ESC T 1 0 EOT` | 제품 카운터 초기화 |
| 연속 인쇄 | `[` (0x5B) | `ESC [ [head] [Y/N] [pitch] EOT` | 연속 인쇄 모드 설정 |

**명령 그룹 (총 5카테고리, 29개 변수):**
- Information (11): 프린터 ID, RTC, 인코더 설정
- Control (4): 라벨 관리, 헤드 활성화, 카운팅
- Status (6): 상태 변경 리포트, 주문형 상태 조회
- Global Format (6): 인쇄 방향, 반전, 굵기, 간격, 바코드 두께
- Extensions (2): LED 상태, 캐비닛 상태

라벨 인덱스: **000~255**, 바코드 타입 인덱스: **0~4**

#### V-Series (FillSerialVar)

```
SOH + "FillSerialVar=" + STX + [variable_id] + ETX + "," + STX + [variable_value] + ETX + ETB
```

예시 (hex):
```
\x01FillSerialVar=\x0202\x03,\x02BB 05 2024\x03\x17
```

### 1.6 QR코드 데이터 전송

- 바코드/2D 코드 필드는 **프린터에 저장된 라벨/메시지** 내에 생성
- 호스트는 **데이터 내용(텍스트/숫자 문자열)만 전송** → 프린터가 QR 렌더링 처리
- 바코드 두께는 Global Format 명령으로 제어
- 바코드 타입은 라벨 설정에서 인덱스(0~4)로 선택

**일반적인 QR 인쇄 워크플로우:**
1. 프린터에서 QR 코드 필드 포함 라벨 설계 (가변 필드)
2. Codenet 명령으로 해당 라벨 선택 (`ESC P`)
3. 가변 데이터 명령으로 QR 필드에 데이터 전송
4. 외부 트리거 또는 연속 인쇄 모드로 인쇄 실행

### 1.7 Print Done 신호 / 응답 메커니즘

#### ACK/NAK 응답

**가변 포맷 (기본):**

| 응답 | 바이트 | 포맷 |
|------|-------|------|
| ACK | 1 byte | `0x06` |
| NAK | 4 bytes | `0x15 [A] [B] [C]` (3자리 hex 에러코드) |

**고정 포맷:**

| 응답 | 바이트 | 포맷 |
|------|-------|------|
| ACK | 4 bytes | `0x06 0x30 0x30 0x30` |
| NAK | 4 bytes | `0x15 [A] [B] [C]` |

#### 응답 타이밍 옵션 (프린터 설정)

- **On Received** — 데이터 수신 즉시 ACK 전송
- **On Processed** — 명령 **처리 완료** 후 ACK/NAK 전송 (**인쇄 완료 확인에 사용**)

#### 하드웨어 인쇄 신호

- **Printer_Busy** 출력 — 인쇄 처리 중 옵토커플러 ON
- 멀티헤드 시스템: 모든 Printer_Busy 신호의 논리적 OR
- **Product Sensor** 입력 — 외부 인쇄 트리거 (PNP/NPN, DIP 스위치 설정)
- 트리거 설정: `Home > Setup > Production line setup > Print trigger > External`

### 1.8 에러 처리

- NAK 응답 내 **3자리 hex 에러코드** (바이트 A, B, C)
- 에러코드 테이블: EPT033760 문서에 수록
- 주요 에러 카테고리: 잘못된 명령, 프린터 미준비, 라벨 미존재, 헤드 장애, 잉크 시스템 장애
- 타임아웃: 재시도 횟수(0~100), 타임아웃(100~600,000ms) 설정
- 통신 검증: 체크섬(Mod-256)

### 1.9 하드웨어 커넥터 (Ax-Series)

**Ax350i / Ax550i:** Product Sensor, Shaft Encoder, Extended GPIO, GPIO, Beacon, RS232, Alarm, Ethernet(RJ-45), USB Type A, Control Port, Power

**Ax150i:** Product Detect, Shaft Encoder, Alarm, Beacon, Ethernet, RS232, USB Type A, GPIO

## 2. Markem-Imaje — NGPCL Protocol

### 2.1 프로토콜 개요

**NGPCL (Next Generation Printer Control Language)**은 Markem-Imaje의 산업용 프린터를 외부 시스템(PLC, PC, SCADA, MES/ERP)에서 제어하기 위한 독점 통신 프로토콜이다.

기존 레거시 프로토콜(MI protocol / SmartDate protocol)을 대체하여 제품 라인 전체에 통합 인터페이스를 제공한다.

**지원 프린터:**
- **9450 / 9750** — CIJ(연속 잉크젯) 프린터
- **2200 / 5800** — 대문자 잉크젯 프린터
- **SmartDate X-Series** — TTO(열전사 오버프린터)
- **SmartLase** — 레이저 코더

**주요 기능:** 가변 데이터 전송, 인쇄 트리거, 프린터 상태 조회, 에러/장애 정보 검색, 메시지 템플릿 관리

### 2.2 통신 인터페이스

| 인터페이스 | 설명 |
|-----------|------|
| **TCP/IP (Ethernet)** | 주요 방식. 프린터=서버, 호스트=클라이언트 |
| **RS-232** | 레거시 지원, 8N1 기본 |
| **RS-485** | 일부 모델, 멀티드롭 구성용 |

### 2.3 기본 포트 및 연결 설정

**TCP/IP:**

| 항목 | 값 |
|------|-----|
| 기본 포트 | **3000** |
| 대안 포트 | 3001, 4000 (설정 가능) |
| 프로토콜 | TCP (UDP 아님) |
| 연결 | 지속적 소켓 (keep-alive 권장) |
| 인코딩 | ASCII 기반 + 바이너리 프레이밍 |
| Timeout | 5~30초 (설정 가능) |

**RS-232:**

| 파라미터 | 기본값 |
|---------|--------|
| Baud Rate | 9600 (최대 115200) |
| Data Bits | 8 |
| Parity | None |
| Stop Bits | 1 |
| Flow Control | None |

### 2.4 메시지 포맷

```
<STX> [Command] [Separator] [Parameters] <ETX> [Checksum]
```

| 필드 | Hex | 설명 |
|------|-----|------|
| STX | `0x02` | 프레임 시작 |
| Command | ASCII | 명령 키워드/코드 |
| Separator | `;` 또는 `,` | 파라미터 구분자 |
| Parameters | ASCII | 명령별 데이터 |
| ETX | `0x03` | 프레임 종료 |
| Checksum | 1~2 bytes | XOR 또는 CRC (모델별 상이) |

**대안 프레이밍 (일부 모델):**
```
<STX><MessageID>;<Command>;<Param1>;<Param2>;...;<ParamN><ETX>
```

- 일부 구현에서 트랜잭션 ID(시퀀스 번호) 포함
- 프린터 응답도 동일한 STX/ETX 프레이밍 사용

### 2.5 주요 명령어

#### 메시지/잡 선택

```
<STX>SELECT_MESSAGE;messageName<ETX>
```
또는
```
<STX>RECALL;messageName<ETX>
```

#### 가변 데이터 필드 설정

```
<STX>SET_FIELD;fieldName;fieldValue<ETX>
```
인덱스 방식:
```
<STX>SET_VAR;1;LOT12345<ETX>
<STX>SET_VAR;2;2026-04-13<ETX>
<STX>SET_VAR;3;SerialNum001<ETX>
```

#### 인쇄 시작/정지

```
<STX>PRINT<ETX>
<STX>START_PRINT<ETX>
<STX>STOP_PRINT<ETX>
```

#### 프린터 상태 조회

```
<STX>GET_STATUS<ETX>
```
응답: 프린터 상태(READY/PRINTING/FAULT/STANDBY), 잉크 레벨, 에러코드, 인쇄 카운터

#### 카운터 관리

```
<STX>SET_COUNTER;counterName;value<ETX>
<STX>GET_COUNTER;counterName<ETX>
```

#### 장애/에러 조회

```
<STX>GET_FAULT<ETX>
```

#### 복합 명령 (선택 + 데이터 설정 + 인쇄)

```
<STX>PRINT_MESSAGE;templateName;field1Value;field2Value;field3Value<ETX>
```
→ 고속 생산라인에서 가장 효율적인 방식

### 2.6 QR코드 데이터 전송

**설정 프로세스:**

1. **프린터 측 (CoLOS 또는 프린터 UI):**
   - QR 코드 필드 포함 메시지 템플릿 생성
   - 오류 정정 레벨(L/M/Q/H), 모듈 크기, 인코딩 모드 설정
   - 필드를 **가변(variable)** 으로 지정

2. **NGPCL 통해 데이터 전송:**

```
<STX>SET_FIELD;QRCode1;https://example.com/product/12345<ETX>
```
또는
```
<STX>SET_VAR;1;https://example.com/product/12345<ETX>
```

**주요 사항:**
- **프린터가 QR 인코딩 생성** — 호스트는 페이로드 데이터(텍스트)만 전송
- 바이너리 데이터: 일부 모델 Base64 인코딩 지원
- GS1 DataMatrix: FNC1 구분자(`\x1D`) 지원, 모델별 이스케이프 시퀀스 확인 필요

### 2.7 Print Done 신호 / 응답 메커니즘

#### (a) 명령 레벨 ACK/NAK

```
<STX>ACK<ETX>                              — 명령 수락
<STX>NAK;errorCode;errorDescription<ETX>   — 명령 거부
```

#### (b) 인쇄 완료 알림 (비동기 이벤트)

프린터 설정으로 인쇄 후 자동 알림 전송 가능:
```
<STX>PRINT_COMPLETE;printCount;status<ETX>
```
또는
```
<STX>EVENT;PRINT_DONE;OK<ETX>
```

#### (c) 하드웨어 Print Done 신호

- **24V PLC호환 디지털 출력 핀** (프린터 I/O 커넥터)
- 펄스 또는 레벨 방식 설정 가능
- **권장:** 고속 라인에서는 하드웨어 신호로 실시간 동기화, NGPCL은 데이터용

#### (d) 폴링 기반 상태 확인

```
<STX>GET_PRINT_COUNT<ETX>
```

### 2.8 에러 처리

**에러 응답:**
```
<STX>NAK;errorCode;errorText<ETX>
```

| 코드 | 의미 |
|------|------|
| 01 | 알 수 없는 명령 |
| 02 | 잘못된 파라미터 |
| 03 | 메시지/템플릿 미존재 |
| 04 | 필드 미존재 |
| 05 | 프린터 미준비 |
| 06 | 통신 에러 |
| 10 | 잉크 시스템 장애 |
| 11 | 프린트헤드 장애 |
| 20 | 커버 열림 |
| 30 | 리본 장애 (TTO) |

**비동기 장애 이벤트:**
```
<STX>EVENT;FAULT;errorCode;description<ETX>
```

**권장 에러 처리 전략:**
1. 모든 명령 전송 후 ACK/NAK 확인
2. 비동기 이벤트 리스너 스레드 구현
3. 주기적 GET_STATUS로 하트비트/keepalive
4. 소켓 단절 시 자동 재연결 로직
5. 모든 통신 로깅
6. 3~5초 내 응답 없으면 실패 처리

## 3. Videojet — CLARiTY Protocol

### 3.1 프로토콜 개요

**CLARiTY**는 Videojet의 독점 운영자 인터페이스 및 통신 플랫폼이다. 두 가지 역할을 수행한다:

- **HMI:** 프린터 터치스크린 UI
- **외부 통신 프로토콜:** 호스트 시스템(PLC, PC, MES/ERP)에서 원격 제어

**지원 프린터:** Videojet 1580, 1880, 1620 UHS (CIJ), 7340/7440 (레이저), 6530/6330 (TIJ) 등

이전 매뉴얼에서는 **"WSI(Workstation Interface)"** 또는 **"External Data Interface"**로 표기.

### 3.2 통신 인터페이스

| 인터페이스 | 설명 |
|-----------|------|
| **Ethernet (TCP/IP)** | 주요 방식. RJ-45 커넥터 |
| **RS-232** | 레거시 지원. DB-9 커넥터 |
| **RS-485** | 일부 모델, 멀티드롭용 |
| **USB** | 로컬 설정/파일 전송용 (실시간 제어에는 미사용) |

**권장: Ethernet TCP/IP**

### 3.3 기본 포트 및 연결 설정

**TCP/IP:**

| 항목 | 값 |
|------|-----|
| 기본 포트 | **3100** |
| 대안 포트 | 3001, 502 (Modbus TCP) |
| 역할 | 프린터=TCP 서버, 호스트=TCP 클라이언트 |
| IP 설정 경로 | `Settings > Communications > Ethernet` |

**RS-232:**

| 파라미터 | 기본값 |
|---------|--------|
| Baud Rate | 9600 (최대 115200) |
| Data Bits | 8 |
| Parity | None |
| Stop Bits | 1 |
| Flow Control | None (또는 XON/XOFF) |

### 3.4 메시지 포맷

```
<STX> [Command] [Delimiter] [Data Fields...] <ETX> [Checksum]
```

| 필드 | Hex | 설명 |
|------|-----|------|
| STX | `0x02` | 메시지 시작 |
| Command | ASCII | 명령 식별자 (1~4자) |
| Delimiter | `,` 또는 `\t` | 필드 구분자 (모델별 상이) |
| Data | ASCII | 가변 길이 페이로드 |
| ETX | `0x03` | 메시지 종료 |
| Checksum | 선택 | STX~ETX 간 바이트의 XOR 또는 CRC |

- 일부 모델: ETX 대신 **길이 접두사** 사용
- 시리얼 모드: CR/LF (`0x0D 0x0A`) 종료, TCP 모드: STX/ETX 프레이밍

### 3.5 주요 명령어

#### 메시지/잡 선택

```
<STX>SELECT,message_name<ETX>
```

#### 가변 데이터 전송

```
<STX>SETFIELD,field_id,field_data<ETX>
```
인덱스 방식:
```
<STX>VD,1,LOT-2026-0413,2,EXP-2027-0413<ETX>
```

#### 인쇄 시작/정지

```
<STX>PRINT,START<ETX>
<STX>PRINT,STOP<ETX>
```

#### 상태 조회

```
<STX>STATUS<ETX>
```
응답:
```
<STX>STATUS,READY,0000<ETX>
```
상태: `READY`, `PRINTING`, `FAULT`, `STANDBY`

#### 장애 조회

```
<STX>FAULTQUERY<ETX>
```

#### 카운터 리셋

```
<STX>RESETCOUNTER,counter_id<ETX>
```

#### ACK/NAK

```
ACK: 0x06
NAK: 0x15
```

### 3.6 QR코드 데이터 전송

**설정 워크플로우:**

1. **프린터 측:** CLARiTY UI에서 QR/DataMatrix 필드 포함 메시지 템플릿 생성, "External Data" 또는 "Variable" 타입 지정
2. **호스트에서 데이터 전송:**

```
<STX>SETFIELD,3,https://example.com/serial/ABC123<ETX>
```

**주요 사항:**
- QR 인코딩(버전, 오류 정정 레벨) → 프린터 메시지 템플릿에서 설정
- 최대 데이터: QR 기준 최대 4,296 영숫자 (프린터 메모리/설정에 따라 제한)
- 바이너리 데이터: hex 인코딩 지원 (`\x48\x65\x6C\x6C\x6F`)
- GS1 DataMatrix/GS1-128: FNC1 구분자 (`0x1D` 또는 `]d2` 프리앰블) 지원

### 3.7 Print Done 신호 / 응답 메커니즘

#### (a) 하드웨어 Print Complete 신호

- **24V 디지털 출력** (옵토커플러)
- 설정: `Settings > I/O > Outputs > Print Complete`
- **가장 신뢰성 높고 지연 최소** — PLC 연동 권장

#### (b) 프로토콜 레벨 응답

Acknowledged Data Mode / Handshake Mode 설정 시:
```
<STX>PRINTDONE,message_name,count<ETX>
```
또는
```
<STX>ACK,PRINT,sequence_number<ETX>
```

#### (c) 상태 폴링

```
<STX>STATUS<ETX>
```
상태 전이 감시: `PRINTING` → `READY`

**권장:** 하드웨어 I/O(PLC 연동)로 Print Done + 프로토콜 ACK(데이터 무결성)

### 3.8 에러 처리

**장애 코드 범위:**

| 코드 범위 | 카테고리 |
|----------|---------|
| 0000 | 장애 없음 |
| 01xx | 잉크 시스템 (잉크 부족, 점도) |
| 02xx | 프린트헤드 장애 |
| 03xx | 통신 장애 |
| 04xx | 인코더/센서 장애 |
| 05xx | 시스템 장애 |

**에러 응답:**
```
<STX>NAK,error_code,error_description<ETX>
```

| 에러 | 의미 |
|------|------|
| `NAK,01,INVALID_COMMAND` | 인식 불가 명령 |
| `NAK,02,FIELD_NOT_FOUND` | 필드 ID 미존재 |
| `NAK,03,MSG_NOT_FOUND` | 메시지명 미존재 |
| `NAK,04,PRINTER_FAULT` | 프린터 장애 상태 |
| `NAK,05,DATA_OVERFLOW` | 데이터 용량 초과 |

**타임아웃:** 2~5초 내 응답 없으면 재시도 또는 에러 플래그. TCP keepalive 및 자동 재연결 권장.

## 5. PyQt6 통합 구현 가이드

### 5.1 공통 아키텍처

```
┌─────────────────────────────────────────────────────┐
│                  PyQt6 제어 프로그램                    │
├─────────────┬─────────────┬─────────────────────────┤
│  작업자 화면  │  관리자 화면  │  마킹기 연결상태 표시      │
├─────────────┴─────────────┴─────────────────────────┤
│              통신 추상화 레이어 (Protocol Adapter)       │
├────────────┬──────────────┬─────────────────────────┤
│  Codenet   │    NGPCL     │       CLARiTY           │
│  Adapter   │   Adapter    │       Adapter           │
├────────────┴──────────────┴─────────────────────────┤
│          TCP/IP Socket  |  RS-232 Serial            │
└─────────────────────────────────────────────────────┘
```

### 5.2 프로토콜 어댑터 패턴 (Python 예시)

```python
from abc import ABC, abstractmethod

class MarkerProtocol(ABC):
    """마킹기 통신 프로토콜 추상 인터페이스"""

    @abstractmethod
    def connect(self, host: str, port: int) -> bool: ...

    @abstractmethod
    def select_message(self, msg_id: str) -> bool: ...

    @abstractmethod
    def set_variable(self, field_id: str, data: str) -> bool: ...

    @abstractmethod
    def trigger_print(self) -> bool: ...

    @abstractmethod
    def get_status(self) -> dict: ...

    @abstractmethod
    def get_print_count(self) -> int: ...

    @abstractmethod
    def disconnect(self) -> None: ...


class DominoCodenet(MarkerProtocol):
    """Domino Codenet 프로토콜 어댑터"""
    ESC, EOT, ACK, NAK = 0x1B, 0x04, 0x06, 0x15
    DEFAULT_PORT = 7000

    def _build_frame(self, *commands: bytes) -> bytes:
        frame = b''
        for cmd in commands:
            frame += bytes([self.ESC]) + cmd
        frame += bytes([self.EOT])
        return frame


class MarkemNGPCL(MarkerProtocol):
    """Markem-Imaje NGPCL 프로토콜 어댑터"""
    STX, ETX = 0x02, 0x03
    DEFAULT_PORT = 3000

    def _build_frame(self, command: str) -> bytes:
        return bytes([self.STX]) + command.encode() + bytes([self.ETX])


class VideojetCLARiTY(MarkerProtocol):
    """Videojet CLARiTY 프로토콜 어댑터"""
    STX, ETX = 0x02, 0x03
    DEFAULT_PORT = 3100

    def _build_frame(self, command: str) -> bytes:
        return bytes([self.STX]) + command.encode() + bytes([self.ETX])
```

### 5.3 PyQt6 연동 시 주의사항

1. **통신 스레드 분리** — QThread 또는 asyncio를 사용하여 TCP/시리얼 통신을 UI 스레드와 분리
2. **시그널/슬롯 패턴** — 인쇄 완료, 에러 발생 등 이벤트를 Qt Signal로 UI에 전달
3. **비동기 이벤트 수신** — 별도 리스너 스레드에서 프린터 비동기 메시지 수신
4. **재연결 로직** — 네트워크 단절 시 자동 재연결 (지수 백오프 권장)
5. **로깅** — 모든 송수신 데이터 로깅 (생산 디버깅용)
