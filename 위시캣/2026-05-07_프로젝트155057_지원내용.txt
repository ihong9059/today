AISG 3.0 프로토콜 기술 분석 (사전 학습 완료)
============================================================

[1. AISG란?]

AISG(Antenna Interface Standards Group)는 이동통신 기지국 안테나 라인
디바이스(ALD)를 원격 제어/모니터링하기 위한 국제 표준 프로토콜입니다.

적용 대상 디바이스:
- RET (Remote Electrical Tilt) — 안테나 빔 틸트 각도 원격 조정
- TMA (Tower Mounted Amplifier) — 타워 장착 증폭기 제어/모니터링
- GLS (Geographic Location Sensor) — 위치 센서
- ASD (Alignment Sensor Device) — 정렬 센서

[2. 프로토콜 스택 구조 (3계층)]

  +-----------------------------+
  | Application Layer           |  디바이스 제어 명령/응답
  +-----------------------------+
  | Data Link Layer (HDLC)      |  프레임 구조, CRC, 흐름 제어
  +-----------------------------+
  | Physical Layer              |  RS-485 또는 OOK (2.176MHz)
  +-----------------------------+

[3. 물리 계층 (Physical Layer)]

- 전송 방식 1: RS-485 반이중(Half-Duplex) — 전용 케이블 사용
- 전송 방식 2: OOK (On-Off Keying) — 2.176MHz 캐리어를 RF 피더
  케이블에 Bias-T로 주입 (별도 케이블 불필요)
- 기본 Baud Rate: 9,600 bps (9.6 kbit/s)
- 버스 토폴로지: Single-Master Multi-Slave (1:N)

--> 당사 연관: RS-485 Modbus RTU 양산 제품 보유. 반이중 통신,
    9600bps 환경 실전 경험 다수.

[4. 데이터 링크 계층 (HDLC 프레임)]

AISG는 HDLC(High-Level Data Link Control) 프레임 구조를 사용합니다.

  +-------+--------+---------+------+-------+-------+
  | Flag  | Addr   | Control | Info | FCS   | Flag  |
  | 0x7E  | 8bit   | 8bit    | 가변 | 16bit | 0x7E  |
  +-------+--------+---------+------+-------+-------+

- Flag: 0x7E (01111110) — 프레임 시작/종료 구분자
- Address: 8비트 — 슬레이브 디바이스 주소
- Control: 8비트 — 프레임 타입 (I/S/U 프레임)
- Information: 가변 길이 — 명령/데이터 페이로드
- FCS: CRC-CCITT 16비트 (Address+Control+Info 필드 대상)
- Bit Stuffing: 데이터 내 연속 5개 '1' 뒤에 '0' 삽입

--> 당사 연관: BLE Mesh/LoRa 패킷에서 동일한 프레임 구분자/CRC/
    비트 스터핑 패턴 구현 경험. CRC-16 Modbus 양산 적용 중.

[5. AISG 2.0 vs 3.0 주요 차이]

  항목              AISG 2.0              AISG 3.0 (2018~)
  ---------------------------------------------------------------
  제어 포트         단일 컨트롤러         Multi-Primary 지원
                                          (여러 기지국이 동일
                                           디바이스 제어 가능)
  디바이스 발견     기본 스캔             Device Discovery +
                                          Connection Mapping +
                                          Ping 패킷
  커넥터 전원       +12V, 10-30V, -48V    10-30V DC 단일
  사이트 맵핑       미지원                RF 채널별 케이블 연결
                                          자동 맵핑
  IOT 테스트        기본                  강화된 상호운용성
                                          테스트 명령 내장
  PHY 계층          RS-485 / OOK          동일 (하위 호환)

핵심 변경점:
(1) Multi-Primary — 하나의 ALD를 여러 컨트롤러가 제어
(2) Device Discovery — 버스에 연결된 모든 디바이스 자동 탐색
(3) Connection Mapping — RF 채널 ↔ 케이블 연결 자동 파악
(4) Ping Packet — 모든 RF 채널에서 핑 송수신 → 장애 감지

--> 당사 연관: BLE Mesh 3,800대 디바이스 스캔/인식과 동일 패턴.
    Device Discovery = BLE Scan, Connection Mapping = Mesh Routing
    Table, Ping = BLE Heartbeat과 구조적으로 대응.

[6. 포팅 작업 핵심 포인트 (2.0 → 3.0)]

기존 AISG 2.0 C++ 소스에서 변경이 필요한 영역:

a) Device Discovery 로직 추가
   - 버스 스캔 → 응답 수집 → 디바이스 목록 구성
   - 기존 단순 주소 지정 방식에서 자동 탐색으로 확장

b) Multi-Primary 지원
   - 제어 포트별 독립 상태 관리
   - 동시 접근 시 충돌 방지 메커니즘

c) Connection Mapping
   - Ping 패킷 송수신 → RF 채널별 연결 맵 구성
   - 새로운 패킷 타입/명령 코드 추가

d) Ping Packet 구현
   - 모든 RF 채널에서 핑 발신/수신 감지
   - 장애 탐지 및 초기 설치 시 검증 도구

e) PHY 계층 변경 없음
   - RS-485 / OOK 물리 계층은 2.0과 동일
   - 기존 하드웨어 모뎀 호환

--> 당사 강점: (a)~(d) 모두 BLE Mesh 3,800대 시스템에서
    구현한 패턴과 구조적으로 동일. PHY 변경 없음은
    펌웨어 레벨 포팅에 집중할 수 있어 유리.

============================================================
지원 사유
============================================================

안녕하세요. 임베디드 시스템 엔지니어 홍광선입니다.

본 프로젝트는 C++ 기반 MCU 펌웨어에서 통신 프로토콜을 업그레이드하는
작업으로, 저희 팀의 핵심 역량과 정확히 일치합니다.

저희는 2인 팀(펌웨어 38년 + 회로설계 25년)으로, RS-485/Modbus RTU
기반 산업용 컨트롤러를 직접 설계하여 양산 판매 중이며,
BLE Mesh/LoRa/EtherCAT/CAN 등 4종의 통신 프로토콜을 실제 제품에
구현한 경험이 있습니다.

특히 일본 자전거주차장 프로젝트에서 BLE Mesh 프로토콜 기반
3,800대 규모의 디바이스 스캔/인식/제어 시스템을 개발하여
실제 수출까지 완료한 실적이 있어, AISG 3.0의 디바이스 스캔 및
프로토콜 포팅 작업에 직접 적용 가능한 노하우를 보유하고 있습니다.

AISG 프로토콜 스펙을 사전 분석한 결과, HDLC 프레임(0x7E 구분자,
CRC-CCITT 16bit) + RS-485 반이중 9600bps 구조로, 저희가 양산 중인
Modbus RTU 컨트롤러와 동일한 물리/데이터링크 계층입니다.
AISG 3.0의 핵심 변경점인 Device Discovery, Connection Mapping,
Ping Packet은 BLE Mesh 3,800대 시스템에서 구현한 디바이스 스캔/
라우팅 테이블/하트비트와 구조적으로 대응되어 즉시 착수 가능합니다.

또한 현장 테스트 장소인 용인시 기흥구에 저희 사무실이 위치하고
있어 즉시 방문이 가능합니다.
