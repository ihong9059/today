## 🎬 시연 자료 4건 (강도순)

### 1️⃣ ⭐ 최강 카드 — REVITA OOK Replay (CC1101 직접 구현)

**왜 강력한가**: AISG의 두 PHY 옵션 중 OOK 변조는 다른 응시자가 보통 학습부터 시작해야 하는 영역. **저희는 5월에 직접 구현 완료** 상태. 캐리어 주파수만 다르고 변조 원리 동일.

#### 시연 시나리오 (5분)

```
"AISG의 두 PHY 옵션 중 OOK 변조 부분을 어떻게 구현했는지 보여드리겠습니다."

[화면 1 — 1분] CC1101 SPI 드라이버 코드 (cc1101.c)
   "Zephyr RTOS 공식 드라이버가 없어서 SPI 통신부터 직접 작성했습니다."
   → 레지스터 접근 함수 / 데이터 시트 매핑 보여줌

[화면 2 — 1분] OOK 변조 설정 (cc1101_ook.c)
   "캐리어 주파수 447.925 MHz, 데이터 레이트 ~3,769 bps, OOK On-Off Keying."
   "AISG는 캐리어 2.176 MHz로 다르지만 변조 원리 동일합니다."

[화면 3 — 1분] TX 앱 (main.c) — 패킷 생성·CRC·송신
   "이 흐름이 AISG HDLC 프레임 송신과 거의 동일합니다."

[화면 4 — 1분] 실제 동작 동영상
   "송신측 버튼 → RF 신호 → 수신측 LED 토글."

[종합 — 30초] AISG 매핑
   "AISG 2.176 MHz Bias-T 도 동일 원리. 캐리어만 바꾸면 됩니다."
```

### 2️⃣ BLE Mesh 일본 자전거주차장 3,800대 양산

**의미**: 디바이스 스캔 3,800대 = AISG Device Discovery 동일 패턴 (대규모).

#### 시연 자료 (2~3분)

| 항목 | 자료 |
|---|---|
| 일본 현장 설치 사진 | 하네다공항 아나모리나역 / 나고야 사카에역 |
| 양산 출하 사진 | 3,800대 박스 (가능 범위) |
| 인증서 PDF | KC / TELEC / CE |

#### 클라이언트에게 전달할 메시지

> "디바이스 3,800대를 양방향 통신으로 스캔·관리한 실 운용 경험입니다. AISG 3.0의 Device Discovery + Multi-Primary + Connection Mapping은 모두 BLE Mesh 게이트웨이 ↔ 노드 구조에서 양산 검증된 패턴입니다."

### 3️⃣ Modbus RTU 컴프레서 밸브 컨트롤러 (RS-485 양산)

**의미**: AISG의 RS-485 PHY + CRC-16 = 동일 패턴, 양산·KC 인증 완료.

#### 시연 자료 (2분)

- 컴프레서 밸브 컨트롤러 제품 사진 1~2장
- KC 인증서 PDF
- Modbus RTU CRC-16 계산 코드 (10~20줄 snippet)
- 프레임 파싱 코드 snippet

#### 클라이언트에게 전달할 메시지

> "AISG의 RS-485 PHY 옵션은 저희가 이미 양산 중인 Modbus RTU 컨트롤러와 같은 물리 계층입니다. CRC-CCITT 16은 Modbus의 CRC-16과 다항식만 다른 동일 계산 방식이고, HDLC 프레임 파싱도 Modbus 프레임 파싱 패턴 그대로 적용 가능합니다."

### 4️⃣ REVITA Solar Monitor 풀스택 (옵션 — 시간 있으면)

**의미**: 통신 + 현장 배포 + 운용 풀스택 능력 입증 (현장 테스트 단계 신뢰도 ↑).

#### 시연 자료 (1~2분)

- RAK4631 + INA219 + LoRa SF12 + Flask Web UI 실시간 동작 화면
- Chart.js 차트 (현장 운용 중)
- systemd 서비스 등록 자료

#### 클라이언트에게 전달할 메시지

> "AISG 프로젝트의 Phase 5(현장 연동 테스트) 패턴이 저희가 운용 중인 REVITA Solar 시스템과 동일합니다. 통신·HW·서버·UI·systemd 운용까지 풀스택 자체 처리 가능합니다."
