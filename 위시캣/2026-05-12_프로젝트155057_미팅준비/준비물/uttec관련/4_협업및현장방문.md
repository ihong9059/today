# 요구 #4 — 협업 방식 + 현장 방문 계획

> 클라이언트 요구:
> - "내부 엔지니어와의 협업, 현장 방문이 필요한 프로젝트입니다."
> - "파트너님께서 업무 진행하실때 어떤 방식으로 협업을 하시는지, 현장 방문 일정은 어떻게 계획하고 계신지 등에 대해 설명해주시기 바랍니다."

## 🤝 협업 방식 (3가지 측면)

### 1. UTTEC 내부 협업 (2인 팀)

| 역할 | 담당 | 본 프로젝트 분담 |
|---|---|---|
| **홍광선** (대표, 펌웨어 38년) | SW 전반 / 임베디드 코드 / 통신 프로토콜 / 시뮬레이션 | Phase 1~4 주력 |
| **임호균** (회로설계 25년 + ARM CPU 설계) | HW 측 / RF 신호 측정 / 회로 분석 / 현장 진단 | Phase 5 동행, 필요 시 Phase 3 |

> 1인 외주 대비 강점: **HW 측 즉시 대응 가능**. 본 프로젝트의 핵심 위험인 "현장 RF 노이즈 / 케이블 손실"은 HW+SW 동시 진단이 필요한 영역.

### 2. 클라이언트 내부 엔지니어와의 협업

#### 정기 동기 (Sync)

| 주기 | 형식 | 시간 | 내용 |
|---|---|:-:|---|
| **격주 1회** | 클라이언트 미팅 (마일스톤 보고) | 60분 | Phase별 진척·산출물·이슈 |
| **주 1회** | 메신저 진척 보고 (텍스트 + 스크린샷) | 비동기 | 주간 작업 요약 |
| 필요 시 | 화상 회의 (Google Meet / Teams) | 30분 | 즉시 이슈 협의 |

#### 비동기 도구 (제안)

| 도구 | 용도 |
|---|---|
| 메신저 (카톡 / Slack / 클라이언트 선호) | 일상 소통 |
| Git Private Repository (GitHub / GitLab) | 소스 코드 (NDA 준수) |
| 이슈 트래커 (GitHub Issues / Notion) | 버그·진척 추적 |
| 공유 폴더 (Google Drive / Dropbox) | 산출물 문서 |

→ **클라이언트 측 선호 도구에 맞춰** 사용. UTTEC는 모든 주요 도구 사용 경험 보유.

### 3. NDA + 보안 정책

| 항목 | 정책 |
|---|---|
| 소스 코드 | Private Repository + UTTEC 측 2인만 접근 |
| 클라이언트 자료 | UTTEC 사무실 외부 반출 금지 (USB·노트북 분리) |
| 통신 로그 | 프로젝트 종료 후 30일 보관 + 삭제 |
| 보안 사고 | 발견 즉시 24시간 내 클라이언트 통보 |

> NDA 서약 후 본격 협업 진입. 본 미팅에서 NDA 양식 확인 가능.

## 🚗 현장 방문 계획 (용인 기흥구)

### 핵심 강점 — 현장 동일 지역

```
UTTEC 사무실     : 경기도 용인시 기흥구 흥덕유타워 2404호
AISG 현장        : 경기도 용인시 기흥구 (공고 명시)

거리                : 같은 지역 (차로 15~30분 이내 추정)
출장비              : 0 (인근)
디버깅 사이클        : 현장 → 사무실 → 현장 당일 가능
```

→ **다른 지역 외주가 따라올 수 없는 본질적 강점**.

### Phase별 현장 방문 일정 (예상)

| Phase | 주차 | 방문 횟수 | 목적 | 동행 |
|:-:|---|:-:|---|---|
| 1 | Week 1~2 | 1회 (옵션) | 환경 확인·인사 | 홍광선 단독 |
| 2 | Week 3~4 | 1회 | 실 ALD 장비 (있다면) 통신 로그 캡처 | 홍광선 단독 |
| 3 | Week 5~8 | 0~1회 | (사무실 작업 중심, 필요 시 1회) | 홍광선 단독 |
| 4 | Week 9~10 | 0회 | (사무실 통합 테스트) | — |
| 5 | **Week 11~12** | **2~3회** | **실증 핵심 단계** | **임호균 동행** |
| 6 | Week 13 | 1회 | 최종 인계·검수 | 홍광선 단독 |

→ **총 5~8회** 현장 방문 (Phase 5 집중)

### Phase 5 (Week 11~12) — 현장 핵심 일정

#### Week 11 — 1차 현장
- 일정 (예): 월·수·금 3회 방문
- 작업:
  - 현장 셋업 + 통신 수립 확인
  - Device Discovery 실증 (실 ALD 1~3대 인식)
  - Multi-Primary 실증
  - 발견 이슈 → 사무실 즉시 수정 → 다음 방문 시 재현장
- 동행: **임호균 (HW 측 즉시 진단)**

#### Week 12 — 2차/3차 현장
- 일정 (예): 화·목 2회 방문
- 작업:
  - Connection Mapping + Ping 실증
  - 부하·내구성 (수 시간 연속 동작)
  - 인증 적합성 사전 점검
- 동행: 임호균 (필요 시)

### 현장 방문 절차 (1회당)

```
[D-1일] 클라이언트 측 담당자에 방문 확정 (메신저)
        + 사전 점검 자료 송부 (PDF, 무엇을 할지)

[당일 09:00] 사무실 출발 (홍광선 + 필요 시 임호균)
[당일 10:00] 현장 도착 + 클라이언트 측 담당자 인사
[당일 10:00~16:00] 작업 (셋업·통신·실증·로그 캡처)
[당일 16:00~17:00] 발견 이슈 정리 + 사진·동영상·로그 수집
[당일 17:00] 클라이언트와 일일 보고 (10~15분 구두 + 후속 메신저 보고)
[당일 18:00] 사무실 복귀 (필요 시 즉시 디버깅)

[D+1일] 발견 이슈 수정 + 메신저로 클라이언트에 진척 보고
```

## 💬 의사소통 원칙

| 원칙 | 설명 |
|---|---|
| **응답 시간 ≤ 4시간** (업무 시간 내) | 메신저·이메일 4시간 내 응답 보장 |
| **주간 보고 의무** | 매주 금요일까지 진척 요약 송부 |
| **이슈 사전 공유** | 일정 위험·기술 위험 발견 즉시 공유 (숨기지 않음) |
| **마일스톤 미팅 사전 자료** | 격주 미팅 48시간 전 자료 송부 |
| **변경 사항 문서화** | 모든 결정·변경 메일·메신저로 박제 |

## 🏃 비상 대응 (위험 시나리오)

| 시나리오 | 대응 |
|---|---|
| 현장 RF 환경에서만 발생하는 이슈 | **임호균 동행**으로 HW + SW 동시 진단. 사무실 동일 지역 → 당일 디버깅 |
| 클라이언트 측 담당자 변경 | 인계 미팅 60분 즉시 요청 + 진척 자료 재공유 |
| 일정 위험 발견 (-1주 이상) | 클라이언트와 즉시 협의 (Scope 축소 또는 일정 연장) |
| HW 손상 / 장비 고장 | 임호균이 사무실에서 회로 분석 + 대체 장비 수배 |
| 보안 사고 의심 | 24시간 내 클라이언트 통보 + 사고 보고서 작성 |

## ⚙️ 본 미팅에서 확인할 사항 (우리 → 클라이언트)

미팅 시 우리가 물어볼 항목 (`08_미팅에서_물어볼_질문.md` 참조):

1. **클라이언트 측 담당자 / 협업 인원**
   - 누가 어떤 역할인가요?
   - 기술 결정권자는 누구입니까?

2. **현장 정확한 위치 / 접근 절차**
   - 정확한 주소·연락처
   - 보안 절차 (사전 신고 / 출입증)
   - 평일 작업 가능 시간대

3. **실 ALD 장비 보유 여부**
   - 사무실에서 검증 가능한 mock 장비 대여 가능?
   - 또는 현장에서만 가능?

4. **결과물 인계 형식**
   - 소스 코드 / 문서 / 동영상 어떤 형태?
   - 검수 절차?
