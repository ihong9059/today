# 요구 #3 — 개발 방식 (⭐ 가장 중요한 요구)

> 클라이언트 요구 원문:
> - "클라이언트가 생각하는 개발 방식은 **AISG 쪽 소스코드를 가지고 계신 경험자가 3.0으로 버전 업데이트를 진행하여 쉽고 빠르게 구현하는 방식**입니다."
> - "이 방식으로 진행가능하실지 먼저 검토해주시고, 이 방식이 불가하다면 **파트너님만의 강점/프로젝트 진행시 수행 타임라인**을 자세히 설명해주시기 바랍니다."

## 🎯 답변 전략 — 3단 구조

### Step 1: 사실을 정직하게 명시 (신뢰 신호)

> "솔직하게 먼저 말씀드리면, 저희는 **AISG 양산 소스 코드는 보유하고 있지 않습니다**. AISG 직접 양산 경험도 없습니다. 다만 위시캣 공고 #155057을 본 직후인 2026-05-07에 AISG 3.0 스펙을 사전 학습 완료한 상태입니다."

→ 정직 시그널이 첫 신뢰 토대. 부풀리기 시 후속 검증 시 신뢰 추락.

### Step 2: 클라이언트의 "쉽고 빠르게" 의도를 충족할 수 있는 두 가지 경로 제시

#### 경로 A — 클라이언트 측 기존 소스 제공 (클라이언트가 원하는 방식 그대로)

> "공고 본문에 '기존 C++ 소스 기반'이라는 표현이 있던데, **클라이언트께서 기존 AISG 2.x 소스 코드를 보유하고 계시고 NDA 하에 제공 가능하시다면**, 저희는 그 소스를 인수받아 3.0으로 버전 업데이트하는 방식이 가장 빠르고 안전합니다."

→ **클라이언트에게 질문 전환**: "혹시 기존 보유 소스가 있으신가요?"
→ 클라이언트가 "있다"고 답할 가능성 (공고 문구 근거) → 우리는 그 방식대로 진행 가능

#### 경로 B — 처음부터 자체 구현 (소스 제공 불가 시)

> "만약 기존 소스 제공이 어렵다면, 저희는 **AISG 표준 문서(AISG v3.0) + 유사 양산 자산**으로 90일 안에 처음부터 안정 구현 가능합니다. 그 근거가 아래 강점 5가지입니다."

## 💪 자체 강점 5가지 — 처음부터 시작해도 90일 안에 가능한 이유

### ① OOK PHY 직접 구현 자산 (★ 희소)

- **5월에 CC1101 트랜시버로 직접 구현 완료**
- Zephyr RTOS 공식 드라이버 없어 SPI 통신부터 자체 작성
- AISG는 캐리어 2.176 MHz, 변조 원리 동일
- → 다른 응시자가 학습부터 시작해야 하는 영역을 **즉시 적용 가능**

### ② BLE Mesh 3,800대 양산 — Device Discovery·Multi-Primary 패턴 검증

- 일본 자전거주차장 BLE Mesh 3,800대 양산 수출
- 디바이스 스캔/인식·게이트웨이 동시성·라우팅 테이블 모두 양산 검증
- AISG 3.0 신규 변경점 4개 모두 BLE Mesh에서 구현한 패턴
- → AISG 3.0 핵심 부분의 **알고리즘 학습 비용 0**

### ③ RS-485 Modbus RTU 양산 + KC 인증 — AISG RS-485 PHY 즉시 대응

- STM32F756 컴프레서 밸브 컨트롤러 양산
- 반이중 9,600 bps + CRC-16 + 다중 슬레이브
- KC 인증 완료
- → AISG RS-485 PHY는 **물리 계층 기반 그대로 활용**

### ④ 현장 동일 지역 (용인 기흥구) — 디버깅 사이클 단축

- UTTEC 사무실: 경기도 용인시 기흥구 흥덕유타워
- AISG 현장: 경기도 용인시 기흥구 (공고 명시)
- → 현장 발견 이슈 → 사무실 즉시 수정 → 당일 재현장 가능 (디버깅 사이클 ↓)
- → Phase 5 (현장 연동 테스트) 단계에서 큰 이점

### ⑤ HW + SW 통합 2인 팀 (홍광선 + 임호균)

- 홍광선: 펌웨어 38년 (삼성/파나소닉/UTTEC)
- 임호균: 회로설계 25년, ARM CPU 설계 (AuthenTec), CAN/RS485 (대한전선)
- → 현장 RF 노이즈·케이블 손실 등 HW 측 이슈도 **즉시 진단·해결**
- → 1인 외주의 약점(HW 측 진단 불가) 보완

## 🔍 클라이언트 후속 질문 예상 + 답변

### Q1. "AISG 직접 경험이 없으신데 어떻게 신뢰할 수 있나요?"

> "정직하게 말씀드린 것 자체가 신뢰 시그널입니다. 부풀려 답변했다가 진행 중 발각되는 위험을 사전에 차단했습니다. 그리고 **AISG의 핵심 알고리즘인 신규 4개 기능(Device Discovery·Multi-Primary·Connection Mapping·Ping)은 BLE Mesh 3,800대 양산에서 모두 구현한 패턴**입니다. AISG라는 이름은 처음이지만, 그 안의 알고리즘은 처음이 아닙니다."

### Q2. "기존 외주가 했던 코드가 있는데 그걸 받아서 이어갈 수 있나요?"

> "물론입니다. C++ 레거시 분석은 삼성·파나소닉 양산 프로젝트에서 38년 경력으로 다수 경험했습니다. **Phase 1 (Week 1~2)** 에서 기존 코드 구조 / 빌드 환경 / 진입점 / 상태 머신을 파악하고, **Phase 2 (Week 3~4)** 에서 회귀 테스트 베이스를 구축합니다. 이후 Phase 3에서 3.0 변경점 4개를 추가하는 방식으로 진행합니다."

### Q3. "왜 90일인가요? 더 빨리 안 되나요?"

> "90일은 다음을 모두 포함한 안전 일정입니다: (1) 기존 코드 분석 2주, (2) 2.0 회귀 베이스 2주, (3) 3.0 변경점 4개 각 1주씩 + 통합 4주, (4) 자체 통합 테스트 2주, (5) 현장 연동 2주, (6) 안정화·인계 1주. 만약 기존 코드 품질이 좋고 분석이 빠르면 80일 안에도 가능합니다. 다만 안전 마진을 두는 게 양쪽에 좋다고 봅니다."

### Q4. "1인 기업이라 진행 중 문제가 생기면?"

> "임호균 협업자가 회로 측 25년 경력으로 즉시 대응 가능합니다. 그리고 본 프로젝트의 핵심 위험인 'RF 현장 이슈'는 HW + SW 동시 디버깅이 필요한데, 2인 팀이 1인 외주보다 유리한 부분입니다. 또한 **사무실이 용인 기흥구로 현장과 같은 지역**이라 현장 → 사무실 → 현장 디버깅 사이클이 당일에 가능합니다."

### Q5. "단가는 어떻게 되나요?"

> "공고 예산 2,400만원을 기준으로 협의 가능합니다. 만약 경로 A (기존 소스 인수)로 진행 시 분석 비용이 줄어 단가 인하 협의도 가능합니다. 결제 조건은 30/20/20/30 단계 결제로 클라이언트 부담을 분산하는 안을 가지고 왔습니다."
