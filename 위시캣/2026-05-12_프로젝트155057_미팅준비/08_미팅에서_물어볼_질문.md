# UTTEC가 클라이언트에게 물어볼 질문 15개

> 미팅은 양방향. 클라이언트가 묻기만 하면 수동적 인상. UTTEC가 사전 준비된 질문을 던지면 **프로페셔널 + 진심 + 위험 사전 식별** 효과.

## 🎯 우선순위 (S = 반드시 / A = 권장 / B = 시간 되면)

## S급 — 반드시 묻기 (5개)

### Q1 [S] — 기존 C++ 소스 코드 규모와 상태?

**왜 묻나**: Phase 1 (코드 분석) 일정 추정에 직접 영향. 가장 큰 위험 (06 문서 §위험 1) 사전 진단.

**구체적 질문**:
1. 라인 수 추정 (수천 / 수만 / 수십만 라인?)
2. 빌드 환경 (Keil / IAR / GCC / Make / CMake?)
3. 타깃 MCU (STM32 / NXP / Nordic / 자체 ASIC?)
4. 주석·문서 수준 (영어? 한글? 부재?)
5. 원작성자가 누구이고, 추가 질의 가능?

**답변에 따른 행동**:
- 수만 라인 + 주석 부재 → Phase 1 일정 +1주 사전 협의
- 빌드 환경이 옛 Keil → 라이선스 / 도구 확보 협의

### Q2 [S] — 실 AISG ALD 장비 제공 여부?

**왜 묻나**: Phase 2~5 검증 환경 결정. 위험 2 (06 문서) 사전 진단.

**구체적 질문**:
1. 실 ALD 장비 (RET / TMA / GLS / ASD) 보유?
2. UTTEC 사무실로 가져갈 수 있나? 또는 현장 전용?
3. 모뎀 / 시뮬레이터 제공?
4. 자체 시뮬레이터 작성이 필요한가?

**답변에 따른 행동**:
- 제공 안 됨 → 자체 시뮬레이터 구축 시간 +3~5일 추가
- 사무실 가져갈 수 있음 → Phase 4 단축 가능

### Q3 [S] — 현장 (용인 기흥구) 접근 절차?

**왜 묻나**: Phase 5 현장 테스트 일정 결정. 차별화 (동일 지역) 활용.

**구체적 질문**:
1. 현장 정확한 위치?
2. 방문 가능 시간대 (평일만? 주말 가능?)?
3. 사전 신청 절차?
4. 야간 작업 필요?
5. 안전 / 보안 교육 필요?

**답변에 따른 행동**:
- 주말 가능 → 일정 유연성 ↑
- 사전 신청 1주 → Phase 5 시작 1주 전 신청 트리거

### Q4 [S] — 클라이언트가 기대하는 산출물?

**왜 묻나**: Scope 명확화. 위험 6 (Scope creep) 사전 방지.

**구체적 질문**:
1. 본 90일 결과물 = "포팅된 펌웨어"만? 또는 추가?
2. 사용자 매뉴얼·문서 필요?
3. 보증 기간 기대치?
4. 인계 후 유지보수 별도 계약?
5. 인증 (AISG / 통신) 절차 본 Scope에 포함?

**답변에 따른 행동**:
- 인증 포함 기대 → "별도 견적" 정중히 안내
- 보증 기간 6개월+ 기대 → 단가 협상에 반영

### Q5 [S] — 결제 조건 + 일정 결정 권한자?

**왜 묻나**: 협상 시 의사결정 속도 파악. 후속 follow-up 누구에게.

**구체적 질문**:
1. 미팅 참석자의 역할 (PM? 기술 책임자? 결정권자?)?
2. 단가·일정 협상 권한이 미팅 자리에 있나?
3. 사내 결정 절차 (보고 → 승인) 며칠 소요?
4. 계약서 작성·검토 일정?

**답변에 따른 행동**:
- 결정권자 미참석 → "추가 자료 보내드리고, 사내 검토 후 결정" 흐름
- 결정권자 참석 → 미팅 자리에서 합의 가능성 ↑

## A급 — 권장 (5개)

### Q6 [A] — 본 프로젝트의 사업 배경?

**구체적 질문**:
1. 어떤 사업·고객 위해 AISG 3.0 포팅이 필요한가?
2. 기지국 운영자 측 요구사항? 통신사 요구?
3. 본 펌웨어가 들어갈 최종 제품 종류 (RET / TMA?)?
4. 양산 계획 일정?

**왜 묻나**: 진심 어린 관심 = 신뢰. 그리고 향후 영업 / 확장 기회 발견.

### Q7 [A] — 동시 진행 다른 응시자 있나?

**구체적 질문**:
1. 다른 후보 회사들과 동시 미팅?
2. 결정 일정?
3. 본인이 비교 대상의 어떤 점이 부족 / 강점인지?

**왜 묻나**: 경쟁 상황 파악 + 약점 보강 기회.

### Q8 [A] — Multi-Primary 실제 사용 환경?

**구체적 질문**:
1. 실 환경에서 컨트롤러 몇 대 동시 사용?
2. 명령 빈도 (초당 N건)?
3. 응답 시간 요구사항 (ms)?
4. 동시성 충돌 발생 시 우선순위 규칙?

**왜 묻나**: Phase 3 Multi-Primary 구현 세부 결정 + 위험 4 (06 문서) 진단.

### Q9 [A] — 인증 / 검수 기준?

**구체적 질문**:
1. 본 작업 완료 검수 기준 (어떤 테스트 통과)?
2. 인증 받을 계획 있다면 누가 진행?
3. AISG 호환성 인증 시험 기관?
4. 클라이언트 측 자체 검증 절차?

**왜 묻나**: 인계 시 분쟁 방지.

### Q10 [A] — 후속 사업 기회?

**구체적 질문**:
1. 본 프로젝트 성공 시 추가 프로젝트?
2. 다른 통신 프로토콜 작업 계획?
3. 양산 후 유지보수 / 펌웨어 업데이트 작업?

**왜 묻나**: 장기 관계 + 영업 자산화.

## B급 — 시간 되면 (5개)

### Q11 [B] — UTTEC 측에 기대하는 의사소통 빈도?

**구체적 질문**:
1. 진척 보고 주기 (주간? 격주? 마일스톤?)?
2. 보고 형식 (이메일? 화상 미팅? 대면?)?
3. 긴급 상황 시 연락 채널?

### Q12 [B] — 클라이언트 측 협조 의무?

**구체적 질문**:
1. 기존 코드 작성자에게 질의 가능?
2. 실 환경 데이터 (실 ALD 통신 캡처)?
3. AISG 표준 문서 사본?

### Q13 [B] — 위험 시나리오 시 책임 분담?

**구체적 질문**:
1. 클라이언트 측 HW 이슈로 일정 지연 시?
2. AISG 표준 자체 모호한 부분 발견 시?
3. 실 ALD 장비 고장 시?

### Q14 [B] — 본인 회사의 다른 양산 제품?

**구체적 질문**:
1. AISG 외 다른 통신 제품?
2. 본인 회사의 시장 위치 (통신 장비 분야)?
3. 본 제품의 경쟁사?

### Q15 [B] — 본인 회사의 가치관 / 사풍?

**구체적 질문**:
1. 외주에 기대하는 것 (속도? 품질? 비용?)?
2. 이전 외주와의 협업 경험에서 만족 / 불만족?
