## 🔑 핵심 메시지 — 미팅에서 반드시 전달

### 1. 정직 시그널 (요구 #3 대응)
> "AISG v3.0 양산 소스·직접 양산 경험은 없음. 단, **PHY 2종(RS-485·OOK) 모두 직접 구현 경험**, HDLC 프레임 처리 4종 양산, BLE Mesh 3,800대 디바이스 스캔·라우팅·heartbeat 패턴 = AISG v3.0 신기능 4종과 구조적으로 동형."

### 2. PHY 변경 0% (핵심 시간 절약)
> "v2.0 → v3.0 마이그레이션의 가장 큰 차이는 **응용 계층(L3) 4가지 신기능**. PHY·HDLC는 동일하므로 기존 v2.0 코드의 PHY·링크 계층은 그대로 재사용 가능. 작업의 90%가 v3.0 신기능 4종 구현에 집중됨."

### 3. OOK PHY 자산 — 차별화
> "AISG 두 PHY 옵션(RS-485 + OOK) 모두 가진 외주는 드뭄. 우리는 CC1101 447.925 MHz OOK Replay 시스템 자체 구현 자산 보유(2026-05). v3.0의 OOK 2.176 MHz Bias-T 옵션 즉시 대응 가능."

### 4. 13/13 매칭 + 13주 일정
> "AISG v3.0 요구 13개 항목 ↔ UTTEC 보유 자산 13개 1:1 매칭. 13주 Phase 1~6 일정 + 6회 진척 미팅 = 클라이언트 가시성 확보."

### 5. 정직한 위험 명시
> "Multi-Primary 동시성 버그가 가장 큰 위험. BLE Mesh 양산 mutex 패턴 재사용 + ThreadSanitizer 활용으로 완화. Phase 3 (Week 5~8) 핵심 집중."

## ⚠️ 본 자료의 한계 (정직 명시)

1. **실 코드 미공개**: AISG 공식 표준은 명령 코드 매핑(예: SetTilt = 0x82 같은 정확한 binary 코드)을 PDF로만 배포. 본 자료는 명령 **이름·시맨틱** 위주이며, 정확한 binary 매핑은 클라이언트의 v2.0 소스 인수 후 확정.
2. **벤더별 차이**: 명령 응답 데이터 포맷·범위는 ALD 벤더(Kathrein, CommScope, Ericsson 등)에 따라 미세 차이. 본 자료는 표준 일반론.
3. **3GPP TS 정확한 release**: TS 25.46x 시리즈는 release별(Rel-12, 13 등)로 미세 차이. 본 자료는 Rel-13 기준 일반론.

→ 미팅에서 위 한계를 정직하게 명시 = 신뢰 가산. "표준 일반은 사전 학습 완료, 정확한 binary 매핑은 소스 인수 후 1주 내 마스터" 메시지.
