# AISG의 목적과 배경 — 왜 이 표준이 필요한가

> 위시캣 #155057 미팅 (2026-05-13) 대비 — AISG가 풀고자 하는 문제, 통일시키는 대상, 이해관계자.
> 학습 권장: **본 문서를 가장 먼저 읽고** → 01 상세 spec → 02 비교 → 03 ALD 타입 순서로 진행.

---

## 1. 한 줄 정의

> **AISG = 이동통신 기지국 안테나 끝단에 매달려 있는 모든 원격 제어 장비(ALD)를 벤더 상관없이 표준화된 한 가지 방식으로 제어·모니터링하기 위한 국제 표준 프로토콜.**

핵심 키워드 3개:
1. **안테나 라인 디바이스(ALD)** — 안테나 + 그 뒤에 매달린 모든 능동 장비
2. **벤더 무관 (Multi-vendor)** — Kathrein 안테나 + CommScope TMA + Ericsson RET이 한 버스에 공존
3. **원격 제어** — 사람이 타워 올라가지 않고 사무실에서 조정

## 2. AISG 이전 — 표준이 없었을 때의 문제

### 2.1 안테나 조정의 고통

```
[과거 — AISG 이전]

   안테나 빔이 잘못 조정되어 옆 셀 간섭 발생
        ↓
   해결책: 작업자가 타워 위로 올라가서
        ↓
   안테나 케이스 열고 → 기계적 틸트 나사 회전
        ↓
   다시 내려와서 측정 → 또 올라가서 조정 → ...
        ↓
   1회 조정에 4~8시간 + 안전 위험 + 셀 다운타임
```

문제점:
- **고비용**: 타워 등반 인력 + 안전 장비 + 셀 다운타임
- **느림**: 셀 1개 조정에 반나절
- **위험**: 추락사고 (실제 사망사고 다수)
- **비반복적**: 한 번 올라가서 정확하게 못 맞추면 재등반

### 2.2 벤더 락인의 고통

```
[과거 — 각 벤더 독자 프로토콜]

기지국 A (Ericsson 컨트롤러)
   ├── Ericsson RET     ← Ericsson 전용 명령
   ├── Nokia TMA        ← Nokia 전용 명령 → 호환 안 됨 ❌
   └── Kathrein 안테나  ← Kathrein 전용 명령 → 호환 안 됨 ❌

→ 결과: 통신사가 한 벤더에 락인
→ 가격 협상력 ↓ / 신제품 도입 어려움 / 부품 수급 의존
```

문제점:
- 통신사가 안테나·RET·TMA 모두 한 벤더에서 구매 강제
- 벤더가 가격·일정·기술 모두 통제
- 신규 벤더 시장 진입 장벽 매우 높음

### 2.3 사이트 관리의 고통

```
[과거 — 종이 도면 의존]

기지국 1개 사이트:
   - 안테나 6개 (3섹터 × 2 band)
   - RET 12개 (각 안테나 2개)
   - TMA 12개
   - RF 케이블 24가닥

→ 어느 케이블이 어느 ALD에 연결?
→ 종이 도면 + 설치자 메모 + 사진
→ 5년 후 유지보수 시 도면 분실 → 매핑 재발견 작업 1~2일
```

문제점:
- 사이트 정보가 사람·종이에 의존 → 잘못된 도면, 분실, 변경 미반영
- 신규 RET·TMA 교체 시 매핑 재확인 필요
- 5G 시대 → 사이트당 ALD 수십~수백 개 → 종이 도면 한계

## 3. AISG의 목적 — 무엇을 통일·제어하는가

### 3.1 통일 대상 5가지

| # | 통일 대상 | Before | After (AISG) |
|---|---|---|---|
| 1 | **물리 인터페이스** | 벤더별 커넥터·전압 | C485 8-pin / 10-30V (v3.0) 단일 |
| 2 | **통신 매체** | 벤더별 케이블 | RS-485 또는 OOK on RF feeder 2종 선택 |
| 3 | **프레임·전송 방식** | 벤더별 protocol | HDLC (ISO/IEC 13239) 단일 |
| 4 | **명령 셋** | 벤더별 API | Elementary Procedures 표준화 (SetTilt 등) |
| 5 | **디바이스 모델** | 벤더별 데이터 구조 | Subunit 추상화 (RET/TMA/GLS/ASD) |

### 3.2 제어 대상 — ALD (Antenna Line Device)

ALD = 안테나 라인에 매달려 **원격으로 조정 가능한 모든 능동 부품**.

```
[기지국 BS]
     │
     │ (RF feeder cable + AISG)
     ▼
[옥상/타워 상단]
     │
     ├─ TMA  (Tower Mounted Amplifier — 저잡음 증폭기)
     │   └─ 제어: bypass on/off, gain, 온도·전류 모니터링
     │
     ├─ 안테나 (Passive)
     │   └─ 부착물:
     │       ├─ RET (Remote Electrical Tilt — 빔 틸트)
     │       │   └─ 제어: 0~10° 사이 원격 각도 조정
     │       ├─ GLS (Geographic Location Sensor)
     │       │   └─ 모니터링: GPS 위치·방위각
     │       └─ ASD (Alignment Sensor Device)
     │           └─ 모니터링: 안테나 자세(틸트/롤/방위)
     │
     └─ (향후) ALS — 통합 위치·자세 센서 (개발 중)
```

### 3.3 제어 행위의 구체적 예시

| 제어 행위 | 효과 |
|---|---|
| `RET.SetTilt(5.5°)` | 안테나 빔을 5.5° 아래로 기울임 → 셀 커버리지·간섭 최적화 |
| `TMA.SetBypass(ON)` | 증폭기 우회 → TMA 점검 또는 고장 시 |
| `TMA.GetTemperature()` | 타워 위 TMA 내부 온도 원격 확인 → 과열 사전 감지 |
| `GLS.GetPosition()` | 안테나 GPS 위치 → 사이트 정보 자동 등록 |
| `ASD.GetMechanicalTilt()` | 풍하중·노후로 안테나 기울기 변화 감지 → 자동 알람 |
| (v3.0) `ScanBus()` | 새로 설치된 ALD 자동 발견 → 수동 주소 지정 불요 |
| (v3.0) `Ping(RFport=2)` | 어느 RF 케이블이 어느 ALD에 연결? 자동 매핑 |

## 4. AISG가 풀어주는 비즈니스 문제 (이해관계자별)

### 4.1 통신사(Operator) 입장

| 문제 | AISG 해결 |
|---|---|
| 안테나 조정에 타워 등반 비용·위험 | **사무실에서 RET 명령으로 원격 조정** (15초) |
| 셀 간섭 최적화에 수동 작업 | **소프트웨어로 일괄 최적화 가능** |
| TMA 고장 발견 늦음 | **실시간 온도·전류 모니터링** → 사전 감지 |
| 벤더 락인으로 가격 협상력 ↓ | **Multi-vendor 호환** → 입찰 경쟁 활성화 |
| 5G 사이트 ALD 수십~수백 개 관리 | **자동 Discovery + Site Mapping** (v3.0) |

### 4.2 ALD 벤더(Kathrein, CommScope 등) 입장

| 문제 | AISG 해결 |
|---|---|
| 통신사마다 다른 프로토콜 요구 → 개발비 증가 | **단일 표준 준수**로 한 번 개발하면 모든 통신사 납품 가능 |
| 통합 검증 비용 ↑ | **IOT (Interoperability Test) 강화** → AISG 인증 받으면 호환성 보장 |
| 시장 진입 장벽 ↑ | **표준 준수만으로 진입 가능** → 경쟁 활성화 |

### 4.3 기지국 벤더(Ericsson, Nokia, Huawei) 입장

| 문제 | AISG 해결 |
|---|---|
| 안테나·TMA·RET 모두 자체 개발 부담 | **표준 인터페이스만 구현**하면 3rd party ALD 통합 가능 |
| 사이트 구성 정보 수동 입력 | **Site Mapping API**로 자동 발견 |

### 4.4 사이트 설치자·유지보수 입장

| 문제 | AISG 해결 |
|---|---|
| ALD 주소 수동 설정 → 휴먼 에러 | **Device Discovery로 자동 인식** (v3.0) |
| 케이블 swap 시 매핑 재확인 | **Ping으로 자동 재매핑** (v3.0) |
| 타워 위 작업 안전 위험 | **현장 작업 시간 단축** → 위험 노출 ↓ |

## 5. AISG의 핵심 철학 — 4가지 원칙

### 5.1 다중 벤더 상호운용성 (Multi-vendor Interoperability)
> "A사 안테나 + B사 TMA + C사 RET이 D사 컨트롤러에서 모두 정상 동작해야 한다."

→ 단일 표준 명령 셋 + IOT 검증 강제

### 5.2 원격 제어 우선 (Remote-First)
> "타워에 사람이 올라가지 않고도 모든 조정·진단·점검이 가능해야 한다."

→ 모든 ALD 기능은 원격 명령으로 노출

### 5.3 케이블 절약 (Cable Economy)
> "RF 피더 케이블을 데이터 통신에도 같이 쓸 수 있어야 한다."

→ OOK 2.176 MHz를 Bias-T로 RF 피더에 합성 = 별도 케이블 불요

### 5.4 자동화 (Self-Discovery, v3.0~)
> "사람이 사이트 도면을 그리지 않아도 시스템이 스스로 구조를 파악해야 한다."

→ Device Discovery + Site Mapping + Ping

## 6. 표준 발전사 — 문제 해결의 진화

```
2001  ┃ AISG 컨소시엄 설립 (5개 창립사)
      ┃   "벤더 락인 깨고 안테나 원격 조정 표준화"
      ┃
2004  ┃ AISG v1.0 출시
      ┃   - RS-485 PHY / HDLC / RET 제어 기본
      ┃   - 첫 multi-vendor 안테나 조정 실현
      ┃
2006  ┃ AISG v2.0 출시 ⭐ 사실상 산업 표준이 됨
      ┃   - OOK 2.176 MHz PHY 추가 (RF feeder 공용)
      ┃   - TMA·GLS·ASD subunit 정식 추가
      ┃   - 3GPP TS 25.46x 시리즈로 통합
      ┃   - 10년 이상 산업 사용
      ┃
2018  ┃ AISG v3.0 출시 ⭐ 5G·복잡한 사이트 대응
      ┃   - Multi-Primary (다중 컨트롤러)
      ┃   - Device Discovery (자동 인식)
      ┃   - Site Mapping + Ping (자동 매핑)
      ┃   - 전원 핀 단순화 (10-30V 단일)
      ┃   - IOT 강화 + Pseudocode 명시
      ┃
2022~ ┃ ALS (Antenna Location & Orientation Sensor) 개발 중
      ┃   - GLS + ASD 통합 후속 표준
```

**핵심 변화 패턴**: 매 메이저 버전마다 "사람의 수동 작업" → "시스템 자동화"로 진화.

| 시대 | 자동화 단계 |
|---|---|
| ~2004 | 타워 등반 + 종이 도면 (자동화 0%) |
| v1~v2 | 원격 명령 가능 (자동화 30%) — 사람이 주소 지정·매핑 |
| v3.0 | Auto Discovery + Mapping (자동화 70%) — 시스템이 스스로 파악 |
| 미래 | AI 기반 자동 최적화 (자동화 90%+) |

## 7. 결정적 통찰 — 왜 본 프로젝트(#155057)가 가치 있는가

### 7.1 시장 규모
- 전 세계 이동통신 기지국 ≈ 700만 개 (2025)
- 한 사이트당 ALD 평균 6~30개
- AISG 기반 ALD 총량 = 약 1억 대 이상
- 5G 확장으로 매년 ~15% 증가

### 7.2 v2.0 → v3.0 마이그레이션 수요
- 2018년 발표 후 7년 경과 (2025) → **운영 시스템 v3.0 전환 본격기**
- 통신사들이 5G 사이트 신규 구축 + 기존 4G 사이트 업그레이드 동시 진행
- 본 프로젝트(#155057)는 그 흐름의 한 사례

### 7.3 통신사 입장에서의 가치
- v3.0 도입 = OPEX 절감 (자동 매핑 + 모니터링)
- v3.0 신기능을 안 쓰면 5G 시대 사이트 관리 인력 ↑ → 운영비 폭증
- **소프트웨어 업그레이드 1회 = 5년 이상 운영비 절감**

### 7.4 UTTEC 입장
- AISG는 **임베디드 펌웨어 + 통신 프로토콜**이 핵심 → 우리 강점 정조준
- ALD 벤더 시장(Kathrein·CommScope 등)은 진입 어렵지만, **포팅·유지보수 외주**는 충분히 가능
- 본 24M 프로젝트 성공 → 후속 v3.0 포팅 시장 진입 발판

## 8. 미팅에서 받을 수 있는 "AISG가 뭔가요" 류 질문 (Cheat Sheet)

**Q: AISG가 뭔가요? 비전공자에게 한 마디로 설명해주세요.**
> "기지국 안테나 옆에 매달린 모든 원격 제어 장비를 — 안테나 기울기 모터, 신호 증폭기, GPS 센서 같은 것들 — 벤더 상관없이 한 가지 방식으로 컴퓨터에서 제어하는 표준 약속입니다. 통신사가 안테나 조정을 하려고 매번 사람이 타워에 올라가지 않게 해주는 거죠."

**Q: 왜 표준이 필요한가요?**
> "표준이 없으면 통신사가 한 벤더 제품만 살 수밖에 없고, 가격·일정·기술 모두 통제당합니다. 또 사람이 30m 타워에 올라가서 안테나 나사 돌리는 작업은 안전 위험이 큽니다. AISG로 두 문제 모두 해결됩니다."

**Q: AISG로 정확히 뭘 제어할 수 있나요?**
> "RET — 안테나 빔 기울기 원격 조정. TMA — 타워 증폭기 ON/OFF·온도·전류 모니터링. GPS·자세 센서 — 안테나 위치·기울기 자동 측정. v3.0부터는 사이트 자동 매핑·자동 디바이스 발견까지."

**Q: AISG v3.0 도입 효과는?**
> "5G 시대에 한 사이트당 ALD가 수십·수백 개로 늘어나면서 v2.0의 수동 매핑이 한계 도달. v3.0의 자동 Discovery + Site Mapping + Ping이 사이트 관리 인력을 70% 줄여줍니다. 5년 운영비로 환산하면 사이트당 수억 원 절감."

**Q: 본 프로젝트가 통신사에게 어떤 가치를 주나요?**
> "기존 v2.0 ALD가 그대로 v3.0 컨트롤러와 통신하게 만들면서 v3.0 신기능까지 활성화시키는 거라, 통신사 입장에서 **기존 ALD 자산 보호 + v3.0 자동화 효과**를 동시에 얻습니다. 90일 24M 비용이 사이트 100개 1년 운영비 수준이지만, ROI는 5년에 10배 이상."

**Q: 다른 표준은 없나요?**
> "AISG가 사실상 산업 표준이고 3GPP TS 25.46x 시리즈로 통합되어 있어 대체 표준은 없습니다. 안테나·RET·TMA 시장에서 AISG 미준수 제품은 거의 없습니다."
