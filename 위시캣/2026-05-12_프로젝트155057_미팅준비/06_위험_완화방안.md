# 위험 / 완화 방안 — 7대 위험

> 본 프로젝트의 잠재 위험을 사전 식별 + 각 완화책 명시.
> 미팅에서 클라이언트에 공유 가능 — "이미 위험을 알고 있고 대비책도 있다"는 신뢰 신호.

## 🔴 위험 1 — 기존 C++ 코드 품질 불확실

### 상황
- 코드 가독성 / 주석 / 문서화 수준이 낮을 수 있음
- 빌드 시스템이 옛 환경 (예: Keil 5 + 옛 라이브러리)
- 분석에 예상보다 더 시간 소요

### 영향
- Phase 1 (Week 1~2) 지연 → 전체 일정 압박

### 완화
1. **Phase 1에 2주 충분히 배정** — 1주 분석 + 1주 환경 셋업
2. **Week 1 종료 시점 사전 진척 점검** — 클라이언트와 소통
3. **만약 Week 2 종료까지 분석 못 끝나면** — 즉시 클라이언트와 협의 (일정 +1주 또는 Scope 조정)
4. **버퍼 1주 자체 보유** — Phase 6 (인계)을 압축 가능

### 사전 미팅에서 확인
- 코드 라인 수 추정?
- 빌드 환경 / 컴파일러?
- 주석·문서 수준?
- 작성자가 누구이고 추가 질의 가능한가?

## 🔴 위험 2 — 실 ALD 장비 부재

### 상황
- 클라이언트가 실 ALD 장비를 제공 못 함
- 현장에서만 테스트 가능 (사무실 사전 검증 불가)

### 영향
- Phase 2~4의 검증 정확도 ↓
- Phase 5 현장 테스트에 모든 검증 압축

### 완화
1. **자체 모의 ALD 시뮬레이터 구축** — RS-485 모뎀 + 응답 시뮬레이터 (UTTEC 자체 제작 가능)
2. **Phase 5 시작 전 사전 현장 방문** — Week 10에 빠른 현장 1회
3. **현장 테스트 횟수 ↑** — Phase 5 압축 시 1~2회 추가 방문 (동일 지역 → 비용 부담 적음)

### 사전 미팅에서 확인
- 실 ALD 장비 제공 여부?
- 사무실에 가져갈 수 있는지?
- 시뮬레이터·에뮬레이터 제공 있는지?

## 🔴 위험 3 — AISG 인증 절차 별도 발생

### 상황
- 본 작업 결과물이 AISG 인증 받아야 양산 가능
- 인증 절차 (적합성 테스트 / 문서 작성)는 본 90일 Scope 밖

### 영향
- 클라이언트가 인증을 기대했으나 별도 견적 필요 → 분쟁 가능

### 완화
1. **미팅에서 사전 명확화** — "본 90일은 포팅 + 현장 테스트. 인증은 별도"
2. **계약서에 명시** — Scope 정의에 인증 작업 제외 명시
3. **인증이 필요하다면 별도 견적** — UTTEC가 진행 가능 (추가 비용)

### 사전 미팅에서 확인
- 인증 받을 계획인지?
- 인증을 누가 받는지 (클라이언트 직접? UTTEC가?)?
- 만약 UTTEC가 받는다면 별도 견적 가능?

## 🟠 위험 4 — Multi-Primary 동시성 버그

### 상황
- AISG 3.0 Multi-Primary는 한 ALD를 여러 컨트롤러가 동시 접근
- 동시성 처리 잘못 → race condition / deadlock 발생 가능
- 디버깅 어려움 (재현 어려운 버그)

### 영향
- Phase 3 (Week 6) Multi-Primary 구현 지연
- Phase 4~5에서 발견 시 더 큰 손실

### 완화
1. **BLE Mesh 3,800대 시스템의 검증된 패턴 재사용** — 게이트웨이 동시성 처리 검증 완료
2. **mutex / 세마포어 명시적 설계** — race condition 차단
3. **ThreadSanitizer 또는 valgrind** 활용 (타깃 환경 따라)
4. **부하 테스트** Phase 4에 24h 연속 동작 + 동시 명령 100건

### 사전 미팅에서 확인
- 실 환경에서 동시 컨트롤러 몇 대 사용?
- 부하 수준 (초당 명령 수)?
- 응답 시간 요구사항?

## 🟠 위험 5 — 현장 RF 환경 특수성

### 상황
- 기지국 환경 = 강한 RF 잡음
- 케이블 길이 / 손실 / 임피던스 미스매치
- 케이블 종단 처리 불량

### 영향
- 자체 사무실 테스트에서 OK인데 현장에서 통신 실패
- Phase 5 (Week 11~12) 지연

### 완화
1. **임호균 협업자 동행** — HW 측 즉시 진단 (RF 측정 / 케이블 손실 / 임피던스 확인)
2. **차폐·차단 장비 지참** — 오실로스코프 / 스펙트럼 분석기 (가능 시)
3. **사무실 동일 지역** → 사무실 ↔ 현장 빠른 사이클로 디버깅
4. **현장 사전 답사 1회** (Phase 5 시작 전) — Week 10에 빠른 방문

### 사전 미팅에서 확인
- 현장 RF 환경 특수성 (옥외? 옥상? 실내?)?
- 케이블 길이?
- 다른 RF 시스템과 간섭 가능성?

## 🟡 위험 6 — Scope creep (추가 기능 요청)

### 상황
- 작업 진행 중 클라이언트가 추가 기능 요청 (예: 클라우드 대시보드 / 모바일 앱)
- "어차피 만드는 김에…" 식 요청

### 영향
- 90일 Scope 초과 → 일정 지연 + 단가 적자

### 완화
1. **계약서에 Scope 명확 정의** — 작업 계획 (03 문서) 그대로 첨부
2. **Scope 변경은 별도 견적** — 사소한 조정은 OK / 추가 기능은 별도
3. **클라이언트와 정기 미팅** — 6회 마일스톤 미팅 = Scope creep 조기 발견
4. **정중 거절 능력** — "본 Scope 밖이라 별도 견적 드릴게요" 일관 톤

### 사전 미팅에서 확인
- 정확한 Scope (어디까지가 본 작업, 어디부터 별도)?
- 예상 추가 기능 후보?

## 🟡 위험 7 — UTTEC 측 일정 충돌 (REVITA / 골프수조 등)

### 상황
- UTTEC는 동시에 REVITA + 한림용인CC 골프수조 진행 중
- 본 AISG 프로젝트도 동시 진행 시 우선순위 충돌

### 영향
- 본 프로젝트 일정 지연 또는 다른 프로젝트 지연

### 완화
1. **본 프로젝트 우선순위 명확** — 24M / 90일 풀 타임 투입
2. **REVITA는 위키 기반 비동기 작업** — 시간 충돌 적음
3. **골프수조는 시공 직전** (1~2주 작업) → 본 AISG와 1개월 시간차로 분리 가능
4. **시간 표 명시** — 본 프로젝트에 일일 6~8시간 보장

### 사전 미팅에서 정직히 공유
- "REVITA / 골프수조가 진행 중이지만 본 프로젝트 우선순위 최상"
- 위험 인식 + 대비책 보유 명시

## 🛡 위험 관리 거버넌스

### 주간 리스크 리뷰
매주 금요일 자체 리뷰:
- 이번 주 발견 위험?
- 다음 주 예상 위험?
- 마일스톤 일정 대비 진척?

### 클라이언트 보고
6회 마일스톤 미팅마다:
- 진척 보고 (계획 vs 실제)
- 발견 위험 + 완화 진행
- 다음 단계 계획

### 예상치 못한 위험 발생 시
1. 24시간 내 클라이언트에 정직히 보고
2. 영향 분석 (일정 / 단가 / Scope)
3. 완화 방안 제시
4. 합의된 방향으로 진행
