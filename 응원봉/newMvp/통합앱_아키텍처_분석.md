# AI FanStick 통합 앱 아키텍처 분석

**작성일:** 2026-02-27
**목적:** Server + FanStickApp을 스마트폰 내장 앱으로 통합 시 장단점 분석

---

## 1. 현재 MVP 아키텍처 (분리형)

### 1.1 구성 요소

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        현재 MVP 아키텍처 (분리형)                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   ┌─────────────────────┐          ┌─────────────────────┐                  │
│   │    Python Server    │  HTTP    │   Android App       │                  │
│   │    (Mac/PC)         │◄────────►│   (FanStickApp)     │                  │
│   │                     │          │                     │                  │
│   │  • FastAPI          │          │  • UI (Compose)     │                  │
│   │  • prompt_generator │          │  • BLE 통신         │                  │
│   │  • gemini_service   │          │  • STT/TTS          │                  │
│   │  • concert_data.json│          │  • OkHttp Client    │                  │
│   └──────────┬──────────┘          └──────────┬──────────┘                  │
│              │                                │                              │
│              │ API Call                       │ BLE                          │
│              ▼                                ▼                              │
│   ┌─────────────────────┐          ┌─────────────────────┐                  │
│   │   AI API Server     │          │    응원봉 (ESP32)   │                  │
│   │  (Gemini/OpenAI)    │          │    • LED 제어       │                  │
│   └─────────────────────┘          │    • 버튼 입력      │                  │
│                                    └─────────────────────┘                  │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 현재 서버 기능 (Python)

| 파일 | 기능 | 코드 라인 |
|------|------|-----------|
| `main.py` | FastAPI REST API 엔드포인트 | ~265 |
| `prompt_generator.py` | 시스템 프롬프트 동적 생성 | ~215 |
| `gemini_service.py` | AI API 호출 + 응답 파싱 | ~283 |
| `concert_data.json` | 콘서트 데이터 (셋리스트, 멤버) | ~176 |

### 1.3 현재 앱 기능 (Kotlin)

| 기능 | 설명 |
|------|------|
| BLE 통신 | ESP32 응원봉과 연결/제어 |
| HTTP Client | 서버 API 호출 |
| STT | Google Speech Recognition |
| TTS | TextToSpeech |
| UI | Jetpack Compose |
| WebSocket | Control Center 연결 |

## 3. 장단점 분석

### 3.1 장점

| 번호 | 장점 | 상세 설명 | 영향도 |
|:----:|------|----------|:------:|
| 1 | **서버 불필요** | Python 서버 실행 없이 앱만으로 동작 | ⭐⭐⭐ |
| 2 | **네트워크 지연 감소** | 앱↔서버 HTTP 통신 제거, AI API만 호출 | ⭐⭐⭐ |
| 3 | **오프라인 부분 지원** | 콘서트 데이터는 로컬에서 조회 가능 | ⭐⭐ |
| 4 | **배포 단순화** | APK 파일 하나로 모든 기능 제공 | ⭐⭐⭐ |
| 5 | **유지보수 용이** | 단일 코드베이스 (Kotlin only) | ⭐⭐ |
| 6 | **비용 절감** | 서버 호스팅 비용 없음 | ⭐⭐ |
| 7 | **실시간성 향상** | 중간 서버 없이 AI API 직접 호출 | ⭐⭐ |
| 8 | **보안 강화** | 서버 노출 없음, API 키만 앱에서 관리 | ⭐ |

### 3.2 단점

| 번호 | 단점 | 상세 설명 | 대응 방안 | 영향도 |
|:----:|------|----------|----------|:------:|
| 1 | **API 키 노출 위험** | 앱에 Gemini/OpenAI API 키 포함 | Firebase Remote Config / 백엔드 프록시 | ⭐⭐⭐ |
| 2 | **코드 변환 비용** | Python → Kotlin 마이그레이션 필요 | 일회성 작업 (~2일) | ⭐⭐ |
| 3 | **중앙 제어 어려움** | 콘서트 진행 상황 실시간 동기화 불가 | WebSocket Control Center 유지 | ⭐⭐ |
| 4 | **데이터 업데이트** | 셋리스트 변경 시 앱 업데이트 필요 | Firebase Realtime DB / 앱 내 JSON 다운로드 | ⭐⭐ |
| 5 | **AI 비용 분산** | 각 사용자가 API 호출 → 비용 추적 어려움 | 사용량 제한 / 백엔드 프록시 | ⭐ |
| 6 | **디버깅 어려움** | 서버 로그 없음 | Firebase Crashlytics / Analytics | ⭐ |

## 4. 아키텍처 비교표

| 항목 | 분리형 (현재) | 통합형 (제안) |
|------|--------------|--------------|
| 구성 요소 | Server + App | App only |
| 네트워크 홉 | App → Server → AI API | App → AI API |
| 응답 시간 | ~3초 (서버 경유) | ~2초 (직접 호출) |
| 서버 비용 | 필요 (호스팅) | 불필요 |
| API 키 관리 | 서버에서 안전하게 | 앱에서 보호 필요 |
| 콘서트 데이터 | 서버에서 중앙 관리 | 앱 내장 / 원격 다운로드 |
| 배포 | Server + APK | APK only |
| 오프라인 | 불가 | 부분 가능 |
| 확장성 | 높음 (서버 확장) | 제한적 |
