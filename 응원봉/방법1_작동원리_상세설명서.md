## 1. 근본적인 질문: 왜 이 방식인가?

### 1.1 문제 상황

```
사용자가 "다음 곡 뭐야?"라고 물었을 때,
AI가 정확히 답하려면 무엇이 필요한가?

┌─────────────────────────────────────────────────────────────────┐
│                                                                  │
│   Q: "다음 곡 뭐야?"                                            │
│                                                                  │
│   AI가 답하려면 알아야 하는 것들:                               │
│                                                                  │
│   1. 오늘 공연의 셋리스트가 뭔지                                │
│   2. 지금 몇 번째 곡을 하고 있는지                              │
│   3. 따라서 다음 곡이 뭔지                                      │
│                                                                  │
│   그런데...                                                      │
│   Gemini/ChatGPT는 이걸 모릅니다!                               │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 왜 AI는 이걸 모르는가?

```
┌─────────────────────────────────────────────────────────────────┐
│                   AI의 지식 구조                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   Gemini/ChatGPT가 아는 것 (학습 데이터):                       │
│   ─────────────────────────────────────                         │
│   ✅ BTS가 누구인지                                             │
│   ✅ 멤버들 이름 (대략적인 정보)                                │
│   ✅ 유명한 노래들                                               │
│   ✅ 일반적인 K-POP 문화                                        │
│                                                                  │
│   Gemini/ChatGPT가 모르는 것:                                   │
│   ─────────────────────────────────────                         │
│   ❌ 오늘 2026년 6월 15일 서울 콘서트 셋리스트                  │
│   ❌ 지금 이 순간 몇 번째 곡을 하고 있는지                      │
│   ❌ 이 특정 콘서트의 응원법                                    │
│   ❌ 최신 팬덤 용어                                              │
│                                                                  │
│   이유:                                                          │
│   - AI는 학습 시점까지의 데이터만 알고 있음                     │
│   - 실시간 정보를 알 수 없음                                    │
│   - 특정 이벤트의 세부 정보는 학습되지 않음                     │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 해결책: "우리가 알려주면 된다"

```
┌─────────────────────────────────────────────────────────────────┐
│                      핵심 아이디어                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   AI가 모르는 정보를 → 우리가 매번 알려주면 됨!                 │
│                                                                  │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                                                          │   │
│   │   "안녕, Gemini!                                        │   │
│   │    너는 지금부터 BTS 콘서트 도우미야.                   │   │
│   │                                                          │   │
│   │    오늘 셋리스트는 이거야:                              │   │
│   │    1. Dynamite                                          │   │
│   │    2. 좋아좋아                                          │   │
│   │    3. 봄날                                               │   │
│   │                                                          │   │
│   │    지금 1번 곡 하고 있어.                               │   │
│   │                                                          │   │
│   │    이제 팬이 질문할 거야, 대답해줘!"                    │   │
│   │                                                          │   │
│   └─────────────────────────────────────────────────────────┘   │
│                              │                                   │
│                              ▼                                   │
│                                                                  │
│   팬: "다음 곡 뭐야?"                                           │
│   AI: "다음 곡은 '좋아좋아'야!" ← 정확한 답변 가능!            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 2. Gemini API가 필요한 이유

### 2.1 "규칙 기반" vs "AI 기반" 비교

```
┌─────────────────────────────────────────────────────────────────┐
│                  방법 A: 규칙 기반 (AI 없음)                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   if (질문.contains("다음 곡")) {                               │
│       return 셋리스트[현재인덱스 + 1];                          │
│   } else if (질문.contains("진") && 질문.contains("생일")) {    │
│       return "12월 4일";                                         │
│   } else if (...) {                                              │
│       ...                                                        │
│   }                                                              │
│                                                                  │
│   문제점:                                                        │
│   ─────────                                                      │
│   ❌ "다음에 뭐 해?" → 인식 못함                                │
│   ❌ "다음 노래가 뭔지 궁금해" → 인식 못함                      │
│   ❌ "쟌 생일 언제야?" (오타) → 인식 못함                       │
│   ❌ "그 다음은?" (맥락 의존) → 인식 못함                       │
│   ❌ 새로운 질문 패턴마다 코드 수정 필요                        │
│                                                                  │
│   → 수백 개의 if문 필요, 유지보수 불가능                        │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                  방법 B: AI 기반 (Gemini 사용)                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   Gemini에게:                                                    │
│   "셋리스트: 1.Dynamite 2.좋아좋아, 현재 1번째 곡"             │
│                                                                  │
│   사용자: "다음에 뭐 해?"                                       │
│   Gemini: "다음 곡은 좋아좋아야!" ✅                            │
│                                                                  │
│   사용자: "그 다음은?"                                          │
│   Gemini: "좋아좋아 다음은 봄날이야!" ✅                        │
│                                                                  │
│   사용자: "쟌 생일?" (오타)                                     │
│   Gemini: "진 오빠 생일 말하는 거지? 12월 4일이야!" ✅          │
│                                                                  │
│   장점:                                                          │
│   ─────────                                                      │
│   ✅ 자연어 이해 (다양한 표현 인식)                             │
│   ✅ 오타 허용                                                   │
│   ✅ 맥락 이해 ("그 다음은?")                                   │
│   ✅ 새 질문 패턴 자동 대응                                     │
│   ✅ 자연스러운 대화체 응답                                     │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 Gemini가 하는 역할 정리

```
┌─────────────────────────────────────────────────────────────────┐
│                  Gemini의 역할                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   Gemini가 하는 것:                                             │
│   ───────────────                                               │
│   1. 자연어 이해                                                 │
│      "다음 곡 뭐야?" = "다음 노래 알려줘" = "뭐 나와?"         │
│      → 전부 "다음 곡 질문"으로 이해                             │
│                                                                  │
│   2. 정보 추출 및 조합                                          │
│      주어진 정보: "현재 1번 곡, 셋리스트: 1.A 2.B 3.C"         │
│      → "다음 곡은 B"라고 추론                                   │
│                                                                  │
│   3. 자연스러운 문장 생성                                       │
│      "B" → "다음 곡은 B야! 파란색으로 바꿔줄게 💙"             │
│                                                                  │
│   4. 대화 맥락 유지                                              │
│      "그 다음은?" → 이전 대화 참고하여 답변                     │
│                                                                  │
│                                                                  │
│   Gemini가 하지 않는 것:                                        │
│   ─────────────────                                             │
│   ❌ 셋리스트 정보 제공 (우리가 알려줌)                         │
│   ❌ 현재 곡 번호 추적 (앱이 관리)                              │
│   ❌ 멤버 생일 기억 (JSON에서 로드)                             │
│   ❌ LED 색상 직접 제어 (앱이 처리)                             │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 왜 로컬 처리만으로는 안 되는가?

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                  │
│   Q: JSON 데이터 + 간단한 매칭으로 안 되나?                     │
│                                                                  │
│   A: 단순 질문은 되지만, 자연스러운 대화는 불가능               │
│                                                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   예시 1: 다양한 표현                                           │
│   ──────────────────                                            │
│   "다음 곡 뭐야?"                                               │
│   "다음 노래 알려줘"                                            │
│   "다음에 뭐 나와?"                                             │
│   "뭐 불러?"                                                     │
│   "이 다음 뭐야?"                                               │
│   "next song?"                                                   │
│                                                                  │
│   → 전부 같은 의도인데, 규칙 기반으로는 모든 패턴 처리 불가    │
│   → AI는 자동으로 의도 파악                                     │
│                                                                  │
│   예시 2: 복합 질문                                             │
│   ──────────────────                                            │
│   "진 생일이랑 정국 생일 알려줘"                                │
│   "다음 곡이랑 응원색 같이 알려줘"                              │
│   "남은 곡 몇 개고 마지막 곡 뭐야?"                             │
│                                                                  │
│   → 규칙 기반으로는 조합 폭발                                   │
│   → AI는 자연스럽게 처리                                        │
│                                                                  │
│   예시 3: 자연스러운 응답                                       │
│   ──────────────────                                            │
│   규칙 기반: "다음 곡: 좋아좋아"                                │
│   AI 기반: "다음 곡은 '좋아좋아'야! 파란색 준비해! 💙"         │
│                                                                  │
│   → 친근감, 이모지, 추가 정보 자동 포함                         │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 데이터셋: 언제, 어떻게 만드는가?

### 3.1 데이터셋의 종류와 생성 시점

```
┌─────────────────────────────────────────────────────────────────┐
│                    데이터의 3가지 계층                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   Layer 1: 정적 데이터 (거의 변하지 않음)                       │
│   ─────────────────────────────────────                         │
│   생성 시점: 앱 개발 시 또는 아티스트 추가 시                   │
│   갱신 주기: 거의 없음 (연 1~2회)                               │
│                                                                  │
│   포함 내용:                                                     │
│   - 멤버 프로필 (이름, 생일, 포지션)                            │
│   - 아티스트 기본 정보 (데뷔일, 소속사)                         │
│   - 팬덤 기본 용어 (아미, 보라해 등)                            │
│   - 대표곡 정보                                                  │
│                                                                  │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  {                                                       │   │
│   │    "members": [                                          │   │
│   │      {"name": "진", "birthday": "1992-12-04", ...}       │   │
│   │    ]                                                     │   │
│   │  }                                                       │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│                                                                  │
│   Layer 2: 반정적 데이터 (콘서트/투어별로 변함)                 │
│   ─────────────────────────────────────                         │
│   생성 시점: 콘서트 셋리스트 확정 후                            │
│   갱신 주기: 투어 시작 전, 또는 셋리스트 변경 시                │
│                                                                  │
│   포함 내용:                                                     │
│   - 이번 투어 셋리스트                                          │
│   - 곡별 응원법, 응원색                                         │
│   - 콘서트 장소, 날짜                                           │
│                                                                  │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  {                                                       │   │
│   │    "setlist": [                                          │   │
│   │      {"order": 1, "title": "Dynamite", ...}              │   │
│   │    ],                                                    │   │
│   │    "concert": {"venue": "잠실", "date": "2026-06-15"}    │   │
│   │  }                                                       │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│                                                                  │
│   Layer 3: 동적 데이터 (실시간 변함)                            │
│   ─────────────────────────────────────                         │
│   생성 시점: 앱 실행 중 실시간                                  │
│   갱신 주기: 곡이 바뀔 때마다                                   │
│                                                                  │
│   포함 내용:                                                     │
│   - 현재 곡 번호 (인덱스)                                       │
│                                                                  │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  var currentSongIndex = 0  // 사용자가 버튼으로 변경     │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 데이터 생성 프로세스

```
┌─────────────────────────────────────────────────────────────────┐
│                    데이터 생성 타임라인                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   [앱 개발 단계] ──────────────────────────────────────────────  │
│        │                                                         │
│        ├── 1. 아티스트 기본 정보 수집                           │
│        │      - 공식 프로필에서 멤버 정보 수집                  │
│        │      - 팬덤 위키에서 용어 정리                         │
│        │      - JSON 파일로 정리                                │
│        │                                                         │
│        └── 2. 앱에 JSON 파일 내장 (assets 폴더)                 │
│                                                                  │
│   [콘서트 전] ──────────────────────────────────────────────────  │
│        │                                                         │
│        ├── 3. 셋리스트 확정 후 데이터 업데이트                  │
│        │      - 기획사 발표 또는 첫 공연 후 확인                │
│        │      - 곡 순서, 응원색, 응원법 정리                    │
│        │                                                         │
│        └── 4. 앱 업데이트 배포 또는 서버에서 다운로드           │
│                                                                  │
│   [콘서트 중] ──────────────────────────────────────────────────  │
│        │                                                         │
│        └── 5. 사용자가 "현재 곡" 직접 설정                      │
│               - 이전/다음 버튼으로 인덱스 변경                  │
│               - 또는 곡 목록에서 직접 선택                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 4. Gemini가 데이터를 참고하는 방법

### 4.1 핵심 메커니즘: 시스템 프롬프트

```

│                                                                  │

┌─────────────────────────────────────────────────────────────────┐
│                  작동 방식 상세                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   STEP 1: 앱이 JSON에서 데이터 로드                             │
│   ───────────────────────────────────────                       │

│                                                                  │
```

## 6. 대안: LLaMA 등 로컬 LLM 내장

### 6.1 로컬 LLM이란?

```
┌─────────────────────────────────────────────────────────────────┐
│                    클라우드 LLM vs 로컬 LLM                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   클라우드 LLM (Gemini, ChatGPT):                               │
│   ────────────────────────────────                              │
│   ┌─────────┐      인터넷       ┌───────────────┐              │
│   │  스마트폰 │ ───────────────► │ Google 서버   │              │
│   │   앱     │ ◄─────────────── │ (Gemini 실행) │              │
│   └─────────┘                   └───────────────┘              │
│                                                                  │
│   • AI 처리가 서버에서 이루어짐                                 │
│   • 인터넷 연결 필수                                            │
│   • 고성능 모델 사용 가능                                       │
│                                                                  │
│                                                                  │
│   로컬 LLM (LLaMA, Gemma, Phi):                                 │
│   ────────────────────────────────                              │
│   ┌─────────────────────────────────────────┐                   │
│   │            스마트폰 앱                    │                   │
│   │                                          │                   │
│   │   ┌────────────────────────────────┐    │                   │
│   │   │     LLaMA 모델 (2~4GB)         │    │                   │
│   │   │     (앱 안에 내장)              │    │                   │
│   │   └────────────────────────────────┘    │                   │
│   │                                          │                   │
│   └─────────────────────────────────────────┘                   │
│                                                                  │
│   • AI 처리가 스마트폰에서 이루어짐                             │
│   • 인터넷 연결 불필요                                          │
│   • 제한된 성능 (스마트폰 칩 한계)                              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 6.2 로컬 LLM 사용 시 구조

```
┌─────────────────────────────────────────────────────────────────┐
│               로컬 LLM 방식의 시스템 구조                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                     스마트폰 앱                          │   │
│   │                                                          │   │
│   │  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐     │   │
│   │  │ concert     │  │ LLaMA 모델  │  │ 추론 엔진   │     │   │
```

### 6.4 로컬 LLM 사용 시 코드 예시

```kotlin
// 로컬 LLM (llama.cpp 기반) 사용 예시

class LocalLLMService(private val context: Context) {

    // LLaMA 모델 로드 (앱 시작 시 1회)
    private val llamaModel = LlamaAndroid.load(
        modelPath = "llama-2-7b-chat.Q4_K_M.gguf",  // 약 4GB
        contextSize = 2048,
        threads = 4  // CPU 코어 수
    )

    /**
     * 로컬 LLM으로 답변 생성
     * Gemini API와 동일한 방식으로 시스템 프롬프트 사용!
     */
    suspend fun ask(systemPrompt: String, userQuestion: String): String {

        // 프롬프트 구성 (Gemini와 동일)
        val fullPrompt = """
            $systemPrompt

            사용자: $userQuestion
            AI:
        """.trimIndent()

        // 로컬에서 추론 실행
        val response = llamaModel.generate(
            prompt = fullPrompt,
            maxTokens = 128,
            temperature = 0.7f,
            stopSequences = listOf("\n사용자:", "\n\n")
        )

        return response
    }
}

// 사용 예:
val localLLM = LocalLLMService(context)
val systemPrompt = promptGenerator.generateSystemPrompt()  // 동일한 프롬프트!
val answer = localLLM.ask(systemPrompt, "다음 곡 뭐야?")
// → "다음 곡은 좋아좋아야!"
```

```
Gemini 2.0 Flash 기준:

예상 사용량 (콘서트 1회):
• 시스템 프롬프트: ~1,000 토큰
• 사용자 질문: ~50 토큰
• AI 응답: ~100 토큰
• 1회 질문 비용: 약 $0.0001

→ 매우 저렴! MVP 단계에서는 무료 티어로 충분
```

### Q2: 오프라인에서 아예 안 되나요?

```
현재 방식: 오프라인 시 AI 답변 불가

대안:
1. 오프라인 시 간단한 규칙 기반 답변
   "다음 곡: 좋아좋아" (단순 텍스트)

2. 미리 자주 묻는 질문 답변 캐싱
   "다음 곡 뭐야?" → 미리 생성된 답변

3. 로컬 LLM 폴백 (용량 여유 시)
```

### Q3: 다른 아티스트 추가하려면?

```
JSON 파일에 데이터 추가:

   - blackpink_data.json

```
