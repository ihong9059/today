## 4. 클라이언트 응답 속도 개선 방안

### 4.1 현재 아키텍처

```
Client → Next.js (SSR) → AI Button → Claude API
```

**문제점:**
- 페이지 로딩 시 전체 문항 데이터 로드
- AI 버튼 클릭 시 외부 API 호출 지연

### 4.2 권장 개선 방안

#### A. 데이터 구조 최적화 (즉시 적용 가능)

```tsx
// 현재: 모든 문항이 page.tsx에 하드코딩
const topics = [
  { id: 'stress-strain', questions: [...100개...] }
];

// 개선: JSON 파일 분리 + 동적 로딩
// /data/it/information-processor/software-design.json
{
  "topics": [
    { "id": "requirement-analysis", "questions": [...] }
  ]
}
```

**장점:**
- 초기 페이지 로딩 속도 향상
- 캐싱 효율성 증가
- 유지보수 용이

#### B. Lazy Loading 적용

```tsx
// 토픽별 문항을 접었다 펼 때만 로딩
const [loadedTopics, setLoadedTopics] = useState<Set<string>>(new Set());

const loadTopic = async (topicId: string) => {
  if (!loadedTopics.has(topicId)) {
    const data = await fetch(`/api/questions/${topicId}`);
    // ...
  }
};
```

#### C. Static Generation 활용

```tsx
// next.config.js - ISR 설정
export const revalidate = 3600; // 1시간마다 재검증

// 정적 생성 + 주기적 업데이트
export async function generateStaticParams() {
  return categories.map((cat) => ({ category: cat.id }));
}
```

#### D. CDN 캐싱 (장기)

```
CloudFront → EC2 (Next.js)
- 정적 자산: 7일 캐싱
- 페이지: 1시간 캐싱
- API: 실시간
```
