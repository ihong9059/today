## 3. 효율적인 작업 전략

### 3.1 전략 A: 템플릿 기반 자동화 (권장)

#### 개념
1. **기계기사 페이지를 마스터 템플릿으로** 사용
2. **각 자격증별 데이터 JSON 파일** 생성
3. **스크립트로 템플릿 + 데이터 병합**하여 페이지 자동 생성

#### 장점
- 일관된 품질 보장
- 빠른 작업 속도 (149개 페이지 1일 내 완료 가능)
- 향후 유지보수 용이

#### 작업 흐름
```
1. 템플릿 컴포넌트화 (2시간)
   - HeroSection, QuickInfoCards, SubjectList 등 분리

2. 자격증별 데이터 수집 (분야당 1-2시간)
   - Q-Net, 각 협회 공식 정보 기준
   - JSON/TypeScript 형태로 정리

3. 페이지 생성 스크립트 실행

4. 일괄 빌드 및 배포
```

### 3.2 전략 B: 분야별 순차 작업

#### 우선순위 (사용자 트래픽/중요도 기준)

| 순위 | 분야 | 자격증 수 | 예상 소요 |
|------|------|----------|----------|
| 1 | IT·정보통신 | 6개 | 3시간 |
| 2 | 회계·세무 | 11개 | 5시간 |
| 3 | 건설 | 5개 | 2.5시간 |
| 4 | 금융 | 7개 | 3.5시간 |
| 5 | 법률 | 4개 | 2시간 |
| 6 | 디자인 | 10개 | 5시간 |
| 7 | 나머지 분야 | 106개 | 50시간 |

### 3.3 전략 C: AI 활용 일괄 생성

#### 개념
Claude Code에서 각 자격증의 공식 정보를 웹 검색하여 자동으로 페이지 생성

#### 작업 방식
```bash
# 예시: IT 분야 일괄 처리
for cert in information-processor information-security computer-organization \
            computer-system-pro information-management-pro network-admin; do
    # 1. 웹 검색으로 자격증 정보 수집
    # 2. 템플릿에 데이터 채우기
    # 3. 파일 생성
done
```

## 5. 배포 최적화 전략

### 5.1 빌드 시간 최적화

현재 791 페이지 빌드에 **7분** 소요

**개선 방안:**
- Incremental Static Regeneration (ISR) 적용 검토
- 빌드 캐시 활용 (`next build --experimental-turbo`)

### 5.2 배포 워크플로우

```bash
# 권장 배포 스크립트
#!/bin/bash
cd ~/cert-guide

# 1. 변경사항 pull
git pull origin main

# 2. 의존성 설치 (필요시)
npm ci --production

# 3. 빌드 (백그라운드)
npm run build

# 4. PM2 재시작
pm2 restart cert-guide

# 5. 상태 확인
pm2 status
```

### 5.3 모니터링

```bash
# PM2 모니터링
pm2 monit

# 로그 확인
pm2 logs cert-guide --lines 100
```
