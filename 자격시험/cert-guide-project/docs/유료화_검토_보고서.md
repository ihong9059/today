## 2. 유료화 모델 비교

### 2.1 모델별 장단점 분석

#### 모델 A: 프리미엄 (Freemium)

```
무료 tier: 기본 시험 정보 + 일부 문제
유료 tier: 전체 문제 + AI 프롬프트 + 추가 기능
```

| 장점 | 단점 |
|------|------|
| 낮은 진입장벽 | 무료 사용자 서버 비용 발생 |
| 바이럴 마케팅 용이 | 전환율 관리 필요 |
| 점진적 수익화 가능 | 무료/유료 경계 설정 어려움 |

**예상 전환율**: 3-7%

#### 모델 B: 구독형 (Subscription)

```
월간/연간 구독으로 전체 콘텐츠 접근
```

| 장점 | 단점 |
|------|------|
| 안정적 반복 수익 | 초기 가입 장벽 높음 |
| 고객 생애가치(LTV) 높음 | 해지율 관리 필요 |
| 예측 가능한 매출 | 지속적 콘텐츠 업데이트 압박 |

**예상 해지율**: 월 5-10%

#### 모델 C: 단건 구매 (One-time Purchase)

```
자격증별/분야별 개별 구매
```

| 장점 | 단점 |
|------|------|
| 명확한 가치 전달 | 반복 구매 유도 어려움 |
| 구매 결정 용이 | 수익 예측 어려움 |
| 가격 유연성 | 콘텐츠 불법 공유 위험 |

#### 모델 D: 하이브리드 (Hybrid)

```
기본 구독 + 프리미엄 애드온 + 단건 구매 옵션
```

| 장점 | 단점 |
|------|------|
| 다양한 고객 니즈 충족 | 가격 체계 복잡 |
| 수익 극대화 가능 | 운영 복잡도 증가 |
| 유연한 확장성 | 고객 혼란 가능성 |

## 5. 기술 구현 방안

### 5.1 필수 개발 항목

#### Phase 1: 기본 인프라 (1-2개월)

```
1. 회원 시스템
   ├── 회원가입/로그인 (이메일, 소셜)
   ├── 사용자 프로필 관리
   └── 구독 상태 관리

2. 결제 시스템
   ├── PG 연동 (토스페이먼츠/아임포트)
   ├── 정기결제 (구독)
   ├── 단건결제
   └── 환불 처리

3. 콘텐츠 접근 제어
   ├── 티어별 콘텐츠 분리
   ├── 일일 제한 기능
   └── 샘플/전체 콘텐츠 구분
```

#### Phase 2: 부가 기능 (2-3개월)

```
1. 학습 관리
   ├── 학습 진도 저장
   ├── 오답 노트
   └── 북마크 기능

2. 분석 기능
   ├── 학습 통계 대시보드
   ├── 약점 분석
   └── 예상 합격률

3. 관리자 기능
   ├── 회원 관리
   ├── 매출 대시보드
   └── 콘텐츠 관리
```

### 5.2 기술 스택 제안

| 영역 | 기술 | 선정 이유 |

### 5.3 데이터베이스 스키마 (핵심)

```sql
-- 사용자 테이블
CREATE TABLE users (
  id UUID PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  name VARCHAR(100),
  subscription_tier ENUM('free', 'pro', 'premium') DEFAULT 'free',
  subscription_start DATE,
  subscription_end DATE,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 구독 테이블
CREATE TABLE subscriptions (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  plan VARCHAR(50) NOT NULL,
  status ENUM('active', 'cancelled', 'expired') DEFAULT 'active',
  amount DECIMAL(10,2),
  billing_cycle ENUM('monthly', 'yearly'),
  next_billing_date DATE,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 학습 진도 테이블
CREATE TABLE learning_progress (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  certification_id VARCHAR(100),
  subject_id VARCHAR(100),
  completed_questions INT DEFAULT 0,
  correct_answers INT DEFAULT 0,
  last_studied_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW()
);

-- 결제 내역 테이블
CREATE TABLE payments (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  amount DECIMAL(10,2),
  payment_method VARCHAR(50),
  status ENUM('pending', 'completed', 'failed', 'refunded'),
  pg_transaction_id VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW()
);
```
