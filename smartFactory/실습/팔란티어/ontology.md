# 온톨로지 (Ontology)

## 일반적 의미

원래 **철학 용어**로 "존재론" — 세상에 존재하는 것들의 본질과 관계를 연구하는 분야.

IT에서는 **"데이터의 구조와 관계를 정의하는 체계"**를 의미한다.

## 쉽게 비유하면

데이터베이스의 ERD(Entity-Relationship Diagram)와 비슷하지만, 더 풍부한 관계와 의미를 표현한다.

```
[일반 DB]          →  테이블, 컬럼, FK
[온톨로지]         →  개체(Object), 속성(Property), 관계(Link), 액션(Action)
```

## Palantir Foundry에서의 온톨로지

Palantir이 말하는 온톨로지는 **"현실 세계를 디지털로 모델링한 것"**이다.

### 예시: 스마트 팩토리

```
[작업자] ──근무──▶ [생산라인]
   │                    │
   │                 보유──▶ [설비]
   │                           │
 담당──▶ [작업지시]        발생──▶ [알람]
              │
           사용──▶ [자재] ──입고──▶ [창고]
```

이렇게 정의해두면:

| 구성 요소 | 예시 |
|-----------|------|
| **Object (개체)** | 작업자, 설비, 자재, 생산라인 |
| **Property (속성)** | 설비.가동률, 자재.재고량, 작업자.이름 |
| **Link (관계)** | 작업자 → 생산라인 (근무), 설비 → 알람 (발생) |
| **Action (액션)** | 발주 생성, 설비 정지, 알림 전송 |

### 왜 중요한가

일반 DB는 **"테이블에 데이터가 있다"** 수준이지만, 온톨로지는 **"이 데이터가 현실에서 무엇이고 어떻게 연결되는지"**를 정의한다.

이 덕분에 AIP에서 LLM이:

- "제품A 재고 부족" → 자재 Object 조회 → 연결된 공급업체 찾기 → 발주 Action 실행

이런 **의미 기반 추론**이 가능해진다. LLM이 테이블명/컬럼명을 외울 필요 없이, 온톨로지가 "이건 자재이고, 이건 공급업체이고, 둘은 이런 관계"라고 알려주는 것이다.

## 다른 분야에서의 온톨로지

| 분야 | 사용 예 |
|------|--------|
| **시맨틱 웹** | RDF/OWL — 웹 데이터에 의미 부여 (W3C 표준) |
| **의료** | SNOMED CT — 질병/증상/치료법 관계 정의 |
| **지식그래프** | Google Knowledge Graph, Wikidata |
| **Palantir** | Foundry Ontology — 기업 데이터의 실세계 모델 |

## 핵심 요약

**"데이터에 의미와 관계를 부여하는 체계"** — 단순한 테이블 구조를 넘어, 현실 세계의 개체·속성·관계·액션을 디지털로 모델링하여 AI가 의미 기반 추론을 할 수 있게 한다.
