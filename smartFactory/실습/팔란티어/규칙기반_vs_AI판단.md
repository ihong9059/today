# 규칙 기반 vs AI(LLM) 판단 — 왜 Palantir AIP는 LLM을 사용하는가

## 핵심 요약

팔란티어 예제에서 Claude API가 하는 역할은 **"데이터를 보고 스스로 판단하여 어떤 액션을 실행할지 결정"**하는 것이다.

---

## 두 가지 방식 비교

### 방식 1: 규칙 기반 (mini_aip_rule_based.py)

**사람이 모든 판단 로직을 미리 if/else로 작성**

```python
if days_left < lead_time:
    create_purchase_order(priority="긴급")      # 리드타임 내 소진 → 긴급 발주
elif days_left < lead_time * 1.5:
    create_purchase_order(priority="일반")      # 1.5배 이내 → 일반 발주
elif days_left > lead_time * 10:
    send_alert(severity="warning")             # 10배 초과 → 과잉 알림
```

- 조건이 명확하고 예측 가능한 상황에서는 잘 동작
- 새로운 상황이나 복합적인 판단이 필요하면 코드 수정 필요
- **비용: 무료** (API 호출 없음)

### 방식 2: AI 판단 (mini_aip_claude.py)

**데이터를 Claude에게 넘기면 AI가 스스로 분석하고 판단**

```
[입력] 팩토리 데이터 전체를 텍스트로 전달

[Claude가 스스로 판단]
  → "알루미늄 프레임은 0.5일치밖에 없으니 긴급 발주"
  → "CNC #2는 알람 상태이고 오류 12건이니 긴급수리 요청"
  → "생산 달성률 67%에 불량률도 높으니 잔업 투입 + 품질팀 알림"
  → "서보모터는 66일치 과잉이니 구매팀에 경고"

[출력] 도구(발주/정비/알림/생산조정)를 자동 호출
```

- 새로운 상황에도 유연하게 대응
- 데이터 간의 연결 관계를 종합 분석
- **비용: API 토큰 사용량에 따라 과금**

---

## 상세 비교표

| 항목 | 규칙 기반 | AI(LLM) 판단 |
|------|----------|-------------|
| **판단 주체** | 개발자가 미리 작성한 조건문 | AI가 실시간 분석·판단 |
| **새로운 상황** | 코드에 없는 조건은 처리 불가 | 유연하게 대응 가능 |
| **복합 판단** | 조건 조합이 복잡해지면 코드 폭발 | 자연어로 종합 분석 |
| **설명 가능성** | 코드를 읽으면 알 수 있음 | AI가 판단 근거를 자연어로 설명 |
| **유지보수** | 조건 변경 시 코드 수정·배포 필요 | 프롬프트 수정만으로 대응 |
| **실행 속도** | 즉시 (밀리초) | API 호출 대기 (1~5초) |
| **비용** | 무료 | API 호출 비용 발생 |
| **인터넷** | 불필요 | 필요 |

## AI 판단이 규칙 기반보다 우수한 구체적 사례

### 사례 1: 데이터 간 연결 관계 파악

```
[규칙 기반]
  CNC #2 고장 → 정비 요청 (끝)
  프레임 재고 부족 → 발주 (끝)
  → 두 이벤트를 별개로 처리

[AI 판단]
  "CNC #2가 고장인데, 이 설비가 알루미늄 프레임 가공에 사용된다.
   설비 복구에 2일이 걸리면 그 동안 프레임 소모는 줄지만,
   이후 밀린 물량을 처리하면 오히려 더 많이 필요하다.
   → 정비 요청 + 프레임 발주량을 추가로 늘려야 한다"
```

### 사례 2: 복합적인 납기 위험 판단

```
[규칙 기반]
  오늘 생산 67대 / 목표 100대 → "미달" 알림 (끝)

[AI 판단]
  "오늘 67대에 불량률 2.3%(목표 1.5% 초과),
   납기까지 D-10에 잔여 420대,
   하루 100대씩 해도 420÷100 = 4.2일이면 되지만,
   불량률을 감안하면 실질 양품은 97.7대/일,
   CNC #2 고장으로 생산 능력이 떨어진 상태...
   → 잔업 투입 + 품질팀 점검 + 설비 긴급수리를 동시에 진행해야 한다"
```

### 사례 3: 과잉 재고의 원인 분석

```
[규칙 기반]
  서보모터 66.7일치 보유 → "과잉" 알림 (끝)

[AI 판단]
  "서보모터가 66일치나 있는 이유를 생각하면,
   일소모 3개인데 200개를 보유 중이다.
   단가가 85,000원이니 재고 금액만 1,700만원이다.
   → 구매팀에 과잉 알림 + 다음 발주 중단 권고 +
     재고 금액까지 포함한 경영진 보고"
```

## 이것이 Palantir AIP의 핵심

```
[기존 시스템]
  데이터 → 미리 정해진 규칙 → 액션
  (변경하려면 코드 수정 필요)

[Palantir AIP]
  데이터(온톨로지) → LLM이 종합 분석·판단 → 액션(Foundry Action) 자동 실행
  (프롬프트만 바꾸면 판단 기준 변경 가능)
```

Palantir가 AIP에 LLM을 도입한 이유는:
1. **복합적인 상황**을 사람처럼 종합적으로 판단
2. **데이터 간 연결 관계**를 자동으로 파악
3. **새로운 유형의 문제**에도 코드 수정 없이 대응
4. **판단 근거**를 자연어로 설명 가능 (의사결정 투명성)

## Claude Max 구독과 API 키의 관계

| 항목 | Claude Max (대화형) | API (프로그래밍용) |
|------|--------------------|--------------------|
| **용도** | claude.ai / Claude Code에서 대화 | 외부 앱에서 코드로 호출 |
| **과금** | 월 정액 ($100/200) | 사용량 기반 (토큰당 과금) |
| **키 발급** | 불필요 | console.anthropic.com에서 발급 |
| **크레딧** | 별도 불필요 | 별도 충전 필요 ($5~) |

> Max 구독 요금과 API 크레딧은 **별도**이다.
> Max를 구독해도 API 크레딧이 자동 충전되지 않으며,
> API를 사용하려면 크레딧을 별도로 구매해야 한다.

### API 키 발급 방법

1. [console.anthropic.com](https://console.anthropic.com) 접속
2. Settings → API Keys → Create Key
3. 키 복사 (`sk-ant-...`)
4. Plans & Billing → 크레딧 충전 (최소 $5)
