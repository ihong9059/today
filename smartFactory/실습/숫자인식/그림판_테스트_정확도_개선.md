# 그림판 테스트 정확도 개선 가이드

## 문제 현상

EMNIST Digits로 학습한 모델의 테스트 정확도는 99%이지만, 그림판에서 직접 그린 숫자를 업로드하면 인식률이 크게 떨어지는 현상이 발생한다.

---

## 원인 분석

### 1. EMNIST 데이터 회전 문제 (가장 큰 원인)

EMNIST 원본 데이터는 **90도 회전 + 좌우 반전**된 상태로 저장되어 있다.

```
[EMNIST 원본]          [사람이 쓰는 방향]
  ┌──────┐              ┌──────┐
  │  ┌┐  │    회전+반전   │  ──  │
  │  ││  │   ───────→   │   │  │
  │  ││  │              │  ──  │
  │  └┘  │              │ │    │
  └──────┘              │  ──  │
  (뒤집힌 2)             └──────┘
                        (정상 2)
```

이 보정 없이 학습하면 AI가 "뒤집힌 숫자"를 학습한 상태가 되어, 정상적으로 그린 숫자를 인식하지 못한다.

**해결**: 데이터 로드 직후 회전 보정 적용

```python
x_train = np.array([
    np.fliplr(np.rot90(img.squeeze(), k=3))[:,:,np.newaxis]
    for img in x_train
])
```

### 2. 색상 반전 문제

| 환경 | 배경 | 글씨 |
|------|------|------|
| **EMNIST 데이터** | 검정 (0) | 흰색 (255) |
| **그림판 기본** | 흰색 (255) | 검정 (0) |

색상이 정반대이기 때문에, 그림판 이미지를 그대로 입력하면 AI 입장에서는 "빈 이미지"처럼 보인다.

**해결**: `ImageOps.invert()`로 색상 자동 반전

```python
from PIL import ImageOps
img = ImageOps.invert(img)  # 흰배경+검은글씨 → 검은배경+흰글씨
```

### 3. 전처리 차이

| 항목 | EMNIST 학습 데이터 | 그림판 이미지 |
|------|-------------------|-------------|
| 이미지 크기 | 28x28 px | 수백~수천 px |
| 숫자 위치 | 정중앙 | 임의 위치 |
| 숫자 크기 | 20x20 영역 (4px 여백) | 임의 크기 |
| 여백 | 균일한 4px | 불균일 |
| 선 굵기 | 일정 | 그리기 도구에 따라 다름 |

단순히 `img.resize((28, 28))`만 하면 여백이 과도하거나 숫자가 치우쳐서 학습 데이터와 형태가 달라진다.

**해결**: EMNIST 원본과 동일한 레이아웃으로 전처리

---

## 해결 방법: 전처리 함수

그림판 이미지를 EMNIST 학습 데이터와 동일한 형태로 변환하는 6단계 전처리:

```
[원본 이미지]  →  [흑백 변환]  →  [색상 반전]  →  [숫자 영역 크롭]
                                                      ↓
[최종 28x28]  ←  [28x28 중앙배치]  ←  [20x20 리사이즈]  ←  [정사각형 패딩]
```

### 각 단계 상세

| 단계 | 처리 | 이유 |
|:----:|------|------|
| 1 | 흑백(Grayscale) 변환 | EMNIST는 1채널 흑백 이미지 |
| 2 | 색상 반전 (Invert) | 그림판 흰배경→검은배경으로 맞춤 |
| 3 | 숫자 영역 크롭 (Bounding Box) | 불필요한 여백 제거, 숫자만 추출 |
| 4 | 정사각형 패딩 | 가로/세로 비율 유지하면서 정사각형화 |
| 5 | 20x20 리사이즈 | EMNIST 원본의 숫자 크기와 맞춤 |
| 6 | 28x28 캔버스 중앙 배치 | 4px 여백으로 EMNIST 레이아웃 재현 |

### 전처리 함수 코드

```python
from PIL import Image, ImageOps
import numpy as np
import io

def preprocess_drawn_image(image_bytes):
    # 1. 흑백 변환
    img = Image.open(io.BytesIO(image_bytes)).convert('L')

    # 2. 색상 반전
    img = ImageOps.invert(img)

    # 3. numpy 변환 후 숫자 영역 크롭
    img_array = np.array(img)
    coords = np.argwhere(img_array > 30)
    if len(coords) == 0:
        return np.zeros((1, 28, 28, 1), dtype='float32')

    y_min, x_min = coords.min(axis=0)
    y_max, x_max = coords.max(axis=0)
    cropped = img_array[y_min:y_max+1, x_min:x_max+1]

    # 4. 정사각형 패딩
    h, w = cropped.shape
    max_side = max(h, w)
    padded = np.zeros((max_side, max_side), dtype=np.uint8)
    y_offset = (max_side - h) // 2
    x_offset = (max_side - w) // 2
    padded[y_offset:y_offset+h, x_offset:x_offset+w] = cropped

    # 5. 20x20 리사이즈
    img_resized = Image.fromarray(padded).resize((20, 20), Image.LANCZOS)
    img_20 = np.array(img_resized)

    # 6. 28x28 중앙 배치 (4px 여백)
    canvas = np.zeros((28, 28), dtype=np.uint8)
    canvas[4:24, 4:24] = img_20

    # 정규화 (0~1)
    result = canvas.astype('float32') / 255.0
    return result.reshape(1, 28, 28, 1)
```

## 그림판에서 그릴 때 팁

전처리 함수가 자동으로 보정하지만, 다음 팁을 따르면 정확도가 더 높아진다:

1. **선 굵기**: 너무 얇지 않게 (3~5px 권장)
2. **숫자 크기**: 캔버스의 50~70%를 채우도록
3. **위치**: 가운데에 그리기 (전처리가 보정하지만 극단적 치우침은 피하기)
4. **한 숫자만**: 이미지 하나에 숫자 하나만 그리기
