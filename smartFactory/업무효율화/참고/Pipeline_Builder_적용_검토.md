# Pipeline Builder 적용 검토

> **질문**: 팔란티어 파운드리의 Pipeline Builder를 우리가 구현할 수 있을까?
> **결론**: 1:1 복제는 불가, 철학을 본인 도구 스택에 적용하는 건 이미 80% 진행 중. 시각 UI만 보충하면 됨 — 직접 만들지 말고 **n8n 활용** 권장.

---

## 1. Pipeline Builder의 본질

팔란티어 파운드리에서 데이터 파이프라인을 시각적 노드 그래프로 만드는 도구.

**진짜 가치 (UI가 아니라)**:
- 비코더 + 코더 + AI가 **같은 캔버스**에서 협업
- 결과가 **온톨로지 객체에 즉시 반영** (Writeback)
- AI 노드(LLM 호출)가 파이프라인 내부에 직접 결합
- 권한·감사·Lineage가 자동 추적

→ 시각 UI는 **표면**일 뿐. 진짜 가치는 **객체 모델 + Writeback + 비코더 협업** 이 셋.

---

## 2. 구현 야망 3단계 평가

### 수준 1 — 1:1 클론 ❌ 불가능

| 항목 | 팔란티어 보유 |
|------|--------------|
| 투자 규모 | 수십억 달러 |
| 기간 | 20년 |
| 인력 | 수천 엔지니어 |
| 인프라 | Spark 기반 실행 엔진, 실시간 협업, 온톨로지 + Writeback, Lineage, 감사·권한 |

→ 1인 또는 소규모 팀이 시도하면 1년 후에도 미완성. **시도 자체가 잘못된 목표.**

### 수준 2 — "Lite" 시각 ETL 도구 자체 구현 ⚠️ 가능하지만 권장 안 함

기술적 부품:
```
React Flow (시각 노드 편집기)
+ 노드 라이브러리 (CSV / 필터 / Join / Claude 호출 / Excel 출력)
+ 실행 엔진 (각 노드를 순서대로 Python으로 컴파일)
+ 온톨로지 저장 (SQLite / PostgreSQL)
```

예상 공수: **MVP 4~8주**.

**문제**: 동일 기능 도구가 이미 5개 이상 무료/저가 존재 → 만들 이유 약함. **Not Invented Here 함정.**

### 수준 3 — 철학을 기존 도구에 적용 ✅ 이미 80% 완료

사용자가 만든 자산이 사실상 Pipeline Builder의 정신적 클론:

| 파운드리 컴포넌트 | 사용자 보유 자산 | 상태 |
|------------------|----------------|------|
| Pipeline Builder (시각) | ❌ 없음 (텍스트 기반) | **빠진 부분** |
| 데이터 변환 노드 | Obsidian 마크다운 + Claude prompt | ✅ |
| 온톨로지 (객체 + 액션) | wiki entities + demo_live.html | ✅ |
| AI 통합 | Claude Code 직접 호출 | ✅ |
| Writeback | demo_live.html 폼 → 시뮬레이션 결과 | ✅ |
| 비코더 협업 | (요청 시 본인이 위키 편집) | △ (본인 의존) |

→ **빠진 건 시각 UI 한 가지**. 이게 정말 필요한지부터 검증해야 함.

---

## 3. 시각 UI가 필요할 때 — 더 싼 길

직접 만들지 말고 **기존 도구**로 해결:

| 도구 | 가격 | 특징 | 우리 영업에 적합 |
|------|------|------|-----------------|
| **n8n** (오픈소스) | 무료 (서버비만) | 노드 400+, AI 노드 포함, Self-host로 보안 OK | ⭐⭐⭐ |
| **Make.com** | 무료~유료 | UI 가장 쉬움, 마케팅·영업 자동화 강함 | ⭐⭐ |
| **Apache Airflow** | 무료 | 코드 기반 + 그래프 UI, 엔터프라이즈급 | ⭐ |
| **Zapier** | 유료 | 가장 쉬운 진입, 비싼 편 | ⭐ |

**중소기업 컨설팅 영업 1순위**: **n8n + Obsidian + Claude** 조합.

---

## 4. 사용자 사업 적용 시나리오

태명과학·한국기계 영업 대상 시 권장 아키텍처:

```
[고객 데이터 사일로]
   ↓ n8n (시각 워크플로우)
   - 엑셀 자동 수집 (네트워크 폴더)
   - PDF OCR (Mistral OCR / Tesseract)
   - 표준화 (Python 노드)
   ↓
[Obsidian Wiki] ← Claude가 정리
   ↓
[demo_live.html / Web 앱] ← 고객이 사용
   ↓
Writeback (Slack 알림 / 이메일 / DB 업데이트)
```

**견적 메시지**: **"팔란티어 Foundry의 1/100 가격으로 동등한 워크플로우 구축"**

---

## 5. 영업·견적 차별화 포인트

기존 3-Stage 패키지(교육 + 위키 공동구축 + 운영 앱)에 **n8n 시각 워크플로우 구축**을 Stage 2에 추가하면:

| 단계 | 기존 가격대 | n8n 추가 시 |
|------|-----------|-----------|
| Stage 1 (교육) | 300만 | 300만 (변동 없음) |
| Stage 2 (위키 + n8n 워크플로우) | 1,500만 | **2,500만** (가치 1.7배) |
| Stage 3 (운영 앱) | 2,500만 | 2,500만 |
| **총액** | 4,300만 | **5,300만** |

**n8n 추가 가치**:
- 비코더(영업·운영팀)가 직접 워크플로우 수정 가능 → 인계 후 자립
- 시각 그래프로 의사결정자(대표)에게 가치 설명 쉬움
- 오픈소스라 자체 호스팅 → 데이터 유출 우려 차단 (대기업 대응 가능)

---

## 6. 솔직한 권장 (실행 순서)

1. **Pipeline Builder 자체 구현은 시도하지 말 것** — 영업 가치 없음, ROI 마이너스
2. **현재 작업(Obsidian + Claude)이 이미 같은 정신** — 시각화 부족만 해결하면 됨
3. **n8n 1주일 학습** → 데모 영상 1개 제작 → 영업 무기 추가
4. **3-Stage 패키지에 "n8n 시각 워크플로우 구축" 추가** → Stage 2의 격을 올림
5. **첫 시범 견적**: 태명과학 또는 한국기계에 Stage 1+2 통합 제안 (~2,800만)
