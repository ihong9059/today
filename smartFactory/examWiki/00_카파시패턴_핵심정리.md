# 00. 카파시 LLM Wiki 패턴 — 핵심 정리

> 이 문서는 examWiki 3종 예시를 보기 전에 **반드시 먼저** 읽어야 합니다.
> 패턴의 본질을 이해해야 예시가 의미 있게 보입니다.

---

## 1. 한 문장 정의

> **"내가 LLM에게 매일 정보를 먹이고, LLM이 그 정보를 정리·연결·되묻는 시스템"**

기존 메모장: 사용자만 읽고 씀 → 시간 지나면 잊혀짐
카파시 위키: 사용자 + LLM이 같이 운영 → 시간 지날수록 똑똑해짐

---

## 2. 왜 "두뇌의 외장 하드"인가

```
인간의 한계                    카파시 위키의 해결
───────────                    ─────────────────
기억 사라짐         →           모든 raw 영구 보존
연결 못 봄          →           [[링크]] + 그래프뷰
패턴 못 봄          →           A+B→C thought 자동 추출
오래된 판단 망각    →           log.md use 로그
바쁘면 정리 못 함   →           Claude가 자동 ingest
```

→ 위키는 **나의 인지 한계를 극복하는 도구**

---

## 3. 핵심 구조 — 3계층

### 3-1. raw/ (불변 원본)
- **무엇**: 책 발췌, 운동 기록, 미팅 메모, 영수증, 대화 캡처
- **규칙**: 한 번 적으면 **수정 금지**. 시간이 흐른 후 "그때 이렇게 적었구나"를 정확히 알 수 있어야 함
- **파일명**: `2026-05-04_제목.md` (날짜 + 키워드)
- **분량**: 짧아도 OK. 한 줄 메모도 raw

### 3-2. *.md (가공된 위키 페이지)
- **무엇**: 정체성·목표·강점·약점·인사이트 등 "해석"
- **규칙**: 자유롭게 갱신. raw를 참조해서 만들어짐
- **종류**:
  - **identity** (me, goals, strengths, gaps): 내가 누구인지
  - **log.md**: 시간순 ingest/use/query 기록
  - **index.md**: 전체 페이지 목록
  - **thoughts/**: 인사이트 (A+B→C 패턴)
  - **entities/**: 사람·도구·개념 페이지

### 3-3. CLAUDE.md (스키마/규칙)
- **무엇**: Claude에게 "이 위키는 이런 위키야"라고 알려주는 안내서
- **포함**: 디렉토리 구조, 페이지 규칙, ingest/query/lint 워크플로우
- **본 examWiki의 모든 wiki에 CLAUDE.md 있음** — 참고 모델

## 4. 핵심 사이클 — 4가지 행동

### 🔵 ① Ingest (정보 먹이기)

**언제**: 새 경험·생각·정보가 생겼을 때
**어떻게**:

```
사용자가 한 줄 던지기:
"오늘 [무엇]을 했는데/봤는데, [어떻게/왜] [내용]"

Claude가 자동으로:
1. raw/2026-MM-DD_제목.md 작성
2. log.md에 한 줄 추가
3. 관련 entities/ 페이지 갱신
4. 새 인사이트 가능성이 있으면 thoughts/ 제안
5. index.md 업데이트
```

**핵심**: 사용자는 **재료만 던지면 됨**. 형식 신경 안 써도 OK. Claude가 분류·연결·기록.

### 🟢 ② Use (위키 참조 → 의사결정)

**언제**: "X에 대해 내가 뭐 생각했었지?" 같은 질문
**어떻게**:

```
사용자: "내가 책에서 '몰입'에 대해 뭐라고 했더라?"

Claude:
1. index.md에서 관련 페이지 검색
2. raw + thoughts 참조
3. 종합 답변
4. log.md에 use 로그 기록 ("[2026-05-04] use | 몰입 관련 검색 → ...")
```

**핵심**: 위키를 **단순 저장소가 아니라 의사결정 도구**로 사용. use 로그는 "내가 이 정보를 언제 어떻게 활용했는지" 추적.

### 🟡 ③ Lint (정원사처럼 점검)

**언제**: 정기적 (예: 매주 금요일, 매월 말)
**어떻게**:

```
사용자: "위키 점검해줘"

Claude:
1. 고아 페이지 — 다른 페이지에서 링크 안 되는 파일
2. 오래된 정보 — 30일 이상 갱신 안 된 페이지
3. 모순 — 두 페이지가 다른 말을 하는 경우
4. 빠진 연결 — A와 B는 관련 있을 텐데 [[링크]] 없음
5. 새 주제 제안 — 비슷한 내용 5건 → entity 페이지 만들기 권장
```

**핵심**: 정원사가 잡초 뽑듯, **위키도 주기적 정리**가 필요. 안 그러면 그래프뷰가 의미 없는 점들의 묶음이 됨.

### 🟣 ④ Interpret (복리 인사이트 도출)

**언제**: ingest가 누적되면 자연스럽게 보임 (또는 강제로 트리거)
**어떻게**:

```
Claude: "어? 이거 흥미롭네요.

[2026-04-15 raw] '운동 후 컨디션 최고'
+
[2026-04-22 raw] '고탄수 식사 후 운동 안 됨'
↓
[새 thought 제안] '운동 컨디션 = 사전 식단의 함수'

thoughts/2026-05-04_운동컨디션_식단상관.md 생성하시겠어요?"
```

**핵심**: 이게 카파시 패턴의 **진짜 가치**. 단순 기록이 아니라 **A+B→C로 새 통찰**이 만들어지는 순간. 사람의 두뇌는 이런 패턴을 잘 못 보지만, LLM은 시간순 데이터를 횡단해서 본다.

## 5. 페이지 형식 표준

### 5-1. Frontmatter (YAML)
모든 페이지 맨 위에 다음 헤더:

```yaml
---
title: 페이지 제목
type: identity | skill | experience | project | goal | thought | entity | raw
created: 2026-05-04
updated: 2026-05-04
tags: [태그1, 태그2]
links: [관련_페이지1, 관련_페이지2]
---
```

### 5-2. 링크 문법
- 내부 링크: `[[파일명]]` (Obsidian 표준)
- 표시 텍스트 변경: `[[파일명|보여줄 글자]]`
- **모든 페이지는 최소 1개 이상의 다른 페이지와 연결** (고아 페이지 금지)

### 5-3. 본문 구조
페이지 종류별로 다르지만 공통 구조:

```markdown
# 제목

## 한 줄 요약
이 페이지가 무엇에 관한 것인지 한 줄

## 내용 (페이지 종류별)
- raw: 사실·인용·관찰
- thought: A+B→C 패턴 + Why·How to apply
- entity: 누가/무엇·역할·관계
- identity: 나의 X·왜 그러한가·근거

## 관련 페이지
- [[페이지A]]
- [[페이지B]]
```

## 6. 본 examWiki 3종을 어떻게 활용해야 가장 효과적인가

### 활용 단계
1. **이 문서 (00_카파시패턴_핵심정리.md) 정독** ← 지금 단계
2. **3개 wiki 중 가장 친숙한 1개 선택** (예: 사업자라면 3_soloBizWiki)
3. **선택한 wiki를 Obsidian으로 열기** (README.md의 등록 방법)
4. **다음 순서로 정독**:
   ```
   README.md           ← 이 wiki는 누가 운영하나
   CLAUDE.md           ← 어떤 규칙·페르소나
   me.md               ← 운영자의 정체성
   goals.md            ← 어떤 목표
   log.md              ← 시간순 사이클 기록 (가장 중요)
   index.md            ← 전체 지도
   raw/2026-04-15_*.md ← 첫 ingest
   raw/2026-04-22_*.md ← 두 번째
   thoughts/...        ← A+B→C 인사이트가 만들어진 순간
   entities/...        ← 도메인 페이지
   ```
5. **그래프뷰 켜기** (`Ctrl+G`) — 모든 노드와 연결 시각화
6. **"아 이렇게 동작하는구나" 체감되면 → 본인 관심 분야로 새 wiki 시작**

### 체감 포인트 (반드시 확인할 것)
- ✅ raw에 적은 "단순 기록"이 thoughts에서 어떻게 "통찰"로 변하는지
- ✅ entities 페이지가 raw들을 어떻게 묶어주는지
- ✅ log.md의 시간순 흐름 — ingest → 또 ingest → thought 발견
- ✅ me.md/goals.md가 운영자의 행동을 어떻게 설명하는지
- ✅ index.md + 그래프뷰로 보는 전체 구조

## 7. 카파시 패턴이 적합한 경우 vs 아닌 경우

### ✅ 적합 (자기 이해형 위키)
- 나의 사고·경험·판단을 추적하고 싶을 때
- 매일/매주 새 정보를 누적하고 싶을 때
- "왜 이런 결정을 했지?" 회고가 자주 있을 때
- 본인 두뇌의 한계를 LLM으로 보완하고 싶을 때

### ❌ 부적합 (도메인 룩업형 위키)
- 고객 응대용 챗봇 (예: smartFactory/업무효율화/태명과학)
- 제품 카탈로그·가격표 같은 정적 데이터
- 여러 사람이 동시 편집하는 협업 문서
- 공개되어야 하는 매뉴얼
