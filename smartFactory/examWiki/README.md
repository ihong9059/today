# examWiki — Karpathy LLM Wiki 패턴 체험용 3종 예시

> **목적**: Karpathy의 LLM Wiki 패턴이 **실제로 어떻게 작동하는지** 직접 체감할 수 있도록, 3가지 다른 분야의 simulation wiki를 만들었습니다.
> **사용법**: Obsidian에 등록 → Claude Code로 ingest/query/lint 사이클 체험
> **위치**: `c:/todo/today/smartFactory/examWiki/`

## 0. 이 폴더가 만들어진 이유

> *"카파시 LLM Wiki라는 건 알겠는데, 정확히 어떻게 해야 하고 무엇을 느낄 수 있는지 모르겠다."*

위 의문을 해결하기 위해, **3가지 살아있는 예시**를 만들었습니다:

| Wiki | 분야 | 데이터 주기 | 핵심 가치 체험 |
|------|------|-----------|-------------|
| **1_readerWiki** | 개인 독서 일지 | 매주 1-2권 (장기) | 내가 읽은 책들이 **충돌·결합**해서 새 사고가 만들어지는 순간 |
| **2_healthWiki** | 운동·건강 추적 | 매일 (정량 데이터) | "어제 X 먹은 날 Y 운동이 잘됐다" 같은 **숨은 패턴** 발견 |
| **3_soloBizWiki** | 1인 사업 운영 | 비정기 (이벤트 기반) | 영업·견적·매출의 **인과관계** 추적 → 판단력 향상 |

각 wiki는 **약 10개 파일**로 구성되어 있고, 모두 동일한 카파시 패턴을 따릅니다.

## 1. 카파시 LLM Wiki 패턴 — 30초 요약

```
┌─────────────────────────────────────────────────────┐
│                  자기 이해형 위키                     │
│  "나는 누구이고, 어디로 갈 것인가"를 추적하는 시스템   │
└─────────────────────────────────────────────────────┘
              │
              ↓
   ┌──────────┴──────────┐
   │   3계층 구조         │
   ├──────────────────────┤
   │  raw/   = 원본 (불변) │ ← 책 발췌·운동 기록·미팅 메모
   │  *.md   = 위키 (가공) │ ← me/goals/log/index/entities/thoughts
   │  CLAUDE.md = 스키마   │ ← Claude에게 주는 규칙
   └──────────────────────┘
              │
              ↓
   ┌──────────┴──────────┐
   │   3명령 사이클        │
   ├──────────────────────┤
   │  ingest = 새 정보 추가 │ ← raw에 데이터 → 위키 업데이트
   │  query  = 횡단 질의   │ ← "내가 X에 대해 뭐라고 했지?"
   │  lint   = 자동 점검   │ ← 고아 페이지·오래된 정보 감지
   └──────────────────────┘
              │
              ↓
   ┌──────────┴──────────────────┐
   │   복리 인사이트 패턴 (A+B→C)  │
   ├──────────────────────────────┤
   │ [사실 A] + [사실 B] → [판단 C]│
   │   ↓        ↓          ↓      │
   │ 책 1    책 2      새로운 통찰  │
   │ 운동A   식단B     성능 향상    │
   │ 미팅A   견적B     영업 패턴    │
   └──────────────────────────────┘
```

→ **위키는 정적인 메모장이 아니라, 시간이 지날수록 똑똑해지는 두뇌**

## 3. Obsidian 등록 방법 (3가지 wiki 모두)

### 3-1. Obsidian 설치 (이미 했으면 건너뛰기)
1. https://obsidian.md/ 에서 다운로드 + 설치
2. 첫 실행 시 "Open folder as vault" 선택

### 3-2. 3개 wiki를 각각 별도 Vault로 등록

각 wiki 폴더를 **독립 Vault**로 등록하는 것이 권장됩니다 (서로 다른 페르소나/규칙이라 섞이면 안 됨):

#### 방법 A: 한 번에 한 wiki 열기
1. Obsidian 실행 → 좌측 하단 **"Open another vault"** 클릭
2. **"Open folder as vault"** 클릭
3. `c:/todo/today/smartFactory/examWiki/1_readerWiki` 폴더 선택
4. "Trust author and enable plugins" 클릭
5. 위키 좌측에 파일 트리가 보이고, `index.md`가 자동 열림

#### 방법 B: 3개 wiki를 모두 동시에 열기 (권장)
1. 위 1번을 3번 반복 — 1_readerWiki, 2_healthWiki, 3_soloBizWiki
2. Obsidian 우측 상단의 vault 전환 메뉴(또는 `Ctrl+P` → "Open another vault")로 전환
3. 각 wiki는 독립된 그래프뷰·플러그인·테마를 가짐

### 3-3. 첫 실행 시 활성화할 핵심 플러그인 (각 vault마다)

Obsidian 설정 (`Ctrl+,`) → "Core plugins"에서:

| 플러그인 | 활성화 이유 |
|---------|------------|
| ✅ **Backlinks** | [[링크]]의 역참조 보기 — 카파시 패턴 핵심 |
| ✅ **Graph view** | 그래프뷰로 위키 구조 시각화 |
| ✅ **Daily notes** | log.md 자동 일일 항목 추가 |
| ✅ **Outgoing links** | 페이지에서 나가는 링크 보기 |
| ✅ **Tags pane** | 태그 기반 탐색 |
| ✅ **Templates** | 새 raw/thoughts 페이지 빠르게 작성 |

### 3-4. (선택) 추천 커뮤니티 플러그인

Settings → "Community plugins" → "Browse"에서:
- **Dataview** — `index.md`에서 자동 표 생성 (예: "type: book인 페이지 모두 나열")
- **Obsidian Git** — Vault를 GitHub에 자동 백업

### 3-5. 그래프뷰 확인 (가장 강력한 시각화)
- 좌측 사이드바의 **그래프 아이콘** 클릭 (또는 `Ctrl+G`)
- 모든 노드(파일)와 연결([[링크]])이 한 화면에 표시됨
- 시간이 지날수록 그래프가 풍성해지는 것을 확인 가능

## 4. 카파시 사이클 — 어떻게 직접 사용해 보는가

각 wiki에서 다음 4단계 사이클을 **반복**하면 위키가 살아 움직입니다.

### 사이클 1: Ingest (새 정보 추가)
```
사용자: "오늘 [책/운동/미팅] 했는데 [내용]이었어"

Claude: 1. raw/2026-05-04_*.md 파일 작성
        2. log.md에 한 줄 추가
        3. 관련 entities/ 페이지 업데이트
        4. 새 인사이트가 보이면 thoughts/에 제안
```

### 사이클 2: Use (위키 참조해서 의사결정)
```
사용자: "X에 대해 내가 뭐라고 했더라?"

Claude: 1. index.md + 관련 페이지 검색
        2. 답변 + log.md에 use 로그 기록
```

### 사이클 3: Lint (위키 건강 점검)
```
정기적으로 (예: 매주 금요일):

사용자: "위키 점검해줘"

Claude: 1. 고아 페이지 (링크 없는 파일) 식별
        2. 30일 이상 갱신 안 된 페이지
        3. 모순되는 기록
        4. 새로 탐색할 주제 제안
```

### 사이클 4: Interpret (복리 인사이트 도출)
```
ingest가 누적되면 자동으로:

Claude: "어? 이거 흥미롭네요.
        [raw/2026-04-15_몰입] + [raw/2026-04-22_딥워크]
        를 연결하면 사용자의 X 행동 패턴이 보여요.
        thoughts/에 기록하시겠어요?"
```

## 5. 이 폴더 사용 권장 순서 (학습자용)

### Step 1: 카파시 패턴 자체를 이해 (10분)
- [00_카파시패턴_핵심정리.md](00_카파시패턴_핵심정리.md) 읽기
- 본 문서 (이 README) 다시 한 번 정독

### Step 2: 가장 친숙한 wiki 1개 선택 (30분)
- 본인 관심사에 가까운 wiki 1개를 Obsidian으로 열기
  - 책 좋아함 → `1_readerWiki`
  - 건강 관심 → `2_healthWiki`
  - 사업 운영 → `3_soloBizWiki`
- 그래프뷰 보기 → "와 이렇게 연결되는구나" 체감

### Step 3: 모든 파일 정독 (60분)
- README.md → CLAUDE.md → me.md → goals.md → log.md → index.md
- raw/ 폴더의 원본 자료
- thoughts/ 폴더의 인사이트 — **여기가 카파시 패턴의 진짜 가치**
- entities/ 폴더

### Step 4: 직접 따라 만들기 (1-2시간)
- 본인의 관심 분야로 새 wiki 생성
- 본 examWiki의 구조를 그대로 복사 + 본인 raw 데이터로 교체
- 1주일간 매일 raw에 1건씩 ingest → 그래프 풍부해지는 것 체감

### Step 5: Claude Code 연동 (선택, 30분)
- 본인 wiki 폴더에서 `claude` 실행
- "오늘 [경험] 했는데 위키에 추가해줘" → ingest 사이클 자동
- "이번 달 내가 뭐를 배웠지?" → query 사이클 자동

## 6. 자주 묻는 질문 (FAQ)

### Q1. 왜 3개 wiki를 따로 만들었나요? 하나에 다 합치면 안 되나요?
A. **합치면 안 됩니다.** 카파시 패턴의 핵심은 *"하나의 위키 = 하나의 정체성"*. 책 일지의 페르소나(읽는 사람)와 사업 일지의 페르소나(경영자)는 다른 사고 회로입니다. **하나의 큰 vault에 다 합치면 그래프가 의미 없게 복잡**해지고, AI 답변도 혼란스러워집니다.

### Q2. raw/ 폴더는 정말 손대지 말아야 하나요?
A. **네.** raw는 "사실의 기록". 시간이 지난 후 "그때 내가 뭐라고 적었지?"를 정확히 알 수 있어야 함. 가공·해석은 모두 위키 페이지에서 하고, raw는 영구 보존.

### Q3. thoughts/ 페이지는 누가 만드나요?
A. **사람과 Claude가 같이.** 사용자가 ingest하다가 "어 이거 흥미롭네" 싶으면 직접 작성하거나, Claude가 raw 누적을 분석해서 "A+B→C 패턴을 발견했어요" 제안 → 사용자 승인 시 thoughts/ 생성.

### Q4. 매일 1건씩 ingest해야 하나요? 부담스러운데요?
A. **아니요.** 일주일에 한 번이라도 OK. 다만 **꾸준해야** 복리 효과. 카파시 본인도 "the wiki only works if you keep feeding it" 라고 말했음.

### Q5. 너무 많은 페이지가 쌓이면 어떻게 되나요?
A. **lint 사이클을 돌립니다.** 6개월에 한 번 정도 "더 이상 의미 없는 페이지 정리" + "새로 만든 카테고리로 재분류". Obsidian의 그래프뷰가 비대해지면 **새 vault로 분리**하는 것도 한 방법.

### Q6. Notion으로는 안 되나요?
A. **됩니다, 단 Obsidian이 더 적합.** 이유:
- Obsidian은 **로컬 마크다운** → AI가 직접 읽기 좋음
- 양방향 [[링크]]가 기본 (Notion은 페이지 링크가 좀 약함)
- Obsidian은 **그래프뷰**가 핵심 — Notion은 없음
- 백업이 단순 (Git push 한 번) — Notion은 export 거쳐야 함

## 7. 다음 단계 — 카파시 위키를 평생 운영하려면

### 1년 후 vs 10년 후 차이
- **1년**: 노트 200개, 그래프뷰가 살짝 재밌음
- **3년**: 노트 1,000개, "내가 그때 뭐 생각했지?" 답변에 위키 사용
- **10년**: 노트 5,000개, **본인보다 본인을 더 잘 아는 외장 두뇌**

### 운영 팁
1. **매일 5분만** — 출퇴근 길에 모바일로 raw에 한 줄 추가
2. **금요일 30분 lint** — 한 주 점검, 새 thought 발굴
3. **연말 회고** — 한 해 thoughts/ 모아 "올해의 5가지 깨달음" 정리
4. **GitHub 백업 필수** — 데이터 손실 = 위키 사망
