## 1. 시계열 데이터의 정의와 특징

### 1.1 시계열 데이터란?

**시계열 데이터 (Time Series Data)** = 시간 순서대로 기록된 데이터

```
일반 데이터:
  이름    나이   키
  김철수   30   175cm    ← 시간 순서 없음, 각 행이 독립적
  이영희   25   162cm

시계열 데이터:
  시간              온도
  09:00:00         25.3°C   ← 시간 순서가 핵심!
  09:00:01         25.4°C   ← 이전 값과 관련 있음
  09:00:02         25.5°C   ← 트렌드(상승 중) 파악 가능
  09:00:03         25.7°C
  09:00:04         26.1°C   ← 갑자기 빨리 올라감 → 이상?
```

### 1.2 시계열 데이터의 4가지 핵심 특성

```
┌─────────────────────────────────────────────────────────────────┐
│              시계열 데이터의 4가지 핵심 특성                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 트렌드 (Trend) — 장기적 방향                                │
│     └─ "온도가 점점 올라가고 있다" (상승 추세)                  │
│     └─ "진동이 점점 커지고 있다" (베어링 마모 진행)             │
│                                                                 │
│  2. 계절성 (Seasonality) — 반복 패턴                            │
│     └─ "매일 오전 9시에 가동 시작 → 온도 상승"                 │
│     └─ "주말에는 비가동 → 온도 하강"                           │
│                                                                 │
│  3. 자기상관 (Autocorrelation) — 이전 값과의 관계               │
│     └─ "지금 온도가 높으면 1초 후에도 높을 가능성 큼"          │
│     └─ "어제 진동이 컸으면 오늘도 클 가능성 높음"              │
│                                                                 │
│  4. 노이즈 (Noise) — 랜덤 변동                                  │
│     └─ "센서 오차, 환경 변화 등 예측 불가한 변동"              │
│                                                                 │
│  비유:                                                           │
│  주식 가격을 생각해 보세요:                                     │
│  • 트렌드: 올해 전반적으로 상승 중                              │
│  • 계절성: 매년 12월에 올라가는 패턴                            │
│  • 자기상관: 어제 올랐으면 오늘도 오를 확률이 약간 높음         │
│  • 노이즈: 예상 못한 뉴스로 갑자기 하락                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 시계열 데이터의 시각화

```
  온도(°C)
  50 ┤                              ╱╲
     │                             ╱  ╲    ← 이상 고온 (이벤트)
  40 ┤                            ╱    ╲
     │                           ╱      ╲

     │  ╱  ╲  ╱  ╲  ╱  ╲  ╱  ╲╱          ╲╱  ╲  ╱  ╲
  25 ┤ ╱    ╲╱    ╲╱    ╲╱                      ╲╱    ╲
     │╱                                                ╲
  20 ┤                ← 정상 운전 범위 →
     │
     └──────────────────────────────────────────────────── 시간
      월   화   수   목   금   토   일   월   화   수

     │← 계절성(일간 패턴) →│        │← 이상 →│
     │← ─ ─ ─ ─ ─ 트렌드(약간 상승) ─ ─ ─ ─ →│
```

## 2. 스마트팩토리에서의 시계열 데이터

### 2.1 슈레더에서 발생하는 시계열 데이터

| 센서 | 데이터 유형 | 샘플링 주기 | 시계열 특성 |
|------|-----------|:-----------:|-----------|
| **VIB-A/B** (진동) | 가속도 (g) | 1ms (1000Hz) | 고주파, FFT 스펙트럼이 핵심 |
| **TMP-A/B** (베어링 온도) | 온도 (°C) | 1초 | 느린 변화, 트렌드 중요 |
| **TMP-IR** (챔버 온도) | 온도 (°C) | 100ms | 급변 감지가 핵심 |
| **CUR-A/B** (전류) | 전류 (A) | 10ms | 부하 변동, 마모 트렌드 |
| **SPD-A/B** (회전속도) | RPM | 10ms | 설정 값 대비 편차 |
| **DST-1** (분진) | 농도 (μg/m³) | 1초 | 누적 트렌드 |
| **GAS-1** (가스) | ppm | 1초 | 패턴 인식 |
| **SCL-1** (처리량) | t/h | 1초 | 생산성 트렌드 |

### 2.2 시계열 예측이 필요한 이유

```
[과거 데이터]                    [현재]     [미래 예측]

  진동 ──────────────────────────┤
  RMS   정상  정상  정상  약간↑  │  ??   ??   ??
  (mm/s) 2.1  2.0  2.3  3.1   │
                                │
  지금까지의 데이터를 보고       │  앞으로 어떻게 될지
  패턴을 학습한다               │  예측한다
                                │
                                │  → "3일 후 위험 수준 도달 예상"
                                │  → "칼날 교체까지 잔여 120시간"
                                │  → "내일 오전 10시 최대 부하 예상"
```

## 3. 시계열 예측이란

### 3.1 시계열 예측의 3가지 유형

| 유형 | 설명 | 예시 |
|------|------|------|
| **단변량 예측** | 하나의 센서만 보고 미래 예측 | 온도만 보고 미래 온도 예측 |
| **다변량 예측** | 여러 센서를 함께 보고 예측 | 온도+전류+진동을 보고 온도 예측 |
| **이상 탐지** | 정상 패턴을 학습 → 비정상 감지 | 진동 패턴이 학습된 정상과 다르면 경고 |

### 3.2 예측 기간에 따른 분류

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  단기 예측 (수초~수분)                                          │
│  └─ 발화 감지: "3초 후 온도 150°C 초과 예측 → 사전 대응"      │
│  └─ 이물질 끼임: "전류 급등 패턴 → 2초 내 역회전 권고"        │
│                                                                 │
│  중기 예측 (수시간~수일)                                        │
│  └─ 칼날 마모: "현재 마모율 38% → 120시간 후 교체 필요"       │
│  └─ 파쇄 품질: "오후 3시에 과대 파쇄 발생 예상 → RPM 조정"    │
│                                                                 │
│  장기 예측 (수주~수개월)                                        │
│  └─ 부품 수명: "베어링 3개월 후 교체 예상 → 발주 시점"        │
│  └─ 생산 계획: "다음 달 처리량 예측 → 정비 일정 조율"         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 4. Prophet

### 4.1 한 줄 요약

> **Prophet = Facebook(Meta)이 만든 "비전문가도 쉽게 쓸 수 있는" 시계열 예측 모델**

### 4.2 핵심 특징

```
┌─────────────────────────────────────────────────────────────────┐
│                     Prophet 핵심 특징                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  만든 곳: Meta (Facebook)                                       │
│  공개: 2017년                                                   │
│  언어: Python, R                                                │
│  난이도: ★☆☆☆☆ (매우 쉬움)                                    │
│                                                                 │
│  핵심 원리:                                                     │
│  시계열 = 트렌드 + 계절성 + 휴일 효과 + 노이즈                 │
│                                                                 │
│  y(t) = g(t) + s(t) + h(t) + ε(t)                              │
│         │       │       │       │                               │
│         │       │       │       └─ 노이즈 (예측 불가)           │
│         │       │       └─ 휴일/이벤트 효과                     │
│         │       └─ 계절성 (일간, 주간, 연간 패턴)               │
│         └─ 트렌드 (장기적 상승/하강)                            │
│                                                                 │
│  장점:                                                           │
│  • 코드 3줄이면 예측 가능                                       │
│  • 결측치, 이상치에 강건                                        │
│  • 계절성 패턴 자동 감지                                        │
│  • 해석이 쉬움 (각 구성요소를 분리해서 볼 수 있음)             │
│                                                                 │
│  단점:                                                           │
│  • 다변량 입력 불가 (단변량만)                                  │
│  • 복잡한 비선형 패턴에 약함                                    │
│  • 초단기 예측(수초)에는 부적합                                 │
│  • 딥러닝 대비 정확도 한계                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 코드 예시

```python
from prophet import Prophet
import pandas as pd

# 데이터 준비 (Prophet은 ds, y 컬럼명 필수)
df = pd.DataFrame({
    'ds': pd.date_range('2026-01-01', periods=1000, freq='h'),
    'y': sensor_temperature_data  # 온도 데이터
})

# 모델 생성 + 학습 (딱 2줄!)
model = Prophet(daily_seasonality=True)
model.fit(df)

# 미래 24시간 예측
future = model.make_future_dataframe(periods=24, freq='h')
forecast = model.predict(future)

# 결과 시각화
model.plot(forecast)              # 예측 그래프
model.plot_components(forecast)   # 트렌드 + 계절성 분리
```

### 4.4 Prophet이 적합한 상황

| 적합 | 부적합 |
|------|--------|
| 일/주/월 단위 트렌드 예측 | 밀리초 단위 실시간 예측 |
| 계절 패턴이 뚜렷한 데이터 | 여러 센서를 동시에 고려 |
| 빠른 프로토타이핑 | 복잡한 비선형 관계 |
| 처리량, 에너지 소비 예측 | 진동 이상 탐지 |

## 5. LSTM

### 5.1 한 줄 요약

> **LSTM = "기억력이 좋은" 딥러닝 모델 — 과거의 패턴을 기억하여 미래를 예측**

### 5.2 핵심 특징

```
┌─────────────────────────────────────────────────────────────────┐
│                       LSTM 핵심 특징                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  정식명: Long Short-Term Memory                                  │
│  유형: 순환 신경망 (RNN)의 개선 버전                             │
│  공개: 1997년 (Hochreiter & Schmidhuber)                         │
│  난이도: ★★★☆☆ (중간)                                          │
│                                                                 │
│  핵심 원리:                                                     │
│  "중요한 정보는 오래 기억하고, 불필요한 정보는 잊는다"          │
│                                                                 │
│  3개의 게이트로 기억을 관리:                                    │
│  ┌──────────────────────────────────────────────┐               │
│  │                                                │               │
│  │  Forget Gate (잊기 게이트)                     │               │
│  │  └─ "이 정보는 더 이상 필요 없으니 잊자"      │               │
│  │     예: 3시간 전의 정상 온도는 잊어도 됨       │               │
│  │                                                │               │
│  │  Input Gate (입력 게이트)                       │               │
│  │  └─ "이 정보는 중요하니 기억하자"              │               │
│  │     예: 갑자기 온도가 5도 상승한 것은 기억!    │               │
│  │                                                │               │
│  │  Output Gate (출력 게이트)                      │               │
│  │  └─ "기억 중에서 지금 필요한 것만 출력하자"    │               │
│  │     예: 현재 온도 예측에 필요한 기억만 사용     │               │
│  │                                                │               │
│  └──────────────────────────────────────────────┘               │
│                                                                 │
│  비유:                                                           │
│  시험 공부하는 학생:                                            │
│  • 잊기: "이 부분은 시험에 안 나올 것 같으니 넘기자"           │
│  • 입력: "이 공식은 중요하니 반드시 기억하자"                  │
│  • 출력: "이 문제를 풀 때는 이 공식을 사용하자"                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.3 LSTM의 작동 흐름

```
시간 흐름 →

  입력: [t-3] → [t-2] → [t-1] → [t] → [???]
        25.1°C  25.3°C  25.8°C  26.5°C   ?

  ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐
  │LSTM  │──▶│LSTM  │──▶│LSTM  │──▶│LSTM  │──▶ 예측: 27.1°C
  │셀    │   │셀    │   │셀    │   │셀    │
  └──────┘   └──────┘   └──────┘   └──────┘
      ↑           ↑           ↑           ↑
    25.1        25.3        25.8        26.5

  각 LSTM 셀이 이전 정보를 "기억"하면서 다음 셀에 전달
  → "온도가 점점 올라가는 패턴" 학습
  → 다음 값도 올라갈 것으로 예측
```

### 5.4 LSTM 변형들

| 변형 | 특징 | 적합 상황 |
|------|------|----------|
| **Vanilla LSTM** | 기본 LSTM | 단변량 예측 |
| **Stacked LSTM** | LSTM을 여러 층 쌓음 | 복잡한 패턴 |
| **Bidirectional LSTM** | 앞뒤 양방향으로 학습 | 패턴 완성 후 분석 (비실시간) |
| **LSTM Autoencoder** | 정상 패턴 학습 → 이상 탐지 | **슈레더 베어링 이상 탐지에 사용** |
| **Seq2Seq LSTM** | 입력 시퀀스 → 출력 시퀀스 | 다중 스텝 예측 |

### 5.5 코드 예시 (LSTM Autoencoder — 이상 탐지)

```python
import numpy as np
import tensorflow as tf
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import LSTM, Dense, RepeatVector, TimeDistributed

# 1. 데이터 준비 (정상 운전 데이터)
# shape: (samples, timesteps, features)
X_train = normal_vibration_data.reshape(-1, 100, 3)  # 100 타임스텝, 3축

# 2. LSTM Autoencoder 모델 구성
model = Sequential([
    # Encoder — 입력을 압축
    LSTM(64, input_shape=(100, 3), return_sequences=True),
    LSTM(32, return_sequences=False),

    # Bottleneck — 핵심 패턴만 남김
    RepeatVector(100),

    # Decoder — 압축을 복원
    LSTM(32, return_sequences=True),
    LSTM(64, return_sequences=True),
    TimeDistributed(Dense(3))
])

model.compile(optimizer='adam', loss='mse')

# 3. 학습 (정상 데이터만으로)
model.fit(X_train, X_train, epochs=50, batch_size=32, validation_split=0.1)

# 4. 이상 탐지
def detect_anomaly(new_data, threshold=0.1):
    reconstructed = model.predict(new_data)
    mse = np.mean(np.power(new_data - reconstructed, 2), axis=(1, 2))
    return mse > threshold  # True = 이상

# 재구성 오차가 크면 = 학습된 정상 패턴과 다름 = 이상!
```

### 5.6 LSTM이 적합한 상황

| 적합 | 부적합 |
|------|--------|
| 센서 이상 탐지 (Autoencoder) | 수백 개 변수 동시 처리 |
| 진동/온도 패턴 학습 | 매우 긴 시퀀스 (수만 스텝) |
| 다변량 시계열 예측 | 해석이 필요한 경우 |
| 실시간 추론 (Edge 배포) | 학습 데이터가 매우 적을 때 |

## 6. TFT (Temporal Fusion Transformer)

### 6.1 한 줄 요약

> **TFT = "시계열에 특화된 Transformer" — 현재 가장 강력한 시계열 예측 모델**

### 6.2 핵심 특징

```
┌─────────────────────────────────────────────────────────────────┐
│                       TFT 핵심 특징                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  정식명: Temporal Fusion Transformer                             │
│  만든 곳: Google Research                                        │
│  공개: 2020년                                                    │
│  난이도: ★★★★☆ (어려움)                                        │
│                                                                 │
│  핵심 혁신: 시계열에 Transformer(GPT와 같은 구조)를 적용        │
│                                                                 │
│  TFT가 LSTM보다 뛰어난 이유:                                    │
│  ┌──────────────────────────────────────────────┐               │
│  │                                                │               │
│  │  1. Multi-head Attention (다중 어텐션)         │               │
│  │     └─ "어떤 과거 시점이 미래 예측에 중요한지" │               │
│  │        자동으로 파악 (LSTM은 순서대로만 봄)     │               │
│  │                                                │               │
│  │  2. Variable Selection (변수 선택)             │               │
│  │     └─ 수십 개 센서 중 "어떤 센서가 예측에     │               │
│  │        가장 중요한지" 자동으로 선별             │               │
│  │                                                │               │
│  │  3. 다양한 입력 유형 동시 처리                 │               │
│  │     └─ 과거 데이터 (known past)                │               │
│  │     └─ 미래에 알 수 있는 정보 (known future)   │               │
│  │        예: 생산 스케줄, 투입 재료 종류          │               │
│  │     └─ 정적 정보 (static)                      │               │
│  │        예: 장비 ID, 칼날 교체 이력             │               │
│  │                                                │               │
│  │  4. 해석 가능성 (Interpretability)             │               │
│  │     └─ "왜 이렇게 예측했는지" 설명 가능        │               │
│  │     └─ 어떤 변수가 얼마나 중요했는지 시각화    │               │
│  │                                                │               │
│  └──────────────────────────────────────────────┘               │
│                                                                 │
│  비유:                                                           │
│  LSTM = 책을 처음부터 끝까지 순서대로 읽는 학생                 │
│  TFT  = 목차를 보고 중요한 챕터를 먼저 읽는 학생               │
│         + "이 부분이 핵심이었다"고 설명할 수 있음               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 6.3 TFT의 구조

```
┌─────────────────────────────────────────────────────────────────┐
│                      TFT 아키텍처 (간소화)                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  입력                                                            │
│  ├── 과거 데이터: 온도, 전류, 진동 (지난 24시간)               │
│  ├── 미래 정보: 생산 스케줄, 투입 재료 종류                     │
│  └── 정적 정보: 장비 ID, 칼날 교체 후 경과 시간                │
│       │                                                          │
│       ▼                                                          │
│  ┌──────────────────┐                                           │
│  │ Variable Selection│ ← "어떤 센서/변수가 중요한지" 자동 선별 │
│  │ Network           │                                           │
│  └────────┬─────────┘                                           │
│           ▼                                                      │
│  ┌──────────────────┐                                           │
│  │ LSTM Encoder      │ ← 시간 순서에 따른 패턴 학습            │
│  │ (과거→현재)       │                                           │
│  └────────┬─────────┘                                           │
│           ▼                                                      │
│  ┌──────────────────┐                                           │
│  │ Multi-head        │ ← "과거의 어떤 시점이 미래에 중요한지"  │
│  │ Attention         │    자동으로 파악                          │
│  └────────┬─────────┘                                           │
│           ▼                                                      │
│  ┌──────────────────┐                                           │
│  │ Feed Forward      │ ← 최종 예측 생성                         │
│  │ + Quantile Output │    확률 분포로 출력 (불확실성 포함)       │
│  └────────┬─────────┘                                           │
│           ▼                                                      │
│  출력: "6시간 후 온도 = 35.2°C (90% 신뢰: 33.1~37.3°C)"       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 6.4 코드 예시 (PyTorch Forecasting 라이브러리)

```python
from pytorch_forecasting import TemporalFusionTransformer, TimeSeriesDataSet
from pytorch_forecasting.data import GroupNormalizer
import pytorch_lightning as pl

# 1. 데이터셋 정의
training = TimeSeriesDataSet(
    data,
    time_idx="time_idx",                    # 시간 인덱스
    target="temperature",                    # 예측 대상
    group_ids=["sensor_id"],                 # 그룹 (센서별)
    max_encoder_length=168,                  # 과거 168시간(7일) 참조
    max_prediction_length=24,                # 미래 24시간 예측
    time_varying_known_reals=["hour", "day_of_week"],  # 미래에 알 수 있는 정보
    time_varying_unknown_reals=[             # 과거에만 있는 센서 데이터
        "temperature", "current", "vibration", "rpm"
    ],
    static_categoricals=["sensor_id"],       # 정적 범주형
    static_reals=["blade_hours"],            # 정적 수치형 (칼날 사용시간)
    target_normalizer=GroupNormalizer(groups=["sensor_id"]),
)

# 2. DataLoader
train_dataloader = training.to_dataloader(batch_size=64, shuffle=True)

# 3. TFT 모델 생성
tft = TemporalFusionTransformer.from_dataset(
    training,
    hidden_size=32,
    attention_head_size=4,
    dropout=0.1,
    hidden_continuous_size=16,
    output_size=7,           # 7개 분위수 (확률 분포)
    loss=QuantileLoss(),
    learning_rate=0.001,
)

# 4. 학습
trainer = pl.Trainer(max_epochs=50, accelerator="auto")
trainer.fit(tft, train_dataloader)

# 5. 예측 + 해석
predictions = tft.predict(val_dataloader)
interpretation = tft.interpret_output(predictions)

# 변수 중요도 시각화 — "어떤 센서가 예측에 가장 기여했는가?"
tft.plot_interpretation(interpretation)
```

### 6.5 TFT가 적합한 상황

| 적합 | 부적합 |
|------|--------|
| 다변량 센서 데이터 예측 | 데이터가 1000건 미만 (너무 적음) |
| "왜 이렇게 예측했는지" 설명 필요 | 밀리초 단위 실시간 추론 |
| 과거+미래 정보를 동시에 활용 | 단순한 단변량 예측 |
| 칼날 마모, 베어링 RUL 예측 | Edge 장비 (모델이 큼) |
| 중장기 예측 (수시간~수일) | 초경량 배포 |

## 7. 기타 주요 모델

### 7.1 ARIMA / SARIMA (통계 기반)

```
[ARIMA]

  Auto-Regressive Integrated Moving Average
  = 자기회귀 + 차분 + 이동평균

  핵심: 과거 값과 과거 오차의 선형 조합으로 예측
  장점: 수학적으로 명확, 적은 데이터로도 작동
  단점: 비선형 패턴 학습 불가, 다변량 어려움
  적합: 단순 트렌드 예측, 기준선(baseline) 모델

  SARIMA = ARIMA + 계절성 (Seasonal)
```

### 7.2 XGBoost / LightGBM (트리 기반)

```
[XGBoost for Time Series]

  원래 분류/회귀용이지만, 시계열 특징(feature)을 만들면 사용 가능

  특징 엔지니어링 예시:
  ├── lag_1h: 1시간 전 온도
  ├── lag_24h: 24시간 전 온도
  ├── rolling_mean_1h: 최근 1시간 이동평균
  ├── rolling_std_1h: 최근 1시간 표준편차
  ├── hour_of_day: 시간 (0~23)
  └── day_of_week: 요일 (0~6)

  장점: 빠르고 정확, 해석 가능, Edge 배포 용이
  단점: 특징을 수동으로 만들어야 함
  적합: 슈레더 칼날 마모 예측 (이 프로젝트에서 사용!)
```

### 7.3 N-BEATS (Neural Basis Expansion)

```
[N-BEATS]

  만든 곳: Element AI (2020)
  특징: "순수한" 딥러닝 — 시계열만을 위해 설계
  장점: 단변량 최고 성능, 해석 가능한 분해
  단점: 다변량 지원 제한
  적합: 단변량 벤치마크에서 LSTM, Prophet을 능가
```

### 7.4 TimesNet (2023)

```
[TimesNet]

  만든 곳: Tsinghua University (2023)
  특징: 시계열을 2D 텐서로 변환 → CNN으로 패턴 학습
  장점: 예측/이상탐지/분류/결측치 보완 모두 가능
  단점: 최신이라 실무 검증 부족
  적합: 연구/실험 단계
```

## 9. 슈레더 센서 데이터에 어떤 모델을 쓸 것인가?

### 9.1 슈레더 AI 시스템의 모델 선택

| 슈레더 AI 기능 | 선택 모델 | 선택 이유 |
|---------------|----------|----------|

| **축 불균형 진단** | **Classical DSP (FFT)** | 물리 법칙 기반, AI 불필요 |
| **발화 감지** | **Rule + Anomaly Detection** | 안전 최우선, 단순하고 빠른 판단 |

### 9.2 왜 전부 TFT를 쓰지 않는가?

```
"최신이고 가장 정확한 TFT를 전부 쓰면 되지 않나요?"

  ❌ 아닙니다. 이유:

  1. Edge 장비 제약
     TFT 모델 크기: ~100MB+ / LSTM: ~10MB / XGBoost: ~1MB
     Jetson Orin NX에서 10개 TFT를 동시 실행하기 어려움

  2. 실시간 추론 속도
     TFT: ~100ms / XGBoost: <5ms / 룰 기반: <1ms
     발화 감지는 100ms도 느림 → 단순 룰이 적합

  3. 학습 데이터 요구량
     TFT: 수천~수만 건 / XGBoost: 수백 건 / Prophet: 수십 건
     초기에는 데이터가 부족 → 가벼운 모델부터 시작

  4. 해석 가능성
     "왜 경보가 울렸는가?" → 단순 모델이 설명하기 쉬움
     안전 관련 판단은 설명 가능해야 신뢰를 얻음

  결론: "적재적소" — 각 기능에 가장 적합한 모델을 선택
```

## 10. 시계열 모델 개발 절차

### 10.1 전체 절차 (7단계)

```
┌─────────────────────────────────────────────────────────────────┐
│              시계열 모델 개발 7단계                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Step 1: 데이터 수집                                             │
│  └─ 센서 데이터 저장 (TimescaleDB)                              │
│  └─ 최소 1~3개월 정상 운전 데이터                               │
│                                                                 │
│  Step 2: 탐색적 데이터 분석 (EDA)                                │
│  └─ 시각화: 트렌드, 계절성, 이상치 확인                        │
│  └─ 통계: 평균, 분산, 자기상관 분석                             │
│                                                                 │
│  Step 3: 전처리                                                  │
│  └─ 결측치 처리 (보간법)                                        │
│  └─ 이상치 제거/표시                                            │
│  └─ 정규화 (Min-Max 또는 StandardScaler)                        │
│  └─ 슬라이딩 윈도우로 학습 데이터 생성                         │
│                                                                 │
│  Step 4: 특징 엔지니어링                                         │
│  └─ 시간 특징: 시간, 요일, 가동 시간                           │
│  └─ 통계 특징: 이동평균, 이동표준편차, 최대/최소               │
│  └─ 주파수 특징: FFT, Envelope (진동 데이터)                    │
│  └─ 도메인 특징: 마모율, 누적 처리량, 칼날 사용시간             │
│                                                                 │
│  Step 5: 모델 학습                                               │
│  └─ Train/Validation/Test 분할 (시간순 분할!)                   │
│  └─ 하이퍼파라미터 튜닝 (Optuna)                                │
│  └─ 교차 검증 (시계열용 TimeSeriesSplit)                        │
│                                                                 │
│  Step 6: 평가                                                    │
│  └─ MAE, RMSE, MAPE 등 정량 지표                               │
│  └─ 예측 vs 실제 그래프 비교                                    │
│  └─ 비즈니스 지표 (조기 경보 정확도, 거짓 경보율)              │
│                                                                 │
│  Step 7: 배포 + 모니터링                                         │
│  └─ Docker 컨테이너로 Edge 배포                                │
│  └─ 성능 드리프트 모니터링                                     │
│  └─ 피드백 루프 → 모델 재학습                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 10.2 시계열 데이터 분할의 주의점

```
[일반 데이터 — 랜덤 분할 OK]

  전체 데이터를 랜덤으로 섞어서 Train/Test 분할
  → 시간 순서 없으므로 문제 없음


[시계열 데이터 — 시간순 분할 필수!]

  ❌ 틀린 방법: 랜덤 분할
  → 미래 데이터로 과거를 예측하는 "데이터 누출(leakage)" 발생

  ✅ 올바른 방법: 시간순 분할

  ──────────────────────────────────────────── 시간 →
  │←──── Train (70%) ────→│← Val (15%) →│← Test (15%) →│
  │  1월       2월        │   3월 초     │   3월 중순~   │

  → 항상 과거로 학습하고, 미래로 테스트
```

## 11. 성능 평가 방법

### 11.1 주요 평가 지표

| 지표 | 수식 | 의미 | 적합 상황 |
|------|------|------|----------|
| **MAE** | 평균 절대 오차 | 예측이 평균적으로 얼마나 틀렸는가 | 일반적 사용 |
| **RMSE** | 평균 제곱근 오차 | 큰 오차에 더 민감 | 큰 오차가 위험한 경우 (발화 감지) |
| **MAPE** | 평균 절대 백분율 오차 | 오차를 %로 표현 | 스케일이 다른 센서 비교 |
| **R²** | 결정 계수 | 예측이 실제를 얼마나 설명하는가 (0~1) | 전반적 모델 품질 |

### 11.2 비즈니스 평가 지표

| 지표 | 설명 | 목표 |
|------|------|:----:|
| **조기 경보 정확도** | "위험" 경보 중 실제 위험이었던 비율 | 95%+ |
| **거짓 경보율** | 경보 중 실제로는 정상이었던 비율 | 5% 이하 |
| **사전 감지 시간** | 실제 고장 발생 전 몇 시간 전에 경보했는가 | 24시간+ |
| **RUL 예측 오차** | 잔여수명 예측의 오차 | ±15% |

## 12. 실전 팁과 주의사항

### 12.1 흔한 실수

| 실수 | 왜 문제인가 | 해결 |
|------|-----------|------|
| 시계열을 랜덤 분할 | 미래→과거 누출 | **시간순 분할** |
| 정규화를 전체 데이터로 | Test 정보 누출 | **Train 데이터만으로 정규화** |
| 최신 모델만 고집 | 데이터 부족 시 과적합 | 단순 모델부터 시작 (baseline) |
| 단일 지표만 봄 | MAE 좋아도 거짓 경보 많을 수 있음 | 비즈니스 지표 함께 평가 |
| 정상 데이터만으로 평가 | 이상 상황에서 성능 검증 못 함 | 이상 이벤트 데이터 별도 확보 |

### 12.2 모델 선택 가이드

```
[데이터가 100건 미만]
  → Prophet 또는 ARIMA (통계 모델)

[데이터가 100~1,000건]
  → XGBoost + 특징 엔지니어링

[데이터가 1,000~10,000건]
  → LSTM 또는 XGBoost (둘 다 시도 후 비교)

[데이터가 10,000건 이상]
  → TFT (최고 성능 기대)
  → 또는 LSTM + XGBoost 앙상블

[Edge 배포 필요]
  → XGBoost (최우선) 또는 LSTM (TensorRT 최적화)

[해석 가능성 필요 (안전 관련)]
  → XGBoost (특징 중요도) 또는 TFT (Attention 시각화)
```

## 13. 요약

### 13.1 핵심 3줄 요약

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  1. Prophet — 쉽고 빠르지만, 복잡한 센서 데이터에는 한계       │
│                                                                 │
│  2. LSTM — 기억력 좋은 딥러닝, 이상 탐지(Autoencoder)에 최적   │
│                                                                 │
│  3. TFT — 최신 최강 모델, 다변량+해석+정확도 모두 잡음         │
│     단, 데이터 많이 필요하고 무거움                             │
│                                                                 │
│  실전 원칙: "최신 모델이 최선이 아니다"                         │
│  → 데이터 양, 배포 환경, 해석 필요성에 따라 적재적소 선택      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 13.2 슈레더 AI 시스템 적용 요약

| 기능 | 모델 | 데이터 | 배포 | 이유 |
|------|------|:------:|:----:|------|
| 베어링 이상 탐지 | LSTM AE | 정상 28일 | Edge | 정상 패턴 학습 → 이탈 감지 |
