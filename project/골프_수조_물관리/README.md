## 1. 프로젝트 현황

### 인프라 (지도 기반)

3개 코스 (사파이어 / 루비 / 다이아몬드), 2개 급수 노선:

| 노선 | 색 | 경로 |
|------|----|------|
| **노선1** | 파랑 | 사파이어 1번·8번 연못 → **펌프1A** → **중계기1** → **고가수조1** (사파이어 3번홀, B) |
| **노선2** | 빨강 | 루비 6번 연못 → **펌프2** → **중계기2** → **고가수조2** (다이아몬드 9번홀) |

총 노드:
- 펌프 (P) × 2
- 중계기 (R) × 2
- 고가수조 (T) × 2
- (+ 견적서 기준 저장탱크 3개소 추가 — 지도에 미표시)

### 거리 추정 (지도 기반)

골프장 부지 직경 약 1.5~2 km 추정.
- 노선1 거리: 사파이어 1번·8번 ↔ 고가수조1 → ~500m~1km
- 노선2 거리: 루비 6번 ↔ 다이아몬드 9번 → **~1~2 km** (코스 가로지름)

→ **LoRa 0.3k air rate (LOS 15-20km, NLOS 1-3km)** 충분히 커버. 중계기 2개는 코스 잡목·언덕 NLOS 보강용으로 합리적.

## 4. UTTEC 자산 매칭 분석 (★ 추가)

### 펌웨어 자산 — 오늘(2026-05-10) 작업 완료분 활용 가능

`oldProject/test/bleModule/`에 **nRF52832 + E22 LoRa config read/write 펌웨어 완성**:
- C1 00 09 register read 검증 ✅
- C0 03 01 [val] register write 검증 ✅
- AT_COMMANDS.md mode mapping 정정 ✅ (Config = M0=0, M1=1)
- E22-400T·900T 모듈 4개 air rate 0.3k 통일 적용 ✅
- 내일 RSSI byte 활성화 예정

→ **견적서의 ESP32 Heltec 대신 nRF52832 + E22 자체 펌웨어 사용 가능**.
→ 이 경우 **개발비 80만원(견적서) → 자체 자산으로 절감** 가능.

### 양산·운용 노하우

- **AMANO BLE Mesh 일본 3,800대 운용** (`myWiki/second-brain/entities/양산제품.md`)
- 다수 노드 동시 제어 + 무인 운전 안정성 검증
- → **BLE Mesh는 거리 부족** (수십m~수백m), 골프장 1~2km엔 LoRa 정답
- → 다만 양산·field test 노하우는 그대로 적용

### 자체 보드 설계 능력 (38년 경력)

- 견적서의 "자체조립 중계기 (20만원)" 부분이 UTTEC 강점
- 산업급 함체 + 자체 PCB로 품질·단가 동시 확보 가능
- → **"산업급 단가 + 자체 펌웨어"** 하이브리드 전략 가능

## 5. 추가 검토 사항 (UTTEC 입장에서)

### 한국 LoRa 인증 (★ 핵심 이슈)

| 대역 | 한국 ISM | 출력 한도 | 비고 |
|------|---------|-----------|------|
| 433 MHz | 433.05~434.79 MHz | ≤10mW (10dBm) | 매우 협소 |
| **920 MHz** | **920.9~923.3 MHz** | **≤200mW (23dBm)** | **★ 양산용 권장** |

- 견적서의 ESP32 Heltec는 433 또는 868/915 MHz 변종 — **한국 920 MHz 필수**
- 30 dBm (1W) 출력은 한국 미인증 → 실험·해외 수출용
- 현재 보유 E22-400T (433MHz)는 미인증 → 시험용
- E22-900T (873MHz, 우리 검증분) → 한국에선 920 MHz 변종으로 교체 필요
- **양산 시 KC 인증 필요** (전자파 적합성 + 무선설비 인증, 모듈 단위 인증된 것 사용 시 시스템 인증 면제 가능)

### 견적서 vs UTTEC 강점 정리

| 항목 | 견적서 권고 | UTTEC 대안 |
|------|-------------|-----------|
| MCU + LoRa | Heltec ESP32 | **nRF52832 + E22-900T (920 MHz 변종)** 자체 보드 |
| 펌웨어 | 템플릿 커스터마이징 (80만) | **자체 펌웨어** (오늘 완성, 무료) |
| 중계기 | 자체조립 ESP32 (20만/대) | **자체 PCB** + 산업급 함체 (단가 비슷, 품질↑) |
| 메인 게이트웨이 | RPi 4 | RPi 4 또는 **자체 보드 + 4G 모듈** |
| 모니터링 | Thingsboard / Node-RED | 동일 (오픈소스) |

→ 결과: **자체 펌웨어로 개발비 절감 + 산업급 PCB로 품질 향상**, 같은 1,000만원에 5~7년이 아닌 **8~10년 수명** 가능.

## 8. 기술 트레이드오프 메모

### Air rate vs 거리 (오늘 검증한 E22 기준)

| Air rate | LOS 거리 | 1KB 전송 시간 |
|----------|---------|---------------|
| **0.3k (현재 설정)** | ~15-20km LOS / 1-3km NLOS | ~30초 |
| 1.2k | ~10-12km / ~2km | ~7초 |
| 2.4k (factory) | ~7-8km / ~1km | ~3.5초 |
| 9.6k | ~3-4km / ~500m | ~1초 |

→ 골프장 (NLOS 1-2km)엔 **0.3k~2.4k 권장**. 현재 0.3k는 가장 보수적 (전 골프장 커버 보장).
→ 수위 데이터는 작음 (수 byte) → 전송 시간 무관, 거리 우선.

### 데이터 흐름 (예상)

```
[저장탱크 노드] -- 수위 BPS 약 0.1bps (1분당 1샘플 8byte) --> [중계기] -- LoRa --> [고가수조 노드 / 펌프]
                                                                       └--> [게이트웨이 RPi 4] --> Web/Mobile
```

→ **0.3k air rate로도 노드당 수십 노드 동시 운용 가능**.

### 펌프 제어 응답성

- 수위 임계값 도달 → LoRa 명령 → 펌프 ON: 약 **3~5초 latency** (RX→처리→ACK)
- 펌프 정전·고장 알림: 약 **3~5초**
- 비상 정지는 별도 hardwired 회로 권장 (LoRa 의존 X)
