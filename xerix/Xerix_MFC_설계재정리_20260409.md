## 3. EtherCAT ESC 교체 — LAN9252 → ET1100

### 3.1 ET1100 지정의 의미

고객이 **BECKHOFF ET1100**을 명시했습니다. 이는:
- Beckhoff 본가 ESC로 **호환성/인증 관점에서 가장 안전**
- **MII 인터페이스 외장 PHY 필수** (LAN9252는 PHY 내장)
- **PDI는 SPI / μC 병렬 / 디지털 IO** 중 선택 (LAN9252는 SPI 전용)

### 3.2 LAN9252 vs ET1100 비교

| 항목 | LAN9252 (어제) | **ET1100 (요구)** |
|---|---|---|
| 제조사 | Microchip | **Beckhoff** |
| 포트 수 | 2 (내장 PHY) | 최대 4 (외장 PHY) |
| PHY | **내장** (100BASE-TX 2포트) | **외장 필수** (KSZ8041/DP83848 등) |
| PDI | SPI / HBI | **SPI / Parallel(16bit) / Digital IO** |
| 패키지 | QFN64 10×10 | BGA128 / LQFP128 |
| 개발 난이도 | 낮음 (SPI만 연결) | 중상 (PHY+ESC 독립) |
| 소비전력 | 낮음 | 중간 |
| STMicro 공식 AN | **AN5397 (LAN9252)** | ❌ 없음 (SOEM/Beckhoff SSC 사용) |
| 한국어 자료 | 중 | **중하** (Beckhoff 포럼/영문 위주) |
| Xerix 의사 | - | **지정** |

### 3.3 ET1100 SPI PDI 구성 (권장)

```
   STM32F429ZI                       ET1100              KSZ8041NL ×2
  ┌────────────┐   SPI1 (≤20MHz)   ┌────────┐   MII    ┌──────────┐
  │ PA5 SCK    │────────────────▶│ SPI_CLK│─────────▶│ PHY0 MII │
  │ PA6 MISO   │◀────────────────│ SPI_DO │          │ (RJ45 P1)│
  │ PA7 MOSI   │────────────────▶│ SPI_DI │          └──────────┘
  │ PB0 nSS    │────────────────▶│ nSS    │          ┌──────────┐
  │ PB1 IRQ    │◀────────────────│ IRQ    │─────────▶│ PHY1 MII │
  │ SYNC0 IRQ  │◀────────────────│ SYNC0  │          │ (RJ45 P2)│
  │ SYNC1 IRQ  │◀────────────────│ SYNC1  │          └──────────┘
  └────────────┘                  └────────┘
                                   + EEPROM I²C (ESI)
                                   + 25MHz XTAL
```

### 3.4 ET1100 부품 조달
- **ET1100-0000-0017** (BGA128): Digi-Key/Mouser 재고 확인, 약 $18~25 @ 100ea
- **KSZ8041NL-TR** (PHY, 32-QFN): 약 $3 × 2 = $6
- **25 MHz 크리스탈** (50 ppm)
- **EEPROM 24LC32/24C32** (SII용, 4KB)
- **자화 트랜스포머** (H1102NL 등 × 2)

### 3.5 ET1100 개발 리소스
- **Beckhoff SSC (Slave Stack Code)**: ETG 가입 회원 무료
- **AN_ET1100** 데이터시트 + Section III (레지스터 맵)
- **Beckhoff Reference Design**: ET1100 + 외장 PHY + μC 예제 회로
- **STMicro X-CUBE-ECAT**: 원래 LAN9252 대상이지만 SPI PDI 부분은 **ET1100 이식 가능** (SPI 명령 포맷 다름 — 포팅 작업 필요)
- 대안: **SOEM Slave 스택 (오픈소스)** — GitHub OpenEtherCATsociety/SOEM

### 3.6 일정 영향
- **Phase 2 (펌웨어 브링업)**: 기존 4주 → **6주** (ET1100 SPI 포팅 + SII EEPROM 쓰기 + PHY 구동)
- **Phase 1 (H/W 설계)**: 기존 5~6주 → **6~7주** (외장 PHY 2ch + 자화 트랜스포머 추가 레이아웃)
- **총 일정**: 6개월 → **6.5~7개월**

## 4. 센서 이원화 — Thermal + Coriolis

### 4.1 두 방식의 공존 난이도

| 항목 | Thermal MFC | Coriolis MFC |
|---|---|---|
| 측정 원리 | 열전달 (ΔT) | 관성 위상차 |
| 센서 구조 | 바이패스 + 히터/감지 코일 | U-tube + Drive/Pickup 코일 |
| 응답 속도 | 500ms~2s | 50~300ms |
| 신호 체인 | 브릿지 → Instrumentation Amp → 12~16bit ADC | Drive AMP → Pickup 24bit ΔΣ ADC → FFT/Phase |
| 밸브 구동 | Solenoid 비례 주로 | Piezo 주로 |
| 가스 의존성 | 큼 (MGMR 필수) | 없음 (직접 질량 측정) |
| 원가 | 낮음 | 높음 (헤드만 200~400만원) |

**결론**: 센서 헤드는 완전히 다르고 신호 체인도 다르므로, **Sensor PCB는 2종으로 분리 제작**이 현실적입니다. Xerix 메일도 *"두 타입이 공존이 어려울 시 분리 개발"*로 허용하고 있습니다.

### 4.2 권장안: Sensor PCB 2종 + Main PCB 공용

```
  [ Main PCB ] ─── DIP SW: SENSOR SELECT ───┬──▶ [ Sensor PCB - Thermal ]
                                             └──▶ [ Sensor PCB - Coriolis ]
                         ↑
         DIP SW로 해당 타입 Sensor PCB 체결 시 자동 인식
         (Sensor PCB EEPROM에 Type ID 저장, 부팅 시 SPI 읽기)
```

- Main PCB는 **공통 AFE 인터페이스**(SPI + 12bit ADC + 드라이브 PWM + Temp/Press 입력) 제공
- Sensor PCB가 타입에 맞는 회로 구현
- Main 펌웨어는 Sensor Type ID에 따라 Thermal/Coriolis 알고리즘 분기

### 4.3 Pressure 센서 (보정용)
- **Sensor PCB에 내장** (공통)
- 0~5 MPa 게이지 센서 (Keller / SMI / Honeywell SSCDAND)
- 1ch I²C 또는 SPI ADC로 Main에서 직접 읽기
- PID에서 `Flow_PV = f(Sensor_PV, Pressure_corr)` 형태로 반영

## 5. SubProtocol PCB — 3종 플러그 구조

### 5.1 공통 커넥터 정의 (Main ↔ SubProtocol)

| 핀 | 신호 | 용도 |
|:---:|---|---|
| 1~4 | VCC 5V / 3.3V / GND × 2 | 전원 |
| 5~8 | SPI1 (SCK/MISO/MOSI/nSS) | ET1100 or 기타 칩셋 |
| 9~10 | UART3 TX/RX | DeviceNet/RS485 대안 |
| 11~12 | UART4 TX/RX | EtherCAT 디버그 |
| 13 | IRQ_A | ET1100 SYNC0 / RS485 TX Enable |
| 14 | IRQ_B | ET1100 SYNC1 / DeviceNet Error |
| 15~16 | GPIO (Board ID A/B) | SubBoard 타입 자동 인식 (00/01/10) |
| 17~20 | Reserved | |

### 5.2 Type별 SubProtocol PCB 구성

#### Type A: PIO + RS485
- 칩: **THVD1500** / SP3485 (RS485 트랜시버)
- PIO: **광절연 DI 8ch + DO 8ch** (PS2801 / TLP521)
- 커넥터: 20핀 스크류 터미널 + RS485 DB9
- 회로 면적: 소

#### Type B: DeviceNet
- 칩: **MCP2515** (CAN Controller) + **MCP2551** (CAN Transceiver)
- ODVA 스택: ESA (Embedded SmartApp) or 커스텀
- 커넥터: Mini Change M12 5핀 (DeviceNet 표준)
- **EDS 파일 작성** 필요 (ODVA 가입 필요)
- 회로 면적: 중

#### Type C: EtherCAT (ET1100)
- 칩: **ET1100** + **KSZ8041NL × 2** + H1102NL × 2
- EEPROM: **24LC32 (ESI용)**
- 커넥터: **RJ45 ×2** (Beckhoff/Omron 스타일)
- 외장 25MHz 크리스탈
- 회로 면적: 대

### 5.3 Board ID 자동 인식
- SubProtocol PCB에 **Board ID 핀 2개** (00: PIO, 01: DeviceNet, 10: EtherCAT, 11: Reserved)
- Main 부팅 시 GPIO 읽어서 해당 프로토콜 드라이버만 활성화
- **DIP SW와 Board ID 불일치 시** 에러 + LED Red

## 7. MGMR (Multi-Gas Multi-Range) 연산

### 7.1 기능
- Thermal MFC는 **가스 성분별 열용량(Cp)** 이 달라 유량이 달라짐
- N₂ 기준으로 교정 후 **Gas Conversion Factor (GCF)** 적용
- 사용자가 UART로 가스 종류(N₂/He/Ar/H₂/SF₆ 등) 선택 → 자동 보정

### 7.2 구현
- 내부 EEPROM에 **Gas Profile 테이블** 저장
  ```c
  typedef struct {
      char     name[8];
      float    gcf;          // Gas Conversion Factor
      float    density_kgm3;
      float    cp_jkgK;
      uint8_t  reserved[8];
  } gas_profile_t;

  // 예시 (vs N₂)
  N₂  : GCF = 1.000
  He  : GCF = 1.454
  Ar  : GCF = 1.410
  H₂  : GCF = 1.010
  O₂  : GCF = 0.993
  CO₂ : GCF = 0.737
  SF₆ : GCF = 0.264
  ```
- UART 명령: `SET GAS N2` 또는 `SET GAS SF6`
- 내부 연산: `Flow_corrected = Flow_raw × GCF[idx]`

### 7.3 Coriolis 모드에서는?
- Coriolis는 직접 질량 측정이므로 **GCF 불필요**
- 단, 부피 유량(SLM) 환산 시 **표준 상태(1 atm, 0°C) 밀도**만 필요
- MGMR 메뉴는 남겨두되, Coriolis 모드에서는 밀도 환산에만 사용

## 8. UART 커맨드 프로토콜

### 8.1 UART1 — Debugging
- 115200 bps, 8N1, Text ASCII
- 명령 예시:
  ```
  HIX            → XERIX v1.0.0
  GET PV         → PV=10.023 SLM
  GET SV         → SV=10.000 SLM
  SET SV 5.0     → OK
  ZERO           → ZERO CAL ING ... OK
  PID AUTO       → AUTO PID ING ... OK
  PID MANUAL 2.5 0.01 0.001  → OK
  GAS LIST       → N2, He, Ar, H2, O2, CO2, SF6
  SET GAS N2     → OK
  TEMP           → 25.3 C
  PRESS          → 250.5 kPa
  STATUS         → RUN/ERROR/CAL
  ```

### 8.2 UART2 — Customer
- 동일하지만 응답 헤더 `"HIC" → "CUSTOMER v1.0.0"`
- 명령 서브셋(고객 공개용): `GET PV / SET SV / ZERO / PID AUTO / PID MANUAL / STATUS`
- 내부 디버그 명령(FLASH WRITE, EEPROM ERASE 등)은 제외

### 8.3 Protocol Hex 모드 (향후)
- Xerix 메일에 *"protocol hex로 대체 예정 참고만 해주세요"* 명시
- 텍스트로 먼저 안정화 후, 공식 배포는 **Hex 바이너리 프로토콜**로 전환 예정
- CRC16 + STX/ETX 프레이밍 설계 필요
