# 템플릿 사용법

> Claude Code (또는 Claude API)와 함께 **프로젝트별 세션 연속성**을 자기-완결적으로 유지하기 위한 템플릿.
> 외부 시스템 (skill, hook, git, 별도 메모리) 없이 **폴더 내 파일만으로** 동작.

---

## 무엇을 위한 템플릿인가

- ✅ **다른 PC·다른 repo에서** 작업해도 동일한 세션 연속성
- ✅ **다른 프로젝트 (도메인·언어·기술 무관)**에 같은 패턴 적용
- ✅ **세션을 넘어** 작업 진행 + 결정 + 미완료 사항 자동 인계
- ✅ **외부 의존 0** — Claude Code의 built-in CLAUDE.md 자동 로드 기능만 사용

## 패키지 구성

```
claude_project_template/
├── CLAUDE.md       — Claude가 자동 로드하는 작업 지침
├── _진행로그.md     — 세션별 작업 기록 (최신이 위)
├── _다음할일.md     — 우선순위 to-do
└── 사용법.md       — 본 파일 (템플릿 사용 안내)
```

---

## 사용 절차

### 1. 새 프로젝트 폴더에 복사
```bash
# Bash / WSL / Mac
cp -r claude_project_template/ /path/to/your_new_project/

# PowerShell (Windows)
Copy-Item -Recurse claude_project_template\ C:\path\to\your_new_project\

# 또는 GUI에서 폴더 통째로 복사
```

새 프로젝트 폴더에는 `CLAUDE.md`, `_진행로그.md`, `_다음할일.md`, `사용법.md` 4개 파일이 들어갑니다. 사용법.md는 삭제해도 됩니다 (템플릿 안내용).

### 2. CLAUDE.md 의 placeholder 수정

`CLAUDE.md` 의 다음 항목을 자기 프로젝트에 맞게 채웁니다:

- **0번 섹션 — 프로젝트 컨텍스트 표**:
  - 프로젝트명·목적·이해관계자·단계·기술 스택·제약
- **3번 섹션 — 작업 가이드라인**:
  - 기술·비즈니스·한계 항목

`[프로젝트명]`, `[프로젝트 정식명]` 같은 placeholder를 검색해서 모두 교체.

### 3. README.md 작성 (필수, 별도)

이 템플릿에는 `README.md`가 없습니다. 프로젝트 특성에 맞게 직접 작성하세요. 일반적 구성:
- 프로젝트 개요·목적
- 아키텍처·구성도
- 주요 자료 링크
- 현재 단계

CLAUDE.md 의 1번 섹션 (세션 시작 프로토콜) 이 README.md 부터 읽도록 되어 있어 필수입니다.

### 4. 첫 세션 entry

`_진행로그.md` 의 예시 entry를 자기 첫 세션 작업으로 교체.
`_다음할일.md` 의 placeholder를 실제 작업으로 교체.

### 5. Claude Code (또는 Claude API) 사용

- Claude Code: 해당 폴더를 cwd로 두고 실행 → CLAUDE.md 자동 로드
- Claude API / Web: 첫 메시지에 CLAUDE.md 내용 포함하거나 첨부

이후 사용자가 "프로젝트 시작" 또는 "마무리" 같은 발화를 하면 CLAUDE.md 의 1번·2번 프로토콜이 자동 적용.

---

## 작동 원리

### 세션 시작 시
1. Claude가 `CLAUDE.md` 자동 로드 (Claude Code의 built-in 동작)
2. 사용자 발화 (예: "프로젝트 시작")
3. Claude가 1번 프로토콜 실행:
   - `README.md` 읽기
   - `_진행로그.md` 최상단 entry 읽기
   - `_다음할일.md` 읽기
4. 사용자에게 직전 세션 요약 + 이번 우선순위 보고

### 세션 종료 시
1. 사용자 발화 (예: "마무리", "오늘 끝")
2. Claude가 2번 프로토콜 실행:
   - `_진행로그.md` 상단에 새 entry append
   - `_다음할일.md` 갱신
   - 변경 사항을 README.md 등에 반영
3. 다음 세션 시작 안내

## 외부 시스템과의 차이

| 항목 | 본 템플릿 | Claude Code skill (`/work-start`) | 외부 메모리 (`~/.claude/memory`) |
|------|----------|-------------------------------|--------------------------------|
| 위치 | 프로젝트 폴더 내 | 사용자 홈 또는 repo 종속 | 사용자 홈 (PC별 분리) |
| 휴대성 | ✅ 폴더 복사로 이동 | ❌ skill 설치 필요 | ❌ PC 마다 별도 |
| 외부 의존 | ❌ | ✅ skill·hook | ✅ Claude Code |
| 프로젝트별 | ✅ 폴더당 1개 | △ skill은 글로벌 | ❌ 글로벌 |
| git 분쟁 | ❌ (파일 통제) | △ | ❌ |

## FAQ

**Q. 이미 myWiki·작업보고서 같은 외부 시스템이 있는데 같이 쓸 수 있나?**

같이 쓰는 건 가능하지만 **추천 안 함**. 본 템플릿은 외부 의존 없이 작동하도록 설계됨.
외부 시스템과 같이 쓸 경우 동일 정보가 두 곳에 기록되어 혼선 발생 가능.

**둘 중 하나 선택**:
- 외부 시스템에 통합하려면 → 본 템플릿 사용 안 함
- 자기-완결로 가려면 → 외부 시스템 의존 제거

**Q. 진행로그가 너무 길어지면?**

월 단위 또는 마일스톤 단위로 archive:
- `_진행로그.md` 의 오래된 entry를 `archive/_진행로그_2026-01.md` 같은 파일로 이동
- 최상단 30~50개 entry만 활성 파일에 유지

**Q. 여러 명이 같이 작업하면?**

git 같은 VCS로 폴더 동기화. 충돌 시 일반 git merge 절차.
또는 한 명이 작업하고 다른 사람은 읽기만 권장.

**Q. Claude가 _진행로그.md 갱신을 잊으면?**

세션 종료 시 사용자가 "마무리해줘" 같이 명시적 신호 주기.
또는 작업 도중 중요한 발견 시 즉시 로그에 기록 요청.

**Q. CLAUDE.md를 더 강제하려면?**

CLAUDE.md 상단에 다음 한 줄 추가:
```markdown
> ⚠️ 본 파일의 1·2번 프로토콜은 모든 세션에서 반드시 실행. 임의 생략 금지.
```
