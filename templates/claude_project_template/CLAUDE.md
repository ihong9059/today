## 1. 세션 시작 프로토콜 (사용자가 작업 시작 시)

다음 순서로 자동 실행:

### Step 1 — 컨텍스트 로드 (필수)
1. **`README.md`** 읽기 — 전체 프로젝트 맥락
2. **`_진행로그.md`** 마지막 (최상단) 항목 읽기 — 직전 세션 작업
3. **`_다음할일.md`** 읽기 — 우선순위 작업 목록
4. 기타 프로젝트 핵심 문서 (체크리스트·요구사항 등) 진행 상태 확인

### Step 2 — 사용자에게 보고
다음 형식으로 1회 표시 (장황하지 않게, 핵심만):
```
[프로젝트명] — {현재 단계}

직전 세션 (YYYY-MM-DD): {1줄 요약}
완료된 항목 N개 / 미완료 N개

이번 세션 우선순위:
1. {다음할일.md 첫 항목}
2. {두번째}
3. {세번째}

이어서 진행할까요? 다른 작업?
```

### Step 3 — 작업 시작
사용자 응답에 따라 작업 진행. 새 정보·결정·자료 발생 시 적절한 파일에 즉시 반영.

---

## 2. 세션 종료 프로토콜 (사용자가 마무리 신호 시)

신호 예: "마무리", "오늘 끝", "정리하자", "다음에 이어서", "/end" 등.

### Step 1 — `_진행로그.md`에 이번 세션 추가
파일 **상단** (최신이 위)에 다음 형식 append:

```markdown
## YYYY-MM-DD HH:MM

### 작업 요약
- {핵심 1~3줄}

### 완료 항목
- [x] {구체적 작업}
- [x] {구체적 작업}

### 발견·결정 사항
- {새로 알게 된 사실 또는 결정}

### 미완료·블로킹
- {중단 사유, 다음에 이어서 할 것}

### 수정·생성된 파일
- `파일명.md` — {변경 내용 요약}
```

### Step 2 — `_다음할일.md` 갱신
- 완료된 항목 체크 (`[x]`)
- 새로 발견된 작업 추가 (우선순위에 맞게 위치)
- 차단 사유·기한 명시

### Step 3 — 관련 문서 반영 확인
- 새 결정 → `README.md` 갱신
- 새 자료 입수 → 관련 체크리스트·요구사항 문서 갱신
- 단계 진척 → 마일스톤 문서 갱신

### Step 4 — 사용자에게 마지막 요약 제공
```
세션 종료. 다음 세션 시작 시:
- 직전 작업: {핵심}
- 이어서 할 것: {1~2줄}
- 갱신 파일: _진행로그.md, _다음할일.md, {기타}
```

## 5. 외부 환경 가정 (의존하지 않음)

이 프로젝트는 다음을 **요구하지 않습니다**:
- ❌ 특정 git repo (어느 repo에 있든 OK)
- ❌ 특정 PC OS (Windows·Mac·Linux 무관)
- ❌ Claude skill (`/work-start`, `/work-end` 등) — 본 CLAUDE.md 프로토콜로 대체
- ❌ 외부 메모리 시스템 (`~/.claude/memory/` 등) — 본 폴더 내 `_진행로그.md`로 대체
- ❌ git push·commit (작업 내용은 폴더 파일로 보관, push는 사용자 판단)
- ❌ 별 repo의 작업보고서 시스템

이 폴더가 어디에 있든 (USB·Dropbox·OneDrive·다른 repo), Claude는 본 CLAUDE.md만 읽으면 즉시 이어 작업 가능.
