# 통합 검증 계획

## 한 줄 결론

> **ESP32-S3 SRAM 520KB에 microGPT 4,192 파라미터 모델을 탑재하여 "외부 인터넷 0% AI" 가설을 검증한다. 성공 시 AI FanStick 차세대 + Stage 4 영업 패키지의 기술 근거 확보.**

---

## 핵심 가설

### 가설 1 — microGPT 탑재 가능성
> microGPT (Karpathy 200줄, 4,192 파라미터)가 ESP32-S3 SRAM 520KB에 들어간다.

- 출처: myWiki log.md 2026-05-06 21:30 (microGPT 분석)
- 계산: 4,192 파라미터 × 4 bytes (FP32) = 16.7 KB. 양자화 시 4 KB~8 KB. **여유 ↑**

### 가설 2 — 외부 인터넷 0%
> AI FanStick 차세대는 클라우드 API 0회로 AI 응답 가능 (microGPT 변종 탑재).

- 차별화 카피: "응원봉 자체 GPT" — 인터넷 끊겨도 동작
- K-POP 시장 매칭: 콘서트장 인터넷 약함 → 자체 처리 필수

### 가설 3 — Stage 4 영업 가능
> 본 검증 결과 → Stage 4 (1,500만) 패키지 기술 근거 + 한국기계·임베디드 스타트업 영업

- 영업 자산: ESP32-S3 SLM 시나리오 (Stage 4 영업 시 보드 옵션 1종)
- 차별화: 다른 강사·외주는 보드 검증 없이 제안만 함

## 진행 흐름 (단계별)

### Phase 1 (보드 도착 전, PC만으로 가능)

**예상 소요**: 4~8시간

```
A. microGPT PC 직접 실행
   ↓ Python으로 4,192 파라미터 모델 학습 + 추론
   ↓ Karpathy 200줄 코드 동작 확인 (1분 학습 / Mac 기준)
   
B. 포팅 가능성 분석
   ↓ FP32 → INT8 양자화 시뮬레이션
   ↓ ESP32-S3 SRAM 사용량 시뮬레이션
   ↓ 추론 시간 예측 (Mac → ESP32 차이)
   ↓ "포팅 가능 / 부분 가능 / 불가능" 결정
```

### Phase 2 (보드 도착 후)

**예상 소요**: 8~16시간

```
C. ESP32-S3 보드 입수 (사용자 직접, 1~2주)
   ↓
D. ESP32-S3 hello_world
   ↓ Arduino IDE 또는 ESP-IDF 환경 셋업
   ↓ LED 점멸 + Serial 출력 (5분 작업)
   ↓
E. microGPT ESP32-S3 포팅
   ↓ Python → C++ 변환 (Karpathy 200줄 → 임베디드 C++)
   ↓ FreeRTOS 태스크 구조
   ↓ SRAM 사용량 측정
   ↓ 추론 시간 측정
```

### Phase 3 (검증 결과 → 영업 자산화)

**예상 소요**: 2~4시간

```
F. AI FanStick SLM 통합 결정
   ↓ "ESP32-S3 유지" vs "더 큰 칩(예: ESP32-S3 N16R8) 변경"
   ↓ 의사결정 로그 작성
   ↓
G. Stage 4 영업 자료 갱신
   ↓ Stage4_OnDeviceAI_검토.md에 실증 데이터 추가
   ↓ entities/uttec-stage-package.md Stage 4 사례 갱신
   ↓ 강사양성·호오컨설팅·인프런 강의 사례로 활용
```

## 위험 / 완화

| 위험 | 발생 확률 | 완화책 |
|---|:-:|---|
| microGPT 양자화 후 정확도 ↓ | 중간 | INT8 vs INT4 두 가지 시도, FP16 백업 |
| ESP32-S3 SRAM 부족 (520KB 한계) | 낮음 | 외부 PSRAM 사용 (8MB 추가 가능) |
| 추론 시간 > 1초 | 중간 | 더 작은 모델 (1K 파라미터) 검토 |
| 보드 입수 지연 (1개월+) | 중간 | Phase 1만 먼저 완료, Phase 2는 도착 시 |
| AI FanStick 칩 변경 비용 ↑ | 낮음 | 검증 후 결정, ESP32-S3 유지 우선 |

- 포팅 가능성 분석 (Phase 1B)
