# Claude + Obsidian 공동 작업 가이드

## 이 문서의 목적

이 문서는 **Claude Code(AI 코딩 에이전트)**와 **Obsidian(노트 앱)**을 함께 사용하여 **"Second Brain(세컨드 브레인)"** 위키를 구축하고 운영하는 방법을 설명합니다.

프로그래밍 경험이 없는 분도 따라할 수 있도록, 처음부터 끝까지 단계별로 설명합니다.

---

## 1부: 기본 개념 이해

### 1.1 세컨드 브레인이란?

사람의 머릿속에 있는 지식, 경험, 판단을 **문서로 정리**해서 컴퓨터에 저장하는 시스템입니다.

왜 필요한가?
- 사람의 기억은 시간이 지나면 사라집니다
- 중요한 판단을 내릴 때 과거 경험을 참고할 수 있습니다
- AI(Claude)가 이 문서를 읽고 **맥락을 이해한 상태로** 도움을 줄 수 있습니다

비유하자면:
- 머릿속 지식 = 사라지는 메모
- 세컨드 브레인 = 영구적인 지식 창고 + AI 비서가 읽을 수 있는 매뉴얼

### 1.2 사용하는 도구 3가지

| 도구 | 역할 | 비유 |
|------|------|------|
| **Obsidian** | 문서를 보고 편집하는 노트 앱 | 공책 |
| **Claude Code** | 문서를 자동으로 작성/수정/분석하는 AI | 비서 |
| **Git** | 문서 변경 이력을 저장하고, 여러 기기에서 동기화 | 타임머신 + 클라우드 |

#### Obsidian이란?
- 마크다운(.md) 파일을 보기 좋게 보여주는 노트 앱입니다
- 문서 간 **링크**를 걸 수 있어서 위키처럼 사용할 수 있습니다
- 무료이며, Windows/Mac/Android/iOS 모두 지원합니다
- 공식 사이트: https://obsidian.md

#### Claude Code란?
- Anthropic이 만든 AI 코딩 에이전트입니다
- 터미널(명령줄)에서 동작합니다
- 파일을 직접 읽고, 쓰고, 수정할 수 있습니다
- **사용자의 위키를 읽고 맥락을 이해한 상태로 작업합니다**

### 1.3 이 두 도구가 만나면?

```
[사용자] ←→ [Obsidian] ←→ [같은 폴더] ←→ [Claude Code]
  보고 편집      시각화        .md 파일들       읽고 자동 작성
```

- Obsidian과 Claude Code는 **같은 폴더의 같은 파일**을 봅니다
- 사용자가 Obsidian에서 메모를 적으면, Claude가 읽을 수 있습니다
- Claude가 파일을 수정하면, Obsidian에서 바로 보입니다
- **서로 실시간으로 같은 문서를 공유**하는 것입니다

## 2부: 처음 시작하기 — 위키 폴더 만들기

### 2.1 폴더 구조 만들기

가장 먼저, 위키가 저장될 폴더를 만듭니다.

```
myWiki/
└── second-brain/          ← 이 폴더가 위키의 본체
    ├── CLAUDE.md           ← AI에게 주는 규칙서 (가장 중요!)
    ├── index.md            ← 전체 페이지 목록
    ├── log.md              ← 작업 기록
    ├── me.md               ← 나는 누구인가
    ├── skills.md           ← 내 기술 목록
    ├── experience.md       ← 경험 타임라인
    ├── projects.md         ← 프로젝트 맵
    ├── goals.md            ← 목표와 방향
    ├── strengths.md        ← 강점 분석
    ├── gaps.md             ← 부족한 부분
    ├── entities/           ← 상세 페이지 모음 (프로젝트, 도구, 사람 등)
    │   ├── 프로젝트A.md
    │   ├── 프로젝트B.md
    │   └── ...
    ├── thoughts/           ← 생각, 인사이트 기록
    └── raw/                ← 원본 자료 (읽기 전용)
```

### 2.2 CLAUDE.md — AI에게 주는 규칙서

**이 파일이 가장 중요합니다.**

CLAUDE.md는 Claude에게 "이 위키를 어떻게 다뤄야 하는지" 알려주는 설명서입니다.

여기에 적는 내용:
- 위키의 목적
- 폴더 구조 설명
- 페이지 작성 규칙 (프론트매터 형식, 링크 규칙)
- 어떤 상황에서 어떤 페이지를 업데이트해야 하는지
- 하지 말아야 할 것 (예: raw/ 폴더는 수정 금지)

Claude Code는 작업 시작 시 이 파일을 자동으로 읽습니다.

**비유**: CLAUDE.md = 신입 직원에게 주는 업무 매뉴얼

### 2.3 Obsidian에서 폴더 열기

1. Obsidian을 실행합니다
2. "Open folder as vault" (폴더를 보관함으로 열기)를 클릭합니다
3. `myWiki/second-brain` 폴더를 선택합니다
4. 이제 왼쪽 사이드바에 모든 .md 파일이 나타납니다

이때부터 Obsidian에서 문서를 보고 편집할 수 있습니다.

### 2.4 첫 번째 페이지 만들기 — me.md

가장 먼저 "나는 누구인가"를 적습니다.

```markdown
---
title: 나
type: identity
created: 2026-04-24
updated: 2026-04-24
tags: [정체성, 핵심]
---

# 나

## 한 줄 정의
[여기에 자신을 한 줄로 설명]

## 주요 역할
- [역할 1]
- [역할 2]

## 핵심 가치
- [가치 1]
- [가치 2]
```

이런 식으로 me.md, skills.md, goals.md 등 핵심 페이지를 하나씩 채워나갑니다.

## 3부: Claude와 함께 작업하기

### 3.1 Claude Code 시작하기

터미널(명령 프롬프트)을 열고, 위키가 있는 폴더로 이동합니다:

```bash
cd C:\todo\today
claude
```

Claude Code가 실행되면, 대화하듯이 작업을 지시할 수 있습니다.

### 3.2 Claude에게 위키 작업 요청하는 방법

자연어(일상 대화)로 요청하면 됩니다:

| 이렇게 말하면 | Claude가 하는 일 |
|-------------|----------------|
| "오늘 위시캣에 3건 지원했어" | experience.md에 추가, 위시캣활동.md 업데이트, log.md 기록 |
| "새 프로젝트 PVDF 센서 시작" | entities/pvdf.md 생성, projects.md에 추가 |
| "이번 주 목표 달성했어" | goals.md 체크, strengths.md 업데이트 |
| "이 기술 새로 배웠어: Flutter" | skills.md에 추가 |
| "사업 방향을 바꾸려고 해" | ai-direction.md 판단 로그 추가, goals.md 수정 |

**핵심**: 사용자는 "재료만 던지면" Claude가 알아서 적절한 페이지에 정리합니다.

### 3.3 Claude가 위키를 업데이트하는 과정

Claude는 다음 순서로 작업합니다:

```
1. CLAUDE.md를 읽어서 규칙 확인
2. 사용자가 말한 내용 분석
3. 어떤 페이지에 넣을지 판단
4. 관련 페이지를 읽어서 현재 상태 확인
5. 페이지 수정 또는 새 페이지 생성
6. 다른 페이지에 링크 추가 (상호 참조)
7. index.md, log.md 업데이트
```

**사용자가 직접 할 일**:
- Claude에게 사실을 알려주는 것
- Obsidian에서 결과를 검토하는 것

**Claude가 하는 일**:
- 적절한 페이지 찾기
- 형식에 맞게 정리
- 페이지 간 링크 연결
- 기록 남기기

### 3.4 실제 대화 예시

```
사용자: "오늘 위시캣에서 PVDF 센서 프로젝트 미팅을 했는데,
        클라이언트가 45일 안에 MVP를 원해.
        예산은 1000만원이고 안산에서 미팅했어."

Claude: [자동으로 수행]
  1. entities/위시캣활동.md → 미팅 기록 추가
  2. experience.md → 이번 달 활동에 미팅 내역 추가
  3. log.md → "2026-04-24 update | 위시캣 PVDF 미팅 완료" 기록
  4. projects.md → 새 프로젝트 후보로 등록

사용자: (Obsidian에서 확인) "잘 정리됐네, 감사합니다"
```

## 4부: 현재 우리가 진행하고 있는 작업

### 4.1 위키의 현재 규모

| 항목 | 수량 |
|------|------|
| 핵심 페이지 | 9개 (me, skills, experience, projects, goals, ...) |
| 엔티티 페이지 | 20개 (사전빌드, 위시캣활동, revita, ...) |
| 생각/인사이트 | 5개 |
| 원본 자료(raw) | 30개+ 폴더 |

### 4.2 어떤 작업들을 하고 있는가?

#### (1) 일일 작업 자동 기록
- 매일 작업 시작(`/work-start`) → 어제 미완료 작업 이월, 할일 통합
- 매일 작업 종료(`/work-end`) → 세션 저장, 작업보고서 작성, 위키 반영, git 커밋
- Claude가 "오늘 뭘 했는지"를 자동으로 위키에 반영합니다

#### (2) 프리랜서 영업 활동 추적
- 위시캣 프로젝트 지원 → 위시캣활동.md + Notion DB 자동 업데이트
- 미팅/계약/진행 상태를 추적합니다
- 지원서 작성 시 과거 경험과 강점을 위키에서 참조합니다

#### (3) 사업 방향 기록과 판단
- AI 3대 사업 전환 선언 → ai-direction.md에 판단 로그 기록
- "왜 이 결정을 했는가"를 기록해두면, 나중에 되돌아볼 수 있습니다
- 시장 인사이트, 경쟁 환경 변화를 기록합니다

#### (4) 기술 스택 관리
- 새 기술 학습/사용 → skills.md 업데이트
- 부족한 부분 발견 → gaps.md에 추가
- 프로젝트 완료 → strengths.md에 검증된 역량 추가

#### (5) 프로젝트별 상세 관리
- 각 프로젝트마다 entities/ 폴더에 전용 페이지가 있습니다
- 프로젝트의 상태, 기술, 이슈, 실적을 한 곳에 모아둡니다

### 4.3 이렇게 작업하게 된 이유

#### 문제: "머릿속에만 있는 정보"

기존에는:
- 프로젝트 경험이 머릿속에만 있었습니다
- 지원서를 쓸 때마다 과거 경험을 처음부터 떠올려야 했습니다
- 사업 방향을 왜 바꿨는지 기록이 없어서, 같은 실수를 반복할 위험이 있었습니다
- 할일 관리가 여러 곳에 흩어져 있었습니다

#### 해결: "위키에 모으고, AI가 활용"

세컨드 브레인을 만들면서:
- 모든 경험과 기술이 **검색 가능한 문서**로 정리됩니다
- Claude가 위키를 읽고 **맥락을 이해한 상태로** 지원서를 작성합니다
- 판단 기록이 남아서 **실수를 반복하지 않습니다**
- 할일이 작업보고서 ↔ Notion ↔ 위키로 **자동 동기화**됩니다

#### 핵심 인사이트

> **"위키는 만드는 것보다 유지하는 것이 중요하다"**

위키를 한번 만들고 끝나면 금방 낡아집니다.
그래서 Claude가 매일 작업 종료 시 자동으로 위키를 업데이트합니다.
사용자는 "재료만 던지면" 위키가 자동으로 성장합니다.

## 5부: 목표나 방향을 바꾸고 싶을 때

### 5.1 goals.md 수정하기

목표를 바꾸는 가장 기본적인 방법입니다.

**방법 1: Obsidian에서 직접 수정**
1. Obsidian에서 goals.md를 엽니다
2. 목표 항목을 직접 수정합니다
3. 저장하면 Claude가 다음 작업 시 변경된 목표를 인식합니다

**방법 2: Claude에게 말하기**
```
"목표에서 'Claude Design 학습'을 삭제하고,
 대신 '고객 관리 시스템 구축'을 추가해줘"
```
Claude가 goals.md를 수정하고, 관련 페이지도 업데이트합니다.

### 5.2 사업 방향을 바꿀 때 — ai-direction.md

큰 방향 전환은 **판단 로그**로 기록합니다.

```
사용자: "LED 사업을 접고 AI 교육 사업으로 전환하려고 해.
        이유는 중국 저가 공세 때문이야."

Claude가 하는 일:
  1. ai-direction.md → 판단 로그 추가
     - 날짜, 결정 내용, 이유, 근거
  2. goals.md → 목표 수정 (LED 관련 삭제, AI 관련 추가)
  3. projects.md → 프로젝트 우선순위 조정
  4. thoughts/ → 전환 배경 인사이트 기록
  5. log.md → 기록
```

이렇게 하면 **"왜 이 결정을 했는가"**가 남아서, 6개월 후에 되돌아볼 수 있습니다.

### 5.3 할일 목록 변경

할일을 추가/삭제/수정하는 방법:

| 방법 | 설명 |
|------|------|
| Notion에서 직접 수정 | "오늘 할 일" 페이지에서 항목 추가/삭제/체크 |
| Claude에게 말하기 | "할일에 XX 추가해줘" / "XX 완료로 처리해줘" |
| 작업보고서 수정 | 작업보고서의 할일 테이블을 직접 수정 |

다음 세션 시작(`/work-start`) 시 **모든 출처의 할일이 자동으로 동기화**됩니다.

### 5.4 위키 페이지 추가/삭제

**새 페이지 추가:**
```
사용자: "새 프로젝트 '스마트팜 센서'에 대한 엔티티 페이지 만들어줘"

Claude가 하는 일:
  1. entities/스마트팜센서.md 생성
  2. projects.md에 링크 추가
  3. index.md에 항목 추가
  4. 관련 페이지에 상호 참조 링크 추가
```

**페이지 삭제:**
- 직접 삭제보다는 **아카이브(보관)를 권장**합니다
- Claude에게 "이 페이지 더 이상 필요 없어"라고 말하면 처리합니다

### 5.5 CLAUDE.md 규칙 변경

위키 운영 방식 자체를 바꾸고 싶을 때:

```
사용자: "앞으로 엔티티 페이지에 '예산' 항목을 필수로 넣어줘"
사용자: "log.md에 매출 기록도 남기도록 해줘"
사용자: "위키 업데이트 주기를 주 1회에서 매일로 바꿔줘"
```

Claude가 CLAUDE.md의 규칙을 수정하고, 이후 작업부터 새 규칙을 따릅니다.

## 6부: 자동화 — 사람이 안 해도 되는 것들

### 6.1 현재 자동화된 작업들

| 시점 | 자동 동작 | 설정 위치 |
|------|----------|----------|
| **세션 시작** | 오늘 작업보고서 생성 | SessionStart hook |
| **세션 시작** | Notion ↔ 작업보고서 할일 동기화 | SessionStart hook |
| **세션 시작** | Notion 체크 항목 → 완료 섹션 이동 | SessionStart hook |
| **작업 종료** | 세션 저장 + 작업보고서 업데이트 | /work-end 스킬 |
| **작업 종료** | 위키 자동 반영 | /work-end 스킬 |
| **작업 종료** | Notion 2일 경과 완료 항목 삭제 | /work-end 스킬 |
| **작업 종료** | git 커밋/푸시 (동기화) | /work-end 스킬 |
| **위시캣 지원** | Notion DB + 위키 자동 업데이트 | /wishket-apply 스킬 |

### 6.2 이 자동화들은 어떻게 만들어졌는가?

모두 Claude Code와의 대화에서 만들어졌습니다:

```
사용자: "매일 작업보고서를 자동으로 만들어줘"
→ Claude가 Python 스크립트 작성 → SessionStart hook에 등록

사용자: "Notion 할일과 작업보고서를 동기화해줘"
→ Claude가 notion-sync.py 작성 → hook에 추가

사용자: "위시캣 지원 결과를 체계적으로 추적하고 싶어"
→ Claude가 Notion DB 생성 + 스킬 연동
```

새로운 자동화가 필요하면 Claude에게 말하면 됩니다.

## 7부: 일상적인 워크플로우

### 7.1 하루의 흐름

```
[아침] 터미널에서 claude 실행 → /work-start
       ↓
       어제 미완료 이월 + Notion 동기화 + 할일 표시
       ↓
[작업] Claude에게 작업 지시 (코딩, 문서 작성, 검토 등)
       ↓
       작업 중 위키 관련 변화 발생 시 자동 반영
       ↓
[마무리] /work-end
       ↓
       세션 저장 + 작업보고서 + 위키 반영 + git push
       ↓
[모바일] Notion에서 할일 확인, 체크 → 다음 세션에 반영
```

### 7.2 모바일에서 하는 일

Notion 앱으로:
- 오늘 할 일 확인 및 체크
- 위시캣 프로젝트 추적 현황 확인
- 미팅 준비 자료 검토
- 메모 추가

Obsidian 모바일 앱으로:
- 위키 검색 및 참조
- 간단한 메모 추가

### 7.3 여러 기기에서 작업할 때

- git push/pull로 동기화합니다
- 사무실 Mac과 외부 Windows PC에서 같은 위키를 사용합니다
- `/work-start`가 자동으로 `git pull`을 실행합니다

## 8부: 자주 묻는 질문 (FAQ)

### Q1. Obsidian 없이 Claude만으로 할 수 있나요?

가능합니다. 하지만 Obsidian이 있으면:
- 문서를 시각적으로 보기 좋게 볼 수 있습니다
- 링크를 클릭해서 페이지 간 이동이 편합니다
- 그래프 뷰로 페이지 연결 관계를 한눈에 볼 수 있습니다
- 모바일에서도 위키를 볼 수 있습니다

### Q2. Claude가 위키를 잘못 수정하면?

- git으로 이전 버전으로 돌아갈 수 있습니다 (`git log`, `git checkout`)
- Obsidian에서 수정 결과를 항상 검토하는 것을 권장합니다
- CLAUDE.md에 "하지 말아야 할 것"을 명시하면 실수를 줄일 수 있습니다

### Q3. 위키가 너무 커지면?

- 현재 35개 페이지, 전혀 문제 없습니다
- 수백 개까지도 Obsidian + Claude 조합으로 관리 가능합니다
- 한 폴더에 30개 이상 파일이 쌓이면 하위 분류를 검토합니다

### Q4. 다른 사람과 같은 위키를 공유할 수 있나요?

- Git으로 공유 가능합니다 (GitHub 등)
- CLAUDE.md 규칙을 공유하면 다른 사람의 Claude도 같은 규칙으로 작업합니다
- 단, 개인 정보가 포함된 페이지는 분리를 권장합니다

### Q5. 처음 시작할 때 가장 먼저 할 일은?

1. Obsidian 설치
2. 폴더 만들기 (second-brain/)
3. CLAUDE.md 작성 (규칙서)
4. me.md 작성 (나는 누구인가)
5. goals.md 작성 (목표)
6. Claude Code 실행 → "위키 시작하자"

나머지는 Claude와 대화하면서 자연스럽게 채워나가면 됩니다.
