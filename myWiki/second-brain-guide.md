## 1. 이것은 무엇인가

### 한 줄 정의
> LLM(Claude Code)이 자동으로 작성하고 유지하는 **나 자신에 대한 구조화된 지식 기반**

### 쉽게 말하면
일기, 메모, 이력서, 포트폴리오, 자기분석, 커리어 전략을 **하나의 연결된 시스템**으로 합친 것이다.
단, 내가 직접 정리할 필요가 없다. **LLM이 모든 정리/연결/업데이트를 대신 한다.**

### 핵심 비유

| 비유 | 설명 |
|------|------|
| 나만의 위키피디아 | 위키피디아가 세상의 지식을 정리하듯, 이 시스템은 **나에 대한 지식**을 정리 |
| IDE와 프로그래머 | Obsidian은 IDE(보는 도구), Claude Code는 프로그래머(쓰는 도구), 위키는 코드베이스 |
| 복리 통장 | 기록할수록 연결이 늘어나고, 연결이 늘어날수록 인사이트가 쌓인다. 시간이 지날수록 가치가 **복리**로 증가 |

### 무엇을 기록하는가

```
┌─────────────────────────────────────────┐
│              나 자신                      │
│                                          │
│  누구인가 ─── 어떤 기술이 있나            │
│     │              │                     │
│  무엇을 경험했나 ── 무엇을 하고 있나       │
│     │              │                     │
│  무엇을 하려 하나 ── 어떤 생각을 하나      │
│     │              │                     │
│  AI 시대에 어디로 가야 하나?              │
│                                          │
└─────────────────────────────────────────┘
```

## 2. 왜 필요한가

### 문제: 흩어진 자기 지식

우리는 매일 경험하고, 배우고, 판단한다. 하지만 이것들이 흩어져 있다:
- 어제 배운 것을 다음 달에 기억하지 못한다
- 비슷한 실수를 반복한다
- "내가 뭘 잘하지?"라는 질문에 체계적으로 답하기 어렵다
- 커리어 방향을 정할 때 감이나 분위기에 의존한다

### 특히 AI 시대에

AI가 빠르게 발전하면서 다음 질문들이 중요해졌다:

- **내가 하는 일 중 AI가 대체할 것은 무엇인가?**
- **AI를 활용해 내 능력을 10배로 만들 수 있는 곳은 어디인가?**
- **AI가 대체할 수 없는 나만의 가치는 무엇인가?**
- **지금 무엇을 배워야 하고, 무엇은 배울 필요가 없는가?**

이 질문들에 답하려면 **나 자신에 대한 정확하고 구조화된 이해**가 필요하다.
그것이 이 세컨드 브레인의 목적이다.

### 일반 메모/일기와의 차이

| | 일반 메모/일기 | 세컨드 브레인 위키 |
|---|---|---|
| 작성자 | 나 | LLM (Claude Code) |
| 구조 | 시간순 나열 | 주제별 구조화 + 상호 연결 |
| 유지보수 | 안 하면 썩는다 | LLM이 자동 유지 |
| 검색 | 키워드 검색 | 연결된 맥락으로 탐색 |
| 축적 | 양만 늘어남 | 연결과 인사이트가 복리로 성장 |
| 활용 | 가끔 다시 읽기 | AI가 종합하여 판단 근거 제공 |

## 3. 기존 방식과 무엇이 다른가

### RAG 방식 (ChatGPT, NotebookLM 등)

```
[문서들] → 질문할 때마다 검색 → 답변 → 사라짐
```
- 매번 처음부터 다시 찾는다
- 연결이 축적되지 않는다
- 질문 안 하면 지식이 활용되지 않는다

### 세컨드 브레인 위키 방식

```
[새 정보] → LLM이 읽고 이해 → 기존 위키에 통합 → 연결 업데이트 → 영구 보존
                                    ↓
              다음에 질문하면 이미 정리된 지식에서 답변
```
- 한 번 정리하면 계속 유지된다
- 새 정보가 올 때마다 기존 지식과 연결된다
- 시간이 지날수록 더 풍부하고 정확해진다

## 4. 시스템 구조 이해하기

### 3계층 구조

```
┌─────────────────────────────────────┐
│  1층: 원본 소스 (raw/)              │  ← 내가 넣는 원본 자료
│  일기, 스크린샷, 기사, 메모 등       │     LLM은 읽기만 함
├─────────────────────────────────────┤
│  2층: 위키 페이지                    │  ← LLM이 작성/유지
│  me.md, skills.md, goals.md ...     │     나는 읽기만 함
├─────────────────────────────────────┤
│  3층: 스키마 (CLAUDE.md)            │  ← 위키 운영 규칙
│  구조, 규칙, 워크플로우 정의         │     나와 LLM이 함께 발전
└─────────────────────────────────────┘
```

### 현재 위키 페이지 구성

```
second-brain/
│
├── CLAUDE.md              스키마 (운영 규칙서)
├── index.md               전체 페이지 목록 (목차)
├── log.md                 시간순 활동 기록
│
│   ── 나는 누구인가 ──
├── me.md                  핵심 정체성
├── strengths.md           강점 5가지 분석
├── gaps.md                부족한 부분 + 대응 계획
│
│   ── 무엇을 할 수 있나 ──
├── skills.md              기술 스택 (7개 영역)
├── experience.md          경험 타임라인
│
│   ── 무엇을 하고 있나 / 할 것인가 ──
├── projects.md            프로젝트 맵
├── goals.md               단기/중기/장기 목표
│
│   ── AI 시대 방향 ──
├── ai-landscape.md        AI 기술 지형도 (관찰 기록)
├── ai-direction.md        방향 판단 프레임워크 ★
│
│   ── 확장 영역 ──
├── thoughts/              생각, 인사이트, 일기
├── entities/              사람, 조직, 도구
└── raw/                   원본 소스 (불변)
```

### 페이지 간 연결 관계

```
            ┌── skills.md ──┐
            │               │
me.md ──────┤               ├── ai-direction.md ★
            │               │        │
            ├── experience  │        │
            │               │        │
            └── strengths ──┘   ai-landscape.md
                    │
                 gaps.md
                    │
            goals.md ── projects.md
```

모든 페이지가 서로 `[[링크]]`로 연결되어 있어서,
Obsidian의 **그래프 뷰**에서 네트워크를 시각적으로 볼 수 있다.

## 5. 초기 설정 방법

### 5-1. Obsidian 설치 및 설정

1. **Obsidian 다운로드**: https://obsidian.md
2. **Vault 열기**: File → Open Vault → `C:\todo\today\myWiki\second-brain` 선택
3. **추천 설정**:
   - Settings → Files and Links → "Wikilinks" 활성화
   - Settings → Files and Links → Default location for new attachments → `raw/`
4. **추천 플러그인**:
   - **Graph View** (기본 내장): 페이지 연결 네트워크 시각화
   - **Dataview** (커뮤니티): 프론트매터 기반 동적 테이블
   - **Calendar** (커뮤니티): 날짜별 생각 페이지 탐색

### 5-2. 위키 초기 데이터 보강

위키가 방금 만들어졌기 때문에, 다음 정보를 Claude Code에게 공유하면 위키가 풍부해진다:

- **이력서/경력 사항**: 과거 직장, 프로젝트 경험
- **교육 배경**: 전공, 자격증, 수료 과정
- **현재 고민**: 커리어, 기술 선택, 사업 방향
- **최근 인상 깊었던 것**: 기사, 영상, 대화, 경험

## 6. 일상 사용법

### 6-1. 수집 (Ingest) — 새 정보 추가하기

새로운 경험, 생각, 정보가 생기면 Claude Code에게 자연어로 말한다.

**예시 대화:**

```
나: "오늘 교육 현장에서 10명이 동시에 빌드를 요청했는데 서버가 죽었어.
    큐 시스템을 도입해야 할 것 같아."

Claude: (위키 업데이트)
  - experience.md → 교육 현장 운영 경험 추가
  - projects.md → 사전빌드 시스템 과제 업데이트
  - gaps.md → 동시성/확장성 항목 업데이트
  - thoughts/ → 새 생각 페이지 생성
  - log.md → 기록 추가
  - index.md → 인덱스 업데이트
```

**수집할 수 있는 것들:**

| 종류 | 예시 | 업데이트되는 페이지 |
|------|------|-------------------|
| 새 기술 학습 | "오늘 MCP 서버 만드는 법을 배웠어" | skills, experience, ai-landscape |
| 프로젝트 변화 | "C6-LCD 사전빌드 시스템 완성했어" | projects, experience, goals |
| AI 관련 관찰 | "Claude가 이제 100만 토큰을 처리해" | ai-landscape, ai-direction |
| 개인 생각 | "하드웨어 교육이 AI 시대에 더 가치있을 것 같아" | thoughts/, ai-direction |
| 사람/조직 | "위시캣에서 좋은 클라이언트를 만났어" | entities/ |
| 실패/교훈 | "Kotlin 앱은 결국 Flutter로 교체했어" | experience, ai-direction (판단 로그) |

### 6-2. 질의 (Query) — 나에 대해 질문하기

위키에 대해 질문하면 Claude가 관련 페이지를 종합하여 답변한다.

**유용한 질문 예시:**

```
"내 핵심 강점 3가지를 위시캣 지원서용으로 정리해줘"
→ me.md + strengths.md + skills.md 를 종합하여 답변

"AI 시대에 내가 가장 먼저 배워야 할 기술은?"
→ ai-direction.md + gaps.md + ai-landscape.md 를 종합하여 답변

"최근 3개월간 내가 가장 많이 시간을 쓴 영역은?"
→ projects.md + experience.md + log.md 를 종합하여 답변

"나의 교육 사업 전략을 한 페이지로 정리해줘"
→ goals.md + projects.md + ai-direction.md + strengths.md 를 종합
→ 가치 있으면 새 위키 페이지로 저장
```

### 6-3. 점검 (Lint) — 위키 건강 체크

주기적으로 (월 1회 권장) Claude에게 점검을 요청한다.

```
"세컨드 브레인 위키 점검해줘"
```

Claude가 확인하는 것:
- 오래된 정보 (updated 날짜가 오래된 페이지)
- 연결이 없는 고아 페이지
- 모순되는 기록 (예: skills에는 '상'인데 gaps에도 있는 항목)
- 빠진 페이지 (언급은 되지만 페이지가 없는 주제)
- 탐색 제안 ("이런 주제의 생각을 정리해보면 어떨까요?")

## 7. AI 방향 판단 시스템 사용법

이 위키에서 가장 중요한 부분은 **ai-direction.md**이다.
AI 시대에 어떤 방향으로 가야 하는지를 **감이 아닌 근거**로 판단하기 위한 시스템이다.

### 5가지 판단 프레임워크

#### 1. 대체 위험 분석
> "내가 하는 일 중 AI가 더 잘하게 될 것은 무엇인가?"

```
나: "요즘 Claude가 웹사이트를 거의 혼자 만들어.
    내가 웹 개발 스킬에 더 투자해야 할까?"

Claude: (ai-direction.md 업데이트)
  대체 위험 테이블에 추가:
  | 단순 웹 개발 | 높음 → 매우 높음 | 하드웨어 연동으로 차별화 |
```

#### 2. 증폭 기회 분석
> "AI를 활용해 내 능력을 10배로 만들 수 있는 곳은 어디인가?"

```
나: "Claude Code로 하루에 사전빌드 117개를 만들었어.
    예전 같으면 일주일 걸렸을 거야."

Claude: (ai-direction.md 업데이트)
  증폭 기회에 추가:
  - 사전빌드 시스템: AI 프롬프트→코드생성→빌드 파이프라인으로 100배 생산성
```

#### 3. 유니크 가치 분석
> "AI가 대체할 수 없는 나만의 가치는 무엇인가?"

이것은 시간이 지나면서 점점 명확해진다.
경험, 프로젝트, 피드백이 쌓이면서 패턴이 보이기 시작한다.

#### 4. 학습 우선순위
> "지금 배워야 하는 것 vs 나중에 배워도 되는 것"

```
나: "MCP 서버 개발을 배워야 할까, 아니면 딥러닝 모델 학습을 배워야 할까?"

Claude: (ai-direction.md + skills.md + ai-landscape.md 종합)
  → MCP: 현재 AI 도구 연동 표준, 내 교육 시스템과 직접 연결 → 지금 배우기
  → 딥러닝 모델 학습: 도구로 충분, 직접 모델을 만들 필요 낮음 → 나중에
```

#### 5. 판단 로그
> "언제, 왜, 어떤 결정을 내렸는가"

모든 중요한 기술/방향 결정을 기록한다.
나중에 돌아보면서 **판단의 패턴**을 발견할 수 있다.

```
| 날짜 | 판단 | 근거 | 결과 |
|------|------|------|------|
| 2026-04-19 | Flutter 단일화 | 생산성 | 성공 ✅ |
| 2026-04-19 | 바이브 코딩 교육 | AI 트렌드 | 진행 중 |
```

### AI 방향 판단 사용 시나리오

```
상황: 새로운 기술 트렌드를 발견했을 때

나: "OpenAI가 코딩 에이전트를 발표했어.
    이게 내 사전빌드 시스템에 어떤 영향을 줄까?"

Claude:
1. ai-landscape.md 업데이트 (새 트렌드 기록)
2. ai-direction.md 분석:
   - 대체 위험: 커스텀 빌드가 에이전트로 자동화될 가능성 → 중간
```

## 10. 자주 묻는 질문

### Q: 직접 위키 파일을 편집해도 되나요?
**가능하지만 권장하지 않습니다.** Claude Code에게 말로 전달하면 관련 페이지들을 자동으로 업데이트합니다. 직접 편집하면 다른 페이지와의 연결이 깨질 수 있습니다. Obsidian은 **보는 용도**로 사용하세요.

### Q: 민감한 정보도 넣어도 되나요?
위키는 **로컬 파일**입니다. 클라우드에 자동 업로드되지 않습니다. 단, git push를 하면 원격 저장소에 올라가므로, 민감한 정보는 `.gitignore`에 추가하거나 raw/ 폴더에 별도 관리하세요.

### Q: 얼마나 자주 업데이트해야 하나요?
**부담 없이, 의미 있을 때만.** 매일 할 필요 없습니다. 중요한 경험, 생각, 판단이 있을 때 Claude에게 한 마디 하면 됩니다. 최소 **월 1회** 점검을 권장합니다.

### Q: 위키가 너무 커지면 어떻게 하나요?
index.md가 목차 역할을 하므로 페이지가 100개가 되어도 탐색이 가능합니다. 더 커지면 qmd 같은 검색 도구를 추가할 수 있습니다. 하지만 이 위키는 **나 자신**에 대한 것이므로 수백 페이지를 넘기기 어렵습니다.

### Q: 다른 LLM으로 바꿔도 되나요?
네. 위키는 **마크다운 파일**이므로 어떤 LLM이든 읽고 쓸 수 있습니다. CLAUDE.md를 해당 LLM의 설정 파일 형식으로 변환하면 됩니다.

### Q: 기존 Claude Code 메모리와 어떤 관계인가요?
Claude Code 메모리(`~/.claude/projects/.../memory/`)는 **Claude Code 사용 방법**에 대한 설정이고, 세컨드 브레인은 **나 자신에 대한 지식 기반**입니다. 목적이 다르며, 서로 보완합니다.
