# LoRa 기술 근거 — 사업방향 흡수 요청

본 vault(lora)에서 LoRa 모듈 4종 통신 검증 완료. 사업방향에 흡수할 기술 역량·결정 근거 cascade.

## 신규 기술 역량 (decision 근거)

1. **모듈 4종 TX/RX 통신 확보** — E22-400T30D(433.125MHz), E22-900T22D(922, 한림 양산), E32-915T30D(923), E32-433T20D(433). 2개 칩 패밀리(SX126x·SX127x) × 2개 대역 전부 구동.
2. **칩별 config 프로토콜 단일 출처 확보** — E22(REG0~3 9바이트) / E32(SPED·CHAN·OPTION 6바이트). 재사용 가능 SOP 박제.
3. **nRF52832 + Ebyte UART LoRa 통합 패턴** — HW UART time-mux debug(단일 UART 공유), 함정 5종 해결.

## gotcha (재사용 자산)

- **E32 config write = EasyDMA 연속 프레임 필수** (poll_out 바이트 틈→모듈 무응답). 향후 E32/E19 작업 필수 적용.
- **주파수 공식 칩별 상이** — E22(x.125 그리드) vs E32(x.000 그리드) → 125kHz 어긋남.
- **APPROTECT** nRF52832 REV2 chiperase 후 → --recover.

## ⭐ 사업방향 매칭 패턴 (전략 함의)

**Ebyte E22 ↔ E32 교차통신 불가** (주파수 그리드 어긋남 + air rate 매핑 차). 함의:
- 현 한림 양산(E22 UART)은 **단일 칩 패밀리 폐쇄망**으로만 확장 가능 — E32 혼용 불가.
- **이종 모듈 혼용·정밀 RF·게이트웨이 통합**이 사업적으로 필요해지면 → **SPI 모듈(E22-M/E19) + Zephyr lora 드라이버** 아키텍처 전환이 정석. raw 칩 제어로 교차운용·저지연·nRF 통합 확보.
- → **SPI 전환 PoC**를 차기 기술 로드맵 후보로 검토 제안.
