# Round 18 후속 ✅ pca10040 64KB 12/12 RAM wall — 13/13 보드 완성

5/23-001 mywiki ACK 카드 후속 권고 ("pca10040 (nRF52832 M4F 64KB) Round 18 패턴 재사용 측정 → 13/13 보드 완료") **5/22 14:18 완료**. pca10056 본편(오전) + pca10040 후속(오후) 모두 sweep 완료 → **Nordic Cortex-M4F 2 보드 CMSIS-NN 매트릭스 완성**.

## 핵심 발견 — pca10040 12/12 RAM wall

| Cell | Round 14 plain C | **Round 18 CMSIS-NN pca10040** | 비고 |
|---|---:|---:|---|
| MLP 128 ~ 16384 (5셀) | RAM wall | **RAM wall** (12/12) | weights ~42KB+ > heap ~30KB |
| CNN 32, 64, 128 (3셀) | RAM wall | **RAM wall** (12/12) | conv buffers + im2col 64KB 초과 |
| TF 64, 484, 1084, 2436 (4셀) | RAM wall | **RAM wall** (12/12) | KV cache + embed table 64KB 초과 |

→ **Round 14 plain C 결과 100% 재현** (CMSIS-NN library 추가로 static .bss 34KB / 64KB = 52.34%, runtime heap ~30KB 부족 — newlib `_sbrk` 영역 < weights). **pca10040 64KB tier는 mandate 최소 셀조차 fit 불가** 정량 박제.

## 영업 결정타 (Stage 4 칩 선택 가이드 강화)

| 양산 트랙 | 칩 | RAM | mandate fit | CMSIS-NN 가속 | 적용 |
|---|---|---:|:-:|:-:|---|
| **AI FanStick 차세대** | ESP32-S3 | 520KB + PSRAM 8MB | ✅ 전셀 | LX7 ESP-DSP +13.4× | SLM 응답 ~150ms |
| **B2B 통합 SoC** | **nRF52840** (256KB) | 256KB | ✅ MLP 128 / TF 64 | **CMSIS-NN +3.23×** | BLE 5 + USB + NFC + AI |
| **저전력 BLE** | **nRF52832 (64KB)** | 64KB | ❌ **전셀 wall** | **빌드 OK, runtime 불가** | **AI 적합 X** — BLE-only |

→ **"Nordic AI 응용 = nRF52840 (256KB) 이상 필수"** 정량 박제. 5/23-001 ACK § "Stage 4 칩 선택 가이드"에 pca10040 부적합 행 신설 권장.

## 빌드 함정 신규 박제 (Nordic 누적 11건 — pca10040 보드별 차이)

pca10056 sweep 때 없던 2건. pca10040 보드별 unique 함정:

| # | 함정 | 우회법 | 박제 위치 |
|---|---|---|---|
| **#23** ⭐ | **pca10040 APPROTECT (readback protection) 활성** → flash 시 `nrfjprog error -90, Access protection is enabled, must be recovered`. pca10056는 unprotected, pca10040은 protected = 보드별 차이 (vendor가 출고 default 설정 다름 추정) | sweep 시작 전 1회: `nrfjprog --recover -f NRF52 --snr <SN>` (30초, AP protect 해제 + UICR/flash erase) | `CLAUDE.md § Nordic 빌드 함정 박제` |
| **#24** ⭐ | **--recover 후 USB re-enumeration** → VCOM0/VCOM1 COM 번호 변경 (예: COM33/COM34 → COM35/COM36). 동일 보드인데 SN 그대로, COM port만 바뀜 = USB host driver의 device descriptor 재할당 추정 | recover 직후 `nrfjprog --com` 재실행으로 새 COM port 재detect → `$env:NRF_COM`에 VCOM0 번호 (콘솔 primary) 갱신 후 sweep 시작 | `CLAUDE.md § Nordic 빌드 함정 박제` |

→ **본 함정 11건 (Round 17 ESP-DSP 4건 + Round 18 본편 5건 + Round 18 후속 2건)** = Nordic Cortex-M 측정 ecosystem 영구 자산. 위시캣 임베디드 / 강사양성 Day 5 모듈 인벤토리 결정타. 미래 Nordic 보드 추가(예: nRF52833 / nRF5340) 시 #23 (APPROTECT 점검) + #24 (post-recover COM 재detect) 자동 적용 SOP 갖춰짐.
