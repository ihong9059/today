# 공용 시스템 보드 = 수조제어 + 조명제어를 단일 HW로 커버 (제품라인 확장 근거)

## 1. 신규 기술 결정 (decision)
한림 수조제어에서 습득한 HW 기능과 LoRa 조명제어의 **유사성(power on/off relay)**을 축으로, 여러 응용을 하나로 커버하는 **공용 시스템 보드 reference**를 확정.
- 단일출처 = `하드웨어/공용_시스템보드/공용_시스템보드_reference.md` (block diagram + 실장 매트릭스).
- **공통 코어(고정)** = `LoRa(E22-900T22D) + power on/off 릴레이 + nRF52832(bleModule) 제어 + 2.4G ESB`.
- **선택 실장** = RS485 수위센서 · PIR 재실감지 · 배터리+솔라/AC220V 전원 · RTC · 전류센서(INA219).

## 2. 사업 함의 (왜 흡수 요청)
- **한 보드로 수조(pump on/off) + 조명(조명 on/off) + 확장(밸브·팬 등)** 커버 → **제품 라인 통합·개발/재고 원가 절감·양산 단순화**.
- 골프장 대상 **2개 시스템**(원거리 수조 자동제어 + 야간 조명 순차 off 절전)이 **동일 HW 플랫폼** 위에 올라감 = 제안·영업에서 "단일 플랫폼" 강점.
- 조명 시스템(야간 순차 off + 인적사고예방)은 **신규 도메인** — 사업/제안서/presentation 방향은 myWiki 소관으로 판단(본 vault=기술 근거만).

## 3. 매칭 패턴 (cross-vault)
- 수조(한림)·조명·shield(RS485/MESH 제품)·revita 모두 **LoRa + 릴레이 제어**라는 공통 뼈대 → 공용 보드가 횡단 자산.

## 4. gotcha / 정직 고지
- ⚠️ **조명 fail-safe 안전논리가 수조와 반대**: 수조=무수신 시 OFF(월류 방지)가 안전 / 조명=재실 중 OFF 금지(인적사고) → **PIR 재실감지 입력과 결합 필요**. 조명 제어논리는 수조 그대로 못 씀(미결·설계 필요).
- 조명=**AC 220V 부하** → 릴레이 opto 절연·정격·연면거리 등 안전 요구가 수조 pump보다 강함.
- 현 시점 = reference block diagram 단계(부품선정·회로·양산 미착수).

## 5. 요청
- myWiki 측 **사업방향/제안 자료**(골프장 2시스템 presentation·동영상)에 "**단일 공용 플랫폼 보드**" 강점을 근거로 반영.
- 조명 응용의 사업 소관(myWiki vs 신규)·우선순위 판단.
