## 기술 검토 결과 (11/17 ondevice-claude, vault 실측 근거)

### 1. 칩 후보 검토 — ESP32-C6 vs nRF52832 (현 BOM)

| 축 | ESP32-C6 | nRF52832 (클라이언트 송부 BOM 기준) |
|---|---|---|
| 연산/RAM | 통과 (R11 실측: MLP128 1.9ms, 512KB SRAM) | 통과 (64KB RAM — 본 앱 ~3KB 모델은 여유, 확장 천장 주의) |
| 전력 | 조건부 — deep sleep 재부팅 함정(매 2초 wake 시 수명 반감) → **LP 코어 polling 또는 light sleep 필수** (적용 시 ~3.7개월 = nRF 동급) | **최강** — 1.9µA + µs wake, 전력 설계 공짜, ~3.8개월 |
| 전원 | 3.0~3.6V — TPS63900 buck-boost 필수 | 1.7V 직결 — 레귤레이터 생략 가능 (BOM 절감 카드) |
| 단가/양산 | **우위** — 모듈 ~$2 + native USB 프로그래밍 (지그 불요) | ~$3~6 + SWD 지그 |
| 무선 | BLE + 802.15.4 (Thread/Matter 확장 카드), WiFi는 배터리 금지 | BLE Mesh LPN 업계 레퍼런스 |
| 판정 | **가능 (조건부)** — 단가·확장성 우위 | 보수적 안전 선택 — 수명 KPI 최우선 시 |

- **R48 전체 파이프라인** (factoryRpi4 학습 carrier → INT8 양자화 → MCU 배포 → 골든 평가) — 입력부만 ToF 64-zone으로 교체
- **R49 비지도 이상탐지** (빈 상태 분포 학습 → 편차 감지, isolation forest F1 0.995) — 어두운 소재 등 ToF edge case 백업 경로 (클라이언트 11/12 반론 기술 뒷받침)
- 보드한계모델 검증 방법론 (검증 표 × 수치 합격선) — 제안서의 완료 기준과 1:1 부합
- 개발 환경: esp32c6(ESP-IDF COM20) + pca10040(Zephyr) 모두 박제 완료, 보드 보유
