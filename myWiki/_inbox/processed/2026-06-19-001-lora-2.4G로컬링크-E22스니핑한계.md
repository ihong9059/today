# LoRa 기술 검토 결론 2건 — 사업방향 흡수 요청

본 vault(lora) 2026-06-19 검토 결론 중 **사업 함의** 있는 2건을 cascade합니다.

## 1. 신규 decision — group 내부 "2.4G ESB + LoRa 하이브리드" 아키텍처 옵션 (검토/17)
- **무엇**: 한림형 group 내부(SENSOR↔ONOFF, 5~6m+벽) 로컬소통을 평상시 **2.4G ESB**(nRF52832 내장 라디오)로, 끊기면 LoRa 2단중계 폴백.
- **사업 함의**: LoRa 채널 air-time 확보(group 확장성↑), ACK-도청 명령 hack·관련 버그 제거(신뢰성↑), ONOFF E22 BOM 절감 여지. **로컬 자율제어 강화** = 한림/factory 등 "현장 자율 + 원격 보조" 제품 패턴에 재사용 가능.
- **gotcha(중요 역량 경계)**: **nRF52832 2.4G는 900M LoRa보다 폐쇄공간 투과 ~30dB 불리**(Coded PHY 미지원·TX +4dBm 한계). → 2.4G 로컬링크는 **근거리·약장애물 한정**. 장거리/투과는 sub-GHz LoRa가 정답. 채택 전 **현장 2.4G RSSI 실측 필수**(측정 SOP·판정표 본 vault 보유).

## 2. 신규 gotcha — Ebyte E22는 generic SX126x로 디코드 불가
- **무엇**: 같은 SX1262 칩(CubeCell)으로도 **Ebyte E22 on-air 프레임을 복조 못 함**(E22가 LoRa PHY 위에 독자 프레이밍). SF/BW·sync·헤더/CRC 전수 스윕 + E22 2개로도 0건 실증.
- **사업 함의**: LoRa 진단/모니터링/멀티벤더 상호운용 설계 시 **"같은 칩=호환"이 아님**. E22 기반 망의 스니핑·게이트웨이는 **E22 모듈로** 구성해야 보장. 제3자 SX126x 보드로 E22망 진입 불가 = 벤더 락인 요소. (← [[검토/10]] "E22↔E32 불가"의 확장)
