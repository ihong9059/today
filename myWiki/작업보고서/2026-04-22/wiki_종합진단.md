## 2. 목적 명확성 진단

### 평가: 양호 (8/10)

CLAUDE.md에 명시된 3대 목적:
1. **자기 이해** — 경험, 기술, 성향, 패턴 구조화
2. **방향 판단** — AI 시대 근거 있는 의사결정
3. **복리 성장** — 기록 간 연결로 점점 풍부해지는 시스템

**잘 된 점:**
- 목적이 "외부 지식이 아닌 나 자신"으로 명확히 한정됨
- ai-direction.md의 5가지 판단 프레임워크가 실용적
- 판단 로그 14건이 실제 의사결정에 활용 가능

**개선 필요:**
- **"복리 성장"이 아직 구조적으로 작동하지 않음**: 페이지 간 상호참조는 있지만, "A를 알게 되니 B가 새롭게 보인다"는 인사이트 연결이 부족
- **목적 3개 중 "방향 판단"에 비중이 쏠림**: me.md, strengths.md는 초기 작성 후 업데이트 없음. 자기 이해 영역이 정체되어 있음
- **성과 측정 기준 없음**: 위키가 실제로 의사결정에 도움을 주었는지 추적하는 메커니즘 부재

## 3. Raw Data 추가 진단

### 평가: 주의 필요 (6/10)

**현재 구조:**
- junction 링크 15개 → 실제 프로젝트 폴더 연결
- 실제 데이터 폴더 5개 (articles, career, projects, webServer, 응원봉)
- .gitignore에 raw/ 전체 제외됨

**문제점:**

#### 문제 1: junction 링크의 불안정성
- Windows junction 링크는 대상 폴더 이동/삭제 시 깨짐
- 15개 junction 중 어떤 것이 유효한지 확인하는 자동화가 없음
- **위험**: 폴더 정리 시 junction이 깨져도 모르고 지나갈 수 있음

#### 문제 2: raw/ 크기 제어 불가
- 응원봉/ 단일 폴더가 11.3GB (node_modules 포함)
- aiHardStudy/ junction이 48K 파일 연결
- **30개 파일 초과 시 분류** 규칙은 있지만, 용량 기준 규칙 없음
- Obsidian이 raw/ 전체를 인덱싱하면 성능 저하 가능

#### 문제 3: raw/ 추가 절차 미정립
- 새 프로젝트 폴더를 raw/에 추가할 때의 체크리스트가 없음
- junction vs 실제 복사 vs symlink 기준이 불명확
- 추가 후 entities/ 페이지 생성, index.md 업데이트, log.md 기록을 매번 수동으로 해야 함

#### 문제 4: articles/, career/, projects/ 활용도 낮음
- articles/: 스크랩은 있지만 위키 본문에서 참조하는 페이지 없음
- career/: 이력서 등이 있지만 skills.md, experience.md와 연결 안 됨
- projects/: raw/projects/와 entities/ 프로젝트 페이지 간 관계 불명확

## 4. 진행 방법 진단

### 평가: 보통 (7/10)

**잘 된 점:**
- Ingest → Query → Lint 워크플로우가 명확
- 프론트매터 표준이 일관되게 적용됨
- 고아 페이지 금지 정책이 잘 지켜짐 (Lint A+)
- /wiki-log, /work-end 자동화 구축

**문제점:**

#### 문제 5: 수집(Ingest) 편중
- 4일간 로그 11건 중 ingest가 5건, update가 3건, thought가 2건, lint가 1건
- **"수집 → 정제 → 활용" 사이클에서 "활용"이 거의 없음**
- 위키를 채우는 데 집중하고, 위키를 읽고 판단하는 데는 활용하지 않는 상태

#### 문제 6: Thought 페이지 부족
- 4일간 4개 — 생각/인사이트 기록이 빈약
- 엔티티 20개에 비해 Thought 4개는 "데이터는 많고 해석은 적은" 상태
- **위키의 핵심 가치는 데이터가 아니라 데이터에서 뽑아낸 인사이트**

#### 문제 7: 업데이트 주기 기준 불명확
- dashboard.md에 "7일 이상 경과" 알림이 있지만, 어떤 페이지가 어떤 주기로 업데이트되어야 하는지 기준 없음
- me.md, strengths.md는 주 1회? 월 1회? 이벤트 기반?

#### 문제 8: obsidian-git 미설정
- data.json 없음 → 자동 백업이 작동하지 않음
- 위키 수정 내역이 git에 자동 기록되지 않아 변경 추적 불가

#### 문제 9: Notion 연동 미구현
- 설계는 완료(Obsidian=원본, Notion=모바일 창구)되었으나 실제 동기화 없음
- 모바일에서 위키 접근 불가 상태
