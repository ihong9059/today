# Second Brain Wiki - Schema

이 위키는 **나와 회사(UTTEC)**에 대한 지식 기반이다.
내부 역량과 외부 환경을 기록·연결하여, 회사의 앞날을 데이터 기반으로 판단하는 시스템.

## 목적

### 내부 역량 (안을 본다)
1. **자기 이해**: 우리의 경험, 기술, 성향, 패턴을 구조화
2. **개선점 도출**: 부족한 부분을 식별하고 해결 방향 제시

### 외부 환경 (밖을 본다)
3. **시장 이해**: 고객 니즈, 시장 트렌드, 경쟁 환경 파악
4. **사업 성과 추적**: 매출, 수주, 실패의 원인을 기록하고 패턴 발견

### 의사결정 (판단한다)
5. **방향 판단**: 내부 역량 + 외부 환경을 종합하여 사업 방향 결정
6. **복리 성장**: 모든 기록이 연결되어 점점 정확한 판단이 가능해지는 시스템

### raw/ 규칙
- 이 폴더의 파일은 **불변**이다. LLM은 읽기만 하고 절대 수정하지 않는다.
- `위시캣/`과 `작업보고서/`는 기존 폴더의 junction 링크이다. 원본은 `C:\todo\today\` 에 있다.
- 새로운 종류의 소스가 반복되면 하위 폴더를 추가한다.
- 한 폴더에 파일이 30개 이상이면 하위 분류를 검토한다.

### raw/ 추가 시 엔티티 자동 감지 (반자동)

Claude는 위키 관련 작업 시 raw/ 폴더를 스캔하여 **엔티티가 없는 raw 폴더**를 감지한다.

**감지 조건:**
- raw/ 하위에 폴더가 존재하지만 entities/에 대응하는 .md 파일이 없을 때
- 작업 시작(/work-start) 또는 위키 작업 중 자동 확인

**감지 시 행동:**
1. 사용자에게 알림: "raw/[폴더명]에 대응하는 엔티티가 없습니다. 생성할까요?"
2. 사용자 승인 시 아래 체크리스트 실행
3. 사용자 거부 시 스킵 (articles/, career/ 등 엔티티 불필요 폴더는 제외 목록에 등록)

**엔티티 불필요 폴더 (제외 목록):**
- articles/ — 스크랩 모음, 개별 엔티티 불필요
- career/ — 이력 증빙, 개별 엔티티 불필요
- projects/ — 프로젝트 원본, 개별 엔티티로 분리됨
- 작업보고서/ — 일일 보고서, 엔티티 불필요

### raw/ 추가 체크리스트

raw/에 새 폴더를 추가할 때 반드시 순서대로 수행:

1. **폴더 생성/링크**: junction 또는 실제 폴더 추가
2. **CLAUDE.md 업데이트**: 디렉토리 구조에 새 폴더 설명 추가
3. **엔티티 생성**: entities/[이름].md 작성 (프론트매터 + 핵심 요약 + 링크)
4. **상호 참조**: 관련 핵심 페이지(projects, skills 등)에 링크 추가
5. **index.md 업데이트**: 엔티티 테이블에 새 항목 추가
6. **log.md 기록**: ingest 로그 1줄 추가

## 페이지 규칙

### 프론트매터
모든 위키 페이지는 YAML 프론트매터를 포함한다:

```yaml
---
title: 페이지 제목
type: identity | skill | experience | project | goal | ai | thought | entity
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [태그1, 태그2]
links: [관련 페이지 파일명]
---
```

### 링크 규칙
- 내부 링크: `[[파일명]]` 형식 (Obsidian 호환, 확장자 `.md` 제외)
- 표시 텍스트 변경: `[[파일명|표시할 텍스트]]` 형식
- 하위 폴더 파일도 파일명만 사용: `[[2026-04-19_제목]]` (경로 불필요)
- 모든 페이지는 최소 1개 이상의 다른 페이지와 연결
- 고아 페이지 금지

### 특수 섹션

**ai-direction.md**에는 반드시 포함:
- 현재 AI 기술 트렌드 (내가 관찰한 것)
- 나의 포지션 (어디에 서 있는가)
- 기회 영역 (어디로 갈 수 있는가)
- 위험 영역 (무엇이 대체될 수 있는가)
- 판단 로그 (언제, 왜, 어떤 결정을 내렸는가)

## 워크플로우

### 수집 (Ingest)
사용자가 새로운 경험, 생각, 정보를 공유하면:
1. 해당 내용을 가장 관련 있는 기존 페이지에 통합
2. 필요시 새 페이지 생성
3. 관련 페이지들의 상호 참조 업데이트
4. index.md 업데이트
5. log.md에 기록 추가

### 해석 (Interpret) — 복리 성장 엔진
사용자가 경험, 감정, 결과를 공유하면 Claude가 **기존 위키와 연결하여 인사이트를 도출**한다.

**사용자의 역할**: 재료만 던지면 된다. 형식 없이 자유롭게.
- "오늘 이거 했어" → experience.md 또는 관련 엔티티에 반영
- "이거 실패했어" → gaps.md에 추가 + 원인 분석
- "이런 생각이 들었어" → thoughts/ 페이지 생성
- "이거 보고 결정했어" → log.md에 use 기록
- "고객이 이런 반응이었어" → 고객/시장 엔티티에 반영
- "이번 달 매출이 이만큼이야" → 사업 성과 기록
- "경쟁사가 이런 걸 하더라" → 경쟁환경 엔티티에 반영

**Claude의 역할**: 재료를 받으면 자동으로 수행.
1. 어떤 페이지에 넣을지 판단
2. 기존 내용과 연결 (A + B → C 패턴)
3. 인사이트가 보이면 thoughts/ 생성하고 사용자에게 공유
4. 행동 패턴이 보이면 me.md 업데이트 제안
5. 사업 판단에 도움되는 연결이 보이면 적극 제안
6. index.md, log.md 업데이트

**복리 인사이트 패턴**:
```
[사실 A] + [사실 B] → [새로운 판단 C] → [행동 변화 D]
```
이 패턴이 발견되면 반드시 thoughts/에 기록한다.

### 활용 (Use) — 성과 추적
위키를 참조하여 의사결정이 이루어지면 log.md에 use 로그를 남긴다:
```
## [날짜] use | 한줄 요약
- 참조: [[페이지명]]
- 판단: 무엇을 결정했는가
- 결과: (추후 기록)
```

사업 성과가 발생하면 log.md에 별도 로그를 남긴다:
```
## [날짜] revenue | 수주/매출 발생
## [날짜] lost | 수주 실패 — 원인 분석
## [날짜] market | 시장/고객 인사이트 발견
```

### 질의 (Query)
사용자가 자신에 대해 질문하면:
1. index.md에서 관련 페이지 탐색
2. 관련 페이지 읽기
3. 종합 답변 생성
4. 가치 있는 답변은 새 페이지로 위키에 저장

### 점검 (Lint)
주기적으로 확인:
- 오래된 정보 (updated 날짜 기준)
- 고아 페이지
- 모순되는 기록
- 빠진 연결
- 새로 탐색할 주제 제안

### 페이지 업데이트 주기
| 페이지 | 트리거 |
|--------|--------|
| me.md | 행동 패턴이 새로 보일 때 (2주 1회 이상) |
| strengths.md | 프로젝트 완료, 수주 성공 시 (월 1회 이상) |
| gaps.md | 이월 발생, 실패 경험 시 (주 1회 이상) |

| thoughts/ | 인사이트 발견 시 (주 2회 이상) |
| 시장/고객 엔티티 | 고객 미팅, 수주/실패, 시장 정보 입수 시 |
| 경쟁환경.md | 경쟁사 정보 발견 시 |
| 영업전략.md | 분기 1회 또는 전략 변경 시 |

### log.md 분기 아카이브 정책 (정책 결정: 2026-05-09)

log.md는 시간순 누적 파일로 사이즈가 계속 커진다. 컨텍스트 점유 부담을 막기 위해 **분기 단위로 아카이브**한다.

**트리거 (둘 중 먼저 도달하는 시점)**:
1. log.md 사이즈 ≥ **500 KB** (= 컨텍스트 약 15% 점유 시점)
2. 직전 분기 종료일 + 7일 경과 (예: Q1 종료 3/31 → 4/7 트리거)

**분리 규칙**:
- 활성 log.md = **최근 90일치만** 유지
- 90일 이상 지난 항목 = `log-archive/YYYY-QN.md`로 이동
- 파일명 예: `log-archive/2026-Q1.md`, `2026-Q2.md`, `2026-Q3.md`, `2026-Q4.md`
- 각 아카이브 파일도 동일한 프론트매터 (`type: log`, 생성일·수정일)

**분리 절차** (트리거 도달 시 사용자 확인 후 수행):
1. log.md에서 분리 대상 분기 항목 추출 (예: 2026-Q1 = 1~3월 entries)
2. `log-archive/2026-Q1.md` 생성 (없으면) — 프론트매터 + 분기별 항목
3. log.md에서 해당 항목 제거
4. log.md 상단의 `updated:` 날짜 갱신 + 분리 사실 1줄 메모
5. work-end 시 함께 commit

**Claude의 참조 패턴**:
- 일상 작업 (work-start, query): 활성 `log.md`만 읽음 (가벼움 유지)
- 과거 기록 조회: `log-archive/*.md` 중 해당 분기 파일만 선택적으로 읽음
- 시간 횡단 검색: `Grep` 도구로 `log*.md` 전체 패턴 매칭

**자동 체크**:
- `/work-end` 스킬 6단계에서 매번 사이즈 자동 측정
- 트리거 도달 시 사용자에게 알림 + 분리 작업 권고
- 트리거 미도달 시 침묵

## 판단 프레임워크

### AI 방향 판단 (ai-direction.md)
1. **대체 위험**: 내가 하는 일 중 AI가 더 잘하게 될 것은?
2. **증폭 기회**: AI를 활용해 내 능력을 10배로 만들 수 있는 곳은?
3. **유니크 가치**: AI가 대체할 수 없는 나만의 가치는?
4. **학습 우선순위**: 지금 배워야 하는 것 vs 나중에 배워도 되는 것
5. **시장 타이밍**: 어떤 기술이 지금 수요가 있고, 앞으로 수요가 생길 것인가?

### 사업 방향 판단 (영업전략.md + thoughts/)
1. **매출 구조**: 어떤 사업 라인이 매출을 만드는가? 비중은?
2. **고객 패턴**: 우리를 찾는 고객은 누구이고, 왜 선택/거절하는가?
3. **경쟁 우위**: 같은 일을 하는 경쟁자 대비 우리의 차별점은?
4. **리스크**: 1인 의존, 특정 고객 의존, 기술 변화 등 위협 요소는?
5. **투자 판단**: 시간/돈을 어디에 집중해야 6개월 후 매출이 오르는가?
