# Second Brain Wiki - Schema

이 위키는 **나 자신**에 대한 지식 기반이다.
외부 지식이 아닌, 내가 누구이고 어디로 가고 있는지를 기록하고 연결하는 시스템.

## 목적

1. **자기 이해**: 나의 경험, 기술, 성향, 패턴을 구조화
2. **방향 판단**: 특히 AI 시대에서 어떤 방향으로 가야 하는지 근거 있는 판단
3. **복리 성장**: 매 기록이 기존 지식과 연결되어 점점 풍부해지는 시스템

## 디렉토리 구조

```
second-brain/
├── CLAUDE.md          # 이 파일 (스키마/규칙)
├── index.md           # 전체 페이지 목록 + 한줄 요약
├── log.md             # 시간순 기록 (수집/질의/점검)
│
├── me.md              # 핵심 정체성 (누구인가)
├── skills.md          # 기술 스택 인벤토리
├── experience.md      # 경험 타임라인
├── projects.md        # 프로젝트 맵 (현재/과거/계획)
├── goals.md           # 목표와 방향
├── ai-landscape.md    # AI 기술 지형도 (내 관점)
├── ai-direction.md    # AI 시대 방향 판단 프레임워크
├── strengths.md       # 강점 분석
├── gaps.md            # 부족한 부분, 채워야 할 것
│
├── entities/          # 엔티티 페이지 (사람, 조직, 도구 등)
│   └── *.md
│
├── thoughts/          # 생각/인사이트/일기 페이지
│   └── *.md
│
└── raw/               # 원본 소스 (불변, LLM 읽기 전용)
    ├── 위시캣/        # 위시캣 지원서, 프로젝트 정보, 수주 이력 (→ junction)
    ├── 작업보고서/     # 일일 작업보고서 (→ junction)
    ├── projects/      # 프로젝트별 기획서, 설계서, 결과물
    ├── career/        # 이력서, 자격증, 교육 이수, 경력 증명
    ├── 영업/          # 마케팅 계획서, 경쟁사 분석, 정부지원 보고서 (→ junction)
    ├── 외벽로봇/       # 설계서, 컨셉 분석, ESP32 리서치 (→ junction)
    ├── 충전기/         # PowerDock Pro 사업계획서, 디자인 (→ junction)
    ├── ai-education-web/ # AI 교육 웹 소스 코드 (→ junction)
    ├── aiHardStudy/   # 바이브코딩 메인 저장소 48K 파일 (→ junction)
    ├── cuda/          # CUDA 6주 커리큘럼 (→ junction)
    ├── doctor/        # 의료AI, SNOMED CT, 병원 인수 (→ junction)
    ├── homepage/      # UTTEC 홈페이지 Next.js (→ junction)
    ├── revita/        # REVITA IoT 펌웨어 (→ junction)
    ├── smartFactory/  # 스마트팩토리 AI 모델/제안서 (→ junction)
    ├── tailscale/     # 장비 네트워크 가이드 (→ junction)
    ├── xerix/         # MFC Controller 제안서 (→ junction)
    └── articles/      # 인상 깊은 기사, 영상 메모, 스크랩
```

### raw/ 규칙
- 이 폴더의 파일은 **불변**이다. LLM은 읽기만 하고 절대 수정하지 않는다.
- `위시캣/`과 `작업보고서/`는 기존 폴더의 junction 링크이다. 원본은 `C:\todo\today\` 에 있다.
- 새로운 종류의 소스가 반복되면 하위 폴더를 추가한다.
- 한 폴더에 파일이 30개 이상이면 하위 분류를 검토한다.

## 페이지 규칙

### 프론트매터
모든 위키 페이지는 YAML 프론트매터를 포함한다:

```yaml
---
title: 페이지 제목
type: identity | skill | experience | project | goal | ai | thought | entity
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [태그1, 태그2]
links: [관련 페이지 파일명]
---
```

### 링크 규칙
- 내부 링크: `[[파일명]]` 형식 (Obsidian 호환, 확장자 `.md` 제외)
- 표시 텍스트 변경: `[[파일명|표시할 텍스트]]` 형식
- 하위 폴더 파일도 파일명만 사용: `[[2026-04-19_제목]]` (경로 불필요)
- 모든 페이지는 최소 1개 이상의 다른 페이지와 연결
- 고아 페이지 금지

### 특수 섹션

**ai-direction.md**에는 반드시 포함:
- 현재 AI 기술 트렌드 (내가 관찰한 것)
- 나의 포지션 (어디에 서 있는가)
- 기회 영역 (어디로 갈 수 있는가)
- 위험 영역 (무엇이 대체될 수 있는가)
- 판단 로그 (언제, 왜, 어떤 결정을 내렸는가)

## 워크플로우

### 수집 (Ingest)
사용자가 새로운 경험, 생각, 정보를 공유하면:
1. 해당 내용을 가장 관련 있는 기존 페이지에 통합
2. 필요시 새 페이지 생성
3. 관련 페이지들의 상호 참조 업데이트
4. index.md 업데이트
5. log.md에 기록 추가

### 질의 (Query)
사용자가 자신에 대해 질문하면:
1. index.md에서 관련 페이지 탐색
2. 관련 페이지 읽기
3. 종합 답변 생성
4. 가치 있는 답변은 새 페이지로 위키에 저장

### 점검 (Lint)
주기적으로 확인:
- 오래된 정보 (updated 날짜 기준)
- 고아 페이지
- 모순되는 기록
- 빠진 연결
- 새로 탐색할 주제 제안

## AI 방향 판단 프레임워크

ai-direction.md를 업데이트할 때 다음 질문을 기준으로:

1. **대체 위험**: 내가 하는 일 중 AI가 더 잘하게 될 것은?
2. **증폭 기회**: AI를 활용해 내 능력을 10배로 만들 수 있는 곳은?
3. **유니크 가치**: AI가 대체할 수 없는 나만의 가치는?
4. **학습 우선순위**: 지금 배워야 하는 것 vs 나중에 배워도 되는 것
5. **시장 타이밍**: 어떤 기술이 지금 수요가 있고, 앞으로 수요가 생길 것인가?
