# 자산 인덱스 완전성 함정 — 사용자 검증 cascade의 가치

## 한 줄 정의

본 vault + myWiki 자산 인덱스는 **자가 검증으로 완전성 보장 안 됨**. 사용자 직접 지적 cascade 없이 자산 누락이 검출되지 않는 1인 운영 second-brain 시스템의 구조적 한계.

## 사건 — 5/20 + 5/21 cascade 2건 연속

| 날짜 | 누락 자산 | 발견 방식 | myWiki 박제 결과 |
|---|---|---|---|
| 5/20 | 정부 R&D 1억 PLC 4축 GMC (2016~2017, 99.1% 집행률, 특허 10-2017-0138381, 기업부설연구소 C0442235) | 사용자 PDF 직접 제공 | [[정부R&D실증사업]] entity 신설 (Tier 3 정부 R&D 입찰 표준 패턴 1순위 자산) |
| 5/21 | nRF52832 USB 시리얼 (USB CDC ACM) + 연동 모바일 앱 수년간 양산 | 사용자 직접 지적 ("수년간 nRF52832를 통하여 USB 시리얼 통신을 구현해 왔고…") | [[skills]] 행 신설 + [[strengths]] § 7 통신 프로토콜 7종→8종 + [[experience]] 박제 |

## 함정의 본질

```
[사실 A] 사용자 머릿속 자산 (38년 임베디드 경력)
     ≠
[사실 B] 본 vault 인덱스 (skills/strengths/experience/entities)
     ↓
[함정 C] Claude는 인덱스만 보고 자산 평가 → 인덱스에 없으면 "없는 자산"으로 단정
     ↓
[누락 사고 D] 매칭 못한 자산을 "솔직 약점"으로 잘못 기재 → 위시캣 지원서에 노출됨
     ↓
[사용자 cascade] 직접 지적으로 정정 강제 → vault 박제 → 다음 작업에 반영
```

## 왜 자가 검증으로 안 보이나

1. **인덱스 = 박제된 것만 존재** — 사용자가 박제 안 하면 vault 모름. 박제 시점 ↔ 매칭 필요 시점 사이 비대칭
2. **vault 갱신 트리거 부재** — 위시캣 지원서 작성처럼 직접 매출에 영향 주는 시점에만 결락이 노출됨. 사용자가 평소에는 vault를 능동 검증하지 않음
3. **Claude 보수적 작성 = 약점 단정 가속** — "직접 양산 없음"으로 일찌감치 단정 → 사용자 정정 cascade 발생 → 박제 순환
4. **38년 경력의 누적 자산 > 38일 vault 운영** — vault 운영 기간이 짧을수록 누락 비율 증가. 본 vault 38일째 (4/19 시작)

## 동일 패턴 발견 — 사용자 cascade는 다른 영역에서도 반복 중

- 5/12 한림용인CC 1,000만 골프장 매출 직전 프로젝트 → today/ 폴더 생성 2일간 myWiki entity 미신설 → 사용자 지적 후 흡수
- 5/19 lemonLabs 6/12 폴더 → 1.5개월 지연 사업 2건 발견 → mywiki 발견 카드 발송
- 5/20 정부 R&D 1억 → 사용자 PDF 제공으로 발견
- 5/21 USB 시리얼 → 사용자 직접 지적

**= 한 달 안 4건 cascade. 분기당 ~12건 추정**. 자산 인덱스의 자가 완전성 결함은 본 vault 운영 한계의 1순위 부채.

## 회피 전략

### 단기 (즉시)

- **룰 3 (위시캣)** — `wishketProject memory/feedback_check_user_assets_before_weakness.md`. 약점 단정 전 사용자 confirm 강제
- **grep 자가 검증 SOP** — 작성 직후 내부 메타 표현 0 hit 통과
- **work-start § 1-C** — 외부 vault 카드 1장이라도 있으면 다음 prompt 디폴트 = 흡수 (사용자 cascade 우선)

### 중기 (워크플로우 신설)

- **work-end 정기 자산 점검 SOP 신설** — 영업 영역별 자산 자동 인벤토리. USB 시리얼 / 산업 통신 / 영상 / AI / 모바일 / 풀스택 / 정부 R&D 등 카테고리별 vault 현황 표를 4주 1회 출력하여 사용자 검증 트리거
- **wishket-apply 스킬 단계 추가** — 모집 자격 매칭 시 약점 명시 전 사용자 confirm 단계 삽입 (Claude 자동화 → 사용자 broker 1회)
- **interview-style 자산 sweep** — 영업 영역별 사용자 직접 인터뷰 (한 영역당 30분, 분기 1회)로 머릿속 자산 → vault 박제 강제

### 장기 (구조 개선)

- **second-brain 운영 패턴 = N 단계 진화**: 박제(현재) → 자가 검증 sweep → 사용자 interview sweep → cross-vault 자동 매칭. 현재 1단계, 2단계 도입 시점은 자산 누락 cascade 분기 ≥ 12건 도달 시 자동 트리거

## 강사양성·obsidian 시리즈 강의 직접 자산 ⭐

본 함정 패턴은 **1인 운영 second-brain 시스템 한계 사례**로 강의 자산화 가치 높음:

- **모범 메시지**: "second-brain은 자가 검증으로 완전성 보장 안 됨. 사용자 직접 검증 cascade가 매번 박제를 보강한다"
- **모범 사례**: 5/20 정부 R&D + 5/21 USB 시리얼 cascade 2건 (실제 본 vault 사건)
- **모범 도구**: 룰 3 (약점 단정 전 사용자 confirm) + grep 자가 검증 SOP + work-end 정기 점검
- **수강생 워크플로우**: 본 vault의 함정 사례를 그대로 시연 → 수강생 자신의 vault에서도 같은 함정 식별 → 회피 패턴 박제

→ obsidian 시리즈 별도 단기 모듈(2~3h)에 § "자산 인덱스 완전성 함정" 추가. 호오컨설팅·인프런·디지털배움터 차별화 자산 가치.

```
[5/20 정부 R&D 누락] + [5/21 USB 시리얼 누락]
     →
```
