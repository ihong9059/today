# 단일 펌웨어 + BLE 현장 프로비저닝 = 양산·현장 배포 비용 최소화

2026-06-19 _inbox 흡수 (lora-claude 카드 2장: 06-18 통합펌웨어+BLE프로비저닝 / 06-19 2.4G하이브리드+E22스니핑한계)에서 도출된 사업 패턴.

## 복리 인사이트 패턴

```
[사실 A: 통합 펌웨어 1개 — 부팅 시 NVS role 분기, 보드별 재빌드 0]
        +
[사실 B: BLE 프로비저닝 — 폰 앱이 GATT로 role+address 주입, 비전문가도 설정]
        ↓
[판단 C: "보드 1종 굽고 앱으로 역할 지정" = 양산 SKU 1개 + 시공 인건비 절감]
        ↓
[행동 D: UTTEC LoRa 제어망 양산 표준 배포 모델로 채택 → 한림 외 SI·공장 자동화 전 현장 재사용]
```

## A — 단일 binary 통합 펌웨어

- 중계기·sensor·on/off 3역할을 **1개 펌웨어**에 통합, 부팅 시 NVS의 role 읽어 분기. 보드별 재빌드 0.
- nRF52832에 **BLE+NVS+LoRa 통합 빌드 적합** 실증 (FLASH 27.6% · RAM 66.1% — 여유 충분).
- 효과: 펌웨어 SKU 1개 = 재고·빌드·flash 관리 비용 최소화. 양산 라인 단순화.

## B — BLE 현장 프로비저닝

- 스마트폰 앱(Native Android Kotlin, SM-M536S end-to-end 실증)이 BLE GATT로 role+address 주입.
- 기존 LoRa addr-set(동시충돌 함정) 폐기 → 현장 **비전문가도 폰 앱으로** 노드 설정.
- 효과: 시공 인건비 절감 + 설정 오류 감소.

## C → D — 사업적 함의

- **양산·현장 배포 비용 최소화** = 가격 경쟁력 + 시공 인건비 절감 narrative ([[ai-direction]] § 결정 54).
- 한림 최종 아키텍처 3패턴(intra-relay 2단 중계 / ACK-도청 명령전달 / 로컬 자율제어 우선)은 **밀폐 설비 내 액추에이터 제어**(공장 자동화) 그대로 재사용 → [[factory]] narrative 직결.
- 교육 자산: "보드 1종 + 앱 설정" 양산 모델 = [[uttec-academy]] 스마트팩토리 실습 커리큘럼 사례화 가능.

## 역량경계 (반드시 함께 carry) ⚠️

매칭 패턴을 영업에 쓸 때 **과대약속 방지** 위해 두 경계를 항상 동반한다:

1. **2.4G ESB 하이브리드는 근거리·약장애물 한정** — nRF52832 2.4G는 900M LoRa比 폐쇄공간 투과 ~30dB 불리(Coded PHY 미지원·TX +4dBm). 장거리·강투과는 sub-GHz LoRa. 채택 전 현장 2.4G RSSI 실측 필수. ([[gaps]] § 2026-06-19)
2. **E22 = generic SX126x로 디코드 불가** — E22망 스니핑·게이트웨이·멀티벤더 상호운용은 E22 모듈로만 보장 = 벤더 락인. "같은 칩=호환" 거짓.
