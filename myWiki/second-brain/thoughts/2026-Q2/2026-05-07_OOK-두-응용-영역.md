# OOK 두 응용 영역 — 통신 프로토콜 포팅 사업 라인의 발견

## 발견의 흐름 — A + B → C → D

### 사실 A — REVITA OOK Replay (2026-04-27 ~ 2026-05-01)
[[revita]] 프로젝트에서 CC1101 트랜시버로 **외부 기기의 OOK 신호 캡처 → 디코딩 → 재현** 시스템을 1주 내 완성.
- 447.925 MHz Sub-GHz 공중파
- 10버튼 코드 디코딩 + ON/OFF 재현
- nRF52840 + Zephyr RTOS, SPI 드라이버 커스텀 작성

### 사실 B — AISG 3.0 PHY 분석 (2026-05-07)
[[위시캣활동]] #155057 공고 사전 학습에서 [[aisg]] 프로토콜 분석. PHY 옵션 중 하나가 **2.176 MHz OOK 변조를 RF 피더 케이블에 Bias-T로 주입**하는 in-band 통신.
- 안테나 라인 디바이스(ALD) 원격 제어용 국제 표준
- 별도 케이블 불필요, RF 케이블 위에 디지털 신호 실음
- 동일한 OOK 변조 원리, 다른 응용 영역

### 새로운 판단 C — "OOK 변조의 두 응용 영역 모두에 실전 경험 보유"
일반적으로 OOK는 둘 중 하나의 응용에만 익숙한 경우가 많다.
- **공중파 RF**: 리모컨 복제, ISM 대역 IoT (CC1101, RFM69 등)
- **In-band on RF feeder**: 안테나 인터페이스, 기지국 ALD (AISG, 일부 케이블 모뎀)

이 둘을 모두 직접 구현/분석한 경험은 희소하다. 사용자는 1주 시차로 두 영역 모두 손에 잡았다.

여기에 기존 자산을 더하면:

```
RS-485 Modbus RTU 양산 (KC 인증)
  + BLE Mesh 양산 (3,800대 일본 수출)
  + LoRa 상용화 (국내 최초, 2018)
  + EtherCAT 양산 (산업용)
  + CAN (대한전선 WINDER)
  + OOK 공중파 RF (REVITA, CC1101 447.925MHz, 2026-05)
  + OOK in-band on RF feeder (AISG 분석 완료, 2026-05)
```

→ **통신 프로토콜 7종 직접 경험** = "통신 프로토콜 포팅·컨설팅" 사업 라인의 잠재력.

3. **회사소개 격상**: "통신 프로토콜 4종"에서 "통신 프로토콜 7종 (양산 5 + 직접 구현 1 + 분석 완료 1)"

## 위키 패턴 — "second-brain이 영업 자산을 발견한다"

본 인사이트가 도출된 메커니즘 자체가 의미 있다:

```
[raw 작업 A: REVITA OOK Replay 4/27~5/1]
   ↓ second-brain ingest 1줄만 (revita.md), log.md 별도 ingest 누락
[raw 작업 B: 위시캣 #155057 지원서 5/7]  ← OOK 누락 상태로 작성
   ↓ 사용자 질문 "wiki에 OOK 있나?"
[연결 발견] A의 자산이 B에 누락됨을 발견 — 매칭률 9/10 셀프 디스카운트
   ↓
[영업 자산 보강] 지원서 9/10 → 11/11
   ↓
[새 사업 라인 발견] 통신 프로토콜 포팅 (본 페이지)
```

### 교훈
- **위키가 없었으면 평생 9/10으로 셀프 디스카운트했을 것.** AISG 매칭률 셀프 디스카운트(9/10) 발견은 위키 단순 검색의 결과.
- **raw 작업이 second-brain entity로 정리되지 않으면 영업에 반영되지 않음** → ingest 누락 비용은 매우 큼.
- **향후 모든 위시캣 지원서는 myWiki 검색 후 작성하는 워크플로우 정착 필요** — `/wishket-apply` 스킬에 myWiki 검색 단계 추가 검토.
