# 제품별 vault 통합 패턴

> 한 제품의 기술 검증 + 비즈니스 운영을 같은 vault에서 추적하면 cross-link 비용이 사라진다. 별도 git repo + multi-agent Claude를 결합하면 부수 효과로 권한 격리 + 자동 흡수까지 얻는다.

## 발견 경로

| 시점 | 사실 |
|---|---|
| 2026-04-22 | revita 패턴: `C:\todo\revitaProject\` 별도 private repo + `application/revitaWiki/` 자체 ingest 사이클 — 한 제품의 기술+비즈니스 한 곳에서 운영 |
| 2026-05-05 ~ 5/7 | uttecBizWiki 신설 (AI FanStick + Stage 4 비즈니스 전용 vault) — myWiki 안에 거주, onDevice_AI vault(기술 검증)와 분리. cross-link 비용 발생 시작. 1주간 컨텐츠 0에 가까운 정전 상태 |
| 2026-05-12 | multi-agent 시스템 도입 (mywiki-claude + revita-claude `_inbox/PROTOCOL.md`) — Claude 협업이 사용자 broker 없이 가능 |
| 2026-05-15 | 동시 3건 인프라 변경: onDevice_AI repo 분리 (today → /todo, private) + uttecBizWiki 흡수 (`business/` 폴더) + multi-agent 합류 (ondevice-claude). **revita 패턴의 두 번째 검증 사례** |

## 패턴의 핵심

**1 제품 → 1 vault → 1 repo → 1 Claude 식별자** 동치.

```
revita (5/15 이전부터): revitaProject/ (private repo) ↔ revita-claude
onDevice (5/15 신규):   /todo/onDevice_AI/ (private repo) ↔ ondevice-claude
공통 허브: today/myWiki/ ↔ mywiki-claude (학습/도구/범 사업)
```

## 부수 효과 (한 결정에서 4개 가치)

1. **cross-link 비용 0**: 기술 검증 ↔ 영업 자산이 같은 vault → 별도 vault 간 link 유지 부담 사라짐 (uttecBizWiki 정전 원인 = link 부담)
2. **권한 격리**: private repo로 외부 공개 차단 (영업 단가·고객 명단·검증 노하우)
3. **자동 흡수**: multi-agent inbox 카드로 myWiki에 흡수 자동화 (사용자 broker 부담 0)
4. **확장성**: 새 제품 라인 등장 시 동일 패턴 복제. 3 Claude → 4·5·N Claude 확장 동일 방식

## A + B → C 인사이트

- **A (사실)**: revita는 1 제품 = 1 vault = 1 repo로 1년 이상 정상 운영
- **B (사실)**: uttecBizWiki는 1 제품을 2 vault로 분리하여 1주 만에 정전 (cross-link 부담)
- **C (판단)**: 통합 비용 < 분리 비용 — 제품 단위로 통합한다. revita가 우연이 아니라 검증된 모델

## 적용 후 행동 변화 (D)

- onDevice_AI 5/15부터 한 vault에서 검증→영업→수주 한 줄로 운영
- 향후 신규 제품(가령 한림용인CC 무선제어 솔루션, AISG, whybiz Tracker, smartFactory MES 등) 본격 사업화 시 **별도 vault + repo + Claude 식별자**로 분리 결정 1순위
- myWiki는 학습/도구/범 사업/제품 미정 영역만 책임 — 더 가벼워짐
