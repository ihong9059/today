# 적정 복잡도 라이프사이클 3부작

> revita-claude ingest #18~#23 (2026-07-05 흡수)에서 도출. SBC↔MCU 통신 설계가 3차 정정되는 서사 속에서, "얼마나 복잡해야 적정한가"의 **양방향 경계**가 리소스 라이프사이클 3축으로 완성됐다.

## A + B + C → 판단 프레임워크

세 개의 독립 ingest가 우연히 하나의 축을 그렸다. 각각은 반대 방향의 실패를 경고한다.

| 축 | ingest | 실패 모드 | 교훈 | 경계 |
|---|:-:|---|---|---|
| **생성** | #20 | 필요 없는 세션/상태기계로 단순 transport를 과설계 | 제약(전원손실·손실링크·안전)이 **없으면** 세션 걷고 transport에 위임 | 과설계 |
| **구조** | #22 | 공유 물리 자원을 "가상 채널" 추상화로 숨김 | 공유 자원이 있으면 추상화 말고 **소유권(handoff)을 명시** 설계 | 과추상화 |
| **소멸** | #23 | 종료를 원자적 이벤트로 취급해 잔여 데이터 유실 | 획득의 **역순**으로, 각 단계 완료를 확인하며 풀어라 | 무순서 종료 |

## 각 축의 실체

### #20 생성 — "제약이 있을 때만 세션"

OTA 트리거를 GW/웹 CREATE 세션 오케스트레이션에서 **reset 하나**로 단순화. coproc no-ACK + QoS0 + reset 트리거 = 제약이 약한 구간은 세션형 상태기계를 걷어내고 transport(MQTT/물리 reset)에 위임. 세션형은 상태기계라서 비용이 크다 — 전원손실·손실링크·안전 요구가 실재할 때만 값을 한다.

### #22 구조 — "물리 자원의 배타성을 먼저 확인하라"

#19에서 채택한 coproc-MQTT(SBC가 `t/{id}/d`에 `src=0xC000`로 MCU 지휘)는 논리적으로 우아했다. 그러나 **RM76 LTE 모뎀이 물리적으로 1개**. SBC가 모뎀을 잡으면 MCU는 자기 MQTT로 아무것도 못 한다. "같은 토픽 + src 구분"이라는 깔끔한 추상화가 하드웨어 공유 제약 앞에서 무너졌다. 해법은 추상화가 아니라 **자원 handoff**(MCU UART ↔ SBC USB host 배타 점유) + 로컬 USB relay. 실증 없이 전제 재검토만으로 자기 설계를 기각한 **자기정정**이 핵심.

### #23 소멸 — "종료는 순서 있는 프로토콜"

relay OFF와 전원 OFF를 한 이벤트로 묶으면 LTE TX ring의 상행 PDU가 flush 전에 링크가 끊겨 조용히 유실된다. 2단계로 분해: `relay_stop`(drain 검증→미완이면 5V 유지한 채 soft 재시도)→`relay_stopped` ACK→`shutdown`. **graceful teardown = 뒤집힌 부팅 시퀀스**이며, 각 계층이 아래 계층에게 "비웠다"는 확인을 받아야 한다.

## 왜 이게 자산인가

- **AI 시대 유니크 가치**: LLM은 코드를 빠르게 쓰지만, "적정 복잡도 판단 / 물리 제약 직시 / 안전 종료 순서"는 사람의 엔지니어링 판단 영역이다. 대체 난이도가 높다 → [[ai-direction]] § 결정 57.
- **강의·컨설팅·포트폴리오 사례연구 1급**: 세 사례 모두 "코드는 됐는데 왜 안 되는가"의 실전 서사 → [[strengths]] §22.
- **자기정정 성숙도**: sunk cost 없이 아키텍처를 되돌리는 것 자체가 시니어 신호. #19→#22의 회귀는 후퇴가 아니라 성숙.
