# 위시캣 요구사항 중심 + 2축 포트폴리오

> wishket-claude 카드 3장 (§4-A 전환 06-19 + 포트폴리오 v2 07-01 + #156394 직접연락 07-03, 2026-07-05 흡수).

## 담당자 한마디가 바꾼 방법론

위시캣 담당자 직접 피드백: *"요구사항에 맞게 더 상세히, 요구사항에 초점. 많이 한 것 나열 금지."*

이 한마디가 지원서 문법을 뒤집었다.

| 기존 (자산 나열형) | 전환 §4-A (요구사항 중심형) |
|---|---|
| "우리가 한 모든 것" 카탈로그 [O] 체크 | 목차 = 클라이언트 요구사항 |
| 자산 많음 = 강함 | 요구마다 "어떻게 풀지 + 직결 실적 1건 + 수치" |
| 무관 자산도 포함 | 무관 자산 생략, 난도 높은 영역에 분량 집중 |

**통찰**: 클라이언트는 "당신이 뭘 했나"가 아니라 "내 문제를 풀 수 있나"를 본다. 자산 나열은 클라이언트에게 매핑 노동을 떠넘긴다. §4-A는 그 매핑을 우리가 대신 해서 정조준한다.

## 포트폴리오 2축 — 같은 실적, 두 진입점

- `by-domain/` — "이 분야를 해봤다" 증명 (임베디드/무선/산업자동화/IoT+클라우드/센서·조명/AI/모바일)
- `by-requirement/` — "당신 문제를 이렇게 푼다" 설득 (§4-A와 동일 문법)

지원서 §4-A ↔ 포트폴리오 by-requirement가 **동일 문법**("요구→해결→증거")으로 정렬 = 영업 카피 일관성. 모바일앱·AWS 자산까지 발굴해 편입(v1 6편에 누락됐던 것).

## push → pull 전환 신호

#156394(차량용 온도·GPS 텔레매틱스 HW/FW 개량+양산)는 위시캣이 **사용자에게 직접 연락**한 이례적 강매칭. nRF52 BLE 온도 양산 자산과 사실상 동일 계열.

**의미**: 우리가 지원서를 던지는 push 영업에서, 축적된 프로필·포트폴리오가 **역방향 리드(직접 연락)를 만드는 pull** 단계로 진입하는 신호. 이 전환이 반복되면 영업 구조 자체가 바뀐다 → 모니터링 가치.
