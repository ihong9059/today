# 공용 시스템 보드 = 단일 HW 플랫폼이 만드는 횡단 자산

> 흡수: lora-claude 카드 `2026-07-08-001` (공용 시스템 보드 = 수조+조명 단일 HW). [[ai-direction]] § 결정 60.

## A + B → C

- **사실 A** (한림 수조제어): LoRa(E22-900T22D) + power on/off 릴레이 + nRF52832 제어로 원거리 pump 자율 제어망을 양산 검증 ([[한림용인cc-고가수조]]).
- **사실 B** (LoRa 조명제어): 골프장 야간 조명 순차 off 절전 시스템도 결국 **power on/off 릴레이**를 LoRa로 원격 제어하는 동일 뼈대.
- **판단 C**: 수조·조명·shield(RS485/MESH)·revita가 **모두 "LoRa + 릴레이 제어"** 공통 뼈대 → 응용마다 보드를 새로 설계할 이유가 없다. `LoRa + 릴레이 + nRF52832 + 2.4G ESB` **고정 코어** + 선택 실장(RS485 수위센서·PIR·솔라/AC220V·RTC·INA219) 매트릭스 = **공용 시스템 보드**가 여러 응용을 하나로 커버하는 횡단 자산.

## 행동 변화 D — 영업·양산 narrative

- **영업 강점**: 골프장 대상 2개 시스템(원거리 수조 자동제어 + 야간 조명 순차 off)이 **동일 HW 플랫폼** 위에 올라감 → 제안서·presentation에서 "**단일 공용 플랫폼**"을 강점으로 명시. 고객 입장 = 한 벤더·한 보드·한 유지보수 체계.
- **원가 구조**: 보드 1종 + 펌웨어 1개화([[ai-direction]] 결정 54 통합 펌웨어) + 재고 통합 = **개발·재고·양산 3중 원가 절감** → 다현장·다응용 배포 가격 경쟁력.
- **제품 라인 통합**: 밸브·팬 등 확장도 같은 코어에 선택 실장으로 흡수 → SKU 폭발 없이 응용 확장.

## 정직 고지 — HW 공유 ≠ 로직 공유 (미결)

공용 보드는 **하드웨어**를 공유하지만 **제어논리는 공유 못 한다** ([[gaps]] § 2026-07-09):

- **fail-safe 반대**: 수조 = 무수신 시 OFF(월류 방지)가 안전 / 조명 = 재실 중 OFF 금지(인적사고)가 안전 → **PIR 재실감지 결합** 필요 (설계 미착수).
- **AC 220V 안전**: 조명은 릴레이 opto 절연·정격·연면거리 요구가 pump보다 강함.
- 현 시점 = reference block diagram 단계. 부품선정·회로·양산 미착수.

## 사업 소관 판단

조명 응용은 신규 도메인이나 이미 **골프장 LoRa 영업 트랙의 두 번째 시스템**으로 진행 중 → 별도 vault 신설 없이 현 골프장 LoRa 영업 트랙 내 하위 시스템으로 유지. 공용 보드가 수조와 HW를 공유하므로 도메인 분리 실익 없음(양산·회로 착수 시 재검토).
