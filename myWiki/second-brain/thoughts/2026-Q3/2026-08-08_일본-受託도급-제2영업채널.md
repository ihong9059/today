# 일본 受託(도급) = 위시캣 도급 모델의 해외 복제

## 복리 인사이트

```
[사실 A] 위시캣 = 도급(외주) 벤더로 프로젝트 통째 수주 = 본 팀 검증된 수주 모델
[사실 B] 일본 임베디드 외주 = 受託開発(도급)형이 위시캣과 동형 (이랜서 일본은 파견형 = 부적합)
[사실 C] 본 팀 = 임호균 파나소닉·비즈니스 일본어 + 홍광선 TELEC 5종·일본 3,800대 수출 트랙레코드
→ [판단 D] 위시캣에서 통하는 도급 수주 문법을 그대로 일본 受託 채널에 이식 = 제2 영업 채널
→ [행동 E] 5社 발송본 + 일본어 랜딩(라이브 URL) 준비 완료 → 발송 → 회신 시 파이프라인 편입
```

## 왜 중요한가 — 채널 다변화

지금까지 UTTEC 영업 파이프라인은 **국내 위시캣 단일 채널** 의존. 단일 채널은 매칭 빈도(2~4시간 검색당 강매칭 0~2건)에 매출이 종속. 일본 受託 채널은 **같은 도급 문법 + 이미 보유한 일본 자산(양산·언어·인증)** 으로 진입 비용이 낮은 제2 채널. → [[영업전략]] 리스크(단일 채널 의존) 완화.

## 핵심 구분 — 파견형 ❌ vs 도급형 ✅

- **이랜서 일본** = 소프트뱅크·N사·F사 DX에 한국 IT 인력 **월단가 파견**. SI/DX·웹·클라우드만, 임베디드/HW 없음. 상주·파견 = 본 팀 도급·비상주 원칙과 이중 불일치.
- **受託開発(도급)** = 발주자가 프로젝트를 벤더에 통째 위탁. イプロス(제조 B2B 매칭) 발주자 직결 1순위. 外部CTO.com·WTI·Cirlution = 본 팀 업무를 일본 도급으로 수행 中 = 벤치마크.

→ **"일본의 위시캣 같은 곳"을 찾을 때 파견 플랫폼과 도급 매칭을 구분**하는 것이 첫 관문. 플랫폼 형태(파견 vs 도급)가 본 팀 원칙과의 정합을 결정.

## 실행 gotcha — 문의폼 PDF 첨부 불가

일본 문의폼 다수가 PDF 첨부 불가 → **라이브 랜딩 URL이 소개자료 대체 채널로 결정적**. 한국식 "발송킷=PDF" 전제가 무효. PDF는 회신 후 2단계 첨부. → [[gaps]] § 2026-08-07.
