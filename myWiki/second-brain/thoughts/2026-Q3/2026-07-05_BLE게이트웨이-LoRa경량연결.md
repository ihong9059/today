# BLE 게이트웨이로 LoRa망 경량 연결

> lora-claude 카드 2장 (BLE↔LoRa 브리지 06-19 + 2.4G ESB dual-radio 06-20, 2026-07-05 흡수). 게이트웨이 하드웨어를 가볍게 만드는 두 갈래.

## 인사이트 — 게이트웨이에서 "전용 하드웨어"를 뺀다

전통적 LoRa 게이트웨이는 RPi에 LoRa HAT/USB 모뎀을 직결한다. 두 카드가 각각 다른 각도로 이 전용 하드웨어 의존을 제거한다.

### 갈래 1 — BLE↔LoRa 브리지 (게이트웨이 무선화)

master 노드(nRF52832+E22)가 **BLE peripheral + LoRa 동시 상시 동작**하며 8B frame을 투명 중계. RPi는 내장 BLE central(bleak)로 구독만 한다.

```
sensor → LoRa/E22 → master(BLE peripheral) → BLE → RPi(bleak) → web
                                    ↑ 역방향 명령도 동일 경로
```

- **핵심**: 게이트웨이(RPi·폰·PC)는 대부분 BLE를 내장한다 → LoRa 모뎀 USB 직결·전용 HAT 없이 기존 LoRa 단말을 그대로 재사용해 monitor/control 게이트웨이를 구성.
- **재사용**: 공장 자동화·다현장 monitor에 그대로. revita 타워 LoRa GW relay와 동일 게이트웨이 도메인.

### 갈래 2 — dual-radio 노드 (2.4G 로컬 + 920M 상위)

한 노드가 LoRa(920M 본부 장거리) + 2.4G ESB(온칩 로컬)를 겸용. 로컬 단말이 본부에 직접 못 닿는 환경(폐쇄공간·간섭분리·산악 골프장)에서 로컬은 2.4G, 상위는 LoRa.

- nRF52832에서 BLE Coded PHY 없이 장거리 확보하는 유일 경로 = **ESB 250kbps**(감도 −104dBm, 1Mbps 대비 +8dB).
- group별 채널·주소 파생 → 다중 group 무간섭.

## 재사용 시 함정 (박제)

- BLE를 끈 채(`bt_disable`) 쓰면 안 됨 — E22 루프와 **동시 상시 동작** 필요.
- RPi BLE 기본 RF-kill 차단(unblock+up) / 브리지에 RTT 붙였다 떼면 nRF halt / **Chrome은 link-local(169.254) 접속 불가 → 직결망 일반 사설IP 필수**.
- ESB와 BLE컨트롤러(MPSL)는 한 이미지 공존 불가 → **2-이미지 패턴**(BLE판 provisioning + ESB판 운영, NVS 보존 reflash). 통합펌웨어 06-18 BLE 프로비저닝과 정합.
- nRF52832 250kbps는 ESB auto-ACK 비대칭 실패 → 양방향 독립송신(noack)+시분할 우회.
