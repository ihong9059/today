[[onDevice-ai|onDevice_AI]] 역할분담상 실기·기술 정본은 그쪽이나, 이 작업은 **교육 프로그램 실기검증**이라 academy 소관(실험 주체도 academy log).

### ① micro:bit v2 실물 입고 + 검증 (입고 = 입문 과정 1순위 critical path 해소)

- 이 PC USB 연결 — **board ID 9906 = micro:bit v2.21**(타겟 nRF52833, 인터페이스칩 nRF52820), 드라이브 `F:`, 시리얼 **COM30 @115200**, DAPLink v0257, WebUSB ✅. `uflash`→F:\micropython.hex, self-test(display+시리얼+버튼) PASS.
- ⚠️ kit 확정은 11-03 "**micro:bit v2.0 단독**"이었으나 실입수품은 **v2.21** — 교육 kit 사양 메모는 v2.21 기준으로 업데이트 필요(동일 nRF52833, 영향 경미).

### ② BLE 제스처 시스템 — Phase 0~3 E2E 동작 ✅ (RAK3172 제스처를 micro:bit로 재현)

- 설계 3종(사용자 결정): **추론=칩 자체(진짜 onDevice) / 학습=PC 로컬 / 링크=BLE(UART Service 커스텀)**. 🚨 MicroPython BLE 미지원 → 펌웨어=**MakeCode(Bluetooth)**, PC측=**bleak**.
- **Phase 0**(BLE 링크): `BBC micro:bit` 페어링 없이 연결·수신 성공. 🔑 실측 GATT = 송신 char `6e400002`가 **indicate(notify 아님)** / 처리량 **~11Hz**(indicate 오버헤드) → Phase 1을 ~25Hz·~1초 창으로 재설계.
- **Phase 1·2**(수집·학습): 수집 **250창**(idle/shake_x/shake_y/wave_z/circle 각 50), PC 로컬 학습(sklearn·torch 없이) → MLP(은닉24)+StandardScaler 1층 융합, **홀드아웃 98.0%** + 융합 forward↔sklearn 250/250 일치.
- ⭐ **설계판단 — INT8 불필요**: micro:bit는 nRF52833 **FPU + MakeCode float** → RAK3172(C/메모리 제약으로 INT8 필수)와 달리 **float 칩 추론으로 단순화**. "AI의 일생"(수집→학습→INT8→칩) 교육 서사에서 입문 과정은 INT8 단계를 생략 가능 = 난이도 하향, 입문 적합성 ↑.
- **Phase 3**(칩 추론): 추론 펌웨어(가중치+BLE+슬라이딩윈도 20샘플~90ms+classify) **E2E 동작 ✅**(칩 분류→BLE→web 실시간, 정지=idle 정확). 🔄 live 정확도 튜닝 중 — 흔들림 반환점마다 순간 idle로 떨어짐·wave_z↔circle 혼동. 사용자 통찰 "더 오래 보고 판단"=시간평활 → **motion-gated**(비-idle ≥30%면 우세 동작) 적용했으나 BLE 재연결 막혀 미검증. 🚨 gotcha = BLE 서버 강제 kill→stale 연결·WinError(보드 리셋이 복구).

### ③ 교육 자산 — v2.21 회로도 박제 + 배터리 4.5V 유령전압 규명

- 공식 오픈HW V2.21 회로도+BOM 박제(`참고자료_하드웨어/microbit_v2.21/`). 배터리 단자 측정 **4.5V = 유령전압**(USB 5V→BAT60 쇼트키 OR→공통노드, 역방향 BAT60 차단·테스터 10MΩ 역누설이 비추는 값, 1kΩ 부하 시 ~0V 붕괴 = 고장 아님). V2는 배터리도 NCP114(입력 max 5.5V) 경유라 4.2V 입력 안전(과방전 미보호 → protected 셀 권장). → "측정값을 회로로 설명"하는 입문 교육 분석 사례.
