## Day 5 비교 사례 모듈 자산 — Round 17·18·18후속·19 vendor 광고 vs 실측 격차 ⭐⭐⭐ (2026-05-22 cascade + 야간 후속)

5/22 ondevice-claude Round 17·18·18후속·19 cascade 흡수로 **Day 5 통합 프로젝트 영역의 비교 사례 모듈 1순위 자산** 확보. 본 모듈은 첫 시범 코스 Day 5의 "통합 프로젝트 + 평가" 시간 중 약 **75~120분** 분량으로 삽입 가능 (야간 후속으로 RAM tier 4번째 조건 + Nordic 함정 11건 추가 → 30분 추가).

### 모듈 컨셉 — "벤치마크 우선 원칙 + 4조건 곱"

**제목**: "AI 가속 칩, 광고 카피 신뢰 X — 4조건 곱 + 벤치마크가 답이다"

**메시지**: vendor TOPS 광고는 best-case 기준. 실제 application class 와 다르면 가속이 손해로 뒤집힘. **AI 가속 = ISA × workload × 메모리 계층 × RAM tier 4조건 곱** 검증이 본질. "AI 응용 ≠ MCU 라벨" — vendor "supports neural network frameworks" 광고는 toolchain·library 호환만 검증, 실제 RAM 적합도는 sweep 측정 필수.

### 4사례 종합 비교 (정량 측정 데이터, 5/22 야간 후속 4번째 사례 추가)

| 사례 | vendor 광고 | 실측 결과 | 교훈 |
|---|---|---|---|
| **Round 17** ESP32-S3 + ESP-DSP `dsps_dp_s8_aes3` | "AI 가속 chip" 마케팅 | MLP 128 **+13.4× 가속** (1,452μs → 108μs) / C3→S3+DSP 종합 24.8× | LX7 128-bit AI vector instruction = 진짜 가속 (단, esp32wroom LX6/RISC-V에 적용은 1.54× 손해 — 칩 매칭 필수) |
| **Round 18 본편** Nordic nRF52840 (256KB) + CMSIS-NN SMLAD | "Cortex-M4F DSP extension AI 가속" | MLP 128 **+3.23× 가속** (7,367μs → 2,285μs) ✅ (Optimistic 가설 적중) / CNN/TF 1.01× (skeleton 미패치) | M4F SMLAD 32-bit DSP extension = 적당한 가속. 단, 클럭 normalize 시 LX7 5.64× M4F 우위 → instruction set design이 진짜 변수 |
| **Round 18 후속** ⭐NEW Nordic nRF52832 (64KB) + CMSIS-NN | "Cortex-M4F + neural network frameworks 지원" (datasheet) | mandate MLP/CNN/TF **12/12 전셀 RAM wall** (CMSIS-NN .bss 34KB / 64KB = 52%, heap < weights) | vendor "supports" ≠ practical fit. **RAM tier 적합도 4번째 조건** = AI mandate 의 최소 RAM 요구치. nRF52832 = BLE-only 트랙 분리 필수 |
| **Round 19** Galaxy A51 5G Eden NPU NNAPI | Samsung 2.1 TOPS / Mobile AI acceleration | MLP 128~16384 plain INT8 **‒79~421× 손해** ⚠️ (CPU Cortex-A77 + asimddp 대비) | NPU = 표준 ML model (MobileNet conv-dominant, batch>1) 전용. small dense + batch=1 + INT8 에는 NPU dispatch overhead 가 compute 의 100× |

### 클럭 normalize 단위 효율 비교 (Day 5 강의 핵심 인사이트)

| ISA | 클럭 | MLP 128 실측 | 클럭 normalize cycles | 단위 효율 |
|---|---|---:|---:|:-:|
| **LX7** (esp32s3) | 240MHz | 108μs (ESP-DSP `aes3` 128-bit AI vector) | 25,920 | **5.64× 우위** ⭐ |
| Cortex-M4F (pca10056) | 64MHz | 2,285μs (CMSIS-NN SMLAD 32-bit DSP extension) | 146,240 | baseline |

→ 강의 핵심: clock speed (240 vs 64MHz, 3.75×) 만으로는 단위 효율 5.64× 우위 설명 못 함. **instruction set design이 AI 가속의 진짜 변수**.

### RAM tier 적합도 표 (4번째 조건, 5/22 야간 후속 추가) ⭐NEW

| RAM tier | 칩 예 | mandate 적합 | 사용 패턴 |
|---|---|:-:|---|
| **8MB+ PSRAM** | ESP32-S3 + PSRAM | ✅ 전셀 | SLM Korean-Small 154K + 응원봉 양산 |
| **256KB SRAM** | nRF52840 (pca10056) | ✅ MLP 128 / TF 64 | B2B BLE+AI 통합 SoC |
| **512KB SRAM (PSRAM 없음)** | esp32c6 RISC-V | △ MLP 1024 wall | RISC-V + WiFi6 응용 |
| **≤64KB SRAM** | **nRF52832 (pca10040)** | ❌ **전셀 wall** | **AI 부적합 — BLE-only / sensor-only 트랙 분리** |

→ 강의 핵심: "AI 응용 ≠ MCU 라벨" — vendor "supports neural network frameworks" 광고는 toolchain·library 호환만 검증, **실제 RAM 적합도 = AI mandate 의 최소 RAM 요구치 = sweep 측정 필수**.

### Nordic 함정 11건 cross-vendor 인벤토리 모듈 (5/22 야간 후속 추가) ⭐NEW

본 vault 5일 측정 누적 (Round 17 ESP-DSP 4건 + Round 18 본편 5건 + Round 18 후속 2건) = **Espressif + Nordic 2종 vendor toolchain 빌드·monitor·setup 함정 11건 인벤토리**:

| 카테고리 | 함정 수 | 대표 사례 |
|---|:-:|---|
| Espressif ESP-DSP (Round 17) | 4건 | `dsps_dp_s8_aes3` API 4 args 고정 / PSRAM 가속 무효 / CNN strided 적용 불가 / LX6·RISC-V ansi fallback 1.54× 느림 |
| Nordic Round 18 본편 (pca10056) | 5건 | Zephyr `CONFIG_STDOUT_CONSOLE=y` 누락 / newlib fully buffered fflush 필요 / Zephyr 4.3.99 console redirect 결함 printk 우회 / esp32_monitor.py prefix 매칭 실패 / monitor race 1.5s backoff + nrfjprog --reset trigger |
| Nordic Round 18 후속 (pca10040) | 2건 | APPROTECT recover 1회 / post-recover USB COM 재assignment |

→ 강의 가치: "임베디드 견적 시 1인 셋업 함정 ~3.5시간/보드" 정량 (Round 18 본편 8차 시도 누적 사례). 위시캣 임베디드 견적 차별화 자산.
