## 3. 실패 항목 및 해결

### 3-1. ttyd 웹 터미널에서 입력 불가

```
문제: ttyd를 통해 브라우저에서 Claude Code 접속 시 키 입력이 안 됨
원인: Claude Code는 Ink/React 기반 TUI로, ttyd의 터미널 에뮬레이션과 비호환
증상: 화면은 렌더링되나 키 입력이 전달되지 않음
해결: SSH 직접 접속으로 전환 (ttyd 방식 폐기)
영향: 웹 브라우저만으로 접속하는 시나리오 불가
```

### 3-2. OAuth 동시 사용 시 401 에러

```
문제: 여러 학생이 동시에 Claude 사용 시 간헐적 401 Unauthorized
원인: 한 학생의 세션에서 토큰 갱신 시 credentials.json 덮어쓰기
     → 다른 학생의 세션이 가진 토큰이 무효화됨
증상: "Unauthorized" 에러 후 Claude 세션 종료
해결:
  - 단기: credentials.json 권한을 644로 유지 (cron)
  - 장기: API Key 방식으로 전환 (AWS 이전 시)
```

### 3-3. credentials 파일 권한 초기화

```
문제: Claude가 토큰 갱신 시 .credentials.json 파일 권한이 600으로 재생성
원인: Claude Code가 보안을 위해 owner-only 권한으로 파일 생성
증상: symlink를 타고 읽는 다른 학생이 "Permission denied"
해결:
  - cron 1분마다: chmod 644 /home/uttec/.claude/.credentials.json
  - 현재 상태: 수동으로 644 설정됨 (cron 미등록)
```

### 3-4. .claude.json symlink 충돌

```
문제: .claude.json을 symlink로 공유하면 파일 손상
원인: 여러 Claude 인스턴스가 동시에 같은 파일에 쓰기
증상: JSON parse error, Claude 실행 불가
해결: 학생별 독립 파일로 복사 (symlink 절대 금지)
교훈: .credentials.json은 symlink OK, .claude.json은 반드시 독립
```

### 3-5. trust 대화상자

```
문제: 첫 실행 시 "Do you trust this workspace?" 대화상자
원인: 새로운 workspace에서 Claude 실행 시 기본 동작
증상: 학생이 응답하기 전까지 Claude 대기
해결: .claude.json에 hasTrustDialogAccepted: true 미리 설정
```

### 3-6. .bashrc에서 claude 자동실행 충돌

```
문제: .bashrc에 'claude' 넣으면 SSH 접속 시 화면 깨짐
원인: .bashrc 실행 시점에 MOTD 배너 출력 + Claude TUI 렌더링 동시 발생
증상: 터미널 화면이 깨지고 입력 불가
해결: .bashrc 비움 (# empty), 학생이 수동으로 claude 입력
교훈: .hushlogin만으로는 완전한 해결이 안 됨
      배너 + 자동실행 조합이 문제
```

### 3-7. Armbian MOTD 배너

```
문제: SSH 접속 시 긴 시스템 정보 배너가 출력됨
원인: Armbian 기본 MOTD (CPU 온도, 로드, 메모리 등)
증상: Claude TUI와 배너가 겹쳐서 화면 깨짐
해결: 각 학생 홈에 .hushlogin 빈 파일 생성
     → SSH 접속 시 MOTD 출력 안 함
```

## 4. 알려진 미해결 이슈

### 4-1. taskset 미적용

```
상태: 미해결
문제: SSH 직접 접속 시 학생이 claude를 실행하면 코어 고정 안 됨
     .bashrc에 alias 미설정
영향: 4코어 중 어느 코어에서든 실행 (OS가 자동 분배)
     → 동시 3명 사용 시 한 코어에 몰릴 수 있음
해결 방안: .bashrc에 alias 추가
     alias claude='taskset -c N claude'
```

### 4-2. credentials 권한 cron 미등록

```
상태: 미해결
문제: Claude가 토큰 갱신 시 credentials 권한이 600으로 바뀜
     수동으로 644로 바꿔야 함
영향: 수업 중 갑자기 한 학생만 인증 실패
해결 방안: cron 등록
     * * * * * chmod 644 /home/uttec/.claude/.credentials.json
```

### 4-3. systemd 서비스 미등록

```
상태: 미해결 (선택사항)
문제: 웹 서버(/opt/claude-education)가 systemd에 등록 안 됨
     서버 재부팅 시 수동 실행 필요
영향: SSH 직접 접속 방식 사용 시 영향 없음
     웹 데모가 필요할 때만 영향
```

### 4-4. RAM 부족 대비 없음

```
상태: 미해결
문제: 2GB RAM에서 3명 동시 사용 시 메모리 부족 가능
     cgroups 미설정으로 한 학생이 과도하게 사용 가능
영향: OOM Killer 발동 시 다른 학생 프로세스 종료
해결 방안:
  - cgroups로 학생당 메모리 제한 (500MB)
  - swap 파일 추가 확대
  - AWS 이전
```

### 4-5. 학생 비밀번호 보안

```
상태: 미해결 (저위험)
문제: 학생 비밀번호가 단순할 가능성 (확인 불가)
영향: Tailscale 내부 네트워크이므로 외부 공격 위험 낮음
해결 방안: 수업 전 비밀번호 재설정
```
