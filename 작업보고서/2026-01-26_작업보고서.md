## 🚨 긴급: Jetson Nano eMMC 부팅 실패 - 복구 필요

### 문제 발생 일시
- **2026년 01월 26일 저녁**

### 문제 상황
- Jetson Nano (Yahboom 보드)가 **NVIDIA 로고에서 멈추고 부팅되지 않음**
- eMMC에서 부팅하는 시스템 (SD 카드 아님)

### 원인
WS2812 LED 제어를 위해 SPI 핀 활성화를 시도하면서 `/boot/extlinux/extlinux.conf` 파일 수정

**수정 전 (정상):**
```
LABEL primary
      MENU LABEL primary kernel
      LINUX /boot/Image
      INITRD /boot/initrd
      APPEND ${cbootargs} quiet root=/dev/mmcblk0p1 rw rootwait rootfstype=ext4 console=ttyS0,115200n8 console=tty0 fbcon=map:0 net.ifnames=0 sdhci_tegra.en_boot_part_access=1
```

**수정 후 (문제 발생):**
```
LABEL primary
      MENU LABEL primary kernel
      LINUX /boot/Image
      INITRD /boot/initrd
      FDT /boot/dtb/tegra210-p3448-0000-p3449-0000-b00.dtb
      FDTOVERLAYS /boot/tegra210-p3448-0000-p3449-0000-a02-hdr40.dtbo
      APPEND ${cbootargs} quiet root=/dev/mmcblk0p1 rw rootwait rootfstype=ext4 console=ttyS0,115200n8 console=tty0 fbcon=map:0 net.ifnames=0 sdhci_tegra.en_boot_part_access=1
```

**문제점:**
1. `FDT` 파일 경로가 잘못되었을 수 있음 (b00 vs a02 버전 불일치)
2. `FDTOVERLAYS` 오버레이 파일이 Yahboom 보드와 호환되지 않을 수 있음
3. 백업 파일 존재: `/boot/extlinux/extlinux.conf.backup`

---

### 원인 분석 및 반성

#### 실수 내역
| 문제 | 설명 |
|:-----|:-----|
| **버전 불일치** | FDT에 `b00.dtb` 사용, 오버레이에 `a02-hdr40.dtbo` 사용 → 호환 안됨 |
| **보드 확인 안함** | Yahboom 보드의 정확한 하드웨어 리비전 확인 없이 진행 |
| **DTB 파일 존재 확인 안함** | `/boot/dtb/tegra210-p3448-0000-p3449-0000-b00.dtb` 파일이 실제 존재하는지 확인 안함 |
| **eMMC 위험성 간과** | SD카드와 달리 eMMC는 복구가 어려운데 충분히 주의하지 않음 |

#### 해야 했던 것 (사전 확인)
```bash
# 보드 리비전 확인
cat /proc/device-tree/nvidia,dtsfilename

# 사용 가능한 DTB 파일 확인
ls /boot/dtb/

# 현재 사용 중인 DTB 확인
dmesg | grep -i dtb
```

#### 근본 원인
**SPI 핀 활성화를 위해 급하게 Device Tree를 수정**
- GPIO/SPI가 동작하지 않음
- jetson-io로 설정 불가 (Yahboom 보드 미지원)
- 수동으로 extlinux.conf 수정
- **검증 없이 적용 → 부팅 실패**

#### 교훈
1. **부팅 설정 수정 전 반드시 백업 및 검증**
2. **eMMC 시스템은 특히 신중하게 작업**
3. **보드 리비전과 DTB 호환성 먼저 확인**
4. **급하게 진행하지 않기**

### 복구 방법

#### 방법 1: 시리얼 콘솔로 복구 (권장)

**필요 장비:**
- USB-TTL 시리얼 어댑터 또는 Jetson Nano의 마이크로 USB 포트 사용

**Mac에서 시리얼 연결:**
```bash
# 시리얼 포트 확인
ls /dev/tty.usb*
ls /dev/cu.usb*

# 시리얼 접속 (115200 baud)
screen /dev/tty.usbserial-XXXXX 115200
# 또는
screen /dev/cu.usbmodem* 115200
```

**복구 절차:**
1. Jetson 전원 끄기
2. 시리얼 케이블 연결
3. Mac에서 screen 명령으로 시리얼 접속
4. Jetson 전원 켜기
5. 부팅 중 **아무 키나 연속해서 누르기** → U-Boot 프롬프트 진입
6. U-Boot 프롬프트에서:

```bash
# 환경 변수 확인
printenv

# 부팅 시도 (백업 사용)
# 또는 단일 사용자 모드 진입
setenv bootargs "root=/dev/mmcblk0p1 rw rootwait init=/bin/bash"
boot
```

7. 쉘 진입 후 파일 복구:
```bash
mount -o remount,rw /
cp /boot/extlinux/extlinux.conf.backup /boot/extlinux/extlinux.conf
sync
reboot
```

---

#### 방법 2: SD 카드 부팅으로 eMMC 수정

**필요 장비:**
- 별도의 Jetson Nano용 SD 카드 (Ubuntu 이미지 플래시)

**절차:**
1. [NVIDIA 공식 사이트](https://developer.nvidia.com/embedded/downloads)에서 Jetson Nano SD 카드 이미지 다운로드
2. Balena Etcher로 SD 카드에 이미지 플래시
3. SD 카드를 Jetson에 삽입하고 부팅
4. SD 카드에서 부팅 후 eMMC 마운트:

```bash
# eMMC 파티션 확인
lsblk

# eMMC 마운트 (보통 /dev/mmcblk0p1)
sudo mkdir /mnt/emmc
sudo mount /dev/mmcblk0p1 /mnt/emmc

# 설정 파일 복구
sudo cp /mnt/emmc/boot/extlinux/extlinux.conf.backup /mnt/emmc/boot/extlinux/extlinux.conf

# 마운트 해제
sudo umount /mnt/emmc
```

5. SD 카드 제거 후 재부팅

### WS2812 LED 문제 요약 (복구 후 계속)

**시도한 방법들:**
| 방법 | 결과 | 비고 |
|:-----|:-----|:-----|
| rpi_ws281x | ❌ 실패 | "Hardware revision not supported" |
| Adafruit Blinka/NeoPixel | ❌ 실패 | 의존성 문제, SEGV 발생 |
| Jetson.GPIO bit-banging | ❌ 실패 | 타이밍 불안정 |
| SPI0 (Pin 19) | ❌ 실패 | 신호 없음 |
| SPI1 (Pin 38) | ❌ 실패 | 신호 없음 |
| GPIO 토글 테스트 | ❌ 실패 | Pin 33, 38, 40 신호 없음 |

**결론:**
- Yahboom 보드의 40-pin 헤더가 기본 Jetson Nano와 다르게 설정되어 있을 가능성
- GPIO/SPI 핀이 기본적으로 비활성화 상태
- **레벨 시프터 필요** (3.3V → 5V) 가능성도 있음

**다음 단계 (복구 후):**
1. Yahboom 보드 공식 문서 확인
2. Yahboom 전용 GPIO 설정 방법 찾기
3. 레벨 시프터(74HCT125) 사용 고려
