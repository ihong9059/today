## 2. WS2812 LED GPIO 비트뱅잉 제어

### 2.1 개요
Jetson Nano 40핀 헤더 Pin 19 (GPIO16)를 사용하여 WS2812 LED 제어 시도

### 2.2 시도한 방법들

| 방법 | 결과 | 비고 |
|:-----|:----:|:-----|
| `/dev/mem` GPIO 레지스터 직접 제어 | △ | 타이밍 불안정 |
| nop 딜레이 | △ | 컴파일러 최적화 문제 |
| ARM cycle counter | △ | 가장 안정적이나 여전히 불안정 |
| sysfs + /dev/mem 혼합 | △ | 초기화 후 동작 |

### 2.3 오실로스코프 타이밍 측정 결과

| 파라미터 | 측정값 | WS2812 스펙 | 상태 |
|:---------|:------:|:-----------:|:----:|
| T0H (bit 0 high) | ~300ns | 220-380ns | ✅ |
| T1H (bit 1 high) | ~700ns | 580-1000ns | ✅ |
| T0L (bit 0 low) | ~800ns | 580-1000ns | ✅ |
| T1L (bit 1 low) | ~600ns | 220-420ns | ✅ |

### 2.4 색상 순서 확인

| 바이트 위치 | 색상 |
|:----------:|:----:|
| Byte 1 | Green |
| Byte 2 | Red |
| Byte 3 | Blue |

**결론: GRB 순서 (WS2812 표준)**

### 2.5 문제점
- Linux 커널 인터럽트로 인한 타이밍 불안정
- 색상이 불규칙하게 표시됨 (가끔 정상, 가끔 흰색)
- **GPIO 비트뱅잉은 실시간 OS가 아닌 Linux에서 근본적으로 불안정**

## 3. WS2812 LED SPI 제어 시도

### 3.1 SPI 상태 확인

| 항목 | 상태 |
|:-----|:-----|
| spidev 모듈 | ✅ 로드됨 |
| /dev/spidev0.0 | ✅ 존재 |
| /dev/spidev1.0 | ✅ 존재 |
| SPI 컨트롤러 | ✅ 활성화 (okay) |

### 3.2 문제점
- **Pin 19에서 SPI 신호 없음**
- Pinmux가 GPIO 모드로 설정됨
- `/dev/mem`으로 pinmux 변경 시도 → 실패
- **Device Tree 수정 필요** (부팅 설정 변경)

### 3.3 Device Tree 수정 위험성
- 이전에 Device Tree 수정으로 부팅 실패 경험
- 백업 및 복구 방법 확인 완료
  - `extlinux.conf.backup` 사용
  - Serial Console 복구
  - SD카드 부팅 복구

## 6. 하드웨어 정보

### 6.1 WS2812 연결

```
Jetson Nano 40-Pin Header:
- Pin 19 (GPIO16): WS2812 DIN
- Pin 2/4 (5V): WS2812 VCC
- Pin 6/9/14/20/25 (GND): WS2812 GND
```

### 6.2 Tegra210 GPIO 레지스터

```
GPIO16 = Port C, Bit 0
GPIO Base: 0x6000d000
- GPIO_CNF: 0x08 (Port C)
- GPIO_OE:  0x18 (Port C)
- GPIO_OUT: 0x28 (Port C)
```
