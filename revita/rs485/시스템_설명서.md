# KC 기능시험 RS485 사전 검증 시스템 설명서

## 1. 이 시스템이 무엇인가?

리비타 링크의 KC 인증 기능시험을 **실제 장비 없이 사전 검증**하기 위한 시뮬레이션 시스템입니다.

실제 KC 시험에서는 시험자가 RS485로 리비타 링크에 명령을 보내 각 기능(밸브, 부저, LoRa 등)을 동작시키고 결과를 확인합니다. 이 시스템은 그 과정을 PC에서 미리 재현합니다.

## 2. 전체 구성도

```
┌─────────────────────────────────────────────────────┐
│                      PC (Windows)                    │
│                                                      │
│  ┌──────────────┐         ┌──────────────────────┐  │
│  │   Host       │         │   DUT Simulator      │  │
│  │  (Flask 웹)  │         │  (가상 리비타 링크)   │  │
│  │              │         │                      │  │
│  │ localhost:   │         │  실제 장비처럼       │  │
│  │  5000        │         │  명령에 응답         │  │
│  └──────┬───────┘         └──────────┬───────────┘  │
│         │                            │               │
│     COM15                        COM16               │
│  (USB-RS485)                  (USB-RS485)            │
│         │                            │               │
└─────────┼────────────────────────────┼───────────────┘
          │                            │
          └──── RS485 A/B 선 연결 ─────┘
```

### 구성 요소 설명

| 구성 요소 | 역할 | 파일 |
|----------|------|------|
| **Host (웹 서버)** | 시험자가 브라우저에서 버튼을 누르면 RS485 명령을 생성하여 COM15로 전송 | `host/app.py` |
| **Web UI** | 브라우저에서 보이는 제어 화면. 각 기능별 버튼과 상태 표시 | `host/templates/index.html` |
| **DUT Simulator** | 실제 리비타 링크 장비를 흉내내는 프로그램. COM16에서 명령을 받아 응답 | `dut/dut_simulator.py` |
| **COM15 ↔ COM16** | 두 USB-RS485 컨버터가 A/B 선으로 물리적으로 연결됨 | (하드웨어) |

## 3. 데이터 흐름

시험자가 브라우저에서 "밸브 X 개방" 버튼을 누르면 아래 순서로 동작합니다:

```
① 브라우저          ② Flask 서버        ③ COM15           ④ RS485선          ⑤ COM16           ⑥ DUT
   (버튼 클릭)  →     (HTTP 요청)   →    (시리얼 송신)  →   (전기 신호)   →    (시리얼 수신)  →   (명령 처리)
                                                                                                    │
   (화면 갱신)  ←     (JSON 응답)   ←    (시리얼 수신)  ←   (전기 신호)   ←    (시리얼 송신)  ←   (응답 전송)
```

### 구체적 예시: "밸브 X 개방 5초"

```
1. 브라우저에서 [Open] 버튼 클릭

2. JavaScript가 HTTP POST 전송
   POST http://localhost:5000/api/valve
   Body: {"axis":"x", "cmd":1, "duration":5}

3. Flask 서버가 Modbus RTU 프레임 생성
   01 10 01 00 00 02 04 00 01 00 05 [CRC]
   │  │  │     │     │  │     │
   │  │  │     │     │  │     └─ 5초
   │  │  │     │     │  └─ 1=개방
   │  │  │     │     └─ 데이터 4바이트
   │  │  │     └─ 레지스터 2개
   │  │  └─ 시작주소 0x0100 (밸브X)
   │  └─ Function 0x10 (다중 쓰기)
   └─ Slave 주소 0x01

4. COM15 → RS485 선 → COM16으로 전기 신호 전달

5. DUT Simulator가 프레임 수신 및 해석
   - CRC 검증
   - 밸브 X 상태를 "개방 중"으로 변경
   - 5초 타이머 설정

6. DUT가 응답 프레임 생성하여 COM16 → COM15로 전송
   01 10 01 00 00 02 [CRC]

7. Flask 서버가 응답 수신, 브라우저에 {"ok": true} 반환

8. 브라우저가 3초 후 자동 폴링으로 상태 읽기
   → 밸브 X 상태 = "Open" 표시
```

## 4. 통신 프로토콜

RS485 위에서 **Modbus RTU** 프로토콜을 사용합니다.

### Modbus RTU 프레임 구조

```
[장치주소 1B] [기능코드 1B] [데이터 NB] [CRC 2B]
```

### 사용하는 기능 코드 3가지

| 코드 | 이름 | 용도 | 예시 |
|------|------|------|------|
| **0x03** | Read Holding Registers | 상태/값 읽기 | 배터리 전압, 밸브 상태 읽기 |
| **0x06** | Write Single Register | 단일 제어 | 부저 ON, LED 모드 변경 |
| **0x10** | Write Multiple Registers | 복합 제어 | 밸브 개방 + 시간 설정 |

### 레지스터 주소 배치 요약

```
읽기 전용 (0x03으로 읽기)
  0x0000~0x0004  기기 정보 (ID, 버전, 시험모드)
  0x0010~0x0015  전원/센서 (배터리, 진동, 버튼, 12V)
  0x0020~0x0023  밸브 상태
  0x0030~0x0035  유량계 카운트
  0x0040~0x0041  부저/LED 상태
  0x0050~0x0056  LoRa 상태
  0x0060~0x0061  BLE 상태
  0x0070~0x0071  Flash 상태

쓰기 (0x06 또는 0x10으로 쓰기)
  0x0100~0x0103  밸브 제어
  0x0110~0x0113  유량계 제어
  0x0120~0x0122  부저/LED/12V 제어
  0x0130~0x013F  LoRa RF 제어
  0x0140~0x014F  BLE RF 제어
  0x0150         Flash 제어
  0x01F0         비상 정지
  0x01F1         셀프테스트 (RF 미포함)
  0x01F2         셀프테스트 (RF 포함)
  0x01FF         시험 모드 진입/해제
```

## 6. 실행 방법

### 방법 1: 자동 실행 (권장)

```
revita\rs485\run.bat 더블클릭
```

자동으로 세 가지가 실행됩니다:
1. DUT Simulator 창 (COM16)
2. Host 웹서버 창 (COM15)
3. 브라우저 (http://localhost:5000)

### 방법 2: 수동 실행

터미널 2개를 열어 각각 실행합니다.

**터미널 1 - DUT Simulator:**
```
cd C:\todo\today\revita\rs485
python dut\dut_simulator.py COM16 9600
```

**터미널 2 - Host 웹서버:**
```
cd C:\todo\today\revita\rs485
python host\app.py COM15 9600 5000
```

**브라우저:**
```
http://localhost:5000
```

### 방법 3: 포트 번호가 다른 경우

```
python dut\dut_simulator.py COM3 9600
python host\app.py COM4 9600 5000
```

또는 웹 UI 상단에서 포트 번호 입력 후 [Connect] 클릭으로 변경 가능.

## 7. 실제 KC 시험과의 관계

```
        [사전 검증 - 지금 이 시스템]          [실제 KC 시험]

        ┌──────────┐                       ┌──────────┐
        │ Web UI   │                       │ 시험 장비 │
        │ (Host)   │                       │ (ModbusPoll│
        └────┬─────┘                       │  등)      │
             │ COM15                       └────┬─────┘
             │                                  │
           RS485                              RS485
             │                                  │
             │ COM16                            │
        ┌────┴─────┐                       ┌────┴─────┐
        │ DUT      │                       │ 실제     │
        │ Simulator│                       │ 리비타   │
        │ (Python) │                       │ 링크     │

```

- **왼쪽**: 지금 만든 시스템. DUT가 Python 프로그램.

- **프로토콜은 동일**: 같은 Modbus RTU 명령, 같은 레지스터 주소를 사용.
- **Host 웹 UI**: 실제 시험에서도 이 웹 UI를 그대로 사용할 수 있음 (COM 포트만 변경).

## 10. 문제 해결

### COM 포트를 열 수 없음 (PermissionError)

다른 프로그램이 포트를 점유 중입니다.

```bash
# 실행 중인 python 프로세스 모두 종료
taskkill /f /im python.exe
taskkill /f /im python3.13.exe
```

### 웹 페이지가 안 열림

1. Host 프로세스가 실행 중인지 확인
2. `http://127.0.0.1:5000` 으로 시도
3. 방화벽에서 5000번 포트 확인

### DUT가 응답하지 않음

1. DUT 콘솔 창에 `[DUT] RX:` 로그가 찍히는지 확인
2. RS485 A/B 선이 올바르게 연결되었는지 확인 (A↔A, B↔B)
3. Baud rate가 양쪽 모두 9600인지 확인

### 상태가 갱신되지 않음

웹 UI 상단의 **녹색 점(●)**이 표시되는지 확인. 빨간색이면 연결이 끊어진 상태.
상단 포트 입력 후 [Connect] 클릭으로 재연결.
