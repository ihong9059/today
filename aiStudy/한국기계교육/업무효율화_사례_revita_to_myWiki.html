1vault 구조 한눈에

UTTEC는 작업을 종류별로 vault(지식 저장소)로 나누고, 각 vault에 전담 AI가 상주합니다. 모든 vault의 작업이 본부 vault(myWiki)에 자동 모입니다.

🏠 myWiki (본부)

전체 사업 자산·결단·전략 hub. 모든 vault의 진행이 자동 모임. 대표(사용자)가 myWiki만 보면 전체 그림 파악.

3-1. 5단계 lifecycle — 각 카드를 어떻게 처리하나

① 신규 entity

새 사람·조직·제품 발견 시 별도 페이지 신설. 기존 페이지에 추가 가능하면 추가.

② 신규 gotcha (시행착오)

본일 9건 박제. 예: "I2C 주소 0x38 충돌 — AHT21 ↔ FT5336 onboard touch". 다음 번 같은 실수 차단.

③ 신규 decision (결단)

본일 4건 박제. 결정 40 노지관리 진입 / 41 sensor 매트릭스 mandate / 42 워크플로우 표준 / 43 CMSIS-NN chip별 검증.

④ 매칭 패턴 (thought)

본일 2건 신설. 사업 결단의 핵심 통찰을 별도 문서로 박제. 향후 비슷한 상황에서 즉시 재사용.

⑤ 기존 entity 갱신

본일 5건 prepend. revita / onDevice-ai / ai-fanstick / strengths / log. 시간순으로 위에 쌓음 — 최신 정보가 항상 맨 위.

3-2. 후처리 4단계 — 마지막 정리

  • 카드 상태: pending → done + 흡수 위치(absorbed_into) 메타데이터 추가
  • 카드 파일: _inbox/pending/ → _inbox/processed/ 이동
  • 회신 카드 발송: revita 측에 1장 + ondevice 측에 1장 = ACK 회신 2장
  • 본부 로그(log.md) 1줄 박제 — 미래 검색용

핵심 가치 — 대표는 '결단'만 합니다

분산된 6장의 카드를 직접 읽고 정리하면 약 3~4시간. vault 시스템으로는 30분 자동. 매주 같은 패턴 반복.

  • 인증팀이 EMC 통과 → 양산팀 BOM 결재 자동 trigger
  • 국책과제 중간보고 시점 → 모든 부서 자동 자료 모음 (대표가 한 번에 확인)
  • 사장 결단 1회 → 6 부서 동시 박제 (별도 회람·전달 불필요)

6한국기계 1순위 우려 — 이 cascade가 외부로 새는가? ⭐

⚠️ 우려: vault끼리 자료가 오가면 외부 클라우드도 거치는 것 아닌가?
✅ 답: 0%. vault는 모두 회사 컴퓨터 안의 폴더입니다.

카드 = 파일. 보내고 받는 것 = 폴더 이동. 외부 서버 거치지 않음.
Phase 3 (5주차)에 도입하는 Ollama 로컬 AI까지 적용하면, AI 분석도 회사 노트북 안에서 완결됩니다.

🔒 모든 vault = 사내 폴더 · 외부 망 차단 환경에서도 작동 · 회사 고유 기술 외부 노출 0%
