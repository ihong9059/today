## 1. 학습률이란?

### 1.1 정의

**학습률(Learning Rate, lr, η)** = 한 번의 업데이트에서 가중치를 "얼마나" 바꿀지 결정하는 값

```
가중치 업데이트 공식:

w_new = w_old - learning_rate × gradient
                    ↑
              이게 학습률!
```

### 1.2 비유로 이해하기

#### 비유 1: 산에서 내려오기

```
┌─────────────────────────────────────────────────────────────┐
│                        🏔️ 산                                │
│                                                             │
│  당신은 눈을 가리고 산꼭대기에 서 있습니다.                    │
│  목표: 가장 낮은 곳(골짜기)까지 내려가기                       │
│                                                             │
│  방법: 발로 바닥을 더듬어 내리막 방향을 찾고,                  │
│        그 방향으로 "한 걸음" 이동                             │
│                                                             │
│  학습률 = 한 걸음의 크기 (보폭)                               │
│                                                             │
│  ├── 보폭이 너무 크면? → 골짜기를 지나쳐서 반대편 산으로!     │
│  ├── 보폭이 너무 작으면? → 해가 져도 산 중턱...               │
│  └── 적당한 보폭? → 효율적으로 골짜기 도착!                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 비유 2: 수도꼭지 조절

```
적절한 온도의 물을 찾는 상황:

학습률이 큰 경우:
  [뜨거움!] ──────→ [차가움!] ──────→ [뜨거움!] (왔다갔다)
  한 번에 많이 돌려서 적정 온도를 계속 지나침

학습률이 작은 경우:
  [뜨거움] → [조금 덜 뜨거움] → [아직 뜨거움] → ... (너무 느림)
  조금씩 돌려서 10분이 지나도 적정 온도 못 찾음

적당한 학습률:
  [뜨거움] → [따뜻함] → [적정!]
  적당히 돌려서 효율적으로 찾음
```

### 1.3 수학적 의미

```python
# 경사하강법 한 스텝
gradient = compute_gradient(loss, weights)  # 현재 위치의 기울기
weights = weights - learning_rate * gradient

# learning_rate의 역할:
# - gradient가 "어느 방향으로" 갈지 알려줌
# - learning_rate가 "얼마나 멀리" 갈지 결정
```

## 2. 왜 학습률이 가장 중요한가?

### 2.1 하이퍼파라미터 중요도 순위

```
┌─────────────────────────────────────────────────────────────┐
│              하이퍼파라미터 중요도                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1위: 학습률 (Learning Rate) ⭐⭐⭐⭐⭐                        │
│       → 이것만 잘못 설정해도 학습이 아예 안됨                 │
│                                                             │
│  2위: 배치 크기 (Batch Size) ⭐⭐⭐⭐                         │
│       → 학습 안정성과 속도에 영향                            │
│                                                             │
│  3위: 네트워크 구조 ⭐⭐⭐                                    │
│       → 층 수, 뉴런 수                                       │
│                                                             │
│  4위: 정규화 관련 ⭐⭐                                        │
│       → Dropout, Weight Decay                               │
│                                                             │
│  5위: 기타 ⭐                                                │
│       → 에포크 수, 데이터 증강 등                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 학습률이 다른 것들보다 중요한 이유

```
다른 하이퍼파라미터가 잘못되면:
├── 배치 크기 잘못 → 느리거나 불안정, 하지만 학습은 됨
├── 네트워크 구조 잘못 → 성능이 낮지만, 학습은 됨
└── 정규화 잘못 → 과적합되지만, 학습은 됨

학습률이 잘못되면:
├── 너무 크면 → 손실이 발산! 학습 자체가 안됨!
└── 너무 작으면 → 며칠이 지나도 수렴 안됨!

결론: 학습률은 "학습이 되느냐 마느냐"를 결정하는 가장 근본적인 값
```

## 3. 학습률이 잘못되면 어떻게 되나?

### 3.1 학습률이 너무 클 때 (발산)

```
손실 그래프:

Loss
  ↑
  │                              ★ 폭발!
  │                           ★
  │                        ★
  │                     ★
  │                  ★
  │               ★
  │    ★      ★
  │       ★
  └────────────────────────────────────→ Epoch

현상:
- 손실이 점점 증가 (NaN이 되기도 함)
- 가중치가 무한대로 발산
- 예측값이 엉망

원인:
- 최적점을 지나쳐서 반대편으로 넘어감
- 그 반대편에서 또 지나침
- 점점 더 멀어짐 (진동 → 발산)
```

### 3.2 학습률이 너무 작을 때 (수렴 안됨)

```
손실 그래프:

Loss
  ↑
  │ ★★★★★★★★★★★★★★★★★★★★★★★★★★★★★★  ← 거의 변화 없음
  │
  │
  │
  │
  │                           ← 목표 손실
  └────────────────────────────────────→ Epoch
                                         100 epoch이 지나도...

현상:
- 손실이 아주 천천히 감소
- 수백 에포크가 지나도 수렴 안됨
- 시간과 자원 낭비

원인:
- 한 번에 너무 조금 이동
- 좋은 방향이어도 진전이 미미
```

### 3.3 학습률이 적당할 때 (이상적)

```
손실 그래프:

Loss
  ↑
  │ ★
  │   ★
  │     ★
  │       ★★
  │          ★★★
  │              ★★★★★★★★★★★★★  ← 수렴!
  │
  │
  └────────────────────────────────────→ Epoch

현상:
- 손실이 빠르게 감소
- 일정 수준에서 안정적으로 수렴
- 효율적인 학습
```

### 3.4 시각적 비교

```
학습률별 가중치 이동 경로 (2D 손실 표면에서):

                    최적점
                      ●

lr=0.0001 (너무 작음)           lr=0.1 (적당)
    ·                              ·
    ·                               ·
    ·                                ·
    ·                                 ·
    ·                                  ●
(목표에 도달 못함)              (효율적으로 도달)


lr=0.5 (약간 큼)                lr=1.5 (너무 큼)
    ·                              ·
     ·                            ·   ·
      ·                          ·     ·
       ·●                       ·       ·
    (진동하며 수렴)                 (발산!)
```

## 4. 적절한 학습률 찾는 방법

### 4.1 방법 1: 경험적 시작값

```
┌─────────────────────────────────────────────────────────────┐
│                   옵티마이저별 시작 학습률                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  SGD:           0.01 ~ 0.1                                  │
│  SGD + Momentum: 0.01 ~ 0.1                                 │
│  Adam:          0.001 ~ 0.0001  ← 가장 많이 사용!           │
│  AdamW:         0.001 ~ 0.0001                              │
│  RMSprop:       0.001 ~ 0.01                                │
│                                                             │
│  💡 Adam은 학습률에 덜 민감해서 초보자에게 추천!              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 방법 2: Learning Rate Range Test (LR Finder)

**원리**: 학습률을 아주 작은 값에서 시작해서 점점 키우면서 손실 변화를 관찰

```
절차:
1. 학습률을 1e-7 같은 아주 작은 값으로 시작
2. 매 배치마다 학습률을 조금씩 증가 (예: 1.1배)
3. 손실을 기록
4. 손실이 급격히 증가하기 시작하면 중단
5. 그래프에서 손실이 가장 빠르게 감소하는 구간의 학습률 선택

Loss
  ↑
  │ ★★★
  │     ★★
  │        ★
  │          ★  ← 이 구간의 학습률이 최적!
  │            ★★
  │               ★★★★  ← 손실 증가 시작
  │                    ★★★★★★
  └────────────────────────────────────→ Learning Rate
     10⁻⁷  10⁻⁶  10⁻⁵  10⁻⁴  10⁻³  10⁻²
```

### 4.3 방법 3: Grid Search / Random Search

```python
# 학습률 후보들
learning_rates = [0.1, 0.01, 0.001, 0.0001]

best_lr = None
best_loss = float('inf')

for lr in learning_rates:
    model = create_model()
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)

    # 짧게 학습 (예: 10 에포크)
    final_loss = train_for_epochs(model, optimizer, epochs=10)

    if final_loss < best_loss:
        best_loss = final_loss
        best_lr = lr

print(f"Best learning rate: {best_lr}")
```

### 4.4 방법 4: 손실 그래프 관찰

```
학습 중 손실 그래프를 보고 판단:

상황 1: 손실이 전혀 안 줄어듦
→ 학습률 10배 키우기 (예: 0.001 → 0.01)

상황 2: 손실이 진동하면서 불안정
→ 학습률 2~10배 줄이기 (예: 0.01 → 0.001)

상황 3: 손실이 NaN이 됨
→ 학습률 10~100배 줄이기

상황 4: 손실이 천천히 줄어듦
→ 현재 학습률 유지, 또는 약간 키우기

상황 5: 손실이 빠르게 줄다가 평탄해짐
→ 완벽! 그대로 유지
```

## 5. 학습률 스케줄링

### 5.1 왜 학습률을 바꾸나?

```
학습 초반:
- 최적점에서 멀리 있음
- 큰 학습률로 빠르게 이동해야 함

학습 후반:
- 최적점 근처에 있음
- 작은 학습률로 섬세하게 조정해야 함
- 큰 학습률이면 최적점 주변에서 계속 진동

해결책: 학습률을 점점 줄여나감 (Learning Rate Scheduling)
```

### 5.2 주요 스케줄링 방법

#### Step Decay (계단식 감소)

```
학습률
  ↑
  │ ████████
  │         ████████
  │                  ████████
  │                           ████████
  └──────────────────────────────────────→ Epoch
      30      60      90      120

설정: "30 에포크마다 학습률을 0.1배로"
```

```python
# PyTorch
scheduler = torch.optim.lr_scheduler.StepLR(
    optimizer,
    step_size=30,  # 30 에포크마다
    gamma=0.1      # 0.1배로 줄임
)
```

#### Cosine Annealing (코사인 감소)

```
학습률
  ↑
  │ ████
  │      ███
  │          ██
  │            ██
  │              ██
  │                ██████████████
  └──────────────────────────────────────→ Epoch

부드럽게 감소 (코사인 곡선)
```

```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer,
    T_max=100  # 총 에포크 수
)
```

#### ReduceLROnPlateau (성능 기반 감소)

```
검증 손실이 더 이상 줄지 않으면 학습률 감소

학습률
  ↑
  │ ████████████████
  │                  ████████
  │                           ████
  └──────────────────────────────────────→ Epoch
             ↑              ↑
        손실 정체!      또 정체!
```

```python
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
    optimizer,
    mode='min',        # 손실이 줄어야 좋음
    factor=0.5,        # 절반으로 줄임
    patience=10        # 10 에포크 동안 개선 없으면
)
```

#### Warmup (워밍업)

```
학습률
  ↑
  │           ████████████████████
  │         ██
  │       ██
  │     ██
  │   ██
  │ ██
  └──────────────────────────────────────→ Epoch
    ↑───────↑
    Warmup 구간

처음엔 작게 시작해서 점점 키움
→ 학습 초기 불안정성 방지
→ Transformer 학습에 필수!
```

### 5.3 스케줄링 선택 가이드

| 스케줄러 | 장점 | 단점 | 추천 상황 |
|----------|------|------|----------|
| **Step Decay** | 단순, 이해 쉬움 | 언제 줄일지 알아야 함 | 전통적인 CNN |
| **Cosine** | 자연스러운 감소 | 하이퍼파라미터 적음 | 일반적으로 추천 |
| **ReduceLROnPlateau** | 자동 감지 | 검증 데이터 필요 | 수렴 상황 모를 때 |
| **Warmup + 다른것** | 안정적 시작 | 구현 복잡 | Transformer, 큰 배치 |

## 6. 옵티마이저별 학습률 가이드

### 6.1 SGD (Stochastic Gradient Descent)

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01,           # 권장: 0.01 ~ 0.1
    momentum=0.9       # 모멘텀 추가 권장
)
```

```
특징:
- 단순하고 이해하기 쉬움
- 학습률에 민감함
- 일반화 성능이 좋을 수 있음

학습률 팁:
- 시작: 0.1 또는 0.01
- 학습 중 1/10씩 감소
- Momentum 0.9와 함께 사용
```

### 6.2 Adam (Adaptive Moment Estimation)

```python
optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001,          # 권장: 0.001 또는 0.0001
    betas=(0.9, 0.999),
    eps=1e-8
)
```

```
특징:
- 학습률을 자동으로 조정 (적응형)
- 학습률에 덜 민감 → 초보자에게 추천!
- 대부분의 경우 잘 작동

학습률 팁:
- 거의 항상 0.001로 시작
- 안되면 0.0001로 줄이기
- 대부분 스케줄링 없이도 OK
```

### 6.3 AdamW (Adam with Decoupled Weight Decay)

```python
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=0.001,          # 권장: 0.001
    weight_decay=0.01  # L2 정규화
)
```

```
특징:
- Adam의 개선 버전
- Weight Decay가 더 정확하게 적용됨
- Transformer 학습에 표준

학습률 팁:
- 0.001로 시작
- Warmup + Cosine 스케줄링 추천
```

### 6.4 옵티마이저 선택 가이드

```
┌─────────────────────────────────────────────────────────────┐
│                   언제 어떤 옵티마이저?                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  처음 시작한다면?                                            │
│  → Adam (lr=0.001)                                          │
│                                                             │
│  일반화 성능을 최대로?                                       │
│  → SGD + Momentum (lr=0.1, 스케줄링 필수)                   │
│                                                             │
│  Transformer / NLP / Vision Transformer?                    │
│  → AdamW (lr=0.001, warmup + cosine)                       │
│                                                             │
│  빠르게 프로토타입?                                          │
│  → Adam (lr=0.001, 스케줄링 없이)                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 7. 실전 코드 예제

### 7.1 기본 학습 루프

```python
import torch
import torch.nn as nn
import torch.optim as optim

# 모델 정의
model = nn.Sequential(
    nn.Linear(784, 256),
    nn.ReLU(),
    nn.Linear(256, 10)
)

# 옵티마이저 설정
optimizer = optim.Adam(model.parameters(), lr=0.001)

# 학습률 스케줄러
scheduler = optim.lr_scheduler.ReduceLROnPlateau(
    optimizer, mode='min', factor=0.5, patience=5
)

# 학습 루프
for epoch in range(100):
    model.train()
    for batch_x, batch_y in train_loader:
        optimizer.zero_grad()
        output = model(batch_x)
        loss = nn.CrossEntropyLoss()(output, batch_y)
        loss.backward()
        optimizer.step()

    # 검증
    model.eval()
    val_loss = evaluate(model, val_loader)

    # 스케줄러 업데이트
    scheduler.step(val_loss)

    # 현재 학습률 확인
    current_lr = optimizer.param_groups[0]['lr']
    print(f"Epoch {epoch}: val_loss={val_loss:.4f}, lr={current_lr}")
```

### 7.2 Learning Rate Finder 구현

```python
import torch
import numpy as np
import matplotlib.pyplot as plt

def find_lr(model, train_loader, optimizer, criterion,
            init_lr=1e-7, final_lr=10, num_iter=100):
    """학습률 범위 테스트"""

    # 모델 상태 저장
    initial_state = model.state_dict().copy()

    # 학습률 스케줄 (지수적 증가)
    lr_mult = (final_lr / init_lr) ** (1 / num_iter)

    lrs = []
    losses = []

    optimizer.param_groups[0]['lr'] = init_lr
    best_loss = float('inf')
    avg_loss = 0
    smoothing = 0.05

    for i, (x, y) in enumerate(train_loader):
        if i >= num_iter:
            break

        # Forward
        optimizer.zero_grad()
        output = model(x)
        loss = criterion(output, y)

        # Smooth loss
        avg_loss = smoothing * loss.item() + (1 - smoothing) * avg_loss
        smoothed_loss = avg_loss / (1 - smoothing ** (i + 1))

        # 발산 감지
        if i > 0 and smoothed_loss > 4 * best_loss:
            break

        if smoothed_loss < best_loss:
            best_loss = smoothed_loss

        # 기록
        current_lr = optimizer.param_groups[0]['lr']
        lrs.append(current_lr)
        losses.append(smoothed_loss)

        # Backward
        loss.backward()
        optimizer.step()

        # 학습률 증가
        optimizer.param_groups[0]['lr'] *= lr_mult

    # 모델 복원
    model.load_state_dict(initial_state)

    # 그래프 그리기
    plt.figure(figsize=(10, 6))
    plt.plot(lrs, losses)
    plt.xscale('log')
    plt.xlabel('Learning Rate')
    plt.ylabel('Loss')
    plt.title('Learning Rate Finder')
    plt.grid(True)
    plt.show()

    # 최적 학습률 추천 (손실이 가장 빠르게 감소하는 구간)
    min_loss_idx = np.argmin(losses)
    suggested_lr = lrs[min_loss_idx] / 10  # 안전하게 1/10
    print(f"추천 학습률: {suggested_lr:.6f}")

    return suggested_lr
```

### 7.3 Warmup + Cosine 스케줄러

```python
import math

class WarmupCosineScheduler:
    def __init__(self, optimizer, warmup_epochs, total_epochs, base_lr, min_lr=1e-6):
        self.optimizer = optimizer
        self.warmup_epochs = warmup_epochs
        self.total_epochs = total_epochs
        self.base_lr = base_lr
        self.min_lr = min_lr
        self.current_epoch = 0

    def step(self):
        if self.current_epoch < self.warmup_epochs:
            # Warmup: 선형 증가
            lr = self.base_lr * (self.current_epoch + 1) / self.warmup_epochs
        else:
            # Cosine decay
            progress = (self.current_epoch - self.warmup_epochs) / (self.total_epochs - self.warmup_epochs)
            lr = self.min_lr + (self.base_lr - self.min_lr) * 0.5 * (1 + math.cos(math.pi * progress))

        for param_group in self.optimizer.param_groups:
            param_group['lr'] = lr

        self.current_epoch += 1
        return lr

# 사용 예시
optimizer = torch.optim.AdamW(model.parameters(), lr=0.001)
scheduler = WarmupCosineScheduler(
    optimizer,
    warmup_epochs=5,
    total_epochs=100,
    base_lr=0.001
)

for epoch in range(100):
    train_one_epoch(model, optimizer)
    current_lr = scheduler.step()
    print(f"Epoch {epoch}: lr = {current_lr:.6f}")
```

## 8. 자주 묻는 질문

### Q1: 학습률을 어떤 값으로 시작해야 하나요?

**A:**
```
Adam을 사용한다면: 0.001로 시작
SGD를 사용한다면: 0.01 또는 0.1로 시작

이것으로 학습이 안되면:
- 손실이 NaN → 10배 줄이기
- 손실이 안 줄어듦 → 10배 키우기
```

### Q2: 학습률과 배치 크기의 관계는?

**A:**
```
경험적 법칙: 배치 크기를 2배로 키우면, 학습률도 2배로 키워야 함

이유:
- 큰 배치 = 더 정확한 기울기 추정 = 더 큰 보폭 가능
- 작은 배치 = 노이즈가 많은 기울기 = 작은 보폭 필요

예시:
  배치 32, lr=0.001
  배치 64, lr=0.002
  배치 128, lr=0.004
```

### Q3: 학습률을 자동으로 찾아주는 방법이 있나요?

**A:**
```
1. Learning Rate Finder (위 코드 참조)
   - 손실이 가장 빠르게 줄어드는 학습률 찾기

2. ReduceLROnPlateau
   - 검증 손실 정체 시 자동 감소

3. 적응형 옵티마이저 (Adam, AdamW)
   - 내부적으로 학습률을 파라미터별로 조정
   - 그래도 기본 학습률은 설정해야 함

4. 자동 하이퍼파라미터 튜닝 (Optuna, Ray Tune)
   - 여러 학습률을 자동으로 시도
```

### Q4: 학습 중에 손실이 갑자기 튀면?

**A:**
```
원인 1: 학습률이 너무 큼
→ 해결: 학습률 줄이기

원인 2: 데이터에 이상치(outlier)가 있음
→ 해결: Gradient Clipping 적용

원인 3: 배치 정규화 레이어 문제
→ 해결: model.train() 모드 확인

Gradient Clipping 적용:
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
```

### Q5: 전이학습 시 학습률은 어떻게?

**A:**
```
전이학습 (Pre-trained 모델 사용) 시:

사전학습된 층:
- 이미 좋은 가중치를 가지고 있음
- 작은 학습률 사용 (예: 0.0001)
- 미세 조정만 필요

새로 추가한 층:
- 랜덤 초기화 상태
- 상대적으로 큰 학습률 (예: 0.001)

# 코드 예시
optimizer = torch.optim.Adam([
    {'params': model.backbone.parameters(), 'lr': 0.0001},  # 작게
    {'params': model.classifier.parameters(), 'lr': 0.001}  # 크게
])
```

## 9. 정리 및 Quick Reference

### 9.1 한 줄 요약

```
학습률 = "한 번에 얼마나 가중치를 바꿀지"를 결정하는 가장 중요한 하이퍼파라미터
```

### 9.2 빠른 참조 테이블

| 옵티마이저 | 시작 학습률 | 스케줄링 | 비고 |
|-----------|-----------|---------|------|
| SGD | 0.01 ~ 0.1 | StepLR 또는 Cosine | Momentum=0.9 추가 |
| Adam | 0.001 | 선택적 | 가장 무난한 선택 |
| AdamW | 0.001 | Warmup + Cosine | Transformer 표준 |

### 9.3 트러블슈팅 가이드

| 증상 | 원인 | 해결책 |
|------|------|--------|
| 손실이 NaN | lr 너무 큼 | lr을 1/10로 |
| 손실이 안 줄어듦 | lr 너무 작음 | lr을 10배로 |
| 손실이 진동 | lr 약간 큼 | lr을 1/2 ~ 1/3로 |
| 학습 초반 불안정 | 초기 lr 너무 큼 | Warmup 추가 |
| 수렴 후 정체 | 고정 lr | 스케줄링 추가 |

### 9.4 실전 체크리스트

```
□ 옵티마이저 선택 (처음이면 Adam)
□ 시작 학습률 설정 (Adam이면 0.001)
□ 몇 에포크 돌려보며 손실 확인
□ 필요시 학습률 조정
□ 스케줄러 추가 고려 (긴 학습 시)
□ 최종 성능 확인
```
