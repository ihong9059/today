## 9-1: 프로젝트 개요

### Q1. 번호판 인식 시스템을 왜 2단계로 나누나요?

**A:** 2단계 구조(검출 → 인식)의 장점:
1. **디버깅 용이**: 검출 문제인지 인식 문제인지 분리해서 파악 가능
2. **모듈 교체 쉬움**: 검출 모델만 업그레이드하거나, 인식 모델만 교체 가능
3. **학습 용이**: 각 단계를 독립적으로 학습하여 난이도 분산
4. **데이터 효율**: End-to-End보다 적은 데이터로 학습 가능

```
End-to-End: 이미지 → 바로 텍스트 (어려움)
2-Stage: 이미지 → 검출(박스) → 인식(텍스트) (쉬움)
```

## 9-2: 데이터 수집/준비

### Q4. "데이터가 60%"라는 말의 의미는?

**A:** AI 프로젝트 시간 배분을 보면:
- 데이터 수집/정제: 40%
- 데이터 라벨링: 20%
- 모델 설계/학습: 25%
- 평가/배포: 15%

데이터 관련 작업이 **전체의 60%**를 차지합니다.
**"Garbage In, Garbage Out"** - 데이터 품질이 모델 성능을 결정합니다.

### Q5. YOLO 라벨 형식은 어떻게 생겼나요?

```
# <class_id> <x_center> <y_center> <width> <height>
# 모든 값은 0~1 사이로 정규화

0 0.448 0.426 0.104 0.037
```

- `class_id`: 클래스 번호 (0 = 번호판)
- `x_center, y_center`: 박스 중심 좌표 (이미지 크기로 나눈 값)
- `width, height`: 박스 크기 (이미지 크기로 나눈 값)

### Q6. 데이터 증강(Augmentation)은 왜 필요한가요?

**A:** 학습 데이터의 다양성을 높여 모델의 일반화 성능을 향상시킵니다.

| 증강 기법 | 시뮬레이션 대상 |
|----------|---------------|
| 밝기/대비 변화 | 주간/야간, 역광 |
| 가우시안 노이즈 | 카메라 센서 노이즈 |
| 모션 블러 | 이동 중 촬영 |
| 회전 | 기울어진 촬영 |
| 비/안개 효과 | 악천후 |

**주의**: 원본 1장 → 5장 변형은 가능하지만, 새로운 장면을 만들어내지는 않습니다.

### Q9. One-stage vs Two-stage 검출기의 차이는?

| 항목 | Two-stage (Faster R-CNN) | One-stage (YOLO) |
|------|-------------------------|------------------|
| 작동 방식 | 후보 영역 생성 → 분류 | 한 번에 위치 + 분류 |
| 속도 | 느림 (5~10 FPS) | 빠름 (30~100+ FPS) |
| 적합한 용도 | 정밀 검출 | 실시간 처리 |

**비유**: Two-stage는 "답이 될 만한 것 추리기 → 정답 고르기", One-stage는 "바로 답 쓰기"

---

### Q10. NMS(Non-Maximum Suppression)란?

하나의 물체에 대해 여러 박스가 겹칠 수 있습니다. NMS는 **가장 신뢰도가 높은 박스만 남기는** 후처리 기법입니다.

```
검출 결과: 박스1(conf=0.95), 박스2(conf=0.87), 박스3(conf=0.72)
   ↓ NMS 적용
최종 결과: 박스1(conf=0.95) - 가장 높은 신뢰도만 선택
```

## 9-5: 모델 통합 및 평가

### Q15. IoU(Intersection over Union)란?

예측 박스와 정답 박스의 **겹침 정도**를 측정하는 지표입니다.

```
IoU = (교집합 면적) / (합집합 면적)
```

- IoU ≥ 0.5: 검출 성공으로 판정
- IoU = 1.0: 완벽하게 일치

---

### Q16. mAP(mean Average Precision)란?

**검출 모델의 종합 성능 지표**입니다.

| 지표 | 의미 |
|------|------|
| mAP@0.5 | IoU 50% 기준 평균 정밀도 |
| mAP@0.5:0.95 | 다양한 IoU 기준의 평균 |

목표: mAP@0.5 ≥ 0.95

---

### Q17. Confusion Matrix는 무엇을 보여주나요?

**어떤 클래스를 어떻게 혼동하는지** 한눈에 보여줍니다.

```
            예측
           가  나  다
실  가    [95  3  2]   ← 가를 정확히 예측
제  나    [ 2 93  5]   ← 나를 정확히 예측
    다    [ 1  4 95]   ← 다를 정확히 예측
```

대각선: 정확한 예측 / 비대각선: 혼동

### Q18. 전체 시스템 정확도 계산 방법은?

```
전체 정확도 = 검출 정확도 × (문자 정확도)^글자수
```

예: 검출 96%, 문자 98%, 7글자
```
0.96 × (0.98)^7 = 0.96 × 0.868 = 0.833 (83.3%)
```

**문자 정확도가 높아야 하는 이유**: 글자 수만큼 거듭제곱되기 때문

## 9-7: MLOps 기초

### Q23. MLOps란 무엇인가요?

**ML + Operations = MLOps**

모델을 한 번 만들고 끝이 아니라, 데이터 변화에 따라 지속적으로 업데이트하고 운영하는 전체 과정을 체계화하는 방법론입니다.

| 전통 소프트웨어 | ML 시스템 |
|--------------|-----------|
| 코드 배포 | 코드 + 모델 배포 |
| 에러 모니터링 | + 예측 품질 모니터링 |
| 코드 수정 | 재학습 (데이터 변경 시) |

---

### Q24. 모델 드리프트(Model Drift)란?

시간이 지나면서 **모델 성능이 떨어지는 현상**입니다.

원인:
- 데이터 분포 변화 (새로운 번호판 형식, 새 차종)
- 환경 변화 (카메라 교체, 조명 변화)

대응: 지속적 모니터링 + 재학습

---

### Q25. A/B 테스트는 왜 필요한가요?

새 모델을 **전체 교체하면 위험**합니다. 트래픽의 일부(10%)만 새 모델로 보내서 성능을 비교합니다.

```
요청 100개 → 모델 A (90개)
           → 모델 B (10개) - 신규 모델 테스트
```

성능이 좋으면 점차 비율을 늘려 최종 전환합니다.
