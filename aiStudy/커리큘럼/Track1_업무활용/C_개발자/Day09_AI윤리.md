## 실습 1: AI 코드의 보안 취약점 (15분)

### 일부러 취약한 코드 생성 요청
```
사용자 로그인 API를 만들어줘. 간단하게.
```

→ Claude가 생성한 코드에서 보안 문제 찾기:

```
위 코드를 OWASP Top 10 기준으로 보안 검토해줘.
발견된 취약점, 심각도, 수정 코드를 각각 제시해줘.
```

### 흔한 AI 코드 보안 문제
| 취약점 | 예시 | 심각도 |
|--------|------|:------:|
| SQL Injection | f-string으로 쿼리 생성 | 높음 |
| 하드코딩 시크릿 | API 키 코드에 직접 삽입 | 높음 |
| 입력 검증 누락 | 사용자 입력을 그대로 사용 | 중간 |
| 에러 정보 노출 | 스택트레이스 응답에 포함 | 중간 |
| CORS 설정 누락 | allow_origins=["*"] | 중간 |

### 핵심
> **AI가 생성한 코드는 "동작"하지만 "안전"하지 않을 수 있다.**
> AI 코드 → 보안 리뷰 → 테스트 → 배포 순서를 반드시 지킨다.

## 실습 4: 개발팀 AI 코딩 정책 (15분)

### Claude Code로 생성
```
개발팀 "AI 코딩 정책"을 작성해줘.

대상: 개발팀 전원 (주니어~시니어)
분량: A4 2페이지

포함:
1. AI 코딩 도구 허용 목록 (Claude Code, GitHub Copilot 등)
2. 허용 범위
   - ✅ 코드 초안 생성, 리팩토링, 테스트, 문서화
   - ✅ 에러 디버깅, 코드 설명
   - ⚠️ 조건부: 새 아키텍처 설계 (시니어 리뷰 필수)
   - ❌ 금지: 고객 데이터 입력, 보안 키 입력, 프로덕션 직접 배포
3. 필수 프로세스
   - AI 코드 → 로컬 테스트 → 코드 리뷰 → CI 통과 → 머지
   - AI 코드는 반드시 이해한 후 커밋 (설명할 수 없는 코드 금지)
4. 보안 규칙
   - .env, API 키, 고객 데이터 절대 입력 금지
   - AI 생성 코드 OWASP 체크 의무
5. 기밀 코드 입력 범위
   - 사내 핵심 비즈니스 로직: 입력 금지
   - 일반적인 CRUD/유틸리티: 입력 가능
6. 커밋 규칙
   - AI 보조 사용 시 커밋 메시지에 명시 (선택)

파일명: 팀_AI_코딩_정책.md
```
