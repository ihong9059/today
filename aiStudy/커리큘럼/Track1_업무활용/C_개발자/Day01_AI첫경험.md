# Day 1: AI 첫 경험 — "Claude에게 기술 상담을 받자"

## 학습 목표
- Claude를 시니어 개발자/아키텍트로 활용하는 패턴 체험
- 기술 의사결정에 AI 활용
- 개발 워크플로우에서 AI 활용 영역 파악

---

## 실습 1: Claude를 시니어 개발자로 (10분)

```
당신은 15년 경력의 풀스택 시니어 엔지니어입니다.
Python, JavaScript, Docker, AWS 전문가입니다.

저는 3년차 백엔드 개발자이고, 현재 FastAPI로 REST API 서버를 운영 중입니다.
사용자가 늘어나면서 응답 속도가 느려지고 있습니다.

다음을 분석해주세요:
1. 일반적인 병목 원인 Top 5
2. 각 원인별 진단 방법
3. 해결 방안 (비용/효과/난이도 표)
4. 우선순위 추천 (바로 할 것 vs 나중에 할 것)
```

### 관찰 포인트
- 답변이 실무에 바로 적용 가능한 수준인가?
- 주니어에게 설명하듯 단계적인가, 시니어에게 말하듯 간결한가?

## 실습 2: 기술 스택 상담 (10분)

```
새 프로젝트를 시작하려고 합니다.
요구사항:
- 사용자 5만명 규모 웹 서비스
- 실시간 알림 (WebSocket)
- 모바일 앱도 필요 (iOS + Android)
- 팀 구성: 백엔드 2명, 프론트 1명, 모바일 1명
- 기간: 6개월

기술 스택을 추천해주세요.
각 선택지의 장단점과 대안을 표로 비교해주세요.
팀 규모를 고려한 현실적 제안을 해주세요.
```

## 실습 4: 개발자 AI 활용 영역 분석 (10분)

```
저의 주간 개발 업무를 나열하면:
- 코드 작성 (새 기능 구현)
- 코드 리뷰 (팀원 PR 3~5개/주)
- 버그 수정 (디버깅)
- 기술 문서 작성 (README, API docs)
- 회의 (스크럼, 설계 리뷰)
- 테스트 작성 (유닛/통합)
- 인프라 관리 (Docker, CI/CD)
- 기술 조사 (새 라이브러리, 트렌드)
- 코드 리팩토링
- 온콜/장애 대응

각 업무별로:
1. AI 활용도 (상/중/하)
2. 구체적 활용 방법
3. 주의할 점
표로 정리해주세요.
```

## 강사 참고 사항
- 개발자는 AI에 대한 기대/우려가 모두 높음 — 실용적 사례 중심
- "AI가 코드를 대신 쓴다"보다 "AI가 시니어 동료 역할을 한다"로 프레이밍
- 기술 스택 상담 결과를 비판적으로 검토하도록 유도 — "왜 이걸 추천했을까?"
- 주니어/시니어 혼재 시, 주니어에게는 "학습 가속기", 시니어에게는 "효율 도구"로 차별화
