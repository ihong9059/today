# Day 2: 프롬프트 엔지니어링 — "같은 요청도 다르게 하면 결과가 다르다"

## 학습 목표
- 프롬프트 품질이 업무 결과를 좌우함을 체험
- 역할 부여 / 맥락 제공 / 형식 지정 / 단계적 지시 4가지 기법
- 업무용 프롬프트 템플릿 만들기

---

## 실습 1: 이메일 프롬프트 비교 (15분)

### 나쁜 프롬프트
```
거래처에 이메일 써줘
```

### 보통 프롬프트
```
거래처에 납기 연장 요청 이메일 써줘
```

### 좋은 프롬프트
```
당신은 B2B 영업 10년 경력의 전문가입니다.

아래 상황에 맞는 거래처 이메일을 작성해주세요.

상황:
- 발신: ○○기업 영업팀 김대리
- 수신: △△전자 구매팀 박과장
- 목적: 납기일 1주 연장 요청 (원자재 수급 지연)
- 기존 납기: 5월 20일 → 변경 희망: 5월 27일
- 관계: 3년 거래, 우호적

조건:
- 톤: 정중하되 자신감 있게
- 대안 제시 포함 (부분 선적 가능)
- 재발 방지 대책 언급
- 분량: 10줄 이내
```

### 비교 분석
| 항목 | 나쁜 | 보통 | 좋은 |
|------|------|------|------|
| 상황 반영 | ✕ | △ | ○ |
| 바로 발송 가능? | ✕ | △ | ○ |
| 전문성 | 낮음 | 보통 | 높음 |

## 실습 2: 보고서 프롬프트 패턴 (15분)

### 패턴 1: 역할 + 맥락 + 조건 + 형식

```
[역할] 당신은 ○○ 전문가입니다.
[맥락] 저는 ○○팀 ○○직급이고, ○○ 상황입니다.
[조건] 다음 조건을 만족해주세요: ...
[형식] 마크다운 표 / 번호 목록 / 3페이지 분량으로 출력해주세요.
```

### 패턴 2: 단계적 지시 (Chain of Thought)

```
다음 순서로 진행해주세요:
1. 먼저 시장 현황을 분석하고
2. 그 다음 경쟁사를 3개 비교하고
3. 우리의 강점/약점을 도출하고
4. 마지막으로 전략 3가지를 제안해주세요
```

### 패턴 3: 출력 형식 지정

```
다음 형식으로 출력해주세요:
- 요약: 3줄 이내
- 본문: 마크다운 표
- 결론: 액션 아이템 3개 (담당자/기한 포함)
```

### 연습 문제
아래를 좋은 프롬프트로 바꿔보세요:
1. "회의록 써줘" → ?
2. "마케팅 전략 알려줘" → ?
3. "경쟁사 분석해줘" → ?

## 실습 3: 업무 문서 2종 비교 (10분)

같은 주제로 **두 가지 톤**의 보고서를 요청:

### 보고서 A: 상사 보고용 (간결)
```
2분기 매출 실적을 상사에게 보고하는 1페이지 요약 보고서를 작성해주세요.
핵심 수치 + 원인 분석 + 대응 방안, 3단 구성.
그래프 대신 표로. 전문적이고 간결하게.
```

### 보고서 B: 팀 공유용 (상세)
```
같은 내용을 팀원 공유용 상세 보고서로 작성해주세요.
배경 설명 포함, 부서별 실적, 문제점 상세 분석.
다음 분기 팀별 액션 아이템 포함.
```

### 비교
| 항목 | A (상사 보고) | B (팀 공유) |
|------|:---:|:---:|
| 분량 | | |
| 디테일 | | |
| 액션 아이템 | | |
| 적절한 상황 | | |

## 실습 4: 나만의 업무 프롬프트 템플릿 (10분)

자기 업무에서 가장 자주 하는 작업 1개를 골라 최적 프롬프트를 만드세요:

```markdown
# 나의 업무 프롬프트 템플릿

## 업무: [예: 주간 보고서 작성]

## 프롬프트:
당신은 [역할]입니다.
[맥락/상황 설명]

다음 조건에 맞게 [결과물]을 작성해주세요:
- 조건 1:
- 조건 2:
- 조건 3:

출력 형식: [표/목록/문단]
분량: [A4 1페이지/500자/3문단]

## 이 프롬프트가 효과적인 이유:
- 역할:
- 맥락:
- 형식:
```

## 강사 참고 사항
- "프롬프트 = 업무 지시서"라는 비유가 직장인에게 공감
- "신입에게 일 시킬 때처럼 구체적으로" → 프롬프트 품질 향상
- 직무별로 다른 프롬프트를 만들게 하고 서로 공유하면 효과적
