# 사전 빌드 DB 구조 및 매칭 전략

> **목적:** 사전 빌드된 펌웨어를 DB에 저장하고, 학생 입력과 비교하여 즉시 제공하는 구조 정의
> **작성일:** 2026-04-16

---

## 1. DB 레코드 구조

### 1.1 기본 필드 (필수)

```
┌──────────────────────────────────────────────────────────────┐
│                       DB 레코드 1건                           │
│                                                              │
│  no              001                    ← 고유 번호           │
│  user_prompt     "빨간 LED 1초마다 깜빡이기"  ← 사용자 프롬프트   │
│  system_prompt   SYSTEM_PROMPT + user_prompt ← 합성된 전체 프롬프트│
│  firmware_bin    firmware.bin (650KB)    ← 빌드된 바이너리      │
│  guide           설명자료 (JSON)          ← 동작설명+퀴즈+코드   │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 확장 필드 (매칭/필터링/운영용)

```
┌──────────────────────────────────────────────────────────────┐
│                      확장 필드                                │
│                                                              │
│  tags            ["빨간","LED","깜빡","blink","1초"]  ← 매칭용  │
│  difficulty      1 (1=기초, 2=중급, 3=고급, 4=프로)   ← 난이도  │
│  components      ["led_red"]                        ← 사용 부품│
│  category        "A"                                ← 카테고리 │
│  firmware_size   651344                             ← 파일 크기│
│  firmware_sha256 "a1b2c3..."                        ← 무결성   │
│  use_count       47                                 ← 사용 횟수│
│  last_used       "2026-04-15"                       ← 최근 사용│
│  code_ino        (생성된 코드 원본)                    ← 학습용  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 2. 매칭 전략

### 2.1 기본 동작 — 예시 리스트에서 선택

현재 앱의 예시 프롬프트 리스트(접기/펼치기)를 그대로 활용합니다.
학생이 리스트에서 예시를 터치하면 **DB에서 즉시 bin + guide를 제공**합니다.

```
  ┌─── 🏠 홈 탭 (현재 UI 구조 유지) ──────────────────────┐
  │                                                       │
  │  ▶ 예시 프롬프트 (터치하여 펼치기)                       │
  │  ┌───────────────────────────────────────────────┐   │
  │  │  [LED 기초]                                    │   │
  │  │   ⚡ 빨간 LED 켜기                              │   │
  │  │   ⚡ 빨간 LED 1초마다 깜빡이기                   │   │
  │  │   ⚡ 빨간 LED 5번 깜빡이고 멈추기                │   │
  │  │                                               │   │
  │  │  [LED 응용]                                    │   │
  │  │   ⚡ 신호등 만들기                               │   │
  │  │   ⚡ 비상등 만들기                               │   │
  │  │   ...                                         │   │
  │  │                                               │   │
  │  │  [멜로디]                                      │   │
  │  │   ⚡ 학교종 멜로디 연주하기                       │   │
  │  │   ⚡ 반짝반짝 작은별 연주하기                     │   │
  │  │   ...                                         │   │
  │  └───────────────────────────────────────────────┘   │
  │                                                       │
  │  학생이 예시 터치 → 즉시 bin 다운로드 → BLE 전송 ⚡     │
  │                                                       │
  └───────────────────────────────────────────────────────┘
```

### 2.2 수동 입력 시 — 태그 매칭으로 DB 검색

학생이 예시 리스트를 사용하지 않고 **직접 입력**할 경우,
입력 내용과 DB의 tags를 비교하여 유사한 사전빌드 항목이 있으면 그것을 사용합니다.

```
  학생이 직접 입력
       │
       ▼
  ┌─ 1단계: DB tags 매칭 ────────────────────────────────┐
  │                                                       │
  │  학생 입력에서 키워드 추출 → DB tags와 비교              │
  │                                                       │
  │  학생: "빨간 LED 깜빡여줘"                              │
  │  추출: ["빨간", "LED", "깜빡"]                          │
  │  매칭: A05 tags=["빨간","LED","깜빡",...] → 3개 일치!   │
  │                                                       │
  │  → 가장 유사한 항목의 bin + guide 즉시 제공 ⚡           │
  │                                                       │
  └───────────────────────────────────────────────────────┘
       │ 매칭 점수 낮음 (유사 항목 없음)
       ▼
  ┌─ 2단계: 실시간 빌드 (기존 방식) ──────────────────────┐
  │                                                       │
  │  Claude CLI → 코드 생성 → Arduino 빌드 → BLE 전송      │
  │  (~50초 소요)                                          │
  │                                                       │
  └───────────────────────────────────────────────────────┘
```

**매칭 점수 기준:**

```
  학생 입력에서 키워드 추출 → DB 각 항목과 비교

  점수 계산:
  ├── user_prompt 정확 일치: → 즉시 사용 (100점)
  ├── 태그 매칭: +3점/태그
  └── 매칭 임계값: 6점 이상이면 DB 항목 사용, 미만이면 실시간 빌드
```

| 학생 입력 | 매칭 항목 | 점수 | 결과 |
|----------|----------|:----:|------|
| "빨간 LED 1초마다 깜빡이기" | A05 (정확 일치) | 100 | ⚡ 즉시 |
| "빨간 LED 깜빡여줘" | A05 (빨간+LED+깜빡 = 9점) | 9 | ⚡ 즉시 |
| "빨간불 깜빡이기" | A05 (빨간+깜빡 = 6점) | 6 | ⚡ 즉시 |
| "무지개 LED 3개 회전" | H03 (LED = 3점) | 3 | 🚀 실시간 빌드 |
| "뭔가 재미있는 거" | (매칭 없음) | 0 | 🚀 실시간 빌드 |

### 2.3 태그 설계 기준

각 프롬프트마다 아래 기준으로 태그를 부여합니다.

| 부품 | 태그 |

| 멜로디 | 멜로디, 음악, 노래, 도레미, 음계, tone, 연주 |
| OLED | OLED, 화면, 디스플레이, 표시, 스크린 |
| 센서 | 온도, 습도, 센서, 온습도, 온도계, 측정 |
| 스위치 | 스위치, 버튼, 누르, 눌러 |
| BLE | BLE, 블루투스, 스마트폰, 전송, 원격 |

| 동작 | 태그 |

## 3. 사용 통계 수집

### 3.1 수집 항목

```json
{
  "no": "A05",
  "use_count": 47,
  "last_used": "2026-04-15T14:30:00",
  "usage_log": [
    {"date": "2026-04-10", "count": 12},
    {"date": "2026-04-11", "count": 8},
    {"date": "2026-04-15", "count": 27}
  ]
}
```

### 3.2 활용 방안

| 활용 | 내용 |
|------|------|
| **인기 순 정렬** | use_count 높은 순으로 추천 목록 상단 배치 |
| **미사용 항목 파악** | use_count=0인 항목 → 프롬프트 개선 또는 제거 검토 |
| **수업 분석** | 어떤 카테고리가 가장 많이 사용되는지 파악 |
| **난이도 조정** | 기초인데 안 쓰이는 항목 → 너무 쉬워서? 프롬프트가 매력적이지 않아서? |

### 3.3 통계 API

```
GET /api/v1/stats
→ {
    "total_uses": 1234,
    "top_10": [{"no":"A05","prompt":"...","count":47}, ...],
    "by_category": {"A": 234, "B": 156, ...},
    "by_difficulty": {"1": 500, "2": 400, "3": 200, "4": 134}
  }
```

## 4. 저장 형식

### 4.1 파일 시스템 기반 (권장)

```
firmware_db/
├── catalog.json              ← 전체 목록 (매칭 데이터 포함)
├── stats.json                ← 사용 통계
│
├── A05/                      ← 프롬프트 no별 폴더
│   ├── firmware.bin          ← 빌드된 바이너리
│   ├── code.ino              ← AI 생성 코드 원본
│   ├── system_prompt.txt     ← 합성된 전체 프롬프트
│   └── guide.json            ← 설명자료
│
├── A06/
│   ├── firmware.bin
│   ├── code.ino
│   ├── system_prompt.txt
│   └── guide.json
│
└── ...
```

### 4.2 catalog.json (매칭용 인덱스)

앱 시작 시 1회 로드하여 클라이언트에 캐싱합니다.
매칭/검색/필터는 모두 클라이언트에서 수행합니다 (서버 부하 없음).

```json
{
  "version": "1.0",
  "board": "ESP32-WROOM-32",
  "build_date": "2026-04-20",
  "total": 178,
  "items": [
    {
      "no": "A01",
      "user_prompt": "빨간 LED 켜기",
      "tags": ["빨간", "빨강", "red", "LED", "켜", "on"],
      "difficulty": 1,
      "components": ["led_red"],
      "category": "A",
      "category_name": "LED 단일 제어",
      "description": "빨간 LED가 계속 켜져 있습니다",
      "firmware_size": 651280
    },
    {
      "no": "A05",
      "user_prompt": "빨간 LED 1초마다 깜빡이기",
      "tags": ["빨간", "빨강", "red", "LED", "깜빡", "blink", "1초", "점멸"],
      "difficulty": 1,
      "components": ["led_red"],
      "category": "A",
      "category_name": "LED 단일 제어",
      "description": "1초 간격으로 깜빡입니다",
      "firmware_size": 651344
    }
  ]
}
```

> **catalog.json 크기 예상:** 178개 × ~300바이트 = ~53KB
> 앱 시작 시 1회 로드, 이후 메모리에서 즉시 검색.

## 5. 전체 동작 흐름 (최종)

```
  ┌─── 앱 시작 ──────────────────────────────────────────┐
  │                                                       │
  │  GET /api/v1/catalog → catalog.json 로드 (1회)        │
  │  → 178개 프롬프트 데이터를 메모리에 캐싱                │
  │  → 예시 리스트에 카테고리별로 표시                       │
  │                                                       │
  └───────────────────────────────────────────────────────┘

  ┌─── 경로 A: 예시 리스트에서 선택 (메인 경로) ─────────────┐
  │                                                       │
  │  예시 프롬프트 리스트 펼치기                              │
  │       │                                               │
  │       ▼                                               │
  │  학생이 예시 터치 (예: "빨간 LED 1초마다 깜빡이기")       │
  │       │                                               │
  │       ▼                                               │
  │  GET /api/v1/prebuilt/{no}                             │
  │  → firmware.bin 즉시 다운로드 (~1초) ⚡                 │
  │                                                       │
  │  GET /api/v1/prebuilt/{no}/guide                       │
  │  → guide.json (설명자료)                               │
  │       │                                               │
  │       ▼                                               │
  │  BLE OTA 전송 (~17초)                                  │
  │       │                                               │
  │       ▼                                               │
  │  완료! 설명자료 + 퀴즈 + 다음 도전 표시                  │
  │  POST /api/v1/stats/{no} (사용 카운트 +1)              │
  │                                                       │
  │  총 소요: ~18초 ⚡                                     │
  │                                                       │
  └───────────────────────────────────────────────────────┘

  ┌─── 경로 B: 수동 입력 ────────────────────────────────┐
  │                                                       │
  │  학생이 직접 프롬프트 입력                               │
  │  "빨간 LED 깜빡여줘"                                   │
  │       │                                               │
  │       ▼                                               │
  │  태그 매칭 (클라이언트에서 catalog.json 검색)             │
  │       │                                               │
  │       ├─ 유사 항목 있음 (점수 6점 이상)                  │
  │       │    → DB의 bin + guide 즉시 제공 ⚡ (~18초)      │
  │       │                                               │
  │       └─ 유사 항목 없음                                 │
  │            → 기존 방식: Claude CLI → 빌드 → BLE (~50초) │
  │                                                       │
  └───────────────────────────────────────────────────────┘
```
