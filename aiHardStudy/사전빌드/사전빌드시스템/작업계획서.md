## 동작 흐름 (최종 확정)

```
  ┌─── 경로 A: 예시 리스트에서 선택 (메인) ─────────────────┐

  │  앱의 예시 프롬프트 리스트 펼치기                          │

  │       → 완료! 설명자료 표시                               │
  │       총 ~18초 ⚡                                        │
  │                                                        │
  └────────────────────────────────────────────────────────┘

  ┌─── 경로 B: 수동 입력 ──────────────────────────────────┐
  │                                                        │
  │  학생이 직접 프롬프트 입력                                │
  │       → 입력 키워드와 DB tags 매칭                        │
  │       → 유사 항목 있음 (6점+) → DB bin 즉시 제공 (~18초)  │

  │                                                        │
  └────────────────────────────────────────────────────────┘
```

### 1-1. prebuild.py 개발 (1일차)

**파일:** `server/prebuild.py`

**1건 빌드 과정:**

```
  catalog_source.json에서 1개 항목 읽기
       │
       ▼
  ① system_prompt 합성
     → 기존 SYSTEM_PROMPT + "\n\nUser request: " + user_prompt
     → system_prompt.txt 저장
       │
       ▼
  ② Claude CLI로 코드 생성
     → claude -p - --output-format text --model claude-sonnet-4-6 --tools ""
     → stdin: system_prompt
     → stdout: 생성된 Arduino 코드
     → code.ino 저장
       │
       ▼
  ③ 코드 병합
     → base firmware(ble_ota_arduino.ino)의 "// ─── LED Task ───" 마커 이전
     → + 마커 + AI 생성 코드
     → #include 줄 제거
     → merged.ino 저장
       │
       ▼
  ④ Arduino-CLI 빌드
     → arduino-cli compile --fqbn esp32:esp32:esp32 ...
     → firmware.bin 저장
     → 실패 시 최대 3회 재시도 (①부터 다시)
       │
       ▼
  ⑤ Claude CLI로 설명자료 생성
     → 별도 프롬프트로 guide.json 형식의 학습 자료 생성
     → guide.json 저장
       │
       ▼
  ⑥ DB 저장
     → firmware_db/{no}/ 에 5개 파일 저장:
        system_prompt.txt, code.ino, merged.ino, firmware.bin, guide.json
```

**스크립트 실행 옵션:**

JSON만 출력하세요:

  "concepts": [{{"term": "개념명", "explanation": "쉬운 설명"}}],
  "code_highlights": [{{"line": "코드", "comment": "설명"}}],
  "try_next": [{{"reason": "다음 도전 제안"}}],

    "question": "퀴즈",
    "options": ["A","B","C","D"],
    "answer": 0,
    "explanation": "정답 설명"
  }}

    # Claude CLI 호출 (현행 방식)

        ["claude", "-p", "-", "--output-format", "text",

**catalog.json 자동 생성:**

빌드 완료 후, 모든 항목의 메타데이터를 모아 catalog.json을 생성합니다.
이 파일은 앱에서 1회 로드하여 예시 리스트 표시 + 태그 매칭에 사용됩니다.

```python
def generate_catalog():
    catalog = {"version": "1.0", "board": "ESP32-WROOM-32", "total": 0, "items": []}

    for item in source_items:
        no = item["no"]
        bin_path = FIRMWARE_DB / no / "firmware.bin"
        if not bin_path.exists():
            continue
        bin_data = bin_path.read_bytes()

        catalog["items"].append({
            "no": no,
            "user_prompt": item["user_prompt"],
            "tags": item["tags"],
            "difficulty": item["difficulty"],
            "components": item["components"],
            "category": item["category"],
            "category_name": item["category_name"],
            "description": item["description"],
            "firmware_size": len(bin_data),
            "firmware_sha256": hashlib.sha256(bin_data).hexdigest()
        })

    catalog["total"] = len(catalog["items"])
    (FIRMWARE_DB / "catalog.json").write_text(json.dumps(catalog, ensure_ascii=False, indent=2))
```

### 2-1. API 엔드포인트

| API | Method | 용도 |
|-----|--------|------|
| `/api/v1/catalog` | GET | 전체 카탈로그 (예시 리스트 + 태그 매칭용) |
| `/api/v1/prebuilt/{no}` | GET | firmware.bin 다운로드 |
| `/api/v1/prebuilt/{no}/guide` | GET | 설명자료 조회 |
| `/api/v1/prebuilt/{no}/code` | GET | 생성 코드 조회 |
| `/api/v1/stats/{no}` | POST | 사용 카운트 +1 |

```python
FIRMWARE_DB = Path.home() / "vibe-firmware" / "firmware_db"
_catalog = None

@app.on_event("startup")
async def startup():
    global _catalog
    cat_path = FIRMWARE_DB / "catalog.json"
    if cat_path.exists():
        _catalog = json.loads(cat_path.read_text(encoding="utf-8"))

@app.get("/api/v1/catalog")
async def get_catalog():
    if not _catalog:
        raise HTTPException(404, "Catalog not found")
    return _catalog

@app.get("/api/v1/prebuilt/{no}")
async def get_prebuilt(no: str):
    bin_path = FIRMWARE_DB / no / "firmware.bin"
    if not bin_path.exists():
        raise HTTPException(404, f"Firmware {no} not found")
    return FileResponse(path=str(bin_path),
        filename=f"firmware_{no}.bin",
        media_type="application/octet-stream")

@app.get("/api/v1/prebuilt/{no}/guide")
async def get_guide(no: str):
    guide_path = FIRMWARE_DB / no / "guide.json"
    if not guide_path.exists():
        raise HTTPException(404, f"Guide {no} not found")
    return json.loads(guide_path.read_text(encoding="utf-8"))

@app.get("/api/v1/prebuilt/{no}/code")
async def get_code(no: str):
    code_path = FIRMWARE_DB / no / "code.ino"
    if not code_path.exists():
        raise HTTPException(404, f"Code {no} not found")
    return {"code": code_path.read_text(encoding="utf-8")}

@app.post("/api/v1/stats/{no}")
async def update_stats(no: str):
    stats_path = FIRMWARE_DB / "stats.json"
    stats = json.loads(stats_path.read_text()) if stats_path.exists() else {}
    stats[no] = stats.get(no, 0) + 1
    stats_path.write_text(json.dumps(stats))
    return {"no": no, "count": stats[no]}
```

> 기존 API (`/api/v1/generate`, `/api/v1/status`, `/api/v1/download` 등)는 **그대로 유지**.
> 자유 프롬프트 실시간 빌드는 기존 방식으로 동작.

### 3-2. 수동 입력 태그 매칭 (1일차)

학생이 예시 리스트를 사용하지 않고 **직접 입력**할 때,
입력 내용을 catalog의 tags와 비교하여 유사 항목이 있으면 DB 결과를 사용합니다.

```javascript
// 클라이언트 태그 매칭 (catalog.json 메모리 검색)
function findMatchingPrebuilt(userInput) {
    const keywords = userInput.split(/\s+/);
    let bestMatch = null, bestScore = 0;

    for (const item of catalog.items) {
        // 정확 일치
        if (item.user_prompt === userInput) return { item, score: 100 };

        // 태그 매칭
        let score = 0;
        for (const kw of keywords) {
            if (item.tags.some(t => t.includes(kw) || kw.includes(t))) score += 3;
        }
        if (score > bestScore) { bestScore = score; bestMatch = item; }
    }

    return bestScore >= 6 ? { item: bestMatch, score: bestScore } : null;
}
```

**기존 빌드 버튼 동작 변경:**

```
  기존: "🚀 빌드하기" 버튼 → 항상 실시간 빌드

  변경: "🚀 빌드하기" 버튼 →
       ① 입력 내용으로 태그 매칭
       ② 매칭 있음 → DB bin 즉시 사용 ⚡ (사용자에게 안내)
       ③ 매칭 없음 → 기존 실시간 빌드 🚀
```
