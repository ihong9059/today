# 10명 교육 시스템 구성 가이드

## 1. 시나리오 분석

### 수업 상황
- 학생 10명, 각자 스마트폰/PC + UTTEC Board 1대
- 교사 1명, 교사 PC에서 서버 운영
- 학생들이 자유롭게 프롬프트를 입력하여 LED/부저/센서 등을 제어

### 요청 유형별 처리

```
학생 요청
   │
   ├─ 80~90% ─→ 사전빌드 매칭 (즉시 전송, 0.1초)
   │             "LED 깜빡여", "부저 울려", "온도 보여줘"
   │             → 서버 부하 거의 없음
   │
   └─ 10~20% ─→ AI 커스텀 빌드 (~1분)
                 "하트 모양으로 LED 깜빡여", "가위바위보 만들어줘"
                 → Claude API + Arduino 컴파일 필요
```

### 최악의 상황 시뮬레이션

```
10명 동시 새 요청 (확률 매우 낮지만 대비 필요)

현재 (순차 빌드):
  학생1: 0분 → 빌드 시작 → 1분 완료
  학생2: 1분 → 빌드 시작 → 2분 완료
  ...
  학생10: 9분 → 빌드 시작 → 10분 완료  ← 마지막 학생 10분 대기!

3개 병렬 빌드:
  학생1,2,3: 0분 → 동시 빌드 → 1분 완료
  학생4,5,6: 1분 → 동시 빌드 → 2분 완료
  학생7,8,9: 2분 → 동시 빌드 → 3분 완료
  학생10:    3분 → 빌드 → 4분 완료  ← 최대 4분 대기
```

## 2. 권장 PC 사양

### 최소 사양 (10명 교육)

| 항목 | 사양 | 이유 |
|------|------|------|
| CPU | 4코어 8스레드 이상 | 동시 빌드 2개 + 서버 + OS |
| RAM | 8GB 이상 | Arduino CLI 빌드당 ~500MB |
| 저장소 | SSD 50GB 이상 | 빌드 속도 + 펌웨어 DB |
| 네트워크 | 인터넷 필수 | Claude API 호출용 |
| OS | Windows 10/11 또는 Linux | Arduino CLI 지원 |

### 권장 사양 (쾌적한 교육)

| 항목 | 사양 | 이유 |
|------|------|------|
| CPU | **8코어 16스레드** 이상 | 동시 빌드 3개 + 여유 |
| RAM | **16GB** 이상 | 동시 빌드 3개 × 500MB + 서버 |
| 저장소 | SSD 100GB 이상 | 빌드 캐시 + 커스텀 DB 성장 |
| 네트워크 | **유선 LAN** | 안정적인 API 호출 |

### 현재 PC (i5-1235U) 평가

```
CPU: 10코어 12스레드  → ✅ 충분 (동시 3개 빌드 가능)
RAM: ?                → 8GB 이상이면 OK
SSD: ?                → 충분하다면 OK
네트워크: WiFi/유선   → OK

결론: 현재 PC로 10명 교육 가능 (동시 빌드 3개 설정 시)
```

## 4. 네트워크 구성

### 필수 조건
- 교사 PC와 학생 스마트폰이 **같은 WiFi 네트워크**에 연결
- 교사 PC의 IP 주소를 학생 앱에 설정 (예: 192.168.0.20)

### 권장 구성

```
인터넷 ─── 공유기 (WiFi) ─┬─ 교사 PC (유선 LAN, 고정 IP)
                           ├─ 학생1 스마트폰 (WiFi)
                           ├─ 학생2 스마트폰 (WiFi)
                           └─ ...학생10 스마트폰 (WiFi)
```

### 방화벽 설정
- Port 8095 (사전빌드 서버) 허용
- Port 8092 (빌드 서버) 허용

## 5. 수업 진행 프로세스

### 수업 전 준비 (교사)

```
1. 교사 PC에서 서버 시작
   $ python prebuild_server.py    # Port 8095
   $ python build_server_arduino.py  # Port 8092

2. 사전빌드 DB 확인
   http://localhost:8095 → 카탈로그 확인

3. PC IP 확인 (학생에게 공유)
   $ ipconfig → WiFi/이더넷 IP 확인

4. UTTEC Board 충전/전원 확인 (10대)
```

### 수업 시작 (5분)

```
1. 학생들 앱 설치 확인 (UTTEC Cloud)
2. 앱 설정에서 서버 IP 입력
   예: http://192.168.0.20:8095
3. BLE 연결 테스트
   각 학생이 자기 보드에 BLE 연결
4. 간단한 예시 전송 테스트
   "빨간 LED 켜기" → 전송 → 보드 확인
```

### 자유 실습 (본수업)

```
학생 활동:
  1. 카탈로그에서 원하는 항목 선택 → 즉시 전송
  2. 자유 프롬프트 입력 → AI 생성 → 전송
  3. 가이드로 코드 학습 → 퀴즈 풀기
  4. 다음 도전 항목으로 이동

교사 활동:
  1. 교사 PC 웹에서 학생 진행 상황 모니터링
  2. 빌드 서버 상태 확인 (큐 대기 여부)
  3. 학생 질문에 대해 "코딩 질문" 기능 안내
```

### 수업 종료

```
1. 학생들 보드 전원 끄기
2. 서버 종료
3. 수업 중 생성된 커스텀 빌드 확인 (Z01~)
   → 다음 수업에 재활용 가능
```

## 6. 부하 분석

### 요청 처리 시간

| 요청 유형 | CPU | 네트워크 | 시간 | 동시 가능 |
|-----------|-----|----------|------|-----------|
| 사전빌드 다운로드 | 거의 없음 | 650KB | 0.1초 | 10개+ |
| 카탈로그 검색 | 거의 없음 | 수 KB | 0.01초 | 10개+ |
| AI 코드 생성 (Claude) | 거의 없음 | API 호출 | 15~30초 | 10개 (API 제한까지) |
| Arduino 컴파일 | **2코어** | 없음 | 40~50초 | 2~3개 |
| 코딩 질문 답변 | 거의 없음 | API 호출 | 10~20초 | 10개 |

### 병목 지점

```
사전빌드 매칭 → 병목 없음 (즉시)
AI 생성       → Claude API 속도 (네트워크 의존)
Arduino 컴파일 → CPU 병목 (동시 2~3개 제한)
                 ^^^^^^^^
                 이것이 유일한 병목!
```

### 해결 전략 (우선순위)

```
1순위: 사전빌드 카탈로그 최대한 확충
       → 155개 + 수업 중 축적 → AI 빌드 자체를 최소화

2순위: 병렬 빌드 구현 (동시 3개)
       → 최악의 경우에도 10명 × 1분 / 3 = ~4분 내 처리

3순위: 빌드 캐시 활용
       → 비슷한 요청의 코드가 같으면 재컴파일 생략
```

## 7. 확장 (20~30명)

### 추가 고려사항

| 학생 수 | PC 사양 | 동시 빌드 | 비고 |
|:-------:|---------|:---------:|------|
| 10명 | i5 10코어 | 3개 | 현재 PC로 가능 |
| 20명 | i7 12코어+ | 4개 | 16GB RAM 이상 |
| 30명 | i9 또는 서버급 | 5~6개 | 32GB RAM, 또는 빌드 서버 분리 |

### 서버 분리 구성 (30명+)

```
교사 PC        → prebuild_server (카탈로그/웹 UI)
ODROID C2      → build_server (Arduino 컴파일 전담)
클라우드 서버  → Claude API 중계 + 추가 빌드 서버

→ 교사 PC 부하 최소화, 빌드는 전용 서버에서 처리
```
