## 1. 시스템 개요

aiPython은 **스마트폰에서 한국어로 Python 프로그램을 만들고 실행**할 수 있는 교육 플랫폼이다.
사용자가 "주사위 100번 굴려서 히스토그램 그려줘"처럼 자연어로 요청하면, AI(Claude)가 Python 코드를 생성하고, 그 코드를 브라우저(Pyodide) 또는 서버에서 실행하여 결과(그래프/텍스트)를 보여준다.

### 핵심 구성 요소

## 2. 실행 모드 비교

aiPython은 두 가지 실행 모드를 지원한다.

| 항목 | 스마트폰 실행 (browser) | 서버 실행 (server) |
|------|------------------------|-------------------|
| **코드 생성** | 서버 (Claude CLI) | 서버 (Claude CLI) |
| **코드 실행** | 브라우저 (Pyodide/WASM) | 서버 (Python 3.x) |
| **사용 가능 라이브러리** | numpy, matplotlib, Pillow, pandas, scipy | + requests, socket, serial, urllib |
| **네트워크 통신** | 불가 | TCP/HTTP/MQTT 가능 |
| **하드웨어 제어** | 불가 | UART/Serial 가능 |
| **실행 속도** | 느림 (WASM 오버헤드) | 빠름 (네이티브 Python) |
| **오프라인** | 코드 생성 불가 / 직접 입력은 가능 | 불가 |
| **시스템 프롬프트** | SYSTEM_PROMPT | SERVER_SYSTEM_PROMPT |

## 3. 핵심 파이프라인: 코드 생성 + 실행

### 3-1. 전체 흐름도 (브라우저 실행 모드)

```
사용자 입력                서버                              브라우저
    │                       │                                  │
    │  "주사위 100번 굴려서   │                                  │
    │   히스토그램 그려줘"    │                                  │
    │                       │                                  │
    ├──── POST /api/v1/generate ───▶                            │
    │   {prompt, sensor_type,│                                  │
    │    run_on:"browser"}   │                                  │
    │                       │                                  │
    │  ◀── {job_id, status:  │                                  │
    │       "pending"} ──────┤                                  │
    │                       │                                  │
    │   [1초 간격 폴링 시작]  │                                  │
    │                       ├── 비동기 태스크 시작               │
    │                       │   │                              │
    │                       │   ├─ 프롬프트 합성                │
    │                       │   │  (시스템 프롬프트 + 센서 정보  │
    │                       │   │   + 사용자 요청)              │
    │                       │   │                              │
    │                       │   ├─ Claude CLI 호출              │
    │                       │   │  type _prompt.txt |           │
    │                       │   │  claude -p -                  │
    │                       │   │  --output-format stream-json  │
    │                       │   │  --verbose                    │
    │                       │   │                              │
    │                       │   ├─ stream-json 파싱             │
    │                       │   │  → assistant.message.content  │
    │                       │   │  → text 블록 추출             │
    │                       │   │                              │
    │                       │   ├─ 후처리                       │
    │                       │   │  → 마크다운 코드블록 제거      │
    │                       │   │  → 자연어 독백 제거            │
    │                       │   │                              │
    │                       │   └─ jobs[id].status = "success"  │
    │                       │      jobs[id].code = 생성된 코드   │
    │                       │                                  │
    ├──── GET /api/v1/status/{id} ──▶                           │
    │  ◀── {status:"success"} ──────┤                           │
    │                       │                                  │

    │  ◀── {code:"import..."} ──────┤                           │
    │                       │                                  │
    │                       │     ┌── Pyodide 실행 ────────────┤
    │                       │     │  1. stdout 캡처 (StringIO)  │
    │                       │     │  2. /tmp/output.png 삭제    │
    │                       │     │  3. runPythonAsync(code)    │
    │                       │     │  4. stdout 수집             │
    │                       │     │  5. /tmp/output.png 확인    │
    │                       │     │  6. base64 인코딩 → 표시    │
    │                       │     └─────────────────────────────┤
    │                       │                                  │
    │   [결과 표시: 그래프 + 텍스트]                              │
```

### 3-2. 전체 흐름도 (서버 실행 모드)

```
사용자 입력                서버
    │                       │
    ├──── POST /api/v1/generate ───▶
    │   {prompt, run_on:     │
    │    "server"}           │
    │                       ├─ Claude CLI → 코드 생성
    │                       │
    │                       ├─ 서버에서 Python 실행
    │                       │  ├─ /tmp → work_dir 매핑
    │                       │  ├─ subprocess.run(python)
    │                       │  ├─ 30초 타임아웃
    │                       │  ├─ stdout/stderr 캡처
    │                       │  └─ output.png → base64
    │                       │
    ├──── GET /api/v1/status/{id} ──▶
    │  ◀── {status:"success",│
    │       exec_result: {   │
    │         stdout, stderr,│
    │         has_image,     │
    │         image_b64      │
    │       }}               │
    │                       │
    │   [결과 바로 표시]      │
```

**핵심 차이**: 서버 실행 모드에서는 코드 실행 결과가 `exec_result`에 포함되어 status API 응답에 함께 돌아온다. 별도의 code API 호출 후 Pyodide 실행이 필요 없다.

## 4. 서버 상세 (server.py)

### 4-1. 서버 구조

```
FastAPI 서버 (:8080)
├── GET  /              → index.html (Web App)
├── GET  /health        → 서버 상태 + Claude 사용 가능 여부
├── POST /api/v1/generate → 코드 생성 요청 (비동기)
├── GET  /api/v1/status/{id} → 작업 상태 조회
├── GET  /api/v1/code/{id}   → 생성된 코드 조회
├── POST /api/v1/chat   → 코딩 질문 AI (별도)
└── /web/*              → 정적 파일 (JS/CSS/아이콘)
```

### 4-2. Job 생명주기

```
pending → generating → success
                    └→ failed (최대 3회 재시도 후)
```

| 상태 | progress | 설명 |
|------|----------|------|
| pending | 0% | 대기열에 등록됨 |
| generating | 20~60% | Claude CLI 호출 중 (시도 횟수에 따라 증가) |
| (서버 실행시) | 70% | Python 코드 서버에서 실행 중 |
| success | 100% | 완료 |
| failed | - | 3회 재시도 실패 |

### 4-3. Claude CLI 호출 방식

```bash
type "_prompt.txt" | claude -p - --output-format stream-json --verbose
```

- **pipe 방식**: 프롬프트 파일을 `type` 명령으로 stdin에 전달
- **stream-json**: JSON Lines 형식으로 실시간 스트리밍 출력
- **파싱 대상**: `type: "assistant"` → `message.content[]` → `type: "text"` 블록

**중요**: `--output-format text`는 동작하지 않음. 반드시 `stream-json` + type 파이프 방식 사용.

### 4-4. 코드 후처리 (Cleanup)

생성된 코드에서 다음을 제거한다:

1. **마크다운 코드블록**: ` ```python ... ``` ` → 내부 코드만 추출
2. **자연어 독백**: "Wait,", "Let me", "Note:", "The ", "I ", "This ", "Sorry", "Actually" 로 시작하는 줄 이후 전체 삭제

### 4-5. 서버 실행 샌드박스

서버에서 코드를 실행할 때, `/tmp/` 경로를 job별 작업 디렉토리로 매핑한다:

```python
# 코드 내 /tmp/output.png → jobs/{job_id}/output.png 로 리디렉션
builtins.open = _patched_open      # open() 함수 패치
matplotlib.pyplot.savefig = _patched_savefig  # savefig() 패치
```

- **타임아웃**: 30초
- **격리**: 각 job은 `jobs/{job_id}/` 디렉토리에서 독립 실행
- **금지 모듈**: os.system, subprocess, \_\_import\_\_, eval, exec

### 5-2. Pyodide 초기화 파이프라인

```
페이지 로드 (window.onload)
    │
    ├─ checkHealth()          → GET /health → 서버 상태 표시
    │
    └─ initPyodide()
       │
       ├─ loadPyodide()       → CDN에서 Pyodide WASM 다운로드
       │                        (https://cdn.jsdelivr.net/pyodide/v0.27.0/full/)
       │                        약 10~20MB, 첫 로딩 시 5~15초 소요
       │
       ├─ loadPackage()       → numpy, matplotlib, Pillow 설치
       │                        추가 약 10~30초 소요
       │
       ├─ runPython()         → /tmp 디렉토리 생성
       │                        matplotlib Agg 백엔드 설정
       │
       └─ pyodideReady = true → 상태 표시: "Python 준비 완료"
```

**주의**: Pyodide 초기화는 총 20~45초 소요될 수 있다. 이 동안 "스마트폰 실행" 모드는 사용 불가하며, "서버 실행" 모드는 즉시 사용 가능하다.

### 5-3. Pyodide 코드 실행 파이프라인

```
executeCode(code)
    │
    ├─ 1. stdout 캡처 설정
    │     sys.stdout = io.StringIO()
    │
    ├─ 2. 기존 출력 파일 삭제
    │     os.remove('/tmp/output.png')
    │
    ├─ 3. 코드 실행
    │     pyodide.runPythonAsync(code)
    │     → WebAssembly 내에서 Python 인터프리터 실행
    │
    ├─ 4. stdout 수집
    │     sys.stdout = sys.__stdout__
    │     text = _captured.getvalue()
    │
    ├─ 5. 이미지 확인
    │     os.path.exists('/tmp/output.png')
    │     → True면 base64 인코딩 → <img src="data:...">
    │
    └─ 6. 결과 표시
          텍스트 → <div class="result-text">
          이미지 → <img class="result-img">
```

### 5-4. 센서 → Pyodide 데이터 연동

```
[카메라]
  촬영(capturePhoto)
    → canvas.toDataURL('image/jpeg')
    → base64 디코딩
    → pyodide.runPython → /tmp/input.jpg 저장
    → 사용자 프롬프트: "카메라 이미지를 흑백으로 변환해줘"
    → AI 코드: PIL.Image.open('/tmp/input.jpg')

[가속도계]
  DeviceMotionEvent 리스너
    → {x, y, z} 실시간 표시
    → (향후) /tmp/input.json에 배열 저장
    → AI 코드: json.load(open('/tmp/input.json'))

[GPS]
  navigator.geolocation.getCurrentPosition
    → {lat, lng, accuracy}
    → pyodide.runPython → /tmp/input.json 저장
    → AI 코드: json.load(open('/tmp/input.json'))
```

## 6. 코딩 질문 (Chat) 파이프라인

```
사용자: "for문이 뭐야?"

    │  (별도의 시스템 프롬프트: 한국어 답변, 초급자용 설명)
```

코드 생성과 독립적인 별도 파이프라인이며, Pyodide가 로딩되지 않아도 사용 가능하다.

| `/health` | GET | - | `{status, system, claude_available, active_jobs}` |
| `/api/v1/generate` | POST | `{prompt, sensor_type, run_on, retry_on_fail, max_retries}` | `{job_id, status}` |
| `/api/v1/status/{id}` | GET | - | `{job_id, status, progress, message, elapsed, timing, exec_result?}` |
| `/api/v1/code/{id}` | GET | - | `{code, status}` |
| `/api/v1/chat` | POST | `{question}` | `{answer, elapsed}` |

### 8-3. 요청 파라미터 상세

**GenerateRequest**:
| 필드 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| prompt | string | (필수) | 사용자 자연어 요청 |
| sensor_type | string | "none" | "none" / "camera" / "accel" / "geo" |
| run_on | string | "browser" | "browser" (Pyodide) / "server" (서버 Python) |
| retry_on_fail | bool | true | 실패 시 자동 재시도 |
| max_retries | int | 3 | 최대 재시도 횟수 |

## 9. 시스템 프롬프트

### 9-1. 브라우저 모드 (SYSTEM_PROMPT)

AI에게 다음을 지시한다:
- **실행 환경**: Pyodide (WebAssembly)
- **사용 가능 라이브러리**: numpy, matplotlib, Pillow, pandas, scipy, math, random, json, statistics
- **출력**: `/tmp/output.png` (이미지) 또는 `print()` (텍스트)
- **입력**: 센서별 `/tmp/input.jpg` 또는 `/tmp/input.json`
- **제약**: 코드만 출력 (설명 없음), matplotlib 텍스트는 영어, print는 한국어
- **금지**: os.system, subprocess, socket, http, urllib, input()

### 9-2. 서버 모드 (SERVER_SYSTEM_PROMPT)

브라우저 모드와 동일하되 추가 허용:
- **네트워크**: requests, socket, urllib, http.client
- **하드웨어**: serial (pyserial), paho.mqtt
- **제약**: 네트워크 타임아웃 5초, 파일 접근은 /tmp/ 만

## 11. 에러 처리 및 재시도 로직

### 11-1. 코드 생성 재시도

```
시도 1 → Claude CLI 호출 → 실패 시
시도 2 → Claude CLI 호출 → 실패 시
시도 3 → Claude CLI 호출 → 실패 시 → status: "failed"
```

- 각 시도마다 progress 10% 증가 (20% → 30% → 40%)
- 타이밍 정보: `timing.claude_try1`, `timing.error_try1` 등으로 기록
- Claude CLI 타임아웃: 180초 (3분)

### 11-2. 서버 Python 실행

- 타임아웃: 30초 → "실행 시간 초과 (30초)" 에러
- stderr 캡처: 파이썬 에러 트레이스백 전체 반환

### 11-3. 프론트엔드 에러 처리

| 상황 | 처리 |
|------|------|
| Pyodide 로딩 실패 | "Python 로딩 실패: {message}" 표시, 서버 모드 안내 |
| 서버 연결 실패 | "서버 연결 실패: {message}" 표시 |
| Pyodide 실행 오류 | "실행 오류: {traceback}" 빨간색 표시, stdout 복원 |
| 폴링 중 네트워크 오류 | 폴링 중단, 버튼 재활성화 |
