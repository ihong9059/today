## 2. Phase A: 요청 수신 + 프롬프트 합성

### 2.1 처리 흐름

```
클라이언트 (Web App / Flutter)
    │
    │  POST /api/v1/generate  {"prompt": "LED 깜빡이기"}
    ▼
Nginx (443 HTTPS) ─── SSL 종료
    │
    │  proxy_pass
    ▼
Web UI 서버 (8094) ─── httpx 프록시
    │
    │  POST /api/v1/generate
    ▼
빌드 서버 (8092) ─── FastAPI 엔드포인트
    │
    │  job_id 생성 (uuid4[:8])
    │  asyncio.create_task(process_job)
    │
    ▼
process_job 시작
    │
    ├── _init_shared_build()          ← 빌드 캐시 디렉토리 확인
    │   (이미 존재하면 skip)
    │
    └── prepare_prompt()              ← 시스템 프롬프트 합성
        │
        │  SYSTEM_PROMPT (2,314문자, ~330단어)
        │  + "\n\nUser request: " + 사용자 프롬프트
        │  = full_prompt
        │
        │  → _prompt.txt 파일 저장 (디버깅용)
        │
        └── return full_prompt
```

### 2.2 시스템 프롬프트 구조 분석

```
SYSTEM_PROMPT (2,314 chars, ~330 words, ~580 tokens)
├── 역할 정의 (1줄)
│   "You are an ESP32 firmware generator using Arduino framework."
│
├── 하드웨어 사양 (7줄, ~150 chars)
│   - LED x3 핀 + 극성
│   - 부저 x2 핀 + 타입
│   - OLED I2C 주소
│   - AHT20 I2C 주소
│   - 스위치 핀
│
├── API 레퍼런스 (14줄, ~500 chars)
│   - AHT20 API: aht20_read() 시그니처
│   - OLED API: SSD1306 클래스 메서드 5개
│
└── 규칙 12개 (24줄, ~1,500 chars) ★ 가장 큰 부분
    1.  코드만 출력
    2.  setup()+loop()만 정의
    3.  #include 금지
    4.  initHardware()+initBLE() 필수
    5.  표준 Arduino 함수 사용
    6.  LED 태스크 xTaskCreate
    7.  기존 함수 재정의 금지
    8.  oled 전역 객체 사용
    9.  loop()에 delay(10000)
    10. 핀 상수 사용
    11. tone() 전용 (LEDC 금지)
    12. 한국어 주석
```

### 2.3 소요 시간

| 항목 | 시간 | 비고 |
|:-----|:-----|:-----|
| Nginx SSL 종료 | <1ms | 이미 연결된 세션 |
| Web UI → 빌드 서버 프록시 | <5ms | localhost 통신 |
| job_id 생성 + 초기화 | <1ms | uuid4 + dict |
| _init_shared_build | <1ms | 이미 존재하면 skip |
| prepare_prompt | <1ms | 문자열 결합 + 파일 쓰기 |
| **Phase A 합계** | **<10ms** | **병목 없음** |

### 2.4 최적화 여지

| 항목 | 현재 | 최적화 | 효과 |
|:-----|:-----|:-------|:-----|

```
Claude 출력 (raw code)

    │   lines = [l for l if not l.startswith("#include")]
    │

        re.search(r'^(void |static |const |//|#)', ...)

    ▼

    │

    │
    └── 병합: ble_base + marker + user_code
        → ble_ota_arduino.ino 덮어쓰기 (공유 빌드 디렉토리)

    ▼
병합된 .ino 파일 (~400~500줄)

## 5. Phase D: Arduino-CLI 빌드 ★★ 두 번째 병목

### 5.1 처리 흐름

```
병합된 ble_ota_arduino.ino
    │
    ├── 빌드 캐시 무효화
    │   for cached in work_dir.rglob("*.ino.cpp"):
    │       cached.unlink()   ← .ino.cpp 삭제로 재컴파일 강제
    │
    ▼
arduino-cli compile
    │
    │  --fqbn esp32:esp32:esp32
    │  --build-property build.partitions=min_spiffs
    │  --output-dir output/
    │
    ├── [전처리]              ~1초
    │   - .ino → .ino.cpp 변환
    │   - Arduino 프레임워크 헤더 포함
    │   - 매크로 확장
    │
    ├── [컴파일]              ~20~25초 ★★
    │   - xtensa-esp32-elf-g++ 호출
    │   - 사용자 코드 컴파일 (.ino.cpp → .o)
    │   - 라이브러리 컴파일 (NimBLE, Wire, Preferences)
    │   - 증분 빌드: 변경된 파일만 재컴파일
    │   - CPU 바운드: 2 vCPU 100% 사용
    │
    ├── [링킹]               ~5~7초
    │   - xtensa-esp32-elf-ld
    │   - 모든 .o 파일 → ELF 바이너리
    │   - 파티션 테이블 적용 (min_spiffs)
    │
    └── [바이너리 변환]       ~1초
        - ELF → .bin (esptool.py)
        - 부트로더 + 파티션 + 앱 바이너리

    ▼
output/ble_ota_arduino.ino.bin (~650KB)
```
