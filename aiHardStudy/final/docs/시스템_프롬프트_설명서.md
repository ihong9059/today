```

### 2.2 구조 분석

시스템 프롬프트는 4개 섹션으로 구성됩니다:

### 2.3 섹션별 상세 설명

#### 섹션 1: 역할 + 하드웨어 스펙

AI에게 "너는 ESP32 펌웨어 생성기다"라고 역할을 부여하고, 보드의 하드웨어 구성을 알려줍니다.

| 부품 | GPIO | 특성 | 프롬프트에서의 설명 |
|------|------|------|-------------------|
| LED RED | 25 | Active LOW (LOW=ON) | `LED: RED=GPIO25 ... (active LOW: LOW=ON, HIGH=OFF)` |
| LED YELLOW | 26 | Active LOW | 위와 동일 줄 |
| LED BLUE | 27 | Active LOW | 위와 동일 줄 |
| 부저 (BEEP) | 14 | Active LOW | `Buzzer (active LOW): GPIO14` |
| 부저 (멜로디) | 33 | PWM tone() | `Melody buzzer (PWM): GPIO33` |
| OLED | SDA=21, SCL=22 | I2C, 0x3C | `OLED SSD1306 I2C: SDA=GPIO21, SCL=GPIO22, addr=0x3C` |
| 온습도센서 | I2C 공유 | 0x38 | `AHT20 temp/humidity I2C: addr=0x38` |
| 스위치 | 32 | INPUT_PULLUP, Active LOW | `Switch: GPIO32 (INPUT_PULLUP, active LOW)` |

**Active LOW 의미**: GPIO를 LOW로 보내면 켜짐(ON), HIGH로 보내면 꺼짐(OFF). 회로에서 LED가 3.3V와 GPIO 사이에 연결되어 있기 때문입니다. AI가 이것을 모르면 LED ON/OFF가 반대로 생성됩니다.

#### 섹션 2: API 설명

AI가 직접 호출할 수 있는 함수(이미 base firmware에 정의됨)를 알려줍니다.

**AHT20 센서 API:**
```c
float temp, humi;
bool ok = aht20_read(temp, humi);  // true: 성공, false: 실패
// temp = 섭씨 온도, humi = 습도 %
```

- `aht20_read()`는 `ble_ota_arduino.ino`의 149~235줄에 정의됨
- I2C 주소 0x38, 측정 대기 80ms, 에러 코드 반환
- AI는 이 함수를 **호출만** 해야 하고 **재정의하면 안 됨**

**OLED API (ssd1306.h):**
```c
// 이미 전역 선언됨: SSD1306 oled(21, 22);
oled.clear();                    // 화면 지우기 (메모리 버퍼만)
oled.drawString(x, y, "text");   // (x, y) 픽셀 위치에 텍스트 그리기
oled.display();                  // 버퍼 → 실제 화면에 전송
```

- 화면 크기: 128×64 픽셀
- 폰트: 5×7 ASCII (한글 미지원, 영문/숫자/특수문자만)
- `oled.pixel(x, y)`: 개별 픽셀 그리기도 가능
- **반드시 `display()` 호출해야** 화면에 반영됨 (clear → draw → display 순서)

#### 섹션 3: 코드 생성 규칙 (12개)

| 규칙 | 내용 | 이유 |
|:----:|------|------|
| 1 | 코드만 출력, 설명/마크다운 없음 | 빌드 시 코드만 필요, 불필요한 텍스트가 있으면 컴파일 에러 |
| 2 | setup()과 loop()만 정의 + 헬퍼 함수 | base firmware에 나머지가 이미 있음 |
| 3 | #include 금지 | base firmware에 이미 포함됨, 중복 시 에러 |
| 4 | setup()에서 반드시 호출 순서: Serial.begin → initHardware() → initBLE() | 하드웨어+BLE 초기화가 이 순서로 필요 |
| 5 | LED/부저 핀에 pinMode() 금지, Wire.begin/oled.init 금지 | initHardware()가 이미 처리함, 중복 호출 시 충돌 |
| 6 | LED 작업은 xTaskCreate로 별도 태스크 | loop()가 delay(10000)이므로, LED 동작은 FreeRTOS 태스크로 분리해야 함 |
| 7 | 기존 함수 재정의 금지 (initBLE, initHardware, oled, aht20_read 등) | 링커 에러 (duplicate symbol) 방지 |
| 8 | oled 객체는 전역으로 이미 선언됨 | 새로 선언하면 중복 에러 |
| 9 | loop()는 delay(10000)만 | BLE OTA가 백그라운드에서 동작하려면 loop가 차단되면 안 됨 |
| 10 | 핀 매크로 사용 가능 (LED_RED=25 등) | #define으로 이미 정의됨 |
| 11 | 멜로디는 tone(33, freq, duration)만 사용, LEDC API 금지 | Arduino ESP32에서 tone()이 LEDC를 내부적으로 사용, 직접 LEDC 호출 시 충돌 |
| 12 | 한국어 주석 추가: `// [주제] 설명` | 학습자가 코드를 이해할 수 있도록 |

## 3. AI가 생성하는 코드의 구조

AI가 생성하는 코드의 전형적 패턴:

```c
// [LED 깜빡이기] 빨간 LED를 0.5초마다 깜빡입니다

// [태스크 함수] FreeRTOS 태스크로 LED 제어
void ledBlinkTask(void *param) {
  while (1) {
    digitalWrite(LED_RED, LOW);   // [LED ON] Active LOW
    vTaskDelay(500 / portTICK_PERIOD_MS);
    digitalWrite(LED_RED, HIGH);  // [LED OFF]
    vTaskDelay(500 / portTICK_PERIOD_MS);
  }
}

void setup() {
  Serial.begin(115200);
  initHardware();   // [하드웨어 초기화] LED, 부저, OLED, 센서
  initBLE();        // [BLE 초기화] OTA 대기 시작

  // [태스크 생성] LED 깜빡이기 태스크 시작
  xTaskCreate(ledBlinkTask, "led", 2048, NULL, 1, NULL);
}

void loop() {
  delay(10000);  // [메인 루프] BLE OTA 백그라운드 동작
}
```

### 코드 병합 과정

```
베이스 펌웨어 (ble_ota_arduino.ino)
┌────────────────────────────────────┐
│ #include <NimBLEDevice.h>          │
│ #include <Update.h>                │
│ #include <Wire.h>                  │
│ #include "ssd1306.h"               │
│                                    │
│ // 핀 정의                          │
│ #define LED_RED 25                  │
│ ...                                │
│                                    │
│ // OTA 콜백, 센서, 하드웨어 초기화    │
│ // BLE 초기화, 명령 처리              │
│ ...                                │
│                                    │
│ // ─── LED Task ───  ← 마커        │
│                                    │  ← 여기서부터 AI 코드로 교체
│ void setup() { ... }               │
│ void loop() { ... }                │
└────────────────────────────────────┘

병합 후:
┌────────────────────────────────────┐
│ (베이스: #include ~ CmdCallbacks)   │  ← 그대로 유지
│                                    │
│ // ─── LED Task ───                │  ← 마커
│                                    │
│ (AI 생성 코드)                      │  ← 교체됨
│ void ledBlinkTask(...) { ... }     │
│ void setup() { ... }               │
│ void loop() { ... }                │
└────────────────────────────────────┘
```

코드 병합 시 처리:
1. `// ─── LED Task ───` 마커 이전의 베이스 코드를 추출
2. AI 생성 코드에서 `#include` 줄 제거 (중복 방지)
3. AI 코드에서 함수/상수 정의 시작점(`void`, `static`, `const`, `//`, `#`) 찾기
4. 베이스 + 마커 + AI 코드를 합쳐서 `.ino` 파일 생성

## 5. Claude CLI 호출 방법

### 5.1 명령어

```bash
claude -p - --output-format text --model claude-sonnet-4-6 --tools ""
```

| 옵션 | 의미 |
|------|------|
| `-p -` | 파이프 모드, stdin에서 프롬프트 읽기 |
| `--output-format text` | 순수 텍스트 출력 (JSON이 아닌) |
| `--model claude-sonnet-4-6` | Sonnet 4.6 모델 사용 |
| `--tools ""` | 도구 사용 비활성화 (코드만 생성) |

### 5.2 입력/출력

```
stdin:  SYSTEM_PROMPT + "\n\nUser request: " + 사용자 프롬프트
stdout: Arduino C/C++ 코드 (또는 마크다운 감싼 코드)
stderr: 에러 메시지 (있는 경우)
```

### 5.3 후처리

```python
# 마크다운 코드블록 제거
if "```c" in code:    code = code.split("```c", 1)[1]
elif "```cpp" in code: code = code.split("```cpp", 1)[1]
elif "```" in code:    code = code.split("```", 1)[1]
if code.endswith("```"): code = code[:-3].rstrip()

# 유효성 검증
if "setup" not in code and "#include" not in code:
    raise RuntimeError("Invalid code")
```

## 6. 재시도 메커니즘

빌드 실패 시 자동 재시도합니다.

```
시도 1: 프롬프트 합성 → Claude 코드 생성 → 병합 → 빌드
          │ 실패 시
          ▼
시도 2: 프롬프트 합성 → Claude 코드 생성 → 병합 → 빌드
          │ 실패 시
          ▼
시도 3: 프롬프트 합성 → Claude 코드 생성 → 병합 → 빌드
          │ 실패 시
          ▼
        최종 실패 반환
```

- 기본 최대 재시도: 3회 (`max_retries: 3`)
- 각 시도마다 Claude를 새로 호출 (다른 코드가 생성될 수 있음)
- timing에 각 시도별 소요 시간 기록: `2b_claude(try1)`, `4_build(try1)` 등

## 7. 베이스 펌웨어에서 제공하는 것들

AI가 **호출만 해야** 하고 **재정의하면 안 되는** 것들:

### 7.1 전역 변수/객체

| 이름 | 타입 | 설명 |
|------|------|------|
| `oled` | `SSD1306` | OLED 디스플레이 객체 (extern 선언) |
| `bleName` | `char[32]` | BLE 기기 이름 |
| `deviceConnected` | `bool` | BLE 연결 상태 |
| `otaInProgress` | `bool` | OTA 진행 중 여부 |

### 7.2 함수

| 함수 | 역할 | AI가 호출 가능? |
|------|------|:---:|
| `initHardware()` | LED/부저/스위치/I2C/OLED 초기화 | O (setup에서 필수) |
| `initBLE()` | BLE 서비스 시작, 광고 시작 | O (setup에서 필수) |
| `aht20_read(temp, humi)` | 온습도 측정 | O |
| `sendStatus(status, progress)` | BLE 상태 알림 | X (OTA 내부용) |
| `aht20_init()` | AHT20 초기화 | X (자동 호출) |

| 매크로 | 값 |
|--------|-----|
| `LED_RED` | 25 |
| `LED_YELLOW` | 26 |
| `LED_BLUE` | 27 |
| `BUZZER` | 14 |
| `I2C_SDA` | 21 |
| `I2C_SCL` | 22 |

### 7.5 OLED API (ssd1306.h)

| 메서드 | 설명 |
|--------|------|
| `oled.init()` | 디스플레이 초기화 (initHardware에서 호출됨) |
| `oled.clear()` | 프레임버퍼 지우기 |
| `oled.drawString(x, y, text)` | (x, y) 픽셀 위치에 텍스트 |
| `oled.display()` | 버퍼를 화면에 전송 |
| `oled.pixel(x, y, on)` | 개별 픽셀 ON/OFF |
| `oled.drawChar(x, y, char)` | 단일 문자 (5×7 폰트) |

화면 좌표계:
```
(0,0) ──────────────── (127,0)
  │                        │
  │    128 × 64 pixels     │
  │    5×7 폰트: ~21자/줄   │
  │    ~8줄 (y=0,8,16,...56)│
  │                        │
(0,63) ─────────────── (127,63)
```

- Melody buzzer (PWM): GPIO33

- AHT20 temp/humidity I2C: addr=0x38
- Switch: GPIO32 (INPUT_PULLUP, active LOW)

  ...

  ...

... (12개 규칙)

```

### 예상 AI 출력:

```c
// [LED 깜빡이기] 빨간 LED를 1초 간격으로 깜빡입니다

void ledTask(void *param) {
  while (1) {
    digitalWrite(LED_RED, LOW);   // [LED ON] Active LOW
    vTaskDelay(500 / portTICK_PERIOD_MS);
    digitalWrite(LED_RED, HIGH);  // [LED OFF]
    vTaskDelay(500 / portTICK_PERIOD_MS);
  }
}

void setup() {
  Serial.begin(115200);
  initHardware();
  initBLE();
  xTaskCreate(ledTask, "led", 2048, NULL, 1, NULL);
}

void loop() {
  delay(10000);
}
```

## 10. 자주 발생하는 빌드 에러와 원인

| 에러 | 원인 | 시스템 프롬프트에서의 대응 |
|------|------|------------------------|
| `multiple definition of 'initHardware'` | AI가 initHardware를 재정의 | 규칙 7: "Do NOT define or redeclare" |
| `'oled' was not declared` | AI가 SSD1306 객체를 새로 선언하려 함 | 규칙 8: "already declared globally" |
| `#include 중복 에러` | AI가 #include를 출력 | 규칙 3 + 병합 시 자동 제거 |
| `ledcSetup 미정의` | Arduino ESP32 3.x에서 LEDC API 변경됨 | 규칙 11: "ONLY use tone()" |
| `LED가 반대로 동작` | Active LOW 무시 | 섹션 1에서 명시적 설명 |
| `loop()에서 LED 동작 안 함` | delay(10000)이 차단 | 규칙 6: "use xTaskCreate" |
| `pinMode 중복 호출 에러` | 이미 initHardware에서 설정 | 규칙 5: "DO NOT call pinMode" |
