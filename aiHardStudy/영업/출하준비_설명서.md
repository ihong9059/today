## 1. 출하 준비 개요

### 1.1 출하 상태란?

교육 기관에 납품 시, 수령자가 **전원 연결 → 앱 실행 → 즉시 수업 시작**할 수 있는 상태를 말합니다.

### 1.2 출하 준비 3단계

```
┌─────────────────────┐     ┌─────────────────────┐     ┌─────────────────────┐
│  STEP 1             │     │  STEP 2             │     │  STEP 3             │
│  보드 펌웨어 설치    │────▶│  앱 설치 확인       │────▶│  클라우드 접속 검증   │
│  (USB, 1회만)       │     │  (APK 또는 Web)     │     │  (E2E 동작 테스트)   │
│  약 2분/대          │     │  약 1분/대          │     │  약 3분/대          │
└─────────────────────┘     └─────────────────────┘     └─────────────────────┘
```

### 1.3 필요 장비/도구

| 항목 | 용도 | 비고 |
|:-----|:-----|:-----|
| Windows/Mac/Linux PC | 펌웨어 최초 설치 | USB 드라이버 필요 |
| USB Micro-B 케이블 | PC ↔ ESP32 연결 | 데이터 케이블 (충전 전용 불가) |
| Android 스마트폰 | 앱 설치 + 동작 검증 | Android 6.0 이상, BLE 지원 |
| Wi-Fi 인터넷 | 클라우드 서버 접속 | 모바일 데이터도 가능 |

## 2. ESP32 보드 초기 펌웨어 설치 (USB)

> **왜 필요한가?**: 공장 출고된 ESP32 보드에는 BLE OTA 부트로더가 없습니다.
> 최초 1회 USB로 펌웨어를 설치하면, 이후에는 스마트폰에서 무선(BLE)으로 업데이트됩니다.

### 2.1 사전 준비

#### (1) Arduino-CLI 설치

**Windows:**
```powershell
# winget으로 설치 (권장)
winget install ArduinoSA.ArduinoCLI

# 또는 직접 다운로드: https://arduino.github.io/arduino-cli/installation/
```

**Mac:**
```bash
brew install arduino-cli
```

**Linux:**
```bash
curl -fsSL https://raw.githubusercontent.com/arduino/arduino-cli/master/install.sh | sh
```

#### (2) ESP32 보드 패키지 + NimBLE 라이브러리 설치

```bash
# ESP32 코어 추가
arduino-cli config add board_manager.additional_urls https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json

# ESP32 코어 설치
arduino-cli core install esp32:esp32@3.2.0

# NimBLE-Arduino 라이브러리 설치
arduino-cli lib install "NimBLE-Arduino@2.3.7"
```

#### (3) USB 드라이버 확인

| 보드 | USB 칩 | 드라이버 |
|:-----|:-------|:---------|
| ESP32 DevKitC (대부분) | CP2102 | [Silicon Labs CP2102 Driver](https://www.silabs.com/developers/usb-to-uart-bridge-vcp-drivers) |
| 일부 보드 | CH340 | [CH340 Driver](http://www.wch-ic.com/downloads/CH341SER_EXE.html) |

설치 후 PC에 보드를 USB로 연결하면 **COM 포트** (Windows) 또는 **/dev/ttyUSB0** (Linux/Mac)가 생성됩니다.

### 2.2 펌웨어 소스 파일 준비

출하용 펌웨어 소스는 2개 파일입니다:

| 파일 | 위치 | 설명 |
|:-----|:-----|:-----|
| `ble_ota_arduino.ino` | `firmware/ble_ota_arduino/` | 메인 펌웨어 (444줄) — BLE OTA + CMD 핸들러 + 센서 |
| `ssd1306.h` | `firmware/ble_ota_arduino/` | OLED 드라이버 (140줄) — SSD1306 I2C 제어 |

두 파일이 **같은 폴더**에 있어야 합니다.

### 2.3 빌드 및 업로드

#### (1) COM 포트 확인

```bash
arduino-cli board list
```

출력 예시:
```
Port         Protocol Type              Board Name          FQBN
COM3         serial   Serial Port (USB) ESP32 Dev Module    esp32:esp32:esp32
```

#### (2) 빌드 (컴파일)

```bash
arduino-cli compile \
  --fqbn esp32:esp32:esp32 \
  --build-property build.partitions=min_spiffs \
  firmware/ble_ota_arduino/
```

- `--fqbn esp32:esp32:esp32`: ESP32-WROOM-32 DevKitC 보드 지정
- `--build-property build.partitions=min_spiffs`: 듀얼 OTA 파티션 활성화 (필수)
- 빌드 시간: 최초 약 2~3분, 이후 약 30~40초 (캐시)

#### (3) 업로드 (플래싱)

```bash
arduino-cli upload \
  --fqbn esp32:esp32:esp32 \
  --port COM3 \
  firmware/ble_ota_arduino/
```

> **COM3** 부분을 실제 포트로 변경하세요 (Linux: `/dev/ttyUSB0`, Mac: `/dev/cu.usbserial-XXX`)

#### (4) 성공 확인

업로드 완료 후 보드가 자동 재부팅되며:

| 확인 항목 | 정상 상태 |
|:---------|:---------|
| OLED 화면 | "UTTEC Firmware" / "BLE OTA Ready!" / "Waiting..." 표시 |
| 시리얼 모니터 | `Hardware initialized` / `BLE advertising started` 출력 |
| BLE 이름 | "UTTEC-OTA" (기본값) |
| LED | 모두 꺼짐 (Active LOW, HIGH=OFF) |

시리얼 모니터로 확인:
```bash
arduino-cli monitor --port COM3 --config baudrate=115200
```

### 2.4 대량 설치 팁 (30대 이상)

```
[효율적인 작업 순서]

1. PC에 USB 허브(4~8포트) 연결
2. 보드를 순서대로 USB 허브에 연결
3. 각 포트별로 upload 명령 실행

# 예시: 4대 동시 (Windows, 각 창에서)
arduino-cli upload --fqbn esp32:esp32:esp32 --port COM3 firmware/ble_ota_arduino/
arduino-cli upload --fqbn esp32:esp32:esp32 --port COM4 firmware/ble_ota_arduino/
arduino-cli upload --fqbn esp32:esp32:esp32 --port COM5 firmware/ble_ota_arduino/
arduino-cli upload --fqbn esp32:esp32:esp32 --port COM6 firmware/ble_ota_arduino/
```

**소요 시간 (대량):**

| 수량 | 방식 | 예상 시간 |
|:----:|:-----|:---------|
| 1대 | 단일 USB | ~2분 |
| 10대 | 허브 4포트 병렬 | ~6분 |
| 30대 | 허브 4포트 병렬 | ~16분 |
| 30대 | 허브 8포트 병렬 | ~8분 |

## 3. 스마트폰 앱 설치 (Flutter APK)

> **참고**: Web App(PWA)을 사용하는 경우 앱 설치가 불필요합니다.
> Chrome에서 `https://uttec-ai.duckdns.org/firmware` 접속만으로 사용 가능합니다.
> Flutter 앱은 자동 BLE 재연결 등 추가 기능이 있어 교육 현장에 더 적합합니다.

### 3.1 설치 방식 비교

| 방식 | 장점 | 단점 | 권장 상황 |
|:-----|:-----|:-----|:---------|
| **APK 직접 설치** (USB) | 인터넷 불필요, 빠름 | 폰마다 개별 작업 | 대량 출하 준비 |
| **APK 다운로드** (QR코드) | 자가 설치 가능 | 인터넷 필요 | 현장 배포 |
| **Web App** (브라우저) | 설치 불필요 | Chrome만 가능, 자동 재연결 없음 | 빠른 데모 |

### 3.2 APK 직접 설치 (USB 전송)

#### (1) APK 빌드 (사전 준비, 1회)

개발 PC에서 APK를 빌드합니다:

```bash
cd smartphone/vibe_ut_cloud/

# Flutter 의존성 설치
flutter pub get

# Release APK 빌드
flutter build apk --release
```

빌드된 APK 위치:
```
smartphone/vibe_ut_cloud/build/app/outputs/flutter-apk/app-release.apk
```

#### (2) 스마트폰에 APK 전송 및 설치

**방법 A — USB 케이블로 전송:**
```
1. 스마트폰을 USB로 PC에 연결
2. "파일 전송" 모드 선택
3. app-release.apk를 스마트폰 Download 폴더에 복사
4. 스마트폰에서 파일 관리자 → Download → app-release.apk 터치
5. "출처를 알 수 없는 앱 설치" 허용 → 설치
```

**방법 B — QR코드로 배포 (서버에 APK 호스팅 시):**
```
1. APK를 웹 서버에 업로드
2. 다운로드 URL을 QR코드로 생성
3. 학생이 QR코드 스캔 → 다운로드 → 설치
```

#### (3) 앱 권한 허용

앱 최초 실행 시 다음 권한을 허용해야 합니다:

| 권한 | 용도 | 필수 여부 |
|:-----|:-----|:---------:|
| 위치 (근처 기기) | BLE 기기 스캔에 필요 (Android 정책) | 필수 |
| Bluetooth | BLE 연결 및 OTA 전송 | 필수 |

> **Android 12+**: "근처 기기" 권한이 추가로 필요합니다. 앱이 자동으로 요청합니다.

#### (4) 설치 확인

| 확인 항목 | 정상 상태 |
|:---------|:---------|
| 앱 아이콘 | 홈 화면에 "UTTEC Cloud" 앱 표시 |
| 앱 실행 | 5탭 화면 (홈/HW/SW/패드/설정) 표시 |
| 설정 탭 → 서버 URL | `http://178.128.90.37:8092` (클라우드) |

### 3.3 Web App 설치 (PWA, 대안)

APK 설치 없이 브라우저만으로 사용하는 방법:

```
1. Chrome (Android) 또는 Chrome (PC)에서 접속:
   https://uttec-ai.duckdns.org/firmware

2. (선택) 홈 화면에 추가:
   Chrome ⋮ 메뉴 → "홈 화면에 추가" 또는 "앱 설치"
   → 홈 화면에 UTTEC 아이콘이 생성됨
   → 탭하면 주소창 없이 전체화면 앱처럼 실행
```

## 4. 클라우드 서버 접속 및 동작 검증

### 4.1 검증 목적

출하 전 각 보드가 **전체 파이프라인**(프롬프트 입력 → AI 코드 생성 → 빌드 → BLE OTA 전송 → 보드 동작)을 정상적으로 수행하는지 확인합니다.

### 4.2 사전 확인

#### 클라우드 서버 상태 확인

브라우저에서 아래 URL 접속:
```
http://178.128.90.37:8092/health
```

정상 응답:
```json
{
  "status": "ok",
  "build_system": "arduino",
  "acli_exists": true,
  "active_jobs": 0
}
```

> `"status": "ok"` 이면 서버 정상. `active_jobs`가 0이면 빌드 대기 중 없음.

### 4.3 E2E 동작 검증 절차

#### STEP 1 — BLE 연결

**Flutter 앱:**
```
1. ESP32 보드에 USB 전원 연결 (OLED에 "BLE OTA Ready!" 표시 확인)
2. UTTEC Cloud 앱 실행
3. 설정 탭 → "BLE 기기 스캔" 터치
4. "UTTEC-OTA" 선택 → 연결
   ✅ 앱 상단에 "연결됨" 표시, 파란색 아이콘
5. (선택) 이름 변경: "UTTEC-A반1번" 등 학생별 이름 지정
```

**Web App:**
```
1. Chrome에서 https://uttec-ai.duckdns.org/firmware 접속
2. 설정 탭 → "BLE 기기 연결" 터치
3. Chrome 팝업에서 "UTTEC-OTA" 선택 → 페어링
   ✅ 앱 화면에 "연결됨" 표시
```

#### STEP 2 — 빌드 테스트 (간단한 프롬프트)

```
1. 홈 탭에서 프롬프트 입력:
   "빨간 LED 1초마다 깜빡이기"

2. [빌드 & 전송] 버튼 터치

3. 진행 상태 확인:
   Step 1: AI 코드 생성 중... (12~70초)
   Step 2: Arduino 빌드 중... (24~26초)
   ✅ "빌드 완료!" 메시지

4. BLE OTA 자동 전송 시작:
   진행률: 0% → 25% → 50% → 75% → 100%
   ✅ "전송 완료!" 메시지 (약 14초)

5. ESP32 자동 재부팅 (약 3초)

6. 결과 확인:
   ✅ 빨간 LED가 1초마다 깜빡이면 성공!
```

#### STEP 3 — 패드 탭 실시간 제어 테스트

```
1. 패드 탭 이동

2. LED 제어 테스트:
   - 빨강 LED ON → ✅ 빨간 LED 켜짐
   - 노랑 LED ON → ✅ 노란 LED 켜짐
   - 파랑 LED ON → ✅ 파란 LED 켜짐
   - ALL OFF → ✅ 전체 LED 꺼짐

3. 부저 테스트:
   - BEEP → ✅ 삐 소리 (100ms)
   - 피아노 → ✅ 도레미파솔라시도

4. OLED 테스트:
   - OLED 텍스트 입력 → ✅ OLED 화면에 텍스트 표시

5. 온도 센서 테스트:
   - TEMP 버튼 → ✅ OLED에 "T:25.3C H:45.2%" 형태로 표시

6. 스위치 모니터:
   - 보드의 스위치 누르기 → ✅ 앱에 "PRESSED" 표시
   - 스위치 놓기 → ✅ 앱에 "RELEASED" 표시
```

### 4.4 학생별 보드 이름 설정 (선택)

교육 기관에 다수의 보드를 납품할 경우, 학생별 보드 구분을 위해 BLE 이름을 미리 설정합니다:

```
설정 탭 → BLE 기기 스캔 → 보드 선택 → 이름 변경

예시:
  보드 1 → "UTTEC-A반1번"
  보드 2 → "UTTEC-A반2번"
  ...
  보드 30 → "UTTEC-A반30번"
```

> 이름은 ESP32 NVS(비휘발성 저장소)에 영구 저장됩니다. 전원을 꺼도 유지됩니다.

## 6. 트러블슈팅

### 6.1 펌웨어 설치 문제

| 증상 | 원인 | 해결 |
|:-----|:-----|:-----|
| `arduino-cli upload` 실패: "No such port" | USB 드라이버 미설치 또는 충전 전용 케이블 | CP2102/CH340 드라이버 설치, 데이터 케이블로 교체 |
| 빌드 에러: "NimBLEDevice.h not found" | NimBLE 라이브러리 미설치 | `arduino-cli lib install "NimBLE-Arduino@2.3.7"` |
| 빌드 에러: "min_spiffs not found" | ESP32 코어 버전 불일치 | `arduino-cli core install esp32:esp32@3.2.0` |
| 업로드 중 "Timed out" | ESP32 BOOT 모드 진입 실패 | 업로드 시작 시 보드의 BOOT 버튼을 눌러줌 |
| OLED에 아무것도 표시 안 됨 | I2C 연결 불량 또는 OLED 불량 | I2C 핀(SDA=21, SCL=22) 확인, OLED 모듈 교체 |

### 6.2 앱 설치 문제

| 증상 | 원인 | 해결 |
|:-----|:-----|:-----|
| APK 설치 차단 | "출처를 알 수 없는 앱" 미허용 | 설정 → 보안 → 출처를 알 수 없는 앱 허용 |
| 앱 실행 시 크래시 | Kotlin 패키지 경로 불일치 | APK 재빌드 (com.uttec.cloud 패키지 확인) |
| BLE 스캔 시 기기 없음 | 위치 권한 미허용 | 앱 권한 → 위치 "허용" 설정 |
| BLE 연결 후 즉시 끊김 | Android BLE 캐시 문제 | Bluetooth OFF → ON, 또는 앱 캐시 삭제 |

### 6.3 클라우드 접속 문제

| 증상 | 원인 | 해결 |
|:-----|:-----|:-----|
| /health 응답 없음 | 빌드 서버 다운 | SSH 접속 후 `sudo systemctl restart uttec-arduino` |
| Web App 접속 불가 | 웹 UI 서버 다운 | SSH 접속 후 `sudo systemctl restart uttec-webui` |
| HTTPS 인증서 만료 | Certbot 자동 갱신 실패 | `sudo certbot renew --force-renewal` |
| 빌드 요청 시 "Building..." 무한 대기 | 이전 빌드가 멈춤 | 서버 재시작: `sudo systemctl restart uttec-arduino` |
| Web Bluetooth "보안 컨텍스트 필요" | HTTP로 접속 | 반드시 `https://` URL 사용 (HTTP에서는 BLE 불가) |

### 6.4 OTA 전송 문제

| 증상 | 원인 | 해결 |
|:-----|:-----|:-----|
| OTA 전송 0%에서 멈춤 | BLE 연결 불안정 | 스마트폰을 보드에 1m 이내로 접근, 재연결 |
| OTA 전송 중간에 실패 | 전파 간섭 또는 MTU 문제 | Wi-Fi 2.4GHz 채널 변경, 재전송 시도 |
| OTA 성공 후 보드 동작 안 함 | 생성 코드 오류 | 다른 프롬프트로 재시도 (예: "LED 깜빡이기") |
| "CRC_FAIL" 상태 | 전송 중 데이터 손상 | BLE 재연결 후 OTA 재전송 |
