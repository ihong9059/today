## 1. 앱의 역할과 위치

스마트폰 앱은 바이브 코딩 시스템에서 **사용자와 시스템을 잇는 유일한 접점**입니다.
사용자는 이 앱 하나만으로 전체 과정을 수행합니다.

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  사용자 ──▶ [스마트폰 앱] ──▶ 클라우드 ──▶ [스마트폰 앱] ──▶ 디바이스
│                  │                              │                │
│                  │                              │                │
│              ① 프롬프트 입력              ② .bin 수신         │
│              ③ 상태 모니터링              ④ BLE OTA 전송      │
│                                                                 │
│  사용자가 만지는 것: 스마트폰 1대                               │
│  사용자가 알아야 할 것: 자연어 (한국어/영어)                    │
│  사용자가 몰라도 되는 것: C언어, 컴파일, GPIO, 플래싱            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 앱이 수행하는 3가지 통신

```
                    ┌──────────────┐
                    │  스마트폰 앱  │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            ▼            ▼
        ① HTTPS      ② BLE GATT   ③ 로컬 저장
        (서버 통신)    (디바이스)    (이력/설정)
              │            │            │
              ▼            ▼            ▼
        클라우드 서버  ESP32 보드    SQLite/파일
        - 프롬프트 전송  - 기기 스캔    - 프롬프트 이력
        - 상태 폴링     - .bin 전송    - 연결 기기 정보
        - .bin 다운로드  - 상태 수신    - 설정값
```

## 2. 핵심 기능 3가지

### 기능 1 — AI 프롬프트 입력 및 빌드 모니터링

```
사용자가 하는 일:
  "LED를 0.5초마다 깜빡여줘"라고 입력하고 [실행] 버튼을 누른다.

앱이 하는 일:
  1. 프롬프트를 클라우드 서버에 HTTPS POST로 전송
  2. 서버가 Claude에게 코드 생성 요청
  3. 서버가 ESP-IDF로 빌드
  4. 앱이 2초마다 서버에 상태 조회 (polling)
  5. 빌드 완료 시 .bin 파일 다운로드
  6. 각 단계의 진행 상태를 실시간 UI로 표시

표시 내용:
  ✅ 프롬프트 전송 완료
  ✅ AI 코드 생성 중... (5초)
  ✅ 펌웨어 빌드 중... (12초)
  ✅ 펌웨어 다운로드 완료 (824KB)
  ⏳ BLE OTA 전송 중... 67%
```

### 기능 2 — BLE OTA 펌웨어 전송

```
사용자가 하는 일:
  없음 (자동 진행) — 또는 최초 1회 디바이스 선택

앱이 하는 일:
  1. BLE 스캔 → OTA 서비스를 가진 디바이스 발견
  2. 디바이스에 BLE 연결
  3. 다운로드받은 .bin을 chunk 단위로 전송
     - OTA_CONTROL에 START 명령 전송
     - OTA_DATA에 500바이트씩 Write Without Response
     - 100 chunk마다 진행률 업데이트
     - OTA_CONTROL에 END 명령 전송
  4. 디바이스 재부팅 대기
  5. 완료 알림
```

### 기능 3 — 디바이스 관리 및 이력

```
사용자가 하는 일:
  - 연결된 디바이스 확인
  - 이전 프롬프트/결과 이력 조회
  - 이전 빌드를 다시 배포 (재전송)

앱이 관리하는 정보:
  - 디바이스 목록 (이름, MAC, 마지막 연결)
  - 프롬프트 이력 (입력, 결과, 날짜)
  - 빌드 캐시 (성공한 .bin 보관)
  - 보드 프로파일 (어떤 보드에 연결되어 있는지)
```

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐

│          │     │ (프로파일)│     │          │     │          │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
                                                        │
                                                        ▼
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│ 동작확인 │◀────│ OTA 완료 │◀────│ 빌드 진행│◀────│프롬프트  │
│ LED 깜빡 │     │ 재부팅   │     │ 모니터링 │     │ 입력     │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
```

### 3-2. 일반 사용 흐름 (Daily Use)

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│ 앱 열기  │────▶│ 자동 연결│────▶│프롬프트  │────▶│ [실행]   │
│          │     │ (이전기기)│     │ 입력     │     │ 버튼     │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
                                                        │
                                                        ▼
                                  ┌──────────┐     ┌──────────┐
                                  │ 동작확인 │◀────│ 자동진행 │
                                  │          │     │ (30초)   │
                                  └──────────┘     └──────────┘

사용자가 하는 것: 앱 열기 → 문장 입력 → [실행] → 30초 대기 → 확인
총 터치 횟수: 3회 (앱 열기, 입력, 실행)
```

### 3-3. 에러 시 흐름

```
[빌드 실패]
  앱: "빌드에 실패했습니다. AI가 코드를 수정하고 있습니다... (재시도 2/3)"
  → 자동 retry → 성공 시 이어서 진행
  → 3회 실패 시: "빌드에 실패했습니다. 프롬프트를 다시 표현해 보세요."
       + 에러 로그 보기 (접이식)

[BLE 연결 끊김]
  앱: "BLE 연결이 끊어졌습니다. 재연결 중..."
  → 자동 재연결 시도 (3회)
  → 실패 시: "디바이스를 가까이 두고 [재연결] 버튼을 눌러주세요."

[OTA 전송 실패]
  앱: "전송이 중단되었습니다. 디바이스가 이전 펌웨어로 복구됩니다."
  → 디바이스는 듀얼 파티션으로 자동 롤백
  → [다시 시도] 버튼 표시
```

## 4. 화면 구성 (Screen Design)

### 4-1. 화면 목록

| # | 화면 | 용도 | 진입 경로 |
|---|------|------|----------|
| 1 | 스플래시 | 앱 로딩, 로고 | 앱 시작 |
| 2 | 온보딩 | 최초 사용 안내 (3장) | 최초 1회 |

| 8 | 디바이스 관리 | 연결 기기 목록 | 하단 탭 |

### 5-1. BLE 서비스/특성 구조

```

├── Generic Access Service (0x1800)

│   └── Appearance (0x2A01): Generic Computer
│

│   └── Hardware Rev (0x2A27): "V1.0"
│
└── OTA Service (0000FE00-0000-1000-8000-00805F9B34FB)  ← 커스텀
    ├── OTA_CONTROL (0000FE01-...)

    │   용도: START, END, ABORT 명령 전송
    │   데이터 형식:
    │     START: [0x01] [total_size: 4B] [sha256: 32B]
    │     END:   [0x02]

    │

    │

        용도: 진행 상태 보고 (디바이스 → 앱)

          [status: 1B] [progress: 1B] [detail: nB]
          status:
            0x00 = IDLE
            0x01 = READY (START 수신 확인)
            0x02 = RECEIVING
            0x03 = VERIFYING
            0x04 = SUCCESS
            0x05 = CRC_FAIL
            0x06 = WRITE_FAIL
            0x07 = ABORT_OK

### 5-3. MTU와 전송 속도

```
BLE 5.0 기준:
  MTU 협상: 최대 517 bytes
  실제 payload: MTU - 3 = 514 bytes (ATT 헤더)
  OTA chunk size: 500 bytes (안전 마진)

전송 속도 계산:
  Connection Interval: 7.5ms (최소)
  Packets per Interval: ~6 (BLE 5.0 LE 2M PHY)
  초당 전송량: 500 × 6 × (1000/7.5) ≈ 400KB/s (이론)
  실제 전송량: ~20-30KB/s (오버헤드, 재전송 포함)

1MB 펌웨어 전송 시간:
  이론: ~2.5초
  실제: ~30-50초
```

/// 서버 상태 폴링 (2초 간격, 최대 90초)
Future<JobStatus> pollJobStatus(String jobId) async {
  const maxWait = Duration(seconds: 90);
  const interval = Duration(seconds: 2);
  final deadline = DateTime.now().add(maxWait);

  while (DateTime.now().isBefore(deadline)) {
    final status = await api.getJobStatus(jobId);

    // UI 업데이트
    updateProgressUI(status);

    if (status.isCompleted) return status;
    if (status.isFailed) throw BuildFailedException(status);

    await Future.delayed(interval);
  }

  throw TimeoutException('빌드 시간 초과 (90초)');
}
```

## 8. UI/UX 디자인 가이드

### 8-1. 디자인 원칙

```
1. 원터치 실행 (One-Touch Execution)
   → 프롬프트 입력 후 [실행] 1번이면 끝
   → 나머지는 모두 자동 진행
   → 사용자가 "다음에 뭘 해야 하지?"를 묻지 않게

2. 진행 투명성 (Progress Transparency)
   → 매 단계마다 "지금 뭘 하고 있는지" 보여줌
   → 시간 표시 (경과 / 예상 남은 시간)
   → 에러 시 "왜 실패했는지 + 어떻게 하면 되는지"

3. 초보자 우선 (Beginner First)
   → 전문 용어 최소화 (GPIO, OTA 등 숨기기)
   → 기본 설정은 "그냥 되는" 상태
   → 고급 옵션은 설정 깊은 곳에

4. 교육 연계 (Educational Bridge)
   → 완료 후 "생성된 코드 보기" 옵션
   → AI가 코드를 한 줄씩 설명하는 모드 (교육 모드)
   → 프롬프트 힌트/예시 제공
```

## 10. 개발 단계

| Phase | 목표 | 기간 |
|:-----:|------|------|
| **S1** | 프로젝트 세팅 + 메인 화면 UI | 2~3일 |
| **S2** | 서버 API 연동 (프롬프트 전송 → 상태 폴링 → .bin 다운로드) | 3~4일 |
| **S3** | BLE 스캔 + 연결 + OTA 전송 | 5~7일 |
| **S4** | E2E 통합 (프롬프트 → 빌드 → OTA → 동작) | 3~4일 |
| **S5** | 이력 관리 + 설정 + 에러 처리 | 3~4일 |
| **S6** | UI 다듬기 + 교육 모드 + 테스트 | 3~4일 |

### 최소 동작 버전 (MVP)

S1~S4 완료 시 MVP:
- 메인 화면에서 프롬프트 입력
- 서버에 빌드 요청 + 상태 모니터링
- BLE로 디바이스 연결 + OTA 전송
- 완료 확인

**MVP에서 빠져도 되는 것**: 이력 관리, 교육 모드, 다크모드, 에러 자동 복구
