# 바이브 Python 코딩 — 스마트폰 하드웨어 활용 계획서

> **목표**: 스마트폰의 센서/카메라/마이크 등 하드웨어를 Python으로 직접 제어하며 코딩을 배우는 교육 시스템
> **작성일**: 2026-04-19
> **기존 시스템과의 관계**: UTTEC Board 사전빌드 시스템과 동일한 개념 — 프롬프트 → 코드 생성 → 실행 → 학습

---

## 1. 개념 비교

### 기존 (UTTEC Board)

```
학생 프롬프트 → AI가 C/Arduino 코드 생성 → 컴파일 → BLE OTA → 보드 LED/부저 동작
```

### 신규 (스마트폰 Python)

```
학생 프롬프트 → AI가 Python 코드 생성 → 스마트폰에서 직접 실행 → 센서/카메라/소리 동작
```

### 핵심 차이

| | UTTEC Board | 스마트폰 Python |
|---|:-:|:-:|
| 실행 환경 | ESP32 보드 | **스마트폰 자체** |
| 언어 | C/Arduino | **Python** |
| 컴파일 | 필요 (Arduino CLI) | **불필요 (인터프리터)** |
| 전송 | BLE OTA (~20초) | **즉시 실행** |
| 하드웨어 | LED, 부저, OLED, 센서 | **카메라, 마이크, GPS, 가속도, 화면** |
| 추가 장비 | 보드 필요 ($3~$13) | **스마트폰만 있으면 됨** |

## 3. 실행 환경 비교

### 방안 A: Termux + Python (권장)

```
장점:
  - 완전한 Linux 환경, pip으로 라이브러리 설치
  - 카메라, GPS, 센서 접근 가능 (termux-api)
  - 서버 실행 가능 (Flask, FastAPI)
  - 무료

단점:
  - CLI 기반 (초보자에게 어려울 수 있음)
  - 터치 UI 직접 구현 어려움

필요 앱:
  - Termux (터미널)
  - Termux:API (하드웨어 접근)
```

### 방안 B: Pydroid 3

```
장점:
  - GUI 지원 (tkinter, kivy)
  - 코드 에디터 내장
  - 초보자 친화적

단점:
  - 하드웨어 접근 제한적
  - 일부 기능 유료
```

### 방안 C: 웹앱 + Python 서버 (가장 현실적)

```
장점:
  - 스마트폰 브라우저에서 실행 (앱 설치 불필요)
  - 서버(PC)에서 Python 실행, 결과를 웹으로 표시
  - 하드웨어 접근: Web API (카메라, 마이크, GPS, 가속도)
  - 기존 사전빌드 시스템과 동일한 구조

단점:
  - PC 서버 필요 (교사 PC)
  - 일부 센서는 웹에서 접근 불가

구조:
  스마트폰 브라우저 → 웹앱 (HTML/JS) → Python 서버 (PC)
  - 웹앱: 센서 데이터 수집 (Web API), 화면 표시
  - Python 서버: 코드 실행, AI 생성, 결과 반환
```

### 방안 D: Flutter 앱 + Python 내장 (하이브리드)

```
장점:
  - 기존 UTTEC 앱과 통합 가능
  - 네이티브 하드웨어 접근 (모든 센서)
  - Chaquopy로 Flutter/Android 내에서 Python 실행

단점:
  - 설정 복잡
  - Chaquopy 라이센스 이슈
```

## 4. 권장 방안: C (웹앱 + Python 서버)

### 이유

1. **기존 시스템과 동일한 구조** — 학생 입력 → 서버 처리 → 결과 표시
2. **앱 설치 불필요** — 스마트폰 브라우저만 있으면 됨
3. **Python 코드를 서버에서 실행** — 안전하고 관리 용이
4. **웹 API로 하드웨어 접근** — 카메라, 마이크, GPS, 가속도 등
5. **교사 PC가 이미 있음** — 사전빌드 서버와 같은 PC에서 운영

### 전체 아키텍처

## 6. 사용자 흐름

```
학생 (스마트폰 브라우저)

1. http://192.168.0.20:8094 접속
         │
2. "스마트폰 흔들면 주사위 굴리기" 입력 → [실행]
         │
3. 사전빌드 검색 → B01 매칭 → 코드+가이드 표시
   또는 → AI가 Python 코드 생성
         │
4. [실행] 버튼 → 브라우저에서 바로 실행
   - 가속도 센서 활성화
   - 화면에 주사위 표시
   - 흔들면 숫자 변경
         │
5. 코드 학습 → 개념 설명, 퀴즈
         │
6. 코드 수정 → 다시 실행 (즉시 반영)
```

### UTTEC Board와의 차이

```
UTTEC Board:  프롬프트 → AI 생성 → 컴파일(~1분) → BLE 전송(~20초) → 보드 동작
스마트폰 Python: 프롬프트 → AI 생성 → 즉시 실행 → 스마트폰 동작
                                       ^^^^^^^^
                                    컴파일/전송 불필요!
```

## 7. 기술 스택

| 구성요소 | 기술 |
|----------|------|
| 프론트엔드 (웹앱) | HTML + JavaScript + Web API |
| 백엔드 (서버) | Python FastAPI |
| Python 실행 | 서버 측 sandbox 또는 브라우저 측 Pyodide |
| AI 코드 생성 | Claude API |
| 센서 접근 | Web API (DeviceMotion, getUserMedia 등) |
| 실시간 통신 | WebSocket |

### Pyodide 옵션 (서버 없이 브라우저에서 Python 실행)

```
Pyodide = 브라우저에서 동작하는 Python (WebAssembly)
  장점: 서버 불필요, 오프라인 가능
  단점: 초기 로딩 느림 (~5초), 일부 라이브러리 미지원
  용도: 기초 Python 학습에 적합
```

## 9. 기존 시스템과의 통합

```
교사 PC 서버

┌──────────────────────────────────────────────┐
│ Port 8095: WROOM 사전빌드 (155개)            │

  [UTTEC Board] → LED/부저/센서 제어 (C언어)
```
