# UTTEC Python Vibe — 앱 구조 설계서

> **작성일**: 2026-04-19
> **참조**: UTTEC Cloud (WROOM) 앱 구조 기반으로 설계

---

## 1. 기존 UTTEC Cloud 앱과의 구조 비교

### UTTEC Cloud (WROOM) — 현재 운영 중

```
MainShell (5탭 BottomNavigation)
├─ HomeTab (🏠 홈) ← 핵심: 카탈로그 + 커스텀 빌드 + Q&A
│  ├─ 사전빌드 카탈로그 (155개, 난이도 필터)
│  ├─ 자유 프롬프트 → AI C코드 생성 → 컴파일 → BLE OTA
│  ├─ 코딩 질문 (Q&A)
│  └─ 빌드 진행률 + OTA 전송 상태
├─ HWTab (🔧 HW) — 하드웨어 학습
├─ SWTab (💻 SW) — 소프트웨어 레퍼런스
├─ PadTab (🎮 패드) — 게임 컨트롤러
└─ SettingsTab (⚙ 설정) — BLE 이름, 서버 URL
```

### UTTEC Python (Python Vibe) — 신규 설계

```
MainShell (4탭 BottomNavigation)
├─ HomeTab (🏠 홈) ← 핵심: 카탈로그 + AI 생성 + Q&A
│  ├─ 사전빌드 카탈로그 (100개, 카테고리+난이도 필터)
│  ├─ 자유 프롬프트 → AI Python 코드 생성 → 즉시 실행
│  └─ 코딩 질문 (Q&A)
├─ LearnTab (📚 학습) — 카테고리별 예시 탐색
├─ PlayTab (▶ 실행) — 코드 에디터 + 실행 결과
└─ SettingsTab (⚙ 설정) — 서버 URL
```

### 핵심 차이

| 구분 | UTTEC Cloud | UTTEC Python |
|------|:---:|:---:|
| BLE/OTA 탭 | 있음 (HW, 패드) | **없음** (스마트폰 자체 실행) |
| 컴파일 대기 | 빌드 진행률 표시 | **불필요** (즉시 실행) |
| 코드 수정 | 불가 (재컴파일 필요) | **가능** (에디터 → 재실행) |
| 실행 환경 | 외부 보드 | **앱 내부** (센서, 카메라 직접) |
| 학습 탭 | 없음 | **있음** (카테고리별 구조적 학습) |

**PlayTab의 코드 실행 방식:**

```
사용자가 코드 입력/수정
  │
  │ [▶ 실행] 클릭
  ▼
코드 유형 판별:
  │
  ├─ 텍스트 출력만 (print, 계산 등)
  │   → expected_output 미리 계산하여 OutputArea에 표시
  │   → 또는 서버에 POST /api/v1/run으로 보내서 실행 결과 받기
  │
  ├─ 센서 사용 코드
  │   → 앱 내 센서 위젯 활성화 (accelerometer, gyroscope)
  │   → 센서 데이터를 코드 결과에 반영
  │
  └─ 카메라/마이크 코드
      → 네이티브 API 호출 (image_picker 등)
      → 결과를 인터랙티브 영역에 표시
```

**참고: 코드 실행 전략**

```
[방안 A] 서버 실행 (추천)
  사용자 코드 → POST /api/v1/run → 서버에서 Python 실행 (sandbox)
  → 결과 반환 → 앱에서 표시
  장점: 실제 Python 실행, 정확한 결과
  단점: 서버 필요, 센서 코드 실행 불가

[방안 B] 앱 내 시뮬레이션
  사용자 코드 → 앱에서 파싱 → 결과 시뮬레이션
  장점: 오프라인 가능
  단점: 제한된 Python 문법만 지원

[방안 C] WebView + Pyodide (하이브리드)
  사용자 코드 → WebView에서 Pyodide(WASM Python) 실행
  장점: 실제 Python, 오프라인 가능
  단점: 초기 로딩 느림, 센서 접근 복잡

→ 현실적 선택: A + 센서 코드는 B의 혼합 방식
  - 텍스트 코드: 서버 실행 (정확한 Python)
  - 센서/카메라 코드: 앱 내 네이티브 위젯
```

## 6. 핵심 흐름: 사용자 입력 → 분기 처리

### HomeTab 입력 처리 흐름

```dart
void _onSubmit(String input) async {
  // 1. 질문인지 판별
  if (_isQuestion(input)) {
    // "~뭐예요?", "~알려줘", "~설명", "~어떻게"
    await _askQuestion(input);
    return;
  }

  // 2. 사전빌드 검색
  final matches = await _searchCatalog(input);

  if (matches.isNotEmpty) {
    // 매칭 결과 표시 + "AI로 만들기" 옵션
    setState(() {
      _searchResults = matches;
      _showSearchResults = true;
    });
  } else {
    // 바로 AI 생성으로 진행
    await _generateCustom(input);
  }
}

bool _isQuestion(String input) {
  final questionPatterns = [
    '뭐예요', '뭐야', '뭔가요', '알려줘', '설명해',
    '어떻게', '왜', '차이', '뭐가 달라', '무슨 뜻',
    '의미가', '언제 써', '쓰는 거', '하는 거',
  ];
  return questionPatterns.any((p) => input.contains(p));
}
```

### ExampleDetailPage — type별 렌더링

```dart
class ExampleDetailPage extends StatelessWidget {
  final Example example;

  Widget _buildInteractiveArea() {
    switch (example.type) {
      case 'text':
        // 실행 버튼 → expected_output 표시
        return TextExampleView(
          expectedOutput: example.expectedOutput!,
        );

      case 'sensor':
        // flutter_widget 키로 위젯 선택
        return _getSensorWidget(example.flutterWidget!);

      case 'camera':
        return CameraWidget();

      case 'canvas':
        return CanvasWidget(webCode: example.webCode!);

      default:
        return TextExampleView(expectedOutput: '');
    }
  }

  Widget _getSensorWidget(String widgetKey) {
    switch (widgetKey) {
      case 'dice':      return DiceWidget();
      case 'sos':       return SOSWidget();
      case 'ball':      return BallWidget();
      case 'pedometer': return PedometerWidget();
      case 'compass':   return CompassWidget();
      // ...
      default:          return GenericSensorWidget();
    }
  }
}
```
