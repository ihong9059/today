> **작성일**: 2026-04-19
> **현재 상태**: 프로토타입 (5개 예시) → 확장 목표 (100개)

---

## 1. 시스템 개요

### 목적
스마트폰의 센서/카메라/마이크 등 하드웨어를 Python 코드로 제어하며 프로그래밍을 배우는 교육 시스템.
기존 UTTEC Board(ESP32 사전빌드)와 동일한 "프롬프트 → 코드 → 실행 → 학습" 구조.

### UTTEC Board vs Python Vibe 비교

```
UTTEC Board:  프롬프트 → AI가 C코드 생성 → Arduino 컴파일(~1분) → BLE OTA(~20초) → 보드 동작
Python Vibe:  프롬프트 → 사전빌드 매칭 또는 AI Python 생성 → 즉시 실행 → 스마트폰 동작
                                                              ^^^^^^^^
                                                          컴파일/전송 불필요!
```

| 구분 | UTTEC Board (WROOM) | UTTEC Mini (C3) | Python Vibe (스마트폰) |
|------|:---:|:---:|:---:|
| 실행 환경 | ESP32 보드 | ESP32-C3 보드 | 스마트폰 자체 |
| 언어 | C/Arduino | C/Arduino | **Python** |
| 컴파일 | 필요 (~1분) | 필요 (~1분) | **불필요** |
| 전송 | BLE OTA (~20초) | BLE OTA (~20초) | **즉시 실행** |
| 추가 장비 | 보드 필요 | 보드 필요 | **스마트폰만** |
| 하드웨어 | LED, 부저, OLED, 센서 | RGB LED, 스피커, 센서 | **카메라, 마이크, GPS, 가속도** |
| 서버 포트 | 8095 (사전빌드), 8092 (커스텀) | 8096 (사전빌드), 8093 (커스텀) | **8094** |

## 3. 실행 경로 (2가지)

학생은 **웹 브라우저** 또는 **Flutter 앱** 중 하나로 접속합니다.

### 경로 A: 웹 브라우저 (index.html + server.py)

```
학생 스마트폰 브라우저
    │
    │  http(s)://192.168.0.20:8094
    ▼
┌─────────────────────────────────────────────────┐
│                server.py (FastAPI, Port 8094)    │
│                                                  │
│  GET /              → index.html 반환            │
│  GET /api/examples  → catalog.json 전체 반환     │
│  GET /api/example/{no} → 특정 예시 반환          │
└─────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────┐
│            index.html (브라우저에서 실행)          │
│                                                  │
│  1. loadExamples()                               │
│     → fetch('/api/examples') → 목록 렌더링       │
│                                                  │
│  2. selectExample(no)                            │
│     → 상세 화면 전환 (코드, 설명 표시)            │
│                                                  │
│  3. runExample()                                 │
│     → new Function(web_code) 실행                │
│     → output(), vibrate(), setBigText() 등 호출  │
│     → showGuide() → 개념 + 퀴즈 표시             │
└─────────────────────────────────────────────────┘
```

**웹 실행의 핵심**: `web_code`(JavaScript)를 `new Function()`으로 동적 실행
- `output(text)` → 결과 영역에 텍스트 출력
- `clearOutput()` → 결과 영역 초기화
- `updateOutput(lineIdx, text)` → 특정 줄 업데이트
- `setBigText(text)` → 큰 글자로 표시 (주사위 이모지 등)
- `vibrate(ms)` → 스마트폰 진동
- `addMotionListener(handler)` → 가속도 센서 이벤트
- `addOrientationListener(handler)` → 자이로 센서 이벤트

**HTTPS 필수**: 센서 API(DeviceMotion, DeviceOrientation)는 HTTPS에서만 동작
- cert.pem/key.pem이 있으면 자동으로 HTTPS 모드
- 없으면 HTTP 모드 (센서 예시 동작 안 됨)

```

    │
    │  앱 실행
    ▼
┌─────────────────────────────────────────────────┐
│             Flutter App (main.dart)              │

│  │  ├─ A04: 카메라 → CameraPage                  │
│  │  └─ A05: 공 굴리기 → BallPage                 │
│  │                                               │

│  ├─ DescCard (설명 + 동작 순서)                   │
```

**Flutter 앱의 특장점**: 네이티브 하드웨어 접근
- `sensors_plus` 패키지 → 가속도/자이로 센서 직접 접근
- `vibration` 패키지 → 진동 모터 제어
- `image_picker` 패키지 → 카메라 촬영
- HTTPS 없어도 센서 동작 (네이티브이므로)
- 오프라인에서도 실행 가능 (서버 불필요)

## 4. 데이터 구조: catalog.json

### 예시 항목 (1개) 전체 구조

```json
{
  "no": "A01",                          // 고유 번호 (카테고리 문자 + 2자리 숫자)
  "title": "화면에 Hello Python! 표시하기",  // 제목
  "category": "화면 출력",               // 카테고리명
  "difficulty": "기초",                  // 난이도: 기초 / 중급 / 고급 / 프로
  "hardware": "화면",                    // 사용 하드웨어
  "description": "Python의 가장 기본...",  // 설명
  "python_code": "print('Hello')\n...",   // Python 코드 (교육용 표시)
  "web_code": "output('Hello');\n...",    // JavaScript 코드 (웹에서 실행)
  "guide": {
    "what_happens": [                     // 동작 순서 (3~4개)
      "화면에 텍스트가 표시됩니다",
      ...
    ],
    "concepts": [                         // 학습 개념 (3개)
      {
        "term": "print()",
        "explanation": "화면에 글자를 보여주는 명령이에요..."
      },
      ...
    ],
    "quiz": {                             // 퀴즈 (1개)
      "question": "print('Hello')를 실행하면?",
      "options": ["Hello", "print", ...],
      "answer": 0,                        // 정답 인덱스 (0부터)
      "explanation": "print()는 괄호 안의 내용을..."
    }
  }
}
```

### python_code vs web_code

| 필드 | 용도 | 언어 | 실행 위치 |
|------|------|------|-----------|
| `python_code` | **교육용 표시** | Python | 실행 안 됨 (보여주기만) |
| `web_code` | **실제 실행** | JavaScript | 웹 브라우저에서 new Function()으로 실행 |

- `python_code`: 학생이 보고 배우는 Python 코드. 실제로 실행되지 않음.
- `web_code`: 같은 동작을 JavaScript로 구현한 것. 브라우저에서 실제 실행됨.
- Flutter 앱에서는 둘 다 사용하지 않음 (Dart로 직접 구현)

## 5. Flutter 앱 내부 구조 (main.dart)

### 클래스 계층

```
PythonVibeApp (MaterialApp)
└─ HomePage (예시 목록 화면)
   ├─ _getPage(no) → switch로 분기
   │  ├─ HelloPage    (A01) — 텍스트 출력만
   │  ├─ DicePage     (A02) — accelerometerEventStream 사용
   │  ├─ SOSPage      (A03) — Vibration.vibrate 사용
   │  ├─ CameraPage   (A04) — ImagePicker 사용
   │  └─ BallPage     (A05) — accelerometerEventStream + CustomPaint
   │
   └─ 공통 위젯 (모든 페이지에서 재사용)
      ├─ CodeCard      — Python 코드 표시 (monospace, 보라색 배경)
      ├─ OutputArea    — 실행 결과 표시 (초록색 텍스트)
      ├─ DescCard      — 설명 + 동작 순서 리스트
      ├─ ConceptCard   — 학습 개념 3개 (왼쪽 보라 테두리)
```

### 각 페이지의 실행 방식

| 페이지 | 센서/하드웨어 | 실행 메커니즘 |
|--------|:---:|---|
| HelloPage | 없음 | 버튼 클릭 → setState()로 미리 정의된 결과 표시 |
| DicePage | 가속도 센서 | initState()에서 accelerometerEventStream 구독 → 흔들림 감지 → Random |
| SOSPage | 진동 모터 | 버튼 클릭 → Vibration.vibrate() 순차 호출 (async/await) |
| CameraPage | 카메라 | 버튼 클릭 → ImagePicker.pickImage(source: camera) → Image.file 표시 |
| BallPage | 가속도 센서 | initState()에서 센서 구독 → 공 좌표 갱신 → CustomPaint 렌더링 |

web_code는 `new Function()`으로 실행되며, 다음 함수들이 주입됩니다:

```javascript

  'output',           // function(text) — 결과 출력
  'clearOutput',      // function() — 결과 초기화
  'updateOutput',     // function(lineIdx, text) — 특정 줄 갱신

  // addOrientationListener(handler) — 자이로 센서
  // document.getElementById('resultArea') — DOM 직접 접근
  web_code_string
);
```

## 7. 센서 접근 경로 비교

### 가속도 센서

```
[Flutter 앱]
sensors_plus 패키지
  → accelerometerEventStream(samplingPeriod: 100ms)
  → Stream<AccelerometerEvent> { x, y, z }
  → HTTPS 불필요, 권한 불필요

[웹 브라우저]
DeviceMotion API
  → addMotionListener(handler)
    → window.addEventListener('devicemotion', handler)
    → event.accelerationIncludingGravity { x, y, z }
  → HTTPS 필수 (cert.pem/key.pem)
  → iOS Safari: requestPermission() 필요
```

### 진동

```
[Flutter 앱]
vibration 패키지
  → Vibration.vibrate(duration: 200)
  → 또는 HapticFeedback.mediumImpact()

[웹 브라우저]
Vibration API
  → navigator.vibrate(200)
  → 대부분 브라우저 지원
```

### 카메라

```
[Flutter 앱]
image_picker 패키지
  → ImagePicker().pickImage(source: ImageSource.camera)
  → File 객체 반환 → Image.file()로 표시

[웹 브라우저]
<input type="file" accept="image/*" capture="environment">
  → FileReader.readAsDataURL()
  → <img src=dataURL>로 표시
  → HTTPS 불필요 (file input 방식)
```

## 8. 서버 API (server.py)

```
FastAPI 서버 (Port 8094)
│
├─ GET /                  → web/index.html 반환 (HTMLResponse)
├─ GET /api/examples      → catalog.json 전체 반환 (JSON)
└─ GET /api/example/{no}  → 특정 번호 예시 반환 (JSON)

CORS: 전체 허용 (allow_origins=["*"])
SSL: cert.pem/key.pem 존재 시 자동 HTTPS
```

### 서버 시작 흐름

```python
if __name__ == "__main__":
    load_examples()              # catalog.json → _examples 변수
    # cert.pem/key.pem 있으면 → HTTPS (센서 동작)
    # 없으면 → HTTP (센서 미동작)
    uvicorn.run(app, host="0.0.0.0", port=8094, ...)
```

## 9. 자유 프롬프트 → AI 코드 생성 → 실행

> 기존 WROOM/Mini의 "커스텀 빌드"에 해당하는 기능.
> 사전빌드 매칭이 안 될 때, AI가 Python 코드를 생성하여 즉시 실행.

### 기존 시스템 (WROOM/Mini) 과의 비교

```
WROOM/Mini 커스텀 빌드:
  프롬프트 → Claude AI → C 코드 생성 → Arduino 컴파일(~1분) → 바이너리 → BLE OTA → 보드 동작
  [build_server_mini.py, Port 8093, /api/v1/generate]

Python Vibe 커스텀 실행:
  프롬프트 → Claude AI → Python 코드 생성 → 즉시 실행 (컴파일 없음!)
  [build_server_vibe.py, Port 8094, /api/v1/generate]
```

| 단계 | WROOM/Mini | Python Vibe |
|------|:---:|:---:|
| AI 코드 생성 | C/Arduino 코드 | **Python + JavaScript(web_code)** |
| 컴파일 | Arduino CLI (~1분) | **불필요** |
| 전송 | BLE OTA (~20초) | **불필요** |
| 실행 | 보드에서 동작 | **브라우저/앱에서 즉시 동작** |
| 빌드 락 | 필요 (동시 컴파일 방지) | **불필요** |
| 결과 저장 | firmware_db/ (Z카테고리) | examples_db/ (Z카테고리) |

### 전체 흐름

```
학생 (스마트폰)
  │
  │ "스마트폰 흔들면 폭죽 터지게 해줘"
  ▼
┌─────────────────────────────────────────────────────────────────┐
│                    웹 UI (index.html) 또는 Flutter 앱           │
│                                                                 │
│  1. smartSearch(prompt)                                         │
│     ├─ GET /api/search?q=폭죽                                  │
│     ├─ 사전빌드 매칭 결과 있으면 → 목록 표시 (사용자 선택)      │
│     └─ 매칭 없으면 → "AI로 만들기" 버튼 표시                   │
│                                                                 │
│  2. 사용자가 "AI로 만들기" 클릭                                 │
│     └─ POST /api/v1/generate  { prompt: "폭죽..." }            │
└─────────────────────────┬───────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────────┐
│               build_server_vibe.py (Port 8094)                  │
│                                                                 │

```

- 동시 요청 문제 없음 (10명이 동시에 요청해도 OK)

## 13. 현재 상태와 한계

### 현재 (프로토타입)

| 항목 | 상태 |
|------|------|
| 예시 개수 | 5개 (A01~A05) |
| 카테고리 | 없음 (A 하나로 통합) |
| Flutter 앱 | **하드코딩** (5개 페이지 클래스) |
| 웹 UI | 동적 (catalog.json에서 로드) |
| AI 코드 생성 | 미구현 |
| 사전빌드 검색 | 미구현 |

### Flutter 앱의 확장 문제

```
현재: 예시 1개 = Dart 클래스 1개 (약 60줄)
      → 100개 = 6,000줄의 하드코딩 = 비현실적

해결 방안:
  1. catalog.json을 앱 assets에 번들
  2. JSON에서 예시 목록 동적 로드
  3. "텍스트 출력" 예시 → GenericPage (코드 + 미리 계산된 출력)
  4. "센서/카메라" 예시 → InteractivePage (네이티브 위젯)
  5. 카테고리별 탭 네비게이션
```

### web_code 확장 문제

```
현재: 각 예시에 python_code + web_code 둘 다 필요
      → 100개 작성 = 200개의 코드 블록

해결 방안:
  A. 순수 텍스트 예시 (변수, 조건문, 반복문 등)
     → web_code = 단순 output() 호출로 자동 생성 가능
     → python_code만 작성하고, expected_output 필드 추가

  B. 센서/하드웨어 예시
     → web_code 수동 작성 필요 (Web API 사용)
     → 10~15개 정도
```

## 17. 작업 순서 (실행 계획)

### Step 1: gen_catalog.py 작성
- 100개 예시 정의 (카테고리별 10개)
- A~G (텍스트): python_code + expected_output
- H~J (인터랙티브): python_code + web_code + flutter_widget
- guide (개념 3개 + 퀴즈 1개) 포함
- → catalog.json 생성

### Step 2: 서버 통합 (server.py 확장)
- 기존 카탈로그 API 유지
- /api/search 추가 (사전빌드 키워드 검색)
- /api/v1/generate 추가 (AI 코드 생성 — 커스텀 요청)
- /api/v1/chat 추가 (코딩 질문 Q&A)
- /api/save-custom 추가 (커스텀 결과 DB 저장)
- 시스템 프롬프트 작성 (Python + 스마트폰 API 맥락)

### Step 3: Flutter 앱 리팩토링
- catalog.json을 assets에 번들
- HomePage: 카테고리 탭 + 검색 + 동적 목록
- ExamplePage: type별 분기 렌더링
- 기존 5개 인터랙티브 위젯 유지 (flutter_widget 키로 매핑)
- 신규 인터랙티브 위젯 추가 (H~J 카테고리)
- 프롬프트 입력창 (자유 입력 → 검색/AI생성 분기)
- 코딩 질문 패널 (하단)

### Step 4: 웹 UI 개선
- 카테고리 탭 추가
- 통합 검색창 (사전빌드 매칭 → AI 생성 폴백)
- 텍스트 예시: expected_output 자동 표시
- 인터랙티브 예시: web_code 실행
- 코드 에디터 (수정 → 재실행 루프)
- 코딩 질문 패널 (하단)

- 사전빌드 매칭 테스트 (100개 예시)

- 코딩 질문 테스트
- 센서/카메라 인터랙티브 테스트 (실기기)
