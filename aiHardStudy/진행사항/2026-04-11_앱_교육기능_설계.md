# 앱 교육 기능 설계 — 하드웨어 이해 + 소프트웨어 학습 + 단축 실행

> **날짜**: 2026-04-11
> **목적**: 단순 제어 도구가 아닌, C언어 문법과 하드웨어 동작 원리를 체계적으로 학습하는 교육 앱으로 확장
> **핵심 변경**: 앱에 3개 탭 추가 — 하드웨어 학습, 소프트웨어 학습, 단축 실행 패드

---

## 1. 설계 방향 전환

### 기존 설계 (제어 도구)

```
프롬프트 입력 → 실행 → 결과 확인 → 끝
(하드웨어가 왜/어떻게 동작하는지 모름)
```

### 변경 설계 (교육 플랫폼)

```
하드웨어를 이해하고 → 코드를 이해하고 → 직접 실행하고 → 원리를 깨닫는다

┌─────────────────────────────────────────────────────────┐
│                    학습 순환 사이클                       │
│                                                          │
│   ① 하드웨어 학습      "LED가 뭐고, 어떻게 연결돼있지?"│
│        │                                                 │
│        ▼                                                 │
│   ② 단축 실행          "버튼 하나로 LED를 켜보자!"      │
│        │                                                 │
│        ▼                                                 │
│   ③ 코드 학습          "아, gpio_set_level이 이 역할!"  │
│        │                                                 │
│        ▼                                                 │
│   ④ 프롬프트 작성      "그럼 깜빡이게 하려면..."        │
│        │                                                 │
│        ▼                                                 │
│   ⑤ 코드 비교          "내가 상상한 것과 AI가 쓴 코드"  │
│        │                                                 │
│        └──▶ ① 로 돌아가 다음 주제 학습                  │
└─────────────────────────────────────────────────────────┘
```

## 2. 앱 탭 구조 변경

### 기존 (4탭)

```
[ 🏠홈 ] [ 📋이력 ] [ 📱기기 ] [ ⚙설정 ]
```

### 변경 (5탭)

```
[ 🏠홈 ] [ 🔧HW ] [ 💻SW ] [ 🎮패드 ] [ ⚙설정 ]
   │        │        │        │          │
   │        │        │        │          └── 기기관리+이력+설정 통합
   │        │        │        └── 단축 실행 패드 (교육용 버튼 모음)
   │        │        └── 소프트웨어 학습 (C언어, 코드 구조)
   │        └── 하드웨어 학습 (회로, 부품, 동작 원리)
   └── 프롬프트 입력 + 실행 (기존과 동일)
```

### 3-2. 부품 카드 탭 시 — 상세 화면 (예: LED)

```
┌─────────────────────────────────────────┐
│  ←  🔴 LED (발광다이오드)               │
├─────────────────────────────────────────┤
│                                         │
│  ┌─ 이게 뭐야? ──────────────────────┐ │
│  │                                    │ │
│  │  LED는 전기를 흘리면 빛나는        │ │
│  │  작은 전구예요.                    │ │
│  │                                    │ │
│  │  [LED 실물 사진]                   │ │
│  │                                    │ │
│  │  이 보드에는 3개가 달려 있어요:    │ │
│  │  🔴 빨강  🟡 노랑  🔵 파랑        │ │
│  └────────────────────────────────────┘ │
│                                         │
│  ┌─ 어떻게 연결돼 있어? ─────────────┐ │
│  │                                    │ │
│  │  ESP32                LED          │ │
│  │  GPIO33 ──[100Ω]──▶|── GND       │ │
│  │           (저항)    (LED)          │ │
│  │                                    │ │
│  │  💡 저항이 왜 필요해?              │ │
│  │  LED에 전류가 너무 많이 흐르면     │ │
│  │  타버려요. 저항이 전류를           │ │
│  │  적당히(13mA) 줄여줍니다.          │ │
│  │                                    │ │
│  │  계산: (3.3V - 2.0V) / 100Ω       │ │
│  │       = 13mA ✅ 안전               │ │
│  └────────────────────────────────────┘ │
│                                         │
│  ┌─ 어떻게 켜고 꺼? ─────────────────┐ │
│  │                                    │ │
│  │  GPIO33에 전압을 주면 (HIGH=3.3V)  │ │
│  │  → 전류가 흘러 → LED가 켜짐 💡    │ │
│  │                                    │ │
│  │  GPIO33에 전압을 끊으면 (LOW=0V)   │ │
│  │  → 전류가 안 흘러 → LED가 꺼짐 ⚫ │ │
│  │                                    │ │
│  │  이것을 "Active HIGH"라고 해요     │ │
│  │  (HIGH 신호 = 켜짐)               │ │
│  └────────────────────────────────────┘ │
│                                         │
│  ┌─ 핀 정보 ─────────────────────────┐ │
│  │  핀 번호    GPIO33                 │ │
│  │  방향       출력 (Output)          │ │
│  │  극성       Active HIGH            │ │
│  │  저항       100Ω (직렬)            │ │
│  │  전류       13mA                   │ │
│  │  board.h    PIN_LED_RED            │ │
│  └────────────────────────────────────┘ │
│                                         │
│  ┌────────────────────────────────────┐ │
│  │  🎮 지금 바로 켜보기 →             │ │  ← 패드 탭으로 이동
│  └────────────────────────────────────┘ │
│  ┌────────────────────────────────────┐ │
│  │  💻 코드로 보기 →                  │ │  ← SW 탭으로 이동
│  └────────────────────────────────────┘ │
│                                         │
└─────────────────────────────────────────┘
```

### 3-3. 부품별 학습 콘텐츠 구조

모든 부품은 동일한 4단계 구조로 설명합니다:

```
[1] 이게 뭐야?        — 실생활 비유 + 실물 사진
[2] 어떻게 연결돼 있어? — 회로 경로 그림 + 저항/전류 설명
[3] 어떻게 제어해?     — HIGH/LOW, PWM, I2C 등 동작 원리
[4] 핀 정보            — GPIO 번호, board.h 매크로명, 극성
```

| 부품 | [1] 비유 | [2] 회로 핵심 | [3] 제어 방식 |
|------|---------|-------------|-------------|
| 🔴 LED | "작은 전구" | GPIO→저항→LED→GND | HIGH=켜짐, LOW=꺼짐 |
| 🔔 BEEP 부저 | "초인종 벨" | VCC→부저→GPIO | LOW=울림 (Active LOW) |
| 🎵 MELODY 부저 | "피아노 건반" | GPIO→저항→트랜지스터→부저 | PWM 주파수=음높이 |
| 🔘 스위치 | "문 열기 버튼" | GPIO←스위치→GND (+캐패시터) | 누름=LOW, 안누름=HIGH |
| 📺 OLED | "작은 TV 화면" | I2C SDA/SCL, 풀업 저항 | I2C 주소 0x3C로 명령 전송 |
| 🌡 AHT20 | "디지털 온도계" | I2C SDA/SCL (OLED과 공유) | 측정 명령 → 80ms 대기 → 읽기 |
| 📡 LoRa | "무전기" | UART TX/RX + M0/M1 모드 | 시리얼로 데이터 송수신 |
| 🌈 NeoPixel | "마법 LED" | 데이터 1핀으로 체인 연결 | 색상 데이터(RGB) 순차 전송 |
| 🔌 SPI | "고속 데이터 도로" | MOSI/MISO/SCK/SS 4핀 | Master-Slave 전이중 통신 |

### 4-3. 코드 뷰어 — 실행 결과와 코드를 나란히 보기

바이브 코딩으로 실행한 결과의 코드를 **한 줄씩 설명**하는 화면:

```
┌─────────────────────────────────────────┐
│  ←  코드 분석: "LED 깜빡이기"           │
├─────────────────────────────────────────┤
│                                         │
│  ┌─ 코드 (탭하면 줄별 설명) ─────────┐ │
│  │                                    │ │
│  │ 1  #include "board.h"             │ │ ← 탭
│  │    ┌─────────────────────────┐     │ │
│  │    │📎 board.h 파일을 가져와  │    │ │  풍선 설명
│  │    │   PIN_LED_RED=33 같은   │     │ │
│  │    │   이름들을 쓸 수 있게   │     │ │
│  │    └─────────────────────────┘     │ │
│  │                                    │ │
│  │ 2                                  │ │
│  │ 3  void app_main(void) {          │ │ ← 탭
│  │    ┌─────────────────────────┐     │ │
│  │    │🚀 프로그램이 여기서     │     │ │
│  │    │   시작돼요!             │     │ │
│  │    │   ESP32가 켜지면 이     │     │ │
│  │    │   함수를 제일 먼저 실행 │     │ │
│  │    └─────────────────────────┘     │ │
│  │                                    │ │
│  │ 4    gpio_set_direction(           │ │
│  │ 5      PIN_LED_RED,                │ │
│  │ 6      GPIO_MODE_OUTPUT);          │ │ ← 탭
│  │    ┌─────────────────────────┐     │ │
│  │    │⚡ GPIO33번 핀을 "출력"  │     │ │
│  │    │   모드로 설정해요       │     │ │
│  │    │   (입력이 아니라 출력!) │     │ │
│  │    │                         │     │ │
│  │    │   🔧HW: LED 페이지 →    │    │ │  HW탭 링크
│  │    └─────────────────────────┘     │ │
│  │                                    │ │
│  │ 7                                  │ │
│  │ 8    while (1) {                   │ │ ← 탭
│  │    ┌─────────────────────────┐     │ │
│  │    │🔄 "계속 반복해!"        │     │ │
│  │    │   while(1)은 "영원히"   │     │ │
│  │    │   라는 뜻이에요         │     │ │
│  │    └─────────────────────────┘     │ │
│  │                                    │ │
│  │ 9      gpio_set_level(             │ │
│  │10        PIN_LED_RED, LED_ON);     │ │ ← 탭
│  │    ┌─────────────────────────┐     │ │
│  │    │💡 빨간 LED를 켜요!      │     │ │

│  │    │   기다려요              │     │ │
│  │    │   이 시간이 깜빡이는   │     │ │
│  │    │   속도를 결정해요!     │     │ │
│  │    │                         │     │ │
│  │    │   🎮 숫자를 바꿔보기 →  │     │ │  패드 링크
│  │    └─────────────────────────┘     │ │

│  │14        PIN_LED_RED, LED_OFF);    │ │
```

### 4-4. 전체 학습 경로 커리큘럼

```
1. C언어 기초
   1-1. 프로그램의 시작점 (app_main)
   1-2. 변수와 숫자 (int, #define)
   1-3. #include와 #define (board.h)
   1-4. 함수 호출하기 (gpio_set_level)
   1-5. 주석 달기 (// 와 /* */)

2. GPIO 제어
   2-1. 핀 모드 설정 (입력/출력)
   2-2. 디지털 출력 (LED 켜기/끄기)
   2-3. 디지털 입력 (스위치 읽기)
   2-4. Active HIGH vs Active LOW

3. 반복과 조건
   3-1. while 무한 루프
   3-2. for 반복문 (LED 순차 점등)
   3-3. if 조건문 (버튼 → LED)
   3-4. if-else (버튼 토글)
   3-5. vTaskDelay (시간 지연)

4. 함수
   4-1. 함수 만들기 (led_on, led_off)
   4-2. 매개변수 (어떤 LED를 켤지)
   4-3. 반환값 (스위치 상태 읽기)
   4-4. 배열과 반복 (LED 3개 제어)

5. I2C 통신
   5-1. I2C란? (SDA, SCL 두 줄로 대화)
   5-2. 주소로 디바이스 선택 (0x3C, 0x38)
   5-3. AHT20 온도 읽기
   5-4. OLED에 문자 표시

6. PWM과 타이머
   6-1. PWM이란? (빠르게 껐다 켰다)
   6-2. LED 밝기 조절
   6-3. 부저로 음계 만들기
   6-4. 멜로디 연주하기

7. 인터럽트
   7-1. 인터럽트란? (급한 전화)
   7-2. 버튼 인터럽트 (누르는 즉시 반응)
   7-3. 디바운스 처리

8. UART 통신
   8-1. 시리얼 통신이란? (TX/RX)
   8-2. 시리얼 모니터에 출력
   8-3. LoRa 모듈과 대화

9. 종합 프로젝트
   9-1. 스마트 온도계 (센서+OLED+부저 경보)
   9-2. 무선 리모컨 (LoRa 송수신)
   9-3. 나만의 프로젝트
```

### 5-3. 단축 버튼 → 코드 연결

모든 단축 버튼은 내부적으로 **미리 작성된 프롬프트**를 실행합니다.
실행 후 "코드 보기"로 어떤 코드가 생성되었는지 확인할 수 있습니다.

```
[버튼]              [내부 프롬프트]                    [학습 포인트]
──────              ──────────────                    ──────────────
🔴 RED ON          "GPIO33을 HIGH로 설정해"          gpio_set_level
🚦 전체 점멸       "3개 LED를 0.5초마다 깜빡여"       while + delay
🌈 순차 돌리기     "빨강→노랑→파랑 순서로 켜줘"       for + 배열
🔔 삐!             "부저를 0.1초 울려줘"               Active LOW
♪ 도               "부저를 262Hz로 0.3초 울려줘"       PWM 주파수
🌡 온도 읽기       "AHT20에서 온도를 읽어 출력해"      I2C 통신
📺 Hello 표시      "OLED에 Hello를 표시해"             I2C 디스플레이
🎪 파티모드        "모든 LED를 랜덤으로 깜빡이고       종합 제어
                    부저로 짧은 멜로디를 재생해"
```

### 5-4. 단축 버튼의 교육 흐름

```
[1] 학습자가 패드에서 🔴 RED 버튼을 탭
         │
         ▼
[2] 앱이 내부적으로 프롬프트 전송 → 빌드 → OTA (또는 직접 명령)
         │
         ▼
[3] LED가 실제로 켜짐 → 학습자: "오! 켜졌다!"
         │
         ▼
[4] 화면 하단에 알림: "💻 방금 실행된 코드를 볼까요?"
         │
         ├── [코드 보기] → 코드 뷰어로 이동 (줄별 설명)
         │
         └── [HW 보기] → LED 하드웨어 설명 페이지로 이동
```

## 9. 이 설계의 교육 효과

```
기존 임베디드 교육:
  교과서 읽기 → 이론 이해 → 코드 작성 → 에러 → 좌절 → 포기
  (이해 → 실행, "안 되는" 경험이 먼저)

바이브 코딩 교육 앱:
  버튼 누르기 → LED 켜짐 → "왜?" → 회로 보기 → 코드 보기 → 이해
  (실행 → 이해, "되는" 경험이 먼저)

최종 목표:
  패드로 체험 → HW로 원리 이해 → SW로 코드 이해
  → 프롬프트로 응용 → 직접 코드 작성
  → "나는 임베디드 개발자다"
```
