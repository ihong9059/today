## 1. 전체 시스템 구조

### 1-1. 3-Tier 아키텍처

```
┌─────────────────────┐     ┌──────────────────────┐     ┌─────────────────────┐
│   스마트폰 (앱)      │     │   빌드 서버 (PC)      │     │   ESP32 (디바이스)   │
│                     │     │                      │     │                     │
│  Flutter 네이티브 앱 │────▶│  FastAPI 서버 (:8092) │     │  Arduino 펌웨어     │
│  - 프롬프트 입력     │HTTP │  - Claude CLI        │     │  - NimBLE BLE 서버  │
│  - 빌드 상태 표시    │◀────│  - Arduino-CLI 빌드   │     │  - OTA 수신 핸들러   │
│  - BLE OTA 클라이언트│     │  - .bin 생성          │     │  - LED/부저/OLED    │
│  - 패드 실시간 제어  │     └──────────────────────┘     │  - 커맨드 수신       │
│                     │                                  │                     │
│  flutter_blue_plus   │─────────────── BLE ─────────────▶│  NimBLE GATT 서버   │
└─────────────────────┘                                  └─────────────────────┘
    Android APK                                           ESP32-WROOM-32
```

### 1-2. 데이터 흐름

```
[1] 사용자: "LED를 깜빡여줘" (스마트폰에서 자연어 입력)
        │
        ▼ HTTP POST /api/v1/generate
[2] 빌드 서버 (PC:8092)
        │
        ├─[2a] Claude CLI: 자연어 → Arduino C 코드 생성 (~15초)
        │       - 시스템 프롬프트에 보드 정보/API 명세 포함
        │       - 한국어 주석 자동 생성 (교육용)
        │       - setup() + loop() 함수 생성
        │
        ├─[2b] 코드 합치기: BLE OTA 베이스 + 생성된 코드
        │       - ble_ota_arduino.ino의 BLE/OTA 부분 유지
        │       - setup()/loop() 부분만 교체
        │
        ├─[2c] Arduino-CLI 빌드: .ino → .bin (~30초)
        │       - arduino-cli compile --fqbn esp32:esp32:esp32
        │       - 파티션: min_spiffs (OTA 지원)
        │
        ▼ HTTP GET /api/v1/download/{job_id}
[3] 스마트폰: .bin 다운로드 (~1초, 약 640KB)
        │
        ▼ BLE GATT Write
[4] BLE OTA 전송 (스마트폰 → ESP32, ~14초)
        │
        ├─[4a] OTA_CONTROL에 START 명령 + 파일 크기 전송
        ├─[4b] OTA_DATA에 240바이트씩 chunk 전송
        ├─[4c] OTA_CONTROL에 END 명령
        │
        ▼
[5] ESP32: 검증 → 파티션 전환 → 재부팅 → 새 펌웨어 동작!
```

## 3. BLE OTA 프로토콜 상세

### 3-1. GATT 서비스 구조

```
OTA Service (UUID: 0000FE00-0000-1000-8000-00805F9B34FB)
│
├── OTA_CONTROL (FE01) — Write
│   └── 명령 전송: START / END / ABORT
│
├── OTA_DATA (FE02) — Write Without Response
│   └── 펌웨어 바이너리 chunk 전송 (240B/chunk)
│
├── OTA_STATUS (FE03) — Notify
│   └── ESP32 → 앱: 진행 상태 알림 [상태코드, 진행률%]
│
└── CMD (FE04) — Write
    └── 패드 실시간 제어 명령 (LED_RED_ON, BEEP, NOTE_0, 등)
```

### 3-2. OTA 전송 절차

```
스마트폰 (클라이언트)                    ESP32 (서버)
    │                                       │
    │  ① GATT 연결 (MTU=256)                │
    │──────────────────────────────────────▶│
    │                                       │
    │  ② OTA_STATUS Notify 구독             │
    │──────────────────────────────────────▶│
    │                                       │
    │  ③ OTA_CONTROL: START [0x01][크기4B]  │
    │──────────────────────────────────────▶│
    │                                       │ Update.begin(크기)
    │  ④ OTA_STATUS: READY (0x01)           │
    │◀──────────────────────────────────────│
    │                                       │
    │  ⑤ OTA_DATA: chunk 1 (240B)          │
    │──────────────────────────────────────▶│ Update.write(chunk)
    │  ⑤ OTA_DATA: chunk 2 (240B)          │
    │──────────────────────────────────────▶│ Update.write(chunk)
    │  ...반복 (~2650회, 640KB 기준)...      │
    │                                       │
    │  ⑥ OTA_STATUS: RECEIVING (0x02, N%)   │ 매 2KB마다
    │◀──────────────────────────────────────│
    │                                       │
    │  ⑦ OTA_CONTROL: END [0x02]            │
    │──────────────────────────────────────▶│ Update.end(true)
    │                                       │ → 검증 + 파티션 전환
    │  ⑧ OTA_STATUS: VERIFYING (0x03, 100%) │
    │◀──────────────────────────────────────│
    │                                       │
    │  ⑨ OTA_STATUS: SUCCESS (0x04, 100%)   │
    │◀──────────────────────────────────────│
    │                                       │ delay(2000)
    │  ⑩ BLE 연결 끊김                      │ ESP.restart()
    │◀ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─│
    │                                       │
    │  ⑪ 5초 후 자동 재연결                  │ 새 펌웨어로 부팅
    │──────────────────────────────────────▶│
    │                                       │
```

### 3-3. OTA 상태 코드

| 코드 | 이름 | 설명 |
|:----:|------|------|
| 0x00 | IDLE | 대기 상태 |
| 0x01 | READY | START 수신, 쓰기 준비 완료 |
| 0x02 | RECEIVING | 데이터 수신 중 (진행률 포함) |
| 0x03 | VERIFYING | 검증 중 |
| 0x04 | SUCCESS | 성공, 재부팅 예정 |
| 0x05 | CRC_FAIL | 검증 실패 |
| 0x06 | WRITE_FAIL | Flash 쓰기 실패 |
| 0x07 | ABORT_OK | 중단 완료 |

### 3-4. OTA 명령 코드

| 코드 | 이름 | 페이로드 | 설명 |
|:----:|------|----------|------|
| 0x01 | START | [크기 4B, Little-Endian] | OTA 시작, 총 크기 전달 |
| 0x02 | END | 없음 | 전송 완료, 검증 요청 |
| 0x03 | ABORT | 없음 | OTA 중단 |

## 4. ESP32 메모리 / 파티션 구성

### 4-1. Flash 메모리 레이아웃 (4MB, min_spiffs 파티션)

```
Flash 주소 공간 (4MB = 0x400000)
┌──────────────────────────────────────┐ 0x000000
│  Bootloader (24KB)                   │
│  - 2차 부트로더                       │
│  - 파티션 테이블 읽기                 │
│  - OTA 파티션 선택                    │
├──────────────────────────────────────┤ 0x008000
│  Partition Table (4KB)               │
│  - 파티션 정보 (이름, 타입, 위치)     │
├──────────────────────────────────────┤ 0x009000
│  NVS (20KB)                          │
│  - Non-Volatile Storage              │
│  - WiFi 설정, BLE 본딩 정보 등       │
├──────────────────────────────────────┤ 0x00E000
│  OTA Data (8KB)                      │
│  - 현재 부팅 파티션 정보              │
│  - app0 또는 app1 중 어디서 부팅할지  │
├──────────────────────────────────────┤ 0x010000
│                                      │
│  app0 / ota_0 (1,920KB = 1.875MB)    │
│  - 첫 번째 앱 파티션                  │
│  - USB 플래싱 시 여기에 기록          │
│  - 현재 실행 중인 펌웨어              │
│                                      │
├──────────────────────────────────────┤ 0x1F0000
│                                      │
│  app1 / ota_1 (1,920KB = 1.875MB)    │
│  - 두 번째 앱 파티션                  │
│  - OTA 수신 시 여기에 기록            │
│  - 다음 부팅 시 사용할 펌웨어         │
│                                      │
├──────────────────────────────────────┤ 0x3D0000
│  SPIFFS (128KB)                      │
│  - 파일 시스템 (설정 파일 등)         │
├──────────────────────────────────────┤ 0x3F0000
│  Coredump (64KB)                     │
│  - 크래시 덤프 저장                   │
└──────────────────────────────────────┘ 0x400000
```

### 4-2. OTA 듀얼 파티션 동작 원리

```
[최초 USB 플래싱]
  app0: ★ 펌웨어 A (실행 중)
  app1: (비어있음)
  OTA Data: → app0

[1차 OTA 전송]
  app0: 펌웨어 A
  app1: ★ 펌웨어 B (새로 기록) ← OTA로 수신
  OTA Data: → app1 (전환!)
  → 재부팅 → app1의 펌웨어 B 실행

[2차 OTA 전송]
  app0: ★ 펌웨어 C (새로 기록) ← OTA로 수신
  app1: 펌웨어 B (이전)
  OTA Data: → app0 (전환!)
  → 재부팅 → app0의 펌웨어 C 실행

[3차 OTA 전송]
  app0: 펌웨어 C (이전)
  app1: ★ 펌웨어 D (새로 기록) ← OTA로 수신
  OTA Data: → app1 (전환!)
  → 재부팅 → app1의 펌웨어 D 실행

→ app0과 app1을 번갈아 사용 (핑퐁 방식)
→ 이전 펌웨어가 항상 남아있어 롤백 가능
```


## 5. 패드 제어 BLE 프로토콜

### 5-1. CMD 특성 (FE04)

스마트폰에서 ESP32로 문자열 명령을 전송합니다.

| 명령 | 동작 |
|------|------|
| `LED_RED_ON` | 빨간 LED 켜기 (GPIO25 HIGH) |
| `LED_RED_OFF` | 빨간 LED 끄기 (GPIO25 LOW) |
| `LED_YELLOW_ON` | 노란 LED 켜기 (GPIO26 HIGH) |
| `LED_YELLOW_OFF` | 노란 LED 끄기 (GPIO26 LOW) |
| `LED_BLUE_ON` | 파란 LED 켜기 (GPIO27 HIGH) |
| `LED_BLUE_OFF` | 파란 LED 끄기 (GPIO27 LOW) |
| `LED_ALL_OFF` | 모든 LED 끄기 |
| `BEEP` | 부저 100ms 울림 (GPIO14 Active LOW) |
| `NOTE_0` ~ `NOTE_7` | 피아노 음 (도~도', GPIO33 PWM) |
| `OLED:텍스트` | OLED에 텍스트 표시 |
| `TEMP` | 온도 읽기 (미구현) |

### 5-2. 패드 동작 흐름

```
[스마트폰 패드 탭]         [BLE]           [ESP32]
     │                      │                │
  🔴 RED 터치               │                │
     │──"LED_RED_ON"────────▶│───Write FE04──▶│
     │                      │                │ digitalWrite(25, HIGH)
     │                      │                │ → LED 켜짐!
     │                      │                │
  🔴 RED 터치 (다시)        │                │
     │──"LED_RED_OFF"───────▶│───Write FE04──▶│
     │                      │                │ digitalWrite(25, LOW)
     │                      │                │ → LED 꺼짐
     │                      │                │
  🎹 '미' 터치              │                │
     │──"NOTE_2"────────────▶│───Write FE04──▶│
     │                      │                │ tone(33, 330, 300)
     │                      │                │ → 미 음 300ms
```

## 6. 보안 고려사항 (현재 상태)

| 항목 | 현재 | 권장 |
|------|------|------|
| 서버 통신 | HTTP (평문) | HTTPS (Let's Encrypt) |
| API 인증 | 없음 | API 키 또는 JWT |
| BLE 페어링 | 없음 (오픈) | Passkey 또는 OOB |
| OTA 서명 | 없음 | SHA256 + RSA 서명 |
| 빌드 격리 | 공유 디렉토리 | Docker 컨테이너 |

> 현재는 교육/개발 환경이므로 보안이 최소화되어 있습니다.
> 프로덕션 배포 시 위 항목들을 반드시 적용해야 합니다.
