## 오늘 완료한 것

### 1. BLE OTA 크래시 해결 (ESP-IDF)
- **원인**: `ble_hs_id_infer_auto(0, NULL)` — NULL 포인터 역참조
- **해결**: `uint8_t own_addr_type` 변수를 전달하도록 수정
- **추가**: no-op store 콜백 제공 (NimBLE IRK 경고 제거)
- **결과**: ESP32 BLE 광고 정상 시작, OTA 듀얼 파티션 전환 성공

### 2. BLE OTA 전체 플로우 검증 (PC → ESP32)
- Python `ota_test_client.py` (bleak 라이브러리)로 PC에서 BLE OTA 전송 성공
- v1(파랑 LED) → v2(RGB 순차) OTA 전환 확인
- 전송 속도: 468KB / 11초 / 43KB/s

### 3. 클라우드 빌드 서버 구축 (Digital Ocean)
- **서버**: 178.128.90.37:8090 (Ubuntu 24.04, 2vCPU, 4GB)
- ESP-IDF v5.5.1 + Claude CLI 설치
- FastAPI 빌드 서버 (`build_server.py`)
- 프롬프트 → Claude 코드 생성 → ESP-IDF 빌드 → .bin 다운로드 API
- 빌드 시간: ~220초

### 4. 로컬 빌드 서버 구축 (이 PC)
- **ESP-IDF 서버**: localhost:8091
  - 최초 270초 → ccache + export 스킵 최적화 → **39초**
- **Arduino 서버**: localhost:8092

  - 증분 빌드 **44~57초**

### 5. ESP-IDF → Arduino 프레임워크 전환
| | ESP-IDF (이전) | Arduino (현재) |
|---|---|---|
| 코드 스타일 | app_main() + FreeRTOS | setup() + loop() |
| BLE | NimBLE 수동 설정 | NimBLE-Arduino 간편 |
| OTA | esp_ota_ops 수동 | Update 라이브러리 자동 |
| 빌드 시간 | 39초 (최적화 후) | 44초 |
| Claude 정확도 | API 불일치 빈번 | 정확도 높음 |
| 교육 적합성 | 어려움 | 초보자 친화적 |

### 6. Flutter 스마트폰 앱 개발
- **Flutter SDK 설치** (3.32.2) + Android APK 빌드
- **USB 설치**: `adb install` → 스마트폰에 네이티브 앱 설치
- **5탭 구조** 구현:

| 탭 | 기능 |
|---|---|
| 🏠 홈 | 프롬프트 입력 → 빌드 → 자동 BLE 연결 → OTA 전송 |
| 🔧 HW | 9개 하드웨어 부품 상세 설명 (LED, 부저, OLED 등) |
| 💻 SW | C언어/GPIO/반복문 학습 + 코드 뷰어 (터치 → 설명 펼침) |
| 🎮 패드 | LED 토글, 부저, 피아노 건반, OLED 실시간 BLE 제어 |
| ⚙ 설정 | 서버 URL, BLE 기기 스캔/선택/이름변경, 영구 저장 |

### 7. 앱 주요 기능 상세

#### 홈 탭
- 예시 프롬프트 칩 (터치 → 자동 입력): LED 깜빡이기, 부저 5회, 멜로디 연주 등
- 빌드 중 경과 시간 실시간 표시 + 무한 프로그레스 바
- 빌드 완료 → 자동 BLE 연결 → 자동 OTA 전송 (원터치)
- OTA 완료 시 ✅ 성공 화면 + "UTTEC 보드를 확인하세요"
- 생성된 코드 학습 카드: `// [주제] 설명` 주석 → 💡 설명 박스로 표시
- 최근 기록 10개 (펼치기/접기, 터치 → 재실행)

#### 패드 탭 (BLE 실시간 제어)
- LED 토글 (RED/YELLOW/BLUE) — 즉시 ESP32 반응
- 부저 (삐!) + 멜로디 (도레미파솔라시도)
- 피아노 건반 8키 — 터치 즉시 음 재생
- OLED 텍스트 표시
- CMD 특성 (FE04) 통한 문자열 명령 프로토콜

#### 설정 탭
- BLE 기기 스캔 → 목록에서 선택 → 이름 + MAC 영구 저장
- 기기 이름 변경 → 앱 SharedPreferences + ESP32 NVS 동시 저장
- ESP32 재부팅 시 변경된 이름으로 BLE 광고
- 서버 URL 영구 저장

### 8. UTTEC 브랜딩 적용
- BLE 이름: ESP32-OTA → **UTTEC-OTA**
- 앱 타이틀: Vibe Firmware → **UTTEC Firmware**
- 모든 UI 문구: ESP32 → **UTTEC 보드**
- OLED 표시: **UTTEC Firmware**
- BLE 이름 NVS 영구 저장 (양산 후 학생별 고유 이름 설정 가능)

### 9. BLE 이름 개별 설정 기능 (양산 대비)
```
교육 현장:
  학생 A → 설정에서 "UTTEC-A반1번" 저장
    ├── 앱: SharedPreferences 영구 저장
    └── ESP32: NVS 영구 저장 + 재부팅 → 새 이름으로 광고

  학생 B → 설정에서 "UTTEC-A반2번" 저장
    → 각자 자기 보드만 찾아서 연결
```

## 해결한 문제들

| # | 문제 | 원인 | 해결 |
|---|------|------|------|
| 1 | BLE 광고 시 StoreProhibited 크래시 | `ble_hs_id_infer_auto(0, NULL)` | `&own_addr_type` 전달 |

| 6 | Flutter BLE 이름 검색 실패 | NimBLE 2.x 광고 이름 | MAC 주소 대체 검색 |
| 7 | OTA 후 앱에서 실패 표시 | ESP32 재부팅 시 연결 끊김 | 95% 이상이면 성공 처리 |
| 8 | OTA 후 이전 펌웨어 유지 | ESP-IDF 파티션 레이아웃 불일치 | Flash 전체 지우기 + Arduino 파티션 |
| 9 | 클라우드 빌드 후 롤백 | rollback 확인 코드 누락 | `esp_ota_mark_app_valid` 추가 |
| 10 | 앱 BLE 버튼 글자 안 보임 | foregroundColor 미설정 | `Colors.white` 명시 |
| 11 | BLE 이름 변경 후 유지 안 됨 | 메모리에서만 저장 | SharedPreferences + NVS |
