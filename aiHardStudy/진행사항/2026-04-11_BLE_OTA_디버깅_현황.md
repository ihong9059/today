## 1. 현재 상황

### 동작하는 것 ✅
- OTA 듀얼 파티션 부팅 (ota_0에서 정상 부팅)
- OLED 상태 표시 ("바이브 코딩", "BLE OTA Ready!", "Waiting connect...")
- 파랑 LED 느린 깜빡임 (BLE 대기 표시)
- NVS 초기화
- NimBLE 초기화 (`BLE_OTA: BLE OTA initialized` 출력)

### 크래시 발생 지점 🔴
```
I (888) BLE_OTA: BLE OTA initialized
I (898) MAIN: === BLE OTA Ready ===
I (898) MAIN: MAC: 78:1C:3C:F4:AD:02
I (898) MAIN: Device name: ESP32-OTA
I (898) MAIN: Waiting for BLE connection...
I (938) NimBLE: Failed to restore IRKs from store; status=8   ← 여기서
Guru Meditation Error: Core 0 panic'ed (StoreProhibited)       ← 크래시!
```

### 크래시 원인 분석
- `StoreProhibited` = 잘못된 메모리 주소에 접근 (읽기/쓰기)
- `Failed to restore IRKs from store; status=8` = NimBLE이 NVS에서 IRK(Identity Resolving Key) 복원 실패
- `on_sync` 콜백 → `start_advertising()` → NimBLE 내부에서 IRK store 접근 시 NULL 포인터 참조 추정
- **NVS_PERSIST를 꺼도** NimBLE 내부에서 여전히 store 접근 시도

### 시도한 해결 방법 (모두 실패)
| # | 시도 | 결과 |
|---|------|------|
| 1 | NVS 파티션만 지우기 (`erase_region 0x9000 0x6000`) | ❌ 동일 크래시 |
| 2 | `CONFIG_BT_NIMBLE_NVS_PERSIST=n` 설정 | ❌ 동일 크래시 |
| 3 | 전체 Flash 지우기 (`erase_flash`) + 재플래싱 | ❌ 동일 크래시 |
| 4 | `ble_svc_gap_device_name()` 대신 상수 문자열 사용 | ❌ 동일 크래시 |
| 5 | `ble_gap_adv_set_fields` 에러 체크 추가 | ❌ 크래시는 그 전에 발생 |

## 2. 다음 세션에서 시도할 것

### 방법 A: NimBLE store 콜백 비활성화
```c
// on_sync 콜백에서 store를 사용하지 않도록
ble_hs_cfg.store_read_cb = NULL;   // ← 추가
ble_hs_cfg.store_write_cb = NULL;  // ← 추가
ble_hs_cfg.store_delete_cb = NULL; // ← 추가
ble_hs_cfg.store_status_cb = NULL; // ← 추가
ble_hs_cfg.sync_cb = on_sync;
```

### 방법 B: NimBLE store를 RAM으로 변경
```
# sdkconfig.defaults에 추가
CONFIG_BT_NIMBLE_STORE_CONFIG_PERSIST=n
```

### 방법 C: 광고 시작을 지연시키기
```c
static void on_sync(void)
{
    ble_hs_id_infer_auto(0, NULL);
    // 500ms 지연 후 광고 시작
    vTaskDelay(500 / portTICK_PERIOD_MS);
    start_advertising();
}
```

## 4. 핵심 설정

### sdkconfig.defaults
```

CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions.csv"
CONFIG_BT_ENABLED=y
CONFIG_BT_NIMBLE_ENABLED=y
CONFIG_BT_NIMBLE_MAX_CONNECTIONS=1
CONFIG_BT_NIMBLE_ROLE_CENTRAL=n
CONFIG_BT_NIMBLE_ROLE_OBSERVER=n
CONFIG_BT_NIMBLE_NVS_PERSIST=n
CONFIG_ESPTOOLPY_FLASHSIZE_4MB=y
CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y

### partitions.csv
```

ota_1,    app,  ota_1,   0x1A0000, 0x180000   (1.5MB)

## 6. BLE OTA 동작 시나리오 (크래시 해결 후)

```
1. ESP32 부팅 → BLE 광고 시작 ("ESP32-OTA")
2. 스마트폰에서 BLE 스캔 → "ESP32-OTA" 발견 → 연결
3. OTA_CONTROL에 START 명령 (총 크기 + SHA256)
4. OTA_DATA에 .bin을 chunk(500B)로 전송
5. OTA_CONTROL에 END 명령
6. ESP32: 검증 → boot 파티션 변경 → 재부팅
7. 새 펌웨어 실행 + BLE OTA 서비스 유지
```
