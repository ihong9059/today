# ESP32-C3 BLE OTA x Claude AI 바이브 코딩 플랫폼 — 개발계획서

> **프로젝트명**: Vibe Firmware (가칭)
> **목표**: 자연어 입력 → Claude 펌웨어 자동 생성 → BLE OTA 무선 플래싱
> **작성일**: 2026-04-11
> **상태**: Phase 0 진행 중

---

## 1. 프로젝트 개요

### 1-1. 한 줄 정의

> "스마트폰에 말하면, ESP32-C3가 동작한다."

사용자가 Android 앱에 자연어로 원하는 동작을 입력하면, 클라우드 서버의 Claude Code CLI가 ESP-IDF 기반 펌웨어를 자동 작성·빌드하고, 생성된 .bin 파일을 스마트폰이 BLE OTA로 ESP32-C3에 무선 플래싱하는 End-to-End 시스템.

### 1-2. 시스템 구성 (3-Tier)

```
┌─────────────────┐       ┌──────────────────┐       ┌─────────────────────┐
│   ESP32-C3      │◀─BLE─▶│  Android App     │◀─HTTPS─▶│  Cloud Server     │
│   (디바이스)    │       │  (Flutter/Kotlin) │        │  (FastAPI+Claude)  │
│                 │       │                   │        │                    │
│ - OTA Bootloader│       │ - 프롬프트 입력 UI│        │ - Claude Code CLI  │
│ - Dual Partition│       │ - BLE OTA Client  │        │ - ESP-IDF Toolchain│
│ - NimBLE OTA Svc│       │ - HTTPS Client    │        │ - FastAPI + Celery │
│ - Health Check  │       │ - 진행 상태 표시  │        │ - 빌드 캐시/서명   │
└─────────────────┘       └──────────────────┘        └─────────────────────┘
```

### 1-3. End-to-End 데이터 흐름

```
[1] 사용자: "LED를 0.5초마다 깜빡여줘"  (자연어 입력)
       │
       ▼
[2] Android App ──HTTPS POST /api/v1/generate──▶ [3] Cloud Server
                                                         │
                                                         │ claude -p "<시스템프롬프트 + 사용자요구>"
                                                         ▼
                                                  [4] Claude Code CLI
                                                         │ main.c, CMakeLists.txt 작성
                                                         │ idf.py build (실패 시 에러 피드백 → 재시도 x3)
                                                         ▼
                                                  [5] firmware.bin 생성 (SHA256 서명)
                                                         │
[6] Android App ◀──HTTPS 200 (.bin download)─────────────┘
       │
       │ BLE GATT Write (chunk 단위, MTU 517)
       ▼
[7] ESP32-C3: OTA partition 기록 → CRC 검증 → 재부팅 → 새 펌웨어 동작
```

## 4. Phase 1 — 클라우드 서버 환경 구축

> **목표**: Linux 서버에 ESP-IDF + Claude Code CLI를 설치하고, 수동으로 펌웨어 빌드가 되는 것을 확인
> **상태**: ⬜ 미착수
> **예상 기간**: 3~5일

### 4-1. 서버 사양

| 항목 | 권장 사양 | 비고 |
|------|-----------|------|
| 클라우드 | AWS EC2 또는 Digital Ocean Droplet | 기존 DO 서버 활용 가능 |
| OS | Ubuntu 22.04 LTS | ESP-IDF 공식 지원 |
| CPU | 4 vCPU 이상 | 빌드 병렬 처리 |
| RAM | 8GB 이상 | ESP-IDF 빌드 시 메모리 사용량 |
| Storage | 50GB SSD | ESP-IDF (~4GB) + 빌드 캐시 |

### 4-2. 설치 항목

| # | 소프트웨어 | 버전 | 용도 |
|---|-----------|------|------|
| 1 | ESP-IDF | v5.2+ (stable) | ESP32-C3 펌웨어 빌드 툴체인 |
| 2 | Python | 3.10+ | ESP-IDF 의존성 + 서버 앱 |
| 3 | Node.js | 20 LTS | Claude Code CLI 실행 환경 |
| 4 | Claude Code CLI | latest | `claude -p` 코드 생성 |
| 5 | ccache | latest | 빌드 캐시 (재빌드 5초 이하) |
| 6 | CMake + Ninja | latest | ESP-IDF 빌드 시스템 |

### 4-3. 설치 절차

```bash
# 1. ESP-IDF 설치
mkdir -p ~/esp && cd ~/esp
git clone -b v5.2.2 --recursive https://github.com/espressif/esp-idf.git
cd esp-idf && ./install.sh esp32c3
source export.sh

# 2. Claude Code CLI 설치
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt-get install -y nodejs
npm install -g @anthropic-ai/claude-code
claude auth login

# 3. ccache 설치
sudo apt install ccache
echo 'export IDF_CCACHE_ENABLE=1' >> ~/.bashrc

# 4. 검증
idf.py --version
claude --version
```

### 4-4. 검증 기준

| # | 테스트 | 성공 조건 |
|---|--------|----------|
| 1 | ESP-IDF hello_world 빌드 | `idf.py set-target esp32c3 && idf.py build` 성공 |
| 2 | Claude CLI 동작 | `claude -p "say hello"` 응답 수신 |
| 3 | Claude로 LED 코드 생성 | main.c 파일 생성 확인 |
| 4 | 생성된 코드 빌드 | .bin 파일 생성 확인 |
| 5 | ccache 재빌드 | 두 번째 빌드 5초 이하 |

### 4-5. 산출물

- 서버 환경 구축 완료 (SSH 접속 가능)

### 5-4. 시스템 프롬프트 (Claude에게 전달)

```
당신은 ESP-IDF v5.2 기반 ESP32-C3 펌웨어 작성자입니다.

규칙:
1. main/ 디렉터리에 main.c를 작성합니다.
2. 필요 시 main/CMakeLists.txt의 SRCS를 수정합니다.
3. app_main() 함수에서 시작합니다.
4. ESP-IDF v5.2 API만 사용합니다 (deprecated 함수 금지).
5. GPIO, LEDC, ADC, I2C, SPI, UART, BLE는 ESP-IDF 공식 예제 패턴을 따릅니다.
6. 설명 없이 코드만 작성합니다.
7. 기존 OTA 부트로더 코드는 수정하지 않습니다.
8. partitions.csv는 수정하지 않습니다.

현재 프로젝트 구조:
- main/main.c (수정 대상)
- main/CMakeLists.txt
- partitions.csv (듀얼 OTA, 수정 금지)
- sdkconfig.defaults
```

### 5-5. 자동 빌드 + Retry 로직

```
generate_firmware_code(prompt, workdir)
    │
    ▼
idf.py set-target esp32c3
idf.py build
    │
    ├─ 성공 → .bin 저장 → 완료
    │
    └─ 실패 → 에러 로그 추출 (마지막 2KB)
              │
              ▼
         claude -p "빌드 실패. 에러를 수정해주세요: {에러로그}"
              │
              ▼
         idf.py build (2차 시도)
              │
              ├─ 성공 → .bin 저장 → 완료
              └─ 실패 → 3차 시도 → 실패 시 "failed" 상태로 종료
```

### 5-6. 검증 기준

| # | 테스트 | 성공 조건 |
|---|--------|----------|
| 1 | curl로 /generate 호출 | 202 + job_id 반환 |
| 2 | /jobs/{id} polling | status 변화 확인 (queued→generating→building→completed) |
| 3 | /firmware/{id}.bin 다운로드 | .bin 파일 다운로드, SHA256 일치 |

| 6 | 동일 프롬프트 재요청 | 정상 처리 (캐싱은 Phase 5) |

## 6. Phase 3 — ESP32-C3 OTA 부트로더 + Android BLE OTA 앱

> **목표**: Android 앱에서 미리 준비된 .bin 파일을 BLE OTA로 ESP32-C3에 플래싱
> **상태**: ⬜ 미착수
> **예상 기간**: 7~10일

### 6-1. ESP32-C3 측 (OTA 부트로더 펌웨어)

#### 파티션 테이블 (`partitions.csv`)

```
# Name,    Type, SubType,  Offset,    Size
nvs,       data, nvs,      0x9000,    0x6000
otadata,   data, ota,      0xf000,    0x2000
phy_init,  data, phy,      0x11000,   0x1000
ota_0,     app,  ota_0,    0x20000,   0x180000    # 1.5MB
ota_1,     app,  ota_1,    0x1a0000,  0x180000    # 1.5MB
```

#### BLE OTA Service 구조

| 항목 | UUID | 속성 | 용도 |
|------|------|------|------|
| OTA Service | `0000FE00-...` | - | 커스텀 OTA 서비스 |
| OTA_CONTROL | `0000FE01-...` | Write | START/END/ABORT 명령 |
| OTA_DATA | `0000FE02-...` | Write Without Response | 펌웨어 chunk 데이터 |
| OTA_STATUS | `0000FE03-...` | Notify | 진행률, 에러, 완료 |

#### OTA 전송 프로토콜

```
[App]                              [ESP32-C3]
  │                                     │
  │─── OTA_CONTROL: START ──────────────▶│  (total_size + sha256)
  │                                     │
  │◀── OTA_STATUS: READY ──────────────│
  │                                     │
  │─── OTA_DATA: chunk[0] ────────────▶│  (MTU 크기, ~500 bytes)
  │─── OTA_DATA: chunk[1] ────────────▶│
  │─── OTA_DATA: chunk[2] ────────────▶│
  │    ...                              │
  │◀── OTA_STATUS: progress 25% ──────│  (100 chunk마다)
  │    ...                              │
  │─── OTA_DATA: chunk[N] ────────────▶│
  │                                     │
  │─── OTA_CONTROL: END ───────────────▶│
  │                                     │
  │◀── OTA_STATUS: VERIFYING ──────────│
  │◀── OTA_STATUS: SUCCESS ────────────│  (SHA256 검증 통과)
  │                                     │
  │                              [자동 재부팅]
  │                              [5초 health check]
  │                              [esp_ota_mark_app_valid]
```

#### BLE OTA 전송 핵심 로직 (Dart 의사코드)

```dart
Future<void> bleOtaUpload(List<int> firmware, BluetoothCharacteristic otaData,
    BluetoothCharacteristic otaControl, BluetoothCharacteristic otaStatus) async {

  // 1. START 명령 전송
  await otaControl.write(
    buildStartCommand(firmware.length, sha256(firmware))
  );

  // 2. READY 대기
  await otaStatus.value.firstWhere((v) => v == OTA_READY);

  // 3. chunk 단위 전송
  final chunkSize = min(mtu - 3, 500);
  for (var i = 0; i < firmware.length; i += chunkSize) {
    final chunk = firmware.sublist(i, min(i + chunkSize, firmware.length));
    await otaData.write(chunk, withoutResponse: true);
    onProgress(i / firmware.length);
  }

  // 4. END 명령
  await otaControl.write(buildEndCommand());

  // 5. 결과 대기
  final result = await otaStatus.value.firstWhere(
    (v) => v == OTA_SUCCESS || v == OTA_FAIL
  );
}
```

Future<void> vibeCoding(String prompt) async {
  updateStatus("프롬프트 전송 중...");

  // 1. 서버에 펌웨어 생성 요청
  final jobId = await api.requestGenerate(prompt);

  // 2. 상태 polling (2초 간격)
  updateStatus("AI 코드 생성 중...");
  JobStatus status;
  do {
    await Future.delayed(Duration(seconds: 2));
    status = await api.getJobStatus(jobId);
    updateStatus(status.displayText);
  } while (status.isInProgress);

  if (status.isFailed) throw BuildFailedException(status.buildLog);

  // 3. .bin 다운로드
  updateStatus("펌웨어 다운로드 중...");
  final firmware = await api.downloadFirmware(status.firmwareUrl);

  // 4. SHA256 검증
  if (sha256(firmware) != status.sha256) throw IntegrityException();

  // 5. BLE OTA 전송
  updateStatus("BLE OTA 전송 중...");
  await bleOtaUpload(firmware);

  updateStatus("완료! 디바이스 재시작 중...");
}
