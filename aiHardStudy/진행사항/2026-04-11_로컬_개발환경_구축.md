# 로컬 개발환경 구축 — 클라우드 서버 대용

> **날짜**: 2026-04-11
> **목적**: 이 PC를 클라우드 서버 대용으로 사용하여 바이브 코딩 파이프라인을 로컬에서 검증
> **상태**: 🔧 진행 중

---

## 1. 개념

클라우드 서버에 구축할 환경을 먼저 로컬 PC에 동일하게 구성합니다.
로컬에서 전체 파이프라인이 동작하면, 이후 클라우드로 이전합니다.

```
[클라우드 구조]                      [로컬 대용 구조]
┌──────────────────┐                ┌──────────────────┐
│ Cloud Server     │                │ 이 PC (Windows)  │
│ - FastAPI        │      ══▶      │ - FastAPI         │
│ - Claude CLI     │                │ - Claude CLI      │
│ - ESP-IDF        │                │ - ESP-IDF         │
│ - 빌드 + .bin    │                │ - 빌드 + .bin     │
└────────┬─────────┘                └────────┬─────────┘
         │ HTTPS                             │ USB Serial
         ▼                                   ▼
  스마트폰 앱 (BLE OTA)              직접 플래싱 (esptool)
```

로컬에서는 BLE OTA 대신 **USB 시리얼로 직접 플래싱**하여 검증합니다.

### 2-3. 해결한 이슈

| # | 이슈 | 원인 | 해결 |
|---|------|------|------|
| 1 | idf.py 실행 불가 | 시스템 Python이 3.11→3.13으로 변경되어 가상환경 불일치 | `install.bat` 재실행 → Python 3.13용 가상환경 신규 생성 |
| 2 | MSYS/Mingw 비지원 | ESP-IDF v5.5+에서 Git Bash(MSYS) 지원 중단 | CMD 또는 PowerShell에서 실행, `set MSYSTEM=` 으로 우회 |
| 3 | idf_cmd_init.bat가 구 venv 사용 | idf-env config가 구 3.11 환경을 가리킴 | `IDF_PYTHON_ENV_PATH` 환경변수로 3.13 venv 명시 지정 |

### 2-4. ESP-IDF 실행 명령어 (확정)

```batch
:: CMD에서 ESP-IDF 환경 초기화 (매 세션마다)
set MSYSTEM=
set IDF_PATH=C:\Espressif\frameworks\esp-idf-v5.5.1
set IDF_PYTHON_ENV_PATH=C:\Espressif\python_env\idf5.5_py3.13_env
C:\Espressif\idf_cmd_init.bat

:: 이후 idf.py 사용 가능
idf.py --version    → ESP-IDF v5.5.1
```

## 5. 클라우드 전환 시 변경 사항 (향후)

| 항목 | 로컬 (현재) | 클라우드 (향후) |
|------|------------|----------------|
| OS | Windows 11 | Ubuntu 22.04 |
| ESP-IDF 경로 | `C:\Espressif\...` | `/opt/esp-idf/...` |
| 배포 방식 | USB Serial (esptool) | .bin 다운로드 URL → BLE OTA |
| idf.py 실행 | CMD batch | bash 직접 |
| 빌드 캐시 | ccache 로컬 | ccache 서버 |
| Claude CLI | 로컬 설치 | 서버 설치 |

로컬에서 검증된 코드/구조를 그대로 클라우드로 이전하면 됩니다.
`board.h`, `board_profile.json`, 시스템 프롬프트는 동일하게 사용됩니다.
