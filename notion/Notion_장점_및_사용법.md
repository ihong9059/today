## 1. Notion이란?

Notion은 **Notion Labs**에서 개발한 올인원 생산성 도구로, 노트 작성, 프로젝트 관리, 데이터베이스, 위키, 문서 협업을 하나의 플랫폼에서 처리할 수 있는 워크스페이스 앱이다.

### 핵심 특징 요약

| 항목 | 설명 |
|------|------|
| **개발사** | Notion Labs, Inc. (2016년 설립, 샌프란시스코) |
| **플랫폼** | 웹, Windows, macOS, iOS, Android |
| **핵심 철학** | "All-in-one workspace" — 여러 도구를 하나로 통합 |
| **주요 사용자** | 개인, 스타트업, 중소기업, 대기업 팀 |
| **경쟁 제품** | Confluence, Coda, Google Docs, Trello, Airtable |

Notion은 단순한 메모 앱이 아니라 **레고 블록처럼 자유롭게 조합할 수 있는 모듈형 구조**를 가지고 있어, 사용자가 원하는 형태의 워크스페이스를 직접 설계할 수 있다.

## 2. Notion의 주요 장점

### 2.1 올인원 워크스페이스

기존에 여러 도구를 따로 사용하던 작업을 Notion 하나로 대체할 수 있다.

| 기존 도구 | Notion 대체 기능 |
|-----------|-----------------|
| Google Docs | 문서 작성 및 공동 편집 |
| Trello / Jira | 칸반 보드, 프로젝트 관리 |
| Airtable | 데이터베이스, 스프레드시트 |
| Confluence | 팀 위키, 지식 베이스 |
| Evernote | 개인 노트, 웹 클리퍼 |
| Google Calendar | 캘린더 뷰 (데이터베이스 기반) |

### 2.2 유연한 블록 시스템

Notion의 모든 콘텐츠는 **블록(Block)** 단위로 구성된다.

- 텍스트, 제목, 목록, 토글, 인용, 구분선 등 **기본 블록**
- 이미지, 동영상, 파일, 북마크 등 **미디어 블록**
- 코드, 수식(KaTeX), 테이블 등 **고급 블록**
- 데이터베이스, 링크드 뷰, 임베드 등 **인라인 블록**

블록은 **드래그 앤 드롭**으로 자유롭게 이동, 복제, 변환이 가능하며, 다단 레이아웃(칼럼)도 지원한다.

### 2.3 강력한 데이터베이스

Notion 데이터베이스는 단순한 표가 아니라 **다양한 뷰로 전환 가능한 구조화된 데이터 관리 시스템**이다.

- 하나의 데이터베이스를 테이블, 보드, 캘린더, 갤러리, 타임라인, 리스트 등 여러 뷰로 표시
- 필터, 정렬, 그룹화 기능
- 관계형 데이터베이스 (Relation) 및 롤업 (Rollup) 지원
- 수식 (Formula) 속성으로 계산 자동화

### 2.4 풍부한 템플릿 생태계

- Notion 공식 템플릿 갤러리에서 수백 가지 무료 템플릿 제공
- 커뮤니티에서 제작한 유/무료 템플릿 활용 가능
- 자체 템플릿을 만들어 팀 내에서 재사용 가능
- 데이터베이스 내 **템플릿 버튼**으로 반복 입력 자동화

### 2.5 실시간 협업

- **실시간 공동 편집**: 여러 사람이 동시에 같은 페이지 편집
- **댓글 및 멘션**: `@사용자명`으로 특정 멤버에게 알림
- **권한 관리**: 페이지별, 워크스페이스별 세밀한 접근 권한 설정
- **게스트 초대**: 외부 협력자를 특정 페이지에만 초대 가능
- **페이지 히스토리**: 변경 내역 추적 및 이전 버전 복원

### 2.6 Notion AI

Notion에 내장된 AI 기능으로 생산성을 높일 수 있다.

- **텍스트 생성**: 초안 작성, 브레인스토밍, 요약
- **편집 지원**: 문법 교정, 톤 변경, 번역
- **Q&A**: 워크스페이스 내 정보를 검색하여 질문에 답변
- **자동 채우기**: 데이터베이스 속성을 AI가 자동으로 채워줌
- **작성 도우미**: 블록 내에서 `/ai`로 즉시 호출

### 2.7 기타 장점

- **오프라인 지원**: 모바일/데스크톱 앱에서 오프라인 접근 가능
- **웹 클리퍼**: 브라우저 확장으로 웹 페이지를 Notion에 저장
- **임베드**: 400개 이상의 외부 서비스 임베드 (Figma, Google Maps, GitHub 등)
- **다국어 지원**: 한국어 UI 지원
- **마크다운 호환**: 마크다운 문법으로 빠르게 작성 가능
- **내보내기/가져오기**: PDF, HTML, Markdown, CSV 등 다양한 포맷 지원

## 3. 핵심 기능 설명

### 3.1 페이지 (Page)

Notion의 기본 단위. 모든 것은 페이지 안에 존재한다.

- 페이지 안에 **하위 페이지**를 무한히 중첩 가능
- 각 페이지에 **아이콘**과 **커버 이미지** 설정 가능
- 페이지 자체가 데이터베이스의 한 행(row)이 될 수 있음
- 공유 시 **웹 퍼블리시** 기능으로 공개 웹페이지로 전환 가능

### 3.2 블록 (Block) 종류

#### 기본 블록

| 블록 | 명령어 | 설명 |
|------|--------|------|
| 텍스트 | 그냥 입력 | 일반 텍스트 단락 |
| 제목 1 | `/h1` 또는 `#` + 스페이스 | 대제목 |
| 제목 2 | `/h2` 또는 `##` + 스페이스 | 중제목 |
| 제목 3 | `/h3` 또는 `###` + 스페이스 | 소제목 |
| 글머리 기호 | `/bullet` 또는 `-` + 스페이스 | 비순서 목록 |
| 번호 목록 | `/numbered` 또는 `1.` + 스페이스 | 순서 목록 |
| 할 일 목록 | `/todo` 또는 `[]` + 스페이스 | 체크박스 목록 |
| 토글 | `/toggle` 또는 `>` + 스페이스 | 접기/펼치기 |
| 인용 | `/quote` 또는 `"` + 스페이스 | 인용 블록 |
| 구분선 | `/divider` 또는 `---` | 수평 구분선 |
| 콜아웃 | `/callout` | 강조 박스 |

#### 고급 블록

| 블록 | 명령어 | 설명 |
|------|--------|------|
| 코드 | `/code` | 구문 강조 코드 블록 |
| 수식 | `/equation` | KaTeX 수학 수식 |
| 테이블 | `/table` | 간단한 표 (데이터베이스 아님) |
| 목차 | `/toc` | 페이지 내 제목 기반 자동 목차 |
| 브레드크럼 | `/breadcrumb` | 페이지 경로 표시 |
| 동기화 블록 | `/synced` | 여러 페이지에서 동일 내용 동기화 |

### 3.3 데이터베이스 종류

Notion에서 데이터베이스를 생성하는 방법은 크게 두 가지이다.

| 유형 | 설명 |
|------|------|
| **전체 페이지 데이터베이스** | 독립된 페이지로 존재하는 데이터베이스 |
| **인라인 데이터베이스** | 페이지 본문 안에 삽입된 데이터베이스 |
| **링크드 뷰 (Linked View)** | 기존 데이터베이스를 다른 페이지에서 필터링하여 보여주는 뷰 |

### 3.4 데이터베이스 뷰 타입

하나의 데이터베이스에 여러 뷰를 추가하여 같은 데이터를 다른 형태로 볼 수 있다.

| 뷰 | 용도 | 적합한 상황 |
|----|------|-------------|
| **테이블 (Table)** | 스프레드시트 형태 | 데이터 일괄 확인/편집 |
| **보드 (Board)** | 칸반 보드 | 상태별 작업 관리 (To-do, In Progress, Done) |
| **캘린더 (Calendar)** | 달력 표시 | 일정, 마감일 관리 |
| **갤러리 (Gallery)** | 카드형 그리드 | 이미지 중심 콘텐츠 (포트폴리오, 레시피) |
| **타임라인 (Timeline)** | 간트 차트 | 프로젝트 일정, 기간 관리 |
| **리스트 (List)** | 심플 목록 | 간결한 항목 나열 |
| **차트 (Chart)** | 시각화 | 데이터 분석, 요약 |

### 3.5 데이터베이스 속성 (Property)

데이터베이스의 각 열(Column)에 다양한 속성 유형을 지정할 수 있다.

| 속성 유형 | 설명 | 예시 |
|-----------|------|------|
| **텍스트 (Text)** | 자유 텍스트 입력 | 메모, 설명 |
| **숫자 (Number)** | 숫자 값 | 금액, 수량 |
| **선택 (Select)** | 단일 선택 태그 | 상태, 카테고리 |
| **다중 선택 (Multi-select)** | 복수 선택 태그 | 라벨, 기술 스택 |
| **날짜 (Date)** | 날짜/기간 | 마감일, 기간 |
| **사람 (Person)** | 워크스페이스 멤버 | 담당자, 작성자 |
| **파일 (Files & Media)** | 첨부 파일 | 문서, 이미지 |
| **체크박스 (Checkbox)** | 참/거짓 | 완료 여부 |
| **URL** | 웹 주소 | 참고 링크 |
| **이메일 (Email)** | 이메일 주소 | 연락처 |
| **전화번호 (Phone)** | 전화번호 | 연락처 |
| **수식 (Formula)** | 계산 결과 | 자동 합계, 조건부 표시 |
| **관계 (Relation)** | 다른 DB 연결 | 프로젝트 ↔ 작업 연결 |
| **롤업 (Rollup)** | 관계 DB 집계 | 하위 작업 완료율 |
| **생성 시간 (Created time)** | 자동 기록 | 생성일 |
| **최종 수정 시간 (Last edited time)** | 자동 기록 | 수정일 |
| **생성자 (Created by)** | 자동 기록 | 생성한 사람 |
| **최종 수정자 (Last edited by)** | 자동 기록 | 수정한 사람 |

### 3.6 관계형 데이터베이스 (Relation)

서로 다른 데이터베이스를 연결하여 데이터 간 관계를 표현한다.

**예시: 프로젝트 관리**

```
[프로젝트 DB]          [작업 DB]           [담당자 DB]
 프로젝트A  ──1:N──  작업1, 작업2, 작업3  ──N:1──  김개발
 프로젝트B  ──1:N──  작업4, 작업5         ──N:1──  이기획
```

**설정 방법:**

1. 작업 DB에 "관계(Relation)" 속성 추가
2. 연결할 대상 DB (프로젝트 DB) 선택
3. 양방향 관계 설정 시 프로젝트 DB에도 자동으로 역방향 속성 생성

### 3.7 수식 (Formula)

데이터베이스 속성 값을 기반으로 계산하거나 조건부 결과를 반환한다.

**자주 쓰는 수식 예시:**

```
// D-Day 계산 (마감일까지 남은 일수)
dateBetween(prop("마감일"), now(), "days")

// 상태에 따른 이모지 표시
if(prop("상태") == "완료", "완료", if(prop("상태") == "진행중", "진행중", "대기"))

// 진행률 계산 (롤업 값 활용)
round(prop("완료 작업 수") / prop("전체 작업 수") * 100)

// 텍스트 결합
prop("성") + " " + prop("이름")

// 빈 값 처리
if(empty(prop("메모")), "메모 없음", prop("메모"))
```

### 3.8 롤업 (Rollup)

Relation으로 연결된 데이터베이스의 속성 값을 집계한다.

| 집계 함수 | 설명 | 예시 |
|-----------|------|------|
| Count all | 전체 개수 | 프로젝트의 총 작업 수 |
| Count values | 값이 있는 항목 수 | 담당자가 배정된 작업 수 |
| Sum | 합계 | 예산 총합 |
| Average | 평균 | 평균 소요 시간 |
| Min / Max | 최소/최대 | 가장 빠른 마감일 |
| Percent checked | 체크 비율 | 작업 완료율 |
| Show original | 원본 값 나열 | 연결된 모든 태그 표시 |

## 4. 활용 사례

### 4.1 프로젝트 관리

**구성 예시:**

```
프로젝트 홈 (페이지)
├── 프로젝트 개요 (텍스트 + 콜아웃)
├── 작업 보드 (데이터베이스 - 보드 뷰)
│   ├── Backlog
│   ├── To Do
│   ├── In Progress
│   └── Done
├── 타임라인 (같은 DB - 타임라인 뷰)
├── 회의록 (데이터베이스)
└── 참고 자료 (페이지)
```

**핵심 속성:** 담당자, 우선순위(Select), 마감일, 상태, 프로젝트(Relation)

### 4.2 문서 관리 / 팀 위키

**구성 예시:**

```
팀 위키 (페이지)
├── 온보딩 가이드
│   ├── 신규 입사자 체크리스트
│   ├── 도구 설정 가이드
│   └── 팀 소개
├── 기술 문서
│   ├── API 문서
│   ├── 아키텍처 설명
│   └── 코딩 컨벤션
├── 정책/규정
│   ├── 휴가 정책
│   └── 보안 가이드
└── FAQ
```

- 동기화 블록으로 공통 내용을 여러 페이지에서 일관성 있게 유지
- 목차 블록으로 긴 문서 내비게이션 지원

### 4.3 개인 생산성

| 용도 | 구현 방법 |
|------|-----------|
| **할 일 관리** | 체크박스 DB + 보드 뷰 (오늘/이번 주/나중에) |
| **독서 기록** | 갤러리 뷰 DB (책 표지, 평점, 메모, 상태) |
| **학습 노트** | 토글 + 콜아웃으로 구조화된 노트 |
| **일기/저널** | 날짜 속성 DB + 캘린더 뷰 + 템플릿 버튼 |
| **재무 관리** | 숫자 속성 + 수식으로 수입/지출 계산 |
| **목표 관리** | OKR 구조 (목표 DB ↔ 핵심 결과 DB, Relation 연결) |

### 4.4 CRM (고객 관계 관리)

```
CRM 워크스페이스
├── 고객사 DB
│   ├── 회사명, 업종, 규모, 담당자
│   └── → 거래 DB (Relation)
├── 거래(Deal) DB
│   ├── 거래명, 금액, 단계(파이프라인), 예상 마감일
│   └── → 고객사 DB (Relation)
├── 연락 기록 DB
│   ├── 날짜, 유형(전화/이메일/미팅), 내용
│   └── → 고객사 DB (Relation)
└── 대시보드 (링크드 뷰로 주요 지표 모아보기)
```

### 4.5 습관 트래커

**데이터베이스 구성:**

| 속성 | 유형 | 설명 |
|------|------|------|
| 날짜 | Date | 매일 기록 |
| 운동 | Checkbox | 운동 여부 |
| 독서 | Checkbox | 독서 여부 |
| 물 8잔 | Checkbox | 수분 섭취 |
| 수면 시간 | Number | 수면 시간 (h) |
| 기분 | Select | 좋음/보통/나쁨 |
| 달성률 | Formula | 체크된 항목 / 전체 항목 비율 계산 |

템플릿 버튼을 설정하면 매일 한 번 클릭으로 오늘 날짜가 채워진 새 항목이 생성된다.

## 5. 시작하기

### 5.1 계정 생성

1. [notion.so](https://www.notion.so) 접속
2. 이메일, Google 계정, 또는 Apple 계정으로 가입
3. 용도 선택 (개인용 / 팀용)
4. 워크스페이스 이름 설정

### 5.2 워크스페이스 기본 설정

**추천 초기 설정:**

1. **사이드바 정리**: "시작하기" 페이지 삭제 후 나만의 구조 설계
2. **아이콘/커버 설정**: 주요 페이지에 시각적 구분용 아이콘 추가
3. **즐겨찾기**: 자주 쓰는 페이지를 사이드바 상단에 고정
4. **멤버 초대**: 설정 > 멤버에서 팀원 초대 (팀 플랜)
5. **연동 설정**: 설정 > 연결에서 Slack, Google Drive 등 연동

### 5.3 첫 페이지 만들기

```
1. 사이드바에서 "+" 클릭 또는 Ctrl+N
2. 페이지 제목 입력
3. 본문에 "/" 입력하여 블록 메뉴 호출
4. 원하는 블록 선택하여 내용 작성
5. 하위 페이지 추가: 본문에서 /page 입력
```

### 5.4 첫 데이터베이스 만들기

```
1. 본문에서 "/database" 또는 "/table" 입력
2. "테이블 뷰 - 전체 페이지" 또는 "테이블 뷰 - 인라인" 선택
3. 열(속성) 이름과 유형 설정
4. 데이터 입력
5. "+ 뷰 추가"로 보드, 캘린더 등 추가 뷰 생성
6. 필터/정렬 설정으로 원하는 조건의 데이터만 표시
```

### 6.4 생산성 팁

1. **슬래시 명령어 활용**: `/`을 입력하면 모든 블록 유형에 빠르게 접근할 수 있다. 한글로도 검색 가능 (예: `/표`, `/코드`).

2. **@멘션 적극 활용**: `@오늘`, `@내일`, `@사용자명`, `@페이지명`으로 빠른 링크 생성.

3. **템플릿 버튼 만들기**: 데이터베이스에서 자주 반복하는 형식이 있으면 템플릿으로 등록해 한 번에 생성.

4. **동기화 블록 (Synced Block)**: 여러 페이지에서 동일한 내용을 보여줘야 할 때, 원본을 수정하면 모든 곳에 반영.

5. **링크드 뷰 활용**: 하나의 DB를 여러 페이지에서 다른 필터/뷰로 보여줄 수 있어 대시보드 구성에 유용.

6. **웹 클리퍼 설치**: 브라우저 확장 프로그램으로 웹 페이지를 Notion에 바로 저장.

7. **페이지 잠금**: 실수로 편집하면 안 되는 중요 문서는 우측 상단 `...` > "페이지 잠금"으로 보호.

8. **데이터베이스 보기 잠금**: 팀원이 뷰 설정(필터, 정렬)을 변경하지 못하도록 뷰 잠금 설정.

## 8. Notion API 소개

### 8.1 개요

Notion API를 사용하면 외부 서비스나 스크립트에서 Notion 데이터를 읽고 쓸 수 있다.

- **공식 문서**: [developers.notion.com](https://developers.notion.com)
- **인증 방식**: OAuth 2.0 또는 Internal Integration Token
- **형식**: REST API (JSON)
- **Rate Limit**: 평균 3 요청/초

### 8.2 시작하기

**1단계: 통합(Integration) 생성**

1. [notion.so/my-integrations](https://www.notion.so/my-integrations) 접속
2. "새 통합 만들기" 클릭
3. 이름 설정, 관련 워크스페이스 선택
4. 권한 설정 (읽기/쓰기/삽입)
5. 시크릿 토큰 복사 (`secret_...`)

**2단계: 페이지/DB에 연결 허용**

해당 페이지나 데이터베이스에서:
1. 우측 상단 `...` 클릭
2. "연결 추가" > 만든 통합 선택
3. 접근 허용 확인

**3단계: API 호출**

### 8.3 주요 엔드포인트

| 엔드포인트 | 메서드 | 설명 |
|-----------|--------|------|
| `/v1/pages` | POST | 새 페이지 생성 |
| `/v1/pages/{id}` | GET | 페이지 정보 조회 |
| `/v1/pages/{id}` | PATCH | 페이지 속성 수정 |
| `/v1/databases/{id}/query` | POST | 데이터베이스 쿼리 (필터/정렬) |
| `/v1/databases/{id}` | GET | 데이터베이스 스키마 조회 |
| `/v1/blocks/{id}/children` | GET | 블록의 하위 블록 조회 |
| `/v1/blocks/{id}/children` | PATCH | 하위 블록 추가 |
| `/v1/search` | POST | 워크스페이스 검색 |
| `/v1/users` | GET | 워크스페이스 사용자 목록 |

### 8.4 코드 예시 (Python)

```python
import requests

NOTION_TOKEN = "secret_YOUR_TOKEN_HERE"
DATABASE_ID = "YOUR_DATABASE_ID"

headers = {
    "Authorization": f"Bearer {NOTION_TOKEN}",
    "Content-Type": "application/json",
    "Notion-Version": "2022-06-28"
}

# 데이터베이스 쿼리 (필터: 상태가 "진행중"인 항목)
query_payload = {
    "filter": {
        "property": "상태",
        "select": {
            "equals": "진행중"
        }
    },
    "sorts": [
        {
            "property": "마감일",
            "direction": "ascending"
        }
    ]
}

response = requests.post(
    f"https://api.notion.com/v1/databases/{DATABASE_ID}/query",
    headers=headers,
    json=query_payload
)

results = response.json()["results"]
for item in results:
    title = item["properties"]["이름"]["title"][0]["plain_text"]
    print(f"- {title}")
```

```python
# 새 페이지(항목) 생성
new_page = {
    "parent": {"database_id": DATABASE_ID},
    "properties": {
        "이름": {
            "title": [{"text": {"content": "새로운 작업"}}]
        },
        "상태": {
            "select": {"name": "대기"}
        },
        "담당자": {
            "people": [{"id": "USER_ID_HERE"}]
        },
        "마감일": {
            "date": {"start": "2026-04-15"}
        }
    }
}

response = requests.post(
    "https://api.notion.com/v1/pages",
    headers=headers,
    json=new_page
)

print(f"생성 완료: {response.json()['url']}")
```

### 8.5 JavaScript (Node.js) 예시

```javascript
const { Client } = require("@notionhq/client");

const notion = new Client({ auth: "secret_YOUR_TOKEN_HERE" });

// 데이터베이스 쿼리
async function queryDatabase() {
  const response = await notion.databases.query({
    database_id: "YOUR_DATABASE_ID",
    filter: {
      property: "상태",
      select: { equals: "진행중" },
    },
  });

  response.results.forEach((page) => {
    const title = page.properties["이름"].title[0]?.plain_text;
    console.log(`- ${title}`);
  });
}

queryDatabase();
```

### 8.6 활용 아이디어

- **자동 일일 보고서 생성**: 매일 특정 시간에 당일 작업 현황을 자동 집계하여 Notion 페이지에 기록
- **폼 → Notion DB 연동**: 외부 폼(Google Forms, Typeform)의 응답을 Notion DB에 자동 저장
- **GitHub 연동**: 커밋/PR 정보를 Notion 프로젝트 DB에 자동 반영
- **Slack 연동**: 특정 채널의 메시지를 Notion에 아카이빙
- **대시보드 자동화**: 주기적으로 데이터를 집계하여 Notion 대시보드 업데이트
