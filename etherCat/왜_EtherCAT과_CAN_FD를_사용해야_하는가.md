## 1. 서론: 산업용 통신의 핵심 요구사항

### 1.1 일반 IT 네트워크 vs 산업용 네트워크

```
┌─────────────────────────────────────────────────────────────────────┐
│              일반 IT 네트워크 vs 산업용 네트워크                      │
├───────────────────────────────┬─────────────────────────────────────┤
│      일반 이더넷 (IT)         │        산업용 네트워크 (OT)          │
├───────────────────────────────┼─────────────────────────────────────┤
│                               │                                     │
│  "빠르면 좋다"                │  "정확한 시간에 도착해야 한다"        │
│                               │                                     │
│  평균 속도가 중요             │  최악의 경우(Worst Case)가 중요      │
│                               │                                     │
│  지연 허용 (수백 ms OK)       │  지연 불허 (수십 μs 필수)            │
│                               │                                     │
│  데이터 손실 시 재전송        │  데이터 손실 = 사고 가능             │
│                               │                                     │
│  Best Effort 전송             │  Deterministic (결정적) 전송         │
│                               │                                     │
└───────────────────────────────┴─────────────────────────────────────┘
```

### 1.2 실시간(Real-Time)의 의미

```
                    응답 시간 요구사항

      │ 웹 브라우징       │ 100ms - 1s     │ Soft Real-Time
      │ 영상 스트리밍     │ 10ms - 100ms   │ Soft Real-Time
      │ VoIP 통화        │ 1ms - 10ms     │ Soft Real-Time
   ───┼──────────────────┼────────────────┼─────────────────
      │ PLC 제어         │ 1ms - 10ms     │ Hard Real-Time
      │ 모션 컨트롤      │ 100μs - 1ms    │ Hard Real-Time
      │ 서보 동기화      │ 10μs - 100μs   │ Hard Real-Time
      │
      ▼
   더 엄격한 요구사항

   * Hard Real-Time: 데드라인 미준수 = 시스템 실패
   * Soft Real-Time: 데드라인 미준수 = 성능 저하
```

## 2. EtherCAT을 사용해야 하는 이유

### 2.1 표준 이더넷으로는 불가능한 이유

#### 2.1.1 표준 이더넷의 근본적 한계

```
┌─────────────────────────────────────────────────────────────────────┐
│                 표준 이더넷의 문제점                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  문제 1: 비결정적(Non-Deterministic) 지연                            │
│  ─────────────────────────────────────────                          │
│                                                                     │
│  ┌─────┐    ┌──────────┐    ┌─────┐                                │
│  │ PC  │───▶│  스위치  │───▶│ PLC │                                │
│  └─────┘    └──────────┘    └─────┘                                │
│                  │                                                  │
│                  ▼                                                  │
│         ┌──────────────┐                                           │
│         │ 다른 트래픽  │  ← 예측 불가능한 지연 발생!                 │
│         └──────────────┘                                           │
│                                                                     │
│  • 스위치 내부 버퍼링으로 인한 지연: 수십 μs ~ 수 ms                 │
│  • 다른 트래픽과의 충돌: 예측 불가능                                 │
│  • CSMA/CD 재전송: 최악의 경우 무한 지연                             │
│                                                                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  문제 2: 각 노드마다 개별 통신 필요                                   │
│  ─────────────────────────────────────                              │
│                                                                     │
│  100개 노드 × 왕복 통신 = 200번의 개별 전송                          │
│                                                                     │
│  Master ──▶ Slave 1 ──▶ Master                                     │
│  Master ──▶ Slave 2 ──▶ Master                                     │
│  Master ──▶ Slave 3 ──▶ Master                                     │
│      ...                                                            │
│  Master ──▶ Slave 100 ──▶ Master                                   │
│                                                                     │
│  → 노드 수에 비례하여 사이클 타임 증가                               │
│                                                                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  문제 3: TCP/IP 스택 오버헤드                                        │
│  ─────────────────────────────────                                  │
│                                                                     │
│  ┌───────────┐                                                      │
│  │Application│  ← 사용자 데이터 처리                                │
│  ├───────────┤                                                      │
│  │    TCP    │  ← 연결 관리, 재전송 (수 ms 지연 가능)               │
│  ├───────────┤                                                      │
│  │    IP     │  ← 라우팅, 단편화                                    │
│  ├───────────┤                                                      │
│  │  Ethernet │  ← 프레임 처리                                       │
│  └───────────┘                                                      │
│                                                                     │
│  각 계층에서 처리 시간 발생 → 총 지연 예측 불가                       │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 2.1.2 실제 지연 시간 비교

| 항목 | 표준 이더넷 (TCP/IP) | EtherCAT |
|------|---------------------|----------|
| **최소 지연** | 100 μs ~ 1 ms | < 10 μs |
| **최대 지연** | 10 ms ~ 무한 | 100 μs (보장) |
| **지터 (Jitter)** | 수 ms | < 1 μs |
| **100개 노드 사이클** | 10 ms 이상 | 100 μs 이하 |

```
지연 시간 비교 (100개 노드)

표준 이더넷 (TCP/IP)
├────────────────────────────────────────────────────────────────┤
0                                                            10+ ms

EtherCAT
├──┤
0  100 μs

                         100배 이상 차이!
```

### 2.2 다른 산업용 이더넷 대신 EtherCAT을 선택하는 이유

#### 2.2.1 산업용 이더넷 프로토콜 비교

```
┌─────────────────────────────────────────────────────────────────────┐
│                 산업용 이더넷 프로토콜 비교                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  프로토콜        사이클타임    토폴로지      라이선스    복잡성       │
│  ─────────────────────────────────────────────────────────────────  │
│  EtherCAT       < 100 μs     자유로움      무료        낮음        │
│  PROFINET IRT   < 1 ms       제한적        유료        높음        │
│  EtherNet/IP    1-10 ms      스타 위주     무료        중간        │
│  POWERLINK      < 400 μs     라인/트리     무료        중간        │
│  SERCOS III     < 1 ms       링 필수       유료        높음        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 2.2.2 EtherCAT의 결정적 우위

**1) "On-the-fly" 처리 방식**

```
┌─────────────────────────────────────────────────────────────────────┐
│                    EtherCAT On-the-fly 처리                         │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  다른 프로토콜 (Store-and-Forward):                                  │
│                                                                     │
│  Master → Slave1 → Master → Slave2 → Master → Slave3 → Master      │
│           ├───┤            ├───┤            ├───┤                  │
│           저장              저장              저장                   │
│           처리              처리              처리                   │
│           전송              전송              전송                   │
│                                                                     │
│  → 각 노드에서 전체 프레임을 받고, 처리하고, 다시 전송               │
│  → 노드 수에 비례하여 지연 증가                                      │
│                                                                     │
│  ─────────────────────────────────────────────────────────────────  │
│                                                                     │
│  EtherCAT (On-the-fly):                                             │
│                                                                     │
│         ┌────────────────────────────────────────────┐              │
│         │              하나의 프레임                  │              │
│  Master ▶ Slave1 ▶ Slave2 ▶ Slave3 ▶ ... ▶ SlaveN ▶ Master        │
│         └────────────────────────────────────────────┘              │
│              │        │        │              │                     │
│            읽기/    읽기/    읽기/          읽기/                    │
│            쓰기     쓰기     쓰기           쓰기                     │
│           (~1μs)   (~1μs)   (~1μs)        (~1μs)                   │
│                                                                     │
│  → 프레임이 통과하는 동안 각 노드가 필요한 데이터만 처리             │
│  → 노드 수와 관계없이 거의 일정한 사이클 타임                        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

**2) 노드 수에 따른 사이클 타임**

```
사이클 타임 (μs)
     │
10000├─────────────────────────────────────────── PROFINET IRT
     │                                      ╱
 5000├─────────────────────────────────────╱
     │                               ╱
 1000├────────────────────────────── EtherNet/IP
     │                        ╱
  500├─────────────────────────────────── POWERLINK
     │              ╱
  100├──────────────────────────────────────────── EtherCAT
     │    ╱                                       (거의 일정)
    0└───────┬────────┬────────┬────────┬────────▶
           10       50       100      200     노드 수
```

**3) 대역폭 효율성**

| 프로토콜 | 100개 I/O 포인트 | 대역폭 효율 |
|----------|-----------------|-------------|
| **EtherCAT** | 1개 프레임 | 90%+ |
| **PROFINET** | 100개+ 프레임 | 50-60% |
| **EtherNet/IP** | 100개+ 프레임 | 40-50% |

### 2.3 EtherCAT이 필수인 응용 분야

#### 2.3.1 다축 모션 컨트롤

```
┌─────────────────────────────────────────────────────────────────────┐
│                    다축 모션 컨트롤 예시                             │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  6축 로봇 팔 제어:                                                   │
│                                                                     │
│       ┌───┐                                                         │
│       │J1 │ ← 축 1 (베이스 회전)                                    │
│       └─┬─┘                                                         │
│         │                                                           │
│       ┌─┴─┐                                                         │
│       │J2 │ ← 축 2 (어깨)                                           │
│       └─┬─┘                                                         │
│         │    모든 축이 동시에,                                       │
│       ┌─┴─┐  정확히 같은 순간에 움직여야 함!                         │
│       │J3 │ ← 축 3 (팔꿈치)                                         │
│       └─┬─┘                                                         │
│         │    1μs의 오차도 궤적 오류 발생                             │
│       ┌─┴─┐                                                         │
│       │J4 │ ← 축 4-6 (손목)                                         │
│       └───┘                                                         │
│                                                                     │
│  요구사항:                                                          │
│  • 6개 축 동기화 오차: < 1 μs                                       │
│  • 위치 명령 주기: 250 μs ~ 1 ms                                    │
│  • 위치 피드백: 실시간 수신 필수                                     │
│                                                                     │
│  ─────────────────────────────────────────────────────────────────  │
│                                                                     │
│  왜 표준 이더넷/다른 프로토콜로는 불가능한가?                         │
│                                                                     │
│  표준 이더넷:                                                       │
│  • 축 1에 명령 전송... 1ms 후 축 2에 전송... → 동기화 불가           │
│  • 지터로 인해 매 사이클마다 타이밍 변동 → 궤적 진동                 │
│                                                                     │
│  PROFINET IRT:                                                      │
│  • 가능하지만, 1ms 사이클이 한계                                    │
│  • 고속 로봇에는 부족                                               │
│                                                                     │
│  EtherCAT:                                                          │
│  • 100μs 사이클로 6축 동시 제어                                     │
│  • 동기화 오차 < 100ns                                              │
│  • 분산 클럭(DC)으로 나노초 단위 정밀도                              │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 2.3.3 왜 다른 선택은 위험한가?

```
┌─────────────────────────────────────────────────────────────────────┐
│                 잘못된 프로토콜 선택의 결과                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  사례 1: CNC 기계에 표준 이더넷 사용                                 │
│  ────────────────────────────────────                               │
│  결과: 가공 정밀도 불량, 표면 품질 저하                              │
│  원인: 불규칙한 통신 지연으로 축 동기화 실패                         │
│  손실: 불량품 발생, 고객 클레임                                      │
│                                                                     │
│  사례 2: 고속 패키징 라인에 EtherNet/IP 사용                         │
│  ────────────────────────────────────────                           │
│  결과: 최대 속도의 60%만 달성                                       │
│  원인: 1ms 사이클로는 고속 라벨링 불가                               │
│  손실: 생산성 40% 감소                                              │
│                                                                     │
│  사례 3: 다축 로봇에 PROFINET 사용                                  │
│  ─────────────────────────────────                                  │
│  결과: 궤적 오차 발생, 충돌 위험                                     │
│  원인: 동기화 정밀도 부족                                           │
│  손실: 안전 사고 위험, 보험료 증가                                   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 3. CAN FD를 사용해야 하는 이유

### 3.1 표준 이더넷으로는 불가능한 이유 (차량/분산 시스템)

#### 3.1.1 차량 환경의 특수성

```
┌─────────────────────────────────────────────────────────────────────┐
│                    차량 환경의 통신 요구사항                         │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  환경적 제약:                                                       │
│  ─────────────                                                      │
│                                                                     │
│  ┌───────────────────────────────────────────────────────────────┐ │
│  │                                                               │ │
│  │  온도: -40°C ~ +125°C (엔진룸)                                │ │
│  │  진동: 지속적인 진동 및 충격                                   │ │
│  │  EMI: 점화 시스템, 모터 노이즈                                 │ │
│  │  공간: 극도로 제한된 배선 공간                                 │ │
│  │  무게: 연비를 위해 최소화 필수                                 │ │
│  │  비용: 대량 생산으로 $0.01 단위 원가 절감 중요                 │ │
│  │                                                               │ │
│  └───────────────────────────────────────────────────────────────┘ │
│                                                                     │
│  이더넷의 문제점:                                                   │
│  ────────────────                                                   │
│                                                                     │
│  1. 케이블 무게/부피                                                │
│     • 이더넷 케이블: 두껍고 무거움                                  │
│     • 차량 1대당 수십 kg 추가 → 연비 악화                           │
│                                                                     │
│  2. 커넥터 비용                                                     │
│     • RJ45 커넥터: 진동에 취약, 고비용                              │
```

```
│ 학습 곡선    │ 중           │ 저           │ 저                    │
├──────────────┼──────────────┼──────────────┼───────────────────────┤
│ 최적 용도    │ 고속 모션    │ 분산 제어    │ IT 네트워킹           │
│              │ 로봇 제어    │ 차량 네트워크│ 비실시간 데이터       │
│              │ 반도체 장비  │ 산업 센서망  │ 웹/파일 전송          │
└──────────────┴──────────────┴──────────────┴───────────────────────┘
```

### 4.3 핵심 메시지

```
┌─────────────────────────────────────────────────────────────────────┐
│                         핵심 메시지                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ╔═══════════════════════════════════════════════════════════════╗ │
│  ║                                                               ║ │
│  ║  "표준 이더넷은 '빠른' 것이지, '정확한 시간'이 아니다"         ║ │
│  ║                                                               ║ │
│  ║  "CAN FD는 '저비용 + 신뢰성 + 호환성'의 최적 조합이다"         ║ │
│  ║                                                               ║ │
│  ║  "EtherCAT은 '실시간 + 동기화 + 효율성'의 극한이다"            ║ │
│  ║                                                               ║ │
│  ╚═══════════════════════════════════════════════════════════════╝ │
│                                                                     │
│  잘못된 프로토콜 선택의 결과:                                        │
│  ─────────────────────────────                                      │
│                                                                     │
│  • 모션 컨트롤에 표준 이더넷 → 정밀도 불량, 진동, 불량품             │
│  • 차량에 이더넷 전면 적용 → 비용 증가, 무게 증가, 연비 악화         │
│  • 분산 센서에 EtherCAT → 과도한 비용, 복잡성                       │
│  • 로봇에 CAN FD → 속도 부족, 동기화 불가                           │
│                                                                     │
│  올바른 선택:                                                       │
│  ────────────                                                       │
│                                                                     │
│  • 고속 모션/로봇/반도체 → EtherCAT                                 │
│  • 차량/분산 센서/저비용 → CAN FD                                   │
│  • 비실시간/IT 통합 → 표준 이더넷                                   │
│  • 복합 시스템 → 게이트웨이로 연결                                   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```
