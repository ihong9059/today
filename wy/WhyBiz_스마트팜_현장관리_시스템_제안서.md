## 1. 시스템 개요

### 1.1 도입 배경

스마트팜 시스템을 운영하는 현장에서는 정기적인 점검, 장비 상태 확인, 이슈 발생 시 대응 등 다양한 업무가 발생합니다. 그러나 이러한 현장 업무들이 체계적으로 기록되지 않으면:

- 문제점의 발생 추이를 파악하기 어려움
- 장비/시설의 상태 변화를 추적하기 어려움
- 영업 활동에 필요한 데이터 확보가 어려움
- 담당자 변경 시 업무 인수인계가 어려움

### 1.2 시스템 목적

**WhyBiz 현장관리 시스템**은 스마트팜 점검 담당자가 현장에서 수집한 데이터를 체계적으로 데이터베이스화하여:

| 목적 | 기대 효과 |
|------|-----------|
| **업무 기록 체계화** | 모든 현장 활동이 GPS 위치, 사진, 텍스트로 기록됨 |
| **문제점 추이 분석** | 이슈 발생 패턴, 빈도, 위치별 분포 파악 가능 |
| **시스템 상태 추적** | 장비/시설의 상태 변화 이력 관리 |
| **영업 활동 지원** | 축적된 데이터를 기반으로 고객 맞춤형 제안 가능 |

## 4. 사용 방법

### 4.1 Android 앱 사용법

#### 4.1.1 앱 설치

1. APK 파일을 Android 기기에 복사
2. 설정 > 보안 > 알 수 없는 출처 허용
3. APK 파일 실행하여 설치
4. 권한 요청 시 모두 허용 (위치, 카메라, 저장소)

#### 4.1.2 데이터 입력 절차

```
1. 앱 실행
   └─▶ GPS 정보 자동 수집 (화면 상단에 표시)

2. 카테고리 선택
   └─▶ 매장: 매장 관련 점검 사항
       시설: 건물, 구조물 관련
       장비: 센서, 제어기 등 장비 관련
       이슈: 문제점, 고장 등
       기타: 그 외 사항

3. 제목 입력
   └─▶ 예: "A농장 온도센서 점검"

4. 내용 입력
   └─▶ 예: "센서 정상 작동 확인, 배선 상태 양호"

5. 사진 촬영 (선택사항)
   └─▶ 사진 영역 탭 → 카메라 촬영 또는 갤러리 선택

6. 데이터 전송
   └─▶ "데이터 전송" 버튼 클릭
```

#### 4.1.3 데이터 조회 절차

```
1. 하단 "검색" 탭 선택

2. 검색 조건 설정
   └─▶ 키워드: 검색어 입력
       카테고리: 특정 카테고리 선택
       기기: 특정 담당자 기기 선택

3. "검색" 버튼 클릭

4. 결과 목록에서 항목 선택
   └─▶ 상세 정보 모달 표시 (사진, 지도, 내용)
```

## 5. 데이터 카테고리 활용 가이드

### 5.1 카테고리별 권장 사용 시나리오

| 카테고리 | 사용 시나리오 | 예시 |
|----------|--------------|------|
| **매장** | 고객사 매장/농장 방문 시 | "B농장 정기 점검", "신규 고객 현장 조사" |
| **시설** | 건물, 하우스, 구조물 점검 | "3동 하우스 비닐 상태 점검", "관수시설 배관 확인" |
| **장비** | 센서, 제어기, 장비 점검 | "온습도 센서 교체", "CO2 센서 보정" |
| **이슈** | 문제점, 고장, 민원 | "환기팬 이상 소음", "통신 장애 발생" |
| **기타** | 위 카테고리에 해당하지 않는 경우 | "교육 참석", "자재 수령" |

### 5.2 효과적인 데이터 입력 팁

1. **제목은 간결하고 명확하게**
   - 좋은 예: "A농장 1동 온도센서 교체"
   - 나쁜 예: "센서 교체함"

2. **내용에는 상세 정보 포함**
   - 점검 결과
   - 조치 사항
   - 후속 조치 필요 여부

3. **사진은 필수로 첨부**
   - 현장 상황 기록
   - 장비 상태 기록
   - 작업 전/후 비교

## 6. 데이터 활용 방안

### 6.1 문제점 추이 분석

```
[이슈 카테고리 데이터 분석]

1. 월별 이슈 발생 건수 추이
   └─▶ 특정 시기에 이슈가 집중되는지 파악

2. 위치별 이슈 분포
   └─▶ 지도에서 이슈 마커 밀집 지역 확인
   └─▶ 특정 지역/농장에 문제가 집중되는지 파악

3. 이슈 유형 분류
   └─▶ 센서 관련 / 통신 관련 / 시설 관련 등
   └─▶ 빈발하는 이슈 유형 도출
```

### 6.2 시스템 상태 추적

```
[장비 카테고리 데이터 분석]

1. 장비별 점검 이력
   └─▶ 특정 장비의 점검/교체 이력 추적

2. 장비 교체 주기 분석
   └─▶ 평균 교체 주기 산출
   └─▶ 예방 정비 계획 수립에 활용

3. 장비 상태 변화
   └─▶ 사진을 통한 시각적 변화 추적
```

### 6.3 영업 활동 지원

```
[데이터 기반 영업 활동]

1. 고객별 방문 이력
   └─▶ 방문 빈도, 점검 내용 확인
   └─▶ 고객 관리 히스토리 제공

2. 이슈 해결 실적
   └─▶ 문제 발생 → 해결까지의 이력
   └─▶ 서비스 품질 입증 자료

3. 제안서 작성 근거
   └─▶ 누적된 데이터로 문제점 분석
   └─▶ 개선 방안 제시에 데이터 활용
```

## 7. API 명세

### 7.1 데이터 제출 API

```
POST /api/data
Content-Type: multipart/form-data

Parameters:
- device_id: 기기 식별자 (string, 필수)
- title: 제목 (string, 필수)
- category: 카테고리 (string, 필수)
  - store | facility | equipment | issue | other
- content: 내용 (string, 선택)
- latitude: 위도 (number, 선택)
- longitude: 경도 (number, 선택)
- photo: 사진 파일 (file, 선택)

Response:
{
  "success": true,
  "id": 123,
  "message": "Data saved"
}
```

### 7.2 데이터 조회 API

```
GET /api/data?keyword=&category=&device_id=&limit=100

Response:
[
  {
    "id": 123,
    "device_id": "tablet-001",
    "title": "A농장 점검",
    "category": "facility",
    "content": "정상",
    "photo": "/uploads/photo-xxx.jpg",
    "latitude": 37.12345,
    "longitude": 127.12345,
    "timestamp": "2026-01-29T10:30:00.000Z"
  },
  ...
]
```

### 7.3 검색 API

```
POST /api/search
Content-Type: application/json

Body:
{
  "keyword": "온도센서",
  "category": "equipment",
  "device_id": "tablet-001",
  "date_from": "2026-01-01",
  "date_to": "2026-01-31",
  "limit": 50
}

Response:
{
  "count": 5,
  "results": [...]
}
```

### 7.4 통계 API

```
GET /api/search/stats

Response:
{
  "total": 150,
  "today": 5,
  "withPhoto": 120
}
```
